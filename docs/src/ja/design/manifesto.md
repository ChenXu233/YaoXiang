## 一、なぜ YaoXiang を作るのか？

### 1.1 埋める言語の空白

プログラミング言語の歴史の流れの中で、数多くの優れた言語の誕生と進化を目の当たりにしてきた。C 言語はシステムプログラミングの効率革命をもたらし、Python は誰もが学べるプログラミング体験を創出し、Rust はメモリ安全性と性能の両立を証明し、TypeScript は大規模フロントエンドプロジェクトを保守可能にした。しかしながら、今日の言語エコを俯瞰すると、依然として明白な断層地帯が存在している——**以下の三つの核心的ニーズを同時に満たす言語は一つとして存在しない**：

| ニーズ         | 既存ソリューションの問題                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------------- |
| **型安全性**   | Rust は厳格すぎ、学習曲線が急峻；TypeScript はオプション型で、コンパイル時の保証を提供できない                      |
| **自然な構文** | Rust の構文は複雑で難解；Haskell の関数型は敷居が高い；従来の静的言語は冗長で煩雑                                   |
| **AI 親和性**  | 既存言語は構文の曖昧さ、AST の複雑さ、隠れた振る舞いの予測困難さを抱え、AI がコードを生成・修正する精度が制限される |

YaoXiang の誕生は、まさにこの空白を埋めるためである。私たちは信じる：**プログラミング言語は強大であると同時に親しみやすく、安全であると同時に効率的であり、厳密であると同時に優雅であるべきだ**。

### 1.2 解決する実際的な問題

**問題一：型システムの断片化**

今日のプログラミング言語は型システムにおいて深刻な断片化を示している。静的型付き言語はコンパイル時の絶対的な正確性を追求するが、往々にして開発効率を犠牲にする；動的型付き言語は柔軟性を提供するが、大規模プロジェクトでは保守困難な欠陥を露呈する。YaoXiang は「すべては型である」という統一抽象フレームワークを提案し、型を言語設計の主軸とし、事後的なパッチではなくする。

**問題二：メモリ安全性とパフォーマンスの二者択一**

長きにわたり、開発者はメモリ安全性と実行性能の間で難しい選択を迫られてきた。GC（ガベージコレクション）は開発者を解放するが、レイテンシの変動とメモリオーバーヘッドをもたらす；手動メモリ管理は効率的だが、綱渡りのように危険である。YaoXiang は Rust スタイルの所有権モデルを採用し、データ競合とメモリリークをコンパイル時に排除しつつ、ゼロコスト抽象を維持し、GC を必要とせずに高性能を実現する。

**問題三：非同期プログラミングの認知負荷**

現代アプリケーションはネットワークと並行処理から切り離せないが、非同期プログラミングは常にプログラマーにとっての悪夢であった。コールバック関数のネスト、Promise チェーン呼び出し、async/await 構文——いずれのソリューションもコードの複雑性を増大させる。YaoXiang は非同期モデルを再設計した：関数シグネチャの後に
`spawn`
マーカーを追加するだけで、コンパイラがすべての非同期の詳細を自動処理し、並行プログラミングを同期コードのように自然にする。

**問題四：AI 支援プログラミングのボトルネック**

AI が開発者のコード記述を支援し始めたとき、言語設計の選択は極めて重要になる。曖昧な構文規則、暗黙的な型変換、複雑な構文糖衣——これらは人間のプログラマーがすでに慣れた特性であるが、AI にとっては理解と生成の障害となる。YaoXiang は設計当初から「AI 親和性」を核心目標とした：厳格なインデント規則、明確なコードブロック境界、曖昧さのない構文構造により、AI がコードを正確に理解、生成、修正できるようにする。

### 1.3 言語の哲学的根幹

YaoXiang の名は『易経』における「爻」と「象」に由来する。「爻」は卦象を構成する基本記号であり、陰陽の変化、動静の相互生成を象徴する；「象」は事物の本質外在する表現であり、万象万物を包括することを表す。

この哲学的思想は言語設計のあらゆる細部に反映されている：

- **統一性**：爻卦の単純な記号が複雑な卦象を構成するように、YaoXiang は少数の核心概念（型、関数、コンストラクタ）で完全なプログラミングモデルを構築する
- **階層性**：象に先天後天の区別があるように、YaoXiang の型システムは原型から generics、値から meta
  type まで明確な階層構造を持つ
- **変化性**：陰陽が流転し変化无穷なるように、YaoXiang は依存型をサポートし、型の値に伴う変化と進化を可能にする
- **識別可能性**：卦象が解釈可能で万物に象があるように、YaoXiang は完全な型リフレクション能力を提供し、実行時の型情報を完全に利用可能にする
- **証明可能性**：卦象が事物の法則を明らかにするように、YaoXiang の型システムは Curry-Howard 同型（型は命題、プログラムは証明）に従い、型検査の過程はすなわち論理的証明の検証である

## 二、核心哲学と原則

以下の設計信条は YaoXiang の礎であり、**妥協不可、違反不可**である。いかなる特性提案もこれらの原則による検証を経なければならない。

### 2.1 原則一：すべては型である

YaoXiang の世界観において、型は最高層の抽象ユニットであり、言語を貫く核心概念である。

**具体的な現れ**：

- **値は型のインスタンス**：`42` は `Int` 型のインスタンス、`"hello"` は `String`
  型のインスタンスである
- **型自身も型である**：`Type` は言語唯一の meta type キーワードであり、`Int` の類は `Type` である
- **関数は型写像**：`add: (a: Int, b: Int) -> Int` は `Int × Int` から `Int` への型写像を記述する
- **モジュールは型の組み合わせ**：モジュールは関数と型を含む名前空間の組み合わせである

**妥協不可の理由**：統一型抽象は言語の意味論を簡素化し、値と型の二元対立を排除し、型システムをコードの正当性の守護者とし、障害物ではなくする。

### 2.2 原則二：厳格な構造化

YaoXiang の構文設計は「曖昧さなし、予測可能、解析容易」を追求する。

**具体的な規則**：

- **4 スペースインデント強制**：タブ文字の使用を禁止し、コードブロック境界を一目瞭然にする
- **括弧省略不可**：関数引数は括弧必須、リスト要素はカンマ必須
- **コードブロックには中括弧必須**：`if`、`while`、`for` などの制御フローは `{ }`
  で囲むことを必須とする
- **キーワード数を最小限に**：核心 17 キーワードのみ保持し、構文糖衣の氾濫を拒否する

**妥協不可の理由**：厳格な構造化は三つの重要な利点をもたらす——（1）IDE のシンタックスハイライトとコード折りたたみがより正確になる；（2）AI コード生成と修正の精度が大幅に向上する；（3）新規学習者が迅速にコード構造を理解できる。

### 2.3 原則三：ゼロコスト抽象

高レベルの抽象が実行時のパフォーマンスオーバーヘッドをもたらすことはあってはならない。

**具体的な保証**：

- **単相化**：ジェネリック関数はコンパイル時に具体バージョンに展開され、仮想テーブル検索のオーバーヘッドがない
- **インライン化最適化**：単純な関数は自動的にインライン化され、関数呼び出しのオーバーヘッドを排除する
- **スタック割り当て優先**：小オブジェクトはデフォルトでスタック割り当て、ヒープ割り当ては必要な場合のみ使用
- **GC なし**：所有権モデルがメモリ安全性を保証し、ガベージコレクタの実行時オーバーヘッドを不要にする

**妥協不可の理由**：パフォーマンスはプログラミング言語の生存の底线である。利便性のためにパフォーマンスを犠牲にする設計は、プログラマーへの裏切りである。

### 2.4 原則四：デフォルト不変

可変性は複雑性と表裏一体である。YaoXiang はデフォルト不変を選択し、コードをより推論しやすく理解しやすくする。

**具体的な規則**：

- 変数はデフォルトで不変、赋值後は再変更不可
- 可変が必要な場合は明示的に `mut` を宣言する必要がある
- 参照はデフォルトで不変、可変参照には `mut` マーカーが必要
- 所有権の移転は元の束縛を無効化する

**妥協不可の理由**：不変性は並行安全性の基礎であり、コード可読性の保障であり、関数型プログラミングの知恵の結晶である。

### 2.5 原則五：型はデータ

型情報はコンパイル期にのみ存在するべきではなく、実行時に完全に利用可能であるべきである。

**具体的な能力**：

- 実行時型クエリ：すべての値はその型情報を取得できる
- 型リフレクション：型自体を構築し操作できる
- パターンマッチによる分解：型コンストラクタは直接パターンマッチに使用できる
- ジェネリック特化：実行時にジェネリック引数の具現化された型を取得できる

**妥協不可の理由**：完全な型リフレクション能力はメタプログラミングの基礎であり、高性能フレームワークとツールの礎である。

## 三、重要な革新と特性

YaoXiang は既存言語の優れた特性を吸収しつつ、以下の革新的な設計を提案する。

### 3.1 革新一：統一型構文

**従来言語の型定義**は往々にして複数のキーワードを必要とする：

```rust
// Rust
struct Point { x: f64, y: f64 }
enum Result<T, E> { Ok(T), Err(E) }
enum Color { Red, Green, Blue }
trait Drawable { fn draw(&self, s: &Surface); }
```

**YaoXiang の統一構文**：すべては `name: type = value`、`Type` は唯一の meta type キーワードである。

```yaoxiang
# === 记录类型 ===

Point: Type = {
    x: Float,
    y: Float,
}

# 带默认值的字段
Point3D: Type = {
    x: Float = 0,
    y: Float = 0,
    z: Float = 0,
}

# === 泛型类型 ===

Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self,
}

Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self,
}

# === 接口（字段全为函数类型的记录） ===

Drawable: Type = {
    draw: (Surface) -> Void,
    bounding_box: () -> Rect,
}

Serializable: Type = {
    serialize: () -> String,
}

# === 接口实现（接口名写在类型体内） ===

Point: Type = {
    x: Float,
    y: Float,
    Drawable,
    Serializable,
}

# === 方法（Type.method 语法） ===

Point.draw: (self: &Point, surface: Surface) -> Void = {
    surface.plot(self.x, self.y)
}
```

**革新の価値**：`fn`、`struct`、`enum`、`trait`、`impl`
キーワードの断片化なし——一つの統一構文ですべての宣言をカバーする。

### 3.2 革新二：コンストラクタは型である

**値構築と関数呼び出しは完全に同一**：

```yaoxiang
# 类型定义
Point: Type = { x: Float, y: Float }
Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self,
}

# 值构造：与函数调用相同
p: Point = Point(3.0, 4.0)
opt: Option(Int) = Option.some(42)
none: Option(Int) = Option.none()

# 模式匹配：直接解构
match opt {
    Option.some(value) -> print(value)
    Option.none -> print("nothing")
}
```

### 3.3 革新三：カリー化メソッド束縛

YaoXiang は純粋関数型設計を採用し、カリー化によりオブジェクトメソッド呼び出しに類似した構文糖衣を実現し、`class`
と `method` キーワードの導入を不要にする。

```yaoxiang
# === 类型定义 ===

Point: Type = {
    x: Float,
    y: Float,
}

# 核心函数：欧几里得距离
distance: (a: Point, b: Point) -> Float = {
    dx = a.x - b.x
    dy = a.y - b.y
    return (dx * dx + dy * dy).sqrt()
}

# 方法语法糖绑定（[0] 表示绑定到第 0 个参数位置）
Point.distance = distance[0]

# === 使用 ===

p1 = Point(3.0, 4.0)
p2 = Point(1.0, 2.0)

# 两种调用方式完全等价
d1 = distance(p1, p2)     # 直接调用核心函数
d2 = p1.distance(p2)      # 方法语法糖

# 柯里化用法
dist_from_p1 = p1.distance  # 部分应用，等待第二个参数
d3 = dist_from_p1(p2)       # 2.828
```

**革新の価値**：純粋関数型設計、隠れた `self` 引数なし、関数は値として自由に渡し組み合わせ可能。

### 3.4 革新四：spawn モデル

> 「万物并作，吾以观复。」——『易経・復卦』
>
> spawn モデルはここに意を取っており、一つのプログラミングパラダイムを記述している：開発者は同期・順次思考でロジックを記述し、言語ランタイムはその中の計算ユニットを万物の并作のように自動的かつ高效に並行実行させ、最終的に統一的に協調させる。

**核心三原則**：

| 原則         | 説明                                             |
| ------------ | ------------------------------------------------ |
| **同期構文** | 見たままの順次コード                             |
| **並行本質** | ランタイムが自動的に並列性を抽出                 |
| **統一協調** | 結果は必要時に自動収束し、ロジックの正確性を保証 |

**用語体系**：

| 公用語                 | 対応構文                     | 説明                                                        |
| ---------------------- | ---------------------------- | ----------------------------------------------------------- |
| **spawn 関数**         | `spawn (params) => body`     | spawn 実行に参加可能な計算ユニットを定義                    |
| **spawn ブロック**     | `spawn { a(), b() }`         | 明示的に宣言された並行領域、ブロック内タスクは spawn 実行   |
| **spawn ループ**       | `spawn for x in xs { ... }`  | データ並列、ループ本体は全要素上で spawn 実行               |
| **spawn 値**           | `Async(T)`                   | spawn 進行中の未来の値、使用時に自動待機                    |
| **spawn グラフ**       | 遅延計算グラフ(DAG)          | spawn が発生する舞台、依存関係と並列関係を記述              |
| **spawn スケジューラ** | ランタイムタスクスケジューラ | 万物を協調させ、正しいタイミングで spawn させるスマート中枢 |

> **詳細**：[RFC-001 spawn モデル](./rfc/deprecated/001-concurrent-model-error-handling.md)

```yaoxiang
# === spawn 函数 ===
# spawn 标记的函数
fetch_data: (url: String) -> JSON spawn = {
    return HTTP.get(url).json()
}

# === spawn 块 ===
# spawn { } 内的表达式强制并行执行
compute_all: () -> (Int, Int, Int) spawn = {
    (a, b, c) = spawn {
        heavy_calc(1),    # 任务 1
        heavy_calc(2),    # 任务 2
        another_calc(3)   # 任务 3
    }
    return (a, b, c)
}

# === 自动等待 ===
main: () -> Void = {
    # 两个独立请求自动并行执行
    users = fetch_data("https://api.example.com/users")
    posts = fetch_data("https://api.example.com/posts")

    # 等待点在需要结果时自动插入
    print(users.length + posts.length)  # 自动等待 users 和 posts
}
```

**スレッド安全性**：

```yaoxiang
# ref 关键字自动处理线程安全（编译器自动选 Rc/Arc）
main: () -> Void = {
    counter = ref SafeCounter(0)

    # 跨任务共享：编译器自动选 Arc
    spawn {
        counter.increment()
    }
    spawn {
        counter.increment()
    }
}
```

**技術文書**：

- 詳細 [RFC-001 spawn モデル](./rfc/deprecated/001-concurrent-model-error-handling.md)

**革新の価値**：非同期プログラミングの認知負荷をゼロに、コード可読性を同期コードと完全に同一にしつつ、高性能並列実行効率を獲得。

### 3.5 革新五：値依存型（RFC-011）

> **ステータス**：設計中、一部実装済み

型は値に依存可能、真の型駆動開発を実現。

```yaoxiang
# 矩阵类型：维度在编译期确定
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),
}

# 编译期计算：factorial(3) = 6
arr: Array(Int, factorial(3)) = Array(Int, 6)()

# 编译期维度验证
identity_3x3: Matrix(Float, 3, 3) = identity(Float, 3)(3)
# multiply(matrix_2x3, matrix_4x2)  # 编译错误：维度不匹配
```

**革新の価値**：コンパイル時により多くのエラーを捕捉し、より精確な型保証を実現。

### 3.6 革新六：極簡キーワード設計

YaoXiang はわずか 17 の核心キーワードのみを定義し、主流言語をはるかに下回る：

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

| 比較言語   | キーワード数 |
| ---------- | ------------ |
| YaoXiang   | **17**       |
| Rust       | 51+          |
| Python     | 35           |
| TypeScript | 64+          |
| Go         | 25           |

**革新の価値**：より低い記憶負荷、より一貫した構文スタイル、より解析容易な構文構造。

### 4.4 所有権モデル（RFC-009 v9）

```yaoxiang
Point: Type = { x: Float, y: Float }

# 默认 Move（零拷贝）
p1 = Point(1.0, 2.0)
p2 = p1              # Move，p1 不可再读

# &T / &mut T 令牌（编译期零开销）
p2.print()           # 编译器自动创建 &Point 令牌
p2.shift(1.0, 1.0)  # 编译器自动创建 &mut Point 令牌

# ref：共享持有（编译器自动选 Rc/Arc）
shared = ref p2      # 跨作用域共享

# clone()：显式深拷贝
backup = p2.clone()

# unsafe + 裸指针：系统级
unsafe {
    ptr: *Point = &p2
    (*ptr).x = 0.0
}
```

**所有権グラデーション**：

```
&T / &mut T    Move       ref        clone()    unsafe
    |             |          |           |          |
借用令牌       默认      共享持有     深拷贝     裸指针
零成本         零拷贝    自动Rc/Arc   显式      系统级
```

## 付録C：よくある質問

**Q: YaoXiang は Rust と比較してどんな優位性がありますか？**

A:
YaoXiang は Rust のメモリ安全性とゼロコスト抽象を保持しつつ、より簡潔な構文とより低い認知負荷を採用している。**spawn モデル**は Rust の
`async/await` より簡潔で——一つの `spawn`
マーカーのみ必要、Future と Pin の手動管理不要。「万物并作、吾以观复」、並行プログラミングを自然法則の記述のように直感的にする。**所有権モデル**（RFC-009
v9）は lifetime 注釈を Move + &T/&mut
T 令牌に置き換え、借用チェッカーを型属性（Duplicate/Linear）に置き換える。統一型構文は
`enum`/`struct`/`trait`/`impl` の概念断片化を排除する。

**Q: YaoXiang はどんな種類の開発に適していますか？**

A: システムプログラミング、アプリケーション開発、Web サービス、スクリプトツール、AI 支援プログラミング。汎用プログラミング言語となることを目指している。

**Q: なぜ 4 スペースインデントを選ぶのですか？**

A:
4 スペースは明確なコードブロック視覚的分隔を提供し、ネストの深さによる混乱を減らす。これは熟考された「AI 親和性」設計決定である。

**Q: いつ 1.0 バージョンがリリースされますか？**

A: v1.0 目標：プロダクション利用可。リリース時期は実装進度に依存する。詳細は
[バージョン計画 RFC](./rfc/rejected/003-version-planning.md) を参照。

**Q: コアチームに連絡するには？**

A: GitHub
Discussions または Discord コミュニティチャンネル経由。コアチームメンバーが定期的に返信する。
