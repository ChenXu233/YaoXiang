# RFC-027a: 終了検査の明示的測度

## 摘要

RFC-027
§7 は終了検査の判定基準を**精化型**（精化すなわち検証モードへの移行）と定め、§6.9 で明示的測度の言語形態（組み込み述語
`Terminates`、Int や Never と同様のコアプリミティブ）を示している。どちらも言語設計であり、ホストRFC に属すためすでに定稿済みである。

本サブ RFC は実装機構に承接する：義務が計算構造からどのように生成されるか、判定パイプラインがどのように構成されるか、導出できないときに診断としての方向をどのように提示するか、相互再帰の測度をどのように共有するか（SCC 最適化）、エラーコードをどのように登録するか。**言語意味は繰り返さない**。機構のみを定める。

## 動機

### なぜサブ RFC が必要か

判定基準（精化型による検証モードへの移行）と形態（`Terminates`
を型位置に記述）は RFC-027 ですでに見定めている。粒度は言語レベルである。ここから先の問題は粒度が細かすぎて、ホストに含めると本文が膨れ上がる：

- 義務の出どころ（再帰呼び出し点、ループバックエッジ、パスガード）
- 測度がタプルを返すときの比較方法（辞書式展開）
- 整列性と厳密減少は2つの独立した義務か統合か
- 自動探索と明示的測度が同一パイプラインで共存する方法
- 相互再帰時に同一測度の繰り返し記述と繰り返し検証を避ける方法
- 導出できないときに拒否ではなく**方向**を提示する方法

### トリガー

方向は #318 によってトリガーされる：非構造的再帰（gcd クラスの非直接減少、相互再帰、マージパーティション）は測度探索のテンプレートシーケンス（RFC-027
§6.2–6.5 の4つの戦略すべてが「有界型変数」または「目標型＋交換操作」を入力とする）を超えており、可読性を損なわず解析可能な反復パターンに書き換えることが不可能である。RFC-027「未解決問題」節の再検討条項がここで発動する。

## 提案

### 自動探索との関係

明示的測度は**別のパイプラインではなく**、探索失敗後の入力である。測度を提供した後も同一の SMT で同一の義務群を検証する；成立しない場合はエラーと反例を添付して報告する。完全自動優先は変わらない：探索が常に先に実行され、ユーザーの介入は探索失敗後のみに発生한다。

これにより、2つのパスがすべての下流機構を共有することが決定される——義務生成、SMT 判定、辞書式展開、診断フォーマットはすべて単一の実装である。

### 義務生成

関数 `f` と測度 `m`
に対して、**独立した**2つの義務を生成し、再帰呼び出し点ごとに（SCC 内の関数間呼び出しを含む）展開する：

1. **整列性**：`m(args) >= 0`——測度は自然数上に存在すること；測度が自然数型を返さない場合は、その型上の適切な順序の下界を取る。パラメータの精化から導出し、導出できない場合は残余義務に回る。
2. **厳密減少**：各呼び出し点で `m(callee_args) < m(caller_args)`
   を、**パスガード**下で判定——ガードは該当呼び出し点を含む分岐条件から来ものであり、RFC-009a のパス条件収集を再利用する。

2つの義務は独立しており統合しない。理由は失敗方向が異なるためである：整列性の失敗は測度の値域が不適切であることを意味し（Int が負になり得るなど）、減少の失敗は再帰パラメータがその方向に歩いていないことを意味する。診断は区別する必要があり、正しい検査方向を提示できる（後述「診断」節参照）。

**ループも同理**で、「呼び出し点」を「バックエッジ」に置き換える：ループ本体の各実行パス上で
`m(次ラウンドの状態) < m(当ラウンドの状態)` であり、ガードはループ条件と本体内の分岐から来る。

**辞書式展開**：`m` がタプル `(m₁, …, mₖ)`
を返す場合、義務は辞書式比較により析取的連鎖に展開される——`(m₁' < m₁) ∨ (m₁' == m₁ ∧ m₂' < m₂) ∨ …`。展開は**義務生成側**で完了し、SMT 側は線形断片のままにし、解算器の辞書式原生サポートに依存しない。

**測度自体はコンパイル時評価可能でなければならない**：`m`
は定数畳み込みまたは構造的再帰で証明可能な関数でなければならない——終了問題を別の未証明関数に再帰的に押し付けてはならない（無限後退の防止）。病理的測度は既存の E4012（定数再帰が深すぎる）および構造検査によって阻止される。

### 判定パイプライン

```
1. 仮引数減少（構造的再帰、最強パス、まず試行）
2. 測度探索：4つの戦略テンプレートシーケンス（RFC-027 §6.2–6.5）、1つ見つかれば停止
3. 探索成功 → 義務生成 → SMT 判定 → 証明済み
4. 探索失敗 → 型位置に明示的測度があるかをチェック（Terminates）
     あり → その測度で義務生成 → SMT 判定
     なし → E4021（終了を証明できない、检查方向の提案を添付）
5. 義務が SMT により偽と判定 → E4022（測度が成立しない、反例を添付）
```

1–3 は RFC-027 の既定パスであり、本 RFC は4段目と2つのエラーコードを追加する。パイプライン全体は精化型がトリガーされたときのみ実行される（RFC-027
§7）——精化のない普通型は義務を生成しない。

### 錨点：一項と二項形態

RFC-027 §6.9 は2つのアリティを定めているが、本 RFC はそれぞれの落点を説明する：

| 形態                    | 錨点                     | 落点                                                                                                                   |
| ----------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `Terminates(m)`         | 所在バインディングの名前 | 定義時のデフォルト形態——自己再帰関数、ループ                                                                           |
| `Terminates(FnType, m)` | 明示的関数型             | 測度をどの関数型に帰属させるかを明示する必要がある場合（測度が别处で定義された場合、同測度が複数の計算に服務する場合） |

これは2つの異なる構成ではなく、同一述語の2つのアリティである：終了義務は常に「精化を含む型位置が标注する那段計算」に落ちる。相互再帰は二項形態を**使用する必要はない**——2つの関数が各自一項形態を書けばよく、共有関係は SCC 認識によって處理される（次節参照）。

### SCC：測度共有最適化

相互再帰の関数群（呼び出しグラフ上の強連結成分）が同一の測度を共有する場合、関数間エッジの義務は
`m_callee(callee_args) < m_caller(caller_args)`
となり、メンバが測度を共有する場合は同測度減少に退化한다。

**これは最適化であり、正しさの前置条件ではない**：共有しない場合、各関数が各自の測度を書けば各自でクローズすれば通る。SCC の価値は「このグループが同じ測度を使っている」と認識し、繰り返し記述と繰り返し検証を省くことにある。

**関数レベルの呼び出しグラフと SCC 収集を新規作成する必要がある**——既存の `TypeDepGraph`
は変数間の型注釈依存を記録しており（RFC-027
§6.1 の VC トリガー）、変数レベルのグラフであり、再利用不可である。

### 例

#### gcd：非構造的再帰

```yaoxiang
// 測度：普通の関数、単体テスト可能、再利用可
gcd_measure: (a: Int, b: Int) -> Int = { b }

gcd: Terminates((a: Int, b: Int) -> Int, gcd_measure) = {
    if b == 0 { return a }
    return gcd(b, a % b)
}
```

義務生成：

1. **整列性**：`gcd_measure(a, b) >= 0` すなわち `b >= 0`——仮引数の精化 `NonNegative(b)`
   から直接導出
2. **厳密減少**：唯一の再帰呼び出し点 `gcd(b, a % b)`、パスガード `b != 0`、義務
   `gcd_measure(b, a % b) < gcd_measure(a, b)`；測度体を代入して展開すると `a % b < b`
3. **SMT**：`b != 0 ∧ a % b >= b` の否定が充足不能であることを検証 → 証明済み

#### ループ：匿名構造に呼称を得る

```yaoxiang
loop: (n: Int) -> Int = {
    mut i = 0
    acc: Terminates(n - i) = while i < n {
        i = i + 1
    }
    return acc
}
```

`Terminates(m)` の精化はループ本体末尾式の値型であり、錨点はバインディング名 `acc`
によって提供される——ループ因此に**呼称可能**となり、「匿名構造に呼称できない」という死角がなくなる。这也是两个元数的统一性の説明：義務は常に精化を含む型位置が标注する那段計算に落ち、関数とループに区別はない。

義務：バックエッジ上で `(n - i') < (n - i)`、ガード `i < n`、`i' = i + 1` を代入すると
`1 > 0`、常に真 → 証明済み。

#### 相互再帰：SCC が測度を共有

```yaoxiang
nat: (n: Int) -> Int = { n }

is_even: Terminates(nat) = {
    if n == 0 { return true }
    return is_odd(n - 1)
}
is_odd: Terminates(nat) = {
    if n == 0 { return false }
    return is_even(n - 1)
}
```

2つの関数は各自一項形態の `Terminates(nat)`
を持つ。SCC 収集により二者とも同一の測度を共有すると認識され、関数間エッジの義務
`nat(n - 1) < nat(n)` はガード `n != 0` のもとで常に真であり、2つの関数を一度の検証でクローズする。

SCC 認識をしなくても、2つの関数が各自で同一の義務を検証すれば通る——ただ1回重复するだけである。これにより SCC の定位が最適化であることが裏付けられる。

### 診断

**整列性が導出できないとき、直接拒否するのではなく、检查方向を提案する。**
これは減少義務失敗の診断と明確に区別する必要がある：前者は測度の値域に向き、後者は再帰パラメータに向き。3種類の失敗각자の提案：

| 失敗                 | 提案する方向                                                                     |
| -------------------- | -------------------------------------------------------------------------------- |
| 整列性が導出できない | 測度が可能な値の上に下限を成しているか（Int 測度は >= 0 が必要か）               |
| 厳密減少が偽と判定   | 再帰パラメータは本当に測度が減少する方向へ進んでいるか；SMT 反例を添付           |
| 測度なしで探索失敗   | その計算に名前をバインディングし型位置に測度を提供できる旨を提示（RFC-027 §6.9） |

反例の提示は RFC-013 診断メッセージ規範に従う。非線形のパスガード下では、Sat 反例が直感的でない可能性がある——既知の制限として記録し、RFC-013 と共に反復する。

### エラーコード

E4xxx 証明失敗ファミリーに揃える（E4018 精化述語違反、E4020 証明関数が必要）：

| 提案コード | 名称           | トリガー                                                          |
| ---------- | -------------- | ----------------------------------------------------------------- |
| E4021      | 終了を証明不可 | 探索失敗かつ型位置に明示的測度なし（Terminates 測度の提供を提示） |
| E4022      | 測度が成立せず | 測度義務が SMT により偽と判定（反例を添付）                       |

最終番号は実装時の RFC-013 レジストリの実情为准じる（セグメントの合法性は build.rs の门槛で保証される）。

### 診断層の既存欠陥

現行実装では、範囲内の終了失敗は **E8001「内部コンパイルエラー」** の形で報告される（`Unproven`
が ICE としてフォーマットされる）——終了検査は ICE ではなく、该コードを使用するとユーザーを误导し真の故障を隠蔽する。本 RFC で一并修正：範囲内の終了失敗は E4021/E4022 に移行し、ICE コードは本物の内部エラーに戻す。

### 後方互換性

- 以前終了検査で拒否されたが**精化注釈がない**プログラム：新判定基準では検証モードに入らず、直接コンパイル通過——意図的な緩和であり、引き締めることはない。
- 以前終了検査で拒否され、**精化注釈がある**プログラム：測度を補完すれば通過可能。
- 構造的再帰の正例、既存の終了テスト：期待出力不变。

## 权衡

### メリット

- **新構文ゼロ**：測度は型位置に書き、精化述語適用メカニズムを再利用する；`decreases`
  のような構文位置がない。
- **証明ドメイン動作の整合**：終了ドメインに正しさドメインと一貫性のあるフォールバックチャネルを追加するが、落点は異なる——正しさドメインで証明できない命題は**本体**に証明関数を書き、終了ドメインで探索できない測度は**型位置**に宣言する。両者のメカニズムは同一（どちらも精化型適用）。
- **インフラの再利用**：義務は線形算術とパスガードで構成され>#292 で既に接通済みのパイプラインを利用し、新規后端がない。
- **ループに呼称を与える**：バインディング名がそのまま錨点となり、ループと関数は義務生成において完全に同型であり、ループのための特例設計が不要である。

### デメリットとリスク

- **前置インフラの量が「配線」並み以上**：関数レベルの呼び出しグラフと SCC 収集を新規作成する必要があり、Z3 も生産パイプラインに接続されていない。SCC 部分は延期可能（它是最適化である）が、呼び出しグラフ部分と SCC は同源であり、延期すると相互再帰は各自の測度を書くしかない——仍然通过可能だが、繰り返し検証するだけである。
- **明示的測度は低頻度パスの記述負担**：2点セット（測度関数＋型位置宣言）はインライン注釈より面倒である。許容——フォールバックは低頻度パスであり、測度の再利用性と单体テスト可能性换来ものである。
- **整列性義務のノイズ**：測度が `Int` を返すとき毎回 `>= 0`
  を証明する必要がある。緩和：パラメータの精화가既に下限を示している場合は自動導出；導出できないときだけ残余義務に回り、拒否ではなく方向のみ提示する。
- **反例品質**：非線形ガード下での Sat 反例は直感的でない。既知の制限。
- **`Terminates`
  は唯一のコンパイラ記述体の述語**：述語本体がすべてユーザー記述可能という純粋性からの逸脱。理由：そのアサーション（各呼び出し点/バックエッジでの測度減少）は計算構造に組み込まれており、ユーザーが書いた述語が関数本体やループ本体を参照できないためである。組み込みは名前に收敛し、機構は新增しない。

## 代替案

- **`with decreases (b)`
  インライン注釈構文**：本 issue の初期提案、既に撤回。「終了検査に**注釈構文**の口を明けさせない」は RFC-027 の既定决策であり、インライン注釈はサポートされていない終了パターンを構文位置ではなく型位置にしてしまい、「すべては YaoXiang 関数了一切は型検査器が検証する」という世界観に反する。
- **独立した証明関数（`gcd_proof` が `Terminates(f, m)`
  を返し、戻り値型をスキャンして発見）**：初期設計。棄却——それは「発見メカニズム」「命名規則」「複数候補から最初を使用」「証明関数体内的の名前解決方法」の4種類の複雑さを引入するが、これらはすべて証明を体外に置いたことによるものである。型位置に記述するように変更后、4種類の複雑さがすべて消失する。
- **測度のみを型に入れる（`Terminates(m)`）、二項形態を取消**：より短いが、「測度の帰属を明示的に指定」する表現位置が失われる（測度が别处で定義されている場合、同一測度が複数の計算に服務する場合に置く場所がない）。2つのアリティは同一述語の2つのアリティであり、保持コストはほぼゼロである。
- **フォールバックなしで、ユーザーに解析可能な反復パターンへの書き換えを要求**：現状維持。gcd
  / マージパーティション / 相互再帰は可読性を損なわずには書き換えられない——それが再検討条項のトリガー条件である。

## 非目標

- 新規構文/キーワード/注釈位置を追加しない。
- 測度自動合成の一般化拡張は行わない（4つの戦略は RFC-027 の既定計画を維持し、射程外は明示的測度による）。一般的な測度推論は「発見」の非決定的側に屬し、テンプレート境界を約束できるだけであり、完备性は約束できない。
- RFC-009a と借用命題の聯合求解を行わない（各自独立して判定し、后端を共有する）。
- 依存型レベルの全定性検証（totality checking）を行わない。
- 測度が自然数型を返すことを强制しない（Lean の `WellFoundedRelation`
  型類メカニズムを追求しない）——測度の戻り値型は制限されず、整列性は独立した義務として精化導出または SMT に委ねる。

## 段階と受入

- [ ] 義務生成（整列性 / 厳密減少、パスガード注入、辞書式展開）
- [ ] 明示的測度配線（`Terminates` 一項と二項形態の錨点解析、型位置から測度を抽出）
