## 概要

本文書は YaoXiang 言語の**量子ネイティブサポート**と**マルチバックエンド統合**方案を定義します。コアコンセプト：**YaoXiang の既存設計（デフォルト Move、所有権回流、不透明型、DAG スケジューラ、ジェネリクス定数パラメータ）は、量子プログラミング言語の完全な基盤を自然に構成しており、新しい量子専用構文を導入する必要はありません**。少数の組み込み型（`Qubit`、`Complex`、`Topology`）と組み込み関数（量子ゲート、測定、トポロジー制約）を追加し、既存の言語メカニズムを利用することで、量子ネイティブセマンティクス、自動並行による量子利用率の最大化、ハイブリッド古典プログラミング、およびマルチバックエンドサポートを実現します。

## 動機

### なぜ量子ネイティブサポートが必要なのか？

現在の量子プログラミングエコシステムには深刻な分断があります：

- **低水準言語（QCIS、OpenQASM）**：物理量子ゲートを直接操作しますが、型システムや抽象化メカニズムが欠けており、複雑なアルゴリズムを書くのが困難です。
- **高水準フレームワーク（Qiskit、Cirq、Q#）**：古典言語（Python、C#）を拡張したもので、量子セマンティクスはライブラリとして実装されるため：
  - 量子状態コピー禁止規則はユーザーが手動で遵守する必要があります（または線形型システムの後付けに依存）。
  - 量子ゲート操作と古典コードの構文が分離しており、学習コストが高い。
- **ハイブリッド計算**：量子部と古典部の明示的な分離が必要で、统一的なデータフローモデルがありません。

### 現在の問題点

YaoXiang の既存設計はこれらの問題を解決するのに十分な基盤を提供してます：

| 量子計算ニーズ       | YaoXiang の既存設計  | 説明                                                     |
| ------------------- | ------------------- | -------------------------------------------------------- |
| 量子状態コピー禁止   | **デフォルト Move セマンティクス** | 代入で所有権が移動し、暗黙的なコピーがないため、no-cloning を自然に満たす |
| 量子ゲートがユニタリ変換 | **所有権回流**      | `q = H(q)` は元の qubit を消費し、新しい qubit を返す。これはゲートのセマンティクスに正確に対応 |
| エンタングルメント状態 | **不透明型**        | `BellPair` は全体としてのみ操作でき、コンパイラがライフサイクルを追跡し、誤った分解を防止 |
| 物理トポロジー制約   | **ジェネリクス定数パラメータ** | `Qubit(Topology, N)` でコンパイル時に隣接性をチェック |
| 測定崩壊             | **空状態の再利用**  | 測定後 qubit が空になり、再初期化が可能。量子状態の崩壊を模擬 |
| 量子回路の自動並行化 | **DAG スケジューラ** | 関数内のステートメントはデータ依存に基づいて自動的に並行化され、依存のないゲートは自然に同時実行 |
| ハイブリッド古典-量子制御フロー | **統一構文** | 量子操作と古典操作は同じ `name: type = value` 形式を使用 |

**YaoXiang は「量子サポートを追加」するのではなく、自分の設計がすでに量子ネイティブであることを発見したのです。**

> **セマンティクス説明**：本文書は量子操作を表現するために YaoXiang の**所有権セマンティクス**を使用します。コンパイラレベルで no-cloning（所有権安全）を保証します。言語レベルの「消費-作成」は**所有権移動**の構文的表現です——消費 = 所有権の取得、返値 = 所有権の移行。実装レベルでは真的可逆量子ゲート（量子状態をインプレースで変更）であり、実際の「新量子状態の作成」ではありません。

### 設計目標

1. **新しい構文ゼロ**：`quantum`、`circuit` などのキーワードを導入せず、すべての量子特性を既存の言語メカニズムで表現します。
2. **型安全**：コンパイラが量子状態がコピーまたは不正に使用されないことを保証します。
3. **トポロジー制約のコンパイル時チェック**：ジェネリクス定数パラメータ `Qubit(T, N)` を通じて、コンパイル時に2量子ビットゲート操作が物理トポロジーに従っていることを検証します。
4. **マルチバックエンド透過性**：同じ量子コードを QIR（汎用エコシステム）または QCIS（国内量子命令セット）にコンパイルでき、コマンドラインパラメータで切り替えます。
5. **ハイブリッド古典的无縫**：量子計算は自由に古典関数を呼び出せ、古典コードも量子データを操作できます（`ref` 共有経由、所有権制約に従う）。

## 提案

### コア設計

#### 1. 量子型システムマッピング

**基本型**：

```yaoxiang
Qubit: Type0 = primitive_qubit
Complex: Type0 = { re: Float, im: Float }
```

- `Qubit` は第一級市民型であり、所有権ルール（Move、RAII）に従います。
- `Complex` は振幅を表すために使用され、コンパイラはインライン最適化を行えます。

**量子ゲートを関数として**：

```yaoxiang
# 組み込み関数シグネチャ
H: (Qubit) -> Qubit = builtin_hadamard
X: (Qubit) -> Qubit = builtin_pauli_x
Y: (Qubit) -> Qubit = builtin_pauli_y
Z: (Qubit) -> Qubit = builtin_pauli_z
CNOT: (control: Qubit, target: Qubit) -> { Qubit, Qubit } = builtin_cnot
```

- すべてのゲートは入力 qubit を消費し、新しい qubit（またはエンタングルメントペア）を返します。所有権回流構文 `q = H(q)` は数学的セマンティクスに直接対応します。
- 複数 qubit ゲートは構造体を返し、パターンマッチングまたはフィールドアクセスで結果を取得します。

**測定**：

```yaoxiang
measure: (Qubit) -> Int = builtin_measure   # qubit を消費し、古典ビットを返す
measure_all: (List(Qubit)) -> List(Int) = builtin_measure_all
```

- 測定後 qubit は消費され（空になり）、ユーザーは空状態の再利用で再初期化できます。

**初期化**：

```yaoxiang
qubit: (Int) -> Qubit = builtin_qubit   # 0 または 1 で初期状態
```

#### 2. エンタングルメントと不透明型カプセル化

エンタングルメントペアを不透明型にカプセル化し、合成操作のみを提供し、分解を禁止します：

```yaoxiang
# 組み込み不透明型
BellPair: Type0 = primitive_bell_pair

# 組み込み関数 - 全体としてのみ操作可能
CNOT: (Qubit, Qubit) -> BellPair
measure_bell: (BellPair) -> { Int, Int }
split_bell: (BellPair) -> { Qubit, Qubit }  # エンタングルメントペアを分解（注意して使用）
apply_cnot_to_bell: (BellPair, Qubit) -> BellPair
```

**重要な設計**：

- フィールドアクセッサを提供せず、組み込み関数でのみ全体として操作可能
- `measure_bell(bp)` はエンタングルメントペア全体を一度に消費し、古典ビットを返す
- コンパイラはエンタングルメントペアの完全なライフサイクルを追跡可能

**Python/Qiskit との比較**：

```
Python (Qiskit): ランタイムで回路を構築し、エラーは送信後に才发现
YaoXiang:       コンパイル時に 대부분의論理エラーを捕捉
```

**残りの 10%**（物理デコヒーレンス、ゲートエラーなど）はハードウェアの問題であり、言語で解決できるものではありません。

#### 3. 物理トポロジー制約

量子チップは制約付きトポロジーグラフであり、**任意の2つの qubit で2量子ビットゲートができるわけではなく**、隣接している必要があります。YaoXiang は**ジェネリクス定数パラメータ**を使用してコンパイル時にトポロジー制約を保証します。

**トポロジー型定義**：

```yaoxiang
# トポロジーを型として定義し、隣接行列を含む
Topology: Type0 = primitive_topology

# 組み込みトポロジー定数
Linear8: Topology = topology(8)          # 線形8ビット: 0-1-2-3-4-5-6-7
Grid3x3: Topology = topology(3, 3)        # 3x3 グリッド
Ring16: Topology = topology(16, ring)    # リング16ビット
```

**Qubit のトポロジー、バインド、位置**：

```yaoxiang
# Qubit(T, N) - T はトポロジー型、N は定数位置パラメータ
q0: Qubit(Grid3x3, 0)   # Grid3x3 トポロジー、位置 (0,0)
q1: Qubit(Grid3x3, 1)   # Grid3x3 トポロジー、位置 (0,1)
q2: Qubit(Grid3x3, 2)   # Grid3x3 トポロジー、位置 (0,2)
q3: Qubit(Grid3x3, 3)   # Grid3x3 トポロジー、位置 (1,0)
```

**ゲート操作の自動制約**：

```yaoxiang
# CNOT 型シグネチャはトポロジー制約を伴う
CNOT: (T: Topology, I: Int, J: Int) -> (
    (Qubit(T, I), Qubit(T, J)) -> { Qubit(T, I), Qubit(T, J) }
) when adjacent(T, I, J)

# コンパイル時チェック
CNOT(q0, q1)  # ✅ Grid3x3 で (0,0) と (0,1) は隣接
CNOT(q0, q2)  # ❌ コンパイルエラー：(0,0) と (0,2) は隣接していない
```

**`adjacent` コンパイル時制約**：

- `adjacent` はコンパイル時関数であり、トポロジーの隣接行列を使用して静的チェックを行います
- 定数インデックス時は 100% コンパイル時検証
- 動的インデックス時はランタイムチェックコードを生成

**仮想から物理へのマッピング**：

```yaoxiang
# コンパイル時に具体的な物理位置がわからない？型推論を使用
q = qubit(Grid3x3)  # 自動的に位置0を割り当て、後続で推論
```

#### 4. 所有権と量子状態の線形フロー

すべての量子操作は Move セマンティクスに従い、qubit がコピーされないことを保証します：

```yaoxiang
q = qubit(0)
q2 = q          # ❌ コンパイルエラー：q はすでに移動しており、再使用不可
q = H(q)        # ✅ q を消費し、新しい q を返す
measure(q)      # ✅ q を消費し、その後 q は空になる
q = qubit(0)    # ✅ 空状態の再利用
```

#### 4. 自動並行化と DAG スケジューリング

Standard または Full Runtime では、DAG スケジューラが量子プログラムを自動的に解析します：

```yaoxiang
apply_two_qubit_gates: () -> {Qubit, Qubit} = () => {
    q1 = H(qubit(0))
    q2 = H(qubit(0))
    # 上記2行はデータ依存がなく、DAG は自動的に並行実行
    CNOT(q1, q2)   # q1 と q2 に依存、自动的に待機
}
```

- スケジューラは `num_workers` 設定（物理量子プロセッサ数）を活用して真の並行性を実現します。
- ユーザーはゲート順序を手動で配置する必要はなく、データフローを記述するだけです。

#### 5. ハイブリッド古典計算

古典コードと量子コードが完全に融合します：

```yaoxiang
grover_search: (target: Int) -> Int = () => {
    n = 4
    qubits = List(Qubit)()
    for i in 0..n {
        qubits.append(H(qubit(0)))
    }
    # 古典ループと量子操作の混合
    oracle(qubits, target)   # oracle は量子ゲート列
    qubits = diffusion(qubits)
    results = measure_all(qubits)
    return decode_result(results)   # 古典後処理
}
```

- 同一関数内で量子ゲートと古典制御フローを自由に混合できます。
- 所有権システムは、量子変数が古典分岐で誤ってコピーされないことを保証します。

#### 6. マルチバックエンドサポートアーキテクチャ

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   YaoXiang ソース │     │   型チェック    │     │   DAG 中間表現  │
│   (統一構文)      │────▶│   + 所有権解析   │────▶│   (データフロー図) │
└─────────────────┘     └─────────────────┘     └────────┬────────┘
                                                          │
                                                          ▼
                          ┌─────────────────────────────────────────────┐
                          │           コード生成バックエンド (プラグイン可能)   │
                          ├─────────────────┬───────────────────────────┤
                          │  QIR バックエンド  │  QCIS バックエンド              │
                          │  (汎用エコシステム) │  (国内量子命令セット)              │
                          ├─────────────────┼───────────────────────────┤
                          │  - .ll ファイル出力 │  - .qcis テキスト出力             │
                          │  - 複数の QPU 対応  │  - 中科院/国盾ハードウェア対応      │
                          └─────────────────┴───────────────────────────┘
```

- **コンパイルフロー**：フロントエンド統一 → DAG 構築 → バックエンド選択 → ターゲットコード生成。
- **QIR バックエンド**：DAG ノードを QIR の量子ゲート intrinsic にマッピングし、LLVM bitcode を生成して、LLVM 最適化ををさらに活用できます。
- **QCIS バックエンド**：DAG を QCIS 命令（例：`H q0`）にシリアライズし、量子チップコントロールコンソールに直接送信可能。

### 例

#### ベル状態準備と測定

```yaoxiang
bell_measure: () -> {Int, Int} = () => {
    q1 = H(qubit(0))
    q2 = H(qubit(0))
    bell = CNOT(q1, q2)  # BellPair 不透明型を返す
    result = measure_bell(bell)  # 2ビットを一度に測定
    return result
}
```

#### 量子テレポーテーション（簡略版）

```yaoxiang
teleport: (msg: Qubit, bell: BellPair) -> Qubit = (msg, bell) => {
    # エンタングルメントペアを分解して2つの独立した qubit を取得
    (alice_qubit, bob_qubit) = split_bell(bell)

    # Alice の操作
    (msg, alice_qubit) = CNOT(msg, alice_qubit)
    msg = H(msg)
    a1 = measure(msg)
    a2 = measure(alice_qubit)

    # 古典情報の伝送 (スケジューラが自動的に依存関係を処理)
    # Bob の操作
    if a2 == 1 { bob_qubit = X(bob_qubit) }
    if a1 == 1 { bob_qubit = Z(bob_qubit) }
    return bob_qubit
}
```

## 詳細設計

### 組み込み型と関数定義

`compiler/builtins` モジュールに追加：

```rust
builtins.insert("Qubit", Ty::Primitive(Primitive::Qubit));
builtins.insert("Complex", Ty::Record(vec![
    ("re", Ty::Primitive(Primitive::Float)),
    ("im", Ty::Primitive(Primitive::Float)),
]));

// 量子ゲート
for (name, sig) in GATES {
    builtins.insert(name, Ty::Function(vec![Ty::Qubit], Ty::Qubit));
}
builtins.insert("CNOT", Ty::Function(
    vec![Ty::Qubit, Ty::Qubit],
    Ty::Record(vec![
        ("q0", Ty::Qubit),
        ("q1", Ty::Qubit)
    ])
));
builtins.insert("measure", Ty::Function(vec![Ty::Qubit], Ty::Primitive(Primitive::Int)));
builtins.insert("qubit", Ty::Function(vec![Ty::Primitive(Primitive::Int)], Ty::Qubit));
```

### 所有権チェッカーの Qubit 的特殊処理

- `Qubit` は `!Copy`（デフォルト Move）としてマークされ、暗黙的なコピーを禁止します。
- 測定関数 `measure` のパラメータは `Qubit`（値渡し）であり、所有権を消費します。
- 複数 qubit ゲートが返すレコード型では、フィールドはすべて `Qubit` であり、所有権ルールに従う必要があります。

### DAG スケジューラの量子ゲート最適化

- 量子ゲートノードは純粋関数（副作用なし）と見なされ、スケジューラは依存のないゲートを自由に再配置できます。
- スケジューラが「量子命令列」を出力する際、データ依存を保持し、並行ゲートをグループ化します（複数量子プロセッサに適用可能）。
- `--target-num-qubits` と `--target-topology` 設定をサポートし、将来のレイアウトとルーティングに使用（将来拡張）。

### QIR バックエンドの詳細マッピング

| YaoXiang 操作  | QIR 命令                                                          |
| -------------- | ----------------------------------------------------------------- |
| `H(q)`         | `call void @__quantum__qis__h__body(%Qubit* %q)`                  |
| `CNOT(q1, q2)` | `call void @__quantum__qis__cnot__body(%Qubit* %q1, %Qubit* %q2)` |
| `measure(q)`   | `%result = call i1 @__quantum__qis__mz__body(%Qubit* %q)`         |
| `qubit(0)`     | `%q = call %Qubit* @__quantum__rt__qubit_allocate()`              |

QIR バックエンドは LLVM の `-O2` をさらに活用し、QIR Alliance と互換性のある bitcode を出力します。

### QCIS バックエンドの詳細マッピング

| YaoXiang 操作                        | QCIS 命令                            |
| ------------------------------------ | ------------------------------------ |
| `H(q)` (q は物理ビット2に対応)        | `H 2`                                |
| `CNOT(q1,q2)` (q1→ビット0, q2→ビット1) | `CNOT 0 1`                           |
| `measure(q)` (ビット0)                | `M 0`                                |
| `qubit(0)` 初期化                     | 最初の使用命令に暗黙的に 포함、追加命令不要 |

- 仮想 qubit（YaoXiang 変数）から物理ビットへのマッピングテーブルを維持する必要があります。
- トポロジー制約チェックをサポート（将来実装）。

### ハイブリッド古典コード生成

- 古典部分（ループ、条件、整数演算など）は通常通りローカルコード（x86/ARM）を生成し、FFI または組込み呼び出しで量子バックエンドとやり取りします。
- QIR バックエンドでは、古典部分は LLVM IR に降格でき、QIR と混合コンパイルされます。

### 型システムへの影響

- 新しい `Qubit` と `Complex` 原始型を追加します。
- `Qubit` は自動的に Move セマンティクスを持ち、コピーを禁止します。
- 量子ゲート関数シグネチャは型システムに登録する必要があります。

### 後方互換性

- ✅ 完全な後方互換性
- 新しい組み込み型と関数は既存のコードに影響しない
- 量子特性はオプションであり、有効にしない場合は追加オーバーヘッドなし

## トレードオフ

### 利点

- **新しい構文なし**：開発者は少数の組み込み関数を学ぶだけで量子プログラムを記述できます。
- **型安全**：所有権システムが自動的に qubit コピーを防止し、一般的な量子プログラミングエラーを回避します。
- **自動並行化**：DAG スケジューラが無料でゲートレベルの並行化を提供し、追加のコンパイラ最適化が不要です。
- **エコシステム互換性**：QIR バックエンドにより YaoXiang は複数の量子クラウドプラットフォームで実行可能；QCIS バックエンドにより自律制御を確保します。
- **ハイブリッド機能**：古典-量子融合が自然で、複雑な量子アルゴリズム（Shor、Grover などの古典的制御）の記述に適しています。

### 欠点

- **Qubit 数の静的性**：現在の設計では qubit 数がコンパイル時に既知であることを前提としており、動的割当ては `List(Qubit)` 経由で行いますが、`List` のヒープ割当ては追加オーバーヘッドを引き起こす可能性があります（最適化で緩和可能）。
- **測定後の再利用**：空状態の再利用により qubit の再初期化が可能ですが、物理量子ビットには緩和時間がある場合があり、ランタイムシステムでの処理が必要です（現在ではユーザーが負責）。
- **動的トポロジーマッピング**：ランタイムでのみ物理トポロジーがわかる場合、コンパイル時チェックが有効にならず、ランタイムチェックコードを生成する必要があります（現在のバージョンは静的チェックのみサポート）。

## 代替案

| 方案                                  | 为什么不選択                                                |
| ------------------------------------- | ---------------------------------------------------------- |
| `quantum` キーワードと `circuit` 型の導入 | 新しい構文を追加すると学習コストが高くなり、YaoXiang の簡潔設計原則に反する |
| 量子サポートをライブラリとして만実装     | コンパイラの量子状態安全保証を利用できず、DAG スケジューラとの深い統合ができない |
| 量子ハードウェアの成熟を待ってからサポート | 量子プログラミング言語設計の重要なウィンドウ期を逃がす                       |
| 既存の量子フレームワーク（Qiskitなど）を再利用 | 量子セマンティクスがライブラリで実装されると、型システムと所有権システムの安全保証が得られない |
| 量子サブ言語の個別設計                  | 言語の複雑さが増加し、保守コストが高くなる                               |

## 実装戦略

### フェーズ区分

| フェーズ  | 期間  | 内容                                                                                                      |
| -------- | ----- | -------------------------------------------------------------------------------------------------------- |
| Phase 1 | 1ヶ月 | 基本量子型と組み込み関数：コンパイラに `Qubit`、`Complex` 型を追加し、組み込み関数の型チェックを実装、所有権チェッカーを拡張 |
| Phase 2 | 1ヶ月 | DAG スケジューラが量子ゲートを認識：DAG 構築ロジックを修正し、量子ゲートを純粋関数としてマーク、並行ゲートグループ出力を実装                          |
| Phase 3 | 2ヶ月 | QIR バックエンドプロトタイプ：DAG から QIR コードジェネレータを実装し、LLVM を統合、QIR シミュレータで検証                                     |
| Phase 4 | 2ヶ月 | QCIS バックエンドプロトタイプ：DAG から QCIS 命令への翻訳を実装し、仮想-物理ビットマッピングを設計、国内量子プラットフォームで検証                      |
| Phase 5 | 2ヶ月 | ハイブリッド古典の強化：古典制御フローと量子ゲートの交差するコード生成を正しく保証し、`List(Qubit)` をサポート、例プログラムを追加                           |
| Phase 6 | 2ヶ月 | 最適化とドキュメント：基本レイアウトとルーティングを実装し、ユーザーガイドと量子プログラミングチュートリアルを编写、プレビュー版をリリース                           |

### リスク

1. **量子ハードウェア可用性**：外部量子シミュレータと実際の QPU の可用性に依存します。
   - **軽減**：まずオープンソースシミュレータ（QIR runner、Qiskit Aer）との連携を優先し、実際の QPU は長期目標とします。

2. **バックエンド実装の複雑さ**：QIR と QCIS 仕様は変更される可能性があります。
   - **軽減**：コード生成インターフェースを抽象化し、バックエンドの差異を隔離して、後続の適応を容易にします。

3. **性能の不確実性**：量子プログラムの性能特性は古典プログラムとは異なります。
   - **軽減**：性能プロファイリングツールを提供し、ユーザーにゲートレベル並行化の効果を知らせます。

## オープン問題

- [x] **トポロジー制約**：`Qubit(Topology, N)` ジェネリクス定数パラメータでコンパイル時チェックを実装済み。
- [ ] **動的量子レジスタ**：`List(Qubit)` は QCIS バックエンドでどのようにマッピングしますか？対応する数の物理ビットを生成できますが、ランタイム割当てメカニズムが必要です。
- [ ] **エラー緩和**：組み込みのエラー緩和（動的デカップリングなど）を提供しますか？最初はライブラリとして実装できます。
- [ ] **既存の量子 SDK との相互運用性**：QASM や QIR モジュールをインポートできますか？将来は FFI を検討できます。
- [ ] **自動レイアウトとルーティング**：仮想 qubit 数が物理 qubit 数を超过えた場合、どう自動的にマッピングしますか？
