# RFC-003：バージョン計画

> **拒否日**: 2026-06-01

## ⚠️ 拒否理由

**本 RFC は RFC 規範に準拠していないため、拒否されました。**

### 問題分析

| 問題                     | 説明                                                                                                                       |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| **文書タイプエラー**     | RFC は「なぜこのように設計するか」の意思決定文書であり、本文は「今どこにいるか、どこへ行くか」のプロジェクト管理文書である |
| **設計意思決定の欠如**   | 技術選定のトレードオフ分析がなく、代替案の比較もなく、設計理由もない                                                       |
| **過剰な計画**           | 9 バージョン（v0.1〜v1.0）を計画しているが、完了したのは 1.5 個のみで、v0.3 以降はすべて推測である                         |
| **保守コスト高**         | 成功指標表に 50 個の状態があり、保守が困難                                                                                 |
| **バージョン番号の混乱** | v0.8 をスキップしており、説明がない                                                                                        |

### 正しい文書タイプ

本ドキュメントは RFC ではなく、**プロジェクトロードマップ（Roadmap）**として管理すべきである。ロードマップは事実と短期計画を記述し、RFC は設計上の意思決定を記述する。

## 概要

YaoXiang のバージョンリリース計画、v0.1 から v1.0 までのロードマップ。

**核心的な目標**：

1. **バイトコードコンパイル**：REPL と段階的コンパイルをサポート
2. **セルフホスティング (Bootstrap)**：YaoXiang を使って YaoXiang コンパイラを記述
3. **AOT コンパイル**：バイトコードからネイティブマシンコードへコンパイル

## 一、動機

### なぜバージョン計画が必要か？

1. **プロジェクト管理**：目標を実行可能なマイルストーンに分解する
2. **ユーザーの期待**：ユーザーに言語の発展段階を理解させる
3. **リソース配分**：各段階の重点を明確にする
4. **リスク管理**：問題を迅速に発見し方向を調整する

### 核心的な設計意思決定

- **バイトコード優先**：まずインタプリタ実行を実装し、AOT は後回し
- **段階的デリバリー**：各バージョンに実用可能な機能を持たせる
- **後方互換性**：v1.0 以前は API が変更される可能性があるが、事前通知する
- **セルフホスティング検証**：セルフホスティングにより言語の表現力を証明
- **性能の階層化**：まず動作させ、その後最適化する

## 四、コンパイル戦略三層設計

| 階層                   | バージョン | 入力                      | 出力                | 説明                   |
| ---------------------- | ---------- | ------------------------- | ------------------- | ---------------------- |
| L1: バイトコード       | v0.1+      | ソースコード (.yx)        | バイトコード (.yxb) | VM インタプリタ実行    |
| L2: セルフホスティング | v0.9+      | YaoXiang ソースコード     | バイトコード        | 自分を自分でコンパイル |
| L3: AOT                | v1.0+      | ソースコード/バイトコード | マシンコード        | ネイティブ性能         |

**バイトコード優先の理由**：

1. **REPL サポート**：入力コードを即時コンパイルし、対話型開発
2. **段階的コンパイル**：単一関数の変更はその部分のみ再コンパイルすればよい
3. **プラットフォーム非依存**：.yxb ファイルはプラットフォーム間で実行可能、対応するプラットフォームの VM のみ必要

## 五、依存関係戦略

**短期**：Rust ライブラリを呼び出して crates.io を再利用（Cargo 寄生）

**現在の依存関係**：

- 並行：parking_lot, crossbeam, rayon
- データ構造：indexmap, hashbrown, smallvec
- ネットワーク：tokio
- シリアライゼーション：serde, ron

**長期**：独自の標準ライブラリとパッケージマネージャを構築
