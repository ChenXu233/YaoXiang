# RFC-003：バージョン計画

> **拒否日**: 2026-06-01

## ⚠️ 拒否理由

**本 RFC は RFC 仕様に不符合のため、却下されました。**

### 問題分析

| 問題             | 説明                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| **文書タイプ錯誤** | RFC は「なぜこのような設計か」の意思決定文書であり、本文は「現在どこにいるか、どこへ行くか」のプロジェクト管理文書である |
| **設計意思決定の欠如** | 技術選択のトレードオフ分析がなく、代替案の比較がなく、設計理由がない                             |
| **過度な計画**     | 9つのバージョン（v0.1-v1.0）を計画しているが、1.5個しか完了しておらず、v0.3以降はすべて推測である   |
| **維持コスト高**   | 成功指標表には50個の状態があり、維持が困難である                                                 |
| **バージョン番号の混乱** | v0.8を飛ばしているが、説明がない                                                               |

### 正しい文書タイプ

本文書は RFC ではなく、**プロジェクトロードマップ（Roadmap）**として管理すべきです。ロードマップは事実と短期計画を記録し、RFC は設計意思決定を記録します。

## 要約

YaoXiang のバージョンリリース計画、v0.1 から v1.0 までのロードマップ。

**核心的な目標**：

1. **バイトコードコンパイル**：REPL と漸進的コンパイルをサポート
2. **ブートストラッピング (Bootstrap)**：YaoXiang で YaoXiang コンパイラを記述
3. **AOT コンパイル**：バイトコードをネイティブマシンコードにコンパイル

## 一、動機

### なぜバージョン計画が必要인가？

1. **プロジェクト管理**：目標を実行可能なマイルストーンに分解する
2. **ユーザーの期待**：ユーザーに言語の発展段階を理解させる
3. **リソース配分**：各段階の重点を明確にする
4. **リスク管理**：適時に問題を発見し方向性を調整する

### 核心的な設計意思決定

- **バイトコード優先**：まずインタープリタ実行を実装し、次に AOT を検討
- **漸進的デリバリー**：各バージョンには利用可能な機能がある
- **後方互換性**：v1.0 前の API は変更される可能性あり，但し事前に告知
- **ブートストラッピング検証**：ブートストラッピングにより言語の表現能力を証明
- **パフォーマンス層別化**：まず動作させ、次に最適化

## 四、コンパイル戦略三層設計

| 层级       | バージョン | 入力          | 出力          | 説明             |
| ---------- | ---------- | ------------- | ------------- | ---------------- |
| L1: バイトコード | v0.1+   | ソースコード (.yx) | バイトコード (.yxb) | VM インタープリタ実行 |
| L2: ブートストラッピング | v0.9+ | YaoXiang ソースコード | バイトコード | 自己コンパイル |
| L3: AOT    | v1.0+      | ソースコード/バイトコード | マシンコード | ネイティブパフォーマンス |

**バイトコード優先の理由**：

1. **REPL サポート**：入力コードを即座にコンパイルし、対話的開発
2. **漸進的コンパイル**：単一の関数を修正只需重新编译該部分のみを再コンパイルすればよい
3. **プラットフォーム非依存**：.yxb ファイルはクロスプラットフォームで実行可能で、対応するプラットフォームの VM のみ必要

## 五、依存関係戦略

**短期**：Rust ライブラリの呼び出しで crates.io を再利用（Cargo 寄生）

**現在の依存関係**：

- 並行：parking_lot, crossbeam, rayon
- データ構造：indexmap, hashbrown, smallvec
- ネットワーキング：tokio
- シリアライゼーション：serde, ron

**長期**：独自の標準ライブラリとパッケージマネージャを構築
