# RFC-027a: 終了検査の証明関数フォールバック

## 概要

RFC-027 の決定記録に予約された再審議条項を履行する：四種の自動戦略では終了証明をカバーできない**非構造的再帰**（gcd のような非直接的な減少、相互再帰）に対し、**証明関数のフォールバック**を提供する——測度と証明はどちらも通常の YaoXiang 関数であり、新たな構文はゼロ、型検査器が検証する。全自動優先原則は不変：自動戦略が依然として第一経路であり、ユーザの介入は Unproven の後にのみ発生する。

## 動機

### ホスト資格と改訂範囲

RFC-027 は子 RFC のスロットを予約していない（RFC-029 が 029a を予約するパターンとは異なる）。本子 RFC のホスト資格は、RFC-027 の決定記録そのものにある再審議条項に由来する：

> どの戦略によっても終了を証明できないループは、コンパイラが直接エラーを返す——これは厳格な安全哲学であり、欠陥ではない。**将来、四種の戦略でカバーできない現実的なシナリオ（学術的構成品ではない）が現れた場合、改めて議論する。**
> —— RFC-027 決定記録

本 RFC はまさにその「再審議」の正式な媒体である。これは既記録の決定を**覆すものではない**——条項自体が決定の一部であり、それを発動することは設計通りに決定が機能していることに他ならない——条項の予期された行使である。

RFC-027 への改訂範囲は正確に三箇所に限定される：

| 改訂点                                     | 原記録                                                   | 改訂後                                                                                                                                                                                                         |
| ------------------------------------------ | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| §7「半自動アノテーションの余地を残さない」 | 終了検査は完全閉鎖                                       | 「**アノテーション構文の**余地を残さない」に絞り込む——証明関数フォールバックはアノテーションではない（新たな構文位置を持たず、関数定義に付随せず）、「コンパイル時述語に新しいキーワードはない」と同一の世界観 |
| 決定記録「Unproven → 直接エラーを返す」    | 終了ドメインはフォールバックを持たない唯一の証明ドメイン | 「Unproven → 証明関数を提供可能」に変更——正当性ドメイン（述語 Unproven → 証明関数、RFC-027 §証明関数）の挙動と整合                                                                                             |
| §6.8 エラーメッセージ                      | 「解析可能なイテレーションパターンを使用してください」   | 「または測度関数と終了証明関数を提供してください」を追記                                                                                                                                                       |

**改訂しない**部分：四種の自動戦略の優先地位、全自動優先原則、厳格な安全哲学の残りの内容（Disproved は依然としてコンパイルエラー＋反例；正当性ドメインの挙動はゼロ変化）。

### 現在の問題（2026-09-14 実測、v0.7.14 以降の dev）

1. **TerminationChecker は構造的再帰しか証明できない**。`termination.rs` は現在 Phase
   1：戦略 3（有界増減）、再帰引数の直接的な減少（`factorial(n-1)`）、`for`
   ループの自然終了。戦略 1/2/4 は未実装（RFC-027 既定の拡張）。非構造的再帰は直接コンパイル失敗する：

   ```yaoxiang
   gcd: (a: Int, b: Int) -> Int = {
       if b == 0 { return a }
       return gcd(b, a % b)
   }
   ```

   再帰引数 `(b, a % b)`
   は引数の直接的な減少ではない——現在エラーを返し、イテレーションパターンへの書き換えを要求する。gcd は可読性を損なわずに「解析可能なイテレーションパターン」に書き換えられない；マージソートのパーティション、相互再帰（偶奇判定）、木走査も同様である。これらは現実的なアルゴリズムであり、学術的構成品ではない——**再審議条項の発動条件が成立する**。

2. **証明ドメインのフォールバックが非対称**。RFC-027 の正当性命題（`Positive(b)`、`IsMax`
   などの述語）が Unproven の時には証明関数のフォールバックがある；終了性は全ての証明ドメインの中で、Unproven 即ち行き止まりである唯一のドメインである。同一世界観において、この非対称に原則的な理由はない。

3. **インフラは既に整っている**。#292 は Z3 バックエンドを実際に接続した（`ConstExpr` → SMTLib →
   Unsat/Sat 判定の連鎖）。再帰呼び出し点の測度減少義務 `measure(args') < measure(args)`
   は一階線形算術の命題であり、まさにその連鎖で開通済みの決定可能フラグメントに収まる——同一のパイプラインを再利用し、新たなバックエンドを追加しない。

## 提案

### 中核設計

三つの概念、全てが「すべては YaoXiang 関数である」：

1. **測度関数**——通常のコンパイル時関数。引数は被測関数と同じシグネチャ、戻り値は `Int` または `Int`
   のタプル（辞書順）。アノテーションではなく、関数定義に付随せず、参照可能で単体テスト可能なファーストクラス関数である。
2. **終了命題 `Terminates(f, m)`**——コンパイラ組み込みの命題（ユーザ再定義不可）：「関数 `f` は測度
   `m` に関して終了する」。その義務はコンパイラが `f`
   の関数本体から自動生成する（詳細設計を参照）ため、純粋なライブラリの述語として表現することはできない。
3. **終了証明関数**——戻り型が `Terminates(f, m)` であるコンパイル時関数。二つの役割を持つ：測度 `m`
   を `f`
   に**明示的にバインド**する（唯一の発見と接続点であり、あらゆるアノテーション構文に取って代わる）；その関数本体は SMT で閉じきれない残余義務を discharge する（多くのシナリオでは空本体）。

### 例

```yaoxiang
# 正例一：非直接的な減少——gcd
gcd: (a: Int, b: Int) -> Int = {
    if b == 0 { return a }
    return gcd(b, a % b)
}

gcd_measure: (a: Int, b: Int) -> Int = { b }

# 空本体で十分：義務 a % b < b（ガード b ≠ 0）は SMT が直接閉じる
gcd_proof: () -> Terminates(gcd, gcd_measure) = { }
```

```yaoxiang
# 正例二：相互再帰——SCC ごとに義務を収集
is_even: (n: Int) -> Bool = { if n == 0 { return true }  return is_odd(n - 1) }
is_odd:  (n: Int) -> Bool = { if n == 0 { return false } return is_even(n - 1) }

nat: (n: Int) -> Int = { n }

is_even_proof: () -> Terminates(is_even, nat) = { }
is_odd_proof:  () -> Terminates(is_odd,  nat) = { }
```

```yaoxiang
# 負例：測度が厳密に減少しない
loop_forever: (n: Int) -> Int = { return loop_forever(n) }
# Terminates(loop_forever, nat) の義務 n < n は偽——
# SMT が Sat と判定 → 反例 → コンパイルエラー E4022（測度が厳密に減少しない、反例付き）
```

### 構文変化

**なし。** 本 RFC は新たな構文、キーワード、アノテーション位置を一切追加しない。既存の系譜との対照：

| 世代              | ユーザ側表現                                 | 構文キャリア             |
| ----------------- | -------------------------------------------- | ------------------------ |
| RFC-022（廃止済） | `//! decreases: n` コメントアノテーション    | コメント規約、型検査なし |
| RFC-027 現行      | なし（全自動、証明できなければエラーを返す） | ——                       |
| 本 RFC            | 測度＋証明、いずれも通常の関数               | 関数定義構文そのもの     |

## 詳細設計

### 義務生成

関数 `f` と測度 `m`
に対し、コンパイラは二組の一階線形算術義務を生成し、再帰呼び出し点（SCC 内の関数間呼び出しを含む）ごとに展開する：

1. **整礎性**：`m(args) >= 0`——測度は自然数上にあり、引数型の境界から導出；導出できない場合は残余義務に入る。
2. **厳密な減少**：各呼び出し点 `m(callee_args) < m(caller_args)`
   を、**パスガード**下で判定する（ガードはその呼び出し点が属する分岐条件から得られ、RFC-009a のパス条件収集を再利用）。

**辞書順の展開**：`m` がタプル `(m₁, …, mₖ)`
を返す場合、義務は辞書順比較に従って選言鎖に展開される——`(m₁' < m₁) ∨ (m₁' == m₁ ∧ m₂' < m₂) ∨ …`。展開は義務生成側で行われ、SMT 側は線形フラグメントを保持し、解法器の辞書順ネイティブサポートに依存しない。

**測度関数自身の有界性**：`m`
はコンパイル時評価可能（定数畳み込み）または構造的再帰として証明可能でなければならない——終了問題を別の未証明関数に再帰的に押し付けることを禁止する（無限回帰防止）。病的測度は既存の E4012（定数再帰過深）と構造検査で阻止される。

### 判定パイプライン

`TerminationChecker`
を五段に拡張する。前三段は RFC-027 現行/既定パスであり、本 RFC は後ろ二段のみを追加する：

```
1. 構造的再帰が直接証明可能（現行ロジック、回帰なし）
2. 自動測度合成：四戦略を順次試行（戦略 1/2/4 は RFC-027 計画通り実装、本 RFC はインタフェースを予約）
3. 合成成功 → 義務の SMT 判定 → Proved
4. 合成失敗（Unproven）→ 証明関数を探索（戻り型が Terminates(f, _) のもの）：
     a. 発見 → その測度 m で義務を生成 → SMT 判定
     b. 残余義務 → 証明関数本体内でアサーションとして検証（正当性ドメインの証明関数プロトコルと同じ）
5. 証明関数なし / 証明関数の義務も失敗 → コンパイルエラー（E4021 / E4022）
```

**証明関数の発見スコープ**：同モジュール内で定義されたもの、または `import`
で見えるエクスポート済みのものである——既存の可視性規則に従い、グローバルな魔法的探索は行わない。同一
`f` に対して複数の候補 `Terminates(f, _)`
がある場合、義務が全て緑になる最初のものを採用し、複数とも失敗した場合は最初のものの反例を報告する（決定論的順序：宣言順）。

**`Terminates` の組み込み性宣言**：述語体系に対する特例である——その「アサーション」はコンパイラが
`f`
の関数本体から生成するため、RFC-027 の述語構文では表現できない。これは意図的な唯一の組み込み命題であり、理由はトレードオフ節に記録する。

### エラーコード

E4xxx 証明失敗ファミリに整合（E4018 精緻化述語違反、E4020 証明関数を要する）：

| 提案コード | 名称                   | トリガ                                                            |
| ---------- | ---------------------- | ----------------------------------------------------------------- |
| E4021      | 終了を証明できない     | 自動合成失敗かつ証明関数なし（`Terminates` 証明関数の提供を促す） |
| E4022      | 測度が厳密に減少しない | 証明関数の義務が SMT で Sat と判定（反例入力を添付）              |

最終番号は実装時の RFC-013 登録テーブル実態に従う（セグメント正当性は build.rs スレッショルドで保証）；W1080（コンパイル時証明の降格）のセマンティクスは本 RFC とは無関係であり、不動。

### 後方互換性

- これまでコンパイル成功していたプログラム：挙動のゼロ変化（前三段のパイプラインがフォールバックに先立って実行される）。
- これまでコンパイル失敗していたプログラム：測度と証明関数を追記すれば通過できる——これは再審議条項が授権する厳格化の緩和であり、「元からエラーを返していた」プログラムにのみ影響する。
- 既存のテストコーパス（構造的再帰の正例、非構造の負例）の期待出力は不変。非構造の負例のエラーコード/メッセージのみ新コードに従って更新される。

## トレードオフ

### 利点

- **新たな構文ゼロ**：Dafny の `decreases`
  インラインアノテーションと対照的に、本設計は構文空間を占有しない；測度は単体テスト可能なファーストクラス関数である。
- **証明ドメイン挙動の整合**：終了ドメインに正当性ドメインと一貫した Unproven フォールバックを補完する。「厳格な安全哲学」を「証明できなければ拒否する」から「証明できなければプログラマに委ねる」へと進化させる——RFC-027 全体の世界観と一致する。
- **インフラの再利用**：義務は線形算術であり、#292 で開通済みのパイプラインを通る；新たなバックエンド、新たな判定ロジックファミリはなし。
- **条項履行がそのままガバナンス**：再審議を子 RFC 形式で記録し、決定記録を監査可能に保つ。

### 欠点とリスク

- **記述負担**：二点セット（測度＋証明関数）は単一のインラインアノテーションより冗長。許容する——フォールバックは低頻度経路であり、その代わり測度が再利用可能でテスト可能になる。
- **`Terminates`
  は唯一の組み込み命題**：「述語は全てユーザ定義可能」という純粋性から逸脱する。理由：義務は関数本体の内部構造に由来し、原理的に純粋なライブラリの述語では表現できない；これはシステムが必要とする最小限の組み込み面である。
- **戦略 1/2/4 未実装期間中、フォールバックが早すぎる可能性**：Phase
  1 の自動面が狭く、より多くの関数が証明関数の経路に落ちる。緩和策：四戦略実装後、フォールバック面は自動的に縮減する；証明関数の先行的記述は無駄ではない——戦略アップグレード後も、残余義務の discharge キャリアとして継続する。
- **反例の品質**：Sat 反例は非線形ガードに対し直感的でない可能性がある。既知の制限事項として記録し、反例提示は RFC-013 診断メッセージ規範に従って反復する。

## 非目標

- 新たな構文/キーワード/アノテーション位置を追加しない。
- 測度自動合成の汎用化拡張を行わない（四戦略は RFC-027 既定計画を維持し、射程外はフォールバックへ）。
- RFC-009a の借用命題と統合解法を行わない（それぞれ独立判定、バックエンド共有）。
- 依存型レベルの totality 検証を行わない。
- 測度推論を実装しない（関数本体からの測度推測は戦略 1/2/4 の射程であり、本 RFC は明示的な測度のみを消費する）。
