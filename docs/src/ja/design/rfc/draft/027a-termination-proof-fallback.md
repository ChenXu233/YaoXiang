# RFC-027a: 終了検査の証明関数フォールバック

## 要約

RFC-027 決定記録の「再討議」条項を履行する：四種類の自動戦略が終止証明をカバーできない**非構造再帰**（gcd 類の間接的でない減少、相互再帰）に対して、**証明関数フォールバック**を提供する——測度と証明はいずれも通常の YaoXiang 関数であり、新たな構文はゼロ、型検査器が検証する。本機構の位置付けは**精化型証明プロトコルの一応用**である。証明側は新たな機構ゼロ（RFC-027 既存の Unproven フォールバックチャンネルをそのまま再利用）で、新規追加されるのはコンパイラ側の呼び出し点義務生成と命題アンカーのみのみ。完全自動優先原則は不変：自動戦略は依然として第一経路であり、利用者の介入は Unproven の後にのみ発生する。

## 動機

### ホスト資格と改訂範囲

RFC-027 はサブ RFC スロットを预留していなかった（RFC-029 が 029a を预留したパターンとは異なる）。本サブ RFC のホスト資格は、RFC-027 決定記録自身の「再討議」条項に由来する：

> どの戦略によっても終了を証明できないループは、コンパイラが直接エラーを出す——これはハードセーフティ哲学であり、欠陥ではない。**将来的に実際のシナリオ（非学術的構成）で四戦略がすべてカバーできないアルゴリズムが現れた場合、再討議する。**
> —— RFC-027 決定記録

本 RFC はまさにその「再討議」の正式な载体である。これは記録された決定を**覆すものではない**——条項自体が決定の一部であり、それを発動することは決定が設計通りに機能していることに他ならない。条項の予期された行使である。

RFC-027 への改訂範囲は正確に三箇所に限定される：

| 改訂点                                     | 元の記録                                                 | 改訂後                                                                                                                                                                                               |
| ------------------------------------------ | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| §7「半自動アノテーションに余地を作らない」 | 終了検査は完全閉鎖                                       | 「**アノテーション構文**の余地はない」に絞り込む——証明関数フォールバックはアノテーションではない（新たな構文位置がなく、関数定義に付随しない）、「コンパイル時述語に新キーワードがない」と同じ世界観 |
| 決定記録「Unproven → 直接エラー」          | 終了ドメインは唯一のフォールバックなしの証明ドメイン     | 「Unproven → 証明関数を提供可能」に変更——正当性ドメイン（述語 Unproven → 証明関数、RFC-027 §証明関数）の挙動と整合                                                                                   |
| §6.8 エラーメッセージ                      | 「コンパイラが解析可能な反復パターンを使用してください」 | 「または測度関数と終了証明関数を提供してください」を追記                                                                                                                                             |

**改訂しない**部分：四種類の自動戦略の優先地位、完全自動優先原則、ハードセーフティ哲学の残る内容（Disproved は依然としてコンパイルエラー + 反例；正当性ドメインの挙動はゼロ変化）。

### 現状の問題（2026-09-14 実測、v0.7.14 以降 dev）

1. **TerminationChecker は構造再帰のみ証明可能**。`termination.rs` は現在 Phase
   1：戦略 3（有界増加/減少）、再帰引数の直接的な減少（`factorial(n-1)`）、`for`
   ループは自然に終了する。戦略 1/2/4 は未着地（RFC-027 既定の拡張）。非構造再帰は直接コンパイル失敗となる：

   ```yaoxiang
   gcd: (a: Int, b: Int) -> Int = {
       if b == 0 { return a }
       return gcd(b, a % b)
   }
   ```

   再帰引数 `(b, a % b)`
   は引数の直接的な減少ではない——現在はエラーを出し、反復パターンへの書き換えを要求する。gcd は「解析可能な反復パターン」に可読性を損なわずに書き換えられない。マージソートのパーティション、相互再帰（偶数/奇数判定）、木走査も同様。これらは実際のアルゴリズムであり、学術的構成ではない——**再討議条項の発動条件が成立する**。

2. **証明ドメインのフォールバックが非対称**。RFC-027 の正当性命題（`Positive(b)`、`IsMax`
   などの述語）が Unproven の場合は証明関数フォールバックがある；終了性はすべての証明ドメインの中で Unproven すなわちデッドエンドの唯一のドメインである。同一世界観において、この非対称に原則的な理由はない。

3. **インフラは既に整っている**。#292 は Z3 バックエンドを実接続済み（`ConstExpr` → SMTLib →
   Unsat/Sat 判定リンク）。再帰呼び出し点の測度減少義務 `measure(args') < measure(args)`
   は一階線形算術命題であり、まさにこのリンクで打通された決定可能フラグメントに該当する——同じパイプラインを再利用し、新たなバックエンドは追加しない。

## 提案

### 中核設計

**位置付け：本 RFC は証明機構を新規追加するものではなく、精化型証明プロトコルの一応用である。**
RFC-027 はすでに「証明関数は YaoXiang 関数であり、その戻り型はアサートされる命題である」を確立している——命題は述語適用であり、述語適用は精化型である。終了証明の人間側は終始この既存チャンネルを通る（Unproven
→ 証明関数を書く → 型検査器が検証 →
witness 消去）、正当性ドメインと完全に同じプロトコルである。新規追加面は三件事に収斂する：

1. **測度関数**——通常のコンパイル時関数で、入力は被測定関数と同じシグネチャ、戻り型は `Int` または
   `Int`
   のタプル（辞書式順序）。アノテーションではなく、関数定義に付随せず、参照可能・単体テスト可能なファーストクラス関数である。
2. **呼び出し点義務生成**——コンパイラが `f`
   の関数本体から各再帰呼び出し点の減少義務を抽出する。これが唯一新規のコンパイラロジックである：呼び出し点の実引数は関数本体内にあり、義務（意味的制約）はコンパイラが代筆せざるを得ず、人間が代筆することはできない——さもないと証明が実際のコードに束縛されなくなる（設計哲学第 3 条を参照）。
3. **終了命題
   `Terminates(f, m)`**——**コンパイラが本体を代筆する精化述語**：その「制約内容」は上述の義務集合であり、そのシグネチャは単に
   `(f, m)`
   を結びつけるアンカーにすぎない。内蔵の必要性はこの点のみであり、機構的には何も新しくない。関数と測度の双方が型に入り、測度のみが入るのではない：相互再帰において
   `is_even`/`is_odd` のシグネチャは同じで、測度のみで発見すると曖昧さが生じる（例を参照）。

証明関数の三つの役割は位置付けから自然に導出される：測度 `m` を `f`
に明示的に束縛する（発見アンカー、すべてのアノテーション構文に取って代わる）；残余義務に discharge 位置を提供する（本体 = 証明空間）；全称量化的に
`f` の引数名を保持する（本体中で `a`、`b`
を参照して事実を記述可能）。構文の落点ごとの詳細は「詳細構文」を、走査全体は「例」を参照。

### 例

#### エンドツーエンド詳解：gcd

```yaoxiang
-- 被測定関数（正当性ドメインは通常通り：引数精化、ガード、再帰呼び出し）
gcd: (a: Int, b: NonNegative(b)) -> Int = {
    if b == 0 { return a }
    return gcd(b, a % b)
}

-- 測度：通常の関数（単体テスト可能、再利用可能）
gcd_measure: (a: Int, b: Int) -> Int = { b }

-- 証明関数：空本体——すべての義務は SMT が自動閉合
gcd_proof: (a: Int, b: Int) -> Terminates(gcd, gcd_measure) = { }
```

コンパイラが `gcd_proof` を処理する全過程：

1. **シグネチャ検証**：証明関数の引数は**基本型**について `gcd`
   の仮引数と一つずつマッチする（`Int`、`Int`）。仮引数精化（`b >= 0`）は証明関数のシグネチャでは繰り返さない——すでにコンパイラが義務コンテキストとして保持しており、証明関数本体と義務はそのコンテキストで検証される。
2. **整礎性義務**：`gcd_measure(a, b) >= 0`、すなわち `b >= 0`——仮引数精化 `NonNegative(b)`
   から直接導出。測度の境界に新たな機構は不要、それは引数の精化制約そのものである（精化型の意味論的条件が整礎性において実現される）。
3. **呼び出し点義務生成**：唯一の再帰呼び出し点 `gcd(b, a % b)`、経路ガード
   `b != 0`、`gcd_measure(b, a % b) < gcd_measure(a, b)` を生成；測度本体を代入して展開すると
   `a % b < b`。
4. **SMT 判定**：義務の否定 `b != 0 ∧ a % b >= b`
   が充足不能であることを検証——線形算術 + モジュロ公理、ミリ秒級 → Proved。
5. **受理**：本体が空、残余的に discharge すべき義務はない。`gcd`
   の終了が証明される；測度と証明関数は witness 消去に従い、ランタイムバイナリには含まれない。

#### 非空本体：残余義務による既証明補題の参照

呼び出し点の減少がコンパイラに見えない事実に依存する場合（次の例の `step`
の本体は依存モジュール内にあり、義務生成にとってはブラックボックス）、人間はその事実を**既証明述語の参照**として本体に書く——裸の式であり、Assert 文ではない：

```yaoxiang
step: (n: Int) -> Int = { ... }

loop_x: (n: NonNegative(n)) -> Void = {
    if n == 0 { return () }
    return loop_x(step(n))
}

x_measure: (n: Int) -> Int = { n }

-- step 定義モジュール内でエクスポートされた既証明後置条件（正当性ドメイン、通常の述語、定義箇所で証明済み）：
step_decreases: (n: Int) -> Type = { n >= 1 ==> step(n) < n }

-- 終了証明 = この補題の参照（既証明述語の参照 = その確立された証明の適用、Curry-Howard）：
x_proof: (n: Int) -> Terminates(loop_x, x_measure) = {
    step_decreases(n)
}
```

検証過程：`loop_x` が存在するモジュール内で義務 `x_measure(step(n)) < x_measure(n)`（ガード
`n != 0`、コンテキスト `n >= 0`）を独立に閉合できない → 非空本体を発見 → アサーション
`step_decreases(n)`
が既証明述語のインスタンスであることを検証、検証成功 → 補題として残余義務を閉合する。本体内で直接
`step(n) < n`
と空書きすれば、検証器は誠実に Unproven を報告する——事実はトレース可能な既証明ソースから来なければならない。

#### 相互再帰：SCC による義務収集

```yaoxiang
is_even: (n: NonNegative(n)) -> Bool = { if n == 0 { return true }  return is_odd(n - 1) }
is_odd:  (n: NonNegative(n)) -> Bool = { if n == 0 { return false } return is_even(n - 1) }

nat: (n: Int) -> Int = { n }

is_even_proof: (n: Int) -> Terminates(is_even, nat) = { }
is_odd_proof:  (n: Int) -> Terminates(is_odd, nat) = { }
```

義務は SCC ごとに収集され、関数間エッジの義務は
`m_callee(callee_args) < m_caller(caller_args)`——ここでは `nat(n - 1) < nat(n)`、ガード
`n != 0`、両関数はそれぞれ閉ループする。両関数のシグネチャは同じで、測度のみで発見するとターゲットを区別できない——これが
`Terminates(f, m)` の二引数の直接的な理由である。

#### 反例：測度が厳密に減少しない

```yaoxiang
loop_forever: (n: Int) -> Int = { return loop_forever(n) }
loop_proof: (n: Int) -> Terminates(loop_forever, nat) = { }
```

義務 `nat(n) < nat(n)`、すなわち `n < n`、その否定は常に充足可能（Sat、モデル
`n = 0`）→ コンパイルエラー **E4022**（測度が厳密に減少しない）、反例は `loop_proof`
を指す。`loop_proof` を削除すると、自動戦略が失敗し証明関数がない →
**E4021**（終了を証明できない、`Terminates` 証明関数の提供を促す）。

### 構文変化

**なし。** 本 RFC はいかなる構文、キーワード、アノテーション位置も追加しない。既存系列との対照：

| 世代                | ユーザ側表現                              | 構文载体                 |
| ------------------- | ----------------------------------------- | ------------------------ |
| RFC-022（廃止済み） | `//! decreases: n` コメントアノテーション | コメント規約、型検査なし |
| RFC-027 現行        | なし（完全自動、証明できなければエラー）  | ——                       |

## 設計哲学：発見と検証の分離

本 RFC の機構選択は一つの原理から導出される：**終了検査 = 証人発見 + 証人検証、両者の難易度は著しく異なり、分離しなければならない。**

| 役割                                                                     | 担当                                                                   | 難易度                                                                               |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 発見（測度と証明の総合）                                                 | 四つの自動戦略（機械、制限テンプレート）または人間の証明関数（無制限） | 一般に**決定不能**（停止問題に帰着）——常に測度を見つけられるアルゴリズムは存在しない |
| 検証（固定された候補について各呼び出し点で `m(args') < m(args)` を照合） | SMT（RFC-009a パイプライン）                                           | 決定可能（一階線形算術）、ミリ秒級                                                   |

「決定不能に探し、決定可能に查す」——構造的に P/NP の witness/verifier 分離と同型であるが、それよりさらに極端である：発見側は困難なのではなく、数学的に常に解があるとは限らない；検証側は固定された候補に対して完全に機械的である。RFC-027 の「誠実に Unproven を報告する」と人間によるフォールバックは、工学的な妥協ではなく、この境界の直接的な帰結である。

三つの帰結が本 RFC の設計制約を構成する：

1. **証明者は信頼できなくても構わない。**
   soundness はすべて検証器に宿る：測度やアサーションが間違っていれば、SMT が Sat と判定し、E4022 が反例を添えて差し戻す——人間は証明できないだけで、誤って証明することはできない。Disproved は依然として構成的である（反例モデルを与える）：検証器は NP 検証器より半件事多く、反証にも証拠を与える。
2. **洞察は検証可能な成果物として凍結される。**
   人間の知的労働が一度証明関数として書かれると、それは機械が検査可能な証明書となり、毎回のコンパイルで再検証され、永続的にリグレッションを防ぐ（proof-carrying）。
3. **命題はコンパイラに帰し、証明は人間に帰す。**
   義務（「何が証明完了とみなされるか」）はコンパイラが関数本体から生成しなければならない；人間に制約まで書かせると、自分の検収基準を自分で書くことになり、証明書は実際に書かれたコードを証明しなくなる。

四つの自動戦略はここから統一的な解釈を得る：それらは**証人総合の制限テンプレート列**である——自動測度合成は文献上、制約求解下のテンプレート列挙であり（線形ランク関数合成が先例）。戦略拡張 = テンプレートの拡張；テンプレート外の発見は人間が代行；検証器は常に同じ SMT である。「測度推論を行わない」非目標の理論的形態もここにある：汎用測度推論は発見の決定不能側に属し、その境界（約束）を約定することはできても、その完全性を約束することはできない。

## 詳細設計

### 詳細構文

証明関数には専用の構文がない——それは「コンパイル時述語定義」を別用法で使うだけである。三つの落点を一つずつ固定する：

**戻り型：述語適用、実引数は関数参照。** `Terminates(gcd, gcd_measure)`
は既存の型位置での精化適用（`f(x: Positive(x))`、`-> (result: IsMax(T, arr, result))`）と同型；関数名は名前束縛による通常の束縛（RFC-010）であり、既存の述語実引数ルール「リテラル、変数（名前束縛）、型適用」の中に収まる。唯一のルールレベルの補足：E1092 実引数形態判定に「**関数参照はコンパイル時定数形態に属する**」を追加——ルール文面を改めるのみで、文法は変えない。

**引数：`f` の基本型をミラー、全称量化。** 引数名と基本型は `f`
の仮引数と一つずつマッチし、マッチしなければコンパイルエラー（E1093 同族を再利用、または登録表に従い新規追加、実装時に決定）。仮引数精化は繰り返さない——精化とガード仮定はコンパイラが義務コンテキストとして注入する。全称量化はまさに述語定義自身の引数意味論である（`Positive: (x: Int) -> Type = { x > 0 }`
の `x` 同样に全称量化される）。ゼロ引数形式は否决：残余義務が `f`
の引数名を参照し、本体内で名前が書けなければならない。

**本体：証明空間、裸のブール式。** 述語定義本体 `{ x > 0 }`
と同じプロトコル——本体内の各項目は True とアサートされる裸の式。空本体は合法であり、多くのシナリオでそうなる（すべての義務が SMT によって閉合される）；非空アサーションは検証後に補題として残余義務に供給される；アサーションの合法なソースは既証明述語の適用である（「非空本体」の例を参照）。

**発見と束縛。** コンパイラは自動合成に失敗した `f`
について、同モジュールと可視インポート内で戻り型が `Terminates(f, _)`
の形の関数を走査する；戻り型で発見し、名前には依存しない（`f_proof`
は自然な慣習にすぎない）。複数の候補がある場合、義務がすべてグリーンとなる最初のものを取る（宣言順）；すべて失敗すれば最初の反例を報告する。前方参照は合法：発見は検査段階で発生し、宣言順に依存しない。

**ランタイム表現。** 証明関数は純粋なコンパイル時実体であり、RFC-027
CompileTime パターンの witness 消去に従う——測度と証明関数のどちらもランタイムバイナリには含まれない。

### 義務生成

関数 `f` と測度 `m`
に対し、コンパイラは二組の一階線形算術義務を生成し、各再帰呼び出し点（SCC 内の関数間呼び出しを含む）で展開する；関数間エッジの義務は
`m_callee(callee_args) < m_caller(caller_args)`
であり、メンバーが同一測度を共有する場合は同一測度減少に退化する：

1. **整礎性**：`m(args) >= 0`——測度は自然数上にあり、引数型境界から導出；導出できなければ残余義務に進む。
2. **厳密減少**：各呼び出し点 `m(callee_args) < m(caller_args)`
   を**経路ガード**下で判定（ガードはその呼び出し点が所在する分岐条件から取得、RFC-009a 経路条件収集を再利用）。

**辞書式順序への展開**：`m` がタプル `(m₁, …, mₖ)`
を返す場合、義務は辞書式順序比較として析出チェーンに展開される——`(m₁' < m₁) ∨ (m₁' == m₁ ∧ m₂' < m₂) ∨ …`。展開は義務生成側で完了し、SMT 側は線形フラグメントを保ち、求解器の辞書式順序ネイティブサポートに依存しない。

**測度関数自身の有界性**：`m`
はコンパイル時評価可能（定数畳み込み）または構造再帰で証明可能でなければならない——終了問題を別の未証明関数に再帰的に押し付けることを禁止する（無限回帰を防ぐ）。病的な測度は既存の E4012（定数再帰過深）と構造検査によって阻止される。

### 判定パイプライン

`TerminationChecker`
を五段階に拡張する、前三段階は RFC-027 現行/既定経路であり、本 RFC が追加するのは後二段階のみ：

```
1. 構造再帰が直接証明可能（現行ロジック、リグレッションなし）
2. 自動測度合成：四戦略を順に試行（戦略 1/2/4 は RFC-027 計画に従って着地、本 RFC はインタフェースを预留）
3. 合成成功 → 義務を SMT で判定 → Proved
4. 合成失敗（Unproven）→ 証明関数を検索（戻り型が Terminates(f, _) の形）：
     a. 発見 → その測度 m で義務を生成 → SMT で判定
     b. 残余義務 → アサーションとして証明関数本体内で検証（正当性ドメインの証明関数プロトコルと同じ）
5. 証明関数なし / 証明関数の義務も失敗 → コンパイルエラー（E4021 / E4022）
```

**証明関数の発見ドメイン**：同モジュール内定義、または `import`
で見えるエクスポート——既存の可視性ルールに従い、グローバルな魔法的検索は行わない。同一 `f`
に対する複数の候補 `Terminates(f, _)`
は、義務がすべてグリーンとなる最初のものを取る；複数とも失敗すれば最初の反例を報告する（決定的な順序：宣言順）。

**`Terminates` の内蔵性宣言**：述語体系に対する特例である——その「アサーション」はコンパイラが `f`
の関数本体から生成し、RFC-027 の述語構文で表現できない。これは意図的な唯一の組み込み命題であり、その理由はトレードオフ節に記録されている。

### エラーコード

E4xxx 証明失敗ファミリに整合（E4018 精化述語違反、E4020 証明関数を必要とする）：

| 提案コード | 名称                   | 発動条件                                                              |
| ---------- | ---------------------- | --------------------------------------------------------------------- |
| E4021      | 終了を証明できない     | 自動合成が失敗し、証明関数がない（`Terminates` 証明関数の提供を促す） |
| E4022      | 測度が厳密に減少しない | 証明関数の義務が SMT によって Sat と判定された（反例入力を添付）      |

### 後方互換性

- これまでコンパイル成功していたプログラム：挙動はゼロ変化（前三段階パイプラインがフォールバックに先行実行される）。
- これまでコンパイル失敗していたプログラム：測度と証明関数を補えば通過可能——これは再討議条項が授权した「厳格化」の緩和であり、影響を受けるのは「元からエラーだった」プログラムのみである。
- 既存テストコーパス（構造再帰の正例、非構造の負例）の期待出力は変わらず、非構造の負例のエラーコード/メッセージのみ新コードに従って更新される。

## トレードオフ

### 利点

- **新構文ゼロ**：Dafny の `decreases`
  インラインアノテーションと対照的に、本設計は構文空間を占有しない；測度は単体テスト可能なファーストクラス関数である。
- **証明ドメイン挙動の整合**：終了ドメインに正当性ドメインと一貫した Unproven フォールバックを補う。「ハードセーフティ哲学」は「証明できなければ拒否」から「証明できなければプログラマに渡す」へと進展——RFC-027 全体の世界観と一致する。
- **インフラの再利用**：義務は線形算術であり、#292 で接通されたパイプラインを通る；新バックエンドなし、新判定ロジックファミリなし。
- **条項履行がそのままガバナンス**：再討議がサブ RFC 形式で痕跡を残し、決定記録は監査可能を維持する。

### 欠点とリスク

- **記述負担**：二点セット（測度 + 証明関数）は単一インラインアノテーションより啰嗦。ただし受け入れる——フォールバックは低頻度経路であり、引き換えに測度が再利用可能でテスト可能になる。
- **`Terminates`
  はコンパイラが本体を代筆する唯一の述語**：「述語本体はすべてユーザが書ける」という純粋性からの逸脱。理由：呼び出し点実引数は関数本体内にあり、ライブラリ述語は原理上参照できない；組み込み面は命題名一つに収斂し、機構的新規追加はゼロ（中核設計と設計哲学を参照）。
- **戦略 1/2/4 が未着地の間、フォールバックが早すぎる可能性**：Phase
  1 の自動面が狭く、より多くの関数が証明関数経路に落ちる。緩和：四戦略の着地後、フォールバック面は自動的に縮小する；証明関数を先行することは無駄ではなく、戦略アップグレード後も残余義務の discharge 载体として機能し続ける。
- **反例の品質**：Sat 反例は非線形ガードに対して直感的でない可能性がある。既知の制限として記録し、反例提示は RFC-013 診断メッセージ規範に従って反復する。

## 非目標

- 構文/キーワード/アノテーション位置を新規追加しない。
- 測度自動合成の汎用化拡張を行わない（四戦略は RFC-027 既定計画を維持、射程外はフォールバックへ）。
- RFC-009a と命題聯合求解を共用しない（独立判定、バックエンド共有）。
- 依存型レベルの totality 検証を行わない。
- 測度推論を実装しない（関数本体からの測度推測は戦略 1/2/4 の射程に属し、本 RFC は明示的な測度のみを消費する——設計哲学末段の理論的境界を参照）。
