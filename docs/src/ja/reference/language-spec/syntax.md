# 構文仕様

このドキュメントでは、YaoXiang プログラミング言語の構文仕様を定義します。字句構造、構文規則、演算子の優先順位を含みます。

---

## 第一章：字句構造

### 1.1 ソースファイル

YaoXiang のソースファイルは UTF-8 エンコーディングを使用しなければなりません。ソースファイルの拡張子は通常
`.yx` です。

### 1.2 トークンの分類

| 種別       | 説明                           | 例                        |
| ---------- | ------------------------------ | ------------------------- |
| 識別子     | 文字またはアンダースコアで開始 | `x`, `_private`, `my_var` |
| キーワード | 言語の定義済み予約語           | `Type`, `pub`, `use`      |
| リテラル   | 固定値                         | `42`, `"hello"`, `true`   |
| 演算子     | 演算記号                       | `+`, `-`, `*`, `/`        |
| 区切り子   | 構文の区切り記号               | `(`, `)`, `{`, `}`, `,`   |

### 1.3 キーワード

YaoXiang は少数のキーワードのみを定義します：

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

これらのキーワードは任意の文脈で特別な意味を持ち、識別子として使用することはできません。

### 1.4 予約語

YaoXiang の「予約語」は 3 つの層に分かれており、パーサ (parser) と型検査器 (type
checker) が異なる段階で識別します：

#### 1.4.1 リテラル予約語

パーサが独立したトークンとして持つリテラル識別子は、通常の識別子として使用できません：

| 識別子  | 所属する型 | 説明                                                                                           |
| ------- | ---------- | ---------------------------------------------------------------------------------------------- |
| `Type`  | —          | メタ型のキーワード                                                                             |
| `true`  | Bool       | ブールの真値                                                                                   |
| `false` | Bool       | ブールの偽値                                                                                   |
| `void`  | Void       | Void リテラル (Unit 値)。小文字の `void` は値リテラル；大文字の `Void` は型名（§1.4.3 参照）。 |

#### 1.4.2 コンストラクタ式

以下のコンストラクタは、パターンマッチと式の文脈でパーサによって認識されます：

| コンストラクタ | 所属する型 | 説明                                |
| -------------- | ---------- | ----------------------------------- |
| `some(T)`      | Option     | Option の値バリアントコンストラクタ |
| `ok(T)`        | Result     | Result の成功バリアント             |
| `err(E)`       | Result     | Result のエラーバリアント           |

#### 1.4.3 組み込み型名

以下の型名は型検査器にあらかじめ登録されており、インポートなしでも型の位置で使用できます。パーサはこれらを通常の識別子として扱います——**予約語ではないため、ローカルバインディングでシャドウイング可能です（推奨されません）**。

| 型名     | 論理的対応  | 説明                                                                                                                                  |
| -------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤ (真/Unit) | ゼロフィールドの積型で、ちょうど 1 つの居住者を持つ（`void` リテラル、§1.4.1 参照）                                                   |
| `Never`  | ⊥ (偽/空型) | ゼロバリアントの和型で、居住者がゼロ。`Never` 値を生成する式は存在しない。すべての `T` に対して `Never <: T` が成立する（爆発原理）。 |
| `Int`    | —           | 符号付き整数                                                                                                                          |
| `Float`  | —           | 浮動小数点数                                                                                                                          |
| `Bool`   | —           | ブール値：`true` / `false`                                                                                                            |
| `Char`   | —           | Unicode 文字                                                                                                                          |
| `String` | —           | 文字列                                                                                                                                |

### 1.5 識別子

識別子は文字またはアンダースコアで始まり、後続の文字は英数字またはアンダースコアです。識別子は大文字と小文字を区別します。

特別な識別子：

- `_` はプレースホルダとして使用し、値を無視することを示す
- アンダースコアで始まる識別子はプライベートメンバーを示す

### 1.6 リテラル

#### 1.6.1 整数

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 浮動小数点数

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 文字列

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 コレクション

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Set         ::= '{' Expr (',' Expr)* '}'
```

#### 1.6.5 リスト内包表記

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

#### 1.6.6 メンバー検査

```
Membership  ::= Expr 'in' Expr
```

### 1.7 コメント

```
// 単一行コメント

/* 複数行コメント
   複数行にまたがることができる */
```

### 1.8 インデント規則

コードは 4 つのスペースでインデントしなければなりません。Tab 文字の使用は禁止されています。これは強制的な構文規則です。

## 第二章：構文規則

### 2.1 式の分類

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 演算子の優先順位

| 優先順位 | 演算子                      | 結合規則 |
| -------- | --------------------------- | -------- |
| 1        | `()` `[]` `.` `?`           | 左から右 |
| 2        | `as`                        | 左から右 |
| 3        | 単項前置 `!` `-` `+`        | 右から左 |
| 4        | `*` `/` `%`                 | 左から右 |
| 5        | `+` `-`                     | 左から右 |
| 6        | `..`                        | 左から右 |
| 7        | `<<` `>>`                   | 左から右 |
| 8        | `&` `\|` `^`                | 左から右 |
| 9        | `==` `!=` `<` `>` `<=` `>=` | 左から右 |
| 10       | `and` `or`                  | 左から右 |
| 11       | `if...else`                 | 右から左 |
| 12       | `=` `+=` `-=` `*=` `/=`     | 右から左 |

> **単項前置演算子**（`!` `-`
> `+`）は強い結合を持ちます：呼び出しとメンバーアクセスより低く、すべての二項演算子より高い。したがって
> `!a == b` ≡ `(!a) == b` (Zig 風のセマンティクス)；`!`
> は純粋な単項演算であり、短絡制御フローには参加せず、 `and`/`or`
> キーワード (短絡) とは直交します (RFC-010 が権威的な定義)。

### 2.3 関数呼び出し

```
FnCall      ::= Expr '(' ArgList? ')'
ArgList     ::= Expr (',' Expr)* (',' NamedArg)* | NamedArg (',' NamedArg)*
NamedArg    ::= Identifier ':' Expr
```

### 2.4 メンバーアクセス

```
MemberAccess::= Expr '.' Identifier
```

### 2.5 インデックスアクセス

```
IndexAccess ::= Expr '[' Expr ']'
```

### 2.6 型変換

```
TypeCast    ::= Expr 'as' TypeExpr
```

### 2.7 条件式

```
IfExpr      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 2.8 パターンマッチ

```
MatchExpr   ::= 'match' Expr '{' MatchArm+ '}'
MatchArm    ::= Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
Pattern     ::= Literal
              | Identifier
              | Wildcard
              | StructPattern
              | TuplePattern
              | EnumPattern
              | OrPattern
```

### 2.9 ブロック式

```
Block       ::= '{' Stmt* Expr? '}'
```

**統一セマンティクス**：すべての `{}` ブロックの return セマンティクスは一貫しています：

| ブロック種別 | return のセマンティクス | デフォルト戻り値 |
| ------------ | ----------------------- | ---------------- |
| 通常の `{}`  | 値を返す                | Void             |
| `unsafe {}`  | 型定義を返す            | Void             |
| `spawn {}`   | 結果を返す              | Void             |

**基本原則**：

- `{}` 内の `return` は常に内容を外側のスコープに返す
- デフォルトでは `return` がないと `Void` を返す
- 式形式 `= expr` は直接値を返す

```yaoxiang
// 通常の {} ブロック：return は値を返す
result = {
    x = compute()
    return x  // 値を外側のスコープに返す
}

// unsafe {} ブロック：return は型定義を返す
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    return SqliteDb  // 型定義を外側のスコープに返す
}

// spawn {} ブロック：return は結果を返す
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    return (result1, result2)  // 結果を外側のスコープに返す
}
```

### 2.10 ラムダ式

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 エラー伝播演算子

```
ErrorPropagate ::= Expr '?'
```

`?` 演算子は後置演算子で、優先順位は `.` と同等です。`Result(T, E)` 型に対して：

- `Ok(v)` の場合は値 `v` を抽出して実行を継続する
- `Err(e)` の場合はエラーを上位に伝播する (`return Err(e)`)

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // 成功時は値を抽出し、失敗時は上位に伝播
    transform(validated)
}
```

### 2.12 範囲式

```
RangeExpr   ::= Expr '..' Expr
```

`..` は範囲型を作成し、`for` ループとスライスに使用されます。

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]
```

### 2.13 ref 式

```
RefExpr     ::= 'ref' Expr
```

`ref` は共有の所有権を作成します。コンパイラは自動的に Rc (単一タスク) または Arc
(タスク横断) を選択し、ユーザは実装の詳細を気にする必要はありません。

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // タスク横断：コンパイラが自動的に Arc を選択
```

### 2.14 unsafe 式

```
UnsafeExpr  ::= 'unsafe' Block
```

`unsafe` ブロックは不透明型の定義と生ポインタの操作に使用されます。`return`
を使用して型定義を外側のスコープに返します。

**セマンティクス**：

- `unsafe {}` 内で型を定義し、生ポインタを操作できる
- 返される型は `unsafe {}` の外側でも使用可能
- 型のフィールドアクセスには unsafe 権限が必要

```yaoxiang
// unsafe ブロック内で不透明型を定義
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // 生ポインタ
    }
    return SqliteDb
}

// SqliteDb は unsafe ブロック外でも使用可能
db = sqlite3_open("test.db")
```

### 2.15 スコープ

**基本規則**：

- 各 `{}` ブロックは 1 つのスコープを作成する
- 内側のスコープは外側のスコープの変数にアクセスできる
- 外側のスコープは内側のスコープの変数にアクセスできない
- 変数宣言は「代入優先」の原則に従う

```yaoxiang
// ブロックスコープ
{
    x = 10
    // x はこのスコープ内で可視
}
// x はこのスコープ外では不可視

// 関数スコープ
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result は関数外では不可視
```

**変数宣言とシャドウイング**：

- `x = value`：スコープチェーンを外側に向かって x を検索し、見つかれば代入、見つからなければ新規宣言
- `mut x = value`：明示的な新しい可変宣言で、外側と同名は禁止
- 同じスコープ内で同じ名前を複数回宣言することはできない

> **詳細な定義**：スコープの完全な規則、変数宣言とシャドウイングの仕組みについては
> [モジュールシステム仕様](./modules.md#第四章作用域) を参照してください。

## 第三章：文

### 3.1 文の分類

```
Stmt        ::= LetStmt
              | ExprStmt
              | ReturnStmt
              | BreakStmt
              | ContinueStmt
              | IfStmt
              | MatchStmt
              | WhileStmt
              | ForStmt
              | SpawnStmt
```

### 3.2 変数宣言

```
LetStmt     ::= ('mut')? Identifier (':' TypeExpr)? '=' Expr
```

### 3.3 return 文

```
ReturnStmt  ::= 'return' Expr?
```

**セマンティクス**：`return` はコードブロックから値を返すために使用されます。`return`
がない場合、コードブロックはデフォルトで `Void` を返します。

### 3.4 break 文

```
BreakStmt   ::= 'break' Identifier?
```

### 3.5 continue 文

```
ContinueStmt::= 'continue'
```

### 3.6 if 文

```
IfStmt      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 3.7 match 文

```
MatchStmt   ::= 'match' Expr '{' MatchArm+ '}'
```

### 3.8 while 文

```
WhileStmt   ::= 'while' Expr Block
```

### 3.9 for 文

```
ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block
```

#### 3.9.1 セマンティクス：各反復は新しい値のバインディング

YaoXiang の for ループのセマンティクスは従来の言語とは異なります：**各反復は同じ変数を変更するのではなく、新しい値をバインドします**。

```yaoxiang
// 例：for i in 1..5
for i in 1..5 {
    print(i)
}
```

**実行プロセス**：

| 反復   | ループ変数の振る舞い                                                                                   |
| ------ | ------------------------------------------------------------------------------------------------------ |
| 1 回目 | 新しいバインディング `i = 1` を作成し、ループ本体を実行して 1 を出力                                   |
| 2 回目 | 新しいバインディング `i = 2` を作成し（以前のバインディングは破棄済み）、ループ本体を実行して 2 を出力 |
| 3 回目 | 新しいバインディング `i = 3` を作成し、ループ本体を実行して 3 を出力                                   |
| 4 回目 | 新しいバインディング `i = 4` を作成し、ループ本体を実行して 4 を出力                                   |
| 終了   | ループ本体が終了し、バインディングが破棄される                                                         |

**重要な点**：各反復が終了すると、その反復で作成されたバインディングは破棄されます。次の反復は完全に新しいバインディングであり、前の反復のバインディングとは何の関係もありません。

#### 3.9.2 for と for mut の違い

| 構文                | ループ変数の可变性 | 説明                                   |
| ------------------- | ------------------ | -------------------------------------- |
| `for i in 1..5`     | 不変               | ループ本体内でバインディングを変更不可 |
| `for mut i in 1..5` | 可変               | ループ本体内でバインディングを変更可能 |

```yaoxiang
// 合法：各反復で新しい値がバインドされるため、変更不要
for i in 1..5 {
    print(i)  // i の値を読み取る
}

// エラー：不変バインディングは変更不可
for i in 1..5 {
    i = i + 1  // エラー：不変バインディングは変更不可
}

// 合法：for mut を使用するとバインディングの変更が許可される
for mut i in 1..5 {
    i = i + 1  // 変更が許可される
}
```

#### 3.9.3 シャドウイング検査

YaoXiang は変数のシャドウイングを禁止します。for ループ変数は外側のスコープの変数と同名にできません：

```yaoxiang
// エラー：i はすでに外側で宣言されている
i = 10
for i in 1..5 {
    print(i)
}

// 正しい：異なる変数名を使用する
i = 10
for j in 1..5 {
    print(j)
}
```

この規則はすべてのコードブロックに適用されます。詳細は
[4.3 シャドウイング規則](./modules.md#43-遮蔽規則) を参照してください。

#### 3.9.4 他の言語との比較

| 言語     | for ループ変数のセマンティクス            |
| -------- | ----------------------------------------- |
| YaoXiang | 各反復で新しい値をバインド                |
| Rust     | 同じ変数を変更 (mut が必要)               |
| Python   | 同じ変数を変更 (mut 不要)                 |
| C/C++    | 同じ変数を変更 (ポインタまたは参照が必要) |

**設計理由**：YaoXiang がバインディングセマンティクスを採用するのは以下の理由によります：

1. **自然言語の意味論により適合する**
   自然言語では、「集合内の各要素 x について」は各 x が独立した個体であることを意味します。YaoXiang の
   `for i in 1..5`
   は「1 から 5 の各 i について」と読まれ、各反復の i は完全に新しいバインディングです。これは人間の直感的な理解と一致します。

2. **意図しない変更の回避**
   デフォルトで不変なバインディングセマンティクスは、ループ本体内でループ変数を誤って変更できないことを意味します。複雑なループ本体内のどこかで誤って
   `i = ...` と書いてしまい、追跡困難なバグを引き起こす心配がありません。

3. **高性能なソリューションへの容易なアクセス**
   反復間で変数を再利用することが実際に必要な場合 (例：アキュムレータ、キャッシュ)、`for mut`
   を使用するだけで可変バインディングモードに切り替えられます。これは暗黙の共有状態よりも明確です——意図は構文によって明示的に表現され、ランタイムの振る舞いに隠されることはありません。

### 3.10 spawn 文

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**spawn ブロック**：並行実行領域を明示的に宣言し、ブロック内の式を並行実行します。

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**spawn ループ**：データ並列ループ。

```yaoxiang
results = spawn for item in items {
    process(item)
}
```


### A.2 エラー処理

```
Expr '?'              // エラー伝播 (Result 型)
```

### A.3 match 構文

```
match value {
    pattern1 => expr1,
    pattern2 if guard => expr2,
    _ => default_expr,
}
```
