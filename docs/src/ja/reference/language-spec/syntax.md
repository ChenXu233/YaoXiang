# 構文仕様

本ファイルは YaoXiang プログラミング言語の構文仕様を定義し、字句構造、構文規則、演算子優先度を含む。

---

## 第一章：字句構造

### 1.1 ソースファイル

YaoXiang ソースファイルは UTF-8 エンコーディングを使用しなければならない。ソースファイルの拡張子は通常
`.yx` である。

### 1.2 字句単位の分類

| 类别   | 说明               | 示例                      |
| ------ | ------------------ | ------------------------- |
| 标识符 | 以字母或下划线开头 | `x`, `_private`, `my_var` |
| 关键字 | 语言预定义保留词   | `Type`, `pub`, `use`      |
| 字面量 | 固定值             | `42`, `"hello"`, `true`   |
| 运算符 | 运算符号           | `+`, `-`, `*`, `/`        |
| 分隔符 | 语法分隔符         | `(`, `)`, `{`, `}`, `,`   |

| 类别       | 説明                           | 例                        |
| ---------- | ------------------------------ | ------------------------- |
| 識別子     | 文字またはアンダースコア始まり | `x`, `_private`, `my_var` |
| キーワード | 言語定義の予約語               | `Type`, `pub`, `use`      |
| リテラル   | 固定値                         | `42`, `"hello"`, `true`   |
| 演算子     | 演算記号                       | `+`, `-`, `*`, `/`        |
| 区切り記号 | 構文区切り                     | `(`, `)`, `{`, `}`, `,`   |

### 1.3 キーワード

YaoXiang はごく少数のキーワードを定義する：

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

これらのキーワードは任意のコンテキストで特別な意味を持ち、識別子として使用することはできない。

### 1.4 予約語

YaoXiang の「予約語」は 3 層に分かれ、それぞれパーサ（parser）と型チェッカー（type
checker）が異なる段階で識別する。

#### 1.4.1 リテラル予約語

パーサが独立したトークンとして持つリテラル識別子は、通常の識別子として使用できない：

| 識別子  | 所属型 | 説明                                                                                        |
| ------- | ------ | ------------------------------------------------------------------------------------------- |
| `Type`  | —      | メタ型キーワード                                                                            |
| `true`  | Bool   | ブール真値                                                                                  |
| `false` | Bool   | ブール偽値                                                                                  |
| `void`  | Void   | Void リテラル（Unit 値）。小文字 `void` は値リテラル；大文字 `Void` は型名（§1.4.3 参照）。 |

#### 1.4.2 コンストラクタ式

以下のコンストラクタは、パターンマッチと式のコンテキストでパーサにより識別される：

| コンストラクタ | 所属型 | 説明                    |
| -------------- | ------ | ----------------------- |
| `some(T)`      | Option | Option 値バリアント構築 |
| `ok(T)`        | Result | Result 成功バリアント   |
| `err(E)`       | Result | Result エラーバリアント |

#### 1.4.3 組み込み型名

以下の型名は型チェッカーにより事前登録され、インポートなしでも型位置で使用できる。パーサはこれらを通常の識別子として扱う——**予約語ではなく、ローカルバインディングでシャドウ可能（非推奨）**。

| 型名     | 論理的対応   | 説明                                                                                                                       |
| -------- | ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤（真/Unit） | 零フィールド積型、正確に一つの居住者（`void` リテラル、§1.4.1 参照）                                                       |
| `Never`  | ⊥（偽/空型） | 零バリアント和型、零居住者。`Never` 値を生成する式は存在しない。`Never <: T` はすべての `T` に対して成立する（爆発原理）。 |
| `Int`    | —            | 符号付き整数                                                                                                               |
| `Float`  | —            | 浮動小数点数                                                                                                               |
| `Bool`   | —            | ブール値：`true` / `false`                                                                                                 |
| `Char`   | —            | Unicode 文字                                                                                                               |
| `String` | —            | 文字列                                                                                                                     |

### 1.5 識別子

識別子は文字またはアンダースコアで始まり、続く文字は文字、数字、アンダースコアが使用可能。識別子は大文字小文字を区別する。

特殊識別子：

- `_` はプレースホルダとして使用し、値の無視を表す
- アンダースコア始まりの識別子はプライベートメンバーを表す

### 1.6 リテラル

#### 1.6.1 整数

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 浮動小数点数

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 文字列

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 集合

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Array       ::= '[' Expr (',' Expr)* ']'   // 目标类型注解为 Array(T, N) 时字面量落定长数组
```

> Set にはリテラル文法がなく、ランタイム表現もない——集合型は計画中であり、需要が生じた際に Dict パターンに従って補完する（std.set +
> HeapValue::Set）。List/Dict リテラルの落点はコンテキスト型注釈により決定される：生の字面量と
> `List(T)` 注釈は可変長リストに落定する；`Array(T, N)`
> 注釈が字面量に直接作用する場合は固定長配列に落定する。List→Array の暗黙的変換は禁止。
>
> Array リテラルセマンティクス：
>
> - 要素数は N と等しくなければならず、等しくない場合はコンパイル時 E1002；空字面量に非ゼロ N の場合も同様に拒否
> - 各要素の型は T と互換でなければならず、互換性がない場合はコンパイル時 E1002
> - N の文法形式：整数字面量のみ（負数可）または定数名；複合式（例：`2+1`）は解析時に拒否
> - N がシンボル定数（関数の const パラメータ、例：`Array(Int, n)`）の場合、要素数検査は型精化段階まで延期
> - v1 のネスト配列リテラル（`Array(Array(Int,2),2) = [[1,2],[3,4]]`）はコンパイル時拒否、層ごとに明示的に構築する必要がある；再帰的な落点は将来のバージョンに先送り

#### 1.6.5 リスト内包表記

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

> **挙動の厳格化（移行記録）**：反復変数の文法は元から `'for' Identifier 'in'`
> だが、旧実装ではパターンが完全な pratt 解析を通っていた——`'in'` が中置演算子として登録された後、
> `x` は `in items`
> を membership 式として呑み込んでいた。修正後は非識別子パターンは直接解析失敗となり、旧実装のように
> `_` へのフォールバック（エラーの静かな吸収）は行われない。影響範囲：以前は解析可能だった
> `[x for (a, b) in pairs]` のような記述はエラーとなる——この形式は定義された動作を持たず（変数は常に
> `_`）、厳格化の方向は正しく、意味的な移行コストはない。

#### 1.6.6 メンバー検査

```
Membership  ::= Expr 'in' Expr
```

> `in` は二項関係演算子で、`Bool` を返す——ヒットすれば `true`、ヒットしなければ `false`
> で、エラーは発生しない。意味の分割：`[]` は存在を表明して値を取り出す（失敗時にエラー）、 `in`
> は存在するかを問い合わせる（ヒットしないのは正常な `false`）。右被演算子の対象：List / Array /
> Dict(キー集合) / Tuple / String(部分文字列) / Range(区間)。`in`
> は一級ホーア述語であり、型精化段階ではコンパイル時に証明可能な命題の基底となる。（Set は右被演算子リストから除外——Set にはランタイム表現がない、§1.6.4 参照）

### 1.7 コメント

```
// 単行コメント

/* 複数行コメント
   複数行に渡ることができる */
```

### 1.8 インデント規則

コードは 4 スペースでインデントしなければならず、Tab 文字の使用は禁止。これは強制的な構文規則である。

## 第二章：構文規則

### 2.1 式の分類

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 演算子優先度

| 優先度 | 演算子                      | 結合性   |
| ------ | --------------------------- | -------- |
| 1      | `()` `[]` `.` `?`           | 左から右 |
| 2      | `as`                        | 左から右 |
| 3      | 単項前置 `!` `-` `+`        | 右から左 |
| 4      | `*` `/` `%`                 | 左から右 |
| 5      | `+` `-`                     | 左から右 |
| 6      | `..`                        | 左から右 |
| 7      | `<<` `>>`                   | 左から右 |
| 8      | `&` `\|` `^`                | 左から右 |
| 9      | `==` `!=` `<` `>` `<=` `>=` | 左から右 |
| 10     | `and` `or`                  | 左から右 |
| 11     | `if...else`                 | 右から左 |
| 12     | `=` `+=` `-=` `*=` `/=`     | 右から左 |

> **単項前置演算子**（`!` `-`
> `+`）は強く結合する：呼び出しとメンバアクセスのみより低く、すべての二項演算子より高い。したがって
> `!a == b` ≡ `(!a) == b`（Zig 式セマンティクス）；`!`
> は純粋な単項演算であり、短絡制御フローには参加せず、 `and`/`or`
> キーワード（短絡）とは直交する（RFC-010 権威定義）。

> **Range の結合強度**：`..` の結合強度は (6,
> 7)——左 6 は加算（5）未満、右 7 は加算を呑み込むが同レベルの `..` は呑み込まない。変更前後の対比：
>
> | 式           | 変更前（レベル 1、右結合）                                                                | 変更後（(6,7)、左結合）                                                  |
> | ------------ | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
> | `x in 1..10` | `x in 1..10`（`in` の右被演算子レベル 4、`..` レベル 1 では呑み込めず、実際には解析不可） | `x in (1..10)`——区間全体が `in` の右被演算子                             |
> | `0..n+2`     | `(0..n)+2`（右結合の落とし穴：上界が食べられ、`for` ループは直接 E3004）                  | `0..(n+2)`——上界は算術式                                                 |
> | `a == b..c`  | `a == (b..c)`（`..` レベル 1 < `==` レベル 3、自然に全体）                                | `a == (b..c)`——**セマンティクス不変**、`..` は引き続き比較レベルより高い |
> | `1..2*3`     | `(1..2)*3`                                                                                | `1..(2*3)`——上界は算術式                                                 |
> | `a..b..c`    | `a..(b..c)`（右結合チェーン、意味のない Range の入れ子）                                  | `(a..b)..c`——**step 形式**（`c` はステップ）                             |
>
> 純効果：複合上界 `for i in 0..n+2` は「解析成功だが E3004」から「直接使用可能」へ； `x in 1..10`
> は「解析不可」から「区間チェック」へ；`a..b..c`
> は「無意味な入れ子」から「step 要素」へ。レベル 6 は `+`（レベル 5）と
> `<<`（レベル 7）の間に位置し、数学的慣習に合致：区間は強く結合する構造であり、上界は当然完全な算術式である。

### 2.3 関数呼び出し

```
FnCall      ::= Expr '(' ArgList? ')'
ArgList     ::= Expr (',' Expr)* (',' NamedArg)* | NamedArg (',' NamedArg)*
NamedArg    ::= Identifier ':' Expr
```

### 2.4 メンバアクセス

```
MemberAccess::= Expr '.' Identifier
```

### 2.5 インデックスアクセス

```
IndexAccess ::= Expr '[' Expr ']'
```

### 2.6 型変換

```
TypeCast    ::= Expr 'as' TypeExpr
```

### 2.7 条件式

```
IfExpr      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 2.8 パターンマッチ

```
MatchExpr   ::= 'match' Expr '{' MatchArm+ '}'
MatchArm    ::= Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
Pattern     ::= Literal
              | Identifier
              | Wildcard
              | StructPattern
              | TuplePattern
              | EnumPattern
              | OrPattern
```

### 2.9 ブロック式

```
Block       ::= '{' Stmt* Expr? '}'
```

> **文の終了規則**：Stmt 間の区切りと改行の振る舞い（`;`
> による明示的区切り、改行による終了、連結の例外、行頭の `(`/`[` は決して連結しない）は
> [RFC-038](../design/rfc/draft/038-statement-termination.md) で定義される。

**統一セマンティクス**：すべての `{}` ブロックの return セマンティクスは一致する：

| ブロック型  | return セマンティクス | デフォルト戻り値 |
| ----------- | --------------------- | ---------------- |
| 通常の `{}` | 値を返す              | Void             |
| `unsafe {}` | 型定義を返す          | Void             |
| `spawn {}`  | 結果を返す            | Void             |

**基本原則**：

- `{}` 内の `return` は常にその内容を一階層上のスコープに返す
- デフォルトでは `return` がない場合は `Void` を返す
- 式形式 `= expr` は直接値を返す

```yaoxiang
// 通常の {} ブロック：return が値を返す
result = {
    x = compute()
    return x  // 一階層上のスコープに値を返す
}

// unsafe {} ブロック：return が型定義を返す
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    return SqliteDb  // 一階層上のスコープに型定義を返す
}

// spawn {} ブロック：return が結果を返す
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    return (result1, result2)  // 一階層上のスコープに結果を返す
}
```

### 2.10 Lambda 式

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 エラー伝播演算子

```
ErrorPropagate ::= Expr '?'
```

`?` 演算子は後置演算子で、優先度は `.` と同レベル。`Result(T, E)` 型に対して：

- `Ok(v)` の場合は値 `v` を抽出して実行を続ける
- `Err(e)` の場合はエラーを上位に伝播する（`return Err(e)`）

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // 成功時は値を抽出し、失敗時は上位に伝播
    transform(validated)
}
```

### 2.12 範囲式

```
RangeExpr   ::= Expr '..' Expr ('..' Expr)?
```

`..` は範囲値を作成する（Range は一級値であり、構文糖ではない）。

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]

// Range は値：バインド、受け渡し、メンバ判定
r = 1..10
assert.assert(5 in r, "membership")
for i in r { print(i) }

// step 形式（第三成分、デフォルト 1）
for i in 0..10..2 { print(i) }  // 0, 2, 4, 6, 8
for i in 10..0..(-2) { print(i) }  // 10, 8, 6, 4, 2
```

> **step セマンティクス**：`a..b..c` における `c` はステップ。`c = 0`
> のリテラルはコンパイル時拒否；動的な `c`
> はランタイムゼロチェック（E6001 系；エラーシステム実装後に Result に格上げ）。 `c < 0`
> は合法で、区間方向は符号に従って反転する（`10..0..(-2)` は降順）。

### 2.13 ref 式

```
RefExpr     ::= 'ref' Expr
```

`ref`
は共有所有を作成する。コンパイラが自動的に Rc（単一タスク）または Arc（タスク横断）を選択し、ユーザは実装詳細を気にする必要はない。

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // タスク横断：コンパイラが自動的に Arc を選択
```

### 2.14 unsafe 式

```
UnsafeExpr  ::= 'unsafe' Block
```

`unsafe` ブロックは不透明型の定義と生ポインタの操作に使用される。`return`
を使用して型定義を一階層上のスコープに返す。

**セマンティクス**：

- `unsafe {}` 内で型定義と生ポインタ操作が可能
- 返された型は `unsafe {}` 外で使用可能
- 型のフィールドアクセスには unsafe 権限が必要

```yaoxiang
// unsafe ブロック内で不透明型を定義
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // 生ポインタ
    }
    return SqliteDb
}

// SqliteDb は unsafe ブロック外で使用可能
db = sqlite3_open("test.db")
```

### 2.15 スコープ

**基本規則**：

- 各 `{}` ブロックはスコープを作成する
- 内側スコープは外側スコープの変数にアクセス可能
- 外側スコープは内側スコープの変数にアクセス不可
- 変数宣言は「代入優先」原則に従う

```yaoxiang
// ブロックスコープ
{
    x = 10
    // x はこのスコープ内で可視
}
// x はこのスコープ外では不可視

// 関数スコープ
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result は関数外では不可視
```

**変数宣言とシャドウイング**：

- `x = value`：スコープチェーンに沿って外側に x を検索し、見つかれば代入、見つからなければ新規宣言
- `mut x = value`：明示的な新規可変宣言で、外側と同名は禁止
- 同一スコープ内で同じ名前を宣言できるのは一度のみ

> **詳細定義**：スコープの完全な規則、変数宣言とシャドウイング機構の詳細については
> [モジュールシステム仕様](./modules.md#第四章スコープ) を参照。

## 第三章：文

### 3.1 文の分類

```
Stmt        ::= LetStmt
              | ExprStmt
              | ReturnStmt
              | BreakStmt
              | ContinueStmt
              | IfStmt
              | MatchStmt
              | WhileStmt
              | ForStmt
              | SpawnStmt
```

### 3.2 変数宣言

```
LetStmt     ::= ('mut')? Identifier (':' TypeExpr)? '=' Expr
```

### 3.3 return 文

```
ReturnStmt  ::= 'return' Expr?
```

**セマンティクス**：`return` はコードブロックから値を返すために使用される。`return`
がない場合、コードブロックはデフォルトで `Void` を返す。

### 3.4 break 文

```
BreakStmt   ::= 'break'
```

**セマンティクス**：属する最も内側の `while`/`for`
ループを直ちに終了し、制御フローをそのループ本体の後へ移す。

- **最も内側の一層のみを出る**：`break`
  は常にそれを含む最も内側のループに作用する。ネストしたループで複数層を一度に抜ける必要がある場合は、内側ループを関数として抽出して
  `return`
  で返すか、フラグ変数を使用する（break/continue にラベルはない；将来ループラベルを導入する場合は、ループ宣言側の構文に従って RFC プロセスを進め、証明パイプラインの複数出口設計と共に決着する）
- **ループ本体内に限定**：`break` は `while`/`for`
  ループ本体内（本体内にネストされたブロック/if/match を含む）にのみ出現でき、ループ外に出現した場合はコンパイルエラー（E1102
  `'break' outside of a loop`）
- **停止性証明に影響しない**：`while`
  ループは依然として停止が証明可能である必要がある（decreases 計量）；`break`
  は停止性の議論に参加せず、`while true { break }` は受理されない
- **借用セマンティクス**：break の制御フロー辺は RFC-009a の逆向き BFS 活性分析の構造的切断に参加する（抜けたイテレーションは逆辺活性導出に参加しない）

```yaoxiang
mut i = 0
while i < 10 {
    i = i + 1
    if i == 3 {
        break              // 制御フローはループの後へ移動、i == 3
    }
}

// ネストループ：break は内側のみを出る
while j < 3 {
    while k < 10 {
        if k == 2 { break }    // 内側ループのみを終了
    }
    j = j + 1                  // 外側イテレーションの各ラウンドはここまで実行される
}
```

### 3.5 continue 文

```
ContinueStmt::= 'continue'
```

**セマンティクス**：現在のイテレーションの残りの文をスキップし、属する最も内側のループの次のラウンドに直接入る——
`while` は条件再評価に戻り、`for` は次の要素を取り出す。

- **最も内側の一層のみに作用**：`break` と同じで、ラベルなし
- **ループ本体内に限定**：ループ外に出現した場合はコンパイルエラー（E1102）

```yaoxiang
mut sum = 0
mut n = 0
while n < 5 {
    n = n + 1
    if n == 3 {
        continue           // 下の累算をスキップ、n == 3 は加算されない
    }
    sum = sum + n
}
// sum == 12（1 + 2 + 4 + 5）
```

### 3.9 for 文

```
ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block
```

#### 3.9.1 セマンティクス：各イテレーションは新しい値をバインドする

YaoXiang の for ループセマンティクスは従来言語と異なる：**各イテレーションは新しい値をバインドし、同じ変数を変更するのではない**。

```yaoxiang
// 例：for i in 1..5
for i in 1..5 {
    print(i)
}
```

**実行プロセス**：

| イテレーション | ループ変数の動作                                                                      |
| -------------- | ------------------------------------------------------------------------------------- |
| 1回目          | 新規バインド `i = 1` を作成し、ループ本体を実行、1 を出力                             |
| 2回目          | 新規バインド `i = 2` を作成し（前回のバインドは破棄済み）、ループ本体を実行、2 を出力 |
| 3回目          | 新規バインド `i = 3` を作成し、ループ本体を実行、3 を出力                             |
| 4回目          | 新規バインド `i = 4` を作成し、ループ本体を実行、4 を出力                             |
| 終了           | ループ本体終了、バインド破棄                                                          |

**要点**：各イテレーション終了後、その回のイテレーションで作成されたバインドは破棄される。次のイテレーションは完全に新しいバインドであり、前回のイテレーションのバインドとは一切関係がない。

#### 3.9.2 for と for mut の違い

| 構文                | ループ変数の可変性 | 説明                                 |
| ------------------- | ------------------ | ------------------------------------ |
| `for i in 1..5`     | 不変               | ループ本体内でバインドを変更できない |
| `for mut i in 1..5` | 可変               | ループ本体内でバインドを変更可能     |

```yaoxiang
// 合法：各イテレーションで新しい値をバインドし、変更は不要
for i in 1..5 {
    print(i)  // i の値を読み取る
}

// エラー：不変バインド、変更不可
for i in 1..5 {
    i = i + 1  // エラー：不変バインドは変更できない
}

// 合法：for mut を使用すればバインドの変更が許可される
for mut i in 1..5 {
    i = i + 1  // 変更が許可される
}
```

#### 3.9.3 シャドウイング検査

YaoXiang は変数のシャドウイングを禁止する。for ループ変数は外側スコープの変数と同名にできない：

```yaoxiang
// エラー：i はすでに外部で宣言済み
i = 10
for i in 1..5 {
    print(i)
}

// 正しい：異なる変数名を使用する
i = 10
for j in 1..5 {
    print(j)
}
```

この規則はすべてのコードブロックに適用される。詳細は
[4.3 シャドウイング規則](./modules.md#43-シャドウイング規則) を参照。

#### 3.9.4 他の言語との対比

| 言語     | for ループ変数のセマンティクス             |
| -------- | ------------------------------------------ |
| YaoXiang | 各イテレーションで新しい値をバインド       |
| Rust     | 同じ変数を変更（mut が必要）               |
| Python   | 同じ変数を変更（mut 不要）                 |
| C/C++    | 同じ変数を変更（ポインタまたは参照が必要） |

**設計理由**：YaoXiang がバインディングセマンティクスを採用する理由は：

1. **自然言語セマンティクスにより適合**
   自然言語において「集合の各要素 x について」は、各 x が独立した個体であることを意味する。YaoXiang の
   `for i in 1..5`
   は「1 から 5 までの各 i について」と読まれ、各イテレーションの i は完全に新しいバインディングであり、人間の直感的な理解と一致する。

2. **偶発的な変更を回避**
   デフォルトの不変バインディングセマンティクスは、ループ本体内で偶発的にループ変数を変更できないことを意味する。複雑なループ本体内のどこかで誤って
   `i = ...` と書いて追跡困難なバグにつながる心配がない。

3. **高性能なソリューションに手が届く**
   イテレーション間で変数を実際に再利用する必要がある場合（例：アキュムレータ、キャッシュ）、`for mut`
   宣言を使用すれば可変バインディングモードに切り替えられる。これは暗黙的な共有状態より明確であり、意図は構文で明示的に表現され、ランタイム動作に隠されない。

### 3.10 spawn 文

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**spawn ブロック**：並行実行領域を明示的に宣言し、ブロック内の式を並行実行する。

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**spawn ループ**：データ並列ループ。

```yaoxiang
results = spawn for item in items {
    process(item)
}
```

**spawn ブロックによる外側変数のキャプチャ**（RFC-024 §2.3、値キャプチャセマンティクス）：

- ブロック本体が外側変数を参照 =
  **Move 値キャプチャ**：値は spawn 作成時点でクロージャ環境にスナップショットされ、ブロック本体は env 経由で読み取る（LoadUpvalue）
- **プリミティブ型**（Int/Float/Bool/Char）は値をコピーし、外側変数は影響を受けない
- **ハンドル型**（Struct/String/List など）のスナップショット = ハンドルコピー、基底オブジェクトを共有；Embedded ランタイム（デフォルト）は同スレッド同ヒープで、ハンドルが有効
- 複数タスク間での共有には明示的な `ref` が必要（§2.13、コンパイラが自動的に Rc/Arc を選択）
- ブロック内の `return` で参照される外側変数も同様にキャプチャされる

```yaoxiang
t1 = 1 + 1
t2 = 2 + 2
result = spawn {
    return t1 + t2    // t1/t2 は値キャプチャ、result == 6
}
```
