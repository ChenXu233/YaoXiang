# 文法仕様

本ファイルは YaoXiang プログラミング言語の文法仕様を定義する。字句構造、文法規則、演算子の優先順位を含む。

---

## 第一章：字句構造

### 1.1 ソースファイル

YaoXiang ソースファイルは UTF-8 エンコーディングを使用しなければならない。ソースファイルの拡張子は通常
`.yx` である。

### 1.2 字句ユニットの分類

| カテゴリー | 説明                             | 例                        |
| ---------- | -------------------------------- | ------------------------- |
| 識別子     | 文字またはアンダースコアで始まる | `x`, `_private`, `my_var` |
| キーワード | 言語の事前定義済み予約語         | `Type`, `pub`, `use`      |
| リテラル   | 固定値                           | `42`, `"hello"`, `true`   |
| 演算子     | 演算記号                         | `+`, `-`, `*`, `/`        |
| 区切り記号 | 文法上の区切り                   | `(`, `)`, `{`, `}`, `,`   |

### 1.3 キーワード

YaoXiang は極めて少数のキーワードを定義する：

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

これらのキーワードはいかなる文脈においても特別な意味を持ち、識別子として使用することはできない。

### 1.4 予約語

YaoXiang の「予約語」は3つの層に分かれ、それぞれパーサ（parser）と型検査器（type
checker）が異なる段階で識別する：

#### 1.4.1 リテラル予約語

パーサが独立したトークンとして持つリテラル識別子は、通常の識別子として使用できない：

| 識別子  | 所属する型 | 説明                                                                                        |
| ------- | ---------- | ------------------------------------------------------------------------------------------- |
| `Type`  | —          | メタ型キーワード                                                                            |
| `true`  | Bool       | ブール真値                                                                                  |
| `false` | Bool       | ブール偽値                                                                                  |
| `void`  | Void       | Void リテラル（Unit 値）。小文字 `void` は値リテラル；大文字 `Void` は型名（§1.4.3 参照）。 |

#### 1.4.2 コンストラクタ式

以下のコンストラクタはパターンマッチングと式の文脈でパーサにより識別される：

| コンストラクタ | 所属する型 | 説明                    |
| -------------- | ---------- | ----------------------- |
| `some(T)`      | Option     | Option 値バリアント構築 |
| `ok(T)`        | Result     | Result 成功バリアント   |
| `err(E)`       | Result     | Result エラーバリアント |

#### 1.4.3 組み込み型名

以下の型名は型検査器により事前登録されており、インポートなしでも型の位置で使用可能。パーサはこれらを通常の識別子として扱う——**予約語ではなく、局所バインディングによるシャドウイングが可能（非推奨）**。

| 型名     | 論理的対応   | 説明                                                                                                                                             |
| -------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Void`   | ⊤（真/Unit） | ゼロフィールドの積型で、唯一の居住者（`void` リテラル、§1.4.1 参照）をちょうど1つ持つ                                                            |
| `Never`  | ⊥（偽/空型） | ゼロバリアントの和型で、居住者を一切持たない。`Never` 型の値を生成する式は存在しない。`Never <: T` がすべての `T` に対して成立する（爆発原理）。 |
| `Int`    | —            | 符号付き整数                                                                                                                                     |
| `Float`  | —            | 浮動小数点数                                                                                                                                     |
| `Bool`   | —            | ブール値：`true` / `false`                                                                                                                       |
| `Char`   | —            | Unicode 文字                                                                                                                                     |
| `String` | —            | 文字列                                                                                                                                           |

### 1.5 識別子

識別子は文字またはアンダースコアで始まり、続く文字は文字、数字、アンダースコアのいずれでもよい。識別子は大文字小文字を区別する。

特別な識別子：

- `_` はプレースホルダとして使われ、値を無視することを示す
- アンダースコア始まりの識別子はプライベートメンバを示す

### 1.6 リテラル

#### 1.6.1 整数

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 浮動小数点数

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 文字列

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 コレクション

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Array       ::= '[' Expr (',' Expr)* ']'   // 対象型注釈が Array(T, N) のときリテラルは固定長配列に決定
```

> #299/#300：Set にはリテラル文法もランタイム表現も存在しない——コレクション型を計画中、必要が発生した時点で Dict のパターンに沿って補完する（std.set +
> HeapValue::Set）。List/Dict リテラルの決定点は文脈型注釈による：素のリテラルと `List(T)`
> 注釈は可変長リストに決定；`Array(T, N)`
> 注釈がリテラルに直接作用する場合は固定長配列に決定。List→Array の暗黙的な変換は禁止。
>
> Array リテラルのセマンティクス（#300）：
>
> - 要素数は N と一致しなければならず、不一致の場合はコンパイル時 E1002；空リテラルに非ゼロ N を割り当てるのも同様に拒否
> - 各要素の型は T と互換でなければならず、不一致の場合はコンパイル時 E1002
> - N の文法形態：整数リテラル（負数可）または定数名のみ；複合式（例：`2+1`）は解析時に拒否
> - N がシンボリック定数（関数の const パラメータ、例：`Array(Int, n)`）の場合、要素数検査は精化型段階まで延期
> - v1 ネスト配列リテラル（`Array(Array(Int,2),2) = [[1,2],[3,4]]`）はコンパイル時に拒否、層ごとに明示的に構築する必要がある；再帰的な決定点は将来のバージョンに先送り

#### 1.6.5 リスト内包表記

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

> **#299 §3 行動の厳格化（移行記録）**：反復変数の文法は元から `'for' Identifier 'in'`
> だが、旧実装では pattern が完全な pratt 解析を行うため——`'in'` を中置演算子として登録した後、 `x`
> は `in items`
> を membership 式として飲み込んでしまう。修正後は非識別子 pattern は直接解析失敗となり、旧実装のように
> `_` にフォールバック（静かにエラーを吸収）することはなくなった。影響範囲：これまで解析できていた
> `[x for (a, b) in pairs]`
> のような書き方は現在エラーとなる——この形式には元々定義された挙動がなく（変数は常に
> `_`）、厳格化方向は正しく、意味的な移行コストは発生しない。

#### 1.6.6 メンバシップ検査

```
Membership  ::= Expr 'in' Expr
```

> #299 §3：`in` は二項関係演算子であり、`Bool` を返す——ヒットすれば `true`、ミスすれば `false`
> でエラーは報告されない。意味の分割：`[]` は存在を表明して値を取り出す（失敗時はエラー）、 `in`
> は存在を問う（ミスは通常の `false`）。右被演算子の対象：List / Array / Dict(キー集合) / Tuple /
> String(部分文字列) / Range(区間)。`in`
> は一級のホール述語であり、精化型段階でコンパイル時に証明可能な命題の基底となる。（#300 決定 4：Set は右被演算子リストから除外——Set にはランタイム表現がない、§1.6.4 参照）

### 1.7 コメント

```
// 単行コメント

/* 複数行コメント
   複数行に渡ることができる */
```

### 1.8 インデント規則

コードは 4 つのスペースでインデントしなければならず、Tab 文字の使用は禁止。これは強制的な文法規則である。

## 第二章：文法規則

### 2.1 式の分類

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 演算子の優先順位

| 優先順位 | 演算子                      | 結合性   |
| -------- | --------------------------- | -------- |
| 1        | `()` `[]` `.` `?`           | 左から右 |
| 2        | `as`                        | 左から右 |
| 3        | 単項前置 `!` `-` `+`        | 右から左 |
| 4        | `*` `/` `%`                 | 左から右 |
| 5        | `+` `-`                     | 左から右 |
| 6        | `..`                        | 左から右 |
| 7        | `<<` `>>`                   | 左から右 |
| 8        | `&` `\|` `^`                | 左から右 |
| 9        | `==` `!=` `<` `>` `<=` `>=` | 左から右 |
| 10       | `and` `or`                  | 左から右 |
| 11       | `if...else`                 | 右から左 |
| 12       | `=` `+=` `-=` `*=` `/=`     | 右から左 |

> **単項前置演算子**（`!` `-`
> `+`）は強い結合を持つ：呼び出しとメンバアクセスより低く、すべての二項演算子より高い。したがって
> `!a == b` ≡ `(!a) == b`（Zig 式のセマンティクス）；`!`
> は純粋な単項演算であり、短絡制御フローには参加せず、 `and`/`or`
> キーワード（短絡）と直交する（RFC-010 が権威ある定義）。

> **Range の結合力（#299 §3 / #300 F 項）**：`..` の結合力は (6,
> 7)——左 6 は加算（7）未満、右 7 は加算を吸収するが同レベルの `..` は吸収しない。変更前後の比較：
>
> | 式           | 変更前（レベル 1、右結合）                                                                | 変更後（(6,7)、左結合）                                              |
> | ------------ | ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
> | `x in 1..10` | `x in 1..10`（`in` の右被演算子レベル 4、`..` レベル 1 では吸収できず、実質的に解析不可） | `x in (1..10)`——区間全体が `in` の右被演算子として                   |
> | `0..n+2`     | `(0..n)+2`（右結合の落とし穴：上限が飲み込まれ、`for` ループで直接 E3004）                | `0..(n+2)`——上限は算術式                                             |
> | `a == b..c`  | `a == (b..c)`（`..` レベル 1 < `==` レベル 3、最初から全体）                              | `a == (b..c)`——**セマンティクス不変**、`..` は依然として比較より強い |
> | `1..2*3`     | `(1..2)*3`                                                                                | `1..(2*3)`——上限は算術式                                             |
> | `a..b..c`    | `a..(b..c)`（右結合の連鎖、無意味な Range の入れ子）                                      | `(a..b)..c`——**step 形式**（`c` はステップ、#300 I 項）              |
>
> 純効果：複合上限 `for i in 0..n+2` は「解析成功だが E3004」から「直接使用可能」に； `x in 1..10`
> は「解析不可」から「区間検査」に；`a..b..c`
> は「無意味な入れ子」から「step 構成要素」に。レベル 6 は `+`（レベル 5）と
> `<<`（レベル 7）の間に位置し、数学的慣習に従う：区間は強く結合する構成であり、上限は当然完全な算術式である。

### 2.3 関数呼び出し

```
FnCall      ::= Expr '(' ArgList? ')'
ArgList     ::= Expr (',' Expr)* (',' NamedArg)* | NamedArg (',' NamedArg)*
NamedArg    ::= Identifier ':' Expr
```

### 2.4 メンバアクセス

```
MemberAccess::= Expr '.' Identifier
```

### 2.5 インデックスアクセス

```
IndexAccess ::= Expr '[' Expr ']'
```

### 2.6 型変換

```
TypeCast    ::= Expr 'as' TypeExpr
```

### 2.7 条件式

```
IfExpr      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 2.8 パターンマッチング

```
MatchExpr   ::= 'match' Expr '{' MatchArm+ '}'
MatchArm    ::= Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
Pattern     ::= Literal
              | Identifier
              | Wildcard
              | StructPattern
              | TuplePattern
              | EnumPattern
              | OrPattern
```

### 2.9 ブロック式

```
Block       ::= '{' Stmt* Expr? '}'
```

> **文の終端規則**：Stmt 間の区切りと改行挙動（`;` の明示的区切り、改行終端、継続行例外、行頭
> `(`/`[` はマージしない）は [RFC-038](../design/rfc/draft/038-statement-termination.md)
> で定義される。

**統一セマンティクス**：すべての `{}` ブロックの return セマンティクスは一貫している：

| ブロック型  | return セマンティクス | デフォルト戻り値 |
| ----------- | --------------------- | ---------------- |
| 通常の `{}` | 値を返す              | Void             |
| `unsafe {}` | 型定義を返す          | Void             |
| `spawn {}`  | 結果を返す            | Void             |

**核心原則**：

- `{}` 内の `return` は常にその内容を外側スコープに返す
- `return` がない場合のデフォルトは `Void` を返す
- 式形式 `= expr` は直接値を返す

```yaoxiang
// 通常の {} ブロック：return は値を返す
result = {
    x = compute()
    return x  // 値を外側スコープに返す
}

// unsafe {} ブロック：return は型定義を返す
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    return SqliteDb  // 型定義を外側スコープに返す
}

// spawn {} ブロック：return は結果を返す
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    return (result1, result2)  // 結果を外側スコープに返す
}
```

### 2.10 ラムダ式

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 エラー伝播演算子

```
ErrorPropagate ::= Expr '?'
```

`?` 演算子は後置演算子であり、優先順位は `.` と同等。`Result(T, E)` 型に対して：

- `Ok(v)` の場合は値 `v` を抽出して実行を継続
- `Err(e)` の場合はエラーを上位に伝播（`return Err(e)`）

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // 成功時は値を抽出し、失敗時は上位に伝播
    transform(validated)
}
```

### 2.12 範囲式

```
RangeExpr   ::= Expr '..' Expr ('..' Expr)?
```

`..` は範囲値を生成する（#300 I 項：Range は一級値であり、構文糖ではない）。

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]

// Range は値である：バインド、受け渡し、メンバ判定
r = 1..10
assert.assert(5 in r, "membership")
for i in r { print(i) }

// step 形式（第三引数、デフォルト 1）
for i in 0..10..2 { print(i) }  // 0, 2, 4, 6, 8
for i in 10..0..(-2) { print(i) }  // 10, 8, 6, 4, 2
```

> **step のセマンティクス**：`a..b..c` において `c` はステップ長。`c = 0`
> のリテラルはコンパイル時に拒否；動的な `c`
> はランタイムでゼロ検査（E6001 ファミリ、#301 エラーシステム実装後に Result に格上げ）。 `c < 0`
> は合法であり、区間の方向は符号に応じて反転する（`10..0..(-2)` は降順）。

### 2.13 ref 式

```
RefExpr     ::= 'ref' Expr
```

`ref`
は共有所有を生成する。コンパイラは自動的に Rc（単一タスク）または Arc（タスク横断）を選択し、ユーザは実装の詳細を気にする必要はない。

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // タスク横断：コンパイラが自動的に Arc を選択
```

### 2.14 unsafe 式

```
UnsafeExpr  ::= 'unsafe' Block
```

`unsafe` ブロックは不透明型の定義と生ポインタの操作に使用される。`return`
を使用して型定義を外側スコープに返す。

**セマンティクス**：

- `unsafe {}` 内で型を定義し生ポインタを操作可能
- 返される型は `unsafe {}` の外側でアクセス可能
- 型のフィールドアクセスには unsafe 権限が必要

```yaoxiang
// unsafe ブロック内で不透明型を定義
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // 生ポインタ
    }
    return SqliteDb
}

// SqliteDb は unsafe ブロックの外側でアクセス可能
db = sqlite3_open("test.db")
```

### 2.15 スコープ

**基本規則**：

- 各 `{}` ブロックはスコープを作成する
- 内側スコープは外側スコープの変数にアクセス可能
- 外側スコープは内側スコープの変数にアクセス不可能
- 変数宣言は「代入優先」原則に従う

```yaoxiang
// ブロックスコープ
{
    x = 10
    // x はこのスコープ内で可視
}
// x はこのスコープの外側では不可視

// 関数スコープ
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result は関数の外側では不可視
```

**変数宣言とシャドウィング**：

- `x = value`：スコープチェーンに沿って外側に x を検索し、見つかれば代入、見つからなければ新規宣言
- `mut x = value`：明示的な新規可変宣言、外側と同名は禁止
- 同一スコープ内で任意の名前を 2 回宣言することはできない

> **詳細定義**：スコープの完全な規則、変数宣言とシャドウィング機構の詳細については
> [モジュールシステム仕様](./modules.md#第四章作用域) を参照。

## 第三章：文

### 3.1 文の分類

```
Stmt        ::= LetStmt
              | ExprStmt
              | ReturnStmt
              | BreakStmt
              | ContinueStmt
              | IfStmt
              | MatchStmt
              | WhileStmt
              | ForStmt
              | SpawnStmt
```

### 3.2 変数宣言

```
LetStmt     ::= ('mut')? Identifier (':' TypeExpr)? '=' Expr
```

### 3.3 return 文

```
ReturnStmt  ::= 'return' Expr?
```

**セマンティクス**：`return` はコードブロックから値を返すために使用される。`return`
がない場合、コードブロックのデフォルト戻り値は `Void` である。

### 3.4 break 文

```
BreakStmt   ::= 'break' Identifier?
```

### 3.5 continue 文

```
ContinueStmt::= 'continue'
```

### 3.6 if 文

```
IfStmt      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 3.7 match 文

```
MatchStmt   ::= 'match' Expr '{' MatchArm+ '}'
```

### 3.8 while 文

```
WhileStmt   ::= 'while' Expr Block
```

### 3.9 for 文

```
ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block
```

#### 3.9.1 セマンティクス：各反復は新しい値のバインド

YaoXiang の for ループのセマンティクスは従来の言語と異なる：**各反復は新しい値をバインドし、同じ変数を変更するのではない**。

```yaoxiang
// 例：for i in 1..5
for i in 1..5 {
    print(i)
}
```

**実行プロセス**：

| 反復   | ループ変数の挙動                                                                  |
| ------ | --------------------------------------------------------------------------------- |
| 1 回目 | 新規バインド `i = 1` を作成し、ループ本体を実行、1 を表示                         |
| 2 回目 | 新規バインド `i = 2` を作成（前のバインドは破棄済み）、ループ本体を実行、2 を表示 |
| 3 回目 | 新規バインド `i = 3` を作成し、ループ本体を実行、3 を表示                         |
| 4 回目 | 新規バインド `i = 4` を作成し、ループ本体を実行、4 を表示                         |
| 終了   | ループ本体終了、バインド破棄                                                      |

**要点**：各反復の終了後、その反復で作成されたバインドは破棄される。次の反復は完全に新しいバインドであり、前の反復のバインドとは一切関係がない。

#### 3.9.2 for と for mut の違い

| 文法                | ループ変数の可変性 | 説明                             |
| ------------------- | ------------------ | -------------------------------- |
| `for i in 1..5`     | 不変               | ループ本体内でバインドを変更不可 |
| `for mut i in 1..5` | 可変               | ループ本体内でバインドを変更可能 |

```yaoxiang
// 合法：各反復で新しい値をバインドし、変更は不要
for i in 1..5 {
    print(i)  // i の値を読み取る
}

// エラー：不変バインドは変更不可
for i in 1..5 {
    i = i + 1  // エラー：不変バインドは変更不可
}

// 合法：for mut を使用すればバインドの変更が可能
for mut i in 1..5 {
    i = i + 1  // 変更可能
}
```

#### 3.9.3 シャドウィング検査

YaoXiang は変数のシャドウィングを禁止する。for ループ変数は外側スコープの変数と同名にすることはできない：

```yaoxiang
// エラー：i は既に外部で宣言されている
i = 10
for i in 1..5 {
    print(i)
}

// 正しい：異なる変数名を使用
i = 10
for j in 1..5 {
    print(j)
}
```

この規則はすべてのコードブロックに適用される。詳細は
[4.3 シャドウィング規則](./modules.md#43-遮蔽规则) を参照。

#### 3.9.4 他の言語との比較

| 言語     | for ループ変数のセマンティクス         |
| -------- | -------------------------------------- |
| YaoXiang | 各反復で新しい値をバインド             |
| Rust     | 同じ変数を変更（mut が必要）           |
| Python   | 同じ変数を変更（mut 不要）             |
| C/C++    | 同じ変数を変更（ポインタや参照が必要） |

**設計理由**：YaoXiang がバインドセマンティクスを採用するのは：

1. **より自然なセマンティクスに合致**
   自然言語では、「コレクションの各要素 x について」は各 x が独立した個体であることを意味する。YaoXiang の
   `for i in 1..5`
   は「1 から 5 の各 i について」と読まれ、各反復の i は完全に新しいバインドであり、人間の直感的理解と一致する。

2. **偶発的な変更の回避**
   デフォルトで不変のバインドセマンティクスは、ループ本体内でループ変数を偶発的に変更できないことを意味する。複雑なループ本体のどこかで誤って
   `i = ...` と書いて追跡困難なバグを引き起こす心配がない。

3. **高性能な解決策への近さ**
   反復間で実際に変数を再利用する必要がある場合（例：アキュムレータ、キャッシュ）、`for mut`
   で宣言すれば可変バインドモードに切り替えられる。これは暗黙的な状態共有より明確である——意図は構文で明示的に表現され、ランタイムの挙動に隠されることはない。

### 3.10 spawn 文

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**spawn ブロック**：並行実行領域を明示的に宣言し、ブロック内の式を並行実行する。

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**spawn ループ**：データ並列ループ。

```yaoxiang
results = spawn for item in items {
    process(item)
}
```

**spawn ブロックは外側の変数をキャプチャする**（RFC-024 §2.3、値キャプチャセマンティクス）：

- ブロック本体が外側の変数を参照 =
  **Move 値キャプチャ**：値は spawn の作成時点でクロージャ環境にスナップショットされ、ブロック本体は env 経由で読み取る（LoadUpvalue）
- **プリミティブ型**（Int/Float/Bool/Char）は値をコピーし、外側の変数は影響を受けない
- **ハンドル型**（Struct/String/List など）のスナップショット = ハンドルのコピー、基底オブジェクトを共有；Embedded ランタイム（デフォルト）では同一スレッド同一ヒープでハンドルが有効
- 複数タスク間の共有には明示的な `ref` が必要（§2.13、コンパイラが自動的に Rc/Arc を選択）
- ブロック内の `return` が参照する外側の変数も同様にキャプチャされる

```yaoxiang
t1 = 1 + 1
t2 = 2 + 2
result = spawn {
    return t1 + t2    // t1/t2 は値キャプチャ、result == 6
}
```
