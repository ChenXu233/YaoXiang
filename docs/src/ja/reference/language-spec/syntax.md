# 文法仕様

本ドキュメントはYaoXiangプログラミング言語の文法仕様を定義する。語彙構造、文法規則、演算子の優先順位を含む。

---

## 第一章：語彙構造

### 1.1 ソースファイル

YaoXiangのソースファイルはUTF-8エンコーディングを使用しなければならない。ソースファイルの拡張子は通常
`.yx` である。

### 1.2 トークンの分類

| カテゴリ   | 説明                             | 例                        |
| ---------- | -------------------------------- | ------------------------- |
| 識別子     | 文字またはアンダースコアで始まる | `x`, `_private`, `my_var` |
| キーワード | 言語で事前定義された予約語       | `Type`, `pub`, `use`      |
| リテラル   | 固定値                           | `42`, `"hello"`, `true`   |
| 演算子     | 演算記号                         | `+`, `-`, `*`, `/`        |
| 区切り記号 | 文法上の区切り                   | `(`, `)`, `{`, `}`, `,`   |

### 1.3 キーワード

YaoXiangは極めて少数のキーワードを定義する：

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

これらのキーワードはあらゆる文脈で特別な意味を持ち、識別子として使用することはできない。

### 1.4 予約語

YaoXiangの「予約語」は3つの層に分かれ、解析器（parser）と型検査器（type
checker）がそれぞれ異なる段階で識別する：

#### 1.4.1 リテラル予約語

解析器が独立したトークンとして持つリテラル識別子は、通常の識別子として使用できない：

| 識別子  | 所属型 | 説明                                                                                         |
| ------- | ------ | -------------------------------------------------------------------------------------------- |
| `Type`  | —      | メタ型キーワード                                                                             |
| `true`  | Bool   | ブールの真値                                                                                 |
| `false` | Bool   | ブールの偽値                                                                                 |
| `void`  | Void   | Voidリテラル（Unit値）。小文字の `void` は値リテラル；大文字の `Void` は型名（§1.4.3参照）。 |

#### 1.4.2 コンストラクタ式

以下のコンストラクタはパターンマッチと式の文脈で解析器によって識別される：

| コンストラクタ | 所属型 | 説明                   |
| -------------- | ------ | ---------------------- |
| `some(T)`      | Option | Option値バリアント構築 |
| `ok(T)`        | Result | Result成功バリアント   |
| `err(E)`       | Result | Resultエラー変異体     |

#### 1.4.3 組み込み型名

以下の型名は型検査器によって事前登録されており、インポートなしで型の位置で使用できる。解析器はこれらを通常の識別子として扱う——**予約語ではないため、ローカルバインディングでshadowing可能（非推奨）**。

| 型名     | 論理的対応   | 説明                                                                                                                       |
| -------- | ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤（真/Unit） | 零フィールド積型、ちょうど1つの居住者（`void` リテラル、§1.4.1参照）                                                       |
| `Never`  | ⊥（偽/空型） | 零変異体和型、零個の居住者。`Never` 値を生成する式は存在しない。`Never <: T` はすべての `T` に対して成立する（爆発原理）。 |
| `Int`    | —            | 符号付き整数                                                                                                               |
| `Float`  | —            | 浮動小数点数                                                                                                               |
| `Bool`   | —            | ブール値：`true` / `false`                                                                                                 |
| `Char`   | —            | Unicode文字                                                                                                                |
| `String` | —            | 文字列                                                                                                                     |

### 1.5 識別子

識別子は文字またはアンダースコアで始まり、後続の文字は文字、数字、またはアンダースコアである。識別子は大文字小文字を区別する。

特殊な識別子：

- `_` は値を無視することを示すプレースホルダとして使用される
- アンダースコアで始まる識別子はプライベートメンバを示す

### 1.6 リテラル

#### 1.6.1 整数

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 浮動小数点数

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 文字列

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 コレクション

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Array       ::= '[' Expr (',' Expr)* ']'   // 目標型注釈がArray(T, N)の場合リテラルは固定長配列に着地
```

> **辞書リテラルは少なくとも1つのキーと値のペアを要求する**：`{}`
> は**空辞書ではない**——空ブロック（値 `Void`、
> [§2.9](#_2-9-ブロック式)参照）である。空辞書にはコンストラクタ `dict.new()` を使用すること：
>
> ```yaoxiang
> empty = dict.new()                  // ✅ 空辞書
> d = { "a": 1 }                       // ✅ 辞書リテラル
> wrong = {}                           // ❌ これは辞書ではなく、空ブロック（Void）
> ```
>
> **判定基準は内容**：`Dict` 文法は少なくとも1つの `String ':' Expr` を要求し、`{}`
> には判定材料がないため、ブロック構造のゼロ形態を取る。非空形態は内容が自己記述する（`{ "k": v }`
> にキーと値のペアがある → 辞書）——`f = { 5 }` が関数ではなく `Int`
> 値であることと同源である：**型は内容によって決定される**。

> Setにはリテラル文法もランタイム表現もない——コレクション型計画では、需要が発生した際にDictパターンに従って補完する（std.set +
> HeapValue::Set）。List/Dictリテラルの着地点はコンテキスト型注釈によって決定される：素のリテラルと
> `List(T)` 注釈は拡張可能リストに着地し；`Array(T, N)`
> 注釈がリテラルに直接作用する場合は固定長配列に着地する。暗黙的なList→Array変換は禁止。
>
> Arrayリテラルのセマンティクス：
>
> - 要素数はNと等しくなければならない。等しくない場合はコンパイル時にE1002；空リテラルに非ゼロのNを割り当てる場合も同様に拒否
> - 各要素の型はTと互換性がなければならない。互換性がない場合はコンパイル時にE1002
> - Nの文法形態：整数リテラル（負の値も可）または定数名のみ。複合式（例：`2+1`）は解析時に拒否
> - Nがシンボリック定数（関数のconst引数、例：`Array(Int, n)`）の場合、個数検査は型精化段階まで延期
> - v1のネストされた配列リテラル（`Array(Array(Int,2),2) = [[1,2],[3,4]]`）はコンパイル時に拒否され、層ごとに明示的に構築する必要がある。再帰的な着地点は将来のバージョンに持ち越す

#### 1.6.5 リスト内包表記

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

> **動作の厳格化（移行記録）**：反復変数の文法は元々 `'for' Identifier 'in'`
> だが、旧実装ではpatternが完全なpratt解析を行っていた——`'in'` が中置演算子として登録された後、 `x`
> は `in items`
> をmembership式として飲み込んでいた。修正後は非識別子patternは直接解析に失敗し、旧実装のように `_`
> にフォールバック（エラーを静かに飲み込む）しなくなった。影響範囲：以前は解析できていた
> `[x for (a, b) in pairs]`
> のような書き方は現在エラーを返す——この形態は定義された動作を持たなかった（変数は常に
> `_`）、厳格化の方向は正しく、意味的な移行コストはない。

#### 1.6.6 メンバーシップ検査

```
Membership  ::= Expr 'in' Expr
```

> `in` は二項関係演算子で、`Bool` を返す——ヒットすれば `true`、ヒットしなければ `false`
> で、エラーは返さない。意味の分割：`[]` は存在を表明して値を取り出す（失敗でエラー）、 `in`
> は是否存在問う（ヒットしないのは正常な `false`）。右被演算子の対象：List / Array / Dict(キー集合)
> / Tuple / String(部分文字列) / Range(区間)。`in`
> は第一級のホール述語であり、型精化段階でコンパイル時に証明可能な命題の基礎となる。（Setは右被演算子リストから除外——Setにはランタイム表現がない、§1.6.4参照）

### 1.7 コメント

```
// 単行コメント

/* 複数行コメント
   複数行に渡ることができる */
```

### 1.8 インデント規則

コードは4つのスペースでインデントしなければならず、Tab文字の使用は禁止されている。これは強制的な文法規則である。

## 第二章：文法規則

### 2.1 式の分類

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 演算子の優先順位

| 優先順位 | 演算子                      | 結合性   |
| -------- | --------------------------- | -------- |
| 1        | `()` `[]` `.` `?`           | 左から右 |
| 2        | `as`                        | 左から右 |
| 3        | 単項前置 `!` `-` `+`        | 右から左 |
| 4        | `*` `/` `%`                 | 左から右 |
| 5        | `+` `-`                     | 左から右 |
| 6        | `..`                        | 左から右 |
| 7        | `<<` `>>`                   | 左から右 |
| 8        | `&` `\|` `^`                | 左から右 |
| 9        | `==` `!=` `<` `>` `<=` `>=` | 左から右 |
| 10       | `and` `or`                  | 左から右 |
| 11       | `if...else`                 | 右から左 |
| 12       | `=` `+=` `-=` `*=` `/=`     | 右から左 |

> **単項前置演算子**（`!` `-`
> `+`）は強い結合を持つ：呼び出しとメンバーアクセスより低く、すべての二項演算子より高い。したがって
> `!a == b` ≡ `(!a) == b`（Zig式のセマンティクス）；`!`
> は純粋な単項演算であり、短絡制御フローには参加せず、`and`/`or`
> キーワード（短絡）とは直交する（RFC-010の権威ある定義）。

> **Range の結合力**：`..` の結合力 (6,
> 7)——左 6 は加算（7）より低く、右 7 は加算を飲み込むが同レベルの `..`
> は飲み込まない。変更前後の対照：
>
> | 式           | 変更前（レベル 1、右結合）                                                                | 変更後（(6,7)、左結合）                                      |
> | ------------ | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
> | `x in 1..10` | `x in 1..10`（`in` の右被演算子レベル 4、`..` レベル 1 では飲み込めず、実際には解析不可） | `x in (1..10)`——区間全体が `in` の右被演算子                 |
> | `0..n+2`     | `(0..n)+2`（右結合の落とし穴：上界が食べられ、`for` ループが直接 E3004）                  | `0..(n+2)`——上界は算術式                                     |
> | `a == b..c`  | `a == (b..c)`（`..` レベル 1 < `==` レベル 3、最初から全体）                              | `a == (b..c)`——**意味は不変**、`..` は比較レベルより依然高い |
> | `1..2*3`     | `(1..2)*3`                                                                                | `1..(2*3)`——上界は算術式                                     |
> | `a..b..c`    | `a..(b..c)`（右結合チェーン、意味のないRangeの入れ子）                                    | `(a..b)..c`——**step 形態**（`c` はステップ）                 |
>
> 純効果：複合上界 `for i in 0..n+2` が「解析成功だが E3004」から「直接使用可能」に； `x in 1..10`
> が「解析不可」から「区間チェック」に；`a..b..c`
> が「無意味な入れ子」から「step 成分」に。レベル 6 は `+`（レベル 5）と
> `<<`（レベル 7）の間にあり、数学的慣例：区間は強い結合の構造であり、上界は当然完全な算術式である。

### 2.9 ブロック式

```
Block       ::= '{' Stmt* Expr? '}'
```

> **文の終端規則**：Stmt間の区切りと改行の挙動（`;`
> による明示的区切り、改行での終端、継続行の例外、行頭の `(`/`[` は決してマージしない）は
> [RFC-038](../design/rfc/draft/038-statement-termination.md) で定義されている。

#### 2.9.1 `{` の3つの形態

式の位置での `{` はちょうど3つの解釈を持ち、**内容**によって一度だけ判定される：

| 形態             | 記法              | 型           | 例               |
| ---------------- | ----------------- | ------------ | ---------------- |
| **空ブロック**   | `{}`              | `Void`       | `x: Void = {}`   |
| **辞書リテラル** | `{ "k": v, ... }` | `Dict(K, V)` | `d = { "a": 1 }` |
| **ブロック**     | `{ Stmt* Expr? }` | 末尾式の型   | `y = { 1 + 1 }`  |

**判定順序**：

1. `{}`（内容なし）→ **空ブロック**、値 `Void`
2. 最初の要素が `String ':' Expr` のキーと値のペア → **辞書リテラル**
3. その他 → **ブロック**、値は末尾式で与えられる

> **なぜ `{}` は空辞書ではないか**：空辞書の「空」は自己記述できない（`Dict(K, V)`
> にも空ブロックにもなり得る）、一方辞書文法 [§1.6.4](#_1-6-4-集合)
> は少なくとも1つのキーと値のペアを要求する。判定材料がない場合はブロック構造のゼロ形態を取る：これは
> `unsafe {}` / `spawn {}` と一致し、特別な場合を導入しない。空辞書には `dict.new()` を使う。
>
> **なぜ関数には注釈が必要か**：`f = { stmt }`
> は**値**（末尾式の型）であり、関数ではない。関数を定義するには Fn 注釈を明示する：`f: () -> Int = { 5 }`。これは辞書と同じ原則である：**型は内容によって決定され**、注釈の存在有無によっては決定されない。（この規則は
> [RFC-010a](./design/rfc/accepted/010a-tail-expression-and-return.md) 付録 D を参照。）

**統一セマンティクス**：すべての `{}` ブロックの値は**末尾式**によって与えられ、`return` は `Never`
型の非ローカル退出である。

| ブロックタイプ | 値出口 | 空ブロック `{}` |
| -------------- | ------ | --------------- |
| 通常 `{}`      | 末尾式 | `Void`          |
| `unsafe {}`    | 末尾式 | `Void`          |
| `spawn {}`     | 末尾式 | `Void`          |

**核心原則**（詳細は [RFC-010a](../design/rfc/accepted/010a-tail-expression-and-return.md) 参照）：

- **ブロックの値 = 末尾式**（最後の式）、唯一の出口、例外なし
- 末尾が**代入文**の場合、ブロックの値は `Void`；`Void` を望むなら明示的に `Void` と書く
- **`return` は最も近い関数境界を退出する**（すべてのブロックを貫通し、ブロックに「返さない」）、型
  `Never`；`Never <: T`
  は任意の型に対して成立（爆発原理）、したがって任意のリターン型の位置に現れることができる
- 式形式 `= expr` は直接値を与える

```yaoxiang
// 通常の {} ブロック：末尾式が値を与える
result = {
    x = compute()
    x                // ブロックの値
}

// unsafe {} ブロック：末尾式が型定義を与える
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    SqliteDb         // ブロックの値
}

// spawn {} ブロック：末尾式が結果を与える
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    (result1, result2)   // ブロックの値
}

// return：ブロックを貫通し、関数を退出する
f: (n: Int) -> Int = {
    if n < 0 {
        return 0     // ifと関数本体を貫通し、関数を退出
    }
    n * 2            // 末尾式
}
```

#### `name = { ... }` は関数かブロック値か？

`name = { ... }`
は関数定義（RFC-007「ゼロ引数最簡」）にもブロック値バインディングにもなり得る。**注釈優先、デフォルト関数**の裁定に従う（RFC-010a 付録D）：

| 場合                | 結果           | 例                                 |
| ------------------- | -------------- | ---------------------------------- |
| 値が Lambda（`=>`） | 関数           | `f = () => 5` → `f()` = 5          |
| 注釈が関数型        | 関数           | `f: () -> Int = { 5 }` → `f()` = 5 |
| 注釈が非関数型      | **ブロック値** | `x: Int = { 5 }` → `x` = 5         |
| 注釈なし            | 関数           | `f = { 5 }` → `f()` = 5            |

**注釈は即ち型**：`x: Int = ...` は `x` が `Int` であることを宣言し、`{ ... }` は `Int`
として評価される； `f: () -> Int = ...` は `f` が関数であることを宣言し、`{ ... }`
は関数本体である。

`{ ... }` をその場で評価したい場合、**目標型を記述するだけでよい**（新しい文法は不要）：

```yaoxiang
// ブロック値：即時評価
x: Int = {
    y = 5
    y            // x = 5
}

// 関数：注釈なしはデフォルト
f = { 5 }        // f() = 5
```

#### ネストされた関数型：カリー化か関数返却か？

`->` の右側のネストされた関数型には2つの読み方があり、**括弧**で区別する（RFC-004）：

| 書き方                          | 意味         | 呼び出し            |
| ------------------------------- | ------------ | ------------------- |
| `(a: Int) -> (b: Int) -> Int`   | **カリー化** | `f(1)(2)`           |
| `(a: Int) -> ((b: Int) -> Int)` | **関数返却** | `g(1)` で関数を得る |

根拠：**注釈は即ち型**。`g: (a: Int) -> ((b: Int) -> Int)` は `g(1) : (b: Int) -> Int`
を宣言するので、 `g(1)` は「次の引数」ではなく**その関数そのもの**でなければならない。

```yaoxiang
// カリー化：2段の引数を逐次与える
add: (a: Int) -> (b: Int) -> Int = { a + b }
add(1)(2)        // → 3

// 関数返却：外側は1段の引数、返されるのが関数
adder: (n: Int) -> ((x: Int) -> Int) = (x) => x + n
adder(10)(5)     // → 15
h = adder(10)    // 返された関数は変数に保存したり、渡したりできる
```

括弧なしのネストされた `Fn` はすべてカリー化（RFC-011の型引数形式を含む）：

```yaoxiang
identity: (T: Type) -> (x: T) -> T = (x) => x   // カリー化
identity(5)      // → 5
```

**型検査**：括弧はリターン型を宣言し、本体はその型を生成しなければならない。
`f: () -> (() -> Int) = { 7 }` はエラー——期待 `() -> Int`、実際は `Int`（E1002）。

### 2.10 Lambda 式

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 エラー伝播演算子

```
ErrorPropagate ::= Expr '?'
```

`?` 演算子は後置演算子で、優先順位は `.` と同レベルである。`Result(T, E)` 型に対して：

- `Ok(v)` の場合は値 `v` を抽出して実行を継続する
- `Err(e)` の場合はエラーを上に伝播する（`return Err(e)`）

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // 成功時は値を抽出し、失敗時は上に伝播
    transform(validated)
}
```

### 2.12 範囲式

```
RangeExpr   ::= Expr '..' Expr ('..' Expr)?
```

`..` は範囲値を作成する（Range は第一級値であり、構文糖ではない）。

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]

// Range は値：バインド、受け渡し、メンバー判定
r = 1..10
assert.assert(5 in r, "membership")
for i in r { print(i) }

// step 形態（第三成分、デフォルト 1）
for i in 0..10..2 { print(i) }  // 0, 2, 4, 6, 8
for i in 10..0..(-2) { print(i) }  // 10, 8, 6, 4, 2
```

> **step のセマンティクス**：`a..b..c` の `c` はステップ長。`c = 0`
> のリテラルはコンパイル時に拒否；動的 `c`
> の実行時ゼロチェック（E6001ファミリ；エラーシステム実装後にResultに格上げ）。 `c < 0`
> は有効で、区間方向は符号に応じて反転する（`10..0..(-2)` は降順）。

### 2.13 ref 式

```
RefExpr     ::= 'ref' Expr
```

`ref`
は共有所有を作成する。コンパイラが自動的にRc（単一タスク）またはArc（タスク間）を選択し、ユーザは実装詳細を気にする必要はない。

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // タスク間：コンパイラが自動的に Arc を選択
```

### 2.14 unsafe 式

```
UnsafeExpr  ::= 'unsafe' Block
```

`unsafe` ブロックは不透明型の定義と生ポインタの操作に使用される。`return`
を使用して型定義を上位スコープに返す。

**セマンティクス**：

- `unsafe {}` 内で型を定義し、生ポインタを操作できる
- 返された型は `unsafe {}` 外で使用可能
- 型のフィールドアクセスにはunsafe権限が必要

```yaoxiang
// unsafe ブロック内で不透明型を定義
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // 生ポインタ
    }
    return SqliteDb
}

// SqliteDb は unsafe ブロック外で使用可能
db = sqlite3_open("test.db")
```

### 2.15 スコープ

**基本規則**：

- 各 `{}` ブロックはスコープを作成する
- 内側スコープは外側スコープの変数にアクセスできる
- 外側スコープは内側スコープの変数にアクセスできない
- 変数宣言は「代入優先」原則に従う

```yaoxiang
// ブロックスコープ
{
    x = 10
    // x はこのスコープ内で可視
}
// x はこのスコープ外では不可視

// 関数スコープ
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result は関数外では不可視
```

**変数宣言とシャドウイング**：

- `x = value`：スコープチェーンに沿って外側に x を検索し、見つかれば代入、見つからなければ新規宣言
- `mut x = value`：明示的な新しい可変宣言、外側と同名は禁止
- 同じスコープ内で同じ名前を宣言できるのは1回のみ

> **詳細定義**：スコープの完全な規則、変数宣言とシャドウイングのメカニズムについては
> [モジュールシステム仕様](./modules.md#第四章作用域) を参照。

### 3.3 return 文

```
ReturnStmt  ::= 'return' Expr?
```

**セマンティクス**：`return`
は**非ローカル退出**であり、最も近い**関数境界**を退出する（すべてのブロックを貫通する——`if` /
`while` / `for` / `match` / 素のブロック / `spawn` / `unsafe`
を含む）、値を呼び出し元に渡す。これは**ブロックに「返さない」**。

**型**：`return e : Never`（`e : T`）。`Never <: T'` は任意の `T'` に対して成立（爆発原理、
[型システム §2.2](./type-system.md) 参照）、したがって `return`
は任意のリターン型の位置に現れることができ、追加の規則制約は不要。

**ブロック評価との関係**：ブロックの値は常に**末尾式**である（§2.9参照）。`{ return n }`
をブロックとすると、その値は `n` で型は `Never`；同時に `return`
の作用は関数の退出である。**両方のことが同時に成立し**、爆発原理によって共存する。

`return` と末尾式は共同で「早期リターン」を成立させ、`return`
が関数を特称する追加規則は不要である——[RFC-010a](../design/rfc/accepted/010a-tail-expression-and-return.md)
を参照。

```yaoxiang
factorial: (n: Int) -> Int = {
    if n <= 1 {
        return 1          // ifを貫通し、関数を退出（型 Never）
    }
    n * factorial(n - 1)  // 末尾式 = ブロックの値
}
```

### 3.4 break 文

```
BreakStmt   ::= 'break'
```

**セマンティクス**：所属する最も内側の `while`/`for`
ループを直ちに終了し、制御をそのループ本体の後へ移す。

- **最も近い1層のみを出る**：`break`
  は常にそれを含む最も内側のループに作用する。ネストしたループで複数層を一度に抜ける必要がある場合は、内側ループを関数として抽出し
  `return`
  で返すか、フラグを使用する（break/continueにはラベルがない；将来ループラベルを導入する場合は、ループ宣言側の文法に従ってRFCプロセスを進め、証明パイプラインの複数出口設計と共に裁定する）
- **ループ体内のみ**：`break` は `while`/`for`
  ループ体内（体内にネストされたブロック/if/matchを含む）にのみ出現でき、ループ外に出現した場合はコンパイルエラー（E1102
  `'break' outside of a loop`）
- **停止性証明に影響しない**：`while`
  ループは依然として停止が証明可能でなければならない（decreasesメトリック）；`break`
  は停止性の論証に参加せず、`while true { break }` は受理されない
- **借用セマンティクス**：breakの制御フロー辺はRFC-009aの逆方向BFS活性分析の構造的切断に参加する（抜けたイテレーションは逆辺活性導出に参加しない）

```yaoxiang
mut i = 0
while i < 10 {
    i = i + 1
    if i == 3 {
        break              // 制御がループ後に移動、i == 3
    }
}

// ネストしたループ：break は内側のみを抜ける
while j < 3 {
    while k < 10 {
        if k == 2 { break }    // 内側ループのみを終了
    }
    j = j + 1                  // 外側イテレーションの各ラウンドでここに到達
}
```

### 3.5 continue 文

```
ContinueStmt::= 'continue'
```

**セマンティクス**：現在のイテレーションの残りの文をスキップし、所属する最も内側のループの次のラウンドに直接入る——
`while` は条件再評価に戻り、`for` は次の要素を取り出す。

- **最も近い1層のみに作用**：`break` と同様、ラベルなし
- **ループ体内のみ**：ループ外に出現した場合はコンパイルエラー（E1102）

```yaoxiang
mut sum = 0
mut n = 0
while n < 5 {
    n = n + 1
    if n == 3 {
        continue           // 下の累算をスキップ、n == 3 は加算されない
    }
    sum = sum + n
}
// sum == 12（1 + 2 + 4 + 5）
```

ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block

#### 3.9.1 セマンティクス：各イテレーションは新しい値をバインドする

YaoXiangの for ループのセマンティクスは従来の言語とは異なる：**各イテレーションは同じ変数を変更するのではなく、新しい値をバインドする**。

```yaoxiang
// 例：for i in 1..5
for i in 1..5 {
    print(i)
}
```

**実行プロセス**：

| イテレーション | ループ変数の挙動                                                                           |
| -------------- | ------------------------------------------------------------------------------------------ |
| 1回目          | 新しいバインド `i = 1` を作成し、ループ本体が実行され、1を出力                             |
| 2回目          | 新しいバインド `i = 2` を作成し（以前のバインドは破棄済み）、ループ本体が実行され、2を出力 |
| 3回目          | 新しいバインド `i = 3` を作成し、ループ本体が実行され、3を出力                             |
| 4回目          | 新しいバインド `i = 4` を作成し、ループ本体が実行され、4を出力                             |
| 終了           | ループ本体が終了し、バインドが破棄                                                         |

**重要な点**：各イテレーション終了後、そのイテレーションで作成されたバインドは破棄される。次のイテレーションは完全に新しいバインドであり、前のイテレーションのバインドとは一切関係がない。

#### 3.9.2 for と for mut の違い

| 文法                | ループ変数の可変性 | 説明                           |
| ------------------- | ------------------ | ------------------------------ |
| `for i in 1..5`     | 不変               | ループ体内でバインドを変更不可 |
| `for mut i in 1..5` | 可変               | ループ体内でバインドを変更可能 |

```yaoxiang
// 合法：各イテレーションで新しい値をバインドするため、変更不要
for i in 1..5 {
    print(i)  // i の値を読み取る
}

// エラー：不変バインド、変更不可
for i in 1..5 {
    i = i + 1  // エラー：不変バインドを変更できない
}

// 合法：for mut を使用すれば変更可能
for mut i in 1..5 {
    i = i + 1  // 変更可能
}
```

#### 3.9.3 シャドウイング検査

YaoXiangは変数のシャドウイングを禁止する。for ループ変数は外側スコープの変数と同名にできない：

```yaoxiang
// エラー：i はすでに外部で宣言済み
i = 10
for i in 1..5 {
    print(i)
}

// 正しい：異なる変数名を使用
i = 10
for j in 1..5 {
    print(j)
}
```

この規則はすべてのコードブロックに適用される。詳細は
[4.3 シャドウイング規則](./modules.md#43-遮蔽规则) を参照。

#### 3.9.4 他の言語との比較

| 言語     | for ループ変数のセマンティクス             |
| -------- | ------------------------------------------ |
| YaoXiang | 各イテレーションで新しい値をバインド       |
| Rust     | 同じ変数を変更（mut が必要）               |
| Python   | 同じ変数を変更（mut 不要）                 |
| C/C++    | 同じ変数を変更（ポインタまたは参照が必要） |

**設計根拠**：YaoXiangがバインディングセマンティクスを採用する理由は：

1. **より自然なセマンティクスに適合**
   自然言語では、「集合の各要素 x について」は各 x が独立した個体であることを意味する。YaoXiangの
   `for i in 1..5`
   は「1から5の各 i について」と読まれ、各イテレーションの i は完全に新しいバインディングであり、これは人間の直感的理解と一致する。

2. **偶発的な変更を避ける**
   デフォルトの不変バインディングセマンティクスは、ループ本体内でループ変数を偶発的に変更できないことを意味する。複雑なループ本体内で誤って
   `i = ...` と書いて追跡困難なバグが発生する心配がない。

3. **高性能ソリューションに手が届く**
   イテレーション間で変数を実際に再利用する必要がある場合（アキュムレータ、キャッシュなど）、`for mut`
   宣言を使用すれば可変バインディングモードに切り替えられる。これは暗黙の共有状態より明確である——意図は構文によって明示的に表現され、ランタイム動作に隠されることはない。

### 3.10 spawn 文

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**spawn ブロック**：並行境界を明示的に宣言し、ブロック内の式を並行実行する。

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**spawn ループ**：データ並列ループ。

```yaoxiang
results = spawn for item in items {
    process(item)
}
```

**spawn ブロックは外側の変数をキャプチャする**（RFC-024 §2.3、値キャプチャのセマンティクス）：

- ブロック本体が外側変数を参照 =
  **Move値キャプチャ**：値はspawn作成時点でクロージャ環境にスナップショットされ、ブロック本体はenv経由で読み取る（LoadUpvalue）
- **プリミティブ**（Int/Float/Bool/Char）は値をコピーし、外側変数は影響を受けない
- **ハンドル型**（Struct/String/List等）のスナップショット = ハンドルのコピー、基になるオブジェクトを共有；Embeddedランタイム（デフォルト）では同じスレッド同じヒープで、ハンドルは有効
- 複数タスク間での共有には明示的な `ref` が必要（§2.13、コンパイラが自動的にRc/Arcを選択）
- ブロック内の `return` が参照する外側変数も同様にキャプチャされる

```yaoxiang
t1 = 1 + 1
t2 = 2 + 2
result = spawn {
    return t1 + t2    // t1/t2 は値キャプチャ、result == 6
}
```

### 3.11 プログラム入口とトップレベル文

ソースファイルはコンパイラの視点で2つの役割を持ち、**`yaoxiang.toml`
の存在有無によって決定される**：

| 役割       | 判定                                       | プログラム本体                                                    |
| ---------- | ------------------------------------------ | ----------------------------------------------------------------- |
| **Script** | 単一ファイル直接実行、`yaoxiang.toml` なし | **トップレベル文**（記述順に実行）；`main` は通常のバインディング |
| **Bin**    | `yaoxiang.toml` が存在                     | **`main` 関数**；トップレベルに実行可能文は不可                   |

#### Script：トップレベル文がそのままプログラム

manifestがない場合、ファイルは「スクリプト」であり、**トップレベル文は記述順に実行される**：

```yaoxiang
use std.io
io.println("hello")          // 直接実行
x: Int = { 42 }              // トップレベルバインディング：ランタイムで初期化
io.println(x)                // 42
```

このモードでは `main` は**特別ではない**——通常のバインディングに過ぎない。`main`
を実行するには、明示的に呼び出す必要がある：

```yaoxiang
use std.io
main: () -> Void = { io.println("only runs if called") }

main()                       // ← この行を必ず書く
```

> **なぜ `main` を自動的に呼び出さないのか？**
> トップレベル文がすでにプログラム本体である。さらに暗黙的に `main` を呼び出すと、明示的に `main()`
> を書いたスクリプトは2回実行されることになる。2つのルールは共存できないため、Scriptモードでは「トップレベル文」という1つの実行入口のみとなる。

#### Bin：`main` が入口

manifestがある場合、ファイルは「実行可能ターゲット」であり、この場合：

- `main`
  を定義しなければならず、それは関数でなければならない（シグネチャは引数なしで呼び出し可能である必要がある）
- トップレベルに実行可能文は許可されない——プログラム本体が `main` である

```yaoxiang
main: () -> Void = {
    print("hello")
}
```

`main` が欠落している場合や `main` が関数でない場合はコンパイルエラー（前者：`main`
がない場合すべての関数は到達不能；後者：値バインディングは呼び出されない）。

> **ライブラリファイル**：他のファイルから `use` されるファイル、または `[lib].path` / `[exports]`
> が指すファイルは `main` を必要としない——これらはプログラム入口ではない。

#### トップレベルバインディングの初期化

トップレベルバインディングの初期化値は**ランタイムで評価される**、コンパイル時定数である必要はない：

```yaoxiang
answer: Int = { 42 }              // ブロック値
inc: (Int) -> Int = (x) => x + 1
computed: Int = inc(41)           // 関数呼び出し
```

初期化は**依存順序**で実行され、記述順には依存しない：

```yaoxiang
derived: Int = base * 3           // 後で宣言される base を参照
base: Int = 7                     // 先に初期化（トポロジカルソート）
```

循環依存はコンパイルエラー（環上の名前が列挙される）：

```yaoxiang
a: Int = b + 1
b: Int = a + 1                    // エラー：a → b → a
```

> **設計根拠**：RFC-029f（ファイル役割モデル）、RFC-010a 付録D（ブロックバインディング裁定）。
