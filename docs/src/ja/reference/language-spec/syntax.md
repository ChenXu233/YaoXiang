# 文法仕様

本ファイルは YaoXiang プログラミング言語の文法仕様を定義する。字句構造、文法規則、演算子の優先順位を含む。

---

## 第一章：字句構造

### 1.1 ソースファイル

YaoXiang のソースファイルは UTF-8 エンコーディングでなければならない。ソースファイルの拡張子は通常
`.yx` である。

### 1.2 字句要素の分類

| カテゴリ   | 説明                             | 例                        |
| ---------- | -------------------------------- | ------------------------- |
| 識別子     | 文字またはアンダースコアで始まる | `x`, `_private`, `my_var` |
| キーワード | 言語が定義する予約語             | `Type`, `pub`, `use`      |
| リテラル   | 固定値                           | `42`, `"hello"`, `true`   |
| 演算子     | 演算記号                         | `+`, `-`, `*`, `/`        |
| 区切り子   | 文法上の区切り                   | `(`, `)`, `{`, `}`, `,`   |

### 1.3 キーワード

YaoXiang は極少量のキーワードを定義する：

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

これらのキーワードはいかなる文脈でも特別な意味を持ち、識別子として使用することはできない。

### 1.4 予約語

YaoXiang の「予約語」は 3 つの層に分かれており、それぞれパーサ（parser）と型検査器（type
checker）が異なる段階で識別する。

#### 1.4.1 リテラル予約語

パーサが独立したトークンとして扱うリテラルの識別子は、通常の識別子としては使用できない：

| 識別子  | 所属する型 | 説明                                                                                            |
| ------- | ---------- | ----------------------------------------------------------------------------------------------- |
| `Type`  | —          | メタ型キーワード                                                                                |
| `true`  | Bool       | 真偽値の真                                                                                      |
| `false` | Bool       | 真偽値の偽                                                                                      |
| `void`  | Void       | Void リテラル（Unit 値）。小文字の `void` は値リテラル、大文字の `Void` は型名（§1.4.3 参照）。 |

#### 1.4.2 コンストラクタ式

以下のコンストラクタは、パターン一致と式の文脈でパーサにより識別される：

| コンストラクタ | 所属する型 | 説明                      |
| -------------- | ---------- | ------------------------- |
| `some(T)`      | Option     | Option 値バリアントの構築 |
| `ok(T)`        | Result     | Result の成功バリアント   |
| `err(E)`       | Result     | Result のエラーバリアント |

#### 1.4.3 組み込み型名

以下の型名は型検査器によって事前登録されており、インポート不要で型の位置で使用できる。パーサはこれらを通常の識別子として扱う——**予約語ではなく、ローカルバインディングでシャドウ可能（推奨されない）**。

| 型名     | 論理的対応   | 説明                                                                                                                                      |
| -------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤（真/Unit） | ゼロフィールドの積型。ちょうど 1 つの居住者を持つ（`void` リテラル、§1.4.1 参照）                                                         |
| `Never`  | ⊥（偽/空型） | ゼロバリアントの総和型。居住者を持たない。`Never` 値を生成する式は存在しない。すべての `T` に対して `Never <: T` が成立する（爆発原理）。 |
| `Int`    | —            | 符号付き整数                                                                                                                              |
| `Float`  | —            | 浮動小数点数                                                                                                                              |
| `Bool`   | —            | 真偽値：`true` / `false`                                                                                                                  |
| `Char`   | —            | Unicode 文字                                                                                                                              |
| `String` | —            | 文字列                                                                                                                                    |

### 1.5 識別子

識別子は文字またはアンダースコアで始まり、続く文字は文字、数字、またはアンダースコアであることができる。識別子は大文字と小文字を区別する。

特殊な識別子：

- `_` はプレースホルダとして使われ、値を無視することを表す
- アンダースコアで始まる識別子はプライベートメンバーを表す

### 1.6 リテラル

#### 1.6.1 整数

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 浮動小数点数

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 文字列

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 コレクション

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Set         ::= '{' Expr (',' Expr)* '}'
```

#### 1.6.5 リスト内包表記

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

#### 1.6.6 メンバーシップテスト

```
Membership  ::= Expr 'in' Expr
```

### 1.7 コメント

```
// 単一行コメント

/* 複数行コメント
   複数行にまたがることができる */
```

### 1.8 インデント規則

コードは 4 つのスペースでインデントしなければならず、Tab 文字の使用は禁止されている。これは必須の文法規則である。

## 第二章：文法規則

### 2.1 式の分類

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 演算子の優先順位

| 優先順位 | 演算子                      | 結合性   |
| -------- | --------------------------- | -------- |
| 1        | `()` `[]` `.` `?`           | 左から右 |
| 2        | `as`                        | 左から右 |
| 3        | 単項前置 `!` `-` `+`        | 右から左 |
| 4        | `*` `/` `%`                 | 左から右 |
| 5        | `+` `-`                     | 左から右 |
| 6        | `..`                        | 左から右 |
| 7        | `<<` `>>`                   | 左から右 |
| 8        | `&` `\|` `^`                | 左から右 |
| 9        | `==` `!=` `<` `>` `<=` `>=` | 左から右 |
| 10       | `and` `or`                  | 左から右 |
| 11       | `if...else`                 | 右から左 |
| 12       | `=` `+=` `-=` `*=` `/=`     | 右から左 |

> **単項前置演算子**（`!` `-`
> `+`）は強い結合を持つ：呼び出しとメンバーアクセスより低く、すべての二項演算子より高い。したがって
> `!a == b` ≡ `(!a) == b`（Zig 風のセマンティクス）となる。`!`
> は純粋な単項演算であり、短絡制御フローには参加しない。短絡を行う `and`/`or`
> キーワードとは直交する（RFC-010 で権威的に定義）。

### 2.3 関数呼び出し

```
FnCall      ::= Expr '(' ArgList? ')'
ArgList     ::= Expr (',' Expr)* (',' NamedArg)* | NamedArg (',' NamedArg)*
NamedArg    ::= Identifier ':' Expr
```

### 2.4 メンバーアクセス

```
MemberAccess::= Expr '.' Identifier
```

### 2.5 インデックスアクセス

```
IndexAccess ::= Expr '[' Expr ']'
```

### 2.6 型変換

```
TypeCast    ::= Expr 'as' TypeExpr
```

### 2.7 条件式

```
IfExpr      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 2.8 パターン一致

```
MatchExpr   ::= 'match' Expr '{' MatchArm+ '}'
MatchArm    ::= Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
Pattern     ::= Literal
              | Identifier
              | Wildcard
              | StructPattern
              | TuplePattern
              | EnumPattern
              | OrPattern
```

### 2.9 ブロック式

```
Block       ::= '{' Stmt* Expr? '}'
```

> **文の終端規則**：Stmt の間の区切りと改行の振る舞い（`;`
> による明示的区切り、改行終端、継続行の例外、行頭の `(`/`[` は決して連結しない）は
> [RFC-038](../design/rfc/draft/038-statement-termination.md) で定義される。

**統一セマンティクス**：すべての `{}` ブロックの return セマンティクスは一貫している：

| ブロック種別 | return セマンティクス | デフォルト戻り値 |
| ------------ | --------------------- | ---------------- |
| 通常の `{}`  | 値を返す              | Void             |
| `unsafe {}`  | 型定義を返す          | Void             |
| `spawn {}`   | 結果を返す            | Void             |

**コア原則**：

- `{}` の中の `return` は常にその内容を外側のスコープに返す
- `return` がない場合のデフォルトは `Void` を返す
- 式形式 `= expr` は直接その値を返す

```yaoxiang
// 通常の {} ブロック：return は値を返す
result = {
    x = compute()
    return x  // 値を外側のスコープに返す
}

// unsafe {} ブロック：return は型定義を返す
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    return SqliteDb  // 型定義を外側のスコープに返す
}

// spawn {} ブロック：return は結果を返す
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    return (result1, result2)  // 結果を外側のスコープに返す
}
```

### 2.10 ラムダ式

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 エラー伝播演算子

```
ErrorPropagate ::= Expr '?'
```

`?` 演算子は後置演算子であり、優先順位は `.` と同等である。`Result(T, E)` 型に対して：

- `Ok(v)` の場合は値 `v` を取り出して実行を継続する
- `Err(e)` の場合はエラーを上位に伝播する（`return Err(e)`）

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // 成功時は値を取り出し、失敗時は上位に伝播
    transform(validated)
}
```

### 2.12 範囲式

```
RangeExpr   ::= Expr '..' Expr
```

`..` は範囲型を生成し、`for` ループやスライスに使用される。

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]
```

### 2.13 ref 式

```
RefExpr     ::= 'ref' Expr
```

`ref`
は共有所有を作成する。コンパイラが自動的に Rc（単一タスク）または Arc（タスク間）を選択し、ユーザーは実装の詳細を気にする必要はない。

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // タスク間：コンパイラが自動的に Arc を選択
```

### 2.14 unsafe 式

```
UnsafeExpr  ::= 'unsafe' Block
```

`unsafe` ブロックは不透明型の定義と生ポインタの操作に使用される。`return`
を使って型定義を外側のスコープに返す。

**セマンティクス**：

- `unsafe {}` の中では型を定義し、生ポインタを操作できる
- 返された型は `unsafe {}` の外側で使用可能
- 型のフィールドアクセスには unsafe 権限が必要

```yaoxiang
// unsafe ブロック内で不透明型を定義
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // 生ポインタ
    }
    return SqliteDb
}

// SqliteDb は unsafe ブロックの外側で使用可能
db = sqlite3_open("test.db")
```

### 2.15 スコープ

**基本規則**：

- 各 `{}` ブロックがスコープを生成する
- 内側のスコープから外側のスコープの変数にアクセスできる
- 外側のスコープから内側のスコープの変数にはアクセスできない
- 変数宣言は「代入優先」原則に従う

```yaoxiang
// ブロックスコープ
{
    x = 10
    // x はこのスコープ内で参照可能
}
// x はこのスコープ外では参照不可

// 関数スコープ
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result は関数の外側では参照不可
```

**変数宣言とシャドウイング**：

- `x = value`：スコープチェーンを遡って x を検索し、見つかれば代入、見つからなければ新規宣言
- `mut x = value`：明示的に新しい可変宣言を行う。外側と同じ名前は禁止
- 同じスコープ内では同じ名前を 1 回しか宣言できない

> **詳細定義**：スコープの完全な規則、変数宣言、シャドウイング機構の詳細は
> [モジュールシステム仕様](./modules.md#第四章作用域) を参照。

## 第三章：文

### 3.1 文の分類

```
Stmt        ::= LetStmt
              | ExprStmt
              | ReturnStmt
              | BreakStmt
              | ContinueStmt
              | IfStmt
              | MatchStmt
              | WhileStmt
              | ForStmt
              | SpawnStmt
```

### 3.2 変数宣言

```
LetStmt     ::= ('mut')? Identifier (':' TypeExpr)? '=' Expr
```

### 3.3 return 文

```
ReturnStmt  ::= 'return' Expr?
```

**セマンティクス**：`return` はコードブロックから値を返すために使われる。`return`
がない場合、コードブロックはデフォルトで `Void` を返す。

### 3.4 break 文

```
BreakStmt   ::= 'break' Identifier?
```

### 3.5 continue 文

```
ContinueStmt::= 'continue'
```

### 3.6 if 文

```
IfStmt      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 3.7 match 文

```
MatchStmt   ::= 'match' Expr '{' MatchArm+ '}'
```

### 3.8 while 文

```
WhileStmt   ::= 'while' Expr Block
```

### 3.9 for 文

```
ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block
```

#### 3.9.1 セマンティクス：各反復は新しい値をバインドする

YaoXiang の for ループのセマンティクスは従来の言語と異なる：**各反復は新しい値をバインドするものであり、同じ変数を変更するものではない**。

```yaoxiang
// 例：for i in 1..5
for i in 1..5 {
    print(i)
}
```

**実行プロセス**：

| 反復   | ループ変数の振る舞い                                                            |
| ------ | ------------------------------------------------------------------------------- |
| 1 回目 | 新しいバインド `i = 1` を作成し、ループ本体を実行、1 を出力                     |
| 2 回目 | 新しいバインド `i = 2` を作成（以前のバインドは破棄済み）、本体を実行、2 を出力 |
| 3 回目 | 新しいバインド `i = 3` を作成し、ループ本体を実行、3 を出力                     |
| 4 回目 | 新しいバインド `i = 4` を作成し、ループ本体を実行、4 を出力                     |
| 終了   | ループ本体終了、バインドを破棄                                                  |

**要点**：各反復が終了すると、その反復で作成されたバインドは破棄される。次の反復は完全に新しいバインドであり、前の反復のバインドとはいかなる関係も持たない。

#### 3.9.2 for と for mut の違い

| 文法                | ループ変数の可変性 | 説明                             |
| ------------------- | ------------------ | -------------------------------- |
| `for i in 1..5`     | 不変               | ループ本体内でバインドを変更不可 |
| `for mut i in 1..5` | 可変               | ループ本体内でバインドの変更可   |

```yaoxiang
// 合法：各反復で新しい値をバインドするため変更不要
for i in 1..5 {
    print(i)  // i の値を読み取る
}

// エラー：不変バインドは変更不可
for i in 1..5 {
    i = i + 1  // エラー：不変バインドは変更できない
}

// 合法：for mut を使うとバインドの変更が許可される
for mut i in 1..5 {
    i = i + 1  // 変更が許可される
}
```

#### 3.9.3 シャドウイング検査

YaoXiang は変数シャドウイングを禁止する。for ループ変数は外側スコープの変数と同じ名前にできない：

```yaoxiang
// エラー：i はすでに外部で宣言されている
i = 10
for i in 1..5 {
    print(i)
}

// 正しい：異なる変数名を使う
i = 10
for j in 1..5 {
    print(j)
}
```

この規則はすべてのコードブロックに適用される。詳細は
[4.3 シャドウイング規則](./modules.md#43-遮蔽规则) を参照。

#### 3.9.4 他の言語との比較

| 言語     | for ループ変数のセマンティクス         |
| -------- | -------------------------------------- |
| YaoXiang | 各反復で新しい値をバインド             |
| Rust     | 同じ変数を変更（mut が必要）           |
| Python   | 同じ変数を変更（mut 不要）             |
| C/C++    | 同じ変数を変更（ポインタや参照が必要） |

**設計理由**：YaoXiang がバインドセマンティクスを採用する理由は以下の通りである：

1. **自然言語のセマンティクスにより合致する**
   自然言語において「集合の各要素 x について」は、各 x が独立した存在であることを意味する。YaoXiang の
   `for i in 1..5`
   は「1 から 5 の各 i について」と読まれ、各反復の i は完全に新しいバインドとなる。これは人間の直感的な理解と一致する。

2. **意図しない変更の防止**
   デフォルトで不変のバインドセマンティクスは、ループ本体内でループ変数をうっかり変更することができない。複雑なループ本体の中で誤って
   `i = ...` と書いてしまい、追跡困難なバグを引き起こす心配がない。

3. **高性能ソリューションへ容易にアクセス可能**
   実際に反復間で変数を再利用する必要（アキュムレータやキャッシュなど）がある場合は、`for mut`
   を使って明示的に可変バインドモードに切り替えればよい。これは暗黙の共有状態より明確である——意図が構文によって明示的に表現され、実行時の振る舞いに隠されることがない。

### 3.10 spawn 文

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**spawn ブロック**：並行領域を明示的に宣言し、ブロック内の式を並行実行する。

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**spawn ループ**：データ並列ループ。

```yaoxiang
results = spawn for item in items {
    process(item)
}
```

**spawn ブロックは外側の変数をキャプチャする**（RFC-024 §2.3、値キャプチャセマンティクス）：

- ブロック本体が外側の変数を参照する場合 =
  **Move 値キャプチャ**：値は spawn の作成時点でクロージャ環境にスナップショットされ、ブロック本体は env を介して読み取る（LoadUpvalue）
- **プリミティブ**（Int/Float/Bool/Char）は値がコピーされ、外側の変数は影響を受けない
- **ハンドル型**（Struct/String/List など）のスナップショット = ハンドルのコピーで、基底オブジェクトを共有する；Embedded ランタイム（デフォルト）では同じスレッドの同じヒープでハンドルが有効
- 複数のタスク間で共有するには明示的に `ref`
  を使う必要がある（§2.13、コンパイラが自動的に Rc/Arc を選択）
- ブロック内の `return` が参照する外側の変数も同様にキャプチャされる

```yaoxiang
t1 = 1 + 1
t2 = 2 + 2
result = spawn {
    return t1 + t2    // t1/t2 は値キャプチャされ、result == 6
}
```

## 付録：文法早見表

### A.1 制御フロー

```
if Expr Block (else if Expr Block)* (else Block)?
match Expr { MatchArm+ }
while Expr Block
for 'mut'? Identifier 'in' Expr Block
```

### A.2 エラー処理

```
Expr '?'              // エラー伝播（Result 型）
```

### A.3 match 文法

```
match value {
    pattern1 => expr1,
    pattern2 if guard => expr2,
    _ => default_expr,
}
```
