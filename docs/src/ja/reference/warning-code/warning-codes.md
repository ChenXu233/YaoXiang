# 警告コード

このドキュメントでは、YaoXiang コンパイラが生成する可能性のある警告コードについて説明します。警告はコンパイルを阻止しませんが、コードに潜在的な問題が存在する可能性を示します。

## 設定

警告の動作は `yaoxiang.toml` で設定できます：

```toml
[lint]
# デッドコード警告のレベル：off | warn | deny
dead-code = "warn"
```

- `off`：警告を無効化する
- `warn`：警告を表示する（デフォルト）
- `deny`：警告をエラーとして扱う

## 警告一覧

### W1001: 未使用のエクスポート関数

**原因**：エクスポートされた関数が、どのコードからも呼び出されていません。

```yaoxiang
pub dead_function: () -> Void = { }  // W1001: 未使用のエクスポート関数

main = {
    // dead_function は一度も呼び出されない
}
```

**推奨**：

- 関数を外部から使用する必要がない場合は、`pub` 修飾子を削除してください
- 関数を残す必要があるが未使用である場合は、設定で `dead-code = "off"` を指定してください

---

### W1002: 未使用のエクスポート型

**原因**：エクスポートされた型（型エイリアスまたはカスタム型）が一度も使用されていません。

**例**：

```yaoxiang
DeadType: Type = Int  // W1002: 未使用のエクスポート型

main = {
    x = 42
}
```

**推奨**：

- 型のエクスポートが必要で未使用である場合は、この警告を無視してください

---

### W1003: 未使用のインポート

**原因**：`use` 文でインポートされたモジュールまたはシンボルが一度も使用されていません。

```yaoxiang
use std.json  // W1003: 未使用のインポート

main = {
    // json モジュールは一度も使用されない
}
```

**推奨**：

- 未使用のインポートを削除してコードを綺麗に保ってください
- インポートを残す必要がある場合（副作用のため）、`use std.json.*`
  の使用やコメントによる説明の追加を検討してください

---

### W1004: 未使用のエクスポート変数

**原因**：`pub` でエクスポートされた変数が一度も読み取られていません。

**例**：

```yaoxiang
pub dead_var = 42  // W1004: 未使用のエクスポート変数

main = {
    // dead_var は一度も読み取られない
}
```

**推奨**：

- 不要な `pub` 修飾子を削除してください
- 変数のエクスポートが必要で未使用である場合は、この警告を無視してください

---

### W1005: 未使用のエクスポートメソッド

**原因**：型でエクスポートされたメソッドが一度も呼び出されていません。

**例**：

```yaoxiang
Foo: Type = { value: Int }

pub Foo.dead_method: (self: Foo) -> Void = { }  // W1005: 未使用のエクスポートメソッド

main = {
    foo = Foo(1)
    // dead_method は一度も呼び出されない
}
```

**推奨**：

- 不要な `pub` 修飾子を削除してください
- メソッドを残す必要があるが未使用である場合は、この警告を無視してください

---

### W1063: const ジェネリック制約が評価できない

**原因**：const ジェネリックパラメータの値制約がコンパイル時に評価できません。

**メッセージ**：``const ジェネリック制約が評価できません: `{constraint}` ({var} = {value})``

```yaoxiang
BadArray(Int, n)  // n はコンパイル時定数ではない
```

**推奨**：

- const パラメータがコンパイル時定数であることを確認してください

---

### W1080: コンパイル時証明の降格

**原因**：制約がコンパイル時に証明できず、実行時チェックに降格されました。

**メッセージ**：`コンパイル時に制約を証明できず、実行時チェックに降格されました`

**推奨**：

- 証明関数を追加して安全性を向上させることを検討してください

---

## 警告レベルの詳細

| レベル | 効果                                             |
| ------ | ------------------------------------------------ |
| `off`  | この警告を完全に無効化する                       |
| `warn` | 警告を表示してコンパイルを続行する（デフォルト） |
| `deny` | 警告をエラーとして扱い、コンパイルを阻止する     |

### 使用シナリオ

- **開発中**：`warn` レベルを使用してコード内の潜在的な問題を把握する
- **リリース前**：`deny` レベルを使用して未使用のコードがないことを確認する
- **レガシーコード**：`off` レベルを使用して警告を一時的に無視する

---

## エラーコードとの違い

警告コードは `W` 接頭辞（例：W1001）を使用し、エラーコードは `E` 接頭辞（例：E1001）を使用します。

- **エラー (Error)**：コンパイルを阻止し、必ず修正が必要
- **警告 (Warning)**：潜在的な問題を提示し、修正は任意
