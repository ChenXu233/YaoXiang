# 所有権モデル

YaoXiang はガベージコレクション（GC）もライフタイム注釈も使用しない。そのメモリ安全性は**5つの概念と1つのグラデーション**の上に成り立っている。

## 5つの概念、1つのグラデーション

```
ちら見/その場変更    持ち出し        共有保持         コピー作成        システムレベル
    │              │              │              │              │
   &T            Move           ref          clone()        unsafe
  &mut T         ゼロコピー      コンパイラ自動  明示的ディープコピー  *T
  ゼロサイズトークン デフォルト    Rc/Arc を選択  ユーザー責任
```

## Move：デフォルトの所有権移転

YaoXiang では、**代入 = 所有権移転**。これはデフォルトの振る舞いで、ゼロコピー：

```yaoxiang
p = Point(1.0, 2.0)
p2 = p              // Move! p の所有権は p2 に移る
                    // この後 p は読み取れない

// p2 を変更したい？mut を使う
mut p3 = Point(3.0, 4.0)
shift(p3, 1.0, 1.0)    // その場で変更
```

関数の引数渡しと戻り値も Move：

```yaoxiang
// 引数：Move で渡す
process: (p: Point) -> Point = {
    p.transform()
    p                  // Move で返す——ゼロコピー
}

// 呼び出し
p = Point(1.0, 2.0)
result = process(p)    // p は Move された
```

## &T / &mut T：借用トークン

所有権を持ち出したくない場合、一時的に「ちら見」（`&T`）や「その場で変更」（`&mut T`）だけで済ませたい場合、コンパイラが自動的に**ゼロサイズの借用トークン**を生成する：

```yaoxiang
data = [1, 2, 3, 4, 5]

// コンパイラが自動的に &List(Int) トークンを渡す——所有権は持ち出さない
print(data.len())    // 5
print(data)          // ✅ data はまだ存在する、ちら見しただけ
```

`&T` と `&mut T` は**ゼロサイズ型**——コンパイル時に存在し、ランタイムには消える。`&`
を手動で書く必要はなく、コンパイラが使用シーンに応じて自動的に判断する：

```yaoxiang
// 読み取り専用アクセス → 自動的に &T
print: (point: &Point) -> Void = {
    print("({point.x}, {point.y})")
}

// 可変変更 → 自動的に &mut T
shift: (point: &mut Point, dx: Float, dy: Float) -> Void = {
    point.x = point.x + dx
    point.y = point.y + dy
}

mut p = Point(1.0, 2.0)
print(p)                // &Point を渡す
shift(p, 1.0, 1.0)      // &mut Point を渡す
```

**重要な違い**：`&T` はコピー可能（共有読み取り専用）、`&mut T`
はコピー不可（排他的可変）。これは特別なルールではなく、**2つの型属性**である。

## ref：スコープを越えた共有

複数の場所で同時に値を保持する必要がある場合、`ref` を使う：

```yaoxiang
data = [1, 2, 3, 4, 5]

// ref は共有保持を作成する
shared = ref data

// コンパイラが自動的に参照カウンタを選択する：
// - タスクを跨がない → Rc（単一スレッド参照カウント）
// - タスクを跨ぐ → Arc（アトミック参照カウント）
spawn {
    use(shared)    // タスクを跨ぐ！コンパイラが自動的に Arc を使用
}

// Rc と Arc の違いを知る必要はない
// コンパイラが自動的に選択してくれる
```

## clone()：明示的ディープコピー

独立したコピーが必要な場合、明示的に `clone()` を呼び出す：

```yaoxiang
original = [1, 2, 3]
backup = original.clone()   // ディープコピー——独立したコピーを所有

// それぞれ独立
original[0] = 10
print(backup[0])    // 1——影響を受けない
```

`clone()`
は明示的である——コピーを明確に要求するものであって、一部の言語のようにデフォルトでコピーするわけではない。

## ライフタイムなし

YaoXiang にはライフタイム `'a` がない。この設計選択は重要な観察から来ている：

> 借用競合問題は本質的にホーア命題検証と等価である。これを型チェッカーの証明パイプラインに統一的に解決させ、別途の借用チェックフレームワークを必要としない。

`'a`
を注釈したり、ライフタイムを理解したりする必要はない——コンパイラが型チェックの段階で自動的に所有権の安全性を検証する。

## GC なし

所有権モデル全体にはガベージコレクションがない。すべてのメモリ解放のタイミングはコンパイル時に決定される：

- **Move 後** → 元の変数は使用不可になり、RAII が自動的に解放
- **ref 後** → 参照カウントがゼロになった時に解放
- **スコープ終了時** → スタック変数を自動的に解放

GC ポーズゼロ、ランタイムオーバーヘッドゼロ。

## まとめ

| 操作             | キーワード/構文  | コピー             | いつ使うか                 |
| ---------------- | ---------------- | ------------------ | -------------------------- |
| 所有権を持ち出す | デフォルトの動作 | ゼロコピー         | 関数引数、代入             |
| ちら見           | 自動 `&T`        | ゼロサイズトークン | 読み取り専用アクセス       |
| その場で変更     | 自動 `&mut T`    | ゼロサイズトークン | 可変変更                   |
| 共有保持         | `ref`            | 参照カウント       | スコープ越え/タスク越え    |
| 明示的コピー     | `.clone()`       | ディープコピー     | 独立したコピーが必要な場合 |
| 生ポインタ       | `unsafe` + `*T`  | 手動               | システムレベル操作         |

**覚えておいて**：Move がデフォルト、ref が共有、clone が例外。3つのルールで GC とは永遠におさらば。
