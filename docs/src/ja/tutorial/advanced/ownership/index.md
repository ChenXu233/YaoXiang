# 所有権モデル

YaoXiang は垃圾回收（GC）もライフタイム标注も用いません。そのメモリ安全は**五つの概念、一つのグラデーション**の上に確立されています。

## 五つの概念、一つのグラデーション

```
一瞬見る/その場で変更    奪い取る           共有保持         一部コピー        システムレベル
     │                  │                 │               │                │
    &T                Move              ref           clone()          unsafe
   &mut T             ゼロコピー        コンパイラが      明示的深コピー     *T
   ゼロサイズトークン    デフォルト        自動選択                       ユーザーは負責
                     Rc/Arc
```

## Move：デフォルトでの所有権移動

YaoXiang では、**代入 = 所有権の移動**です。これはデフォルトの動作で、ゼロコピーです：

```yaoxiang
p = Point(1.0, 2.0)
p2 = p              // Move! p の所有権が p2 に移動
                    // その後 p は読めなくなる

// p2 を変更したい？mut を使う
mut p3 = Point(3.0, 4.0)
shift(p3, 1.0, 1.0)    // その場で変更
```

関数への引数渡しも戻り値も Move です：

```yaoxiang
// 引数：Move で渡される
process: (p: Point) -> Point = {
    p.transform()
    p                  // Move で返す——ゼロコピー
}

// 呼び出し
p = Point(1.0, 2.0)
result = process(p)    // p は Move された
```

## &T / &mut T：借用トークン

所有権を奪いたくない，只是で「一瞬見たい」（`&T`）또는「その場で変更したい」（`&mut T`）場合、コンパイラは自動的に**ゼロサイズの借用トークン**を生成します：

```yaoxiang
data = [1, 2, 3, 4, 5]

// コンパイラが自動的で &List(Int) トークンを渡す——所有権を奪わない
print(data.len())    // 5
print(data)          // ✅ data はまだある，只是見ただけ
```

`&T` と `&mut T` は**ゼロサイズタイプ**——コンパイル時に存在し、実行時に消えます。手動で `&` を書く必要はありません。

```yaoxiang
// 読み取り専用アクセス → 自動的 &T
print: (point: &Point) -> Void = {
    print("({point.x}, {point.y})")
}

// 変更可能 → 自動的 &mut T
shift: (point: &mut Point, dx: Float, dy: Float) -> Void = {
    point.x = point.x + dx
    point.y = point.y + dy
}

mut p = Point(1.0, 2.0)
print(p)                // &Point を渡す
shift(p, 1.0, 1.0)      // &mut Point を渡す
```

**重要な区別**：`&T` はコピー可能（共有読み取り専用）、`&mut T` はコピー不可（独占的可変）です。これは特別なルールではありません——二つのタイプ属性です。

## ref：スコープを跨いだ共有

複数の場所で**同時に**一つの値を保持する必要がある場合、`ref` を使います：

```yaoxiang
data = [1, 2, 3, 4, 5]

// ref で共有所有権を生成
shared = ref data

// コンパイラが自動的に参照カウンタを選択：
// - タスクを跨がない → Rc（単一スレッド参照カウント）
// - タスクを跨ぐ → Arc（アトミック参照カウント）
spawn {
    use(shared)    // タスクを跨ぐ！コンパイラが自動的に Arc を使用
}

// Rc と Arc の違いを知る必要はない
// コンパイラが自動的に選択してくれる
```

## clone()：明示的深コピー

独立したコピーが必要な場合、明示的に `clone()` を呼び出します：

```yaoxiang
original = [1, 2, 3]
backup = original.clone()   // 深コピー——独立したコピーを持つ

// それぞれ独立している
original[0] = 10
print(backup[0])    // 1——影響されない
```

`clone()` は明示的なものです——コピーする임을明確にする，不像某些语言那样默认复制。

## ライフタイムなし

YaoXiang にはライフタイム `'a` がありません。この設計選択は重要な観察に基づいています：

> 借用冲突問題の本质はホーア命題の证明と同等です。それを型检查器の证明パイプラインに统一的に解决させ、追加の借用检查フレームワークは不要です。

`'a` を标注したり、ライフタイムを理解したりする必要はありません——コンパイラが型检查フェーズで自動的に所有権の安全性を検証します。

## GC なし

所有権モデル全体に垃圾回収がありません。すべてのメモリの解放タイミングはコンパイル時に确定されます：

- **Move 後** → 元の変数は使用不可、RAII が自動的に解放
- **ref 後** → 参照カウントがゼロになった時に解放
- **スコープ終了時** → スタック変数は自動的に解放

GC の一時停止はなく、実行時のオーバーヘッドもありません。

## まとめ

| 操作           | キーワード/構文      | コピー？      | 使用タイミング          |
| -------------- | -------------------- | ------------- | ---------------------- |
| 所有権を奪う   | デフォルトの動作      | ゼロコピー    | 関数引数、代入         |
| 一瞬見る       | 自動的 `&T`          | ゼロサイズ    | トークン読み取り専用アクセス |
| その場で変更   | 自動的 `&mut T`      | ゼロサイズ    | トークン可変変更       |
| 共有保持       | `ref`                | 参照カウント  | スコープ/タスクを跨ぐ  |
| 明示的コピー   | `.clone()`           | 深コピー      | 独立したコピーが必要   |
| 生ポインタ     | `unsafe` + `*T`      | 手動          | システムレベル操作     |

**覚えておいてください**：Move はデフォルト、ref は共有、clone は例外。三つのルールで、GC と永久に別れましょう。
