# 変数の宣言

本章では YaoXiang における変数宣言の中心的な構文を紹介します。他のプログラミング言語の経験があれば、YaoXiang の変数システムは非常にシンプルであることがわかるでしょう。すべての宣言は同じ構文モデルを共有しています。

## 統一構文モデル

YaoXiang の設計哲学は「すべてを統一する」です。整数を宣言しようが、関数を定義しようが、型を作成しようが、すべて同じ一套の構文を使用します：

```
name: type = value
```

これが YaoXiang の最も核心的な設計理念です。いくつかの例を見れば這種の一貫性が感じられるでしょう：

```yaoxiang
// 変数の宣言
x: Int = 42
name: String = "YaoXiang"

// 関数の定義
add: (a: Int, b: Int) -> Int = a + b

// 型の定義
Point: Type = { x: Float, y: Float }
```

構文仕様における変数宣言の形式的定義は：

```
('mut')? Identifier (':' TypeExpr)? '=' Expr
```

わかりやすく言えば：オプションの `mut` キーワードがあり、次に 변수명（変数名）が続き、オプションの `: 型` があり、最後に `= 値` となります。この構造は言語全体で一貫しており、一回学べば十分です。

## 不変変数（デフォルトの動作）

YaoXiang では、すべての変数は**デフォルトで不変**です。一度代入すると、もう変更できません。これは言語の安全設計です。

```yaoxiang
x = 10
// x = 20   // コンパイルエラー！x は不変
```

`=` を使用して宣言された変数について、コンパイラはスコープチェーンに沿って同じ名前の変数を外側に向かって検索します。見つかった場合はそこに代入し、見つからなければ現在のスコープ内に新しい不変変数を作成します。

```yaoxiang
x = 1       // 外側のスコープに x がないので、新しい変数として宣言
x = 2       // 外側の x が見つかり、代入を試みる → コンパイルエラー！x は不変
```

これは直感に反するように見えるかもしれません。他の言語を経験したことがあるなら、「見つかるならなぜ代入できないのか」と思うかもしれません。これは YaoXiang が安全性を最優先に考えているからです：デフォルトで不変ということは、コードのどこかで変数が偶発的に変更される心配をしなくてよいということです。

## mut 可変変数

実際に変数を変更する必要がある場合は、`mut` キーワードを使用して明示的に宣言します：

```yaoxiang
mut counter = 0
counter = counter + 1   // 変更可能
counter = 100           // これも可能
```

`mut` にはいくつかの重要なルールがあります：

**ルール1**：`mut` は明示的な新規宣言であり、コンパイラは外側のスコープ去了同じ名前の変数を検索しません。

```yaoxiang
mut x = 10      // 現在のスコープに新しい可変変数 x を作成
mut x = 20      // コンパイルエラー！同じスコープ内で x はすでに宣言済み
```

**ルール2**：`mut` で宣言した変数は、外側のスコープの変数と同じ名前を持つことはできません（シャドウイング禁止）。

```yaoxiang
x = 10
{
    mut x = 20   // コンパイルエラー！x はすでに外側で宣言されており、シャドウイングは不可
}
```

**ルール3**：同じスコープ内で、各名前は一度しか宣言できません。`=` でも `mut` でも同じです。

```yaoxiang
x = 10
mut x = 20   // コンパイルエラー！x はすでに宣言済み
```

これらのルールにより、各変数名は現在のスコープ内で一意であることが保証されます。同じ名前を持つ変数が一体どれを指すのかという混乱に決して遭遇しません。

## 型推論 vs 明示的な型注釈

YaoXiang は Hindley-Milner（HM）型推論アルゴリズムを使用しています。コンパイラはあなたが書いた値から自動的に型を推論できるため 대부분의場合で手動で型を書く必要はありません。

```yaoxiang
x = 42              // コンパイラは Int と推論
name = "YaoXiang"   // String と推論
pi = 3.14159        // Float と推論
is_valid = true     // Bool と推論
```

型を明示的にマークしたい場合（例えばコードの可読性を高めるため、またはコンパイラが推論できない場合など）、`: Type` 構文を使用します：

```yaoxiang
count: Int = 100
greeting: String = "Hello"
ratio: Float = 0.618
```

この2つの書き方は完全に同等です。型を省略してコードを作成し、必要に応じて型注釈を追加していくことができます。これによりプロトタイプ開発が非常に高速になると同時に、最終的なコードの型安全性を損なうことがありません。

## 基本型一覧

YaoXiang には基本的な型がいくつか組み込まれており、日常的なプログラミングのほとんどのシナリオをカバーしています。

### Int（整数）

```yaoxiang
a = 42              // 十進法
b = 0o52            // 八進法（0o プレフィックス）
c = 0x2A            // 十六進法（0x プレフィックス）
d = 0b101010        // 二進法（0b プレフィックス）
e = 1_000_000       // アンダースコアで数字を区切ることができる（読みやすさのため）
```

### Float（浮動小数点数）

```yaoxiang
pi = 3.14159
speed = 2.998e8         // 科学的記数法：2.998 × 10^8
tiny = 1.6e-19
```

### String（文字列）

```yaoxiang
name = "YaoXiang"
empty = ""              // 空文字列
escape = "Hello\nWorld" // エスケープシーケンス対応：\n 改行、\t タブ、\\ バックスラッシュ、\" ダブルクォート
unicode = "\u{4F60}\u{597D}"  // Unicode エスケープ
```

### Bool（真理値）

```yaoxiang
is_ready = true
is_done = false
```

真理値は通常、条件判断に使用されます：

```yaoxiang
if is_ready {
    print("処理を開始")
}
```

## 変数のスコープ

スコープは変数の可視範囲を決定します。YaoXiang のスコープ規則は非常にシンプルです：**各 `{}` ブロックは新しいスコープを作成します**。

### 基本ルール

```yaoxiang
{
    x = 10
    print(x)   // アクセス可能：x は現在のスコープ内
}
// print(x)    // エラー：x はスコープ外で可視でない
```

内側のスコープは外側の変数をアクセスできます：

```yaoxiang
outer = "外側にある"
{
    print(outer)   // 外側の outer にアクセス可能
    inner = "内側にある"
}
// print(inner)    // エラー：inner はスコープ外で可視でない
```

### 関数パラメータのスコープ

```yaoxiang
greet: (name: String) -> Void = {
    print("こんにちは, " + name)
    // name はこの関数ボディ内で可視
}
// name は関数体の外では可視でない
```

### ブロック式

YaoXiang の `{}` ブロックは式でもあり、値を返すことができます：

```yaoxiang
result = {
    x = 10
    y = 20
    return x + y   // 上一のスコープに 30 を返す
}
// result の値は 30
// x と y はブロック外で可視でない
```

ブロックの戻り値の詳細については、後続の関数章を参照してください。ここで覚えておいてほしいことは：**波括弧はスコープを作成し、内側は外側が見えるが、外側は内側看不到内**。

## まとめ

これで YaoXiang の変数システムの核心理念をマスターしました：

| 概念           | 要点                                             |
| -------------- | ------------------------------------------------ |
| 統一構文モデル | `name: type = value`、変数・関数・型すべてこれを使用 |
| デフォルト不変 | `x = 10` の後、`x` は変更不可                     |
| 可変変数       | `mut` で明示的に宣言 `mut x = 10`                 |
| シャドウイング禁止 | 同じ名前は同じスコープ内で一度しか宣言できない     |
| 型推論         | HM アルゴリズムが自動推論、`: Type` で明示可能    |
| スコープ       | 各 `{}` がスコープを作成、内は外が見える、外は内看不到内 |
