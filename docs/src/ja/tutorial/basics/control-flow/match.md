# match の基礎

`match`
は YaoXiang の最も強力な制御フロー構造です。**値**の形に応じて、異なる処理パスを選択することができます。他の言語の
`switch` を使ったことがあるなら、`match`
はそれを全面的にアップグレードしたバージョンだと感じるでしょう。

## 基本構文

言語仕様における `match` 式の定義：

```
match Expr { MatchArm+ }
MatchArm : Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
```

分解して見てみましょう：

- `match` の後にマッチ対象の値が続く
- `{}` の中に 1 つ以上の **マッチアーム**（MatchArm）を含める
- 各マッチアーム：**パターン** の後に `=>`、続いて**結果式**
- 各アームはカンマで終わる

最も簡単な例：

```yaoxiang
number = 2

text = match number {
    0 => "零",
    1 => "一",
    2 => "二",
}
print(text)  // "二"
```

## match は式である

`if` と同様に、`match`
も**式**——つまり、値を計算します。すべてのマッチアームの戻り値の型は一致している必要があります：

```yaoxiang
score = 85

grade = match score {
    90..100 => "A",    // 範囲パターン（発展内容）
    80..89 => "B",
    70..79 => "C",
    60..69 => "D",
    _ => "F",          // ワイルドカード：残りのすべてにマッチ
}
print(grade)  // "B"
```

> **注意**：範囲パターン `90..100`
> などは発展内容であり、[パターンマッチング発展](../pattern-matching.md)
> で詳しく解説します。本章ではまず基礎パターンに焦点を当てます。

## 基礎パターン

### リテラルパターン

具体的な値でマッチします：

```yaoxiang
response = 404

message = match response {
    200 => "OK",
    301 => "Moved",
    404 => "Not Found",
    500 => "Server Error",
    _ => "Unknown",
}
print(message)  // "Not Found"
```

### 識別子パターン

変数名を使ってマッチした値をキャプチャします：

```yaoxiang
result: Result(Int, String) = ok(42)

description = match result {
    ok(value) => "成功，値: " + value.to_string(),
    err(error) => "失敗，原因: " + error,
}
print(description)  // "成功，値: 42"
```

`ok(value)` の `value` は識別子パターンであり、`ok` が包んでいる実際の値をキャプチャして、`=>`
の後ろの式内で使用できます。

### ワイルドカードパターン

`_`
はワイルドカードで、**あらゆる値**にマッチします。通常は最後に配置し、フォールバックとして使います：

```yaoxiang
command = "exit"

action = match command {
    "start" => "起動",
    "stop" => "停止",
    "restart" => "再起動",
    _ => "未知指令: " + command,
}
print(action)  // "未知指令: exit"
```

## マッチは網羅的である必要がある

YaoXiang の `match`
は、すべての可能なケースをカバーすることを要求します——もしコンパイラが一部の可能な値を漏らしていると発見したら、直接エラーを出します。これが
`match` の安全性の体現です。

```yaoxiang
// このコードはコンパイルに失敗する
// value = true
// result = match value {
//     true => "是",
//     // false 分支が欠如——コンパイルエラー！
// }

// 正しい書き方——_ でフォールバックする
value = true
result = match value {
    true => "是",
    _ => "否",      // _ が false の処理も保証する
}
```

有限のケースしか存在しないと明確に分かっている場合（例えば列挙型のマッチング）、コンパイラがすべての値変体をカバーしているかチェックしてくれます。これは分岐の書き漏れによるバグを防ぐ強力な仕組みです。

## 複数パターンの組み合わせ

1 つのマッチアームは `|` で区切ることで複数のパターンにマッチできます：

```yaoxiang
day = "sunday"

type = match day {
    "monday" | "tuesday" | "wednesday" | "thursday" | "friday" => "工作日",
    "saturday" | "sunday" => "休息日",
    _ => "無効",
}
print(type)  // "休息日"
```

## マッチアームは順番に実行される

`match`
は最初の ARM から順にマッチを試み、**最初にマッチした分岐が有効**となり、それ以降は実行されません：

```yaoxiang
number = 5

result = match number {
    _ => "その他",     // ワイルドカードはすべてにマッチするので、ここでマッチする
    5 => "五",         // 永遠に実行されない——上で既にマッチしている
}
print(result)  // "その他"
```

この特性は、**ワイルドカード `_` を最後に配置する**ことが良い習慣であることを意味しています。

## まとめ

| 要点               | 説明                                             |
| ------------------ | ------------------------------------------------ |
| 構文               | `match 値 { パターン => 式, ... }`               |
| 式                 | `match` は値を計算し、全分岐の型は一致する       |
| リテラルパターン   | 具体的な値を正確にマッチ：`200 => "OK"`          |
| 識別子パターン     | 値を変数にキャプチャ：`ok(value) => ...`         |
| ワイルドカード `_` | あらゆる値にマッチし、フォールバックとなる       |
| 網羅性             | すべての可能性カバーが必要、コンパイラがチェック |
| 複数パターン       | `パターン1 \| パターン2 => 式`                   |
| 順次実行           | 上から下へ、最初にマッチした分岐が有効になる     |
