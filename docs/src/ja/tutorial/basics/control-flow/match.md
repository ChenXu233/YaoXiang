# match 基礎

`match`
は YaoXiang の中で最も強力な制御フロー構造です。**値**の形に応じて、異なる処理パスを選択することができます。他の言語の
`switch` を使ったことがあるなら、`match` はその全面的なアップグレード版だと分かるでしょう。

## 基本構文

言語仕様における `match` 式の定義：

```
match Expr { MatchArm+ }
MatchArm : Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
```

分解して見ていきます：

- `match` の後にマッチ対象の値が続く
- `{}` の中に 1 つ以上の **マッチアーム**（MatchArm）を含める
- 各マッチアーム：**パターン** の後に `=>` が続き、その後に**結果式**
- 各アームはカンマで終わる

最も簡単な例：

```yaoxiang
number = 2

text = match number {
    0 => "零",
    1 => "一",
    2 => "二",
}
print(text)  // "二"
```

## match は式

`if` と同様、`match`
も**式**であり、値を計算します。すべてのマッチアームの戻り値の型は一致している必要があります：

```yaoxiang
score = 85

grade = match score {
    90..100 => "A",    // 範囲パターン（応用内容）
    80..89 => "B",
    70..79 => "C",
    60..69 => "D",
    _ => "F",          // ワイルドカード：残りのすべてにマッチ
}
print(grade)  // "B"
```

> **注意**：範囲パターン `90..100`
> などは応用内容であり、[パターンマッチング応用](../pattern-matching/index.md)
> で詳しく解説します。本章ではまず基礎パターンに焦点を当てます。

## 基礎パターン

### リテラルパターン

具体的な値でマッチします：

```yaoxiang
response = 404

message = match response {
    200 => "OK",
    301 => "Moved",
    404 => "Not Found",
    500 => "Server Error",
    _ => "Unknown",
}
print(message)  // "Not Found"
```

### 識別子パターン

変数名を使ってマッチした値をキャプチャします：

```yaoxiang
result: Result(Int, String) = ok(42)

description = match result {
    ok(value) => "成功、値は: " + value.to_string(),
    err(error) => "失敗、理由: " + error,
}
print(description)  // "成功、値は: 42"
```

`ok(value)` の `value` は識別子パターンであり、`ok` が包んでいる実際の値をキャプチャしています。`=>`
の後ろの式内で使用することができます。

### ワイルドカードパターン

`_`
はワイルドカードで、**すべての値**にマッチします。通常は最後に配置し、フォールバックとして使います：

```yaoxiang
command = "exit"

action = match command {
    "start" => "サービスを起動",
    "stop" => "サービスを停止",
    "restart" => "サービスを再起動",
    _ => "不明なコマンド: " + command,
}
print(action)  // "不明なコマンド: exit"
```

## マッチは網羅的である必要がある

YaoXiang の `match`
はすべての可能性をカバーすることを要求します。コンパイラが漏れている可能性のある値を検出すると、エラーを出します。これは
`match` の安全性を体现する仕組みです。

```yaoxiang
// このコードはコンパイルに失敗する
// value = true
// result = match value {
//     true => "はい",
//     // false 分岐が欠けています——コンパイルエラー！
// }

// 正しく書くには——_ でフォールバックする
value = true
result = match value {
    true => "はい",
    _ => "いいえ",    // _ が false も処理することを保証
}
```

有限の場合だけしかありえないことが明確な場合（例えば列挙型にマッチする場合）、コンパイラがすべての変種をカバーしているかどうかをチェックしてくれます。これは分岐の書き漏れのバグを防ぐ強力な仕組みです。

## 複数パターンの組み合わせ

1 つのマッチアームで複数のパターンにマッチすることができ、`|` で区切ります：

```yaoxiang
day = "sunday"

type = match day {
    "monday" | "tuesday" | "wednesday" | "thursday" | "friday" => "平日",
    "saturday" | "sunday" => "休日",
    _ => "無効",
}
print(type)  // "休日"
```

## マッチアームは上から順に実行される

`match`
は最初のアームから順にマッチを試み、**最初にマッチに成功した分岐が有効**になり、後のものは実行されません：

```yaoxiang
number = 5

result = match number {
    _ => "その他",     // ワイルドカードはすべての値にマッチするので、ここでマッチする
    5 => "五",         // 決して実行されない——上で既にマッチしている
}
print(result)  // "その他"
```

この特性のため、**ワイルドカード `_` を最後に配置する**のは良い習慣です。

## まとめ

| ポイント           | 説明                                                           |
| ------------------ | -------------------------------------------------------------- |
| 構文               | `match 値 { パターン => 式, ... }`                             |
| 式                 | `match` は値を計算し、すべての分岐の型は一致する               |
| リテラルパターン   | 具体的な値に正確にマッチ：`200 => "OK"`                        |
| 識別子パターン     | 値を変数にキャプチャ：`ok(value) => ...`                       |
| ワイルドカード `_` | すべての値にマッチし、フォールバックとして機能する             |
| 網羅性             | すべての可能性をカバーする必要があり、コンパイラがチェックする |
| 複数パターン       | `パターン1 \| パターン2 => 式`                                 |
| 順次実行           | 上から下へ、最初にマッチした分岐が有効になる                   |

> **次のステップ**：本文では `match`
> の基礎的な使い方を扱いました。より高度なパターン（ネストしたパターン、ガード式、構造体の分解など）については
> [パターンマッチング応用](../pattern-matching/index.md) を参照してください。
