# match 基礎

`match` は YaoXiang において最も強力な制御フロー構造です。値の形に応じて、異なる処理パスを選択できます。他の言語の `switch` を使ったことがある場合、`match` が全面的にアップグレードされた版であることが分かるでしょう。

## 基本構文

構文仕様における `match` 式の定義：

```
match Expr { MatchArm+ }
MatchArm : Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
```

分解すると：

- `match` の後に照合する値を指定
- `{}` の中には1つ以上の **マッチアーム**（MatchArm）が含まれる
- 各マッチアーム：**パターン** の後に `=>` を記述し、その後に**結果式**を続ける
- 各アームはカンマで終了する

最も単純な例：

```yaoxiang
number = 2

text = match number {
    0 => "零",
    1 => "一",
    2 => "二",
}
print(text)  // "二"
```

## match は式である

`if` と同様に、`match` も**式**です——値を計算します。すべてのマッチアームの戻り値の型が一致する必要があります：

```yaoxiang
score = 85

grade = match score {
    90..100 => "A",    // 範囲パターン（上級コンテンツ）
    80..89 => "B",
    70..79 => "C",
    60..69 => "D",
    _ => "F",          // ワイルドカード：残りのすべてのケースにマッチ
}
print(grade)  // "B"
```

> **注意**：範囲パターン `90..100` などは上級コンテンツに属し、[パターン照合上級](../pattern-matching/index.md) で詳しく説明します。本章ではまず基本パターンに焦点を当てます。

## 基本パターン

### リテラルパターン

具体的な値で照合します：

```yaoxiang
response = 404

message = match response {
    200 => "OK",
    301 => "Moved",
    404 => "Not Found",
    500 => "Server Error",
    _ => "Unknown",
}
print(message)  // "Not Found"
```

### 識別子パターン

変数名で照合した値をキャプチャします：

```yaoxiang
result: Result(Int, String) = ok(42)

description = match result {
    ok(value) => "成功、値は: " + value.to_string(),
    err(error) => "失敗、理由は: " + error,
}
print(description)  // "成功、値は: 42"
```

`ok(value)` の `value` は識別子パターンです——`ok` でラップされた実際の値をキャプチャし、`=>` の後の式で中使用できます。

### ワイルドカードパターン

`_` はワイルドカードで、**任意の値**にマッチします。通常、最後に置いてフォールバックとして使用します：

```yaoxiang
command = "exit"

action = match command {
    "start" => "サービス開始",
    "stop" => "サービス停止",
    "restart" => "サービス再起動",
    _ => "不明なコマンド: " + command,
}
print(action)  // "不明なコマンド: exit"
```

## 照合は網羅的である必要がある

YaoXiang の `match` はすべての可能なケースをカバーする必要があります——コンパイラが可能性のある値を見落とすとエラーを報告します。これは `match` の安全性の表れです。

```yaoxiang
// このコードはコンパイルに失敗する
// value = true
// result = match value {
//     true => "はい",
//     // false ブランチが不足——コンパイルエラー！
// }

// 正しい——_ を使用してフォールバック
value = true
result = match value {
    true => "はい",
    _ => "いいえ",      // _ が false にも対応することを保証
}
```

限られた数のケースしかないことを明確に知っている場合（例えば enum 型を照合する場合）、コンパイラは各バリアントがカバーされているかを確認帮你检查是否每个变体都覆盖到了。这是防止漏写分支 bug の 강력한手段です。

## 複数パターンの組み合わせ

1つのマッチアームで `|` で区切って複数のパターンを照合できます：

```yaoxiang
day = "sunday"

type = match day {
    "monday" | "tuesday" | "wednesday" | "thursday" | "friday" => "平日",
    "saturday" | "sunday" => "休日",
    _ => "無効",
}
print(type)  // "休日"
```

## マッチアームは順番に実行される

`match` は最初のアームから照合を試み、**最初にマッチしたブランチが有効になり**、その後は実行されません：

```yaoxiang
number = 5

result = match number {
    _ => "その他",     // ワイルドカードはすべてにマッチ、ここではマッチする
    5 => "五",         // 常に実行されない——上で既にマッチしているため
}
print(result)  // "その他"
```

この特性により、**ワイルドカード `_` を最後に配置することが良い習慣**です。

## まとめ

| ポイント     | 説明                                               |
| ---------- | -------------------------------------------------- |
| 構文        | `match 値 { パターン => 式, ... }`                  |
| 式          | `match` は値を計算し、すべてのブランチの型が一致する  |
| リテラルパターン | 具体的な値を正確に照合：`200 => "OK"`              |
| 識別子パターン | 変数値をキャプチャ：`ok(value) => ...`              |
| ワイルドカード `_` | 任意の値にマッチ、フォールバック用               |
| 網羅性       | すべての可能性をカバーする必要があり、コンパイラがチェックする |
| 複数パターン   | `パターン1 \| パターン2 => 式`                      |
| 順番に実行    | 上から下へ、最初のマッチしたブランチが有効になる       |

> **次のステップ**：本文では `match` の基本的な使い方を説明しました。より高度なパターン（ネストされたパターン、ガード式、構造体デストラクトなどについては、[パターン照合上級](../pattern-matching/index.md) を参照してください。
