# リリーステンプレート

> `/release` コマンドはこのテンプレートに基づいて changelog を生成します。  
> changelog は**人向けの変更説明**であり、commit リストではありません。

## フォーマット仕様

```
:bookmark: V<バージョン番号>: <タイトル>
```

## 📦 バージョン情報

| 項目           | 値                                  |
| -------------- | ----------------------------------- |
| 公開日         | YYYY-MM-DD                          |
| バージョン変更 | `<旧バージョン>` → `<新バージョン>` |
| コミット数     | N 件の commit                       |

## 📋 今回の更新概要

2〜3 文で今回のリリースの核となる内容と意義を概述します。

## タイトルルール

核心的な変更を一行で概括し、50 文字以内:

```
:bookmark: V0.7.2: REPL 再実装と型システム改良
:bookmark: V0.7.3: 型システム修正と所有権モデル改良
:bookmark: V0.8.0: 並発モデルと泛化型システム
```

## 分類ルール

`type` プレフィックスで分類し、空の分類は省略:

|    type    |          分類           |    プレフィックス    |
| :--------: | :---------------------: | :------------------: |
|   `feat`   |        ✨ 新機能        |     `:sparkles:`     |
|   `fix`    |       🐛 Bug 修正       |       `:bug:`        |
| `refactor` |   ♻️ リファクタリング   |     `:recycle:`      |
|   `perf`   | ⚡ パフォーマンス最適化 |       `:zap:`        |
|   `docs`   |     📝 ドキュメント     |       `:memo:`       |
|  `style`   |     🎨 フォーマット     |       `:art:`        |
|   `test`   |        ✅ テスト        | `:white_check_mark:` |
|  `chore`   |    🔧 ビルド/ツール     |      `:wrench:`      |
|    `ci`    |        💚 CI/CD         |   `:green_heart:`    |

## コミットログの取得

```bash
git log <最新tag>..HEAD --oneline --no-merges
```

## 📋 今回の更新概要

今回のリリースは型システムと所有権モデルの安定性修正に焦点を当てています。泛化型のインスタンス化（例：
`List(Int) = List(1, 2, 3)`）が正常に動作するようになり、`&T`
フィールドアクセスとタプル分解代入の複数のエッジケースが修正されました。同時に所有権チェックの統一リファクタリングが完了し、今後の move セマンティクスの整備奠定了基礎。

## ✨ 新機能

### 泛化型インスタンス化

`List(Int) = List(1, 2, 3)`
構文をサポートし、型コンストラクタが Struct として正しく登録されるようになりました。泛化関数の複数呼び出し時に型推論が衝突不再発生し、各呼び出しが独立した型変数インスタンスを取得します。

- 型コンストラクタを Struct として登録し、インスタンス化の根本原因を修正
- 泛化関数の複数呼び出しが独立して推論される
- インターフェースメソッドバインディングを修正

### move 後の再バインディング

変数が move された後に新しい値を再バインディングできるようになり、代入優先検索が moved 状態を正しく処理し、「変数はすでに移動済み」という误報告を抑制します。

- VarInfo に moved 状態フラグを追加
- 代入優先検索に moved 分岐を追加

### Resource marker trait

IO 副作用的类型を标记する新しい `Resource` marker
trait を追加しました。今後の副作用追跡と并发安全分析の基礎を提供します。

### PLDI SRC デモ

エンドツーエンドの型チェックとコード生成を含む PLDI SRC デモ MVP の全タスクを完了しました。

## 🐛 Bug 修正

### &T フィールドアクセス

不変参照型のフィールドアクセスにおける型チェックの複数の問題を修正しました。フィールド代入やコンストラクタへの参照を通じた呼び出しの推論を含みます。

- `&T` フィールドアクセスの型チェックを修正
- フィールド代入の対象型推論
- 参照を通じたコンストラクタ呼び出しの推論

### LSP セマンティックハイライト

`spawn {}` ブロック内の変数とタプル分解代入 `(a, b) = ...`
のセマンティックハイライト缺失を修正しました。AST の `DestructureAssign.names`
が各変数名の位置情を持つようになりました。

- spawn ブロック内の変数の正しい色分け
- タプル分解代入の変数名の正しい色分け
- 今後の move セマンティクスの LSP サポートの基礎を築く

### freeze の移除

廃止予定の `freeze` 関数を移除し、関連するテストケースを整理しました。

## ♻️ リファクタリングと最適化

### 統合診断システム

残りの 5 つのエラー列挙型を統合 `ErrorCodeDefinition`
診断システムに移行し、エラーコード охват を 60% から 80% に引き上げました。すべてのコンパイルエラーが統一されたフォーマットとエラーコード標準に準拠するようになりました。

### 所有権チェックの統一

複数箇所に分散していた所有権チェックロジックを `OwnershipPass`
として統一し、单一エントリポイントで borrow、move、ライフサイクルチェックを処理します。メンテナンスコストを低減し、エラーの一貫性を向上させます。

### 並発モデルの簡素化

Send/Sync 制約システムを移除し、`spawn {}`
をグループ実行モデルにリファクタリングしました。`@block`/`@eager`/`@auto`
デコレータ関連のコードを移除（RFC-024 phase
1）。並発モデルを簡素化し、拡張可能な並発プリミティブ設計への道を開きます。
