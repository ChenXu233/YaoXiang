# 检查准入与退役策略（草案，2026-11-04）

> 状态：**提案**。未提交、未接入任何门禁。采用前需：① 用户裁决本文第 11 节的四个问题；② 补 sidebar 条目与 `check-docs-orphan` 登记；③ 与 [coding-rules](coding-rules.md) 的「红线」逐条对齐。

## 0. 一句话

**检查存在的理由只有两条：拦得住，或抓得到。** 两条都不成立，它只是给守规矩的人加税。

## 1. 什么算「检查」

本文把下列都视为检查，适用同一道闸：

- CI job、提交钩子、构建脚本里的强制校验；
- 回归测试、单元测试、快照测试；
- 语料差分基线、IR 快照基线；
- 审查清单里的机械项（「必须 grep 过引用点」这类由人执行的，算人读判据，不算检查）。

**人读判据**（写进文档、由审查者判断的）不受本文约束——它们没有运行成本，但也没有自动拦截力。

## 2. 准入闸：两问

任何新检查在落地前必须回答：

**问一：能不能绕过？**
能拦在**不可绕过**的位置吗——CI 强制、提交钩子、类型系统、编译失败、测试失败。绕开需要一行代码或一句注释就能做到的，答案是否。

**问二：抓到过什么真问题？**
登记具体的、会回归的错误：哪次改动、哪个缺陷、如果不拦会怎样。

| 问一 | 问二 | 处置 |
| --- | --- | --- |
| 不可绕过 | 有检出 | **保留**，进 CI |
| 不可绕过 | 尚无检出 | **冷启动**：先证明能红（见 §2.1），给 3 个月观察期 |
| 可绕过 | 有检出 | **改造**：挪到可观测的位置，或降级为人读判据 |
| 可绕过 | 无检出 | **不写**。写成文档里的一句话，或直接不写 |

### 2.1 冷启动条款（对「两问」的补充）

「有真实检出」这条有个循环依赖：新检查还没机会检出，就按「无检出」判死。

所以新检查必须先通过一道**能红证明**：用机械可逆的变异（改坏被测代码 → 检查必须转红 → 还原 → 逐文件比对回原状）证明它有检出能力。证明不了能红的检查，不是检查，是仪式。

> 本仓实例：2026-11-03 的 6.8.3 批次里，两处「防御性对齐」代码在 2950 条测试全绿的情况下被删掉，没有任何判据转红。事后补的单元判据必须用变异证明「删掉即红」，才被接受。

## 3. 检查的四类与门禁地位

| 类别 | 断言什么 | 实现重构时 | 门禁地位 |
| --- | --- | --- | --- |
| **不变量** | 无论实现怎么写都必须成立的性质 | 不该红 | **门禁** |
| **差分** | 与 SPEC/RFC 推导出的期望一致 | 不该红（除非 SPEC 改了） | **门禁**，但必须引 SPEC 条款（§6） |
| **特征化** | 当前实现的选择（渲染文本、消息措辞、精确行号） | **会红** | **只提示，不阻塞** |
| **冻结** | 既有可观察行为（用户能看到的东西） | 会红 | 门禁，但允许随裁决改判并登记 |

**判据**：一条检查属于哪一类，看「一个正确的替代实现会不会让它红」。会红 = 特征化。

## 4. 回归测试四问

测试也是检查，落地前答四问：

1. **防的是哪种用户可见的破损？** 说不出来 = 不是回归测试。
2. **最小现场是什么？** 一条命令、一个文件、几行代码。
3. **更便宜的检查为什么抓不到？** 如果类型系统、编译器警告、一行 grep 就能拦，别写测试。
4. **它每天跑的成本值吗？** 为一年一遇的破损起三个进程跑十分钟，是给所有人加税。

四问的答案写进测试文件头部注释或提交说明。

## 5. 两个常见误判

**误判一：把「概率低」当删除理由。**
一年一次但不可逆的破损（凭据泄漏、并发丢消息），一条便宜的守卫该留。判断的是成本与收益，不是概率阈值。

**误判二：把「防君子不防小人」的断言当守卫。**
「代码里调用了某个函数」「文件里没出现某个字符串」「这个辅助函数行为如预期」——诚实的实现天然通过，绕开只要一行。它提供仪式感，不是安全性。要拦就拦在破损**可观测**的地方。

## 6. SPEC 优先原则

**差分的 oracle 必须是 SPEC/RFC，不是昨天的编译器。**

昨天的实现如果本身是错的，把它冻成基线就是把错误升级成门禁。本仓 2026-11-02/04 的 6.8.x 批次里，多个判定点（柯里声明的实现头绑哪一层、`E1112` 的分母、依赖类型值形参、借用/值形参对齐）在规范里**没有条款**，争议最终是按「既有测试是绿的」裁定的——那是拿历史当规范。

由此三条约束：

1. **未定义行为不得冻结**。没有条款覆盖的形态，测试只能标 `characterization`，不进差分门禁。
2. **语料条目必须引条款**。每条夹具注明它证的是哪一条规范；每个条款至少一条夹具。空条款与空夹具都要能被列出来。
3. **改判据的判定标准**：如果改一条判据时发现它背后没有条款支撑，那它从一开始就是特征化而非不变量——应当**降级**，而不是「改绿了事」。

## 7. 成本核算与退役

每条检查登记三项：**最近 12 个月检出次数**、**单次运行成本**、**可绕过性**。

退役条件（需同时满足）：
- 12 个月零检出；
- 可绕过（诚实实现天然通过，绕开只要一行）；
- 单次运行成本显著。

退役方式：降级为提示（不进 CI）、转为人读判据、或删除。**必须登记理由与替代方案。**

### 7.1 与「红线」的关系

[coding-rules](coding-rules.md) 的红线禁止「因为红了就放宽断言」——那是**为绿灯而改判据**。

本文允许「有论证地删除无检出检查」——判据不同：
- 红线针对的是**动机**（为了让 CI 变绿）；
- 本文针对的是**成本收益**（这条检查值不值）。

两者冲突时的裁决顺序：先问「它现在红，是因为实现错了还是判据错了」；答不上来时**不得删除**。

| 手段 | 规模 | 抓到真问题 | 备注 |

结论：**快照类检查在本批检出率为 0**；真正抓到问题的是差分与人工复审。

## 9. 迁移路径（分四阶段，每阶段可独立回退）

1. **立真门禁**：`check` 通过 ⇒ `run` 不出现类型错误（健全性判据）。不依赖新机制，可直接对现有语料跑。
2. **拆假门禁**：IR 快照从「零漂移门禁」降为「变更提示」；特征化测试标注类别。
3. **差分引用化**：语料条目加 SPEC 条款引用；补双向覆盖检查。
4. **规则固化**：本文并入 [coding-rules](coding-rules.md) 与 [test-specification](test-specification.md)。

## 10. 风险与反对意见

- **「今天没检出 ≠ 明天不会」**：所以有冷启动期与能红证明；零检出的退役需要 12 个月观察，不是一次审查决定。
- **降级快照后渲染回归无人看**：接受。渲染回归由「变更提示」在 PR 里显示给人看，不阻塞。代价是可能漏看，收益是不再为无关重构付返工。
- **形式化验证的边界**：语言支持形式化验证，指的是**用户程序**可被证明；编译器实现（Rust，约 16 万行）不在其管辖内。形式化能防「已写明的性质被违反」，防不了「没人想到要写的性质」——后者只能靠写 SPEC 与对抗性审查发现。
- **删除检查的心理成本**：删掉一条绿了很久的检查会让人不安。用 §7 的三项登记对冲：零检出、可绕过、成本高，是事实而不是感觉。
