# RFC-027a: 终止检查的证明函数兜底

## 摘要

兑现 RFC-027 决策记录预留的再讨论条款：对四种自动策略无法覆盖终止证明的**非结构递归**（gcd 类非直接递减、相互递归），提供**证明函数兜底**——测度与证明都是普通 YaoXiang 函数，零新语法，类型检查器验证。机制定位是**精化类型证明协议的一次应用**：证明侧零新机制（RFC-027 既有 Unproven 兜底通道原样复用），新增的只有编译器侧的调用点义务生成与一个命题锚点。全自动优先原则不变：自动策略仍是第一路径，用户介入只发生在 Unproven 之后。

## 动机

### 宿主资格与修订范围

RFC-027 未预留子 RFC 槽位（不同于 RFC-029 预留 029a 的模式）。本子 RFC 的宿主资格来自 RFC-027 决策记录自身的再讨论条款：

> 不能由任何策略证明终止的循环，编译器直接报错——这是硬安全哲学，不是缺陷。**如果未来有真实场景（非学术构造）的算法四种策略都无法覆盖，再重新讨论。**
> —— RFC-027 决策记录

本 RFC 即该次「再讨论」的正式载体。它**不是推翻**已记录的决策——条款本身就是决策的一部分，触发它恰恰是决策按设计工作；它是对条款的预期行使。

对 RFC-027 的修订范围精确限定为三处：

| 修订点 | 原记录 | 修订后 |
| --- | --- | --- |
| §7「不给半自动标注留口子」 | 终止检查完全封闭 | 收窄为「无**标注语法**口子」——证明函数兜底不是标注（无新语法位、不挂在函数定义上），与「编译期谓词没有新关键字」同一世界观 |
| 决策记录「Unproven → 直接报错」 | 终止域唯一无兜底的证明域 | 改为「Unproven → 可提供证明函数」——与正确性域（谓词 Unproven → 证明函数，RFC-027 §证明函数）行为对齐 |
| §6.8 报错文案 | 「请使用可被编译器分析的迭代模式」 | 增补「或提供测度函数与终止证明函数」 |

**不修订**的部分：四种自动策略的优先地位、全自动优先原则、硬安全哲学的其余内容（Disproved 仍是编译错误 + 反例；正确性域行为零变化）。

### 当前的问题（2026-09-14 实测，v0.7.14 后 dev）

1. **TerminationChecker 只能证明结构递归**。`termination.rs` 现处 Phase 1：策略 3（有界递增/递减）、递归参数直接递减（`factorial(n-1)`）、`for` 循环天然终止。策略 1/2/4 尚未落地（RFC-027 既定扩展）。非结构递归直接编译失败：

   ```yaoxiang
   gcd: (a: Int, b: Int) -> Int = {
       if b == 0 { return a }
       return gcd(b, a % b)
   }
   ```

   递归参数 `(b, a % b)` 不是参数的直接递减——现报错并要求改写迭代模式。gcd 无法改写成「可分析的迭代模式」而不破坏可读性；归并排序分区、相互递归（偶/奇判定）、树遍历同理。这些是真实算法，不是学术构造——**再讨论条款的触发条件成立**。

2. **证明域兜底不对称**。RFC-027 的正确性命题（`Positive(b)`、`IsMax` 等谓词）Unproven 时有证明函数兜底；终止性是全部证明域中唯一 Unproven 即死路的域。同一世界观下这个不对称没有原则性理由。

3. **基建已就绪**。#292 已将 Z3 后端真实接通（`ConstExpr` → SMTLib → Unsat/Sat 判定链路）。递归调用点的测度递减义务 `measure(args') < measure(args)` 是一阶线性算术命题，恰落在该链路已打通的可判定片段内——复用同一条管道，不新增后端。

## 提案

### 核心设计

**定位：本 RFC 不新增证明机制，是精化类型证明协议的一次应用。** RFC-027 已确立「证明函数就是一个 YaoXiang 函数，其返回类型是被断言的命题」——命题即谓词应用，谓词应用即精化类型。终止证明的人类侧全程走这条既有通道（Unproven → 写证明函数 → 类型检查器验证 → witness 擦除），与正确性域完全同一协议。新增面收敛为三件：

1. **测度函数**——普通编译期函数，入参同被测函数签名，返回 `Int` 或 `Int` 元组（字典序）。不是标注、不挂在函数定义上，是可引用、可单测的一等函数。
2. **调用点义务生成**——编译器从 `f` 的函数体提取每个递归调用点的递减义务。这是唯一的新编译器逻辑：调用点实参长在函数体里，义务（语义约束）必须由编译器代写，人类不可代写——否则证明不再绑定真实代码（见设计哲学第 3 条）。
3. **终止命题 `Terminates(f, m)`**——一个**由编译器代写函数体的精化谓词**：其「约束内容」即上述义务集，其签名只是把 `(f, m)` 绑在一起的锚点。内置的必要性仅在于此，机制上没有任何新东西。函数与测度双双入型而非只入测度：互递归中 `is_even`/`is_odd` 签名相同，仅按测度发现会产生歧义（见示例）。

证明函数的三个角色随定位自然导出：把测度 `m` 显式绑定到 `f`（发现锚点，取代一切标注语法）；为残余义务提供 discharge 位（体 = 证明空间）；全称量化地持有 `f` 的参数名（体中可引用 `a`、`b` 书写事实）。语法逐落点见「详细语法」，完整走查见「示例」。

### 示例

#### 端到端详解：gcd

```yaoxiang
-- 被测函数（正确性域照常：参数精化、守卫、递归调用）
gcd: (a: Int, b: NonNegative(b)) -> Int = {
    if b == 0 { return a }
    return gcd(b, a % b)
}

-- 测度：普通函数（可单测、可复用）
gcd_measure: (a: Int, b: Int) -> Int = { b }

-- 证明函数：空体——全部义务由 SMT 自动闭合
gcd_proof: (a: Int, b: Int) -> Terminates(gcd, gcd_measure) = { }
```

编译器处理 `gcd_proof` 的全过程：

1. **签名校验**：证明函数参数按**基础类型**逐一匹配 `gcd` 形参（`Int`、`Int`）。形参精化（`b >= 0`）不在证明函数签名中重复——它已由编译器作为义务上下文持有，证明函数体与义务都在该上下文中验证。
2. **良基性义务**：`gcd_measure(a, b) >= 0`，即 `b >= 0`——从形参精化 `NonNegative(b)` 直接导出。测度的界不需要新机制，就是参数的精化约束（精化类型的语义化条件在良基性上的兑现）。
3. **调用点义务生成**：唯一递归调用点 `gcd(b, a % b)`，路径守卫 `b != 0`，生成 `gcd_measure(b, a % b) < gcd_measure(a, b)`；代入测度体展开为 `a % b < b`。
4. **SMT 判定**：验证义务的否定 `b != 0 ∧ a % b >= b` 不可满足——线性算术 + 取模公理，毫秒级 → Proved。
5. **接受**：体为空，无残余义务需要 discharge。`gcd` 终止得证；测度与证明函数按 witness 擦除，不进运行时二进制。

#### 非空体：残余义务引用已证引理

当调用点的递减依赖编译器看不见的事实（下例中 `step` 的体在依赖模块里，对义务生成是黑盒），人类把该事实以**引用已证谓词**的方式写进体——裸表达式，非 Assert 语句：

```yaoxiang
step: (n: Int) -> Int = { ... }

loop_x: (n: NonNegative(n)) -> Void = {
    if n == 0 { return () }
    return loop_x(step(n))
}

x_measure: (n: Int) -> Int = { n }

-- step 定义模块内导出的已证后置条件（正确性域，普通谓词，定义处已证明）：
step_decreases: (n: Int) -> Type = { n >= 1 ==> step(n) < n }

-- 终止证明 = 引用该引理（引用已证谓词 = 应用其已建立的证明，Curry-Howard）：
x_proof: (n: Int) -> Terminates(loop_x, x_measure) = {
    step_decreases(n)
}
```

验证过程：义务 `x_measure(step(n)) < x_measure(n)`（守卫 `n != 0`、上下文 `n >= 0`）在 `loop_x` 所在模块无法独立闭合 → 发现非空体 → 断言 `step_decreases(n)` 是已证谓词的实例，验证通过 → 作为引理闭合剩余义务。体里若直接凭空写 `step(n) < n`，验证器会诚实地报 Unproven——事实必须来自可追溯的已证来源。

#### 相互递归：按 SCC 收集义务

```yaoxiang
is_even: (n: NonNegative(n)) -> Bool = { if n == 0 { return true }  return is_odd(n - 1) }
is_odd:  (n: NonNegative(n)) -> Bool = { if n == 0 { return false } return is_even(n - 1) }

nat: (n: Int) -> Int = { n }

is_even_proof: (n: Int) -> Terminates(is_even, nat) = { }
is_odd_proof:  (n: Int) -> Terminates(is_odd, nat) = { }
```

义务按 SCC 收集，跨函数边的义务为 `m_callee(callee_args) < m_caller(caller_args)`——此处 `nat(n - 1) < nat(n)`，守卫 `n != 0`，两函数各自闭环。两函数签名相同，仅按测度发现无法区分目标——这是 `Terminates(f, m)` 双参数的直接理由。

#### 负例：测度不严格递减

```yaoxiang
loop_forever: (n: Int) -> Int = { return loop_forever(n) }
loop_proof: (n: Int) -> Terminates(loop_forever, nat) = { }
```

义务 `nat(n) < nat(n)` 即 `n < n`，其否定恒可满足（Sat，模型 `n = 0`）→ 编译错误 **E4022**（测度不严格递减），反例指向 `loop_proof`。若删掉 `loop_proof`，自动策略失败且无证明函数 → **E4021**（终止无法证明，提示提供 `Terminates` 证明函数）。

### 语法变化

**无。** 本 RFC 不新增任何语法、关键字、标注位。与既有谱系对照：

| 世代 | 用户侧表达 | 语法载体 |
| --- | --- | --- |
| RFC-022（已废） | `//! decreases: n` 注释标注 | 注释约定，无类型检查 |
| RFC-027 现行 | 无（全自动，证明不了即报错） | —— |
| 本 RFC | 测度 + 证明，皆为普通函数 | 函数定义语法本身 |

## 设计哲学：发现与验证分离

本 RFC 的机制选择由一条原理导出：**终止检查 = 见证发现 + 见证验证，两者难度悬殊，必须分离。**

| 角色 | 承担方 | 难度 |
| --- | --- | --- |
| 发现（综合出测度与证明） | 四条自动策略（机器、受限模板）或人类证明函数（不受限） | 一般**不可判定**（归约到停机问题）——不存在总能找到测度的算法 |
| 验证（对固定候选逐调用点核对 `m(args') < m(args)`） | SMT（RFC-009a 管道） | 可判定（一阶线性算术），毫秒级 |

「不可判定地找，可判定地查」——结构上同构于 P/NP 的 witness/verifier 分离，但比它更极端：发现侧不是难，是数学上不可能总有解；验证侧对固定候选完全机械。RFC-027「诚实报告 Unproven」与人类兜底由此不是工程妥协，而是这条边界的直接推论。

三个推论构成本 RFC 的设计约束：

1. **证明者不可信也无妨。** soundness 全部住在验证器：测度或断言写错，SMT 判 Sat、E4022 带反例打回——人只能证不出来，不能证错。Disproved 还是构造性的（给出反例模型）：验证器比 NP 验证器多做半件事，反驳也给证据。
2. **洞见冻结为可复验工件。** 人类的智力劳动一旦写成证明函数，即成为机器可检查的证书，每次编译重验、永久防回归（proof-carrying）。
3. **命题归编译器，证明归人类。** 义务（「什么算证毕」）必须由编译器从函数体生成；让人类连约束一起写，等于自己写自己的验收标准，证书不再证明实际写下的代码。

四条自动策略由此获得统一解释：它们是**见证综合的受限模板序列**——自动测度合成在文献中即约束求解下的模板枚举（线性秩函数综合为先例）。策略扩展 = 模板加宽；模板外的发现由人类代劳；验证器始终同一台 SMT。「不做测度推断」非目标的理论形态也在此：通用测度推断属于发现的不可判定侧，只能约定其边界（模板），不能承诺其完备。

## 详细设计

### 详细语法

证明函数没有专门语法——它就是「编译期谓词定义」换个用法。三个落点逐一钉死：

**返回类型：谓词应用，实参为函数引用。** `Terminates(gcd, gcd_measure)` 与既有精化在类型位置的应用（`f(x: Positive(x))`、`-> (result: IsMax(T, arr, result))`）同构；函数名是按名绑定的普通绑定（RFC-010），落在既有谓词实参规则「字面量、变量（按名绑定）、类型应用」之内。唯一规则级补充：E1092 实参形态判定增补「**函数引用属编译期常量形态**」——改规则文字，不动文法。

**参数：镜像 `f` 的基础类型，全称量化。** 参数名与基础类型逐一匹配 `f` 形参，不匹配报编译错误（复用 E1093 同族或按注册表新增，实现时定）。形参精化不重复——精化与守卫假设由编译器作为义务上下文注入。全称量化正是谓词定义自己的参数语义（`Positive: (x: Int) -> Type = { x > 0 }` 的 `x` 同样全称量化）。零参形式被否决：残余义务引用 `f` 的参数名，体中必须名字可写。

**体：证明空间，裸布尔表达式。** 与谓词定义体 `{ x > 0 }` 同一协议——体内每一项是被断言为 True 的裸表达式。空体合法且是多数场景（义务全由 SMT 闭合）；非空断言验证后作为引理喂给剩余义务；断言的合法来源是已证谓词的应用（见示例「非空体」）。

**发现与绑定。** 编译器对自动合成失败的 `f`，在同模块与可见导入中扫描返回类型形如 `Terminates(f, _)` 的函数；按返回类型发现，与名字无关（`f_proof` 仅为自然约定）。多个候选取首个义务全绿者（声明序），全败报首个反例。前向引用合法：发现发生在检查阶段，不依赖声明顺序。

**运行时表示。** 证明函数是纯编译期实体，沿用 RFC-027 CompileTime 模式的 witness 擦除——测度与证明函数都不进运行时二进制。

### 义务生成

对函数 `f` 与测度 `m`，编译器生成两组一阶线性算术义务，逐递归调用点（含 SCC 内跨函数调用）展开；跨函数边的义务为 `m_callee(callee_args) < m_caller(caller_args)`，成员共享同一测度时退化为同测度递减：

1. **良基性**：`m(args) >= 0`——测度落在自然数上，从参数类型界推导；推不出时进入残余义务。
2. **严格递减**：每个调用点 `m(callee_args) < m(caller_args)`，在**路径守卫**下判定（守卫来自该调用点所在的分支条件，复用 RFC-009a 路径条件收集）。

**字典序展开**：`m` 返回元组 `(m₁, …, mₖ)` 时，义务按字典序比较展开为析取链——`(m₁' < m₁) ∨ (m₁' == m₁ ∧ m₂' < m₂) ∨ …`。展开在义务生成侧完成，SMT 侧保持线性片段，不依赖求解器对字典序的原生支持。

**测度函数自身的有界性**：`m` 必须可编译期求值（常量折叠）或结构递归可证——禁止把终止问题递归推给另一个未证函数（防无穷回归）。病态测度由既有 E4012（常量递归过深）与结构检查拦住。

### 判定管线

`TerminationChecker` 扩展为五级，前三级为 RFC-027 现行/既定路径，本 RFC 只增后两级：

```
1. 结构递归直接可证（现行逻辑，不回归）
2. 自动测度合成：四策略逐一尝试（策略 1/2/4 随 RFC-027 计划落地，本 RFC 预留接口）
3. 合成成功 → 义务 SMT 判定 → Proved
4. 合成失败（Unproven）→ 搜索证明函数（返回类型形如 Terminates(f, _)）：
     a. 找到 → 取其测度 m 生成义务 → SMT 判定
     b. 残余义务 → 作为断言在证明函数体内验证（同正确性域证明函数协议）
5. 无证明函数 / 证明函数义务仍失败 → 编译错误（E4021 / E4022）
```

**证明函数的发现域**：同模块内定义，或经 `import` 可见的导出——跟随现有可见性规则，不做全局魔搜索。同一 `f` 多个候选 `Terminates(f, _)` 时取首个义务全绿者，多个都失败则报首个的反例（确定性序：声明序）。

**`Terminates` 的内置性声明**：它对谓词体系是特例——其「断言」由编译器从 `f` 的函数体生成，无法用 RFC-027 的谓词语法表达。这是有意的唯一内置命题，理由记录在权衡节。

### 错误码

对齐 E4xxx 证明失败家族（E4018 精化谓词违反、E4020 需要证明函数）：

| 提案码 | 名称 | 触发 |
| --- | --- | --- |
| E4021 | 终止无法证明 | 自动合成失败且无证明函数（提示提供 `Terminates` 证明函数） |
| E4022 | 测度不严格递减 | 证明函数的义务被 SMT 判 Sat（附反例输入） |

最终编号以实现时 RFC-013 注册表实况为准（段位合法性由 build.rs 门槛保证）；W1080（编译期证明降级）语义与本 RFC 无关，不动。

### 向后兼容性

- 此前编译通过的程序：行为零变化（前三级管线先于兜底执行）。
- 此前编译失败的程序：补写测度与证明函数后可通过——这是再讨论条款授权的收紧放松，且只影响「原本就报错」的程序。
- 既有测试语料（结构递归正例、非结构负例）期望输出不变，仅非结构负例的错误码/文案按新码更新。

## 权衡

### 优点

- **零新语法**：对照 Dafny 的 `decreases` 内联标注，本设计不占语法空间；测度是可单测的一等函数。
- **证明域行为对齐**：终止域补上与正确性域一致的 Unproven 兜底，「硬安全哲学」从「证明不了就拒绝」演进为「证明不了就交给程序员」——与 RFC-027 全文的世界观一致。
- **复用基建**：义务是线性算术，走 #292 已接通的管道，无新后端、无新判定逻辑族。
- **条款兑现即治理**：再讨论以子 RFC 形式留痕，决策记录保持可审计。

### 缺点与风险

- **书写负担**：两件套（测度 + 证明函数）比单个内联标注啰嗦。接受——兜底是低频路径，且换来测度可复用可测试。
- **`Terminates` 是唯一编译器代写体的谓词**：偏离「谓词体全部可用户书写」的纯度。理由：调用点实参长在函数体里，库谓词原理上引用不到；内置面收敛为一个命题名，机制零新增（见核心设计与设计哲学）。
- **策略 1/2/4 未落地期间，兜底可能被过早触发**：Phase 1 自动面窄，更多函数会落到证明函数路径。缓解：四策略落地后兜底面自动收窄；证明函数先行不是浪费——它们在策略升级后继续作为残余义务的 discharge 载体。
- **反例质量**：Sat 反例对非线性守卫可能不直观。记录为已知限制，反例呈现按 RFC-013 诊断消息规范迭代。

## 非目标

- 不新增语法/关键字/标注位。
- 不做测度自动合成的通用化扩展（四策略维持 RFC-027 既定计划，超出射程走兜底）。
- 不与 RFC-009a 借用命题联合求解（各自独立判定，共享后端）。
- 不做依赖类型层面的总性验证（totality checking）。
- 不实现测度推断（从函数体猜测测度属于策略 1/2/4 的射程，本 RFC 只消费显式测度——见设计哲学末段的理论边界）。
