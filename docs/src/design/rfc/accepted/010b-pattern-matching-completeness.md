# RFC-010b: 模式匹配完备化（变体解构与穷尽性）

> 本文是 [RFC-010](../accepted/010-unified-type-syntax.md)（统一类型语法）的子 RFC。变体的
> 声明、构造调用形态与运行时 tagged union 表示（含 `variant_id` 声明序——本文穷尽性检查的
> 变体集输入）由 RFC-010〔记录式和类型的变体构造（权威定义）〕一节定义；本文承载其镜像侧：
> match 解构与穷尽性检查。构造与解构必须成对，故同归 RFC-010。
>
> 原编号 RFC-039（2026-09-03 立稿）；2026-09-25 经所有者决定归并入 RFC-010 子 RFC 并改号
> RFC-010b，追踪 issue 仍为 #330。正文于 2026-09-27 充实并随实现落地（head e368958f）；
> 同日经所有者确认转正（accepted）。

## 摘要

将 `match` 的模式匹配从"仅字面量 + 通配符"补全为完备能力：变体解构（含零载荷与多载荷）、
结构体/元组模式、或模式与守卫、标识符绑定语义定案，以及穷尽性检查（E1030/E1031 从空挂码
转为真实发射）。本 RFC 是 `Error { kind: ErrorKind, message }` 演进路线（RFC-013「运行时
错误值与码贯通」演进节）的前置，但动机独立——模式匹配是通用语言能力，服务于所有带变体的类型。

## 动机

### 现状实证（2026-09-03，v0.7.12 代码；2026-09-27 全部消解）

1. **IR 层只有字面量模式是真的**。AST 已定义完整模式集，但 IR 生成只实现 `Literal`
   分支，其余模式落入 stub——加载常量 0 参与相等比较，永不匹配；且 scrutinee 恰为 0 时
   会误匹配进 stub arm。
2. **stdlib.md 的 `match ok(v)/err(e)` 示例是纸面能力**。
3. **穷尽性检查空挂**。E1030/E1031 在码表中注册但无发射点。
4. **错误处理演进被阻塞**（RFC-013 结构化错误建模依赖变体解构）。

### 设计目标

- **变体解构可用**：`match r { ok(v) => ..., err(e) => ... }` 与用户自定义变体集的解构在
  所有执行路径语义一致。
- **穷尽性可依赖**：E1030/E1031 真实发射，match 漏分支是编译错误。
- **stub 清除**：未支持模式在编译期报错而非静默走错（#330 安全网——此过渡策略在实现期
  逐阶段替代为真实编码，最终 stub 全部清除）。

## 提案（2026-09-27 定案并落地）

| 能力                       | 状态 | 说明                                                                 |
| -------------------------- | ---- | -------------------------------------------------------------------- |
| Union 变体模式             | ✅   | `Variant` / `Variant(binding)` / 多载荷 `make(a, b)` + 载荷绑定进 arm 作用域 |
| Struct / Tuple 模式        | ✅   | 字段模式（简写绑定 / `名: 子模式`）、元组模式；声明字段须完整覆盖      |
| Or 模式与 Guard            | ✅   | `p1 \| p2` 与 `pat if cond`：备选级失败链、守卫失败落下一臂            |
| 穷尽性检查                 | ✅   | E1030 漏分支、E1031 不可达，作用域覆盖变体集                           |
| Identifier 模式语义确认    | ✅   | 定案为**绑定**（见下节）                                               |

## 设计决策

### Identifier 模式：绑定，不是赋值，也不是比较

`match x { y => ... }` 的裸标识符 `y` 定案为**绑定**——引入一个新名字接住被匹配的值，
恒匹配（等价于带名字的通配符）。三点依据：

1. **结构论证**：模式位置里标识符天然有两个角色——判别位（`ok(v)` 的 `ok`，对照变体表）
   与叶位（`ok(v)` 的 `v`，绑定）。参数表（lambda）只有叶位，所以无歧义；裸标识符既站在
   判别位又长得像叶位，歧义由此而来。YaoXiang 有静态变体表：判别名按「查表命中」裁决
   （模式头是 scrutinee 变体集里的名字或字面量 → 判别；查不中的裸名 → 绑定），无需 Rust
   式大小写约定。
2. **值比较的退化性**：「模式里的已绑定名字表示相等」（合一语义）是单赋值传统的产物；
   可变语言里无法静态判定"绑过没有"，该语义不成立。YaoXiang 变量可重赋值（`mut`），
   走 Rust 立法。
3. **匹配已有值的需求归守卫**：`n if n == threshold`（守卫落地前写 if 链）。

**绑定不是赋值**（2026-09-27 与所有者对齐的口径）：模式绑定引入**新名字**，臂内辖区、
遮蔽外层同名变量、出臂即逝（探针：外层 `v = 999` 在 `some(v)` 命中后原样）；赋值是改写
已存在的名字（E2010/`mut` 那套法律）。二者在本语言中并存且概念分立，`=` 按名字是否已
存在分流（spec §4.3 赋值优先），模式位只属于绑定侧。

### match 是表达式，不是赋值语句

`match` 产出被命中臂的值（整个表达式的值），`v = match ...` 只是普通绑定语法接住它。
穷尽性检查的牙齿来自「臂必须产值」：漏形状 = 被赋值方拿不到值 = 编译错误（E1030）；
语句形态的 switch 漏分支只能静默。

### 臂的语义模型与实现

臂 = **带门牌的单参函数**：`some(v) => body` ≈ `λv.body`，仅在实参为 some 形状时被调用；
绑定语义来自「左边是参数位」。与 lambda 共用 `=>` 同源。实现上臂**不是闭包**：IR 递归
模式编译器（`compile_pattern`）内联发射测试链（VariantTag/LoadField/Eq + JmpIfNot）与
载荷提取（VariantPayload），命中即落臂体，失败跳下一臂——零调用开销。

### 或模式与守卫

- `p1 | p2`：备选顺序尝试；非末位备选失败 → 下一备选，命中 → 提取载荷后直达臂体；
  末位备选失败 → 下一臂。**各备选的绑定名集必须一致**（E1033），同名绑定共享臂级
  预分配寄存器（体读到的必然是命中备选写入的值）。
- `pat if cond`：模式命中后求值 `cond`（**模式绑定对守卫可见**），为假落下一臂。
  守卫条件必须产出 `Bool`。**带守卫的臂不计入穷尽性覆盖**（守卫可能不命中，Rust 同规），
  但带守卫的重复变体臂可达（是对前臂的细化）。

### 结构体模式

`Point { x, y: b }`：字段简写绑定同名，`名: 子模式` 递归。**声明字段必须完整覆盖**
（E1034 缺字段），未知字段拒绝（E1042），同字段重复出现报 E1032。`..` 略名与泛型结构体
模式尚未支持（见开放问题）。

### 变体解构（与 RFC-010 构造对称）

| 构造 | 解构 | 载荷表示 |
| ---- | ---- | -------- |
| `Result(Int, String).ok(5)` | `ok(v)` | 单载荷：直接绑定 |
| `Pair.make(3, 4)` | `make(a, b)` | 多载荷：Tuple 打包，按位拆包 |
| `Color.red()` / `Option(T).none()` | `red()` / `none()` | 零载荷：`pattern: None`，元数校验（`ok()` 写在带载荷变体上报错） |

载荷类型 = 变体参数经 scrutinee 类型实参替换（声明序）；嵌套模式（`ok(some(v))` 跨和
类型、`Point { pos: Tuple(a, b) }` 跨结构体）按子类型递归。

### 穷尽性与可达性

- **E1030（漏分支）**：仅和类型 scrutinee。无兜底臂时，变体集必须被无守卫 Union 臂全覆盖。
  带守卫的臂不计入（守卫可能不命中）。
- **E1031（不可达）**：兜底臂（无条件命中的不可驳斥模式：Identifier/Wildcard/Tuple/Struct，
  未带守卫）之后的任何臂；无守卫的重复变体臂、重复字面量臂。
- **非和类型 scrutinee**：值域开放，不做 E1030（允许全字面量臂 + 无兜底的宽松语义，
  现状保留）；E1031 照常。

### 诊断

| 码 | 含义 |
| --- | --- |
| E1030 | 模式穷举不足（列出缺失变体） |
| E1031 | 不可达模式（兜底臂之后 / 重复变体 / 重复字面量） |
| E1032 | 模式重复绑定（同一模式内同名绑定出现多次） |
| E1033 | 或模式绑定不一致（各备选绑定名集不同） |
| E1034 | 结构体模式缺字段 |
| E3008 | IR 层安全网保留（防御性分支，正常程序不可达） |

### 与赋值/lambda 的边界（防混淆备忘）

- 模式绑定 ≠ 赋值：引入新名字 vs 改写已有名字（E2010/`mut`）；
- 或模式 ≈ lambda 应用的扩展（语义模型），但实现为内联跳转，非闭包调用；
- 字面量模式编译为 Eq + 条件跳转链——「if/elif 的优化形式」的直觉对字面量成立，
  match 的增量在形状判断与拆包绑定。

## 实现落点

- parser：`parse_pattern`（变体调用重组 / 结构体模式 `Ident { .. }` 分支 / 嵌套或模式
  还原）、`parse_match` 或模式收链 + 守卫（`no_fat_arrow` 旗标使 `=>` 不作 lambda 中缀）
- typecheck：`check_match_expr` 统一臂循环 + `check_pattern` 递归检查器（绑定注册、
  守卫 Bool 校验、穷尽性记账）
- ir_gen：`compile_pattern` 递归模式编译器 + `sum_type_variants` 镜像携带载荷类型与
  `sum_type_param_names`（载荷类型按 scrutinee 实参替换）
- 语料：`02-type-system/pattern_destructure.yx`、`pattern_or_guard.yx`；
  单测 E1030/E1031/E1032/E1033/E1034（rfc011b.rs）

## 开放问题

- [x] Identifier 模式：绑定新变量还是匹配已存在值？→ **绑定**（判别位按变体表查表裁决，
      无大小写约定）；匹配已存在值归守卫。
- [x] 穷尽性的适用边界：→ 变体集穷尽仅对和类型；非和类型值域开放不做 E1030。
- [x] stub 加载 0 误匹配在修复前的过渡期是否先报编译错？→ 是（#330 安全网），已全部
      替代为真实编码。
- [ ] 结构体模式 `..` 略名（部分字段 + 兜底）是否需要？（影响字段覆盖规则）
- [ ] 泛型结构体模式（`Box { v, n }` 于 `Box(Int)` 值）待定——当前由 typecheck 前置拒绝。
- [ ] non_exhaustive 类属性（std 变体集扩展对用户 match 的破坏半径）待定。
