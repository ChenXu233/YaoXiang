# Модель владения

YaoXiang не использует сборщик мусора (GC) и не требует аннотаций времени жизни. Её безопасность памяти основана на **пяти концепциях и одном градиенте**.

## Пять концепций, один градиент

```
Посмотреть/Изменить    Забрать         Разделяемое       Копия           Системный
    на месте           │               владение           │              уровень
    │                  │                   │              │                │
   &T               Move               ref             clone()          unsafe
  &mut T            Нуль-копия      Компилятор         Явное            *T
  Токен нулевого     По умолчанию    автоматически      глубокое         Пользователь
  размера                             выбирает           копирование      отвечает
                                   Rc/Arc
```

## Move: передача владения по умолчанию

В YaoXiang **присваивание = передача владения**. Это поведение по умолчанию, нуль-копия:

```yaoxiang
p = Point(1.0, 2.0)
p2 = p              // Move! владение p передаётся p2
                    // после этого p больше нельзя читать

// Хотите изменить p2? Используйте mut
mut p3 = Point(3.0, 4.0)
shift(p3, 1.0, 1.0)    // изменение на месте
```

Передача параметров и возврат функции также являются Move:

```yaoxiang
// Параметр: передаётся через Move
process: (p: Point) -> Point = {
    p.transform()
    p                  // Move возврат — нуль-копия
}

// Вызов
p = Point(1.0, 2.0)
result = process(p)    // p был перемещён
```

## &T / &mut T: токены заимствования

Если вы не хотите забирать владение, а просто хотите временно «посмотреть» (`&T`) или «изменить на месте» (`&mut T`), компилятор автоматически создаёт **токен заимствования нулевого размера**:

```yaoxiang
data = [1, 2, 3, 4, 5]

// Компилятор автоматически передаёт токен &List(Int) — не забирает владение
print(data.len())    // 5
print(data)          // ✅ data всё ещё существует, только что на неё посмотрели
```

`&T` и `&mut T` — это **типы нулевого размера** — существуют на этапе компиляции, исчезают во время выполнения. Не нужно вручную писать
`&`, компилятор автоматически определяет в зависимости от контекста использования:

```yaoxiang
// Только чтение → автоматически &T
print: (point: &Point) -> Void = {
    print("({point.x}, {point.y})")
}

// Изменение → автоматически &mut T
shift: (point: &mut Point, dx: Float, dy: Float) -> Void = {
    point.x = point.x + dx
    point.y = point.y + dy
}

mut p = Point(1.0, 2.0)
print(p)                // передаётся &Point
shift(p, 1.0, 1.0)      // передаётся &mut Point
```

**Ключевое различие**: `&T` копируемо (разделяемое только для чтения), `&mut T`
некопируемо (эксклюзивное изменение). Это не особое правило — это два свойства типов.

## ref: совместное использование за пределами области видимости

Когда вам нужно **одновременно держать** значение в нескольких местах, используйте `ref`:

```yaoxiang
data = [1, 2, 3, 4, 5]

// ref создаёт разделяемое владение
shared = ref data

// Компилятор автоматически выбирает счётчик ссылок:
// - без пересечения задач → Rc (подсчёт ссылок для одного потока)
// - с пересечением задач → Arc (атомарный подсчёт ссылок)
spawn {
    use(shared)    // пересечение задач! компилятор автоматически использует Arc
}

// Вам не нужно знать разницу между Rc и Arc
// Компилятор выбирает за вас автоматически
```

## clone(): явное глубокое копирование

Когда вам нужна независимая копия, вызывайте `clone()` явно:

```yaoxiang
original = [1, 2, 3]
backup = original.clone()   // глубокое копирование — независимая копия

// Каждая независима
original[0] = 10
print(backup[0])    // 1 — не затронуто
```

`clone()` — это явное действие — вы чётко указываете, что хотите копировать, в отличие от некоторых языков с копированием по умолчанию.

## Без времени жизни

В YaoXiang нет времени жизни `'a`. Этот выбор дизайна исходит из ключевого наблюдения:

> Проблема конфликтов заимствования по сути эквивалентна проверке предложений Хоара. Передача её в конвейер доказательств проверки типов решает проблему единообразно — без дополнительной системы проверки заимствований.

Вам не нужно аннотировать `'a`, не нужно понимать время жизни — компилятор автоматически проверяет безопасность владения на этапе проверки типов.

## Без GC

Вся модель владения работает без сборщика мусора. Момент освобождения всей памяти определяется на этапе компиляции:

- **После Move** → исходная переменная недоступна, RAII автоматически освобождает
- **После ref** → освобождение при достижении счётчиком ссылок нуля
- **При выходе из области видимости** → автоматическое освобождение стековых переменных

Нуль пауз GC, нуль накладных расходов времени выполнения.

## Итог

| Операция        | Ключевое слово/синтаксис | Копирование    | Когда использовать       |
| --------------- | ------------------------ | -------------- | ----------------------- |
| Забрать владение | По умолчанию             | Нуль-копия     | Передача параметров, присваивание |
| Посмотреть       | Автоматически `&T`       | Токен нулевого размера | Только чтение           |
| Изменить на месте| Автоматически `&mut T`  | Токен нулевого размера | Изменение               |
| Разделяемое владение | `ref`               | Подсчёт ссылок | За пределами области видимости/задач |
| Явное копирование| `.clone()`            | Глубокое копирование | Нужна независимая копия |
| Голый указатель  | `unsafe` + `*T`          | Вручную        | Системные операции      |

**Запомните**: Move — это по умолчанию, ref — для разделения, clone — исключение. Три правила, и забудьте про GC.
