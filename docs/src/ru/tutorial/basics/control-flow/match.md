# Основы match

`match` — это самая мощная конструкция управления потоком в YaoXiang. Она позволяет выбирать разные
пути обработки в зависимости от формы **значения**. Если вы работали с `switch` в других языках, то
обнаружите, что `match` — это его全面升级ная версия.

## Базовый синтаксис

Определение выражения `match` в спецификации синтаксиса:

```
match Expr { MatchArm+ }
MatchArm : Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
```

Разберём по частям:

- После `match` следует значение для сопоставления
- `{}` содержат одну или несколько **веток сопоставления** (MatchArm)
- Каждая ветка: после **паттерна** идёт `=>`, затем **выражение-результат**
- Каждая ветка заканчивается запятой

Простейший пример:

```yaoxiang
number = 2

text = match number {
    0 => "ноль",
    1 => "один",
    2 => "два",
}
print(text)  // "два"
```

## match — это выражение

Как и `if`, `match` является **выражением** — оно вычисляет значение. Типы возвращаемых значений
всех веток должны быть одинаковыми:

```yaoxiang
score = 85

grade = match score {
    90..100 => "A",    // диапазонный паттерн (продвинутая тема)
    80..89 => "B",
    70..79 => "C",
    60..69 => "D",
    _ => "F",          // подстановочный знак: соответствует всем остальным случаям
}
print(grade)  // "B"
```

> **Примечание**: диапазонные паттерны вида `90..100` относятся к продвинутым темам и будут подробно
> рассмотрены в разделе [Продвинутое pattern matching](../pattern-matching.md). В этой главе мы
> сосредоточимся на базовых паттернах.

## Базовые паттерны

### Литеральные паттерны

Сопоставление с конкретными значениями:

```yaoxiang
response = 404

message = match response {
    200 => "OK",
    301 => "Moved",
    404 => "Not Found",
    500 => "Server Error",
    _ => "Unknown",
}
print(message)  // "Not Found"
```

### Паттерн-идентификатор

Использование имени переменной для захвата сопоставленного значения:

```yaoxiang
result: Result(Int, String) = ok(42)

description = match result {
    ok(value) => "Успех, значение: " + value.to_string(),
    err(error) => "Неудача, причина: " + error,
}
print(description)  // "Успех, значение: 42"
```

`value` в `ok(value)` — это паттерн-идентификатор: он захватывает фактическое значение, обёрнутое в
`ok`, и вы можете использовать его в выражении после `=>`.

### Подстановочный паттерн

`_` — это подстановочный знак, соответствующий **любому значению**. Обычно располагается в конце как
универсальный вариант:

```yaoxiang
command = "exit"

action = match command {
    "start" => "Запустить сервис",
    "stop" => "Остановить сервис",
    "restart" => "Перезапустить сервис",
    _ => "Неизвестная команда: " + command,
}
print(action)  // "Неизвестная команда: exit"
```

## Сопоставление должно быть исчерпывающим

`match` в YaoXiang требует покрытия всех возможных случаев — если компилятор обнаружит, что вы
пропустили какие-то возможные значения, он сразу же сообщит об ошибке. Это проявление безопасности
`match`.

```yaoxiang
// Этот код не скомпилируется
// value = true
// result = match value {
//     true => "Да",
//     // Отсутствует ветка false — ошибка компиляции!
// }

// Правильно — используем _ как универсальный вариант
value = true
result = match value {
    true => "Да",
    _ => "Нет",      // _ гарантирует обработку и false
}
```

Когда вы точно знаете, что возможен лишь有限ный набор случаев (например, при сопоставлении с enum),
компилятор проверяет, покрыт ли каждый вариант. Это мощное средство для предотвращения багов из-за
пропущенных веток.

## Комбинирование нескольких паттернов

Одна ветка может сопоставляться с несколькими паттернами, разделёнными `|`:

```yaoxiang
day = "sunday"

type = match day {
    "monday" | "tuesday" | "wednesday" | "thursday" | "friday" => "рабочий день",
    "saturday" | "sunday" => "выходной",
    _ => "неверно",
}
print(type)  // "выходной"
```

## Ветки сопоставления выполняются по порядку

`match` начинает перебор веток с первой, **срабатывает первая успешно сопоставленная ветка**,
последующие не выполняются:

```yaoxiang
number = 5

result = match number {
    _ => "Другое",     // подстановочный знак соответствует всему, сработает здесь
    5 => "пять",       // никогда не выполнится — выше уже сработало
}
print(result)  // "Другое"
```

Эта особенность означает, что **размещение подстановочного знака `_` в конце** — хорошая практика.

## Резюме

| Пункт                   | Описание                                                              |
| ----------------------- | --------------------------------------------------------------------- |
| Синтаксис               | `match значение { паттерн => выражение, ... }`                        |
| Выражение               | `match` вычисляет значение, типы всех веток одинаковы                 |
| Литеральный паттерн     | Точное сопоставление с конкретным значением: `200 => "OK"`            |
| Паттерн-идентификатор   | Захват значения в переменную: `ok(value) => ...`                      |
| Подстановочный знак `_` | Соответствует любому значению, используется как универсальный вариант |
| Исчерпывающесть         | Необходимо покрыть все варианты, компилятор это проверяет             |
| Несколько паттернов     | `паттерн1 \| паттерн2 => выражение`                                   |
| Порядок выполнения      | Сверху вниз, срабатывает первая сопоставленная ветка                  |
