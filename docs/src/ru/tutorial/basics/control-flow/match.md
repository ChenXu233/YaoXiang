# Основы match

`match` — это самая мощная структура управления потоком в YaoXiang. Она позволяет выбирать разные
пути обработки в зависимости от формы **значения**. Если вы использовали `switch` в других языках,
вы обнаружите, что `match` — это значительно улучшенная версия.

## Базовый синтаксис

Определение выражения `match` в спецификации синтаксиса:

```
match Expr { MatchArm+ }
MatchArm : Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
```

Разберём по частям:

- После `match` идёт значение для сопоставления
- `{}` содержит одну или несколько **веток сопоставления** (MatchArm)
- Каждая ветка: после **паттерна** идёт `=>`, затем **выражение-результат**
- Каждая ветка заканчивается запятой

Самый простой пример:

```yaoxiang
number = 2

text = match number {
    0 => "零",
    1 => "一",
    2 => "二",
}
print(text)  // "二"
```

## match — это выражение

Как и `if`, `match` тоже является **выражением** — оно вычисляет значение. Типы возвращаемых
значений всех веток должны совпадать:

```yaoxiang
score = 85

grade = match score {
    90..100 => "A",    // 范围模式（进阶内容）
    80..89 => "B",
    70..79 => "C",
    60..69 => "D",
    _ => "F",          // 通配符：匹配所有剩余情况
}
print(grade)  // "B"
```

> **Примечание**: паттерн диапазона `90..100` и подобные относятся к продвинутому материалу и
> подробно рассматриваются в [Продвинутом сопоставлении с образцом](../pattern-matching/index.md). В
> этой главе мы сосредоточимся на базовых паттернах.

## Базовые паттерны

### Паттерны литералов

Сопоставление с конкретными значениями:

```yaoxiang
response = 404

message = match response {
    200 => "OK",
    301 => "Moved",
    404 => "Not Found",
    500 => "Server Error",
    _ => "Unknown",
}
print(message)  // "Not Found"
```

### Паттерны идентификаторов

Использование имени переменной для захвата сопоставленного значения:

```yaoxiang
result: Result(Int, String) = ok(42)

description = match result {
    ok(value) => "成功，值是: " + value.to_string(),
    err(error) => "失败，原因: " + error,
}
print(description)  // "成功，值是: 42"
```

`value` в `ok(value)` — это паттерн идентификатора — он захватывает фактическое значение, обёрнутое
в `ok`, и вы можете использовать его в выражении после `=>`.

### Подстановочный паттерн

`_` — это подстановочный знак (wildcard), соответствующий **любому значению**. Обычно его помещают в
конце как «запасной вариант»:

```yaoxiang
command = "exit"

action = match command {
    "start" => "启动服务",
    "stop" => "停止服务",
    "restart" => "重启服务",
    _ => "未知指令: " + command,
}
print(action)  // "未知指令: exit"
```

## Сопоставление должно быть исчерпывающим

`match` в YaoXiang требует покрытия всех возможных случаев — если компилятор обнаружит, что вы
пропустили какие-то возможные значения, он сразу выдаст ошибку. Это отражает безопасность `match`.

```yaoxiang
// Этот код не скомпилируется
// value = true
// result = match value {
//     true => "是",
//     // Отсутствует ветка false — ошибка компиляции!
// }

// Правильно — используем _ как запасной вариант
value = true
result = match value {
    true => "是",
    _ => "否",      // _ гарантирует обработку false
}
```

Когда вы точно знаете, что существует лишь ограниченное число случаев (например, при сопоставлении
enum), компилятор проверяет, покрыт ли каждый вариант. Это мощное средство для предотвращения багов
из-за пропущенных веток.

## Комбинирование нескольких паттернов

Одна ветка может соответствовать нескольким паттернам, разделённым `|`:

```yaoxiang
day = "sunday"

type = match day {
    "monday" | "tuesday" | "wednesday" | "thursday" | "friday" => "工作日",
    "saturday" | "sunday" => "休息日",
    _ => "无效",
}
print(type)  // "休息日"
```

## Ветки выполняются по порядку

`match` начинает пробовать сопоставление с первой ветки, **первая успешно совпавшая ветка
срабатывает**, последующие не выполняются:

```yaoxiang
number = 5

result = match number {
    _ => "其他",     // Подстановка соответствует всему, сработает здесь
    5 => "五",       // Никогда не выполнится — выше уже совпало
}
print(result)  // "其他"
```

Эта особенность означает, что **ставить подстановочный знак `_` в конце** — хорошая практика.

## Резюме

| Пункт                      | Описание                                                     |
| -------------------------- | ------------------------------------------------------------ |
| Синтаксис                  | `match значение { паттерн => выражение, ... }`               |
| Выражение                  | `match` вычисляет значение, типы всех веток должны совпадать |
| Паттерны литералов         | Точное сопоставление с конкретным значением: `200 => "OK"`   |
| Паттерны идентификаторов   | Захват значения в переменную: `ok(value) => ...`             |
| Подстановка `_`            | Соответствует любому значению, запасной вариант              |
| Исчерпывающее соответствие | Необходимо покрыть все возможности, компилятор проверяет     |
| Несколько паттернов        | `паттерн1 \| паттерн2 => выражение`                          |
| Порядок выполнения         | Сверху вниз, первая совпавшая ветка срабатывает              |
