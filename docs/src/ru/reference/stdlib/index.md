# Справочник по стандартной библиотеке

Стандартная библиотека YaoXiang (`std`) организована в виде модулей; каждый модуль импортируется
через `use` и вызывается как `имя_модуля.имя_функции(...)`. Данный раздел представляет собой
справочную документацию по API, разбитую по модулям.

## Соглашения об импорте

Импорт модуля целиком:

```yaoxiang
use std.list
use std.string

main: () -> Void = {
    parts = string.split("a,b,c", ",")
    println(list.len(parts))
}
```

Также можно импортировать по имени из модуля, включая константы:

```yaoxiang
use std.assert
use std.math.{E, PI, TAU}

main: () -> Void = {
    assert(PI > 3.14)
}
```

## Соглашения о заимствовании параметров

Символ `&` в сигнатуре означает **автоматическое заимствование только для чтения** (RFC-009 §2.8):
переменная, переданная вызывающей стороной, не перемещается и может использоваться после вызова. Это
форма по умолчанию для многочисленных функций только-для-чтения в стандартной библиотеке.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    nums = [1, 2, 3]

    // Все три вызова только заимствуют nums для чтения, после чего он остаётся доступным
    assert(list.len(nums) == 3)
    assert(list.len(nums) == 3)
    assert(list.contains(nums, 2))
}
```

Параметр без `&` означает **передачу по значению**. Поэтому большинство «изменяющих» функций имеют
**функциональную форму, поглощающую исходное значение и возвращающую новое**, а не модификацию на
месте:

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    base = [1, 2]
    extended = list.push(base, 3)   // возвращает новый список; base перемещён
    assert(list.len(extended) == 3)
}
```

В разделе «Семантическая классификация» на странице каждого модуля перечислено, какие функции
заимствуют, какие поглощают, а какие изменяют на месте. Необходимо обратить особое внимание на один
момент:

- [`list.pop`](./list#pop) / [`list.remove_at`](./list#remove_at) — в сигнатуре указано `&List(A)`,
  однако они **изменяют список на месте**

## Модель ошибок

В стандартной библиотеке существует две формы сбоев, которые в описании каждой функции помечены как
«ошибка» и «возвращает …» соответственно:

| Форма                            | Проявление                                               | Типичные сценарии                                                                               |
| -------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Выброс ошибки времени выполнения | Завершает текущее выполнение с кодом `E6xxx`             | Отсутствующий ключ словаря `E6008`, выход за границы индекса `E6003`, сбой утверждения          |
| Возврат контрольного значения    | Не прерывает выполнение, возвращает `Void` / `-1` / `""` | Чтение за пределами списка, взятие первого элемента пустого списка, отсутствие переменной среды |

Распространённые коды ошибок времени выполнения:

| Код ошибки | Значение                                            | Пример срабатывания                      |
| ---------- | --------------------------------------------------- | ---------------------------------------- |
| `E6003`    | Выход за границы индекса                            | `list.set(l, 99, v)`                     |
| `E6005`    | Сбой утверждения                                    | `assert(false)`                          |
| `E6007`    | Универсальная ошибка времени выполнения             | Файл не существует, сбой `result.unwrap` |
| `E6008`    | Отсутствующий ключ                                  | `dict.get(d, "nope")`                    |
| `E6010`    | Сбой разбора целого числа (как значение Err)        | `string.parse_int("abc")`                |
| `E6011`    | Сбой разбора вещественного числа (как значение Err) | `string.parse_float("abc")`              |

Полную таблицу кодов ошибок см. в [Справочнике по кодам ошибок](../error-code/).

`string.parse_int` / `string.parse_float` представляют третью форму: **не выбрасывают ошибку**, а
оборачивают сбой в значение `Err` типа `Result`, которое можно распаковать через
[`std.result`](./result) или распространить с помощью `?`.

```yaoxiang
use std.assert
use std.result
use std.string

main: () -> Void = {
    assert(result.is_ok(string.parse_int("42")))
    assert(result.is_err(string.parse_int("abc")))
}
```

## Протокол итерации

`std.list` и `std.range` предоставляют один и тот же протокол итератора. Сам итератор является
носителем состояния в виде `Tuple`.

> **Семантика перемещения**: и `next`, и `has_next` **перемещают** итератор (в сигнатуре нет `&`),
> поэтому при каждом обращении его необходимо создавать заново, либо использовать `for ... in`
> напрямую.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    it = list.iter([1, 2, 3])
    assert(list.has_next(it))

    // has_next перемещает it, поэтому после повторного создания берём элемент
    it2 = list.iter([1, 2, 3])
    assert(list.next(it2) == 1)
}
```

Для повседневного обхода используйте `for ... in` напрямую:

```yaoxiang
use std.assert

main: () -> Void = {
    mut sum = 0
    for x in [1, 2, 3] {
        sum = sum + x
    }
    assert(sum == 6)
}
```

[`range.map`](./range#map) / [`range.filter`](./range#filter) возвращают **ленивые** адаптеры,
которые дают результат только после потребления через `collect` / `reduce` / `for_each` /
`for ... in`:

```yaoxiang
use std.assert
use std.list
use std.range
use std.result

main: () -> Void = {
    doubled = range.collect(range.map(result.unwrap(range.iter(1..4)), x => x * 2))
    assert(list.get(doubled, 0) == 2)
    assert(list.len(doubled) == 3)
}
```

## Доступность на платформах

Следующее зависит от возможностей операционной системы и **не экспортируется** для целевой платформы
`wasm32`:

| Область                                                         | Требует                |
| --------------------------------------------------------------- | ---------------------- |
| `std.os` полностью, `std.net` полностью, `std.weak` полностью   | Файлы/сеть             |
| `std.concurrent` полностью                                      | Потоки                 |
| `std.io.read_line` / `read_file` / `write_file` / `append_file` | Стандартный ввод/вывод |
| `std.time.sleep`                                                | Задержка потока        |

`std.string` / `std.list` / `std.dict` / `std.math` / `std.convert` / `std.result` / `std.range` /
`std.assert`, а также `std.io.print` / `println` / `format_fallback` доступны на всех платформах.

## Сопровождение документации

Данный раздел имеет **смешанную структуру (генерация + ручное написание)**:

- **Генерируемая область** (между маркерами `<!-- stdlib:KEY start/end -->`): сводные таблицы
  функций и блоки сигнатур, порождённые из `StdModule::exports()`. Сигнатуры побайтово берутся из
  `NativeExport::signature` и не могут расходиться с реализацией.
- **Рукописная область** (вне маркеров): обзоры модулей, семантика заимствования/перемещения, модель
  ошибок, известные пробелы и примеры.

Проверки (запускаются в CI вместе с `cargo test --lib`):

| Проверка                   | Тест                                          | Назначение                                                                 |
| -------------------------- | --------------------------------------------- | -------------------------------------------------------------------------- |
| Обнаружение расхождений    | `test_stdlib_docs_match_generation`           | Генерируемая область должна совпадать с `exports()`                        |
| Обнаружение потерянных     | `test_stdlib_docs_has_no_orphan_module_pages` | Страниц модулей не должно быть больше, чем генерирует генератор            |
| Покрытие                   | `test_stdlib_docs_covers_interface_modules`   | Набор документированных модулей должен покрывать представление интерфейсов |
| Работоспособность примеров | `test_stdlib_docs_examples_run`               | Каждый ```yaoxiang пример должен реально запускаться                       |

После изменения `exports()` используйте инструмент исправления для перезаписи генерируемой области:

```bash
cargo run --example gen-stdlib-docs
```

Это изоморфно по отношению к `gen-std-interfaces` (представление интерфейсов, RFC-037) и
`tools/code-tables --fix` (таблица кодов, RFC-013).
