# Справочник стандартной библиотеки

Стандартная библиотека YaoXiang (`std`) организована по модулям; каждый модуль импортируется через
`use` и вызывается как `имя_модуля.имя_функции(...)`. Данный каталог представляет собой справочную
документацию по API, разбитую по модулям.

## Соглашения об импорте

Импорт модуля целиком:

```yaoxiang
use std.list
use std.string

main: () -> Void = {
    parts = string.split("a,b,c", ",")
    println(list.len(parts))
}
```

Также возможен именованный импорт из модуля, включая константы:

```yaoxiang
use std.assert
use std.math.{E, PI, TAU}

main: () -> Void = {
    assert(PI > 3.14)
}
```

## Соглашения о заимствовании аргументов

Символ `&` в сигнатуре означает **автоматическое заимствование только для чтения** (RFC-009 §2.8):
переменная, переданная вызывающей стороной, не перемещается и остаётся доступной после вызова. Это
форма по умолчанию для большого количества функций только-для-чтения в стандартной библиотеке.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    nums = [1, 2, 3]

    // Во всех трёх вызовах nums заимствуется только для чтения, после чего остаётся доступной
    assert(list.len(nums) == 3)
    assert(list.len(nums) == 3)
    assert(list.contains(nums, 2))
}
```

Аргументы без `&` означают **передачу по значению**. Поэтому большинство «изменяющих» функций имеют
**функциональную форму, потребляющую исходное значение и возвращающую новое**, а не модификацию на
месте:

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    base = [1, 2]
    extended = list.push(base, 3)   // возвращается новый список; base перемещён
    assert(list.len(extended) == 3)
}
```

В разделе «Семантическая классификация» на странице каждого модуля перечислено, какие функции
заимствуют, какие потребляют, а какие изменяют на месте. Необходимо обратить внимание на два особых
случая:

- [`list.pop`](./list#pop) / [`list.remove_at`](./list#remove_at) помечены в сигнатуре как
  `&List(A)`, но **изменяют список на месте**
- Дескриптор, возвращаемый [`os.open`](./os#open), является **одноразовым** — цепочка `open` →
  `write` → `close` не скомпилируется

## Модель ошибок

В стандартной библиотеке существует две формы сбоя, которые в описании функций обозначаются как
«ошибка» и «возвращает …» соответственно:

| Форма                                   | Поведение                                                    | Типичный сценарий                                                                                     |
| --------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| Выбрасывается ошибка времени выполнения | Выполнение прерывается с кодом `E6xxx`                       | Отсутствующий ключ словаря `E6008`, выход за границы индекса `E6003`, сбой утверждения                |
| Возвращается сигнальное значение        | Выполнение не прерывается, возвращается `Void` / `-1` / `""` | Чтение за пределами списка, получение первого элемента пустого списка, отсутствующая переменная среды |

Распространённые коды ошибок времени выполнения:

| Код     | Значение                                            | Пример срабатывания                      |
| ------- | --------------------------------------------------- | ---------------------------------------- |
| `E6003` | Выход за границы индекса                            | `list.set(l, 99, v)`                     |
| `E6005` | Сбой утверждения                                    | `assert(false)`                          |
| `E6007` | Универсальная ошибка времени выполнения             | Файл не существует, сбой `result.unwrap` |
| `E6008` | Отсутствующий ключ                                  | `dict.get(d, "nope")`                    |
| `E6010` | Сбой разбора целого числа (как значение Err)        | `string.parse_int("abc")`                |
| `E6011` | Сбой разбора вещественного числа (как значение Err) | `string.parse_float("abc")`              |

Полная таблица кодов ошибок приведена в [Справочнике кодов ошибок](../error-code/).

`string.parse_int` / `string.parse_float` относятся к третьей форме: **ошибка не выбрасывается**, а
неудача оборачивается в значение `Err` типа `Result`, которое можно распаковать через
[`std.result`](./result) или распространить с помощью `?`.

```yaoxiang
use std.assert
use std.result
use std.string

main: () -> Void = {
    assert(result.is_ok(string.parse_int("42")))
    assert(result.is_err(string.parse_int("abc")))
}
```

## Протокол итератора

`std.list` и `std.range` предоставляют единый протокол итератора. Сам итератор представляет собой
носитель состояния типа `Tuple`.

> **Семантика перемещения**: `next` и `has_next` **перемещают** итератор (в сигнатуре нет `&`),
> поэтому при каждом обращении необходимо создавать его заново, либо использовать `for ... in`
> напрямую.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    it = list.iter([1, 2, 3])
    assert(list.has_next(it))

    // has_next переместил it; создаём заново, чтобы получить элемент
    it2 = list.iter([1, 2, 3])
    assert(list.next(it2) == 1)
}
```

Для повседневного обхода используйте `for ... in` напрямую:

```yaoxiang
use std.assert

main: () -> Void = {
    mut sum = 0
    for x in [1, 2, 3] {
        sum = sum + x
    }
    assert(sum == 6)
}
```

[`range.map`](./range#map) / [`range.filter`](./range#filter) возвращают **ленивые** адаптеры,
которые порождают результат только после потребления через `collect` / `reduce` / `for_each` /
`for ... in`:

```yaoxiang
use std.assert
use std.list
use std.range
use std.result

main: () -> Void = {
    doubled = range.collect(range.map(result.unwrap(range.iter(1..4)), x => x * 2))
    assert(list.get(doubled, 0) == 2)
    assert(list.len(doubled) == 3)
}
```

## Доступность на платформах

Следующие возможности зависят от операционной системы и **не экспортируются** для целевой платформы
`wasm32`:

| Область                                                         | Требуется              |
| --------------------------------------------------------------- | ---------------------- |
| `std.os` целиком, `std.net` целиком, `std.weak` целиком         | Файлы / сеть           |
| `std.concurrent` целиком                                        | Потоки                 |
| `std.io.read_line` / `read_file` / `write_file` / `append_file` | Стандартный ввод-вывод |
| `std.time.sleep`                                                | Задержка потока        |

`std.string` / `std.list` / `std.dict` / `std.math` / `std.convert` / `std.result` / `std.range` /
`std.assert`, а также `std.io.print` / `println` / `format_fallback` доступны на всех платформах.

## Сопровождение документации

Данный каталог имеет **гибридную структуру: сгенерированные + написанные вручную** части:

- **Сгенерированная область** (между маркерами `<!-- stdlib:KEY start/end -->`): сводные таблицы
  функций и сигнатуры, порождённые `StdModule::exports()`. Сигнатуры побайтово берутся из
  `NativeExport::signature`, что исключает их расхождение с реализацией.
- **Ручная область** (за пределами маркеров): обзоры модулей, семантика заимствования/перемещения,
  модель ошибок, известные пробелы и примеры.

Проверки (запускаются в CI вместе с `cargo test --lib`):

| Проверка               | Тест                                          | Назначение                                                                 |
| ---------------------- | --------------------------------------------- | -------------------------------------------------------------------------- |
| Обнаружение дрейфа     | `test_stdlib_docs_match_generation`           | Сгенерированная область должна совпадать с `exports()`                     |
| Обнаружение сирот      | `test_stdlib_docs_has_no_orphan_module_pages` | Страниц модулей не должно быть больше, чем производит генератор            |
| Покрытие               | `test_stdlib_docs_covers_interface_modules`   | Набор документированных модулей должен покрывать представление интерфейсов |
| Запускаемость примеров | `test_stdlib_docs_examples_run`               | Каждый ```yaoxiang пример должен реально выполняться                       |

После изменения `exports()` перепишите сгенерированные области с помощью инструмента-«лекаря`:

```bash
cargo run --example gen-stdlib-docs
```

Он изоморфен `gen-std-interfaces` (представление интерфейсов по RFC-037) и `tools/code-tables --fix`
(таблица кодов по RFC-013).
