# Справочник по стандартной библиотеке

Стандартная библиотека YaoXiang (`std`) организована в виде модулей; каждый модуль импортируется
через `use`, после чего его функции вызываются как `имя_модуля.имя_функции(...)`. Данный каталог
представляет собой справочную документацию по API, разделённую по модулям.

## Соглашения об импорте

Импорт модуля целиком:

```yaoxiang
use std.list
use std.string

main: () -> Void = {
    parts = string.split("a,b,c", ",")
    println(list.len(parts))
}
```

Можно также импортировать отдельные имена из модуля, включая константы:

```yaoxiang
use std.assert
use std.math.{E, PI, TAU}

main: () -> Void = {
    assert(PI > 3.14)
}
```

## Соглашения о заимствовании аргументов

Символ `&` в сигнатуре означает **автоматическое заимствование только для чтения** (RFC-009 §2.8):
переданная вызывающей стороной переменная не перемещается и может быть использована после вызова.
Это форма, принятая по умолчанию для многочисленных функций только-для-чтения в стандартной
библиотеке.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    nums = [1, 2, 3]

    // Во всех трёх вызовах nums заимствуется только для чтения, после чего доступен
    assert(list.len(nums) == 3)
    assert(list.len(nums) == 3)
    assert(list.contains(nums, 2))
}
```

Параметры без `&` означают **передачу по значению**. Большинство «модифицирующих» функций поэтому
имеют **функциональную форму, поглощающую исходное значение и возвращающую новое**, а не выполняют
изменение на месте:

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    base = [1, 2]
    extended = list.push(base, 3)   // возвращается новый список; base перемещён
    assert(list.len(extended) == 3)
}
```

В разделе «Семантическая классификация» на странице каждого модуля перечислено, какие функции
заимствуют, какие поглощают, а какие изменяют на месте. Здесь есть один особый случай, на который
стоит обратить внимание:

- [`list.pop`](./list#pop) / [`list.remove_at`](./list#remove_at) подписаны как `&List(A)`, однако
  фактически **изменяют список на месте**

## Модель ошибок

В стандартной библиотеке существует две формы сбоя, которые в описаниях функций отмечаются метками
«ошибка» и «возвращает …» соответственно:

| Форма                                   | Поведение                                                  | Типичный сценарий                                                                                         |
| --------------------------------------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Выбрасывается ошибка времени выполнения | Выполнение прерывается с кодом `E6xxx`                     | Отсутствующий ключ словаря `E6008`, выход индекса за границы `E6003`, сбой утверждения                    |
| Возвращается контрольное значение       | Не прерывает выполнение, возвращается `Void` / `-1` / `""` | Чтение за пределами списка, извлечение первого элемента из пустого списка, отсутствующая переменная среды |

Распространённые коды ошибок времени выполнения:

| Код     | Значение                                            | Пример срабатывания                      |
| ------- | --------------------------------------------------- | ---------------------------------------- |
| `E6003` | Выход индекса за границы                            | `list.set(l, 99, v)`                     |
| `E6005` | Сбой утверждения                                    | `assert(false)`                          |
| `E6007` | Универсальная ошибка времени выполнения             | Файл не существует, сбой `result.unwrap` |
| `E6008` | Отсутствующий ключ                                  | `dict.get(d, "nope")`                    |
| `E6010` | Сбой разбора целого числа (как значение Err)        | `string.parse_int("abc")`                |
| `E6011` | Сбой разбора вещественного числа (как значение Err) | `string.parse_float("abc")`              |

Полная таблица кодов ошибок приведена в [Справочнике по кодам ошибок](../error-code/).

`string.parse_int` / `string.parse_float` представляют третью форму: **без выбрасывания ошибки** —
неудача оборачивается в значение `Err` типа `Result`, которое можно распаковать через
[`std.result`](./result) либо распространить оператором `?`.

```yaoxiang
use std.assert
use std.result
use std.string

main: () -> Void = {
    assert(result.is_ok(string.parse_int("42")))
    assert(result.is_err(string.parse_int("abc")))
}
```

## Протокол итерации

`std.list` и `std.range` предоставляют единый протокол итераторов. Сам итератор представляет собой
носитель состояния `Tuple`.

> **Семантика перемещения**: `next` и `has_next` **перемещают** итератор (в их сигнатурах нет `&`),
> поэтому при каждом обращении требуется создавать его заново, либо сразу использовать `for ... in`.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    it = list.iter([1, 2, 3])
    assert(list.has_next(it))

    // has_next переместил it, поэтому для извлечения элемента создаём заново
    it2 = list.iter([1, 2, 3])
    assert(list.next(it2) == 1)
}
```

Для повседневного обхода используется `for ... in`:

```yaoxiang
use std.assert

main: () -> Void = {
    mut sum = 0
    for x in [1, 2, 3] {
        sum = sum + x
    }
    assert(sum == 6)
}
```

[`range.map`](./range#map) / [`range.filter`](./range#filter) возвращают **ленивые** адаптеры,
которые дают результат только после потребления через `collect` / `reduce` / `for_each` /
`for ... in`:

```yaoxiang
use std.assert
use std.list
use std.range
use std.result

main: () -> Void = {
    doubled = range.collect(range.map(result.unwrap(range.iter(1..4)), x => x * 2))
    assert(list.get(doubled, 0) == 2)
    assert(list.len(doubled) == 3)
}
```

## Доступность на платформах

Перечисленное ниже зависит от возможностей операционной системы и **не экспортируется** для целевой
платформы `wasm32`:

| Область                                                         | Требует                |
| --------------------------------------------------------------- | ---------------------- |
| `std.os` целиком, `std.net` целиком, `std.weak` целиком         | Файлы/сеть             |
| `std.concurrent` целиком                                        | Потоки                 |
| `std.io.read_line` / `read_file` / `write_file` / `append_file` | Стандартный ввод-вывод |
| `std.time.sleep`                                                | Засыпание потока       |

`std.string` / `std.list` / `std.dict` / `std.math` / `std.convert` / `std.result` / `std.range` /
`std.assert`, а также `std.io.print` / `println` / `format_fallback` доступны на всех платформах.

## Сопровождение документации

Данный каталог имеет **смешанную структуру: автоматическая генерация + ручное написание**:

- **Генерируемая область** (между маркерами `<!-- stdlib:KEY start/end -->`): сводные таблицы
  функций и блоки сигнатур, порождаемые из `StdModule::exports()`. Сигнатуры побайтово берутся из
  `NativeExport::signature` и не могут расходиться с реализацией.
- **Рукописная область** (за пределами маркеров): обзор модуля, семантика заимствования/перемещения,
  модель ошибок, известные пробелы и примеры.

Шлюзы контроля качества (выполняются в CI вместе с `cargo test --lib`):

| Шлюз                    | Тест                                          | Назначение                                                                 |
| ----------------------- | --------------------------------------------- | -------------------------------------------------------------------------- |
| Обнаружение расхождений | `test_stdlib_docs_match_generation`           | Генерируемая область должна совпадать с `exports()`                        |
| Обнаружение сирот       | `test_stdlib_docs_has_no_orphan_module_pages` | Страниц модулей не должно быть больше, чем выдаёт генератор                |
| Покрытие                | `test_stdlib_docs_covers_interface_modules`   | Набор документированных модулей должен покрывать представление интерфейсов |
| Запускаемость примеров  | `test_stdlib_docs_examples_run`               | Каждый пример на ```yaoxiang должен реально выполняться                    |

После изменения `exports()` воспользуйтесь целебной утилитой для перезаписи генерируемой области:

```bash
cargo run --example gen-stdlib-docs
```

Она изоморфна `gen-std-interfaces` (представление интерфейсов по RFC-037) и
`tools/code-tables --fix` (таблица кодов по RFC-013).
