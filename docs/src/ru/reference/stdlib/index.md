# Справочник по стандартной библиотеке

Стандартная библиотека YaoXiang (`std`) организована в виде модулей; каждый модуль импортируется
через `use`, после чего его функции вызываются в форме `имя_модуля.имя_функции(...)`. Данный раздел
содержит справочную документацию по API, разбитую по модулям.

## Соглашения об импорте

Импорт модуля целиком:

```yaoxiang
use std.list
use std.string

main: () -> Void = {
    parts = string.split("a,b,c", ",")
    println(list.len(parts))
}
```

Также можно импортировать из модуля по имени, включая константы:

```yaoxiang
use std.assert
use std.math.{E, PI, TAU}

main: () -> Void = {
    assert(PI > 3.14)
}
```

## Соглашения о заимствовании аргументов

Символ `&` в сигнатуре означает **автоматическое заимствование только для чтения** (RFC-009 §2.8):
переменная, переданная вызывающей стороной, не перемещается и может использоваться после вызова. Это
форма по умолчанию для многочисленных функций стандартной библиотеки только для чтения.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    nums = [1, 2, 3]

    // Во всех трёх вызовах nums заимствуется только для чтения, после чего по-прежнему доступен
    assert(list.len(nums) == 3)
    assert(list.len(nums) == 3)
    assert(list.contains(nums, 2))
}
```

Аргументы без `&` означают **передачу по значению**. Поэтому большинство «изменяющих» функций имеют
**функциональную форму, потребляющую исходное значение и возвращающую новое**, а не модификацию на
месте:

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    base = [1, 2]
    extended = list.push(base, 3)   // Возвращается новый список; base перемещён
    assert(list.len(extended) == 3)
}
```

В разделе «Семантическая классификация» на странице каждого модуля перечислено, какие функции
заимствуют, какие потребляют, а какие изменяют на месте. Один момент заслуживает особого внимания:

- [`list.pop`](./list#pop) / [`list.remove_at`](./list#remove_at) в сигнатуре помечены как
  `&List(A)`, но **изменяют список на месте**

## Модель ошибок

В стандартной библиотеке есть два вида отказов, которые в описании каждой функции помечаются
соответственно «ошибка» и «возвращает …»:

| Вид                            | Проявление                                               | Типичный сценарий                                                                                          |
| ------------------------------ | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Выбрасывает ошибку выполнения  | Завершает текущее выполнение с кодом `E6xxx`             | Отсутствие ключа в словаре `E6008`, выход индекса за границы `E6003`, сбой утверждения                     |
| Возвращает сигнальное значение | Не прерывает выполнение, возвращает `Void` / `-1` / `""` | Чтение за пределами списка, извлечение первого элемента из пустого списка, отсутствие переменной окружения |

Распространённые коды ошибок выполнения:

| Код ошибки | Значение                                            | Пример срабатывания                      |
| ---------- | --------------------------------------------------- | ---------------------------------------- |
| `E6003`    | Выход индекса за границы                            | `list.set(l, 99, v)`                     |
| `E6005`    | Сбой утверждения                                    | `assert(false)`                          |
| `E6007`    | Общая ошибка выполнения                             | Файл не существует, сбой `result.unwrap` |
| `E6008`    | Отсутствие ключа                                    | `dict.get(d, "nope")`                    |
| `E6010`    | Сбой разбора целого числа (как значение Err)        | `string.parse_int("abc")`                |
| `E6011`    | Сбой разбора вещественного числа (как значение Err) | `string.parse_float("abc")`              |

Полную таблицу кодов ошибок см. в [Справочнике по кодам ошибок](../error-code/).

`string.parse_int` / `string.parse_float` относятся к третьему виду: **не выбрасывают ошибку**, а
упаковывают сбой в значение `Err` типа `Result`, которое можно распаковать с помощью
[`std.result`](./result) или распространить через `?`.

```yaoxiang
use std.assert
use std.result
use std.string

main: () -> Void = {
    assert(result.is_ok(string.parse_int("42")))
    assert(result.is_err(string.parse_int("abc")))
}
```

## Протокол итерации

`std.list` и `std.range` предоставляют общий протокол итераторов. Сам итератор является носителем
состояния `Tuple`.

> **Семантика перемещения**: `next` и `has_next` обе **перемещают** итератор (в сигнатуре нет `&`),
> поэтому при каждом использовании его нужно создавать заново, либо сразу использовать `for ... in`.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    it = list.iter([1, 2, 3])
    assert(list.has_next(it))

    // has_next переместил it, поэтому перед извлечением элемента создаём заново
    it2 = list.iter([1, 2, 3])
    assert(list.next(it2) == 1)
}
```

Для повседневного обхода просто используйте `for ... in`:

```yaoxiang
use std.assert

main: () -> Void = {
    mut sum = 0
    for x in [1, 2, 3] {
        sum = sum + x
    }
    assert(sum == 6)
}
```

[`range.map`](./range#map) / [`range.filter`](./range#filter) возвращают **ленивые** адаптеры,
которые дают результат только после потребления через `collect` / `reduce` / `for_each` /
`for ... in`:

```yaoxiang
use std.assert
use std.list
use std.range
use std.result

main: () -> Void = {
    doubled = range.collect(range.map(result.unwrap(range.iter(1..4)), x => x * 2))
    assert(list.get(doubled, 0) == 2)
    assert(list.len(doubled) == 3)
}
```

## Доступность по платформам

Следующее зависит от возможностей ОС и **не экспортируется** для целевой платформы `wasm32`:

| Область                                                         | Требует                |
| --------------------------------------------------------------- | ---------------------- |
| `std.os` целиком, `std.net` целиком, `std.weak` целиком         | Файлы/сеть             |
| `std.concurrent` целиком                                        | Потоки                 |
| `std.io.read_line` / `read_file` / `write_file` / `append_file` | Стандартный ввод-вывод |
| `std.time.sleep`                                                | Засыпание потока       |

`std.string` / `std.list` / `std.dict` / `std.math` / `std.convert` / `std.result` / `std.range` /
`std.assert`, а также `std.io.print` / `println` / `format_fallback` доступны на всех целевых
платформах.

по всем открыты issue.

**Исправлено (2026-09-19)**: пункты #337 / #338 / #339 / #340 — все четыре исправлены, основной
текст соответствующих страниц переписан в виде инструкций по нормальному использованию:

| Расположение                                  | Исходная проблема                                                                 | Исправление                                             |
| --------------------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------- |
| [`os.open`](./os#open)                        | Дескриптор одноразовый, `open`→`write`→`close` не компилируется                   | Дескриптор передаётся по ссылке ✅                      |

| [`time.parse_time`](./time#parse_time)        | Параметр `fmt` игнорируется; возвращаемое значение нельзя использовать дальше     | Пошаговый разбор по fmt ✅                              |
| [`math.clamp`](./math#clamp)                  | `min > max` вызывает панику интерпретатора вместо возврата ошибки                 | Возвращает `E6007` ✅                                   |

## Сопровождение документации

Данный раздел имеет **смешанную структуру: генерируемая + ручная**:

- **Генерируемая область** (между метками `<!-- stdlib:KEY start/end -->`): сводные таблицы функций
  и блоки сигнатур, порождаемые из `StdModule::exports()`. Сигнатуры берутся побайтово из
  `NativeExport::signature` и не могут расходиться с реализацией.
- **Ручная область** (вне меток): обзор модуля, семантика заимствования/перемещения, модель ошибок,
  известные пробелы и примеры.

Проверки-шлюзы (выполняются в CI вместе с `cargo test --lib`):

| Шлюз                    | Тест                                          | Назначение                                                              |
| ----------------------- | --------------------------------------------- | ----------------------------------------------------------------------- |
| Обнаружение расхождений | `test_stdlib_docs_match_generation`           | Генерируемая область должна совпадать с `exports()`                     |
| Обнаружение сирот       | `test_stdlib_docs_has_no_orphan_module_pages` | Страниц модулей не должно быть больше, чем выдаёт генератор             |
| Покрытие                | `test_stdlib_docs_covers_interface_modules`   | Набор модулей в документации должен покрывать представление интерфейсов |
| Примеры выполняются     | `test_stdlib_docs_examples_run`               | Каждый пример ```yaoxiang должен реально запускаться                    |

После изменения `exports()` используйте целительный инструмент для перезаписи генерируемой области:

```bash
cargo run --example gen-stdlib-docs
```

Изоморфно `gen-std-interfaces` (представление интерфейсов RFC-037) и `tools/code-tables --fix`
(таблица кодов RFC-013).
