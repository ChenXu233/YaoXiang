# Справочник по стандартной библиотеке

Стандартная библиотека YaoXiang (`std`) организована по модулям; каждый модуль импортируется через
`use`, после чего вызывается как `имя_модуля.имя_функции(...)`. Данный каталог представляет собой
API-справочник, разбитый по модулям.

## Соглашения об импорте

Импорт модуля целиком:

```yaoxiang
use std.list
use std.string

main: () -> Void = {
    parts = string.split("a,b,c", ",")
    println(list.len(parts))
}
```

Также можно импортировать отдельные имена из модуля, включая константы:

```yaoxiang
use std.assert
use std.math.{E, PI, TAU}

main: () -> Void = {
    assert(PI > 3.14)
}
```

## Соглашения о заимствовании параметров

`&` в сигнатуре означает **автоматическое заимствование только для чтения** (RFC-009 §2.8):
переменная, переданная вызывающей стороной, не перемещается и после вызова может быть использована
дальше. Это форма по умолчанию для большинства функций только-для-чтения в стандартной библиотеке.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    nums = [1, 2, 3]

    // все три вызова только заимствуют nums, после чего он по-прежнему доступен
    assert(list.len(nums) == 3)
    assert(list.len(nums) == 3)
    assert(list.contains(nums, 2))
}
```

Параметр без `&` означает **передачу по значению**. Поэтому большинство «изменяющих» функций имеют
**функциональную форму, потребляющую исходное значение и возвращающую новое**, а не модификацию на
месте:

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    base = [1, 2]
    extended = list.push(base, 3)   // возвращает новый список; base уже перемещён
    assert(list.len(extended) == 3)
}
```

Раздел «Семантическая классификация» на странице каждого модуля перечисляет, какие функции
заимствуют, какие потребляют, а какие модифицируют на месте. Один момент заслуживает особого
внимания:

- [`list.pop`](./list#pop) / [`list.remove_at`](./list#remove_at) имеют сигнатуру `&List(A)`, но
  **модифицируют список на месте**

## Модель ошибок

Стандартная библиотека имеет две формы сбоев, которые в записях функций обозначены как «ошибка» и
«возвращает …» соответственно:

| Форма                            | Поведение                                     | Типичные сценарии                                                                                          |
| -------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Выброс ошибки времени выполнения | Завершает текущее выполнение с кодом `E6xxx`  | Отсутствующий ключ словаря `E6008`, выход за границы индекса `E6003`, сбой утверждения                     |
| Возврат контрольного значения    | Не прерывает, возвращает `Void` / `-1` / `""` | Чтение списка за границами, извлечение первого элемента из пустого списка, отсутствие переменной окружения |

Распространённые коды ошибок времени выполнения:

| Код ошибки | Значение                                                 | Пример срабатывания                      |
| ---------- | -------------------------------------------------------- | ---------------------------------------- |
| `E6003`    | Выход за границы индекса                                 | `list.set(l, 99, v)`                     |
| `E6005`    | Сбой утверждения                                         | `assert(false)`                          |
| `E6007`    | Универсальная ошибка времени выполнения                  | Файл не существует, сбой `result.unwrap` |
| `E6008`    | Отсутствующий ключ                                       | `dict.get(d, "nope")`                    |
| `E6010`    | Сбой разбора целого числа (как значение Err)             | `string.parse_int("abc")`                |
| `E6011`    | Сбой разбора числа с плавающей точкой (как значение Err) | `string.parse_float("abc")`              |

Полная таблица кодов ошибок приведена в [Справочнике по кодам ошибок](../error-code/).

`string.parse_int` / `string.parse_float` относятся к третьей форме: **не выбрасывают ошибку**, а
оборачивают сбой в значение `Err` типа `Result`, которое можно распаковать через
[`std.result`](./result) или распространить оператором `?`.

```yaoxiang
use std.assert
use std.result
use std.string

main: () -> Void = {
    assert(result.is_ok(string.parse_int("42")))
    assert(result.is_err(string.parse_int("abc")))
}
```

## Протокол итерации

`std.list` и `std.range` предоставляют единый протокол итератора. Сам итератор — это носитель
состояния типа `Tuple`.

> **Семантика перемещения**: `next` и `has_next` **перемещают** итератор (сигнатура без `&`),
> поэтому для каждого извлечения его нужно создавать заново, либо просто использовать `for ... in`.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    it = list.iter([1, 2, 3])
    assert(list.has_next(it))

    // has_next переместил it; создаём заново и извлекаем элемент
    it2 = list.iter([1, 2, 3])
    assert(list.next(it2) == 1)
}
```

Обычный обход делается непосредственно через `for ... in`:

```yaoxiang
use std.assert

main: () -> Void = {
    mut sum = 0
    for x in [1, 2, 3] {
        sum = sum + x
    }
    assert(sum == 6)
}
```

[`range.map`](./range#map) / [`range.filter`](./range#filter) возвращают **ленивые** адаптеры,
которые дают результат только после потребления через `collect` / `reduce` / `for_each` /
`for ... in`:

```yaoxiang
use std.assert
use std.list
use std.range
use std.result

main: () -> Void = {
    doubled = range.collect(range.map(result.unwrap(range.iter(1..4)), x => x * 2))
    assert(list.get(doubled, 0) == 2)
    assert(list.len(doubled) == 3)
}
```

## Доступность на платформах

Следующие возможности зависят от возможностей ОС и **не экспортируются** для целевой платформы
`wasm32`:

| Диапазон                                                        | Требуется              |
| --------------------------------------------------------------- | ---------------------- |
| `std.os` целиком, `std.net` целиком, `std.weak` целиком         | Файлы/сеть             |
| `std.concurrent` целиком                                        | Потоки                 |
| `std.io.read_line` / `read_file` / `write_file` / `append_file` | Стандартный ввод-вывод |
| `std.time.sleep`                                                | Ожидание потока        |

`std.string` / `std.list` / `std.dict` / `std.math` / `std.convert` / `std.result` / `std.range` /
`std.assert`, а также `std.io.print` / `println` / `format_fallback` доступны на всех платформах.

## Сопровождение документации

Данный каталог имеет **гибридную сгенерированную + рукописную** структуру:

- **Сгенерированная область** (между маркерами `<!-- stdlib:KEY start/end -->`): таблицы функций и
  блоки сигнатур, выводимые из `StdModule::exports()`. Сигнатуры побайтово берутся из
  `NativeExport::signature` и не могут расходиться с реализацией.
- **Рукописная область** (вне маркеров): обзор модуля, семантика заимствования/перемещения, модель
  ошибок, известные пробелы и примеры.

Шлюзы (запускаются в CI вместе с `cargo test --lib`):

| Проверка                        | Тест                                          | Назначение                                                                 |
| ------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------- |
| Обнаружение расхождений         | `test_stdlib_docs_match_generation`           | Сгенерированная область должна совпадать с `exports()`                     |
| Обнаружение осиротевших страниц | `test_stdlib_docs_has_no_orphan_module_pages` | Страниц модулей не должно быть больше, чем выдаёт генератор                |
| Покрытие                        | `test_stdlib_docs_covers_interface_modules`   | Набор документированных модулей должен покрывать представление интерфейсов |
| Запускаемость примеров          | `test_stdlib_docs_examples_run`               | Каждый ```yaoxiang пример должен реально запускаться                       |

После изменения `exports()` перепишите сгенерированную область инструментом-генератором:

```bash
cargo run --example gen-stdlib-docs
```

Изоморфно с `gen-std-interfaces` (представление интерфейсов RFC-037) и `tools/code-tables --fix`
(таблица кодов RFC-013).
