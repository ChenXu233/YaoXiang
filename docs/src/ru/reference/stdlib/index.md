# Справочник по стандартной библиотеке

Стандартная библиотека YaoXiang (`std`) организована по модулям. После импорта модуля через `use`
его функции вызываются в форме `имя_модуля.имя_функции(...)`. Данный раздел — это API-справочник,
разбитый по модулям.

## Соглашения об импорте

Импорт модуля целиком:

```yaoxiang
use std.list
use std.string

main: () -> Void = {
    parts = string.split("a,b,c", ",")
    println(list.len(parts))
}
```

Также возможен именной импорт из модуля, включая константы:

```yaoxiang
use std.assert
use std.math.{E, PI, TAU}

main: () -> Void = {
    assert(PI > 3.14)
}
```

## Соглашение о заимствовании параметров

Символ `&` в сигнатуре означает **автоматическое заимствование только для чтения** (RFC-009 §2.8):
переменная, переданная вызывающей стороной, не перемещается и остаётся доступной после вызова. Это
форма по умолчанию для большинства read-only функций стандартной библиотеки.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    nums = [1, 2, 3]

    // Все три вызова только читают nums, после них nums доступен
    assert(list.len(nums) == 3)
    assert(list.len(nums) == 3)
    assert(list.contains(nums, 2))
}
```

Параметр без `&` означает **передачу по значению**. Большинство «модифицирующих» функций поэтому
имеют **функциональную форму — потребляют исходное значение и возвращают новое**, а не изменяют на
месте:

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    base = [1, 2]
    extended = list.push(base, 3)   // возвращается новый список; base перемещён
    assert(list.len(extended) == 3)
}
```

В разделе «Семантическая классификация» на странице каждого модуля перечислено, какие функции
заимствуют, какие потребляют, а какие изменяют на месте. Есть два особых случая, на которые стоит
обратить внимание:

- [`list.pop`](./list#pop) / [`list.remove_at`](./list#remove_at) помечены в сигнатуре как
  `&List(A)`, но **изменяют список на месте**
- дескриптор, возвращаемый [`os.open`](./os#open), является **одноразовым**: цепочка `open` →
  `write` → `close` не компилируется

## Модель ошибок

Стандартная библиотека использует две формы сбоев; в описании функций они отмечены как «ошибка» и
«возвращает …» соответственно:

| Форма                            | Поведение                                                | Типичный сценарий                                                                                           |
| -------------------------------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Выброс ошибки времени выполнения | Завершает текущее выполнение с кодом `E6xxx`             | Отсутствующий ключ словаря `E6008`, выход за границы индекса `E6003`, сбой утверждения                      |
| Возврат контрольного значения    | Не прерывает выполнение, возвращает `Void` / `-1` / `""` | Чтение элемента списка за границами, взятие первого элемента пустого списка, отсутствующая переменная среды |

Часто встречающиеся коды ошибок времени выполнения:

| Код     | Значение                                            | Пример срабатывания                      |
| ------- | --------------------------------------------------- | ---------------------------------------- |
| `E6003` | Выход за границы индекса                            | `list.set(l, 99, v)`                     |
| `E6005` | Сбой утверждения                                    | `assert(false)`                          |
| `E6007` | Универсальная ошибка времени выполнения             | Файл не существует, сбой `result.unwrap` |
| `E6008` | Отсутствующий ключ                                  | `dict.get(d, "nope")`                    |
| `E6010` | Сбой разбора целого числа (как значение Err)        | `string.parse_int("abc")`                |
| `E6011` | Сбой разбора вещественного числа (как значение Err) | `string.parse_float("abc")`              |

Полный перечень кодов ошибок см. в [Справочнике по кодам ошибок](../error-code/).

`string.parse_int` / `string.parse_float` относятся к третьей форме: **не выбрасывают ошибку**, а
упаковывают неудачу в значение `Err` типа `Result`, которое можно распаковать через
[`std.result`](./result) или распространить оператором `?`.

```yaoxiang
use std.assert
use std.result
use std.string

main: () -> Void = {
    assert(result.is_ok(string.parse_int("42")))
    assert(result.is_err(string.parse_int("abc")))
}
```

## Протокол итераторов

`std.list` и `std.range` предоставляют единый протокол итераторов. Сам итератор — это `Tuple`,
несущий состояние.

> **Семантика перемещения**: и `next`, и `has_next` **перемещают** итератор (в сигнатуре нет `&`),
> поэтому при каждом обращении его нужно создавать заново, либо сразу использовать `for ... in`.

```yaoxiang
use std.assert
use std.list

main: () -> Void = {
    it = list.iter([1, 2, 3])
    assert(list.has_next(it))

    // has_next переместил it, создаём заново, прежде чем взять элемент
    it2 = list.iter([1, 2, 3])
    assert(list.next(it2) == 1)
}
```

Для повседневного обхода просто используйте `for ... in`:

```yaoxiang
use std.assert

main: () -> Void = {
    mut sum = 0
    for x in [1, 2, 3] {
        sum = sum + x
    }
    assert(sum == 6)
}
```

[`range.map`](./range#map) / [`range.filter`](./range#filter) возвращают **ленивые** адаптеры; для
получения результата их должен потребить `collect` / `reduce` / `for_each` / `for ... in`:

```yaoxiang
use std.assert
use std.list
use std.range
use std.result

main: () -> Void = {
    doubled = range.collect(range.map(result.unwrap(range.iter(1..4)), x => x * 2))
    assert(list.get(doubled, 0) == 2)
    assert(list.len(doubled) == 3)
}
```

## Доступность по платформам

Перечисленное ниже зависит от возможностей операционной системы и **не экспортируется** для целевой
платформы `wasm32`:

| Область                                                         | Требуется              |
| --------------------------------------------------------------- | ---------------------- |
| `std.os` целиком, `std.net` целиком, `std.weak` целиком         | Файлы/сеть             |
| `std.concurrent` целиком                                        | Потоки                 |
| `std.io.read_line` / `read_file` / `write_file` / `append_file` | Стандартный ввод-вывод |
| `std.time.sleep`                                                | Засыпание потока       |

`std.string` / `std.list` / `std.dict` / `std.math` / `std.convert` / `std.result` / `std.range` /
`std.assert`, а также `std.io.print` / `println` / `format_fallback` доступны на всех платформах.

## Сопровождение документации

Данный раздел имеет **гибридную структуру: сгенерированная + рукописная** части:

- **Сгенерированная часть** (между маркерами `<!-- stdlib:KEY start/end -->`): сводные таблицы
  функций и блоки сигнатур, порождаемые `StdModule::exports()`. Сигнатуры побайтово берутся из
  `NativeExport::signature` и не могут разойтись с реализацией.
- **Рукописная часть** (за пределами маркеров): обзор модуля, семантика заимствования/перемещения,
  модель ошибок, известные пробелы и примеры.

Шлюзы (запускаются в CI вместе с `cargo test --lib`):

| Шлюз                           | Тест                                          | Назначение                                                                 |
| ------------------------------ | --------------------------------------------- | -------------------------------------------------------------------------- |
| Обнаружение расхождений        | `test_stdlib_docs_match_generation`           | Сгенерированная часть должна совпадать с `exports()`                       |
| Обнаружение потерянных страниц | `test_stdlib_docs_has_no_orphan_module_pages` | Страниц модулей не должно быть больше, чем порождает генератор             |
| Покрытие                       | `test_stdlib_docs_covers_interface_modules`   | Набор документированных модулей должен покрывать представление интерфейсов |
| Запускаемость примеров         | `test_stdlib_docs_examples_run`               | Каждый ```yaoxiang пример должен реально выполняться                       |

После изменения `exports()` перепишите сгенерированную часть с помощью целительной утилиты:

```bash
cargo run --example gen-stdlib-docs
```

Она изоморфна `gen-std-interfaces` (представление интерфейсов RFC-037) и `tools/code-tables --fix`
(таблица кодов RFC-013).
