# Спецификация системы типов

Настоящий документ определяет спецификацию системы типов языка программирования YaoXiang, включая примитивные типы, составные типы, дженерики и трейты.

---

## Глава 0: Теоретические основы

### 0.1 Соответствие Карри-Ховарда

Соответствие Карри-Ховарда (Curry-Howard correspondence) является теоретической основой системы типов YaoXiang. Оно раскрывает глубокое соответствие между системой типов языка программирования и математической логикой:

| Логика | Язык программирования |
|--------|----------------------|
| Высказывание \(P\) | Тип `Type` |
| Доказательство \(p: P\) | Программа `x: T = ...` |
| Импликация \(P \rightarrow Q\) | Тип функции `(P) -> Q` |
| Конъюнкция \(P \wedge Q\) | Тип произведения `{ a: P, b: Q }` |
| Дизъюнкция \(P \vee Q\) | Тип суммы `{ a(P) \| b(Q) }` |
| Квантор всеобщности \(\forall x:T. P(x)\) | Дженерики `(T: Type) -> ...` |
| Истина \(\top\) | `Void` (Unit, имеет значение по умолчанию) |
| Ложь \(\bot\) | `Never` (нуль конструкторов, ни одно значение не может населять) |
| Вселенная типов \(Type_n : Type_{n+1}\) | Стратификация вселенных (предотвращение парадокса Рассела) |
| Анализ случаев | Сопоставление с образцом на уровне типов |

> **Примечание**: Сопоставление с образцом на уровне типов — это анализ случаев (case analysis), а не математическая индукция. Для индукции требуются рекурсивные функции на уровне типов + проверка завершимости компилятором.

### 0.2 Тип как высказывание, программа как доказательство

В YaoXiang это соответствие является первичным принципом проектирования:

- **Завершающиеся вычисления на уровне типов соответствуют корректным конструктивным доказательствам**. Семейства типов YaoXiang (такие как `Add` с анализом случаев + рекурсивный вызов на `Nat`) по сути являются кодированием математической индукции на уровне типов — при условии, что компилятор выполняет проверку завершимости.
- **Проверка типов — это проверка доказательства**. Когда программа проходит проверку типов, это эквивалентно конструктивному доказательству логического высказывания.

### 0.3 Влияние на проектирование языка

Конкретное проявление соответствия Карри-Ховарда в YaoXiang:

1. **Стратификация вселенных** (RFC-010): `Type₀ : Type₁ : Type₂ …` избегает логических парадоксов (парадокс Жирара), вызванных `Type: Type`
2. **Семейства типов** (RFC-011): анализ случаев + рекурсивный вызов на уровне типов для натуральных чисел `Nat(Zero/Succ)` соответствует аксиомам Пеано — при условии, что компилятор выполняет проверку завершимости
3. **Условные типы** (RFC-011): `If: (C: Bool, T: Type, E: Type) -> Type` соответствует логической дизъюнкции случаев
4. **Типы, зависящие от значений** (RFC-011): `Vec: (n: Int) -> Type` соответствует ограниченной квантификации "для каждого целого числа n существует тип"

### 1.1 Выражения типов

```
TypeExpr    ::= PrimitiveType
              | RecordType
              | InterfaceType
              | TupleType
              | FnType
              | GenericType
              | TypeRef
              | TypeUnion
              | TypeIntersection
```

> **Пояснение к проектированию**: Хотя RFC-010 предлагает унифицированную модель "всё есть присваивание" (`name: type = value`), на уровне синтаксиса типы и значения всё же необходимо различать. В реализации компилятора `Type` и `Expr` — это два независимых перечисления AST (`ast.rs:406` и `ast.rs:25`), `TypeExpr` служит BNF-заполнителем, соответствующим перечислению `Type` в реализации и означающим "в этой позиции ожидается тип".

## Глава 2: Примитивные типы

### 2.1 Примитивные типы

| Тип | Логическое соответствие | Описание | Размер по умолчанию |
|-----|------------------------|----------|---------------------|
| `Type` | — | Метатип | 0 байт |
| `Never` | ⊥ (ложь/пустой тип) | Нуль конструкторов, ни одного значения. Тип возврата при расходимости/panic. `Never <: T` выполняется для любого T. | 0 байт |
| `Void` | ⊤ (истина/Unit) | Имеет значение void по умолчанию, тип произведения с нулевым числом полей. Допустимо `x: Void = <по умолчанию>`. | 0 байт |
| `Bool` | — | Логическое значение: `true` / `false` | 1 байт |
| `Int` | — | Знаковое целое число | 8 байт |
| `Uint` | — | Беззнаковое целое число | 8 байт |
| `Float` | — | Число с плавающей точкой | 8 байт |
| `String` | — | Строка в кодировке UTF-8 | переменный |
| `Char` | — | Символ Unicode | 4 байта |
| `Bytes` | — | Сырые байты | переменный |

Целые с разрядностью: `Int8`, `Int16`, `Int32`, `Int64`, `Int128`
Вещественные с разрядностью: `Float32`, `Float64`

### 2.2 Never и Void: ⊥ и ⊤

`Never` и `Void` — это логические примитивы системы типов, соответствующие лжи (⊥) и истине (⊤) соответственно.

**Never (⊥, ложь/пустой тип)** — три безоговорочных свойства:

1. **Нуль конструкторов**: Ни один литерал или выражение не может породить значение типа `Never`. Для `x: Never = ...` нет правой части, которую можно было бы записать.
2. **Принцип взрыва**: `Never <: T` выполняется для любого типа `T`. `assert(false)` возвращает `Never`, после чего последующий код проходит проверку типов (хотя никогда не будет выполнен).
3. **Маркер расходимости**: `f: (...) -> Never` означает, что `f` гарантированно не возвращается. Компилятор использует это для анализа мёртвого кода и слияния ветвей `match`.

`Never` — это встроенное имя типа (с тем же путём регистрации, что и `Int`/`Bool`), а не ключевое слово.

**Void (⊤, истина/Unit)** — ровно один обитатель (значение void по умолчанию). `Void` — это единичный элемент для типа произведения с нулевым числом полей. Допустимо `x: Void = <по умолчанию>`, функция по умолчанию возвращает `Void`, если не имеет явного `return`.

## Глава 3: Составные типы

### 3.1 Тип записи

**Унифицированный синтаксис**: `Name: Type = { field1: Type1, field2: Type2, ... }`

```
RecordType  ::= '{' FieldList? '}'
FieldList   ::= Field (',' Field)* ','?
Field       ::= Identifier ':' TypeExpr
            |  Identifier                 // ограничение интерфейса
```

```yaoxiang
// Простой тип записи
Point: Type = { x: Float, y: Float }

// Пустой тип записи
Empty: Type = {}

// Тип записи с дженериками
Pair: (T: Type) -> Type = { first: T, second: T }

// Тип записи, реализующий интерфейсы
Point: Type = {
    x: Float,
    y: Float,
    Drawable,
    Serializable
}
```

**Правила**:
- Тип записи определяется с помощью фигурных скобок `{}`
- После имени поля сразу следуют двоеточие и тип
- Имя интерфейса, записанное в теле типа, означает реализацию этого интерфейса

> **Принадлежность пространству имён**: Префикс `Type.name` (например, `Point.draw`) указывает, что функция принадлежит пространству имён `Point`.
> Это не вызывает никакого неявного связывания. Чтобы синтаксис вызова через `.` (например, `p.draw()`) работал, необходимо явное связывание:
> `Point.draw = draw[0]`.
> Подробности см. в RFC-004 и RFC-010.

#### 3.1.1 Значения полей по умолчанию

Поля типа могут иметь значения по умолчанию; при создании они могут быть указаны опционально:

```yaoxiang
// Поля со значениями по умолчанию - опциональны при создании
Point: Type = {
    x: Float = 0,
    y: Float = 0
}

// Использование
Point()           // -> Point(x=0, y=0)
Point(x=1)       // -> Point(x=1, y=0)
Point(x=1, y=2) // -> Point(x=1, y=2)

// Поля без значений по умолчанию - обязательны при создании
Point2: Type = {
    x: Float,
    y: Float
}

// Использование
Point2(x=1, y=2) // Корректно
Point2()          // Ошибка
```

**Правила**:
- `field: Type = expression` -> имеет значение по умолчанию, опционально при создании
- `field: Type` -> без значения по умолчанию, обязательно при создании

#### 3.1.2 Встроенное связывание

В теле определения типа можно напрямую связывать методы:

```yaoxiang
// Способ 1: Ссылка на внешнюю функцию для связывания
distance: (a: Point, b: Point) -> Float = { ... }
Point: Type = {
    x: Float = 0,
    y: Float = 0,
    distance = distance[0]    // Связывание с позицией 0
}
// Вызов: p1.distance(p2) -> distance(p1, p2)

// Способ 2: Анонимная функция + позиционное связывание
Point: Type = {
    x: Float = 0,
    y: Float = 0,
    distance: ((a: Point, b: Point) -> Float)[0] = ((a, b) => {
        dx = a.x - b.x
        dy = a.y - b.y
        return (dx * dx + dy * dy).sqrt()
    })
}
// Синтаксис: ((params) => body)[position]
// Вызов: p1.distance(p2) -> distance(p1, p2)
```

### 3.2 Тип интерфейса

```
InterfaceType ::= '{' FnField (',' FnField)* ','?
FnField       ::= Identifier ':' FnType
FnType        ::= '(' ParamTypes? ')' '->' TypeExpr
```

**Синтаксис**: Интерфейс — это тип записи, все поля которого являются типами функций

```yaoxiang
// Определение интерфейса
Drawable: Type = {
    draw: (Surface) -> Void,
    bounding_box: () -> Rect
}

Serializable: Type = {
    serialize: () -> String
}

// Пустой интерфейс
EmptyInterface: Type = {}
```

**Реализация интерфейса**: Тип реализует интерфейсы путём перечисления их имён в конце определения

```yaoxiang
// Тип, реализующий интерфейсы
Point: Type = {
    x: Float,
    y: Float,
    Drawable,        // Реализация интерфейса Drawable
    Serializable     // Реализация интерфейса Serializable
}
```

**Прямое присваивание интерфейсу**: Конкретный тип может быть напрямую присвоен переменной интерфейсного типа (структурная подтипизация)

```yaoxiang
// Прямое присваивание (конкретный тип определим во время компиляции -> вызов без накладных расходов)
d: Drawable = Circle(1)
d.draw(screen)        // После компиляции: прямой вызов circle_draw, без vtable

// Возвращаемое значение функции (не может быть определено во время компиляции -> вызов через vtable)
d: Drawable = get_shape()
d.draw(screen)        // Поиск метода через vtable

// Интерфейс как параметр функции
process: (d: Drawable) -> Void = d.draw(screen)
```

**Стратегия оптимизации во время компиляции**:

| Сценарий | Результат вывода | Способ вызова |
|----------|------------------|---------------|
| Прямое присваивание конкретного типа | Конкретный тип определим | Прямой вызов (без накладных расходов) |
| Возвращаемое значение функции | Неизвестно | vtable |
| Гетерогенная коллекция | Несколько типов | vtable |

### 3.4 Тип кортежа

```
TupleType   ::= '(' TypeList? ')'
TypeList    ::= TypeExpr (',' TypeExpr)* ','?
```

### 3.5 Тип функции

```
FnType      ::= '(' ParamList? ')' '->' TypeExpr
ParamList   ::= TypeExpr (',' TypeExpr)*
```

## Глава 4: Дженерики

### 4.1 Синтаксис параметров дженериков

Параметры дженериков являются частью типа функции и используют единый синтаксис `()` наравне с обычными параметрами:

```
GenericType     ::= Identifier '(' TypeArgList ')'
TypeArgList     ::= TypeExpr (',' TypeExpr)* ','?
TypeBound       ::= Identifier
                 |  Identifier '+' Identifier ('+' Identifier)*
```

В определении дженерик-типа `(T: Type)` — это сигнатура параметров конструктора типа, а `-> Type` указывает возвращаемый тип:

```yaoxiang
List: (T: Type) -> Type = { ... }
Map: (K: Type, V: Type) -> Type = { ... }
```

В дженерик-функциях параметры типов также объявляются в сигнатуре, и компилятор автоматически выводит их из фактических аргументов:

```yaoxiang
map: (T: Type, R: Type) -> ((list: List(T), f: (T) -> R) -> List(R)) = ...
```

### 4.2 Определение дженерик-типа

```yaoxiang
// Базовый дженерик-тип
Option: (T: Type) -> Type = {
    some: (T) -> Option(T),
    none: () -> Option(T)
}

Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Result(T, E),
    err: (E) -> Result(T, E)
}

List: (T: Type) -> Type = {
    data: Array(T),
    length: Int,
    push: (self: List(T), item: T) -> Void,   // self — просто соглашение об именовании, не ключевое слово
    get: (self: List(T), index: Int) -> Option(T)
}
```

### 4.3 Вывод типов

```yaoxiang
// Компилятор автоматически выводит параметры дженериков
numbers: List(Int) = List(1, 2, 3)  // Компилятор выводит List(Int)
```

## Глава 5: Ограничения типов

### 5.1 Одиночное ограничение

```
ConstrainedType ::= '(' Identifier ':' TypeBound ')' TypeExpr
```

```yaoxiang
// Определение интерфейса (выступающего как ограничение)
Clone: Type = {
    clone: () -> Clone
}

// Использование ограничения
clone: (T: Clone)(value: T) -> T = value.clone()
```

### 5.2 Множественные ограничения

```yaoxiang
// Синтаксис множественных ограничений
combine: (T: Clone + Add)(a: T, b: T) -> T = {
    a.clone() + b
}

// Сортировка дженерик-контейнера
sort: (T: Clone + PartialOrd)(list: List(T)) -> List(T) = {
    result = list.clone()
    quicksort(&mut result)
    return result
}
```

### 5.3 Ограничения типа функции

```yaoxiang
// Ограничения для функций высшего порядка
call_twice: (T: Type, F: () -> T)(f: F) -> (T, T) = (f(), f())

compose: (A: Type, B: Type, C: Type, F: (A) -> B, G: (B) -> C)(a: A, f: F, g: G) -> C = g(f(a))
```

Iterator: (T: Type) -> Type = {
    Item: T,                    // Ассоциированный тип
    next: () -> Option(T),
    has_next: () -> Bool

// Использование ассоциированного типа
collect: (T: Type, I: Iterator(T))(iter: I) -> List(T) = {

        if let Some(item) = iter.next() {
            result.push(item)
        }
    }
    return result
}

## Глава 7: Дженерики времени компиляции

### 7.1 Параметры-константы времени компиляции

```
LiteralType   ::= Identifier ':' Int          // константа времени компиляции
CompileTimeFn ::= '(' Identifier ':' Int ')' '(' Identifier ')' '->' TypeExpr
```

**Ключевая идея**: Используя параметр дженерика `(n: Int)` + параметр значения `(n: n)`, различаются константы времени компиляции и значения времени выполнения.

```yaoxiang
// Факториал времени компиляции: аргумент должен быть литералом, известным во время компиляции
factorial: (n: Int)(n: n) -> Int = {
    match n {
        0 => 1,
        _ => n * factorial(n - 1)
    }
}

// Массив констант времени компиляции
StaticArray: (T: Type, N: Int) -> Type = {
    data: Array(T, N),      // Размер известен во время компиляции
    length: N
}

// Использование
arr: StaticArray(Int, factorial(5))  // Компилятор вычисляет factorial(5) = 120 во время компиляции
```

### 7.2 Массивы констант времени компиляции

## Глава 8: Условные типы

### 8.1 Условный тип If

```
IfType        ::= 'If' '(' BoolExpr ',' TypeExpr ',' TypeExpr ')'
```

```yaoxiang
// If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E
}

// Пример: ветвление во время компиляции
NonEmpty: (T: Type) -> Type = If(T != Void, T, Never)
// IsTrue как мост и Assert как уточняющий тип (подробности см. в §8.3)
IsTrue: (b: Bool) -> Type = match b {
    true => Void,      // ⊤, программа продолжается
    false => Never,    // ⊥, расходимость/ошибка компиляции
}
Assert: (cond: Bool) -> Type = IsTrue(cond)
```
### 8.2 Семейства типов

```yaoxiang
// Преобразование типов во время компиляции
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String
}
```


### 8.3 Уточняющий тип Assert и утверждение assert

`assert` и `Assert` — это две стороны одного уточняющего примитива, автоматически выбираемого dispatch-конвейером по принципу "достижимы ли свободные переменные предиката во время компиляции".

**Базовая сигнатура**: `assert: (cond: Bool, ?msg: String | Error) -> Assert(IsTrue(cond))`

**Правила диспетчеризации**:

| Критерий | Режим | Поведение |
|----------|-------|-----------|
| Все свободные переменные известны во время компиляции (параметры дженериков, константы времени компиляции) | CompileTime | Входит в конвейер доказательств: true → стирается в Void, false → ошибка компиляции (Never не может быть населён) |
| Существуют свободные переменные времени выполнения (параметры функции, внешний ввод) | Runtime | Вставляется проверка Bool во время выполнения, в чувствительный к потоку набор предположений Γ инжектируется уточняющий факт |

**Чувствительный к потоку набор предположений Γ**:

Компилятор поддерживает набор известных высказываний для каждой точки потока управления:

```yaoxiang
assert(x > 0)       // Γ = {x > 0}
y = x + 1           // Γ = {x > 0, y > 1}  ← распространение SP
mut x = x - 5       // Γ = {}  ← mut kill set: старые предположения более не действительны
```

После присваивания переменной `mut` все предположения, связанные с этой переменной, удаляются (kill set). При слиянии ветвей Γ является пересечением предположений ветвей.

## Глава 11: Свойства типов

В YaoXiang существует только одно свойство типов, которое нужно различать: линейность vs возможность копирования. Оно выводится компилятором автоматически.

### 11.1 Move (передача владения по умолчанию)

Все типы по умолчанию следуют семантике Move. Присваивание, передача параметра, возврат = передача владения.

```yaoxiang
p: Point = Point(1.0, 2.0)
q = p           // Move, p больше не может быть прочитан
```

### 11.2 Dup (поверхностное копирование: копирование дескриптора, общие данные)

**Свойство Dup используется для типов ссылок/токенов**. Присваивание типа Dup = поверхностное копирование — копируется дескриптор/токен, нижележащие данные являются общими. Несколько владельцев указывают на один и тот же блок данных.

| Тип | Свойство | Описание |
|-----|----------|----------|
| `&T` | Dup | Токен чтения нулевого размера; копирование токена = несколько точек зрения на одни данные |
| `ref T` | Dup | Копирование Rc/Arc = счётчик ссылок +1, общие данные в куче |
| `&mut T` | Linear | Токен записи нулевого размера, эксклюзивный, не копируется |
| Все остальные типы | Move | Передача владения по умолчанию |

**Примитивные типы значений** (Int, Float, Bool, Char) — это специальная встроенная обработка компилятора: при присваивании автоматически копируется значение, два значения полностью независимы. Это нативное поведение компилятора, не относящееся к свойству Dup.

```yaoxiang
// &T: Dup, свободное создание псевдонимов
view: &Point = &p
view2 = view     // Dup: копирование токена, оба действительны
print(view.x)    // Доступно
print(view2.x)   // Доступно

// &mut T: Linear, не копируется
mut_ref: &mut Point = &mut p
// r2 = mut_ref  // ❌ &mut T не Dup, нельзя копировать
```

### 11.3 Clone (явное глубокое копирование) и его отношение к Dup

**Clone** — это интерфейс явного глубокого копирования. Все типы могут реализовать Clone, предоставляя метод `.clone()`.

```yaoxiang
// Определение интерфейса Clone (стандартная библиотека)
Clone: Type = {
    clone: () -> Clone
}

// Использование
p: Point = Point(1.0, 2.0)
backup = p.clone()    // Глубокое копирование, p по-прежнему доступен
p2 = p.clone()        // Можно клонировать несколько раз
```

**Различия между Dup и Clone**:

| | Dup | Clone |
|---|---|---|
| **Семантика** | Поверхностное копирование: копирование дескриптора/токена, общие нижележащие данные | Глубокое копирование: создание полной независимой копии |
| **Способ вызова** | Неявный (автоматически при присваивании/передаче параметра) | Явный (`.clone()`) |
| **Влияние изменений** | Взаимное (общие нижележащие данные) | Не влияют друг на друга (независимые копии) |
| **Применимые типы** | Токены `&T`, `ref T` | Любой тип, реализующий интерфейс Clone |
| **Стоимость** | Нулевые накладные расходы (токен — тип нулевого размера) | Зависит от типа |

**Dup не влечёт Clone, Clone не влечёт Dup** — это две ортогональные концепции:

```yaoxiang
// Тип Dup: копирование токена, общие нижележащие данные
view: &Point = &p
view2 = view        // Dup: копирование токена, оба указывают на один и тот же p
print(view.x)       // Доступно
print(view2.x)      // Доступно, видят одни и те же данные

// Примитивный тип значения: автоматическое копирование значения компилятором (не Dup)
x: Int = 42
y = x               // Копирование значения, x и y полностью независимы
print(x)            // Доступно

// Clone: явное глубокое копирование, создание независимой копии
p: Point = Point(1.0, 2.0)
q = p.clone()       // Clone: глубокое копирование, p по-прежнему доступен
r = p               // Move: передача владения, потому что Point не Dup и не примитивный тип значения
```

**Замысел проектирования**:
- Dup используется для типов токенов/ссылок, решая проблему "несколько точек зрения на одни и те же данные"
- Clone используется в сценариях, где нужна независимая копия; явный вызов делает стоимость видимой
- Копирование примитивных типов значений (Int/Float/Bool/Char) — встроенное поведение компилятора, не относится к Dup
- Большинство пользовательских типов по умолчанию Move, обеспечивая нулевое копирование и высокую производительность

## Глава 12: Типы токенов заимствования

### 12.1 Основные концепции

`&T` и `&mut T` — это **токены типов нулевого размера на этапе компиляции**. Это не "ссылки", а "доказательства на уровне типов права доступа".

```
&T      →  Нулевой размер, замораживает исходные данные (запрещает получение WriteToken в этот период),
          при гарантии замораживания множественное чтение безопасно → Dup (можно копировать)
&mut T  →  Нулевой размер, исключительные чтение и запись (запрещает любые другие токены),
          при исключительном доступе копирование бессмысленно → Linear (не Dup)
```

**Ключевые свойства**:
- Токен — это **обычный тип**, подчиняющийся тем же правилам области видимости, что и все остальные типы
- Не требует аннотации времени жизни `'a`
- Не требует специального анализатора заимствований — свойства типов (Dup/Linear) естественным образом выводят права
- Полностью исчезает после компиляции, нулевые накладные расходы во время выполнения

### 12.2 Базовое использование

```yaoxiang
// На стороне метода: объявление типа параметра определяет требуемые права
Point.print: (self: &Point) -> Void = {
    print(self.x)               // Токен &Point даёт право чтения
    print(self.y)
}

Point.shift: (self: &mut Point, dx: Float, dy: Float) -> Void = {
    self.x = self.x + dx        // Токен &mut Point даёт право записи
    self.y = self.y + dy
}

// На стороне вызова: компилятор автоматически выбирает заимствование или Move
p = Point(1.0, 2.0)
p.print()                       // Компилятор автоматически создаёт токен &Point
p.shift(1.0, 1.0)              // Компилятор автоматически создаёт токен &mut Point
p.print()                       // OK, предыдущий токен был освобождён по завершении вызова shift

// Несколько токенов &T сосуществуют — тип Dup разрешает свободное копирование
distance: (a: &Point, b: &Point) -> Float = {
    sqrt((a.x - b.x)**2 + (a.y - b.y)**2)
}
d = distance(p, p2)
```

### 12.3 Область видимости и распространение токенов

Токен — это обычный тип, поэтому он поддерживает все операции, доступные обычным типам:

**Возврат токена** — токен распространяется вместе с возвращаемым значением:

```yaoxiang
// ✅ Подтокен и родительский токен возвращаются вместе
Point.get_x: (self: &Point) -> (&Float, &Point) = {
    return (&self.x, self)
}

p = Point(1.0, 2.0)
(px_ref, p) = p.get_x()        // Токен возвращается вызывающему
print(px_ref)                    // OK, токен всё ещё в области видимости
```

**Сохранение в структуре** — структура может содержать поля-токены:

```yaoxiang
// ✅ Структура содержит токен в качестве поля
Window: Type = {
    target: Point,
    view: &Point,              // Поле-токен — содержит представление target только для чтения
}
```

**Захват замыканием** — замыкание захватывает токены, как и любые другие значения:

```yaoxiang
// ✅ Замыкание захватывает токен &Float (тип Dup, свободно копируется в замыкание)
filter_by_threshold: (items: List(Point), threshold: &Float) -> List(Point) = {
    items.filter(|p| p.x > threshold)
}
```

### 12.4 Автоматический выбор заимствования

На стороне вызова компилятор автоматически выбирает по следующему приоритету:

```
1. Если аргумент будет использоваться далее → приоритет: создать токен (&T или &mut T, в зависимости от сигнатуры метода)
2. Если аргумент больше не будет использоваться → Move
3. Порядок приоритета: &T < &mut T < Move
```

```yaoxiang
p = Point(1.0, 2.0)
p.print()          // Тип параметра print — &Point → компилятор создаёт токен &Point
p.shift(1.0, 1.0)  // Тип параметра shift — &mut Point → компилятор создаёт токен &mut Point
p2 = p             // Далее не используется → Move
```

### 12.5 Обнаружение конфликтов токенов

Компилятор выполняет **чувствительный к потоку анализ живучести** значений токенов, отслеживая состояние каждого токена (активен/перемещён):

```yaoxiang
// ❌ &mut и производный &T не могут быть одновременно активны
bad_alias: (p: &mut Point) -> Void = {
    p.x = 10.0                   // ✅ Обычное использование WriteToken
    print(p.y)
}

// ✅ Токен автоматически освобождается по завершении области видимости
good_seq: (p: &mut Point) -> Void = {
    {
        // Внутренняя область видимости
        print(p.x)               // Используется &mut Point
    }
    // Конец внутренней области видимости
    p.x = 10.0                   // ✅ WriteToken всё ещё доступен
}

// ❌ Из одного и того же аргумента нельзя одновременно создать токен &mut и другой токен
alias_bad: (a: &mut Point, b: &Point) -> Void = { ... }
p = Point(1.0, 2.0)
alias_bad(p, p)                  // ❌ p одновременно порождает токены &mut и &
```

### 12.6 Внутреннее устройство компилятора: механизм брендинга

Пользователь никогда не взаимодействует с брендингом. Компилятор внутри назначает каждому токену уникальный идентификатор на этапе компиляции:

```
Видимое пользователю         Внутреннее представление компилятора
────────────────────────────────────────
&Point         →  ReadToken(Point, #N)    // #N — уникальное целое на этапе компиляции
&mut Point     →  WriteToken(Point, #M)   // #M — уникальное целое на этапе компиляции
```

Назначение брендинга:
- **Предотвращение подделки**: Токен может быть получен только из капсулы владельца, не может быть сконструирован из ниоткуда
- **Отслеживание связей**: Производный `&Float` от доступа к полю несёт производный бренд (`#N.field_x`), компилятор может отследить его до родительского токена
- **Обнаружение конфликтов**: WriteToken и производный ReadToken из одного источника не могут быть одновременно активны

Брендинг полностью исчезает после мономорфизации и инлайнинга, в сгенерированном машинном коде он отсутствует. **Нулевые накладные расходы во время выполнения.**

### 12.7 Sum-тип токенов

```
&BorrowToken ::= &T          // ReadToken (замораживает исходные данные → Dup безопасен)
               | &mut T      // WriteToken (исключительные чтение-запись → Linear)
```

### 12.8 Токены заимствования vs ref

| | `&T` / `&mut T` | `ref` |
|------|------|------|
| Что делает | Взглянуть / изменить на месте | Общее владение |
| Область | С областью видимости значения токена | Через области видимости |
| Стоимость | Нулевые накладные расходы (тип нулевого размера, исчезает после компиляции) | Rc или Arc (выбирает компилятор) |
| Побег | Возможен (токен распространяется через возвращаемое значение/структуру/замыкание) | Именно для этого и предназначен |
| Между задачами | Невозможно (токены не поддерживают передачу между задачами) | Возможно (компилятор автоматически выбирает Arc) |
| Обнаружение циклов | Не применимо | Молчаливое в пределах задачи, lint между задачами |

// === Move（默认） ===
// 所有类型默认 Move。赋值、传参、返回 = 所有权转移

// === 原语值类型（编译器内置） ===
Int, Float,     // 赋值时自动值复制，两个值完全独立
Bool, Char      // 不是 Dup，是编译器对原语的内置处理

// === Dup（浅拷贝：复制句柄，共享底层数据） ===

// === Clone（显式深复制） ===

```

### A.4 Краткий справочник токенов заимствования

// 调用端自动选择
// 1. 实参后续还有使用 → 创建令牌
// 2. 实参后续不再使用 → Move
// 3. 优先匹配：&T < &mut T < Move

// 令牌传播
// ✅ 可返回、可存结构体、可被闭包捕获
// ❌ 不可跨任务（令牌未实现跨任务传递）
```
