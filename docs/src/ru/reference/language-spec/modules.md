# Система модулей: спецификация

Данный документ определяет спецификацию системы модулей языка программирования YaoXiang, включая
определение модулей, импорт/экспорт и области видимости.

---

## Глава 1: Определение модулей

### 1.1 Основы модулей

В качестве границ модулей используются файлы. Каждый файл `.yx` — это модуль.

```
// Имя файла является именем модуля
// Math.yx
pub pi: Float = 3.14159
pub sqrt: (x: Float) -> Float = (x) => { ... }
```

### 1.2 Правила именования модулей

- Имя модуля определяется именем файла
- Расширение файла `.yx` не участвует в имени модуля
- Имена модулей используют нотацию PascalCase

## Глава 2: Импорт модулей

### 2.1 Синтаксис импорта

```
Import       ::= 'use' ModuleRef ImportSpec?
ImportSpec   ::= ('{' ImportItems '}') ('as' AliasList)?
              |  'as' AliasList
ImportItems  ::= Identifier (',' Identifier)* ','?
AliasList    ::= Identifier (',' Identifier)*
```

### 2.2 Способы импорта

| Синтаксис                    | Описание                                     | Пример                                          |
| ---------------------------- | -------------------------------------------- | ----------------------------------------------- |
| `use path;`                  | Импорт модуля, доступ по последней части     | `use std.io;` -> `io.print`                     |
| `use path.{a, b};`           | Импорт указанных элементов                   | `use std.io.{print};` -> `print`                |
| `use path as alias;`         | Импорт с переименованием                     | `use std.io as io;` -> `io.print`               |
| `use path.{i1, i2} as a, b;` | Импорт указанных элементов с переименованием | `use std.io.{print, read} as p, r;` -> `p`, `r` |

### 2.3 Примеры импорта

```yaoxiang
// Импорт всего модуля
use std.io
io.print("Hello")

// Импорт указанных элементов
use std.io.{print, read}
print("Hello")

// Импорт с переименованием
use std.io as io_module
io_module.print("Hello")

// Импорт указанных элементов с переименованием
use std.io.{print, read} as p, r
p("Hello")
```

## Глава 3: Экспорт модулей

### 3.1 Ключевое слово `pub`

Для объявления экспортируемых элементов используется ключевое слово `pub`:

```yaoxiang
// Math.yx
pub pi: Float = 3.14159
pub sqrt: (x: Float) -> Float = (x) => { ... }

// Приватный элемент (не экспортируется)
internal_value: Int = 42
```

### 3.2 Правила экспорта

- По умолчанию все элементы являются приватными
- Элементы, объявленные с `pub`, доступны из других модулей
- Приватные элементы доступны только внутри текущего модуля

### 3.3 Автоматическое связывание `pub`

Для функций, объявленных с `pub`, компилятор автоматически выполняет привязку к типам, определённым
в том же файле:

```yaoxiang
// Объявление с pub, компилятор выполняет автоматическое связывание
pub distance: (p1: Point, p2: Point) -> Float = {
    dx = p1.x - p2.x
    dy = p1.y - p2.y
    (dx * dx + dy * dy).sqrt()
}

// Автоматический вывод компилятора:
// 1. Point определён в текущем файле
// 2. Параметры функции содержат Point
// 3. Выполнить Point.distance = distance[0]

// Вызов
d = distance(p1, p2)           // Функциональный
d2 = p1.distance(p2)           // Синтаксический сахар ООП
```

## Глава 4: Области видимости

### 4.1 Область видимости модуля

Каждый модуль имеет собственную область видимости; элементы внутри модуля по умолчанию недоступны
извне.

### 4.2 Вложенные области видимости

```yaoxiang
// Область видимости блока
{
    x = 10
    // x виден внутри данной области видимости
}
// x не виден за пределами данной области видимости

// Область видимости функции
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result не виден за пределами функции
```

### 4.3 Объявление переменных и затенение

В YaoXiang нет ключевого слова `let`. Является ли `x = value` объявлением или присваиванием? Следует
одному принципу:

**Приоритет присваивания.** Объявление выполняется лишь единожды, а присваивание — многократно.
Пусть частые операции идут по кратчайшему пути.

```
x = value:
  Поиск x по цепочке областей видимости наружу
    → Найден mut x          : присваивание, OK (через токен &mut)
    → Найден x (перемещён)   : считается "допустимая привязка не найдена", повторное объявление в текущей области видимости
    → Найден x (неизменяемый, живой) : E2010 невозможно повторно присвоить
    → Не найден              : новое объявление в текущей области видимости (единственный путь объявления)

mut x = value:
    → x уже существует в текущей области видимости : E2002 повторное определение
    → x существует во внешней области видимости  : E2013 запрет затенения (явное новое объявление не может иметь то же имя, что и внешнее)
    → Конфликтов нет          : новое изменяемое объявление
```

- **В одной области видимости**: любое имя может быть объявлено только один раз (E2002)
- **Во внутренней области без `mut`**: приоритетный поиск во внешней области, присваивание или
  ошибка
- **Во внутренней области с `mut`**: явное новое объявление, запрещено совпадение имён с внешней
  областью (E2013)

> **Блок — это настоящая область видимости**: предпосылкой «поиска по цепочке областей видимости»
> является то, что каждый блок `{}` действительно создаёт свой уровень — имена, объявленные во
> внутренней области, **не утекают наружу** (см. §2.15).

#### В одной области видимости

```yaoxiang
x = 10
x = 20              // E2010: 'x' неизменяемый, нельзя присвоить повторно

mut y = 10
y = 20              // OK: та же привязка, повторное присваивание
mut y = 30          // E2002: 'y' уже определён в данной области видимости (явное новое объявление конфликтует)

z = 10
mut z = 20          // E2002: 'z' уже определён в данной области видимости (mut не может перезаписать существующее объявление)
```

Обратите внимание, что `x = 20` выдаёт **E2010** (невозможно повторно присвоить), а не E2002
(повторное определение): `x = value` без `mut` семантически является **присваиванием** (поиск по
цепочке областей видимости), а не «повторным объявлением x». Только `mut x = value` является явным
новым объявлением, и конфликт имён в этом случае выдаёт E2002.

#### Повторная привязка после Move

Если неизменяемая переменная обладает владением, после того как её значение перемещено (поглощено),
исходная привязка переходит в состояние **moved** — имя по-прежнему занимает слот в области
видимости, но значение становится недоступным. В этом случае `x = value` не модифицирует старую
привязку, а повторно объявляет `x` в той же области видимости.

```
Ветвь "перемещён" при приоритетном поиске присваивания:
  x существует в текущей области видимости, но находится в состоянии moved
    → Компилятор считает "допустимая привязка не найдена"
    → Повторное объявление x в текущей области видимости (перезаписывает старый слот moved)
```

**Ключевой механизм:** после того как старое значение поглощено, привязка становится
недействительной, и имя возвращается в состояние «объявляемое». Это не затенение — старая привязка
уже не существует.

```yaoxiang
// Конвейерный поток данных: каждый шаг поглощает старое значение и порождает новое
data = fetch()           // Неизменяемое, владеет
data = transform(data)   // move data → старая data становится недействительной, новая data привязывается заново
data = filter(data)      // То же самое
process(data)

// Эквивалентная явная запись (для сравнения):
data1 = fetch()
data2 = transform(data1)  // data1 перемещён, повторное использование невозможно
data3 = filter(data2)     // data2 перемещён, повторное использование невозможно
process(data3)
```

**Семантическое разделение:**

| Операция               | Значение                                   | Механизм                    | Синтаксис      |
| ---------------------- | ------------------------------------------ | --------------------------- | -------------- |
| **Повторная привязка** | Старое значение исчезает, появляется новое | move + повторное объявление | `x = f(x)`     |
| **Изменение на месте** | Изменение значения в той же области памяти | присваивание mut            | `mut x; x = v` |

**Почему это отличается от затенения:**

- Затенение (Rust `let x = ...`): старая привязка по-прежнему существует, просто скрыта новой
- Повторная привязка после Move: старая привязка уже поглощена, имя возвращается в
  неинициализированное состояние, повторное объявление — единственный выход

**Ограничения:**

- Перемещать можно только значения, обладающие владением. Ссылки (`&T`, `&mut T`) копируются, а не
  перемещаются
- Проверка Move выполняется на этапе компиляции; чтение переменной в состоянии moved в любом
  выражении вызовет E2014
- IDE может отображать серую подсказку на перемещённых переменных, указывающую на
  неинициализированное состояние имени

```yaoxiang
// Чтение после move → ошибка
data = fetch()
result = process(data)   // data перемещён
print(data)              // E2014: 'data' был перемещён, повторное использование невозможно

// Ссылки не вызывают move
ref_data = &value
copy1 = ref_data         // Копирование ссылки, ref_data по-прежнему доступна
copy2 = ref_data         // OK

// Между областями видимости: состояние moved проникает наружу
data = fetch()
{
    data = transform(data)  // move внешней data → повторная привязка (новое объявление во внутренней области)
    print(data)             // OK: используется внутренняя data
}
print(data)                 // E2014: внешняя data была перемещена
```

#### Между областями видимости

```yaoxiang
// Внешняя неизменяемая, внутреннее присваивание → неизменяемую переменную нельзя присвоить повторно
x = 10
{
    x = 20          // E2010: 'x' неизменяемый, нельзя присвоить повторно
}
{
    mut x = 20      // E2013: нельзя затенить существующую переменную 'x' (явное объявление новой привязки)
}

// Внешняя mut, внутреннее присваивание → модификация той же привязки
mut y = 10
{
    y = 20          // OK: та же привязка, модификация через токен &mut
}
print(y)            // 20

// Внешняя mut, во внутренней области нельзя объявлять одноимённую
mut z = 10
{
    z = 30          // OK: та же привязка
}
{
    mut z = 30      // E2013: нельзя затенить существующую переменную 'z'
}

// Множественная вложенность: mut проникает через все уровни
mut a = 0
{
    {
        a = 10      // OK
    }
}
print(a)            // 10

// Неизменяемое нельзя повторно присвоить даже через все уровни вложенности
b = 0
{
    {
        b = 10      // E2010: 'b' неизменяемый, нельзя присвоить повторно
    }
}
```

#### Цикл for

```yaoxiang
// Переменная цикла на каждой итерации — новая привязка, а не модификация
for i in 1..5 {
    print(i)        // OK: на каждой итерации новое значение привязки
    i = 10          // E2010: неизменяемая переменная цикла, нельзя присвоить повторно
}

for mut i in 1..5 {
    i = 10          // OK: изменяемая переменная цикла
}

// Переменная цикла не может затенять внешнюю
i = 0
for i in 1..5 {     // E2013: нельзя затенить существующую переменную 'i'
}

// Изменяемый внешний аккумулятор можно модифицировать внутри тела цикла
mut sum = 0
for i in 1..5 {
    sum = sum + i   // OK: та же привязка, модификация через токен &mut
}
print(sum)          // 15

// Неизменяемый внешний аккумулятор нельзя модифицировать внутри тела цикла
sum2 = 0
for i in 1..5 {
    sum2 = sum2 + i // E2010: 'sum2' неизменяемый, нельзя присвоить повторно
}
```

#### Связанные коды ошибок

| Код   | Сообщение                                      | Сценарий срабатывания                                                                           |
| ----- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| E2002 | `'{name}' is already defined in this scope`    | Повторное объявление в одной области видимости (независимо от mut)                              |
| E2010 | `Cannot assign to immutable variable '{name}'` | При присваивании без `mut` во внутренней области внешняя переменная неизменяема и не перемещена |
| E2013 | `Cannot shadow existing variable '{name}'`     | Внутреннее явное объявление (`mut x` или `x: Type`) совпадает по имени с внешним                |
| E2014 | `'{name}' has been moved and cannot be used`   | Чтение уже перемещённой переменной                                                              |

## Глава 5: Организация модулей

### 5.1 Структура каталогов

```
src/
├── main.yx          // Главный модуль
├── math/
│   ├── index.yx     // Точка входа модуля math
│   ├── vector.yx    // Модуль векторов
│   └── matrix.yx    // Модуль матриц
└── utils/
    ├── index.yx     // Точка входа модуля utils
    └── string.yx    // Утилиты для строк
```

### 5.2 Точка входа модуля

Файл `index.yx` в каталоге служит точкой входа модуля:

```yaoxiang
// math/index.yx
use math.vector
use math.matrix

pub Vector = vector.Vector
pub Matrix = matrix.Matrix
```

### 5.3 Относительный импорт

```yaoxiang
// В math/vector.yx
use math.matrix  // Абсолютный импорт
use .matrix      // Относительный импорт (тот же каталог)
```
