# Спецификация синтаксиса

В этом документе определяется спецификация синтаксиса языка программирования YaoXiang, включая
лексическую структуру, синтаксические правила и приоритет операторов.

---

## Глава 1: Лексическая структура

### 1.1 Исходный файл

Исходные файлы YaoXiang должны использовать кодировку UTF-8. Исходные файлы обычно имеют расширение
`.yx`.

### 1.2 Классификация лексических единиц

| Категория      | Описание                                       | Пример                    |
| -------------- | ---------------------------------------------- | ------------------------- |
| Идентификатор  | Начинается с буквы или подчёркивания           | `x`, `_private`, `my_var` |
| Ключевое слово | Предопределённые зарезервированные слова языка | `Type`, `pub`, `use`      |
| Литерал        | Фиксированное значение                         | `42`, `"hello"`, `true`   |
| Оператор       | Символ операции                                | `+`, `-`, `*`, `/`        |
| Разделитель    | Синтаксический разделитель                     | `(`, `)`, `{`, `}`, `,`   |

### 1.3 Ключевые слова

YaoXiang определяет крайне малое количество ключевых слов:

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

Эти ключевые слова имеют особое значение в любом контексте и не могут использоваться в качестве
идентификаторов.

### 1.4 Зарезервированные слова

«Зарезервированные слова» YaoXiang разделены на три уровня, которые распознаются парсером (parser) и
проверщиком типов (type checker) на разных этапах:

#### 1.4.1 Литеральные зарезервированные слова

Парсер имеет независимые токены для литеральных идентификаторов, которые не могут использоваться как
обычные идентификаторы:

| Идентификатор | Принадлежность к типу | Описание                                                                                                    |
| ------------- | --------------------- | ----------------------------------------------------------------------------------------------------------- |
| `Type`        | —                     | Ключевое слово метатипа                                                                                     |
| `true`        | Bool                  | Логическое значение «истина»                                                                                |
| `false`       | Bool                  | Логическое значение «ложь»                                                                                  |
| `void`        | Void                  | Литерал Void (значение Unit). Строчный `void` — литерал значения; заглавный `Void` — имя типа (см. §1.4.3). |

#### 1.4.2 Конструкторы выражений

Следующие конструкторы распознаются парсером в контекстах сопоставления с образцом и выражений:

| Конструктор | Принадлежность к типу | Описание                             |
| ----------- | --------------------- | ------------------------------------ |
| `some(T)`   | Option                | Конструктор варианта значения Option |
| `ok(T)`     | Result                | Успешный вариант Result              |
| `err(E)`    | Result                | Вариант ошибки Result                |

#### 1.4.3 Встроенные имена типов

Следующие имена типов предварительно зарегистрированы проверщиком типов и могут использоваться в
позиции типа без импорта. Парсер рассматривает их как обычные идентификаторы — **это не
зарезервированные слова, они могут быть затенены (shadow) локальными привязками (не
рекомендуется)**.

| Имя типа | Логическое соответствие | Описание                                                                                                                                              |
| -------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤ (Истина/Unit)         | Тип-произведение с нулём полей, ровно один обитатель (литерал `void`, см. §1.4.1)                                                                     |
| `Never`  | ⊥ (Ложь/пустой тип)     | Тип с нулём вариантов, ноль обитателей. Никакое выражение не может породить значение `Never`. `Never <: T` справедливо для всех `T` (принцип взрыва). |
| `Int`    | —                       | Целое число со знаком                                                                                                                                 |
| `Float`  | —                       | Число с плавающей точкой                                                                                                                              |
| `Bool`   | —                       | Логическое значение: `true` / `false`                                                                                                                 |
| `Char`   | —                       | Символ Unicode                                                                                                                                        |
| `String` | —                       | Строка                                                                                                                                                |

### 1.5 Идентификаторы

Идентификаторы начинаются с буквы или подчёркивания, последующие символы могут быть буквами, цифрами
или подчёркиваниями. Идентификаторы чувствительны к регистру.

Специальные идентификаторы:

- `_` используется как заглушка, означающая игнорирование значения
- Идентификаторы, начинающиеся с подчёркивания, обозначают приватные члены

### 1.6 Литералы

#### 1.6.1 Целые числа

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 Числа с плавающей точкой

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 Строки

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 Коллекции

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Array       ::= '[' Expr (',' Expr)* ']'   // При аннотации целевого типа как Array(T, N) литерал становится массивом фиксированной длины
```

> #299: Set не имеет литерального синтаксиса — для множеств используйте конструктор `std.set`. Место
> определения литералов List/Dict определяется аннотацией контекстного типа: голый литерал и литерал
> с аннотацией `List(T)` попадают в расширяемый список; аннотация `Array(T, N)`, применённая
> непосредственно к литералу, формирует массив фиксированной длины. Неявное преобразование
> List→Array запрещено.

#### 1.6.5 Генератор списков

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

#### 1.6.6 Проверка принадлежности

```
Membership  ::= Expr 'in' Expr
```

> #299 §3: `in` — бинарный оператор отношения, возвращающий `Bool` — `true` при попадании, `false`
> при непопадании, без ошибки. Семантическое разделение: `[]` — это утверждение существования и
> извлечение значения (ошибка при неудаче), `in` — это запрос о наличии (непопадание — нормальный
> `false`). Покрытие правого операнда: List / Array / Dict(набор ключей) / Set / Tuple /
> String(подстрока) / Range(интервал). `in` — это предикат Хоара первого класса, основа для
> компиляционно доказуемых утверждений на этапе уточнения типов.

### 1.7 Комментарии

```
// однострочный комментарий

/* многострочный комментарий
   может охватывать несколько строк */
```

### 1.8 Правила отступов

Код должен использовать 4 пробела для отступов, использование символов табуляции запрещено. Это
обязательное синтаксическое правило.

## Глава 2: Синтаксические правила

### 2.1 Классификация выражений

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 Приоритет операторов

| Приоритет | Оператор                    | Ассоциативность |
| --------- | --------------------------- | --------------- |
| 1         | `()` `[]` `.` `?`           | Слева направо   |
| 2         | `as`                        | Слева направо   |
| 3         | Унарный префикс `!` `-` `+` | Справа налево   |
| 4         | `*` `/` `%`                 | Слева направо   |
| 5         | `+` `-`                     | Слева направо   |
| 6         | `..`                        | Слева направо   |
| 7         | `<<` `>>`                   | Слева направо   |
| 8         | `&` `\|` `^`                | Слева направо   |
| 9         | `==` `!=` `<` `>` `<=` `>=` | Слева направо   |
| 10        | `and` `or`                  | Слева направо   |
| 11        | `if...else`                 | Справа налево   |
| 12        | `=` `+=` `-=` `*=` `/=`     | Справа налево   |

> **Унарные префиксные операторы** (`!` `-` `+`) плотно связываются: только ниже вызова и доступа к
> членам, выше всех бинарных операторов. Поэтому `!a == b` ≡ `(!a) == b` (семантика в стиле Zig);
> `!` — чистая унарная операция, не участвующая в короткозамыкающем потоке управления, ортогональна
> ключевым словам `and`/`or` (короткое замыкание) (авторитетное определение RFC-010).

### 2.3 Вызов функции

```
FnCall      ::= Expr '(' ArgList? ')'
ArgList     ::= Expr (',' Expr)* (',' NamedArg)* | NamedArg (',' NamedArg)*
NamedArg    ::= Identifier ':' Expr
```

### 2.4 Доступ к члену

```
MemberAccess::= Expr '.' Identifier
```

### 2.5 Доступ по индексу

```
IndexAccess ::= Expr '[' Expr ']'
```

### 2.6 Преобразование типа

```
TypeCast    ::= Expr 'as' TypeExpr
```

### 2.7 Условное выражение

```
IfExpr      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 2.8 Сопоставление с образцом

```
MatchExpr   ::= 'match' Expr '{' MatchArm+ '}'
MatchArm    ::= Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
Pattern     ::= Literal
              | Identifier
              | Wildcard
              | StructPattern
              | TuplePattern
              | EnumPattern
              | OrPattern
```

### 2.9 Блочное выражение

```
Block       ::= '{' Stmt* Expr? '}'
```

> **Правила завершения операторов**: Разделение между Stmt и поведение переноса строк (явное
> разделение `;`, завершение переносом строки, исключения для продолжения строки, никогда не
> объединять `(`/`[` в начале строки) определены в
> [RFC-038](../design/rfc/draft/038-statement-termination.md).

**Единообразная семантика**: семантика return для всех блоков `{}` согласована:

| Тип блока    | Семантика return         | Возврат по умолчанию |
| ------------ | ------------------------ | -------------------- |
| Обычный `{}` | Возврат значения         | Void                 |
| `unsafe {}`  | Возврат определения типа | Void                 |
| `spawn {}`   | Возврат результата       | Void                 |

**Основные принципы**:

- `return` в `{}` всегда возвращает содержимое во внешнюю область видимости
- По умолчанию отсутствие `return` означает возврат `Void`
- Форма выражения `= expr` непосредственно возвращает значение

```yaoxiang
// Обычный блок {}: return возвращает значение
result = {
    x = compute()
    return x  // возвращает значение во внешнюю область видимости
}

// Блок unsafe {}: return возвращает определение типа
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    return SqliteDb  // возвращает определение типа во внешнюю область видимости
}

// Блок spawn {}: return возвращает результат
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    return (result1, result2)  // возвращает результат во внешнюю область видимости
}
```

### 2.10 Лямбда-выражение

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 Оператор распространения ошибки

```
ErrorPropagate ::= Expr '?'
```

Оператор `?` является постфиксным оператором с приоритетом, равным `.`. Для типа `Result(T, E)`:

- При `Ok(v)` извлекает значение `v` и продолжает выполнение
- При `Err(e)` распространяет ошибку вверх (`return Err(e)`)

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // при успехе извлекает значение, при неудаче распространяет вверх
    transform(validated)
}
```

### 2.12 Выражение диапазона

```
RangeExpr   ::= Expr '..' Expr
```

`..` создаёт тип диапазона, используемый для цикла `for` и срезов.

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]
```

### 2.13 Выражение ref

```
RefExpr     ::= 'ref' Expr
```

`ref` создаёт общее владение. Компилятор автоматически выбирает Rc (одна задача) или Arc (между
задачами), пользователю не нужно беспокоиться о деталях реализации.

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // между задачами: компилятор автоматически выбирает Arc
```

### 2.14 Выражение unsafe

```
UnsafeExpr  ::= 'unsafe' Block
```

Блок `unsafe` используется для определения непрозрачных типов и работы с сырыми указателями.
Используйте `return`, чтобы вернуть определение типа во внешнюю область видимости.

**Семантика**:

- В `unsafe {}` можно определять типы и работать с сырыми указателями
- Возвращённый тип доступен за пределами `unsafe {}`
- Доступ к полям типа требует разрешения unsafe

```yaoxiang
// Определение непрозрачного типа в блоке unsafe
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // сырой указатель
    }
    return SqliteDb
}

// SqliteDb доступен за пределами блока unsafe
db = sqlite3_open("test.db")
```

### 2.15 Область видимости

**Основные правила**:

- Каждый блок `{}` создаёт область видимости
- Внутренняя область видимости может обращаться к переменным внешней области видимости
- Внешняя область видимости не может обращаться к переменным внутренней области видимости
- Объявление переменных следует принципу «приоритет присваивания»

```yaoxiang
// Блочная область видимости
{
    x = 10
    // x видна в данной области видимости
}
// x невидима за пределами данной области видимости

// Область видимости функции
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result невидима за пределами функции
```

**Объявление и затенение переменных**:

- `x = value`: поиск x вверх по цепочке областей видимости — если найдена, присваивает; если не
  найдена, объявляет новую
- `mut x = value`: явное новое изменяемое объявление, запрещено совпадение имени с внешней областью
- В одной области видимости любое имя может быть объявлено только один раз

> **Подробное определение**: полные правила области видимости, объявления и затенения переменных см.
> в [Спецификации системы модулей](./modules.md#第四章作用域).

```
ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block
```

#### 3.9.1 Семантика: каждая итерация — новое связывание

Семантика цикла for в YaoXiang отличается от традиционных языков: **каждая итерация создаёт новое
связывание, а не модифицирует одну и ту же переменную**.

```yaoxiang
// Пример: for i in 1..5
for i in 1..5 {
    print(i)
}
```

**Процесс выполнения**:

| Итерация   | Поведение переменной цикла                                                                                  |
| ---------- | ----------------------------------------------------------------------------------------------------------- |
| 1-я        | Создаётся новое связывание `i = 1`, выполняется тело цикла, печатается 1                                    |
| 2-я        | Создаётся новое связывание `i = 2` (предыдущее связывание уничтожено), выполняется тело цикла, печатается 2 |
| 3-я        | Создаётся новое связывание `i = 3`, выполняется тело цикла, печатается 3                                    |
| 4-я        | Создаётся новое связывание `i = 4`, выполняется тело цикла, печатается 4                                    |
| Завершение | Тело цикла завершается, связывание уничтожается                                                             |

**Ключевой момент**: после завершения каждой итерации созданное в этой итерации связывание
уничтожается. Следующая итерация представляет собой совершенно новое связывание, никак не связанное
со связыванием предыдущей итерации.

#### 3.9.2 Различие между for и for mut

| Синтаксис           | Изменяемость переменной цикла | Описание                                      |
| ------------------- | ----------------------------- | --------------------------------------------- |
| `for i in 1..5`     | Неизменяемая                  | Нельзя модифицировать связывание в теле цикла |
| `for mut i in 1..5` | Изменяемая                    | Можно модифицировать связывание в теле цикла  |

```yaoxiang
// Допустимо: каждая итерация связывает новое значение, модификация не требуется
for i in 1..5 {
    print(i)  // чтение значения i
}

// Ошибка: неизменяемое связывание, нельзя модифицировать
for i in 1..5 {
    i = i + 1  // ошибка: нельзя модифицировать неизменяемое связывание
}

// Допустимо: использование for mut разрешает модификацию связывания
for mut i in 1..5 {
    i = i + 1  // модификация разрешена
}
```

#### 3.9.3 Проверка затенения

YaoXiang запрещает затенение переменных. Переменная цикла for не может иметь то же имя, что и
переменная во внешней области видимости:

```yaoxiang
// Ошибка: i уже объявлена во внешней области
i = 10
for i in 1..5 {
    print(i)
}

// Правильно: использование другого имени переменной
i = 10
for j in 1..5 {
    print(j)
}
```

Это правило применяется ко всем блокам кода, подробности см. в
[§4.3 Правила затенения](./modules.md#43-遮蔽规则).

#### 3.9.4 Сравнение с другими языками

| Язык     | Семантика переменной цикла for                                         |
| -------- | ---------------------------------------------------------------------- |
| YaoXiang | Каждая итерация — новое связывание                                     |
| Rust     | Модификация одной и той же переменной (требуется mut)                  |
| Python   | Модификация одной и той же переменной (без mut)                        |
| C/C++    | Модификация одной и той же переменной (требуется указатель или ссылка) |

**Обоснование дизайна**: YaoXiang применяет семантику связывания по следующим причинам:

1. **Более соответствует естественной семантике** В естественном языке фраза «для каждого элемента x
   в множестве» означает, что каждый x является независимой сущностью. YaoXiang-овское
   `for i in 1..5` читается как «для каждого i от 1 до 5», и i в каждой итерации — это совершенно
   новое связывание, что согласуется с человеческой интуицией.

2. **Предотвращение случайных модификаций** Семантика неизменяемого связывания по умолчанию
   означает, что переменная цикла не может быть случайно модифицирована внутри тела цикла. Не нужно
   беспокоиться о том, что где-то в сложном теле цикла случайно напишется `i = ...`, что приведёт к
   трудноотслеживаемой ошибке.

3. **Высокопроизводительные решения под рукой** Когда действительно необходимо повторно использовать
   переменную между итерациями (например, аккумулятор, кэш), используйте `for mut` для переключения
   в режим изменяемого связывания. Это яснее, чем неявное разделение состояния — намерение
   выражается явно через синтаксис, а не скрывается в поведении времени выполнения.

### 3.10 Оператор spawn

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**Spawn блок**: явное объявление параллельной области; выражения в блоке выполняются параллельно.

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**Spawn цикл**: параллельный по данным цикл.

```yaoxiang
results = spawn for item in items {
    process(item)
}
```

**Spawn блок захватывает переменные внешней области** (RFC-024 §2.3, семантика захвата значений):

- Ссылки на внешние переменные в теле блока = **захват значения через Move**: значение снимается в
  окружение замыкания в точке создания spawn, тело блока читает через env (LoadUpvalue)
- **Примитивы** (Int/Float/Bool/Char) — копируются по значению, внешняя переменная не затрагивается
- **Типы-дескрипторы** (Struct/String/List и т.д.) — снимок = копия дескриптора, общий базовый
  объект; во встроенной среде выполнения (по умолчанию) один поток — одна куча, дескриптор
  действителен
- Совместное использование несколькими задачами требует явного `ref` (§2.13, компилятор
  автоматически выбирает Rc/Arc)
- `return` внутри блока ссылается на захваченные внешние переменные тем же способом

```yaoxiang
t1 = 1 + 1
t2 = 2 + 2
result = spawn {
    return t1 + t2    // t1/t2 захвачены по значению, result == 6
}
```
