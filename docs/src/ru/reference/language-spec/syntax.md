# Спецификация синтаксиса

Данный документ определяет спецификацию синтаксиса языка программирования YaoXiang, включая
лексическую структуру, правила грамматики и приоритет операторов.

---

## Глава 1: Лексическая структура

### 1.1 Исходный файл

Файлы исходного кода YaoXiang должны использовать кодировку UTF-8. Файлы исходного кода обычно имеют
расширение `.yx`.

### 1.2 Классификация лексических единиц

| Категория      | Описание                                        | Пример                    |
| -------------- | ----------------------------------------------- | ------------------------- |
| Идентификатор  | Начинается с буквы или подчёркивания            | `x`, `_private`, `my_var` |
| Ключевое слово | Предопределённое языком зарезервированное слово | `Type`, `pub`, `use`      |
| Литерал        | Фиксированное значение                          | `42`, `"hello"`, `true`   |
| Оператор       | Символ операции                                 | `+`, `-`, `*`, `/`        |
| Разделитель    | Синтаксический разделитель                      | `(`, `)`, `{`, `}`, `,`   |

### 1.3 Ключевые слова

YaoXiang определяет крайне небольшой набор ключевых слов:

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

Эти ключевые слова имеют специальное значение в любом контексте и не могут использоваться в качестве
идентификаторов.

### 1.4 Зарезервированные слова

«Зарезервированные слова» в YaoXiang разделены на три уровня и распознаются парсером (parser) и
проверщиком типов (type checker) на разных этапах:

#### 1.4.1 Литеральные зарезервированные слова

Идентификаторы литералов, имеющие в парсере собственные токены и не могущие использоваться как
обычные идентификаторы:

| Идентификатор | Принадлежность к типу | Описание                                                                                                    |
| ------------- | --------------------- | ----------------------------------------------------------------------------------------------------------- |
| `Type`        | —                     | Ключевое слово меатипа                                                                                      |
| `true`        | Bool                  | Логическое значение истина                                                                                  |
| `false`       | Bool                  | Логическое значение ложь                                                                                    |
| `void`        | Void                  | Литерал Void (значение Unit). Строчная `void` — литерал значения; заглавная `Void` — имя типа (см. §1.4.3). |

#### 1.4.2 Конструкторы выражений

Следующие конструкторы распознаются парсером в контекстах сопоставления с образцом и выражений:

| Конструктор | Принадлежность к типу | Описание                             |
| ----------- | --------------------- | ------------------------------------ |
| `some(T)`   | Option                | Конструктор варианта значения Option |
| `ok(T)`     | Result                | Успешный вариант Result              |
| `err(E)`    | Result                | Ошибочный вариант Result             |

#### 1.4.3 Встроенные имена типов

Следующие имена типов предварительно зарегистрированы проверщиком типов и могут использоваться в
позиции типа без импорта. Парсер рассматривает их как обычные идентификаторы — **это не
зарезервированные слова, они могут быть затенены (shadow) локальными привязками (не
рекомендуется)**.

| Имя типа | Логическое соответствие | Описание                                                                                                                                      |
| -------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤ (истина/Unit)         | Тип-произведение с нулём полей, имеющий ровно одного обитателя (литерал `void`, см. §1.4.1)                                                   |
| `Never`  | ⊥ (ложь/пустой тип)     | Тип с нулём вариантов и нулём обитателей. Никакое выражение не может породить значение `Never`. `Never <: T` для любого `T` (принцип взрыва). |
| `Int`    | —                       | Целое число со знаком                                                                                                                         |
| `Float`  | —                       | Число с плавающей точкой                                                                                                                      |
| `Bool`   | —                       | Логическое значение: `true` / `false`                                                                                                         |
| `Char`   | —                       | Символ Unicode                                                                                                                                |
| `String` | —                       | Строка                                                                                                                                        |

### 1.5 Идентификаторы

Идентификатор начинается с буквы или подчёркивания, последующие символы могут быть буквами, цифрами
или подчёркиваниями. Идентификаторы чувствительны к регистру.

Особые идентификаторы:

- `_` используется как заглушка, обозначающая игнорирование значения
- Идентификаторы, начинающиеся с подчёркивания, обозначают приватные члены

### 1.6 Литералы

#### 1.6.1 Целые числа

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 Числа с плавающей точкой

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 Строки

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 Коллекции

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Set         ::= '{' Expr (',' Expr)* '}'
```

#### 1.6.5 Генератор списков

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

#### 1.6.6 Проверка принадлежности

```
Membership  ::= Expr 'in' Expr
```

### 1.7 Комментарии

```
// однострочный комментарий

/* многострочный комментарий
   может занимать несколько строк */
```

### 1.8 Правила отступов

Код должен использовать отступ в 4 пробела, использование символов табуляции запрещено. Это
обязательное синтаксическое правило.

## Глава 2: Правила грамматики

### 2.1 Классификация выражений

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 Приоритет операторов

| Приоритет | Оператор                       | Ассоциативность |
| --------- | ------------------------------ | --------------- |
| 1         | `()` `[]` `.` `?`              | Слева направо   |
| 2         | `as`                           | Слева направо   |
| 3         | Унарный префиксный `!` `-` `+` | Справа налево   |
| 4         | `*` `/` `%`                    | Слева направо   |
| 5         | `+` `-`                        | Слева направо   |
| 6         | `..`                           | Слева направо   |
| 7         | `<<` `>>`                      | Слева направо   |
| 8         | `&` `\|` `^`                   | Слева направо   |
| 9         | `==` `!=` `<` `>` `<=` `>=`    | Слева направо   |
| 10        | `and` `or`                     | Слева направо   |
| 11        | `if...else`                    | Справа налево   |
| 12        | `=` `+=` `-=` `*=` `/=`        | Справа налево   |

> **Унарные префиксные операторы** (`!` `-` `+`) плотно связывают: уступают только вызовам и доступу
> к членам, но выше всех бинарных операторов. Поэтому `!a == b` ≡ `(!a) == b` (семантика в стиле
> Zig); `!` — чистая унарная операция, не участвующая в короткозамыкающем потоке управления, и
> ортогональна ключевым словам `and`/`or` (короткое замыкание) (авторитетное определение в RFC-010).

### 2.3 Вызов функции

```
FnCall      ::= Expr '(' ArgList? ')'
ArgList     ::= Expr (',' Expr)* (',' NamedArg)* | NamedArg (',' NamedArg)*
NamedArg    ::= Identifier ':' Expr
```

### 2.4 Доступ к члену

```
MemberAccess::= Expr '.' Identifier
```

### 2.5 Доступ по индексу

```
IndexAccess ::= Expr '[' Expr ']'
```

### 2.6 Преобразование типа

```
TypeCast    ::= Expr 'as' TypeExpr
```

### 2.7 Условное выражение

```
IfExpr      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 2.8 Сопоставление с образцом

```
MatchExpr   ::= 'match' Expr '{' MatchArm+ '}'
MatchArm    ::= Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
Pattern     ::= Literal
              | Identifier
              | Wildcard
              | StructPattern
              | TuplePattern
              | EnumPattern
              | OrPattern
```

### 2.9 Блочное выражение

```
Block       ::= '{' Stmt* Expr? '}'
```

**Унифицированная семантика**: семантика return во всех блоках `{}` одинакова:

| Тип блока    | Семантика return            | Возврат по умолчанию |
| ------------ | --------------------------- | -------------------- |
| Обычный `{}` | Возвращает значение         | Void                 |
| `unsafe {}`  | Возвращает определение типа | Void                 |
| `spawn {}`   | Возвращает результат        | Void                 |

**Основные принципы**:

- `return` в `{}` всегда возвращает содержимое во внешнюю область видимости
- По умолчанию отсутствие `return` возвращает `Void`
- Форма выражения `= expr` возвращает значение напрямую

```yaoxiang
// Обычный блок {}: return возвращает значение
result = {
    x = compute()
    return x  // возвращает значение во внешнюю область видимости
}

// Блок unsafe {}: return возвращает определение типа
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    return SqliteDb  // возвращает определение типа во внешнюю область видимости
}

// Блок spawn {}: return возвращает результат
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    return (result1, result2)  // возвращает результат во внешнюю область видимости
}
```

### 2.10 Лямбда-выражение

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 Оператор распространения ошибки

```
ErrorPropagate ::= Expr '?'
```

Оператор `?` — постфиксный оператор, с тем же приоритетом, что и `.`. Для типа `Result(T, E)`:

- При `Ok(v)` извлекает значение `v` и продолжает выполнение
- При `Err(e)` распространяет ошибку вверх (`return Err(e)`)

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // при успехе извлекает значение, при неудаче распространяет вверх
    transform(validated)
}
```

### 2.12 Выражение диапазона

```
RangeExpr   ::= Expr '..' Expr
```

`..` создаёт тип диапазона, используемый в циклах `for` и срезах.

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]
```

### 2.13 Выражение ref

```
RefExpr     ::= 'ref' Expr
```

`ref` создаёт разделяемое владение. Компилятор автоматически выбирает Rc (в пределах задачи) или Arc
(между задачами), пользователю не нужно заботиться о деталях реализации.

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // между задачами: компилятор автоматически выберет Arc
```

### 2.14 Выражение unsafe

```
UnsafeExpr  ::= 'unsafe' Block
```

Блок `unsafe` используется для определения непрозрачных типов и работы с сырыми указателями.
Используйте `return`, чтобы вернуть определение типа во внешнюю область видимости.

**Семантика**:

- В `unsafe {}` можно определять типы и работать с сырыми указателями
- Возвращённый тип доступен за пределами `unsafe {}`
- Доступ к полям типа требует привилегий unsafe

```yaoxiang
// Определение непрозрачного типа в блоке unsafe
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // сырой указатель
    }
    return SqliteDb
}

// SqliteDb доступен за пределами блока unsafe
db = sqlite3_open("test.db")
```

### 2.15 Область видимости

**Основные правила**:

- Каждый блок `{}` создаёт область видимости
- Внутренняя область видимости может обращаться к переменным внешней области
- Внешняя область видимости не может обращаться к переменным внутренней области
- Объявление переменных следует принципу «приоритет присваивания»

```yaoxiang
// Блочная область видимости
{
    x = 10
    // x виден в данной области видимости
}
// x недоступен за пределами данной области видимости

// Область видимости функции
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result недоступен за пределами функции
```

**Объявление и затенение переменных**:

- `x = value`: поиск x вверх по цепочке областей видимости, если найден — присвоить, если нет —
  новое объявление
- `mut x = value`: явное новое объявление изменяемой переменной, запрещено совпадение имени с
  внешней областью
- В одной области видимости любое имя может быть объявлено только один раз

> **Подробное определение**: полные правила области видимости, объявления переменных и механизма
> затенения см. в [Спецификации модульной системы](./modules.md#第四章作用域).

```

```

```

**Семантика**: `return` используется для возврата значения из блока кода. При отсутствии `return`

```

```

### 3.8 Оператор while

```

### 3.9 Оператор for

```
ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block
```

#### 3.9.1 Семантика: каждая итерация — это новая привязка значения

Семантика цикла for в YaoXiang отличается от традиционных языков: **каждая итерация — это новая
привязка значения, а не модификация одной и той же переменной**.

```yaoxiang
// Пример: for i in 1..5
for i in 1..5 {
    print(i)
}
```

**Процесс выполнения**:

| Итерация   | Поведение переменной цикла                                                                              |
| ---------- | ------------------------------------------------------------------------------------------------------- |
| 1-я        | Создаётся новая привязка `i = 1`, выполняется тело цикла, печатается 1                                  |
| 2-я        | Создаётся новая привязка `i = 2` (предыдущая привязка уничтожена), выполняется тело цикла, печатается 2 |
| 3-я        | Создаётся новая привязка `i = 3`, выполняется тело цикла, печатается 3                                  |
| 4-я        | Создаётся новая привязка `i = 4`, выполняется тело цикла, печатается 4                                  |
| Завершение | Тело цикла завершается, привязка уничтожается                                                           |

**Ключевой момент**: после завершения каждой итерации созданная в ней привязка уничтожается.
Следующая итерация — это совершенно новая привязка, никак не связанная с привязкой предыдущей
итерации.

#### 3.9.2 Различие между for и for mut

| Синтаксис           | Изменяемость переменной цикла | Описание                                    |
| ------------------- | ----------------------------- | ------------------------------------------- |
| `for i in 1..5`     | Неизменяемая                  | Тело цикла не может модифицировать привязку |
| `for mut i in 1..5` | Изменяемая                    | Тело цикла может модифицировать привязку    |

```yaoxiang
// Допустимо: каждая итерация привязывает новое значение, модификация не требуется
for i in 1..5 {
    print(i)  // чтение значения i
}

// Ошибка: неизменяемая привязка, нельзя модифицировать
for i in 1..5 {
    i = i + 1  // ошибка: нельзя модифицировать неизменяемую привязку
}

// Допустимо: использование for mut разрешает модификацию привязки
for mut i in 1..5 {
    i = i + 1  // модификация разрешена
}
```

#### 3.9.3 Проверка затенения

YaoXiang запрещает затенение переменных. Переменная цикла for не может иметь то же имя, что и
переменная во внешней области видимости:

```yaoxiang
// Ошибка: i уже объявлена во внешней области
i = 10
for i in 1..5 {
    print(i)
}

// Правильно: использование другого имени переменной
i = 10
for j in 1..5 {
    print(j)
}
```

Это правило применяется ко всем блокам кода, подробнее см.
[4.3 Правила затенения](./modules.md#43-遮蔽规则).

#### 3.9.4 Сравнение с другими языками

| Язык     | Семантика переменной цикла for                                         |
| -------- | ---------------------------------------------------------------------- |
| YaoXiang | Каждая итерация привязывает новое значение                             |
| Rust     | Модификация одной и той же переменной (требуется mut)                  |
| Python   | Модификация одной и той же переменной (без mut)                        |
| C/C++    | Модификация одной и той же переменной (требуется указатель или ссылка) |

**Обоснование дизайна**: YaoXiang использует семантику привязки по следующим причинам:

1. **Более соответствует естественной семантике** В естественном языке «для каждого элемента x в
   коллекции» подразумевает, что каждый x — это отдельная сущность. YaoXiang-овское `for i in 1..5`
   читается как «для каждого i от 1 до 5», где i в каждой итерации — совершенно новая привязка, что
   согласуется с интуитивным пониманием человека.

2. **Избежание случайной модификации** Семантика неизменяемой привязки по умолчанию означает, что
   тело цикла не может случайно модифицировать переменную цикла. Не нужно беспокоиться о том, что
   где-то в сложном теле цикла случайно напишется `i = ...`, приводящее к трудно отслеживаемой
   ошибке.

3. **Высокопроизводительное решение под рукой** Когда действительно необходимо переиспользовать
   переменную между итерациями (например, аккумулятор, кэш), используйте `for mut` для переключения
   в режим изменяемой привязки. Это яснее, чем неявное разделение состояния — намерение выражается
   явно через синтаксис, а не скрывается в поведении во время выполнения.

### 3.10 Оператор spawn

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**Блок spawn**: явно объявляет область параллелизма, выражения внутри блока выполняются параллельно.

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**Цикл spawn**: цикл с параллелизмом по данным.

```yaoxiang
results = spawn for item in items {
    process(item)
}
```
