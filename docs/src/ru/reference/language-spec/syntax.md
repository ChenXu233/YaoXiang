# Спецификация синтаксиса

Настоящий документ определяет спецификацию синтаксиса языка программирования YaoXiang, включая
лексическую структуру, синтаксические правила и приоритет операторов.

---

## Глава 1: Лексическая структура

### 1.1 Файлы исходного кода

Исходные файлы YaoXiang должны использовать кодировку UTF-8. Исходные файлы обычно имеют расширение
`.yx`.

### 1.2 Классификация лексем

| Категория      | Описание                                       | Пример                    |
| -------------- | ---------------------------------------------- | ------------------------- |
| Идентификатор  | Начинается с буквы или подчёркивания           | `x`, `_private`, `my_var` |
| Ключевое слово | Предопределённые зарезервированные слова языка | `Type`, `pub`, `use`      |
| Литерал        | Фиксированное значение                         | `42`, `"hello"`, `true`   |
| Оператор       | Знак операции                                  | `+`, `-`, `*`, `/`        |
| Разделитель    | Синтаксический разделитель                     | `(`, `)`, `{`, `}`, `,`   |

### 1.3 Ключевые слова

YaoXiang определяет крайне малый набор ключевых слов:

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

Эти ключевые слова имеют специальное значение в любом контексте и не могут использоваться как
идентификаторы.

### 1.4 Зарезервированные слова

«Зарезервированные слова» YaoXiang делятся на три уровня, распознаваемые парсером и проверщиком
типов на разных этапах:

#### 1.4.1 Литералы как зарезервированные слова

Литеральные идентификаторы, для которых парсер выделяет отдельные токены; не могут использоваться
как обычные идентификаторы:

| Идентификатор | Принадлежит типу | Описание                                                                                                    |
| ------------- | ---------------- | ----------------------------------------------------------------------------------------------------------- |
| `Type`        | —                | Ключевое слово мета-типа                                                                                    |
| `true`        | Bool             | Логическое истинное значение                                                                                |
| `false`       | Bool             | Логическое ложное значение                                                                                  |
| `void`        | Void             | Литерал Void (значение Unit). Строчная `void` — литерал значения; заглавная `Void` — имя типа (см. §1.4.3). |

#### 1.4.2 Конструкторы выражений

Следующие конструкторы распознаются парсером в контекстах сопоставления с образцом и выражений:

| Конструктор | Принадлежит типу | Описание                             |
| ----------- | ---------------- | ------------------------------------ |
| `some(T)`   | Option           | Конструктор варианта значения Option |
| `ok(T)`     | Result           | Успешный вариант Result              |
| `err(E)`    | Result           | Вариант ошибки Result                |

#### 1.4.3 Имена встроенных типов

Следующие имена типов предварительно зарегистрированы проверщиком типов и могут использоваться в
позиции типа без импорта. Парсер рассматривает их как обычные идентификаторы — **это не
зарезервированные слова, они могут быть затенены локальными привязками (не рекомендуется)**.

| Имя типа | Логическое соответствие | Описание                                                                                                                                             |
| -------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤ (истина/Unit)         | Тип-произведение с нулём полей, ровно с одним обитателем (литерал `void`, см. §1.4.1)                                                                |
| `Never`  | ⊥ (ложь/пустой тип)     | Тип-сумма с нулём вариантов, ноль обитателей. Никакое выражение не может породить значение типа `Never`. `Never <: T` для всех `T` (принцип взрыва). |
| `Int`    | —                       | Знаковое целое                                                                                                                                       |
| `Float`  | —                       | Число с плавающей точкой                                                                                                                             |
| `Bool`   | —                       | Логическое значение: `true` / `false`                                                                                                                |
| `Char`   | —                       | Символ Unicode                                                                                                                                       |
| `String` | —                       | Строка                                                                                                                                               |

### 1.5 Идентификаторы

Идентификатор начинается с буквы или подчёркивания, за которыми могут следовать буквы, цифры или
подчёркивания. Идентификаторы чувствительны к регистру.

Специальные идентификаторы:

- `_` используется как заполнитель, означающий игнорирование значения
- Идентификаторы, начинающиеся с подчёркивания, обозначают приватные члены

### 1.6 Литералы

#### 1.6.1 Целые числа

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 Числа с плавающей точкой

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 Строки

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 Коллекции

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Array       ::= '[' Expr (',' Expr)* ']'   // 目标类型注解为 Array(T, N) 时字面量落定长数组
```

> #299/#300: Set не имеет грамматики литералов и представления во время выполнения — тип коллекции в
> планировании, при появлении потребности доработать по образцу Dict (std.set + HeapValue::Set).
> Привязка литералов List/Dict определяется аннотацией контекстного типа: голый литерал и аннотация
> `List(T)` привязываются к расширяемому списку; аннотация `Array(T, N)`, применённая
> непосредственно к литералу, привязывает его к массиву фиксированной длины. Неявное преобразование
> List→Array запрещено.
>
> Семантика литерала Array (#300):
>
> - Количество элементов должно быть равно N, иначе ошибка E1002 на этапе компиляции; пустой литерал
>   с ненулевым N также отклоняется
> - Каждый элемент должен быть совместим с T, иначе ошибка E1002 на этапе компиляции
> - Грамматическая форма N: только целочисленный литерал (может быть отрицательным) или имя
>   константы; составные выражения (например, `2+1`) отклоняются на этапе разбора
> - Когда N является символьной константой (const-параметр функции, например `Array(Int, n)`),
>   проверка количества откладывается до фазы уточнения типов
> - Литералы вложенных массивов v1 (`Array(Array(Int,2),2) = [[1,2],[3,4]]`) отклоняются на этапе
>   компиляции, требуется явное построение слой за слоем; рекурсивная привязка оставлена для будущих
>   версий

#### 1.6.5 Генераторы списков

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

> **#299 §3 Ужесточение поведения (запись миграции)**: Грамматика переменной итерации изначально
> была `'for' Identifier 'in'`, но в старой реализации pattern проходил полный Pratt-разбор — после
> регистрации `'in'` как инфиксного оператора, `x` поглощал `in items` как выражение принадлежности.
> После исправления pattern, не являющийся идентификатором, сразу завершается неудачей при разборе,
> без отката к `_` (тихого проглатывания ошибки), как в старой реализации. Область влияния: ранее
> успешно разбиравшиеся записи вида `[x for (a, b) in pairs]` теперь приводят к ошибке — эта форма
> никогда не имела определённого поведения (переменная всегда была `_`), направление ужесточения
> верное, без затрат на миграцию семантики.

#### 1.6.6 Проверка принадлежности

```
Membership  ::= Expr 'in' Expr
```

> #299 §3: `in` — бинарный оператор отношения, возвращающий `Bool` — при попадании `true`, при
> отсутствии `false`, без ошибки. Разделение семантики: `[]` — утверждение существования и
> извлечение значения (при неудаче ошибка), `in` — запрос о наличии (отсутствие — нормальный
> `false`). Покрытие правого операнда: List / Array / Dict (множество ключей) / Tuple / String
> (подстрока) / Range (интервал). `in` — полноценный предикат Хоара, на фазе уточнения типов
> выступает основой для доказуемых на этапе компиляции утверждений. (#300 Решение 4: Set исключён из
> списка правых операндов — Set не имеет представления во время выполнения, см. §1.6.4)

### 1.7 Комментарии

```
// однострочный комментарий

/* многострочный комментарий
   может охватывать несколько строк */
```

## Глава 2: Синтаксические правила

### 2.1 Классификация выражений

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 Приоритет операторов

| Приоритет | Оператор                    | Ассоциативность |
| --------- | --------------------------- | --------------- |
| 1         | `()` `[]` `.` `?`           | слева направо   |
| 2         | `as`                        | слева направо   |
| 3         | Унарный префикс `!` `-` `+` | справа налево   |
| 4         | `*` `/` `%`                 | слева направо   |
| 5         | `+` `-`                     | слева направо   |
| 6         | `..`                        | слева направо   |
| 7         | `<<` `>>`                   | слева направо   |
| 8         | `&` `\|` `^`                | слева направо   |
| 9         | `==` `!=` `<` `>` `<=` `>=` | слева направо   |
| 10        | `and` `or`                  | слева направо   |
| 11        | `if...else`                 | справа налево   |
| 12        | `=` `+=` `-=` `*=` `/=`     | справа налево   |

> **Унарные префиксные операторы** (`!` `-` `+`) имеют сильное связывание: уступают только вызову и
> доступу к членам, превосходят все бинарные операторы. Следовательно, `!a == b` ≡ `(!a) == b`
> (семантика в стиле Zig); `!` — чистая унарная операция, не участвует в потоке управления с
> коротким замыканием, и ортогональна ключевым словам `and`/`or` (короткое замыкание) (авторитетное
> определение в RFC-010).

> **Сила связывания Range (#299 §3 / #300 пункт F)**: сила связывания `..` — (6, 7) — левая 6 меньше
> сложения (7), правая 7 поглощает сложение, но не поглощает `..` того же уровня. Сравнение до и
> после изменения:
>
> | Выражение    | До изменения (уровень 1, правоассоциативно)                                                              | После изменения ((6,7), левоассоциативно)                                           |
> | ------------ | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
> | `x in 1..10` | `x in 1..10` (правый операнд `in` уровня 4, `..` уровня 1 не может поглотить, фактически не разбирается) | `x in (1..10)` — весь интервал как правый операнд `in`                              |
> | `0..n+2`     | `(0..n)+2` (ловушка правоассоциативности: верхняя граница поглощена, цикл `for` сразу приводит к E3004)  | `0..(n+2)` — верхняя граница — арифметическое выражение                             |
> | `a == b..c`  | `a == (b..c)` (`..` уровня 1 < `==` уровня 3, естественно целиком)                                       | `a == (b..c)` — **семантика не изменилась**, `..` по-прежнему выше уровня сравнения |
> | `1..2*3`     | `(1..2)*3`                                                                                               | `1..(2*3)` — верхняя граница — арифметическое выражение                             |
> | `a..b..c`    | `a..(b..c)` (цепочечно правоассоциативно, бессмысленное вложение Range в Range)                          | `(a..b)..c` — **форма с шагом** (`c` — шаг, #300 пункт I)                           |
>
> Итоговый эффект: составная верхняя граница `for i in 0..n+2` из «успешный разбор, но E3004»
> превращается в «непосредственно пригодно к использованию»; `x in 1..10` из «не удаётся разобрать»
> превращается в «проверка интервала»; `a..b..c` из «бессмысленного вложения» превращается в
> «компонент шага». Уровень 6 находится между `+` (уровень 5) и `<<` (уровень 7), в соответствии с
> математической конвенцией: интервал — сильносвязанная конструкция, верхняя граница естественно
> является полным арифметическим выражением.


### 2.4 Доступ к членам

### 2.5 Доступ по индексу

```
IndexAccess ::= Expr '[' Expr ']'
```

### 2.6 Приведение типов

```
TypeCast    ::= Expr 'as' TypeExpr
```

### 2.7 Условные выражения

```
IfExpr      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 2.8 Сопоставление с образцом

```
MatchExpr   ::= 'match' Expr '{' MatchArm+ '}'
MatchArm    ::= Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
Pattern     ::= Literal
              | Identifier
              | Wildcard
              | StructPattern
              | TuplePattern
              | EnumPattern
              | OrPattern
```

### 2.9 Блочные выражения

```
Block       ::= '{' Stmt* Expr? '}'
```

> **Правила завершения операторов**: разделение операторов и поведение перевода строки (явное
> разделение `;`, завершение переводом строки, исключение для продолжения строки, никогда не
> объединяемые `(`/`[` в начале строки) определены в
> [RFC-038](../design/rfc/draft/038-statement-termination.md).

**Единая семантика**: семантика `return` всех блоков `{}` одинакова:

| Тип блока    | Семантика return            | Возврат по умолчанию |
| ------------ | --------------------------- | -------------------- |
| Обычный `{}` | Возвращает значение         | Void                 |
| `unsafe {}`  | Возвращает определение типа | Void                 |
| `spawn {}`   | Возвращает результат        | Void                 |

**Основные принципы**:

- `return` в `{}` всегда возвращает содержимое во внешнюю область видимости
- При отсутствии `return` по умолчанию возвращается `Void`
- Выражение в форме `= expr` напрямую возвращает значение

```yaoxiang
// 普通 {} 块：return 返回值
result = {
    x = compute()
    return x  // 返回值给上一作用域
}

// unsafe {} 块：return 返回类型定义
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    return SqliteDb  // 返回类型定义给上一作用域
}

// spawn {} 块：return 返回结果
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    return (result1, result2)  // 返回结果给上一作用域
}
```

### 2.10 Лямбда-выражения

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 Оператор распространения ошибок

```
ErrorPropagate ::= Expr '?'
```

Оператор `?` — постфиксный оператор, имеющий тот же приоритет, что и `.`. Для типа `Result(T, E)`:

- При `Ok(v)` извлекается значение `v` и выполнение продолжается
- При `Err(e)` ошибка распространяется вверх (`return Err(e)`)

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // 成功时提取值，失败时向上传播
    transform(validated)
}
```

### 2.12 Выражения диапазона

```
RangeExpr   ::= Expr '..' Expr ('..' Expr)?
```

`..` создаёт значение диапазона (#300 пункт I: Range — полноценное значение, а не синтаксический
сахар).

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]

// Range 是值：绑定、传递、成员判断
r = 1..10
assert.assert(5 in r, "membership")
for i in r { print(i) }

// step 形态（第三分量，默认 1）
for i in 0..10..2 { print(i) }  // 0, 2, 4, 6, 8
for i in 10..0..(-2) { print(i) }  // 10, 8, 6, 4, 2
```

> **Семантика шага**: в `a..b..c` `c` — это шаг. Литерал `c = 0` отклоняется на этапе компиляции;
> для динамического `c` — проверка нуля во время выполнения (семейство E6001, после внедрения
> системы ошибок в #301 возводится в Result). `c < 0` допустимо, направление интервала инвертируется
> в зависимости от знака (`10..0..(-2)` — убывающий).

### 2.13 Выражение `ref`

```
RefExpr     ::= 'ref' Expr
```

`ref` создаёт разделяемое владение. Компилятор автоматически выбирает Rc (одна задача) или Arc
(между задачами), пользователю не нужно беспокоиться о деталях реализации.

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // 跨任务：编译器自动选 Arc
```

### 2.14 Выражение `unsafe`

```
UnsafeExpr  ::= 'unsafe' Block
```

Блок `unsafe` используется для определения непрозрачных типов и операций над сырыми указателями.
Используйте `return` для возврата определения типа во внешнюю область видимости.

**Семантика**:

- В `unsafe {}` можно определять типы и выполнять операции над сырыми указателями
- Возвращённый тип доступен за пределами `unsafe {}`
- Доступ к полям типа требует разрешения `unsafe`

```yaoxiang
// 在 unsafe 块中定义不透明类型
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // 裸指针
    }
    return SqliteDb
}

// SqliteDb 在 unsafe 块外可用
db = sqlite3_open("test.db")
```

### 2.15 Области видимости

**Основные правила**:

- Каждый блок `{}` создаёт область видимости
- Внутренняя область видимости может обращаться к переменным внешней области видимости
- Внешняя область видимости не может обращаться к переменным внутренней области видимости
- Объявление переменных следует принципу «приоритет присваивания»

```yaoxiang
// 块作用域
{
    x = 10
    // x 在此作用域内可见
}
// x 在此作用域外不可见

// 函数作用域
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result 在函数外不可见
```

**Объявление и затенение переменных**:

- `x = value`: поиск `x` по цепочке областей видимости наружу; если найдено — присваивание, иначе —
  новое объявление
- `mut x = value`: явное новое объявление изменяемой переменной, запрещено совпадение имён с внешней
  областью
- В одной области видимости любое имя может быть объявлено только один раз

> **Подробное определение**: полные правила областей видимости, механизм объявления и затенения
> переменных подробно описаны в [спецификации системы модулей](./modules.md#第四章作用域).

## Глава 3: Операторы

### 3.1 Классификация операторов

```
Stmt        ::= LetStmt
              | ExprStmt
              | ReturnStmt
              | BreakStmt
              | ContinueStmt
              | IfStmt
              | MatchStmt
              | WhileStmt
              | ForStmt
              | SpawnStmt
```

### 3.2 Объявление переменных

```
LetStmt     ::= ('mut')? Identifier (':' TypeExpr)? '=' Expr
```

### 3.3 Оператор `return`

```
ReturnStmt  ::= 'return' Expr?
```

**Семантика**: `return` используется для возврата значения из блока кода. При отсутствии `return`
блок кода по умолчанию возвращает `Void`.

### 3.4 Оператор `break`

```
BreakStmt   ::= 'break'
```

**Семантика**: немедленно завершает ближайший вложенный цикл `while`/`for`, поток управления
переходит после тела этого цикла.

- **Выходит только из ближайшего вложенного уровня**: `break` всегда действует на ближайший
  вложенный цикл, содержащий его. При необходимости выхода из нескольких уровней вложенного цикла
  вынесите внутренний цикл в функцию и используйте `return`, или используйте флаг (окончательное
  решение #314: `break`/`continue` без меток; если в будущем будут введены метки циклов, синтаксис
  будет следовать за стороной объявления цикла по процессу RFC и будет решён вместе с проектом
  множественных выходов из конвейера доказательств)
- **Допустимо только внутри тела цикла**: `break` может появляться только в теле цикла `while`/`for`
  (включая вложенные блоки/`if`/`match` в теле), появление вне цикла приводит к ошибке компиляции
  (E1102 `'break' outside of a loop`)
- **Не влияет на доказательство завершаемости**: цикл `while` по-прежнему должен быть доказуемо
  завершаемым (decreases-мера); `break` не участвует в аргументации завершаемости,
  `while true { break }` не будет принят
- **Семантика заимствования**: ребро потока управления `break` участвует в структурном отсечении
  обратного BFS-анализа живости в RFC-009a (итерация, из которой совершен выход, не участвует в
  выводе живости обратных рёбер)

```yaoxiang
mut i = 0
while i < 10 {
    i = i + 1
    if i == 3 {
        break              // 控制流转到循环之后，i == 3
    }
}

// 嵌套循环：break 只出内层
while j < 3 {
    while k < 10 {
        if k == 2 { break }    // 只终止内层循环
    }
    j = j + 1                  // 每轮外层迭代都会执行到这里
}
```

### 3.5 Оператор `continue`

```
ContinueStmt::= 'continue'
```

**Семантика**: пропускает оставшиеся операторы текущей итерации и сразу переходит к следующей
итерации ближайшего вложенного цикла — `while` повторно проверяет условие, `for` берёт следующий
элемент.

- **Действует только на ближайший вложенный уровень**: аналогично `break`, без меток (#314)
- **Допустимо только внутри тела цикла**: появление вне цикла приводит к ошибке компиляции (E1102)

```yaoxiang
mut sum = 0
mut n = 0
while n < 5 {
    n = n + 1
    if n == 3 {
        continue           // 跳过下面的累加，n == 3 不计入
    }
    sum = sum + n
}
// sum == 12（1 + 2 + 4 + 5）
```

### 3.7 Оператор `match`

### 3.9 Оператор `for`

```
ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block
```

#### 3.9.1 Семантика: каждая итерация — это новая привязка значения

Семантика цикла `for` в YaoXiang отличается от традиционных языков: **каждая итерация — это новая
привязка значения, а не изменение той же переменной**.

```yaoxiang
// 示例：for i in 1..5
for i in 1..5 {
    print(i)
}
```

**Процесс выполнения**:

| Итерация | Поведение переменной цикла                                                                          |
| -------- | --------------------------------------------------------------------------------------------------- |
| 1-я      | Создаёт новую привязку `i = 1`, выполняется тело цикла, печатает 1                                  |
| 2-я      | Создаёт новую привязку `i = 2` (предыдущая привязка уничтожена), выполняется тело цикла, печатает 2 |
| 3-я      | Создаёт новую привязку `i = 3`, выполняется тело цикла, печатает 3                                  |
| 4-я      | Создаёт новую привязку `i = 4`, выполняется тело цикла, печатает 4                                  |
| Конец    | Конец тела цикла, привязка уничтожена                                                               |

**Ключевой момент**: после каждой итерации привязка, созданная в текущей итерации, будет уничтожена.
Следующая итерация — это совершенно новая привязка, не имеющая никакой связи с привязкой предыдущей
итерации.

#### 3.9.2 Разница между `for` и `for mut`

| Синтаксис           | Изменяемость переменной цикла | Описание                              |
| ------------------- | ----------------------------- | ------------------------------------- |
| `for i in 1..5`     | Неизменяемая                  | Привязку нельзя изменять в теле цикла |
| `for mut i in 1..5` | Изменяемая                    | Привязку можно изменять в теле цикла  |

```yaoxiang
// 合法：每次迭代绑定新值，不需要修改
for i in 1..5 {
    print(i)  // 读取 i 的值
}

// 错误：不可变绑定，不能修改
for i in 1..5 {
    i = i + 1  // 错误：不能修改不可变绑定
}

// 合法：使用 for mut 允许修改绑定
for mut i in 1..5 {
    i = i + 1  // 允许修改
}
```

#### 3.9.3 Проверка затенения

YaoXiang запрещает затенение переменных. Переменная цикла не может иметь то же имя, что и переменная
во внешней области видимости:

```yaoxiang
// 错误：i 已经在外部声明
i = 10
for i in 1..5 {
    print(i)
}

// 正确：使用不同的变量名
i = 10
for j in 1..5 {
    print(j)
}
```

Это правило применяется ко всем блокам кода, подробности см. в
[4.3 Правила затенения](./modules.md#43-遮蔽规则).

#### 3.9.4 Сравнение с другими языками

| Язык     | Семантика переменной цикла `for`                             |
| -------- | ------------------------------------------------------------ |
| YaoXiang | Каждая итерация привязывает новое значение                   |
| Rust     | Изменение той же переменной (требуется `mut`)                |
| Python   | Изменение той же переменной (`mut` не требуется)             |
| C/C++    | Изменение той же переменной (требуется указатель или ссылка) |

**Обоснование проектирования**: YaoXiang использует семантику привязки по следующим причинам:

1. **Более соответствует естественной семантике**. В естественном языке «для каждого элемента `x` в
   коллекции» означает, что каждый `x` — отдельная сущность. YaoXiang `for i in 1..5` читается как
   «для каждого `i` от 1 до 5», `i` в каждой итерации — это совершенно новая привязка, что
   соответствует интуитивному пониманию человека.

2. **Избежание случайных изменений**. Семантика неизменяемой привязки по умолчанию означает, что
   переменная цикла не может быть случайно изменена в теле цикла. Не нужно беспокоиться о том, что
   где-то в сложном теле цикла случайно написал `i = ...`, приводящий к трудноотслеживаемым ошибкам.

3. **Высокопроизводительные решения всегда под рукой**. Когда действительно необходимо повторно
   использовать переменную между итерациями (например, аккумулятор, кэш), используйте объявление
   `for mut` для переключения в режим изменяемой привязки. Это яснее, чем неявное разделяемое
   состояние — намерение выражается явно через синтаксис, а не скрыто в поведении во время
   выполнения.

### 3.10 Оператор `spawn`

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**Блок spawn**: явно объявляет параллельную область, выражения в блоке выполняются параллельно.

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**Цикл spawn**: параллельный цикл по данным.

```yaoxiang
results = spawn for item in items {
    process(item)
}
```

**Блок spawn захватывает внешние переменные** (RFC-024 §2.3, семантика захвата значения):

- Когда тело блока ссылается на внешнюю переменную = **захват значения по `Move`**: значение
  копируется в снимок в среду замыкания в точке создания `spawn`, тело блока читает через `env`
  (LoadUpvalue)
- **Примитивы** (Int/Float/Bool/Char) — копирование значения, внешняя переменная не затрагивается
- **Типы-дескрипторы** (Struct/String/List и т.д.) — снимок = копирование дескриптора, разделяет
  нижележащий объект; во встроенной среде выполнения (по умолчанию) один поток, одна куча,
  дескриптор действителен
- Для обмена между несколькими задачами требуется явный `ref` (§2.13, компилятор автоматически
  выбирает Rc/Arc)
- Внешняя переменная, на которую ссылается `return` внутри блока, также захватывается

```yaoxiang
t1 = 1 + 1
t2 = 2 + 2
result = spawn {
    return t1 + t2    // t1/t2 值捕获，result == 6
}
```
