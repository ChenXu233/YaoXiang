# Спецификация синтаксиса

Данный файл определяет спецификацию синтаксиса языка программирования YaoXiang, включая лексическую
структуру, грамматические правила и приоритеты операторов.

---

## Глава 1: Лексическая структура

### 1.1 Исходный файл

Исходные файлы YaoXiang должны использовать кодировку UTF-8. Исходные файлы обычно имеют расширение
`.yx`.

### 1.2 Классификация лексических единиц

| Категория      | Описание                                       | Пример                    |
| -------------- | ---------------------------------------------- | ------------------------- |
| Идентификатор  | Начинается с буквы или подчёркивания           | `x`, `_private`, `my_var` |
| Ключевое слово | Предопределённые зарезервированные слова языка | `Type`, `pub`, `use`      |
| Литерал        | Фиксированное значение                         | `42`, `"hello"`, `true`   |
| Оператор       | Символ операции                                | `+`, `-`, `*`, `/`        |
| Разделитель    | Синтаксический разделитель                     | `(`, `)`, `{`, `}`, `,`   |

### 1.3 Ключевые слова

YaoXiang определяет минимальное количество ключевых слов:

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

Эти ключевые слова имеют особое значение в любом контексте и не могут использоваться в качестве
идентификаторов.

### 1.4 Зарезервированные слова

«Зарезервированные слова» YaoXiang разделены на три слоя и распознаются парсером и проверщиком типов
на разных этапах:

#### 1.4.1 Литеральные зарезервированные слова

Идентификаторы литералов, являющиеся у парсера самостоятельными токенами; они не могут
использоваться как обычные идентификаторы:

| Идентификатор | Принадлежит типу | Описание                                                                                                    |
| ------------- | ---------------- | ----------------------------------------------------------------------------------------------------------- |
| `Type`        | —                | Ключевое слово мета-типа                                                                                    |
| `true`        | Bool             | Булево значение «истина»                                                                                    |
| `false`       | Bool             | Булево значение «ложь»                                                                                      |
| `void`        | Void             | Литерал Void (значение Unit). Строчное `void` — литерал значения; прописное `Void` — имя типа (см. §1.4.3). |

#### 1.4.2 Конструкторные выражения

Следующие конструкторы распознаются парсером в контекстах сопоставления с образцом и выражений:

| Конструктор | Принадлежит типу | Описание                             |
| ----------- | ---------------- | ------------------------------------ |
| `some(T)`   | Option           | Конструктор варианта значения Option |
| `ok(T)`     | Result           | Успешный вариант Result              |
| `err(E)`    | Result           | Ошибочный вариант Result             |

#### 1.4.3 Имена встроенных типов

Следующие имена типов предварительно зарегистрированы проверщиком типов и могут использоваться в
позициях типов без импорта. Парсер рассматривает их как обычные идентификаторы — **не являются
зарезервированными словами и могут быть затенены локальными привязками (не рекомендуется)**.

| Имя типа | Логическое соответствие | Описание                                                                                                                                                    |
| -------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤ (истина/Unit)         | Тип-произведение с нулём полей, ровно один обитатель (литерал `void`, см. §1.4.1)                                                                           |
| `Never`  | ⊥ (ложь/пустой тип)     | Тип-сумма с нулём вариантов, ноль обитателей. Никакое выражение не может породить значение `Never`. `Never <: T` выполняется для всех `T` (принцип взрыва). |
| `Int`    | —                       | Знаковое целое                                                                                                                                              |
| `Float`  | —                       | Число с плавающей точкой                                                                                                                                    |
| `Bool`   | —                       | Булево значение: `true` / `false`                                                                                                                           |
| `Char`   | —                       | Символ Unicode                                                                                                                                              |
| `String` | —                       | Строка                                                                                                                                                      |

### 1.5 Идентификаторы

Идентификатор начинается с буквы или подчёркивания, последующие символы могут быть буквами, цифрами
или подчёркиваниями. Идентификаторы чувствительны к регистру.

Особые идентификаторы:

- `_` используется как placeholder, означающий игнорирование значения
- Идентификаторы, начинающиеся с подчёркивания, обозначают приватные члены

### 1.6 Литералы

#### 1.6.1 Целые числа

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 Числа с плавающей точкой

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 Строки

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 Коллекции

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Array       ::= '[' Expr (',' Expr)* ']'   // 目标类型注解为 Array(T, N) 时字面量落定长数组
```

> #299/#300: Set не имеет грамматики литерала и представления во время выполнения — типы множеств
> находятся в планировании; при появлении требований будут дополнены по образцу Dict (std.set +
> HeapValue::Set). Место «приземления» литералов List/Dict определяется контекстной аннотацией типа:
> голый литерал и аннотация `List(T)` приземляются в расширяемый список; аннотация `Array(T, N)`,
> применённая непосредственно к литералу, приземляет его в массив фиксированной длины. Неявное
> преобразование List→Array запрещено.
>
> Семантика литерала Array (#300):
>
> - Количество элементов должно равняться N, иначе ошибка компиляции E1002; пустой литерал с
>   ненулевым N также отвергается
> - Тип каждого элемента должен быть совместим с T, иначе ошибка компиляции E1002
> - Грамматическая форма N: только целочисленный литерал (может быть отрицательным) или имя
>   константы; составные выражения (например, `2+1`) отвергаются на этапе разбора
> - Когда N — символьная константа (const-параметр функции, например `Array(Int, n)`), проверка
>   количества откладывается до этапа уточнения типов
> - Вложенные литералы массивов v1 (`Array(Array(Int,2),2) = [[1,2],[3,4]]`) отвергаются на этапе
>   компиляции, требуя явного конструирования слой за слоем; рекурсивная точка приземления остаётся
>   для последующих версий

#### 1.6.5 Генератор списков

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

> **#299 §3 Ужесточение поведения (запись миграции)**: Грамматика переменной итерации изначально —
> `'for' Identifier 'in'`, но старая реализация выполняла полный Pratt-разбор шаблона — после
> регистрации `'in'` как инфиксного оператора `x` поглощал бы `in items` как membership-выражение.
> После исправления шаблоны, не являющиеся идентификаторами, приводят к ошибке разбора напрямую, без
> отката к `_` (тихому проглатыванию ошибки) как в старой реализации. Область влияния: ранее
> разбираемые формы вроде `[x for (a, b) in pairs]` теперь сообщают об ошибке — эта форма никогда не
> имела определённого поведения (переменная всегда была `_`), направление ужесточения верное, без
> затрат на семантическую миграцию.

#### 1.6.6 Проверка членства

```
Membership  ::= Expr 'in' Expr
```

> #299 §3: `in` — бинарный оператор отношения, возвращающий `Bool` — попадание `true`, непопадание
> `false`, без ошибки. Семантическое разделение: `[]` утверждает существование и извлекает значение
> (ошибка при неудаче), `in` спрашивает, существует ли (непопадание — нормальное `false`). Покрытие
> правого операнда: List / Array / Dict (набор ключей) / Tuple / String (подстрока) / Range
> (интервал). `in` — предикат Хоара первого класса, являющийся базисом для доказуемых утверждений во
> время компиляции на этапе уточнения типов. (Решение #300, п. 4: Set исключён из списка правых
> операндов — Set не имеет представления во время выполнения, см. §1.6.4)

### 1.7 Комментарии

```
// однострочный комментарий

/* многострочный комментарий
   может занимать несколько строк */
```

синтаксическое правило.

## Глава 2: Грамматические правила

### 2.1 Классификация выражений

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 Приоритет операторов

| Приоритет | Оператор                    | Ассоциативность |
| --------- | --------------------------- | --------------- |
| 1         | `()` `[]` `.` `?`           | слева направо   |
| 2         | `as`                        | слева направо   |
| 3         | Унарный префикс `!` `-` `+` | справа налево   |
| 4         | `*` `/` `%`                 | слева направо   |
| 5         | `+` `-`                     | слева направо   |
| 6         | `..`                        | слева направо   |
| 7         | `<<` `>>`                   | слева направо   |
| 8         | `&` `\|` `^`                | слева направо   |
| 9         | `==` `!=` `<` `>` `<=` `>=` | слева направо   |
| 10        | `and` `or`                  | слева направо   |
| 11        | `if...else`                 | справа налево   |
| 12        | `=` `+=` `-=` `*=` `/=`     | справа налево   |

> **Унарные префиксные операторы** (`!` `-` `+`) связаны сильно: только ниже вызова и доступа к
> члену, выше всех бинарных операторов. Следовательно, `!a == b` ≡ `(!a) == b` (семантика в стиле
> Zig); `!` — чистая унарная операция, не участвует в потоке управления с коротким замыканием,
> ортогональна ключевым словам `and`/`or` (короткое замыкание) (авторитетное определение в RFC-010).

> **Сила связывания Range (#299 §3 / #300 п. F)**: `..` имеет силу связывания (6, 7) — левая 6 ниже
> сложения (7), правая 7 поглощает сложение, но не поглощает `..` того же уровня. Сравнение до и
> после изменения:
>
> | Выражение    | До изменения (уровень 1, правоассоц.)                                                                    | После изменения ((6,7), левоассоц.)                                               |
> | ------------ | -------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
> | `x in 1..10` | `x in 1..10` (правый операнд `in` уровня 4, `..` уровня 1 не может поглотить, фактически не разбирается) | `x in (1..10)` — интервал целиком как правый операнд `in`                         |
> | `0..n+2`     | `(0..n)+2` (ловушка правоассоциативности: верхняя граница поглощена, цикл `for` сразу E3004)             | `0..(n+2)` — верхняя граница — арифметическое выражение                           |
> | `a == b..c`  | `a == (b..c)` (`..` уровня 1 < `==` уровня 3, естественно как единое целое)                              | `a == (b..c)` — **семантика не меняется**, `..` по-прежнему выше уровня сравнения |
> | `1..2*3`     | `(1..2)*3`                                                                                               | `1..(2*3)` — верхняя граница — арифметическое выражение                           |
> | `a..b..c`    | `a..(b..c)` (правоассоциативная цепочка, бессмысленный Range внутри Range)                               | `(a..b)..c` — **форма со шагом** (`c` — шаг, #300 п. I)                           |
>
> Чистый эффект: составная верхняя граница `for i in 0..n+2` меняется с «разбор успешен, но E3004»
> на «непосредственно пригодно»; `x in 1..10` меняется с «не разбирается» на «проверка интервала»;
> `a..b..c` меняется с «бессмысленной вложенности» на «компонент шага». Уровень 6 расположен между
> `+` (уровень 5) и `<<` (уровень 7), математическое соглашение: интервал — сильно связанная
> конструкция, верхняя граница естественно является полным арифметическим выражением.


### 2.7 Условное выражение

```
IfExpr      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 2.8 Сопоставление с образцом

```
MatchExpr   ::= 'match' Expr '{' MatchArm+ '}'
MatchArm    ::= Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
Pattern     ::= Literal
              | Identifier
              | Wildcard
              | StructPattern
              | TuplePattern
              | EnumPattern
              | OrPattern
```

### 2.9 Блочное выражение

```
Block       ::= '{' Stmt* Expr? '}'
```

> **Правила завершения инструкций**: Поведение разделения и перевода строк между Stmt (явное
> разделение `;`, завершение переводом строки, исключения для продолжения строки, никогда не
> сливающиеся с `(`/`[` в начале строки) определены в
> [RFC-038](../design/rfc/draft/038-statement-termination.md).

**Единая семантика**: все блоки `{}` имеют согласованную семантику return:

| Тип блока    | Семантика return         | Возврат по умолчанию |
| ------------ | ------------------------ | -------------------- |
| Обычный `{}` | Возврат значения         | Void                 |
| `unsafe {}`  | Возврат определения типа | Void                 |
| `spawn {}`   | Возврат результата       | Void                 |

**Основные принципы**:

- `return` в `{}` всегда возвращает содержимое во внешнюю область видимости
- По умолчанию без `return` возвращается `Void`
- Выражение-форма `= expr` возвращает значение напрямую

```yaoxiang
// Обычный блок {}: return возвращает значение
result = {
    x = compute()
    return x  // Возврат значения во внешнюю область видимости
}

// Блок unsafe {}: return возвращает определение типа
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    return SqliteDb  // Возврат определения типа во внешнюю область видимости
}

// Блок spawn {}: return возвращает результат
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    return (result1, result2)  // Возврат результата во внешнюю область видимости
}
```

### 2.10 Лямбда-выражение

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 Оператор распространения ошибки

```
ErrorPropagate ::= Expr '?'
```

Оператор `?` — постфиксный оператор с тем же приоритетом, что и `.`. Для типа `Result(T, E)`:

- При `Ok(v)` извлекается значение `v` и выполнение продолжается
- При `Err(e)` ошибка распространяется вверх (`return Err(e)`)

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // При успехе извлекается значение, при неудаче — распространение вверх
    transform(validated)
}
```

### 2.12 Выражение диапазона

```
RangeExpr   ::= Expr '..' Expr ('..' Expr)?
```

`..` создаёт значение диапазона (#300 п. I: Range — значение первого класса, не синтаксический
сахар).

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]

// Range — это значение: связывание, передача, проверка членства
r = 1..10
assert.assert(5 in r, "membership")
for i in r { print(i) }

// Форма со шагом (третий компонент, по умолчанию 1)
for i in 0..10..2 { print(i) }  // 0, 2, 4, 6, 8
for i in 10..0..(-2) { print(i) }  // 10, 8, 6, 4, 2
```

> **Семантика шага**: в `a..b..c` `c` — шаг. Литерал `c = 0` отвергается во время компиляции;
> динамический `c` проверяется на ноль во время выполнения (семейство E6001, после приземления
> системы ошибок #301 будет повышен до Result). `c < 0` допустим, направление интервала меняется в
> зависимости от знака (`10..0..(-2)` убывает).

### 2.13 Выражение ref

```
RefExpr     ::= 'ref' Expr
```

`ref` создаёт разделяемое владение. Компилятор автоматически выбирает Rc (одна задача) или Arc
(между задачами), пользователю не нужно беспокоиться о деталях реализации.

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // Между задачами: компилятор автоматически выберет Arc
```

### 2.14 Выражение unsafe

```
UnsafeExpr  ::= 'unsafe' Block
```

Блок `unsafe` используется для определения непрозрачных типов и работы с сырыми указателями.
Используйте `return`, чтобы вернуть определения типов во внешнюю область видимости.

**Семантика**:

- В `unsafe {}` можно определять типы и работать с сырыми указателями
- Возвращённые типы доступны за пределами `unsafe {}`
- Доступ к полям типа требует привилегии unsafe

```yaoxiang
// Определение непрозрачного типа в блоке unsafe
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // Сырой указатель
    }
    return SqliteDb
}

// SqliteDb доступен за пределами блока unsafe
db = sqlite3_open("test.db")
```

### 2.15 Область видимости

**Основные правила**:

- Каждый блок `{}` создаёт область видимости
- Внутренняя область видимости может обращаться к переменным внешней области
- Внешняя область видимости не может обращаться к переменным внутренней области
- Объявление переменных следует принципу «присваивание первым»

```yaoxiang
// Блочная область видимости
{
    x = 10
    // x виден внутри этой области видимости
}
// x не виден за пределами этой области видимости

// Область видимости функции
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result не виден за пределами функции
```

**Объявление и затенение переменных**:

- `x = value`: поиск x по цепочке областей видимости — если найден, присваивание; если не найден,
  новое объявление
- `mut x = value`: явное новое объявление изменяемой переменной, запрещено совпадение имён с внешней
  областью
- Любое имя может быть объявлено только один раз в одной области видимости

> **Подробное определение**: Полные правила области видимости, механизм объявления и затенения
> переменных подробно описаны в [Спецификации модульной системы](./modules.md#第四章作用域).

#### 3.9.1 Семантика: каждая итерация связывает новое значение

Семантика цикла for в YaoXiang отличается от традиционных языков: **каждая итерация связывает новое
значение, а не модифицирует ту же переменную**.

```yaoxiang
// Пример: for i in 1..5
for i in 1..5 {
    print(i)
}
```

**Процесс выполнения**:

| Итерация | Поведение переменной цикла                                                                        |
| -------- | ------------------------------------------------------------------------------------------------- |
| 1-я      | Создаётся новая привязка `i = 1`, выполняется тело цикла, печатается 1                            |
| 2-я      | Создаётся новая привязка `i = 2` (предыдущая привязка уничтожена), тело выполняется, печатается 2 |
| 3-я      | Создаётся новая привязка `i = 3`, тело выполняется, печатается 3                                  |
| 4-я      | Создаётся новая привязка `i = 4`, тело выполняется, печатается 4                                  |
| Конец    | Тело цикла завершается, привязка уничтожается                                                     |

**Ключевой момент**: после завершения каждой итерации созданная в этой итерации привязка
уничтожается. Следующая итерация — это совершенно новая привязка, никак не связанная с привязкой
предыдущей итерации.

#### 3.9.2 Различие между for и for mut

| Синтаксис           | Изменяемость переменной цикла | Описание                                    |
| ------------------- | ----------------------------- | ------------------------------------------- |
| `for i in 1..5`     | Неизменяемая                  | Нельзя модифицировать привязку в теле цикла |
| `for mut i in 1..5` | Изменяемая                    | Можно модифицировать привязку в теле цикла  |

```yaoxiang
// Допустимо: каждая итерация связывает новое значение, модификация не нужна
for i in 1..5 {
    print(i)  // Чтение значения i
}

// Ошибка: неизменяемая привязка, нельзя модифицировать
for i in 1..5 {
    i = i + 1  // Ошибка: нельзя модифицировать неизменяемую привязку
}

// Допустимо: использование for mut разрешает модификацию привязки
for mut i in 1..5 {
    i = i + 1  // Модификация разрешена
}
```

#### 3.9.3 Проверка затенения

YaoXiang запрещает затенение переменных. Переменная цикла for не может иметь то же имя, что и
переменная во внешней области видимости:

```yaoxiang
// Ошибка: i уже объявлен во внешней области
i = 10
for i in 1..5 {
    print(i)
}

// Правильно: использование различных имён переменных
i = 10
for j in 1..5 {
    print(j)
}
```

Это правило применяется ко всем блокам кода, см. [4.3 Правила затенения](./modules.md#43-遮蔽规则).

#### 3.9.4 Сравнение с другими языками

| Язык     | Семантика переменной цикла for                                 |
| -------- | -------------------------------------------------------------- |
| YaoXiang | Каждая итерация связывает новое значение                       |
| Rust     | Модификация той же переменной (требуется mut)                  |
| Python   | Модификация той же переменной (mut не требуется)               |
| C/C++    | Модификация той же переменной (требуется указатель или ссылка) |

**Обоснование дизайна**: YaoXiang использует семантику связывания, потому что:

1. **Более соответствует естественной семантике** В естественном языке «для каждого элемента x в
   коллекции» означает, что каждый x — независимая сущность. `for i in 1..5` в YaoXiang читается как
   «для каждого i от 1 до 5», i в каждой итерации — совершенно новая привязка, что согласуется с
   интуитивным пониманием человека.

2. **Предотвращение случайной модификации** Семантика неизменяемого связывания по умолчанию
   означает, что переменная цикла не может быть случайно модифицирована в теле цикла. Не нужно
   беспокоиться о том, что где-то в сложном теле цикла случайно напишется `i = ...` и вызовет
   трудноотслеживаемую ошибку.

3. **Высокопроизводительные решения всегда под рукой** Когда действительно необходимо
   переиспользовать переменные между итерациями (например, аккумуляторы, кэши), достаточно
   использовать `for mut` для переключения в режим изменяемого связывания. Это яснее неявного
   разделения состояния — намерение явно выражается через синтаксис, а не скрыто в поведении во
   время выполнения.

### 3.10 Инструкция spawn

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**spawn-блок**: явное объявление параллельной области, выражения в блоке выполняются параллельно.

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**spawn-цикл**: цикл с параллелизмом по данным.

```yaoxiang
results = spawn for item in items {
    process(item)
}
```

**spawn-блок захватывает внешние переменные** (RFC-024 §2.3, семантика захвата значений):

- Тело блока ссылается на внешнюю переменную = **Move-захват значения**: значение копируется в
  окружение замыкания в точке создания spawn, тело блока читает через env (LoadUpvalue)
- **Примитивы** (Int/Float/Bool/Char) копируются по значению, внешняя переменная не затрагивается
- **Типы-дескрипторы** (Struct/String/List и т.д.) — копия снимка = копия дескриптора, разделяет
  нижележащий объект; во встроенном (Embedded) времени выполнения (по умолчанию) один поток — одна
  куча, дескриптор валиден
- Для разделения между несколькими задачами требуется явный `ref` (§2.13, компилятор автоматически
  выбирает Rc/Arc)
- `return` в блоке, ссылающийся на внешние переменные, также выполняет захват

```yaoxiang
t1 = 1 + 1
t2 = 2 + 2
result = spawn {
    return t1 + t2    // t1/t2 захвачены по значению, result == 6
}
```
