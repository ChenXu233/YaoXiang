# Спецификация синтаксиса

Этот документ определяет спецификацию синтаксиса языка программирования YaoXiang, включая
лексическую структуру, правила грамматики и приоритет операторов.

---

## Глава 1: Лексическая структура

### 1.1 Исходный файл

Исходный файл YaoXiang должен использовать кодировку UTF-8. Исходные файлы обычно имеют расширение
`.yx`.

### 1.2 Классификация лексических единиц

| Категория      | Описание                             | Примеры                   |
| -------------- | ------------------------------------ | ------------------------- |
| Идентификатор  | Начинается с буквы или подчёркивания | `x`, `_private`, `my_var` |
| Ключевое слово | Зарезервированное слово языка        | `Type`, `pub`, `use`      |
| Литерал        | Фиксированное значение               | `42`, `"hello"`, `true`   |
| Оператор       | Символ операции                      | `+`, `-`, `*`, `/`        |
| Разделитель    | Синтаксический разделитель           | `(`, `)`, `{`, `}`, `,`   |

### 1.3 Ключевые слова

YaoXiang определяет минимальное количество ключевых слов:

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

Эти ключевые слова имеют специальное значение в любом контексте и не могут использоваться в качестве
идентификаторов.

### 1.4 Зарезервированные слова

«Зарезервированные слова» в YaoXiang делятся на три уровня, которые распознаются парсером (parser) и
проверщиком типов (type checker) на разных этапах:

#### 1.4.1 Литеральные зарезервированные слова

Идентификаторы литералов, имеющие собственные токены в парсере, не могут использоваться как обычные
идентификаторы:

| Идентификатор | Принадлежность к типу | Описание                                                                                                            |
| ------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `Type`        | —                     | Ключевое слово метатипа                                                                                             |
| `true`        | Bool                  | Логическое значение «истина»                                                                                        |
| `false`       | Bool                  | Логическое значение «ложь»                                                                                          |
| `void`        | Void                  | Литерал Void (значение Unit). Строчный `void` — это литерал значения; заглавный `Void` — это имя типа (см. §1.4.3). |

#### 1.4.2 Выражения-конструкторы

Следующие конструкторы распознаются парсером в контекстах сопоставления с образцом и выражений:

| Конструктор | Принадлежность к типу | Описание                             |
| ----------- | --------------------- | ------------------------------------ |
| `some(T)`   | Option                | Конструктор варианта значения Option |
| `ok(T)`     | Result                | Успешный вариант Result              |
| `err(E)`    | Result                | Вариант ошибки Result                |

#### 1.4.3 Встроенные имена типов

Следующие имена типов предварительно зарегистрированы проверщиком типов и могут использоваться в
позиции типа без импорта. Парсер рассматривает их как обычные идентификаторы — **не
зарезервированные слова, могут быть затенены (shadow) локальной привязкой (не рекомендуется)**.

| Имя типа | Логическое соответствие | Описание                                                                                                                                              |
| -------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤ (True/Unit)           | Тип-произведение без полей, ровно один обитатель (литерал `void`, см. §1.4.1)                                                                         |
| `Never`  | ⊥ (False/пустой тип)    | Тип с нулём вариантов, ноль обитателей. Никакое выражение не может породить значение `Never`. `Never <: T` выполняется для всех `T` (принцип взрыва). |
| `Int`    | —                       | Знаковое целое                                                                                                                                        |
| `Float`  | —                       | Число с плавающей точкой                                                                                                                              |
| `Bool`   | —                       | Логическое значение: `true` / `false`                                                                                                                 |
| `Char`   | —                       | Символ Unicode                                                                                                                                        |
| `String` | —                       | Строка                                                                                                                                                |

### 1.5 Идентификаторы

Идентификаторы начинаются с буквы или подчёркивания, последующие символы могут быть буквами, цифрами
или подчёркиваниями. Идентификаторы чувствительны к регистру.

Специальные идентификаторы:

- `_` используется как заполнитель, означающий игнорирование значения
- Идентификаторы, начинающиеся с подчёркивания, обозначают закрытые члены

### 1.6 Литералы

#### 1.6.1 Целые числа

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 Числа с плавающей точкой

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 Строки

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 Коллекции

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Set         ::= '{' Expr (',' Expr)* '}'
```

#### 1.6.5 Генераторы списков

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

#### 1.6.6 Проверка принадлежности

```
Membership  ::= Expr 'in' Expr
```

### 1.7 Комментарии

```
// однострочный комментарий

/* многострочный комментарий
   может занимать несколько строк */
```

### 1.8 Правила отступов

Код должен использовать отступ в 4 пробела; использование символов табуляции запрещено. Это
обязательное синтаксическое правило.

## Глава 2: Правила грамматики

### 2.1 Классификация выражений

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 Приоритет операторов

| Приоритет | Операторы                   | Ассоциативность |
| --------- | --------------------------- | --------------- |
| 1         | `()` `[]` `.` `?`           | слева направо   |
| 2         | `as`                        | слева направо   |
| 3         | унарный префикс `!` `-` `+` | справа налево   |
| 4         | `*` `/` `%`                 | слева направо   |
| 5         | `+` `-`                     | слева направо   |
| 6         | `..`                        | слева направо   |
| 7         | `<<` `>>`                   | слева направо   |
| 8         | `&` `\|` `^`                | слева направо   |
| 9         | `==` `!=` `<` `>` `<=` `>=` | слева направо   |
| 10        | `and` `or`                  | слева направо   |
| 11        | `if...else`                 | справа налево   |
| 12        | `=` `+=` `-=` `*=` `/=`     | справа налево   |

> **Унарные префиксные операторы** (`!` `-` `+`) тесно связаны: уступают только вызовам и доступу к
> членам, но имеют более высокий приоритет, чем все бинарные операторы. Поэтому `!a == b` ≡
> `(!a) == b` (семантика в стиле Zig); `!` — чисто унарная операция, не участвующая в
> короткозамыкающем потоке управления, ортогональна ключевым словам `and`/`or` (короткое замыкание)
> (авторитетное определение в RFC-010).

### 2.3 Вызов функции

```
FnCall      ::= Expr '(' ArgList? ')'
ArgList     ::= Expr (',' Expr)* (',' NamedArg)* | NamedArg (',' NamedArg)*
NamedArg    ::= Identifier ':' Expr
```

### 2.4 Доступ к члену

```
MemberAccess::= Expr '.' Identifier
```

### 2.5 Доступ по индексу

```
IndexAccess ::= Expr '[' Expr ']'
```

### 2.6 Приведение типа

```
TypeCast    ::= Expr 'as' TypeExpr
```

### 2.7 Условное выражение

```
IfExpr      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 2.8 Сопоставление с образцом

```
MatchExpr   ::= 'match' Expr '{' MatchArm+ '}'
MatchArm    ::= Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
Pattern     ::= Literal
              | Identifier
              | Wildcard
              | StructPattern
              | TuplePattern
              | EnumPattern
              | OrPattern
```

### 2.9 Блочное выражение

```
Block       ::= '{' Stmt* Expr? '}'
```

> **Правила завершения операторов**: разделение между Stmt и поведение переноса строк (явное
> разделение через `;`, завершение переносом строки, исключения для продолжения строки, `(`/`[` в
> начале строки никогда не объединяются) определены в
> [RFC-038](../design/rfc/draft/038-statement-termination.md).

**Единая семантика**: семантика return для всех блоков `{}` согласована:

| Тип блока    | Семантика return            | Возврат по умолчанию |
| ------------ | --------------------------- | -------------------- |
| Обычный `{}` | Возвращает значение         | Void                 |
| `unsafe {}`  | Возвращает определение типа | Void                 |
| `spawn {}`   | Возвращает результат        | Void                 |

**Основные принципы**:

- `return` в `{}` всегда возвращает содержимое во внешнюю область видимости
- При отсутствии `return` возвращается `Void`
- Форма выражения `= expr` напрямую возвращает значение

```yaoxiang
// Обычный блок {}: return возвращает значение
result = {
    x = compute()
    return x  // возвращает значение во внешнюю область видимости
}

// Блок unsafe {}: return возвращает определение типа
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    return SqliteDb  // возвращает определение типа во внешнюю область видимости
}

// Блок spawn {}: return возвращает результат
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    return (result1, result2)  // возвращает результат во внешнюю область видимости
}
```

### 2.10 Лямбда-выражение

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 Оператор распространения ошибки

```
ErrorPropagate ::= Expr '?'
```

Оператор `?` является постфиксным оператором с тем же приоритетом, что и `.`. Для типа
`Result(T, E)`:

- При `Ok(v)` извлекается значение `v` и выполнение продолжается
- При `Err(e)` ошибка распространяется вверх (`return Err(e)`)

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // при успехе извлекается значение, при неудаче — распространение вверх
    transform(validated)
}
```

### 2.12 Выражение диапазона

```
RangeExpr   ::= Expr '..' Expr
```

`..` создаёт тип диапазона, используемый для циклов `for` и срезов.

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]
```

### 2.13 Выражение ref

```
RefExpr     ::= 'ref' Expr
```

`ref` создаёт разделяемое владение. Компилятор автоматически выбирает Rc (одна задача) или Arc
(между задачами), пользователю не нужно беспокоиться о деталях реализации.

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // между задачами: компилятор автоматически выбирает Arc
```

### 2.14 Выражение unsafe

```
UnsafeExpr  ::= 'unsafe' Block
```

Блок `unsafe` используется для определения непрозрачных типов и работы с сырыми указателями.
Используйте `return` для возврата определения типа во внешнюю область видимости.

**Семантика**:

- В `unsafe {}` можно определять типы и работать с сырыми указателями
- Возвращаемый тип доступен вне `unsafe {}`
- Доступ к полям типа требует разрешения unsafe

```yaoxiang
// Определение непрозрачного типа в блоке unsafe
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // сырой указатель
    }
    return SqliteDb
}

// SqliteDb доступен вне блока unsafe
db = sqlite3_open("test.db")
```

### 2.15 Область видимости

**Основные правила**:

- Каждый блок `{}` создаёт область видимости
- Внутренняя область видимости имеет доступ к переменным внешней области
- Внешняя область видимости не имеет доступа к переменным внутренней области
- Объявление переменных следует принципу «приоритет присваивания»

```yaoxiang
// Блочная область видимости
{
    x = 10
    // x виден в этой области видимости
}
// x не виден за пределами этой области видимости

// Область видимости функции
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result не виден за пределами функции
```

**Объявление и затенение переменных**:

- `x = value`: поиск `x` по цепочке областей видимости наружу, при нахождении — присваивание, при
  отсутствии — новое объявление
- `mut x = value`: явное новое изменяемое объявление, запрещено совпадение имён с внешней областью
- В одной области видимости любое имя может быть объявлено только один раз

> **Подробное определение**: полные правила области видимости, механизм объявления и затенения
> переменных подробно описаны в [Спецификации модульной системы](./modules.md#第四章作用域).

## Глава 3: Операторы

### 3.1 Классификация операторов

```

              | ExprStmt
              | ReturnStmt
              | BreakStmt
              | ContinueStmt
              | IfStmt
              | MatchStmt
              | WhileStmt
              | ForStmt
              | SpawnStmt
```

### 3.2 Объявление переменной

```

```

### 3.3 Оператор return

```
ReturnStmt  ::= 'return' Expr?
```

**Семантика**: `return` используется для возврата значения из блока кода. При отсутствии `return`
блок по умолчанию возвращает `Void`.

### 3.4 Оператор break

```

```

### 3.5 Оператор continue

```

```

### 3.6 Оператор if

```
IfStmt      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 3.7 Оператор match

```
MatchStmt   ::= 'match' Expr '{' MatchArm+ '}'
```

### 3.8 Оператор while

```
WhileStmt   ::= 'while' Expr Block
```

### 3.9 Оператор for

```
ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block
```

#### 3.9.1 Семантика: каждая итерация — это новая привязка значения

Семантика цикла for в YaoXiang отличается от традиционных языков: **каждая итерация — это новая
привязка значения, а не изменение одной и той же переменной**.

```yaoxiang
// Пример: for i in 1..5
for i in 1..5 {
    print(i)
}
```

**Процесс выполнения**:

| Итерация   | Поведение переменной цикла                                                                             |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| 1-я        | Создаётся новая привязка `i = 1`, выполняется тело цикла, выводится 1                                  |
| 2-я        | Создаётся новая привязка `i = 2` (предыдущая привязка уничтожена), выполняется тело цикла, выводится 2 |
| 3-я        | Создаётся новая привязка `i = 3`, выполняется тело цикла, выводится 3                                  |
| 4-я        | Создаётся новая привязка `i = 4`, выполняется тело цикла, выводится 4                                  |
| Завершение | Тело цикла завершается, привязка уничтожается                                                          |

**Ключевой момент**: после завершения каждой итерации созданная в ней привязка уничтожается.
Следующая итерация — это совершенно новая привязка, никак не связанная с привязкой предыдущей
итерации.

#### 3.9.2 Разница между for и for mut

| Синтаксис           | Изменяемость переменной цикла | Описание                              |
| ------------------- | ----------------------------- | ------------------------------------- |
| `for i in 1..5`     | Неизменяемая                  | Нельзя изменять привязку в теле цикла |
| `for mut i in 1..5` | Изменяемая                    | Можно изменять привязку в теле цикла  |

```yaoxiang
// Корректно: каждая итерация — новое значение, изменение не требуется
for i in 1..5 {
    print(i)  // чтение значения i
}

// Ошибка: неизменяемая привязка, нельзя изменить
for i in 1..5 {
    i = i + 1  // ошибка: нельзя изменить неизменяемую привязку
}

// Корректно: использование for mut разрешает изменение привязки
for mut i in 1..5 {
    i = i + 1  // изменение разрешено
}
```

#### 3.9.3 Проверка затенения

YaoXiang запрещает затенение переменных. Переменная цикла for не может иметь то же имя, что и
переменная во внешней области видимости:

```yaoxiang
// Ошибка: i уже объявлена во внешней области
i = 10
for i in 1..5 {
    print(i)
}

// Корректно: использование разных имён переменных
i = 10
for j in 1..5 {
    print(j)
}
```

Это правило применяется ко всем блокам кода, подробности см. в
[4.3 Правила затенения](./modules.md#43-遮蔽规则).

#### 3.9.4 Сравнение с другими языками

| Язык     | Семантика переменной цикла for                                       |
| -------- | -------------------------------------------------------------------- |
| YaoXiang | Новое значение привязывается на каждой итерации                      |
| Rust     | Изменение одной и той же переменной (требуется mut)                  |
| Python   | Изменение одной и той же переменной (без mut)                        |
| C/C++    | Изменение одной и той же переменной (требуется указатель или ссылка) |

**Обоснование дизайна**: YaoXiang использует семантику привязки, потому что:

1. **Более соответствует естественной семантике** В естественном языке «для каждого элемента x из
   множества» означает, что каждый x — это независимая сущность. Конструкция YaoXiang
   `for i in 1..5` читается как «для каждого i от 1 до 5», и i в каждой итерации — это совершенно
   новая привязка, что согласуется с интуитивным человеческим пониманием.

2. **Предотвращение случайных изменений** Семантика неизменяемой привязки по умолчанию означает, что
   в теле цикла нельзя случайно изменить переменную цикла. Не нужно беспокоиться о том, что где-то в
   сложном теле цикла случайно появится `i = ...`, приводящее к трудноотслеживаемой ошибке.

3. **Высокопроизводительные решения всегда под рукой** Когда действительно необходимо повторно
   использовать переменную между итерациями (например, аккумулятор, кэш), достаточно использовать
   `for mut`, чтобы переключиться в режим изменяемой привязки. Это яснее, чем неявное разделение
   состояния — намерение выражается явно через синтаксис, а не скрыто в поведении во время
   выполнения.

### 3.10 Оператор spawn

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**spawn-блок**: явное объявление параллельной области, выражения в блоке выполняются параллельно.

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**spawn-цикл**: параллельный по данным цикл.

```yaoxiang
results = spawn for item in items {
    process(item)
}
```

**spawn-блок захватывает переменные внешней области** (RFC-024 §2.3, семантика захвата по значению):

- Тело блока ссылается на переменные внешней области = **захват Move по значению**: значение снимком
  (snapshot) помещается в замыкание в точке создания spawn, тело блока читает через env
  (LoadUpvalue)
- **Примитивы** (Int/Float/Bool/Char) копируются по значению, внешняя переменная не затрагивается
- **Типы-дескрипторы** (Struct/String/List и т.д.) снимок = копирование дескриптора, базовый объект
  разделяется; в Embedded-среде исполнения (по умолчанию) с одной и той же кучей потока дескрипторы
  действительны
- Для разделения между несколькими задачами требуется явный `ref` (§2.13, компилятор автоматически
  выбирает Rc/Arc)
- `return` в блоке, ссылающийся на внешние переменные, также захватывает их

```yaoxiang
t1 = 1 + 1
t2 = 2 + 2
result = spawn {
    return t1 + t2    // t1/t2 захвачены по значению, result == 6
}
```
