# Спецификация синтаксиса

Этот документ определяет спецификацию синтаксиса языка программирования YaoXiang, включая
лексическую структуру, правила грамматики и приоритет операторов.

---

## Глава 1: Лексическая структура

### 1.1 Исходный файл

Исходные файлы YaoXiang должны использовать кодировку UTF-8. Исходные файлы обычно имеют расширение
`.yx`.

### 1.2 Классификация лексических единиц

| Категория      | Описание                                          | Примеры                   |
| -------------- | ------------------------------------------------- | ------------------------- |
| Идентификатор  | Начинается с буквы или подчёркивания              | `x`, `_private`, `my_var` |
| Ключевое слово | Языковые предопределённые зарезервированные слова | `Type`, `pub`, `use`      |
| Литерал        | Фиксированное значение                            | `42`, `"hello"`, `true`   |
| Оператор       | Символ операции                                   | `+`, `-`, `*`, `/`        |
| Разделитель    | Синтаксический разделитель                        | `(`, `)`, `{`, `}`, `,`   |

### 1.3 Ключевые слова

YaoXiang определяет минимальный набор ключевых слов:

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

Эти ключевые слова имеют специальное значение в любом контексте и не могут использоваться как
идентификаторы.

### 1.4 Зарезервированные слова

«Зарезервированные слова» YaoXiang разделены на три уровня, распознаваемых на разных этапах парсером
(parser) и проверщиком типов (type checker):

#### 1.4.1 Литеральные зарезервированные слова

Идентификаторы литералов, имеющие отдельные токены в парсере и не могущие использоваться как обычные
идентификаторы:

| Идентификатор | Принадлежность к типу | Описание                                                                                                    |
| ------------- | --------------------- | ----------------------------------------------------------------------------------------------------------- |
| `Type`        | —                     | Ключевое слово метатипа                                                                                     |
| `true`        | Bool                  | Логическое значение «истина»                                                                                |
| `false`       | Bool                  | Логическое значение «ложь»                                                                                  |
| `void`        | Void                  | Литерал Void (значение Unit). Строчная `void` — литерал значения; прописная `Void` — имя типа (см. §1.4.3). |

#### 1.4.2 Конструкторы выражений

Следующие конструкторы распознаются парсером в контекстах сопоставления с образцом и выражений:

| Конструктор | Принадлежность к типу | Описание                    |
| ----------- | --------------------- | --------------------------- |
| `some(T)`   | Option                | Конструктор варианта Option |
| `ok(T)`     | Result                | Успешный вариант Result     |
| `err(E)`    | Result                | Вариант ошибки Result       |

#### 1.4.3 Имена встроенных типов

Следующие имена типов предварительно зарегистрированы проверщиком типов и могут использоваться в
позиции типа без импорта. Парсер рассматривает их как обычные идентификаторы — **не являются
зарезервированными словами и могут быть затенены (shadow) локальными привязками (не
рекомендуется)**.

| Имя типа | Логическое соответствие | Описание                                                                                                                                              |
| -------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤ (истина/Unit)         | Тип произведения с нулём полей, ровно один обитатель (литерал `void`, см. §1.4.1)                                                                     |
| `Never`  | ⊥ (ложь/пустой тип)     | Тип с нулём вариантов, ноль обитателей. Никакое выражение не может породить значение `Never`. `Never <: T` выполняется для всех `T` (принцип взрыва). |
| `Int`    | —                       | Знаковое целое число                                                                                                                                  |
| `Float`  | —                       | Число с плавающей точкой                                                                                                                              |
| `Bool`   | —                       | Логическое значение: `true` / `false`                                                                                                                 |
| `Char`   | —                       | Символ Unicode                                                                                                                                        |
| `String` | —                       | Строка                                                                                                                                                |

### 1.5 Идентификаторы

Идентификаторы начинаются с буквы или подчёркивания, последующие символы могут быть буквами, цифрами
или подчёркиваниями. Идентификаторы чувствительны к регистру.

Специальные идентификаторы:

- `_` используется как заглушка, обозначающая игнорирование значения
- Идентификаторы, начинающиеся с подчёркивания, обозначают закрытые члены

### 1.6 Литералы

#### 1.6.1 Целые числа

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 Числа с плавающей точкой

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 Строки

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 Коллекции

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Array       ::= '[' Expr (',' Expr)* ']'   // При аннотации целевого типа Array(T, N) литерал становится массивом фиксированной длины
```

> Set не имеет литеральной грамматики и представления во время выполнения — тип множества в
> планировании, при появлении потребности будет дополнен по модели Dict (std.set + HeapValue::Set).
> Целевая точка литералов List/Dict определяется аннотацией контекстного типа: голый литерал и
> аннотация `List(T)` создают растущий список; аннотация `Array(T, N)`, применённая непосредственно
> к литералу, создаёт массив фиксированной длины. Неявное преобразование List→Array запрещено.
>
> Семантика литерала Array:
>
> - Количество элементов должно быть равно N, иначе ошибка компиляции E1002; пустой литерал с
>   ненулевым N также отвергается
> - Тип каждого элемента должен быть совместим с T, несоответствие — ошибка компиляции E1002
> - Грамматическая форма N: только целочисленный литерал (возможно отрицательный) или имя константы;
>   составные выражения (например, `2+1`) отвергаются на этапе разбора
> - Когда N является символьной константой (параметр const функции, например `Array(Int, n)`),
>   проверка количества откладывается до фазы уточнения типов
> - Вложенные литералы массивов версии v1 (например, `Array(Array(Int,2),2) = [[1,2],[3,4]]`)
>   отвергаются на этапе компиляции, требуется явное поэтапное конструирование; рекурсивная целевая
>   точка остаётся для будущих версий

#### 1.6.5 List comprehension (генератор списков)

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

> **Ужесточение поведения (запись миграции)**: грамматика переменной итерации изначально была
> `'for' Identifier 'in'`, но в старой реализации pattern проходил через полный pratt-разбор — после
> регистрации `'in'` как инфиксного оператора `x` поглощал `in items` как membership-выражение.
> После исправления pattern, не являющийся идентификатором, приводит к прямому сбою разбора и больше
> не откатывается к `_` (тихому проглатыванию ошибки) как в старой реализации. Область влияния:
> ранее разбираемая запись `[x for (a, b) in pairs]` теперь вызывает ошибку — такая форма никогда не
> имела определённого поведения (переменная всегда была `_`), направление ужесточения корректно,
> затрат на семантическую миграцию нет.

#### 1.6.6 Проверка членства

```
Membership  ::= Expr 'in' Expr
```

> `in` — бинарный оператор отношения, возвращающий `Bool` — `true` при попадании, `false` при
> непопадании, без ошибки. Разделение семантики: `[]` — это утверждение существования и извлечение
> значения (ошибка при сбое), `in` — это запрос о существовании (непопадание — нормальный `false`).
> Правый операнд охватывает: List / Array / Dict (набор ключей) / Tuple / String (подстрока) / Range
> (интервал). `in` — это предикат первого класса, на этапе уточнения типов служит базой для
> доказуемых во время компиляции утверждений. (Set исключён из списка правых операндов — Set не
> имеет представления во время выполнения, см. §1.6.4)

### 1.7 Комментарии

```
// однострочный комментарий

/* многострочный комментарий
   может занимать несколько строк */
```

обязательное синтаксическое правило.

## Глава 2: Правила грамматики

### 2.1 Классификация выражений

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 Приоритет операторов

| Приоритет | Операторы                      | Ассоциативность |
| --------- | ------------------------------ | --------------- |
| 1         | `()` `[]` `.` `?`              | слева направо   |
| 2         | `as`                           | слева направо   |
| 3         | унарные префиксные `!` `-` `+` | справа налево   |
| 4         | `*` `/` `%`                    | слева направо   |
| 5         | `+` `-`                        | слева направо   |
| 6         | `..`                           | слева направо   |
| 7         | `<<` `>>`                      | слева направо   |
| 8         | `&` `\|` `^`                   | слева направо   |
| 9         | `==` `!=` `<` `>` `<=` `>=`    | слева направо   |
| 10        | `and` `or`                     | слева направо   |
| 11        | `if...else`                    | справа налево   |
| 12        | `=` `+=` `-=` `*=` `/=`        | справа налево   |

> **Унарные префиксные операторы** (`!` `-` `+`) имеют сильное связывание: уступают только вызову
> функций и доступу к членам, но выше всех бинарных операторов. Поэтому `!a == b` ≡ `(!a) == b`
> (семантика в стиле Zig); `!` является чисто унарной операцией, не участвует в короткозамыкающем
> потоке управления и ортогональна ключевым словам `and`/`or` (короткое замыкание) (авторитетное
> определение в RFC-010).

> **Сила связывания Range**: `..` имеет силу связывания (6, 7) — левая часть 6 ниже сложения (7),
> правая часть 7 поглощает сложение, но не поглощает `..` того же уровня. Сравнение до и после
> изменения:
>
> | Выражение    | До изменения (уровень 1, правоассоц.)                                                                    | После изменения ((6,7), левоассоц.)                                           |
> | ------------ | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
> | `x in 1..10` | `x in 1..10` (правый операнд `in` уровня 4, `..` уровня 1 не может поглотить, фактически не разбирается) | `x in (1..10)` — интервал целиком как правый операнд `in`                     |
> | `0..n+2`     | `(0..n)+2` (ловушка правоассоц.: верхняя граница съедается, `for` цикл сразу E3004)                      | `0..(n+2)` — верхняя граница — арифметическое выражение                       |
> | `a == b..c`  | `a == (b..c)` (`..` уровня 1 < `==` уровня 3, естественно целиком)                                       | `a == (b..c)` — **семантика не меняется**, `..` всё ещё выше уровня сравнения |
> | `1..2*3`     | `(1..2)*3`                                                                                               | `1..(2*3)` — верхняя граница — арифметическое выражение                       |
> | `a..b..c`    | `a..(b..c)` (правоассоц. цепочка, бессмысленный Range внутри Range)                                      | `(a..b)..c` — **форма со шагом** (`c` — шаг)                                  |
>
> Чистый эффект: составная верхняя граница `for i in 0..n+2` переходит из «разбор успешен, но E3004»
> в «сразу доступно»; `x in 1..10` переходит из «не разбирается» в «проверка интервала»; `a..b..c`
> переходит из «бессмысленной вложенности» в «компонент шага». Уровень 6 располагается между `+`
> (уровень 5) и `<<` (уровень 7), математическое соглашение: интервал — сильно связывающая
> конструкция, верхняя граница естественно является полным арифметическим выражением.

### 2.9 Блочное выражение

```
Block       ::= '{' Stmt* Expr? '}'
```

> **Правила завершения операторов**: разделение Stmt и поведение переноса строк (`;` явное
> разделение, завершение переносом строки, исключения продолжения строки, никогда не объединять с
> `(`/`[` в начале строки) определены в [RFC-038](../design/rfc/draft/038-statement-termination.md).

**Единая семантика**: значение всех блоков `{}` определяется **хвостовым выражением**; `return` —
нелокальный выход типа `Never`.

| Тип блока    | Выход значения      | Пустой блок `{}` |
| ------------ | ------------------- | ---------------- |
| Обычный `{}` | Хвостовое выражение | `Void`           |
| `unsafe {}`  | Хвостовое выражение | `Void`           |
| `spawn {}`   | Хвостовое выражение | `Void`           |

**Основные принципы** (подробности см. в
[RFC-010a](../design/rfc/accepted/010a-tail-expression-and-return.md)):

- **Значение блока = хвостовое выражение** (последнее выражение), единственный выход, без исключений
- Если в конце — **оператор присваивания**, значение блока — `Void`; если нужен `Void`, пишите
  `Void` явно
- **`return` выходит за ближайшую границу функции** (проходит сквозь все блоки, не «возвращается
  блоку»), тип `Never`; `Never <: T` выполняется для любого типа (принцип взрыва), поэтому может
  появляться в любой позиции возвращаемого типа
- Форма выражения `= expr` непосредственно даёт значение

```yaoxiang
// Обычный блок {}: хвостовое выражение даёт значение
result = {
    x = compute()
    x                // значение блока
}

// Блок unsafe {}: хвостовое выражение даёт определение типа
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    SqliteDb         // значение блока
}

// Блок spawn {}: хвостовое выражение даёт результат
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    (result1, result2)   // значение блока
}

// return: проходит сквозь блок, выходит из функции
f: (n: Int) -> Int = {
    if n < 0 {
        return 0     // проходит сквозь if и тело функции, выходит из функции
    }
    n * 2            // хвостовое выражение
}
```

#### `name = { ... }` — это функция или значение блока?

`name = { ... }` может быть как определением функции (RFC-007 «простейшая форма без параметров»),
так и привязкой значения блока. Решение принимается по **приоритету аннотации, по умолчанию
функция** (RFC-010a, приложение D):

| Случай                            | Результат          | Пример                             |
| --------------------------------- | ------------------ | ---------------------------------- |
| Значение — Lambda (`=>`)          | Функция            | `f = () => 5` → `f()` = 5          |
| Аннотация — функциональный тип    | Функция            | `f: () -> Int = { 5 }` → `f()` = 5 |
| Аннотация — не функциональный тип | **Значение блока** | `x: Int = { 5 }` → `x` = 5         |
| Без аннотации                     | Функция            | `f = { 5 }` → `f()` = 5            |

**Аннотация есть тип**: `x: Int = ...` объявляет `x` как `Int`, значит `{ ... }` вычисляется в
`Int`; `f: () -> Int = ...` объявляет `f` как функцию, значит `{ ... }` — тело функции.

Чтобы `{ ... }` вычислялся сразу, **просто напишите целевой тип** (новый синтаксис не нужен):

```yaoxiang
// Значение блока: немедленное вычисление
x: Int = {
    y = 5
    y            // x = 5
}

// Функция: без аннотации по умолчанию
f = { 5 }        // f() = 5
```

#### Вложенные функциональные типы: каррирование или возврат функции?

Вложенный функциональный тип справа от `->` имеет два прочтения, различаемых **скобками** (RFC-004):

| Запись                          | Значение            | Вызов               |
| ------------------------------- | ------------------- | ------------------- |
| `(a: Int) -> (b: Int) -> Int`   | **Каррирование**    | `f(1)(2)`           |
| `(a: Int) -> ((b: Int) -> Int)` | **Возврат функции** | `g(1)` даёт функцию |

Принцип: **аннотация есть тип**. `g: (a: Int) -> ((b: Int) -> Int)` объявляет, что
`g(1) : (b: Int) -> Int`, поэтому `g(1)` должно **быть** той функцией, а не «следующей порцией
аргументов».

```yaoxiang
// Каррирование: два сегмента аргументов подаются послойно
add: (a: Int) -> (b: Int) -> Int = { a + b }
add(1)(2)        // → 3

// Возврат функции: внешний сегмент аргументов, возвращается сама функция
adder: (n: Int) -> ((x: Int) -> Int) = (x) => x + n
adder(10)(5)     // → 15
h = adder(10)    // возвращённую функцию можно сохранить в переменную, передать
```

Вложенная `Fn` без скобок всегда каррируется (включая форму с параметрами типа из RFC-011):

```yaoxiang
identity: (T: Type) -> (x: T) -> T = (x) => x   // каррирование
identity(5)      // → 5
```

**Проверка типов**: скобки объявляют тип возврата, тело должно порождать этот тип.
`f: () -> (() -> Int) = { 7 }` — ошибка: ожидается `() -> Int`, фактически `Int` (E1002).

### 2.11 Оператор распространения ошибки

```
ErrorPropagate ::= Expr '?'
```

Оператор `?` является постфиксным оператором с приоритетом, эквивалентным `.`. Для типа
`Result(T, E)`:

- При `Ok(v)` извлекает значение `v` и продолжает выполнение
- При `Err(e)` распространяет ошибку вверх (`return Err(e)`)

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // при успехе извлекает значение, при сбое распространяет вверх
    transform(validated)
}
```

### 2.12 Выражение диапазона

```
RangeExpr   ::= Expr '..' Expr ('..' Expr)?
```

`..` создаёт значение диапазона (Range — значение первого класса, не синтаксический сахар).

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]

// Range — это значение: можно связывать, передавать, проверять членство
r = 1..10
assert.assert(5 in r, "membership")
for i in r { print(i) }

// Форма со шагом (третий компонент, по умолчанию 1)
for i in 0..10..2 { print(i) }  // 0, 2, 4, 6, 8
for i in 10..0..(-2) { print(i) }  // 10, 8, 6, 4, 2
```

> **Семантика шага**: в `a..b..c` `c` — это шаг. `c = 0` как литерал отвергается на этапе
> компиляции; динамический `c` проверяется во время выполнения на ноль (семейство E6001; после
> внедрения системы ошибок будет повышен до Result). `c < 0` допустимо, направление интервала
> меняется на противоположное в зависимости от знака (`10..0..(-2)` — убывание).

### 2.13 Выражение ref

```
RefExpr     ::= 'ref' Expr
```

`ref` создаёт разделяемое владение. Компилятор автоматически выбирает Rc (одна задача) или Arc
(между задачами); пользователю не нужно беспокоиться о деталях реализации.

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // между задачами: компилятор автоматически выбирает Arc
```

### 2.14 Выражение unsafe

````
UnsafeExpr  ::= 'unsafe' Block`

Блок `unsafe` используется для определения непрозрачных типов и работы с сырыми указателями. Используйте `return` для возврата определения типа в вышестоящую область видимости.

**Семантика**:

- В `unsafe {}` можно определять типы и работать с сырыми указателями
- Возвращённый тип доступен за пределами `unsafe {}`
- Доступ к полям типа требует полномочий unsafe

```yaoxiang
// Определение непрозрачного типа в блоке unsafe
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // сырой указатель
    }
    return SqliteDb
}

// SqliteDb доступен за пределами блока unsafe
db = sqlite3_open("test.db")
````

### 2.15 Область видимости

**Основные правила**:

- Каждый блок `{}` создаёт область видимости
- Внутренняя область видимости может обращаться к переменным внешней области
- Внешняя область видимости не может обращаться к переменным внутренней области
- Объявление переменных подчиняется принципу «приоритет присваивания»

```yaoxiang
// Блочная область видимости
{
    x = 10
    // x виден в этой области видимости
}
// x не виден за пределами этой области видимости

// Область видимости функции
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result не виден за пределами функции
```

**Объявление и затенение переменных**:

- `x = value`: поиск x вверх по цепочке областей видимости; если найден — присваивание, если не
  найден — новое объявление
- `mut x = value`: явное объявление новой изменяемой переменной, запрещено совпадение имён с внешней
  областью
- В одной области видимости любое имя может быть объявлено только один раз

> **Подробное определение**: полные правила области видимости, механизмы объявления и затенения
> переменных подробно описаны в [спецификации модульной системы](./modules.md#第四章作用域).

### 3.3 Оператор return

```
ReturnStmt  ::= 'return' Expr?
```

**Семантика**: `return` — это **нелокальный выход**, выходящий за ближайшую **границу функции**
(проходит сквозь все блоки — включая `if` / `while` / `for` / `match` / голые блоки / `spawn` /
`unsafe`), передавая значение вызывающему. Он **не «возвращается блоку»**.

**Тип**: `return e : Never` (при `e : T`). `Never <: T'` выполняется для любого `T'` (принцип
взрыва, см. [type system §2.2](./type-system.md)), поэтому `return` может появляться в любой позиции
возвращаемого типа без дополнительных правил.

**Отношение к вычислению блока**: значение блока всегда равно **хвостовому выражению** (см. §2.9).
`{ return n }` как блок имеет значение `n` типа `Never`; одновременно `return` выполняет выход из
функции. **Оба утверждения истинны одновременно**, что обеспечивается принципом взрыва.

`return` и хвостовое выражение совместно обеспечивают «досрочный возврат» без специальных правил,
указывающих `return` на функцию — см.
[RFC-010a](../design/rfc/accepted/010a-tail-expression-and-return.md).

```yaoxiang
factorial: (n: Int) -> Int = {
    if n <= 1 {
        return 1          // проходит сквозь if, выходит из функции (тип Never)
    }
    n * factorial(n - 1)  // хвостовое выражение = значение блока
}
```

### 3.4 Оператор break

```
BreakStmt   ::= 'break'
```

**Семантика**: немедленно завершает самый внутренний цикл `while`/`for`, поток управления переходит
к коду после тела цикла.

- **Выходит только на ближайший уровень**: `break` всегда действует на самый внутренний цикл, его
  содержащий. Если во вложенных циклах нужно выйти сразу на несколько уровней, извлеките внутренний
  цикл в функцию и используйте `return`, либо используйте флаг (break/continue без меток; если в
  будущем будут введены метки циклов, они пойдут через RFC-процесс на стороне объявления цикла, и
  будут решаться совместно с конструкцией множественных выходов в доказательственном конвейере)
- **Только в теле цикла**: `break` может появляться только в теле циклов `while`/`for` (включая
  вложенные блоки/if/match внутри тела); появление вне цикла вызывает ошибку компиляции (E1102
  `'break' outside of a loop`)
- **Не влияет на доказательство завершимости**: цикл `while` всё равно должен быть доказуемо
  завершающимся (метрика decreases); `break` не участвует в аргументации завершимости,
  `while true { break }` не будет принято
- **Семантика заимствования**: ребро потока управления break участвует в структурном разрыве
  обратного BFS-анализа живости RFC-009a (выпрыгнувшие итерации не участвуют в выводе живости
  обратных рёбер)

```yaoxiang
mut i = 0
while i < 10 {
    i = i + 1
    if i == 3 {
        break              // поток управления переходит после цикла, i == 3
    }
}

// Вложенные циклы: break выходит только из внутреннего
while j < 3 {
    while k < 10 {
        if k == 2 { break }    // завершает только внутренний цикл
    }
    j = j + 1                  // каждая итерация внешнего цикла выполняется до этой точки
}
```

### 3.5 Оператор continue

```
ContinueStmt::= 'continue'
```

**Семантика**: пропускает оставшиеся операторы текущей итерации и непосредственно переходит к
следующей итерации самого внутреннего цикла — `while` возвращается к переоценке условия, `for` берёт
следующий элемент.

- **Действует только на ближайший уровень**: то же, что `break`, без меток
- **Только в теле цикла**: появление вне цикла вызывает ошибку компиляции (E1102)

```yaoxiang
mut sum = 0
mut n = 0
while n < 5 {
    n = n + 1
    if n == 3 {
        continue           // пропускает накопление ниже, n == 3 не учитывается
    }
    sum = sum + n
}
// sum == 12 (1 + 2 + 4 + 5)
```

### 3.9 Оператор for

```
ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block
```

#### 3.9.1 Семантика: каждая итерация — это новая привязка значения

Семантика цикла for в YaoXiang отличается от традиционных языков: **каждая итерация — это новая
привязка значения, а не изменение той же переменной**.

```yaoxiang
// Пример: for i in 1..5
for i in 1..5 {
    print(i)
}
```

**Процесс выполнения**:

| Итерация   | Поведение переменной цикла                                                                        |
| ---------- | ------------------------------------------------------------------------------------------------- |
| 1-я        | Создаётся новая привязка `i = 1`, выполняется тело, печатается 1                                  |
| 2-я        | Создаётся новая привязка `i = 2` (предыдущая привязка уничтожена), выполняется тело, печатается 2 |
| 3-я        | Создаётся новая привязка `i = 3`, выполняется тело, печатается 3                                  |
| 4-я        | Создаётся новая привязка `i = 4`, выполняется тело, печатается 4                                  |
| Завершение | Тело цикла завершается, привязка уничтожается                                                     |

**Ключевой момент**: после завершения каждой итерации созданная в ней привязка уничтожается.
Следующая итерация — это совершенно новая привязка, никак не связанная с привязкой предыдущей
итерации.

#### 3.9.2 Различие между for и for mut

| Синтаксис           | Изменяемость переменной цикла | Описание                              |
| ------------------- | ----------------------------- | ------------------------------------- |
| `for i in 1..5`     | Неизменяемая                  | В теле цикла нельзя изменить привязку |
| `for mut i in 1..5` | Изменяемая                    | В теле цикла можно изменить привязку  |

```yaoxiang
// Допустимо: каждая итерация привязывает новое значение, модификация не нужна
for i in 1..5 {
    print(i)  // чтение значения i
}

// Ошибка: неизменяемая привязка, нельзя изменить
for i in 1..5 {
    i = i + 1  // ошибка: нельзя изменить неизменяемую привязку
}

// Допустимо: использование for mut разрешает изменение привязки
for mut i in 1..5 {
    i = i + 1  // изменение разрешено
}
```

#### 3.9.3 Проверка затенения

YaoXiang запрещает затенение переменных. Переменная цикла for не может иметь то же имя, что и
переменная во внешней области видимости:

```yaoxiang
// Ошибка: i уже объявлен снаружи
i = 10
for i in 1..5 {
    print(i)
}

// Правильно: используйте разные имена переменных
i = 10
for j in 1..5 {
    print(j)
}
```

Это правило применяется ко всем блокам кода, подробности см. в
[4.3 правила затенения](./modules.md#43-遮蔽规则).

#### 3.9.4 Сравнение с другими языками

| Язык     | Семантика переменной цикла for                             |
| -------- | ---------------------------------------------------------- |
| YaoXiang | Каждая итерация привязывает новое значение                 |
| Rust     | Изменение той же переменной (требует mut)                  |
| Python   | Изменение той же переменной (без mut)                      |
| C/C++    | Изменение той же переменной (требует указателя или ссылки) |

**Обоснование дизайна**: YaoXiang использует семантику привязки, потому что:

1. **Более соответствует естественной семантике**. В естественном языке «для каждого элемента x в
   коллекции» означает, что каждый x — это отдельная сущность. `for i in 1..5` в YaoXiang читается
   как «для каждого i от 1 до 5», где i каждой итерации — это совершенно новая привязка, что
   согласуется с человеческой интуицией.

2. **Предотвращение случайных изменений**. Семантика неизменяемой привязки по умолчанию означает,
   что в теле цикла невозможно случайно изменить переменную цикла. Не нужно беспокоиться о том, что
   где-то в сложном теле цикла случайно написано `i = ...`, вызывающее трудноотслеживаемый баг.

3. **Высокопроизводительное решение под рукой**. Когда действительно нужно повторно использовать
   переменную между итерациями (например, аккумулятор, кэш), используйте `for mut` для переключения
   в режим изменяемой привязки. Это яснее неявного общего состояния — намерение выражается
   синтаксически явно, а не скрывается в поведении во время выполнения.

### 3.10 Оператор spawn

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**spawn блок**: явное объявление параллельной области, выражения внутри блока выполняются
параллельно.

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**spawn цикл**: параллельный по данным цикл.

```yaoxiang
results = spawn for item in items {
    process(item)
}
```

**spawn блок захватывает переменные внешней области** (RFC-024 §2.3, семантика захвата значения):

- Тело блока ссылается на внешнюю переменную = **захват значения с перемещением (Move)**: значение
  снимается в снимок в среде замыкания в точке создания spawn, тело блока читает через env
  (LoadUpvalue)
- **Примитивы** (Int/Float/Bool/Char) копируются по значению, внешняя переменная не затрагивается
- **Типы-дескрипторы** (Struct/String/List и т.д.) снимок = копия дескриптора, разделяет нижележащий
  объект; в Embedded runtime (по умолчанию) один поток и одна куча, дескриптор действителен
- Для разделения между несколькими задачами требуется явный `ref` (§2.13, компилятор автоматически
  выбирает Rc/Arc)
- `return` внутри блока, ссылающийся на внешнюю переменную, также захватывает её

```yaoxiang
t1 = 1 + 1
t2 = 2 + 2
result = spawn {
    return t1 + t2    // t1/t2 захвачены по значению, result == 6
}
```
