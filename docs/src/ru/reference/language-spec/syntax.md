# Спецификация синтаксиса

В данном документе определяется спецификация синтаксиса языка программирования YaoXiang, включая
лексическую структуру, синтаксические правила и приоритеты операторов.

---

## Глава 1: Лексическая структура

### 1.1 Файлы исходного кода

Файлы исходного кода YaoXiang должны использовать кодировку UTF-8. Исходные файлы обычно имеют
расширение `.yx`.

### 1.2 Классификация лексических единиц

| Категория      | Описание                                       | Примеры                   |
| -------------- | ---------------------------------------------- | ------------------------- |
| Идентификаторы | Начинаются с буквы или подчёркивания           | `x`, `_private`, `my_var` |
| Ключевые слова | Предопределённые зарезервированные слова языка | `Type`, `pub`, `use`      |
| Литералы       | Фиксированные значения                         | `42`, `"hello"`, `true`   |
| Операторы      | Символы операций                               | `+`, `-`, `*`, `/`        |
| Разделители    | Синтаксические разделители                     | `(`, `)`, `{`, `}`, `,`   |

### 1.3 Ключевые слова

YaoXiang определяет минимальный набор ключевых слов:

```
pub    use    spawn
ref    mut    if     else
else   match  while  for    return
break  continue as     in     unsafe
```

Эти ключевые слова имеют специальное значение в любом контексте и не могут использоваться в качестве
идентификаторов.

### 1.4 Зарезервированные слова

«Зарезервированные слова» в YaoXiang разделены на три уровня, распознаваемые парсером (parser) и
проверщиком типов (type checker) на разных этапах:

#### 1.4.1 Литеральные зарезервированные слова

Идентификаторы литералов, имеющие отдельные токены в парсере и не могущие использоваться как обычные
идентификаторы:

| Идентификатор | Принадлежность к типу | Описание                                                                                                                |
| ------------- | --------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `Type`        | —                     | Ключевое слово мета-типа                                                                                                |
| `true`        | Bool                  | Логическое значение «истина»                                                                                            |
| `false`       | Bool                  | Логическое значение «ложь»                                                                                              |
| `void`        | Void                  | Литерал Void (значение Unit). Строчный `void` является литералом значения; заглавный `Void` — именем типа (см. §1.4.3). |

#### 1.4.2 Выражения-конструкторы

Следующие конструкторы распознаются парсером в контексте сопоставления с образцом и в контексте
выражений:

| Конструктор | Принадлежность к типу | Описание                             |
| ----------- | --------------------- | ------------------------------------ |
| `some(T)`   | Option                | Конструктор варианта значения Option |
| `ok(T)`     | Result                | Успешный вариант Result              |
| `err(E)`    | Result                | Вариант ошибки Result                |

#### 1.4.3 Встроенные имена типов

Следующие имена типов предварительно зарегистрированы проверщиком типов и могут использоваться в
позиции типа без импорта. Парсер рассматривает их как обычные идентификаторы — **это не
зарезервированные слова, они могут быть затенены (shadow) локальными привязками (не
рекомендуется)**.

| Имя типа | Логическое соответствие | Описание                                                                                                                                          |
| -------- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Void`   | ⊤ (истина/Unit)         | Тип-произведение без полей, ровно один обитатель (литерал `void`, см. §1.4.1)                                                                     |
| `Never`  | ⊥ (ложь/пустой тип)     | Тип без вариантов, ноль обитателей. Никакое выражение не может породить значение `Never`. `Never <: T` выполняется для всех `T` (принцип взрыва). |
| `Int`    | —                       | Знаковое целое число                                                                                                                              |
| `Float`  | —                       | Число с плавающей точкой                                                                                                                          |
| `Bool`   | —                       | Логическое значение: `true` / `false`                                                                                                             |
| `Char`   | —                       | Символ Unicode                                                                                                                                    |
| `String` | —                       | Строка                                                                                                                                            |

### 1.5 Идентификаторы

Идентификаторы начинаются с буквы или подчёркивания, последующие символы могут быть буквами, цифрами
или подчёркиваниями. Идентификаторы чувствительны к регистру.

Специальные идентификаторы:

- `_` используется как заглушка, обозначающая игнорирование значения
- Идентификаторы, начинающиеся с подчёркивания, обозначают приватные члены

### 1.6 Литералы

#### 1.6.1 Целые числа

```
Decimal     ::= [0-9][0-9_]*
Octal       ::= 0o[0-7][0-7_]*
Hex         ::= 0x[0-9a-fA-F][0-9a-fA-F_]*
Binary      ::= 0b[01][01_]*
```

#### 1.6.2 Числа с плавающей точкой

```
Float       ::= [0-9][0-9_]* '.' [0-9][0-9_]* ([eE][+-]?[0-9][0-9_]*)?
```

#### 1.6.3 Строки

```
String      ::= '"' ([^"\\] | EscapeSequence)* '"'
Escape      ::= '\\' ([nrt'"\\] | UnicodeEscape)
Unicode     ::= 'u' '{' HexDigit+ '}'
```

#### 1.6.4 Коллекции

```
List        ::= '[' Expr (',' Expr)* ']'
Dict        ::= '{' String ':' Expr (',' String ':' Expr)* '}'
Array       ::= '[' Expr (',' Expr)* ']'   // При аннотации целевого типа как Array(T, N) литерал становится массивом фиксированной длины
```

> Для Set нет грамматики литерала, нет представления в runtime — тип множества в планах, при
> появлении требований будет дополнен по образцу Dict (std.set + HeapValue::Set). Куда попадают
> литералы List/Dict, определяется аннотацией контекстного типа: голый литерал и литерал с
> аннотацией `List(T)` попадают в растущий список; литерал с аннотацией `Array(T, N)`, действующей
> непосредственно на литерал, попадает в массив фиксированной длины. Неявное преобразование
> List→Array запрещено.
>
> Семантика литерала Array:
>
> - Количество элементов должно равняться N, иначе ошибка компиляции E1002; пустой литерал с
>   ненулевым N также отвергается
> - Тип каждого элемента должен быть совместим с T, иначе ошибка компиляции E1002
> - Грамматическая форма N: только целочисленный литерал (может быть отрицательным) или имя
>   константы; составные выражения (например, `2+1`) отвергаются на этапе парсинга
> - Когда N является символьной константой (например, параметр const функции `Array(Int, n)`),
>   проверка количества откладывается до этапа уточнения типов
> - Вложенные литералы массивов версии v1 (например, `Array(Array(Int,2),2) = [[1,2],[3,4]]`)
>   отвергаются на этапе компиляции; необходимо явное поэтапное конструирование; рекурсивная схема
>   определения оставлена для последующих версий

#### 1.6.5 Генераторы списков

```
ListComp    ::= '[' Expr 'for' Identifier 'in' Expr (',' Expr)* ('if' Expr)? ']'
```

> **Ужесточение поведения (запись миграции)**: грамматика переменной итерации изначально была
> `'for' Identifier 'in'`, но в старой реализации pattern проходил полный pratt-парсинг — после
> регистрации `'in'` как инфиксного оператора `x` поглощал бы `in items` как выражение membership.
> После исправления не-идентификаторный pattern сразу приводит к ошибке парсинга, вместо fallback на
> `_` в старой реализации (тихое проглатывание ошибки). Сфера влияния: ранее парсящаяся запись
> `[x for (a, b) in pairs]` теперь выдаёт ошибку — эта форма никогда не имела определённого
> поведения (переменная всегда была `_`), направление ужесточения правильное, без затрат на
> семантическую миграцию.

#### 1.6.6 Проверка принадлежности

```
Membership  ::= Expr 'in' Expr
```

> `in` — бинарный оператор отношения, возвращающий `Bool` — `true` при наличии, `false` при
> отсутствии, ошибки не возникает. Разделение семантики: `[]` — это утверждение существования и
> извлечение значения (ошибка при провале), `in` — это вопрос о наличии (отсутствие — нормальный
> `false`). Правый операнд: List / Array / Dict(набор ключей) / Tuple / String(подстрока) /
> Range(интервал). `in` — предикат Хоара первого класса, на этапе уточнения типов выступает базой
> доказуемых утверждений времени компиляции. (Set исключён из списка правых операндов — у Set нет
> представления в runtime, см. §1.6.4)

## Глава 2: Синтаксические правила

### 2.1 Классификация выражений

```
Expr        ::= Literal
              | Identifier
              | FnCall
              | MemberAccess
              | IndexAccess
              | UnaryOp
              | BinaryOp
              | TypeCast
              | RangeExpr
              | ErrorPropagate
              | RefExpr
              | IfExpr
              | MatchExpr
              | Block
              | Lambda
```

### 2.2 Приоритет операторов

| Приоритет | Операторы                   | Ассоциативность |
| --------- | --------------------------- | --------------- |
| 1         | `()` `[]` `.` `?`           | слева направо   |
| 2         | `as`                        | слева направо   |
| 3         | унарный префикс `!` `-` `+` | справа налево   |
| 4         | `*` `/` `%`                 | слева направо   |
| 5         | `+` `-`                     | слева направо   |
| 6         | `..`                        | слева направо   |
| 7         | `<<` `>>`                   | слева направо   |
| 8         | `&` `\|` `^`                | слева направо   |
| 9         | `==` `!=` `<` `>` `<=` `>=` | слева направо   |
| 10        | `and` `or`                  | слева направо   |
| 11        | `if...else`                 | справа налево   |
| 12        | `=` `+=` `-=` `*=` `/=`     | справа налево   |

> **Унарные префиксные операторы** (`!` `-` `+`) имеют сильное связывание: только ниже вызова и
> доступа к членам, выше всех бинарных операторов. Следовательно, `!a == b` ≡ `(!a) == b` (семантика
> в стиле Zig); `!` — чисто унарная операция, не участвующая в коротком замыкании потока управления,
> и ортогональна ключевым словам `and`/`or` (короткое замыкание) (авторитетное определение RFC-010).

> **Сила связывания Range**: `..` имеет силу связывания (6, 7) — левая 6 ниже сложения (7), правая 7
> поглощает сложение, но не поглощает `..` того же уровня. Сравнение до и после изменения:
>
> | Выражение    | До изменения (уровень 1, правоассоц.)                                                           | После изменения ((6,7), левоассоц.)                                             |
> | ------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
> | `x in 1..10` | `x in 1..10` (правый операнд `in` уровня 4, `..` уровня 1 не поглощает, фактически не парсится) | `x in (1..10)` — интервал целиком как правый операнд `in`                       |
> | `0..n+2`     | `(0..n)+2` (ловушка правоассоц.: верхняя граница поглощается, цикл `for` сразу E3004)           | `0..(n+2)` — верхняя граница — арифметическое выражение                         |
> | `a == b..c`  | `a == (b..c)` (уровень `..` 1 < уровня `==` 3, естественно целиком)                             | `a == (b..c)` — **семантика не изменилась**, `..` всё ещё выше уровня сравнения |
> | `1..2*3`     | `(1..2)*3`                                                                                      | `1..(2*3)` — верхняя граница — арифметическое выражение                         |
> | `a..b..c`    | `a..(b..c)` (правоассоц. цепочка, бессмысленный Range в Range)                                  | `(a..b)..c` — **форма со шагом** (`c` — шаг)                                    |
>
> Чистый эффект: составная верхняя граница `for i in 0..n+2` превращается из «успешный парсинг, но
> E3004» в «сразу работает»; `x in 1..10` превращается из «не парсится» в «проверка интервала»;
> `a..b..c` превращается из «бессмысленной вложенности» в «компонент шага». Уровень 6 располагается
> между `+` (уровень 5) и `<<` (уровень 7), математическая конвенция: интервал — сильно связывающая
> конструкция, верхняя граница естественно является полным арифметическим выражением.

### 2.3 Вызов функции

```
FnCall      ::= Expr '(' ArgList? ')'
ArgList     ::= Expr (',' Expr)* (',' NamedArg)* | NamedArg (',' NamedArg)*
NamedArg    ::= Identifier ':' Expr
```

### 2.4 Доступ к членам

```
MemberAccess::= Expr '.' Identifier
```

### 2.5 Доступ по индексу

```
IndexAccess ::= Expr '[' Expr ']'
```

### 2.6 Преобразование типа

```
TypeCast    ::= Expr 'as' TypeExpr
```

### 2.7 Условное выражение

```
IfExpr      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 2.8 Сопоставление с образцом

```
MatchExpr   ::= 'match' Expr '{' MatchArm+ '}'
MatchArm    ::= Pattern ('|' Pattern)* ('if' Expr)? '=>' Expr ','
Pattern     ::= Literal
              | Identifier
              | Wildcard
              | StructPattern
              | TuplePattern
              | EnumPattern
              | OrPattern
```

### 2.9 Блочное выражение

```
Block       ::= '{' Stmt* Expr? '}'
```

> **Правила завершения операторов**: разделение между Stmt и поведение переноса строк (явное
> разделение `;`, завершение переносом строки, исключения для продолжения строки, никогда не
> объединять `(`/`[` в начале строки) определяется
> [RFC-038](../design/rfc/draft/038-statement-termination.md).

**Единая семантика**: семантика `return` для всех блоков `{}` согласована:

| Тип блока    | Семантика return            | Возврат по умолчанию |
| ------------ | --------------------------- | -------------------- |
| Обычный `{}` | Возвращает значение         | Void                 |
| `unsafe {}`  | Возвращает определение типа | Void                 |
| `spawn {}`   | Возвращает результат        | Void                 |

**Основные принципы**:

- `return` в `{}` всегда возвращает содержимое во внешнюю область видимости
- При отсутствии `return` по умолчанию возвращается `Void`
- Форма выражения `= expr` возвращает значение напрямую

```yaoxiang
// Обычный блок {}: return возвращает значение
result = {
    x = compute()
    return x  // возвращает значение во внешнюю область видимости
}

// Блок unsafe {}: return возвращает определение типа
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void
    }
    return SqliteDb  // возвращает определение типа во внешнюю область видимости
}

// Блок spawn {}: return возвращает результат
(a, b) = spawn {
    result1 = fetch("url1"),
    result2 = fetch("url2")
    return (result1, result2)  // возвращает результат во внешнюю область видимости
}
```

### 2.10 Лямбда-выражение

```
Lambda      ::= '(' ParamList? ')' '=>' Expr
            |  '(' ParamList? ')' '=>' Block
```

### 2.11 Оператор распространения ошибки

```
ErrorPropagate ::= Expr '?'
```

Оператор `?` является постфиксным, с приоритетом, аналогичным `.`. Для типа `Result(T, E)`:

- При `Ok(v)` извлекает значение `v` и продолжает выполнение
- При `Err(e)` распространяет ошибку вверх (`return Err(e)`)

```yaoxiang
process: (data: Data) -> Result(Data, Error) = {
    validated = validate(data)?     // при успехе извлекает значение, при неудаче распространяет вверх
    transform(validated)
}
```

### 2.12 Выражение диапазона

```
RangeExpr   ::= Expr '..' Expr ('..' Expr)?
```

`..` создаёт значение диапазона (Range — значение первого класса, не синтаксический сахар).

```yaoxiang
for i in 0..10 { print(i) }
slice = array[0..5]

// Range — это значение: связывание, передача, проверка принадлежности
r = 1..10
assert.assert(5 in r, "membership")
for i in r { print(i) }

// Форма со шагом (третий компонент, по умолчанию 1)
for i in 0..10..2 { print(i) }  // 0, 2, 4, 6, 8
for i in 10..0..(-2) { print(i) }  // 10, 8, 6, 4, 2
```

> **Семантика шага**: в `a..b..c` `c` — это шаг. Литерал `c = 0` отвергается на этапе компиляции;
> динамический `c` проверяется в runtime (семейство E6001; после внедрения системы ошибок будет
> повышен до Result). `c < 0` допустимо, направление интервала меняется в зависимости от знака
> (`10..0..(-2)` — убывание).

### 2.13 Выражение ref

```
RefExpr     ::= 'ref' Expr
```

`ref` создаёт разделяемое владение. Компилятор автоматически выбирает Rc (одна задача) или Arc
(между задачами), пользователю не нужно беспокоиться о деталях реализации.

```yaoxiang
data = ref heavy_data
spawn { use(data) }   // между задачами: компилятор автоматически выберет Arc
```

### 2.14 Выражение unsafe

```
UnsafeExpr  ::= 'unsafe' Block
```

Блок `unsafe` используется для определения непрозрачных типов и операций с сырыми указателями.
Используйте `return`, чтобы вернуть определение типа во внешнюю область видимости.

**Семантика**:

- В `unsafe {}` можно определять типы и оперировать сырыми указателями
- Возвращаемый тип доступен за пределами `unsafe {}`
- Доступ к полям типа требует права unsafe

```yaoxiang
// Определение непрозрачного типа в блоке unsafe
SqliteDb = unsafe {
    SqliteDb: Type = {
        handle: *Void  // сырой указатель
    }
    return SqliteDb
}

// SqliteDb доступен за пределами блока unsafe
db = sqlite3_open("test.db")
```

### 2.15 Области видимости

**Основные правила**:

- Каждый блок `{}` создаёт область видимости
- Внутренняя область видимости может обращаться к переменным внешней области видимости
- Внешняя область видимости не может обращаться к переменным внутренней области видимости
- Объявление переменных следует принципу «приоритет присваивания»

```yaoxiang
// Блочная область видимости
{
    x = 10
    // x видна в данной области видимости
}
// x не видна за пределами данной области видимости

// Область видимости функции
add: (a: Int, b: Int) -> Int = {
    result = a + b
    return result
}
// result не виден за пределами функции
```

**Объявление и затенение переменных**:

- `x = value`: поиск x идёт по цепочке областей видимости наружу; если найдено — присваивание, если
  не найдено — новое объявление
- `mut x = value`: явное новое объявление изменяемой переменной, запрещено совпадение имён с внешней
  областью видимости
- В одной области видимости любое имя может быть объявлено только один раз

> **Подробное определение**: полные правила областей видимости, механизм объявления и затенения
> переменных см. в [Спецификации модульной системы](./modules.md#第四章作用域).

## Глава 3: Операторы

### 3.1 Классификация операторов

```
Stmt        ::= LetStmt
              | ExprStmt
              | ReturnStmt
              | BreakStmt
              | ContinueStmt
              | IfStmt
              | MatchStmt
              | WhileStmt
              | ForStmt
              | SpawnStmt
```

### 3.2 Объявление переменной

```
LetStmt     ::= ('mut')? Identifier (':' TypeExpr)? '=' Expr
```

### 3.3 Оператор return

```
ReturnStmt  ::= 'return' Expr?
```

**Семантика**: `return` используется для возврата значения из блока кода. При отсутствии `return`
блок по умолчанию возвращает `Void`.

### 3.4 Оператор break

```
BreakStmt   ::= 'break'
```

**Семантика**: немедленно завершает самый внутренний цикл `while`/`for`, поток управления переходит
к коду после тела цикла.

- **Выход только из ближайшего уровня**: `break` всегда действует на самый внутренний содержащий его
  цикл. Для выхода из нескольких уровней вложенного цикла выделите внутренний цикл в функцию и
  используйте `return`, либо примените флаг (break/continue без метки; если в будущем будут введены
  метки циклов, их синтаксис будет определён через RFC в соответствии со стороной объявления цикла,
  и решение будет принято совместно с дизайном многоточечного выхода из доказательного конвейера)
- **Только внутри тела цикла**: `break` может появляться только внутри тела цикла `while`/`for`
  (включая вложенные блоки/if/match внутри тела), появление вне цикла вызывает ошибку компиляции
  (E1102 `'break' outside of a loop`)
- **Не влияет на доказательство завершаемости**: цикл `while` по-прежнему должен быть доказуемо
  завершаемым (метрика decreases); `break` не участвует в аргументации завершаемости,
  `while true { break }` не будет принят
- **Семантика заимствования**: ребро потока управления break участвует в структурном разрезании
  анализа живости обратным BFS из RFC-009a (вырванные итерации не участвуют в выводе живости
  обратных рёбер)

```yaoxiang
mut i = 0
while i < 10 {
    i = i + 1
    if i == 3 {
        break              // поток управления переходит после цикла, i == 3
    }
}

// Вложенные циклы: break выходит только из внутреннего
while j < 3 {
    while k < 10 {
        if k == 2 { break }    // завершает только внутренний цикл
    }
    j = j + 1                  // каждая итерация внешнего цикла дойдёт сюда
}
```

### 3.5 Оператор continue

```
ContinueStmt::= 'continue'
```

**Семантика**: пропускает оставшиеся операторы текущей итерации и сразу переходит к следующему
раунду самого внутреннего содержащего его цикла — для `while` — перевычисление условия, для `for` —
взятие следующего элемента.

- **Только ближайший уровень**: аналогично `break`, без метки
- **Только внутри тела цикла**: появление вне цикла вызывает ошибку компиляции (E1102)

```yaoxiang
mut sum = 0
mut n = 0
while n < 5 {
    n = n + 1
    if n == 3 {
        continue           // пропускает накопление ниже, n == 3 не учитывается
    }
    sum = sum + n
}
// sum == 12 (1 + 2 + 4 + 5)
```

### 3.6 Оператор if

```
IfStmt      ::= 'if' Expr Block ('else' 'if' Expr Block)* ('else' Block)?
```

### 3.7 Оператор match

```
MatchStmt   ::= 'match' Expr '{' MatchArm+ '}'
```

### 3.8 Оператор while

```
WhileStmt   ::= 'while' Expr Block
```

### 3.9 Оператор for

```
ForStmt     ::= 'for' 'mut'? Identifier 'in' Expr Block
```

#### 3.9.1 Семантика: каждая итерация — это связывание нового значения

Семантика цикла for в YaoXiang отличается от традиционных языков: **каждая итерация — это связывание
нового значения, а не изменение одной и той же переменной**.

```yaoxiang
// Пример: for i in 1..5
for i in 1..5 {
    print(i)
}
```

**Процесс выполнения**:

| Итерация   | Поведение переменной цикла                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------------- |
| 1-я        | Создаётся новая привязка `i = 1`, тело цикла выполняется, печатает 1                                  |
| 2-я        | Создаётся новая привязка `i = 2` (предыдущая привязка уничтожена), тело цикла выполняется, печатает 2 |
| 3-я        | Создаётся новая привязка `i = 3`, тело цикла выполняется, печатает 3                                  |
| 4-я        | Создаётся новая привязка `i = 4`, тело цикла выполняется, печатает 4                                  |
| Завершение | Тело цикла заканчивается, привязка уничтожается                                                       |

**Ключевой момент**: после каждой итерации созданная в этой итерации привязка уничтожается.
Следующая итерация — это полностью новая привязка, никак не связанная с привязкой предыдущей
итерации.

#### 3.9.2 Различие между for и for mut

| Синтаксис           | Изменяемость переменной цикла | Описание                              |
| ------------------- | ----------------------------- | ------------------------------------- |
| `for i in 1..5`     | Неизменяемая                  | Тело цикла не может изменить привязку |
| `for mut i in 1..5` | Изменяемая                    | Тело цикла может изменить привязку    |

```yaoxiang
// Допустимо: каждая итерация связывает новое значение, изменение не требуется
for i in 1..5 {
    print(i)  // чтение значения i
}

// Ошибка: неизменяемая привязка, нельзя изменить
for i in 1..5 {
    i = i + 1  // ошибка: нельзя изменить неизменяемую привязку
}

// Допустимо: использование for mut разрешает изменение привязки
for mut i in 1..5 {
    i = i + 1  // изменение разрешено
}
```

#### 3.9.3 Проверка затенения

YaoXiang запрещает затенение переменных. Переменная цикла for не может иметь то же имя, что и
переменная во внешней области видимости:

```yaoxiang
// Ошибка: i уже объявлена снаружи
i = 10
for i in 1..5 {
    print(i)
}

// Правильно: использовать разные имена переменных
i = 10
for j in 1..5 {
    print(j)
}
```

Это правило применяется ко всем блокам кода, см. подробности в
[4.3 Правила затенения](./modules.md#43-遮蔽规则).

#### 3.9.4 Сравнение с другими языками

| Язык     | Семантика переменной цикла for                                       |
| -------- | -------------------------------------------------------------------- |
| YaoXiang | Каждая итерация связывает новое значение                             |
| Rust     | Изменение одной и той же переменной (требуется mut)                  |
| Python   | Изменение одной и той же переменной (без mut)                        |
| C/C++    | Изменение одной и той же переменной (требуется указатель или ссылка) |

**Обоснование дизайна**: YaoXiang использует семантику связывания по следующим причинам:

1. **Более естественная семантика** В естественном языке «для каждого элемента x в коллекции»
   означает, что каждый x — это отдельная сущность. `for i in 1..5` в YaoXiang читается как «для
   каждого i от 1 до 5», где i каждой итерации — это полностью новая привязка, что согласуется с
   человеческой интуицией.

2. **Предотвращение случайных изменений** Семантика неизменяемой привязки по умолчанию означает, что
   в теле цикла невозможно случайно изменить переменную цикла. Не нужно беспокоиться о том, что
   где-то в сложном теле цикла случайно написано `i = ...`, что приводит к трудно отслеживаемым
   ошибкам.

3. **Высокопроизводительные решения под рукой** Когда действительно необходимо переиспользовать
   переменную между итерациями (например, аккумулятор, кэш), достаточно использовать объявление
   `for mut` для переключения в режим изменяемой привязки. Это яснее, чем неявное разделение
   состояния — намерение выражается явно через синтаксис, а не скрыто в поведении runtime.

### 3.10 Оператор spawn

```
SpawnBlock  ::= '(' Pattern (',' Pattern)* ')' '=' 'spawn' '{' Expr (',' Expr)* '}'
SpawnFor    ::= Identifier '=' 'spawn' 'for' 'mut'? Identifier 'in' Expr '{' Expr '}'
SpawnStmt   ::= SpawnBlock | SpawnFor
```

**Блок spawn**: явно объявляет область параллелизма, выражения внутри блока выполняются параллельно.

```yaoxiang
(result_a, result_b) = spawn {
    parse(fetch("url1")),
    parse(fetch("url2"))
}
```

**Цикл spawn**: параллельный по данным цикл.

```yaoxiang
results = spawn for item in items {
    process(item)
}
```

**Блок spawn захватывает переменные внешней области видимости** (RFC-024 §2.3, семантика захвата
значений):

- Обращение тела блока к переменным внешней области видимости = **захват значения Move**: значение
  копируется в замыкание в точке создания spawn, тело блока читает его через env (LoadUpvalue)
- **Примитивы** (Int/Float/Bool/Char) копируются по значению, внешняя переменная не затрагивается
- **Типы-дескрипторы** (Struct/String/List и т.д.) копируется дескриптор, разделяя базовый объект;
  во встроенном runtime (по умолчанию) один поток — одна куча, дескриптор действителен
- Для разделения между несколькими задачами требуется явный `ref` (§2.13, компилятор автоматически
  выберет Rc/Arc)
- `return` в блоке, ссылающийся на внешние переменные, также выполняет их захват

```yaoxiang
t1 = 1 + 1
t2 = 2 + 2
result = spawn {
    return t1 + t2    // t1/t2 захвачены по значению, result == 6
}
```
