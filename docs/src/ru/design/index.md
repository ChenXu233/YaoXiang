# Дизайн-документ YaoXiang

> Дао рождает единое, единое рождает двойственное, двойственное рождает тройственное, тройственное
> рождает все существа.

Этот каталог содержит проектные решения, предложения и обсуждения по языку программирования
YaoXiang.

## Основные концепции дизайна

| Концепция                  | Описание                                                                 |
| -------------------------- | ------------------------------------------------------------------------ |
| **Всё есть тип**           | Значения, функции, модули — всё это типы; типы — граждане первого класса |
| **Естественный синтаксис** | Читаемость как в Python, близость к естественному языку                  |
| **Модель владения**        | Абстракции с нулевой стоимостью, без GC, высокая производительность      |
| **Модель spawn**           | Синхронный синтаксис, асинхронная сущность, автоматический параллелизм   |
| **AI-дружественность**     | Строгая структурированность, ясный AST                                   |

## Участие в обсуждении дизайна

### Жизненный цикл RFC

Предложения RFC имеют 5 состояний:

| Состояние       | Значение                           |
| --------------- | ---------------------------------- |
| Черновик        | Работа в процессе                  |
| На рассмотрении | Открытое обсуждение                |
| Принят          | Дизайн одобрен                     |
| Устарел         | Был принят, заменён новым дизайном |
| Отклонён        | Не прошёл                          |

Полный жизненный цикл:

```
Черновик → На рассмотрении → Принят → Устарел (заменён)
                                ↓
                          Отклонён (не прошёл)
```

### Процесс подачи предложения

```
1. Составить предложение (используя шаблон RFC)
   → Поместить в rfc/draft/

2. Подать на рассмотрение
   → Переместить в rfc/review/, открыть общественное обсуждение

3. Оценка основной командой
   → Принять → Переместить в rfc/accepted/
   → Отклонить → Переместить в rfc/rejected/

4. Дальнейшее сопровождение
   → Заменён → Переместить в rfc/deprecated/
```

### Принципы дизайна

- **Чёткие границы**: каждое проектное решение должно иметь ясную область применения
- **Практичность прежде всего**: решать реальные проблемы, а не воображаемые угрозы
- **Видимое пользователю поведение неизменно**: Never break userspace

## Ключевые проектные решения

### 1. Система типов

- **Унифицированный синтаксис типов**: упразднение `enum`, `struct`, `union`, унификация через
  `Name: Type = {...}`
- **Конструктор есть тип**: устранение пропасти между «типом» и «значением»
- **Поддержка generics**: мономорфизация на этапе компиляции, нулевые накладные расходы на этапе
  выполнения

### 2. Модель spawn

```yaoxiang
// Модель spawn: по умолчанию последовательное выполнение, spawn вводит параллелизм потоков данных

// Default sequential execution
compute: (Int) -> Int = (n) => {
    a = heavy_calc(1)
    b = heavy_calc(2)  // последовательное выполнение, ожидание завершения a
    c = heavy_calc(3)  // последовательное выполнение, ожидание завершения b
    a + b + c
}

// spawn block introduces dataflow parallelism
process: () -> Void = () => {
    spawn {
        users = fetch_users()   // параллельно
        posts = fetch_posts()   // параллельно
    }
    // Вызывающая сторона синхронно блокируется в ожидании результата
    render(users, posts)
}
```

### 3. Обработка ошибок

```yaoxiang
Result: (T: Type, E: Type) -> Type = { ok: (T) -> Result(T, E), err: (E) -> Result(T, E) }

process: () -> Result(Data, Error) = {
    data = fetch_data()?      // оператор ? прозрачно распространяет ошибку
    transformed = transform(data)?
    save(transformed)?
}
```
