# YaoXiang 设计文档

> 道生一，一生二，二生三，三生万物。

本目录包含 YaoXiang 编程语言的设计决策、提案和讨论。

## 核心设计理念

| 理念               | 描述                                       |
| ------------------ | ------------------------------------------ |
| **Всё является типом** | Значения, функции, модули — всё типы; типы — объекты первого класса |
| **Естественный синтаксис** | Читаемость как у Python, близость к естественному языку |
| **Модель владения** | Нулевая стоимость абстракции, без GC, высокая производительность |
| **Модель спавна** | Синхронный синтаксис, асинхронная суть, автоматический параллелизм |
| **Дружественность к AI** | Строгая структурированность, чёткий AST   |

## Участие в обсуждении дизайна

### Жизненный цикл RFC

У RFC-предложения 5 статусов:

| Статус       | Значение                                     |
| ------------ | -------------------------------------------- |
| Черновик     | Работа в процессе                            |
| На рассмотрении | Открыто для обсуждения                    |
| Принято      | Дизайн одобрен                               |
| Устарело      | Было принято, заменено новым дизайном       |
| Отклонено    | Не одобрено                                  |

Полный жизненный цикл:

```
Черновик → На рассмотрении → Принято → Устарело (заменено)
                        ↓
                  Отклонено (не одобрено)
```

### Процесс подачи предложений

```
1. Составление черновика (по шаблону RFC)
   → Помещается в rfc/draft/

2. Подача на рассмотрение
   → Перемещается в rfc/review/, открыто обсуждение сообщества

3. Рассмотрение основной командой
   → Принятие → Перемещается в rfc/accepted/
   → Отклонение → Перемещается в rfc/rejected/

4. Последующее сопровождение
   → Замена → Перемещается в rfc/deprecated/
```

### Принципы проектирования

- **Чёткие границы**: Каждое проектное решение должно иметь чёткую область применения
- **Практичность прежде всего**: Решайте реальные проблемы, а не воображаемые угрозы
- **Обратная совместимость поведения для пользователей**: Never break userspace

## Ключевые проектные решения

### 1. Система типов

- **Унифицированный синтаксис типов**: Убраны `enum`, `struct`, `union`, унифицировано через `Name: Type = {...}`
- **Конструкторы являются типами**: Устранён разрыв между «типами» и «значениями»
- **Поддержка обобщений**: Мономорфизация на этапе компиляции, нулевые накладные расходы во время выполнения

### 2. Модель спавна

```yaoxiang
// Модель спавна: последовательное выполнение по умолчанию, спавн вводит потоковый параллелизм данных

// Последовательное выполнение по умолчанию
compute: (Int) -> Int = (n) => {
    a = heavy_calc(1)
    b = heavy_calc(2)  // Последовательно, ожидание a
    c = heavy_calc(3)  // Последовательно, ожидание b
    a + b + c
}

// Спавн-блок вводит потоковый параллелизм данных
process: () -> Void = () => {
    spawn {
        users = fetch_users()   // Параллельно
        posts = fetch_posts()   // Параллельно
    }
    // Синхронная блокировка вызывающего до получения результатов
    render(users, posts)
}
```

### 3. Обработка ошибок

```yaoxiang
Result: (T: Type, E: Type) -> Type = { ok: (T) -> Result(T, E), err: (E) -> Result(T, E) }

process: () -> Result(Data, Error) = {
    data = fetch_data()?      // Оператор ? прозрачно распространяет
    transformed = transform(data)?
    save(transformed)?
}
```
