## Жизненный цикл RFC

```
Черновик → На рассмотрении → Принят → Устарел (заменён)
                          ↓
                       Отклонён (не прошёл)
```

### Описание статусов

| Статус              | Расположение      | Описание                                                                 |
| ------------------- | ----------------- | ------------------------------------------------------------------------ |
| **Черновик**        | `rfc/draft/`      | Черновик автора, ожидает отправки на рассмотрение                        |
| **На рассмотрении** | `rfc/review/`     | Открыто для обсуждения сообществом и обратной связи                      |
| **Принят**          | `rfc/accepted/`   | Становится официальным проектным документом, переходит в фазу реализации |
| **Устарел**         | `rfc/deprecated/` | Был принят, заменён новым дизайном                                       |
| **Отклонён**        | `rfc/rejected/`   | Документ RFC, который был отклонён                                       |

## Правила редактирования документации

**Документы RFC могут содержать только корректную информацию.** При изменении дизайна просто
изменяйте оригинальный текст так, чтобы он выражал текущую корректную семантику; **недопустимо
сохранять неверное содержимое, а затем добавлять блок «исправлений» для его корректировки**.

Сохранение «оригинала + исправления» — наихудший способ написания: читатель, дойдя до середины,
обнаруживает, что всё предыдущее аннулировано, затраты на его чтение потрачены впустую, и возникает
риск ошибочного цитирования отменённых абзацев как текущей семантики. Блок исправлений выглядит
осторожным, но на самом деле перекладывает затраты на упорядочивание на читателя.

### Правильный подход

| Ситуация                                                    | Подход                                                                                                                                           |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Реализация не соответствует оригиналу, оригинал опровергнут | Непосредственно перепишите абзац в правильное содержимое, удалите исходную формулировку                                                          |
| Пример кода больше не запускается                           | Непосредственно измените его в работоспособную форму, не сохраняйте старый пример                                                                |
| Необходимо дать читателю знать, «как было раньше»           | Сохраняйте ошибочное содержимое только при **намеренном сравнении ошибок** и сразу помечайте «этот способ написания неверен» с указанием причины |
| Необходимо отследить эволюцию дизайна                       | Записывайте в сообщениях коммитов Git или в issue, не в основной текст RFC                                                                       |

### Исключения

Допускается сохранять следующую неверную информацию:

- **Специально созданные учебные сравнения**: явно помечены как сравнение правильного и
  неправильного, при этом неправильная сторона сопровождается объяснением «почему неверно»
- **Устаревшие RFC** (`rfc/deprecated/`): служат в качестве исторической записи, но должны быть
  помечены тем, кем они были заменены

### Вспомогательные средства

- Поля `status` / `updated` в верхней части RFC отражают время последней редакции, нет необходимости
  писать в основном тексте «что было отредактировано в этот раз»
- Статус реализации выражается с помощью таблицы ✅ / ❌, избегайте вплетения повествования о
  статусе в основной текст
- Полная история редактирования просматривается с помощью `git log -- <файл>`

## Отправка RFC

1. Прочтите [RFC_TEMPLATE.md](RFC_TEMPLATE.md), чтобы понять требования к формату
2. Обратитесь к [EXAMPLE_full_feature_proposal.md](EXAMPLE_full_feature_proposal.md), чтобы изучить
   способ написания
3. Создайте новый файл с именем `номер-описательное-название.md`
4. Поместите файл в каталог `docs/reference/rfc/draft/`
5. Обновите этот файл индекса, добавив новую запись RFC
6. Отправьте PR, чтобы войти в процесс рассмотрения
