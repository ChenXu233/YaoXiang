## Жизненный цикл RFC

```
Черновик → На рассмотрении → Принято → Устарело (заменено)
                            ↓
                         Отклонено (не прошло)
```

### Описание статусов

| Статус              | Расположение      | Описание                                                                   |
| ------------------- | ----------------- | -------------------------------------------------------------------------- |
| **Черновик**        | `rfc/draft/`      | Черновик автора, ожидает подачи на рассмотрение                            |
| **На рассмотрении** | `rfc/review/`     | Открыто для обсуждения сообществом и обратной связи                        |
| **Принято**         | `rfc/accepted/`   | Становится официальным проектным документом, переходит в стадию реализации |
| **Устарело**        | `rfc/deprecated/` | Было принято, но заменено новым дизайном                                   |
| **Отклонено**       | `rfc/rejected/`   | Отклонённый документ RFC                                                   |

## Правила редактирования документов

**Документы RFC должны содержать только корректную информацию.** При изменении дизайна следует
напрямую изменять исходный текст, чтобы он отражал текущую корректную семантику; **нельзя сохранять
ошибочное содержимое и добавлять блок «Опечатки» для исправления**.

Сохранение «оригинала + опечаток» — наихудший вариант: читатель, дойдя до определённого места,
обнаруживает, что всё предыдущее стало недействительным, затраты на чтение оказываются напрасными, и
возникает риск принять отменённые абзацы за действующую семантику. Блок опечаток выглядит
осторожным, но на деле перекладывает затраты на упорядочивание на читателя.

### Правильный подход

| Ситуация                                                        | Действие                                                                                                                                     |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Реализация не соответствует оригиналу, оригинал был пересмотрен | Напрямую перепишите абзац в корректное содержимое, удалив прежнюю формулировку                                                               |
| Пример кода больше не запускается                               | Напрямую измените его на работающий вариант, не сохраняя старый пример                                                                       |
| Необходимо дать читателю понять, «как было раньше»              | Сохраняйте ошибочное содержимое только при **намеренном сравнении ошибок**, и сразу рядом указывайте «этот вариант записи неверен» и причину |
| Необходимо отследить эволюцию дизайна                           | Фиксируйте в сообщениях коммитов Git или в issue, не включайте в основной текст RFC                                                          |

### Исключения

Допускается сохранять следующую ошибочную информацию:

- **Намеренное сравнительное обучение**: чётко обозначено как сравнение правильного и неправильного,
  при этом ошибочная сторона сопровождается объяснением «почему это неверно»
- **Устаревшие RFC** (`rfc/deprecated/`): как историческая запись, но с указанием, чем они были
  заменены

### Вспомогательные средства

- Поля `status` / `updated` в верхней части RFC отражают время последней редакции, не нужно писать в
  основном тексте «что было изменено в этой редакции»
- Статус реализации выражайте с помощью таблиц с ✅ / ❌, избегая вплетения описаний статуса в
  основной текст
- Полную историю редакций можно просмотреть с помощью `git log -- <файл>`

## Подача RFC

1. Прочитайте [RFC_TEMPLATE.md](RFC_TEMPLATE.md), чтобы узнать требования к формату
2. Обратитесь к [EXAMPLE_full_feature_proposal.md](EXAMPLE_full_feature_proposal.md), чтобы изучить
   стиль написания
3. Создайте новый файл с именем `номер-описательное-название.md`
4. Поместите файл в каталог `docs/reference/rfc/draft/`
5. Обновите этот индексный файл, добавив новую запись RFC
6. Отправьте PR для перехода к процессу рассмотрения
