## Жизненный цикл RFC

```
Черновик → На рассмотрении → Принят → Устарел (заменён)
                                  ↓
                              Отклонён (не прошёл)
```

### Описание статусов

| Статус              | Расположение      | Описание                                               |
| ------------------- | ----------------- | ------------------------------------------------------ |
| **Черновик**        | `rfc/draft/`      | Черновик автора, ожидает отправки на рассмотрение      |
| **На рассмотрении** | `rfc/review/`     | Открытое обсуждение и обратная связь от сообщества     |
| **Принят**          | `rfc/accepted/`   | Стал официальным проектным документом, этап реализации |
| **Устарел**         | `rfc/deprecated/` | Был принят, но заменён новым дизайном                  |
| **Отклонён**        | `rfc/rejected/`   | Документы RFC, которые были отклонены                  |

## Правила редактирования документов

**Документ RFC должен содержать только корректную информацию.** При изменении дизайна редактируйте
исходный текст напрямую, чтобы он отражал текущую корректную семантику; **запрещается сохранять
ошибочное содержимое и добавлять блок «Опечатки» для исправления**.

Сохранение «оригинала + опечаток» — наихудший подход: читатель, дойдя до определённого места,
обнаруживает, что всё, что было прочитано ранее, уже недействительно; затраты на прочтение тратятся
впустую, и существует риск ошибочно сослаться на отменённые абзацы как на текущую семантику. Блок
опечаток выглядит осторожным, но на деле перекладывает затраты на упорядочивание на читателя.

### Правильный подход

| Ситуация                                                               | Действие                                                                                                                                      |
| ---------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Реализация не соответствует исходному тексту, исходный текст отвергнут | Переписать абзац напрямую с корректным содержимым, удалив исходную формулировку                                                               |
| Пример кода больше не запускается                                      | Изменить его в форму, которая запускается; не сохранять старый пример                                                                         |
| Необходимо показать читателю, «как было раньше»                        | Сохранять ошибочное содержимое только при **намеренном сравнении ошибок** и сразу помечать «этот вариант записан неверно» с указанием причины |
| Необходимо отследить эволюцию дизайна                                  | Писать в сообщениях Git-коммитов или в issue, но не в основной текст RFC                                                                      |

### Исключения

Допускается сохранение следующей ошибочной информации:

- **Намеренные обучающие сравнения**: чётко обозначенные как «сравнение правильного и
  неправильного», при этом неправильная сторона сразу сопровождается объяснением «почему это
  неверно»
- **Устаревшие RFC** (`rfc/deprecated/`): как историческая запись, но с указанием, кем заменены

### Вспомогательные средства

- Поля `status` / `updated` в начале RFC отражают время последней правки; нет необходимости писать в
  тексте «что было изменено в этой редакции»
- Статус реализации выражается таблицей с ✅ / ❌, чтобы избежать вкраплений описания статуса в
  основной текст
- Полную историю изменений можно посмотреть с помощью `git log -- <файл>`

## Отправка RFC

1. Прочтите [RFC_TEMPLATE.md](RFC_TEMPLATE.md), чтобы узнать требования к формату
2. Обратитесь к [EXAMPLE_full_feature_proposal.md](EXAMPLE_full_feature_proposal.md) для изучения
   стиля написания
3. Создайте новый файл с именем `номер-описательный-заголовок.md`
4. Поместите файл в каталог `docs/reference/rfc/draft/`
5. Обновите этот файл индекса, добавив новую запись RFC
6. Отправьте PR для перехода к процессу рассмотрения
