# RFC-023: Модель захвата замыканий

> **Ссылки**:
>
> - [RFC-007: Унификация синтаксиса функций](./accepted/007-function-syntax-unification.md)
> - [RFC-009: Модель владения v9](./accepted/009-ownership-model.md)
> - [RFC-011: Проектирование системы дженериков](./accepted/011-generic-type-system.md) — Раздел
>   2.4: Встроенные marker trait Dup/Clone

## Резюме

Настоящий RFC определяет **модель захвата замыканий** языка YaoXiang. Компилятор автоматически
анализирует внешние переменные, на которые ссылается тело замыкания, и на основе типа переменной
(Dup/не Dup) и факта побега замыкания автоматически выбирает способ захвата — Dup-типы копируются
напрямую, не-Dup без побега заимствуются, не-Dup с побегом — перемещаются (Move). Пользователь не
указывает аннотации; правила разделяются с автоматическим выбором заимствования при вызове функций.

## Мотивация

### Зачем это нужно?

В настоящее время захват замыканий — это **пустая реализация** — поле `env` инструкции `MakeClosure`
всегда пустое, лямбда не может ссылаться ни на какие внешние переменные. Система токенов
заимствования требует, чтобы замыкание могло захватывать токены `&T` (копирование с нулевой
стоимостью) — это ключевой сценарий использования.

### Текущая проблема

```yaoxiang
# Этот код в данный момент не компилируется — лямбда не может ссылаться на threshold
filter_by: (items: List(Point), threshold: &Float) -> List(Point) = {
    items.filter(|p| p.x > threshold)  # ❌ threshold не может быть захвачен
}
```

## Предложение

### Основной дизайн

Захват замыкания определяется компилятором полностью автоматически. Правила **полностью совпадают**
с автоматическим выбором заимствования при вызове функций:

```
Тип переменной    Побег замыкания    Способ захвата
─────────────────────────────────────────────────────
Dup               любой              Копирование (побитовое или с нулевой стоимостью)
не Dup            без побега         Автоматическое заимствование (&T или &mut T)
не Dup            с побегом          Move (передача владения)
```

**Определение побега**:

```
spawn { || ... }           → с побегом
return || ...              → с побегом
let x = || ... ;  x сохранён в поле → с побегом
items.filter(|p| ...)      → без побега (синхронный вызов функции высшего порядка)
||.method()                → без побега (вызов на месте)
```

Консервативный принцип: когда невозможно определить — обрабатывается как побег.

### Примеры

```yaoxiang
# 1. Токен Dup — прямое копирование (нулевая стоимость)
filter_by: (items: List(Point), threshold: &Float) -> List(Point) = {
    # threshold: &Float → Dup → компилятор копирует токен в замыкание
    # Токен нулевого размера, нулевые накладные расходы в runtime
    items.filter(|p| p.x > threshold)
}

# 2. Не Dup + без побега — автоматическое заимствование
process: (buf: Buffer) -> Void = {
    # buf не Dup, filter без побега → автоматически создаётся токен &Buffer
    transform(|b| b.read())
    # После возврата замыкания токен освобождается, buf снова доступен
}

# 3. Побег замыкания — Move
spawn_worker: (data: Data) -> Void = {
    # data не Dup, spawn → с побегом → Move
    spawn { use(data) }
}

# 4. Смешанный захват
complex: (items: List(Point), config: &Config, buf: Buffer) -> List(Point) = {
    # config: &Config → Dup → копирование токена
    # buf: Buffer → не Dup, без побега → заимствование &mut Buffer
    items.filter(|p| {
        let threshold = config.get_threshold()
        buf.update(p)
        p.x > threshold
    })
}

# 5. Обнаружение конфликтов заимствования
bad: (buf: Buffer) -> Void = {
    closure = |b| b.write()
    buf.read()  # ❌ buf уже заимствован замыканием, здесь конфликт
}
```

### Изменения синтаксиса

**Нулевые изменения синтаксиса**. Способ захвата определяется компилятором автоматически,
пользователю не нужно указывать аннотации.

## Детальный дизайн

### Влияние на систему типов

Сигнатура типа лямбды остаётся неизменной: `(params) -> Return`. Захваченные переменные не
отражаются в сигнатуре типа, обрабатываются компилятором на этапе генерации IR.

### Изменения в компиляторе

| Компонент            | Изменение                                     | Примечание |
| -------------------- | --------------------------------------------- | ---------- |
| `capture.rs` (новый) | Анализ захвата + анализ побега + выбор режима | ~150 строк |
| `expressions.rs`     | Вывод типа лямбды вызывает анализ захвата     | ~10 строк  |
| `ir_gen.rs`          | Заполнение env в MakeClosure; пропуск ZST     | ~80 строк  |
| `ir.rs`              | Возможна корректировка типа env в MakeClosure | ~5 строк   |

**Процесс анализа захвата**:

```
1. Обход AST тела лямбды
2. Сбор всех ссылок Expr::Var(name)
3. Фильтрация: оставить только переменные из внешней области видимости
4. Классификация: Read (только чтение) / Write (чтение-запись) / Move (перемещены)
5. Проверка свойства типа: является ли Dup
6. Определение побега: способ использования замыкания
7. Выбор режима захвата:
   Dup → Copy
   не Dup + без побега + Read → Borrow (&T)
   не Dup + без побега + Write → BorrowMut (&mut T)
   не Dup + с побегом → Move
```

**Генерация IR**:

```rust
// Текущее (пустое)
Instruction::MakeClosure { dst, func, env: Vec::new() }

// Изменяется на
Instruction::MakeClosure { dst, func, env: captured_env }

// Логика генерации captured_env:
for captured in captures {
    match captured.mode {
        Copy if is_zst(captured.ty) => {
            // Тип нулевого размера — не генерируется никаких инструкций
            // Тело замыкания напрямую ссылается на внешний (устранение в compile-time)
        }
        Copy => {
            // Генерация Move dst, src (поверхностное копирование Dup-типа)
        }
        Borrow => {
            // Генерация Borrow dst, src (создание ReadToken)
        }
        BorrowMut => {
            // Генерация Borrow dst, src (создание WriteToken)
        }
        Move => {
            // Генерация Move dst, src (передача владения)
        }
    }
}
```

### Поведение в runtime

Способ захвата не влияет на производительность в runtime:

- **Dup + ZST** (например, токены `&T`) → нулевые инструкции, тело замыкания напрямую ссылается на
  внешнюю переменную
- **Dup + не ZST** (например, Int) → однократное копирование через регистр
- **Borrow/BorrowMut** → создание токена (концепция compile-time, нулевые накладные расходы)
- **Move** → та же стоимость, что и обычный Move

### Обратная совместимость

Полностью совместимо. В настоящее время все лямбды не могут захватывать внешние переменные;
настоящий RFC только добавляет выразительности, не нарушая никакого существующего кода.

## Компромиссы

### Преимущества

1. **Нулевые аннотации**: пользователю не нужно писать какие-либо аннотации захвата
2. **Единообразие с вызовом функций**: правила захвата = правила автоматического заимствования при
   вызове функций
3. **Нулевая стоимость**: захват токенов Dup полностью устраняется в compile-time
4. **Безопасность**: анализ побега предотвращает use-after-free

### Недостатки

1. **Консервативный анализ побега**: при невозможности определения обрабатывается как побег, что
   может приводить к ненужным Move
2. **Неявность**: способ захвата не отражён в коде, для отладки необходимо смотреть вывод
   компилятора

## Альтернативы

| Подход                                        | Почему не выбран                                                  |
| --------------------------------------------- | ----------------------------------------------------------------- |
| Rust-подобное явное ключевое слово `move`     | Вводит новый синтаксис, увеличивает когнитивную нагрузку          |
| Всегда Move                                   | Невозможно выразить заимствование токенов с нулевой стоимостью    |
| Всегда заимствование                          | Побег замыкания приведёт к висячим ссылкам                        |
| Ручное указание способа захвата пользователем | Противоречит философии дизайна «полная автоматизация компилятора» |

## Стратегия реализации

### Этапы

1. **Фаза 1**: Анализ захвата (только распознавание ссылок на внешние переменные, без различия
   способов захвата)
2. **Фаза 2**: Анализ побега + выбор режима
3. **Фаза 3**: Генерация IR + оптимизация ZST
4. **Фаза 4**: Интеграция обнаружения конфликтов заимствования

### Зависимости

- Зависит от RFC-011 (система дженериков, раздел 2.4 trait Dup/Clone) — требуется trait Dup для
  определения, является ли переменная копируемой
- Зависит от RFC-009 v9 (токены заимствования) — режимы захвата Borrow/BorrowMut требуют типов
  токенов
- После реализации RFC-023 и данного RFC можно приступать к реализации системы токенов заимствования
  (реализация RFC-009 v9)

### Риски

- Анализ побега может быть слишком консервативным, что приведёт к ненужным Move; возможна
  последующая оптимизация
- Анализ захвата для дженерик-замыканий может потребовать дополнительной обработки
