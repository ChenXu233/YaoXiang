# RFC-021: Библиотечно-управляемое расширение FFI и поддержка межъязыковых вызовов

> **⚠️ Устарел**: этот документ устарел, его содержимое объединено в
> [RFC-026: Основной механизм FFI](../accepted/026-ffi-core-mechanism.md).

> **Ссылки**:
>
> - [RFC-001: Модель spawn и система обработки ошибок](./001-concurrent-model-error-handling.md)
> - [RFC-008: Модель конкурентности Runtime и дизайн с разделением планировщика](../accepted/008-runtime-concurrency-model.md)

## Резюме

В этом документе предлагается **библиотечно-управляемая** схема расширения FFI (внешнего интерфейса
функций). Единственная точка входа для FFI — это объявление `native("symbol")` плюс таблица
регистрации `FfiRegistry` во время выполнения; в ядре не вводится второй механизм. Поверх этого
стандартная библиотека предоставляет возможности загрузки динамических библиотек, привязки
межъязыковых вызовов и т.д. Привязки вызовов для конкретных языков (таких как C, Python, JavaScript)
автоматически генерируются официальным инструментарием или пишутся отдельными проектами по мере
необходимости.

## Мотивация

### Недостатки текущей реализации

Текущая реализация FFI уже обладает следующими возможностями:

- объявление внешних функций с помощью синтаксиса `native("symbol")`
- таблица регистрации функций `FfiRegistry`

Но функциональность относительно ограничена:

- отсутствует поддержка загрузки динамических библиотек
- нет инфраструктуры для межъязыковых вызовов
- отсутствуют автоматизированные инструменты генерации привязок

### Философия дизайна

YaoXiang следует принципу **«минимализм ядра, вынос сложности в библиотеки»**:

> **Хороший вкус (Good Taste)**: задача языка — предоставлять атомарные возможности, а не раздутый
> набор функций. Сложность должна решаться через библиотеки, а не накапливаться в компиляторе.

Поэтому данное предложение:

- ✅ **Нулевые изменения синтаксиса** — полная обратная совместимость, точка входа FFI только
  `native("symbol")`
- ✅ **Библиотека как язык** — функциональность расширяется через стандартную библиотеку
- ✅ **Автоматизация инструментарием** — привязки автоматически генерируются `yx-bindgen`, а не
  пишутся вручную
- ✅ **Прогрессивное улучшение** — разработчики подключают функциональность по мере необходимости

## Предложение

### 1. Расширение основной библиотеки FFI

Расширение модуля `std.ffi`. Обратите внимание: все вызовы внешних функций по-прежнему
осуществляются через объявление `native("symbol")`; `std.ffi` предоставляет лишь вспомогательные
возможности.

#### 1.1 Загрузка динамических библиотек

```yaoxiang
import ffi

# 加载动态库 (.so/.dll/.dylib)
lib = ffi.load_library("./libmyext.so")

# 从库中获取函数符号，返回 native 可用的 symbol 名
ffi.register_library_symbols(lib, [
    "my_function",
    "another_func",
])
```

`load_library` возвращает дескриптор `DynamicLibrary`, а `register_library_symbols` регистрирует
имена символов в известной таблице FfiRegistry. После этого пользователь по-прежнему использует их
через объявление `native`:

```yaoxiang
my_func: (a: Int, b: Int) -> Int = native("my_function")
```

Никакого второго синтаксиса вызова, никакой обёртки `try_call`.

#### 1.2 Управление библиотеками

```yaoxiang
# 列出已加载的库
loaded = ffi.loaded_libraries()

# 卸载库
ffi.unload_library(lib)

# 库版本检查
ffi.check_version(lib, "1.0.0")
```

#### 1.3 Разрешение символов

```yaoxiang
# 按名称查找符号（返回 Symbol 结构）
sin_sym = ffi.dlsym("libm.so", "sin")
```

Соглашения о вызовах между языками и преобразования типов обрабатываются не через универсальную
обёртку во время выполнения, а генерируются `yx-bindgen` во время компиляции.

### 2. Реализация загрузки динамических библиотек

#### 2.1 Основные структуры данных

```rust
pub struct DynamicLibrary {
    handle: *mut std::ffi::c_void,
    path: String,
}

impl DynamicLibrary {
    pub fn load(path: &str) -> Result<Self, FfiError>;
    pub fn get_symbol(&self, name: &str) -> Result<*mut std::ffi::c_void, FfiError>;
    pub fn unload(self) -> Result<(), FfiError>;
}
```

#### 2.2 Типы ошибок

```rust
pub enum FfiError {
    LibraryNotFound { name: String, os_error: Option<OsError> },
    SymbolNotFound { name: String, os_error: Option<OsError> },
    CallFailed { message: String, os_error: Option<OsError> },
    Timeout,
}

pub struct OsError {
    pub code: i32,
    pub message: String,
}
```

`OsError` несёт в себе собственный код ошибки платформы (`dlerror()` в Linux, `GetLastError()` в
Windows), что обеспечивает возможность отладки.

### 3. Многоязыковые привязки: решение на основе инструментария

Отказ от фантазии «авторы привязок из сообщества по каждому языку». Вместо этого — автоматическая
генерация официальным инструментарием.

#### 3.1 Архитектура

```
┌───────────────────────────────────────────────┐
│  YaoXiang 代码                                │
│                                               │
│  // 用户只写 native 声明                       │
│  my_func: (a: Int) -> Int = native("my_func") │
└───────────────────────────────────────────────┘
         ↑                          ↑
         |  编译时                   | 运行时
┌──────────────────┐   ┌────────────────────────┐
│  yx-bindgen       │   │  std.ffi + FfiRegistry  │
│  (C 头文件 → .yx) │   │  - dlopen/dlsym         │
│                   │   │  - LoadLibrary/GetProc  │
└──────────────────┘   └────────────────────────┘
```

#### 3.2 Генератор привязок (`yx-bindgen`)

`yx-bindgen` — это отдельный инструмент CLI, генерирующий код привязок YaoXiang FFI из заголовочных
файлов C:

```bash
yx-bindgen --header /usr/include/sqlite3.h --output sqlite3.yx
```

Сгенерированный пример:

```yaoxiang
# 自动生成，不要手动编辑
# Source: /usr/include/sqlite3.h

sqlite3_open: (filename: *const u8, ppDb: *mut *mut opaque) -> Int
    = native("sqlite3_open")

sqlite3_close: (db: *mut opaque) -> Int
    = native("sqlite3_close")

sqlite3_exec: (
    db: *mut opaque,
    sql: *const u8,
    callback: *mut opaque,
    arg: *mut opaque,
    errmsg: *mut *mut u8,
) -> Int
    = native("sqlite3_exec")
```

`yx-bindgen` поддерживается официально и гарантирует:

- полноту отображения типов (`int` → `Int`, `char*` → `*const u8`, `void*` → `*mut opaque`)
- выравнивание раскладки структур (автоматический аналог `#[repr(C)]`)
- преобразование сигнатур обратных вызовов (callback)

#### 3.3 Официально поддерживаемые пакеты привязок

Основная команда YaoXiang не обязуется поддерживать универсальные библиотеки привязок для всех
языков, но предоставляет официальный пакет привязок `libc` (подмножество POSIX + Windows API) в
качестве образца лучших практик FFI и базовой функциональности.

Привязки для других языков и библиотек:

- генерируются самостоятельно с помощью `yx-bindgen`
- могут публиковаться как пакеты YaoXiang (например, `libsqlite3`, `libcurl`, `libsdl2`)
- основная команда не несёт ответственности за их поддержку, но предоставляет механизм публикации и
  управления версиями пакетов

### 4. Уровень преобразования типов

#### 4.1 Отображение типов на этапе компиляции

Преобразование типов выполняется не через обёртки времени выполнения, а определяется статически на
этапе генерации `yx-bindgen`:

| C тип        | Тип YaoXiang      | Способ преобразования              |
| ------------ | ----------------- | ---------------------------------- |
| `int`        | `Int`             | передача по значению               |
| `char*`      | `*const u8`       | передача указателя                 |
| `void*`      | `*mut opaque`     | непрозрачный указатель             |
| `struct T`   | `extern struct T` | совпадение раскладки               |
| `int*`       | `*mut Int`        | передача указателя (изменяемый)    |
| `const int*` | `*const Int`      | передача указателя (только чтение) |

#### 4.2 Ручное преобразование (вспомогательные средства стандартной библиотеки)

```yaoxiang
# 显式转换
raw_ptr = ffi.to_pointer(my_bytes)
c_string = ffi.to_c_string(my_string)
```

### 5. Модель владения памятью

#### 5.1 Основные принципы

Каждое выделение памяти через границу FFI должно явно отвечать на два вопроса:

1. **Кто выделяет?** (сторона C через `malloc` / среда выполнения YaoXiang)
2. **Кто освобождает?** (сторона C через `free` / среда выполнения YaoXiang)

При генерации `yx-bindgen` добавляет аннотации для распространённых шаблонов:

```yaoxiang
# C 分配，调用者释放
sqlite3_exec: (...) -> Int
    = native("sqlite3_exec")
    # memory: C-allocated, caller must free errmsg via sqlite3_free

# 调用者分配指针
read: (fd: Int, buf: *mut u8, count: Int) -> Int
    = native("read")
    # memory: caller-allocated buf
```

Среда выполнения не выполняет автоматическое управление памятью для ссылок-указателей через границу
FFI — владение явно остаётся на стороне вызывающего.

#### 5.2 Обработка строк

`char*`, возвращаемый функцией C, немедленно копируется при преобразовании в YaoXiang `String`.
Владение исходным указателем определяется функцией C (объявляется через аннотацию) и не
освобождается автоматически.

### 6. Соображения безопасности

#### 6.1 Потокобезопасность

Вызовы FFI-функций **по умолчанию не участвуют в планировании DAG** и рассматриваются как
блокирующие операции. C-функции, гарантированно реентерабельные, могут быть помечены как
`@concurrent`:

```yaoxiang
# 纯函数，无全局状态，可并发
sin_safe: (x: Float) -> Float = native("sin")
    # reentrant: true

# 有全局状态，不能并发
strtok: (s: *const u8, delim: *const u8) -> *const u8 = native("strtok")
    # reentrant: false
```

`yx-bindgen` по возможности аннотирует информацию о реентерабельности для стандартных функций
библиотеки C (варианты `_r` для `strtok` и т.д.).

**Требования к асинхронным вызывающим сторонам:** перед вызовом FFI-функции вызывающая сторона
должна убедиться, что целевая функция реентерабельна. Среда выполнения не выполняет автоматического
обнаружения — это статически неразрешимая задача.

#### 6.2 Изоляция ошибок

- ошибки вызовов FFI распространяются через тип `Result` (если функция объявила тип возврата Result)
- механизм таймаута предотвращает зависание внешних функций

```yaoxiang
# 带超时的调用（在 FfiRegistry 层实现）
result = ffi.call_with_timeout("blocking_func", 5000)  # 5秒超时
```

#### 6.3 Безопасность указателей

- параметры-указатели требуют пометки `unsafe` на стороне YaoXiang
- время жизни указателей через границу FFI гарантируется вызывающей стороной

### 7. Изменения компилятора

**Нулевые изменения синтаксиса** — требуется только объявление `native("symbol")`, уже реализованное
в текущем компиляторе.

В интерпретаторе/среде выполнения добавляется:

- инструкции загрузки динамических библиотек (FFI-привязки для `DynamicLibrary`)
- механизм таймаута

### 8. Не включённые функции

Следующие функции были рассмотрены и явно исключены, и больше не входят в RFC:

- **`ffi.try_call`**: избыточно, уже есть `native` + тип возврата `Result`
- **`ffi.verify_signature`**: компиляторные задачи в среде выполнения — неправильный уровень
  абстракции
- **`ffi.async_call`**: требуется дождаться прояснения модели контракта реентерабельности
- **Таблица привязок, поддерживаемая сообществом**: нереализуемо, заменено решением на основе
  `yx-bindgen`

## Компромиссы

### Преимущества

- ✅ **Нулевые изменения синтаксиса** — точка входа FFI только `native("symbol")`, полная обратная
  совместимость
- ✅ **Библиотека как язык** — функциональность подключается прогрессивно через стандартную
  библиотеку
- ✅ **Управление через инструментарий** — `yx-bindgen` автоматически обрабатывает генерацию
  привязок
- ✅ **Безопасность памяти** — модель владения чёткая, без автоматической сборки, приводящей к
  use-after-free
- ✅ **Отлаживаемость** — ошибки несут в себе собственные коды ошибок ОС

### Недостатки

- ⚠️ безопасность типов ограничена выразительностью заголовочных файлов C (`void*` нельзя статически
  различить)
- ⚠️ `yx-bindgen` требует постоянной поддержки для отслеживания эволюции стандарта C
- ⚠️ для не-C языков (Python/JS/Java) привязки должны обрабатываться каждым проектом самостоятельно,
  единого решения нет

## Приложение B: Примеры кода

### Полный пример: использование C-библиотеки

```yaoxiang
# 加载 C 数学库
libm = ffi.load_library("libm.so")

# 将 C 符号注册到运行时表（yx-bindgen 会在编译时做这个）
ffi.register_library_symbols(libm, ["sin", "cos", "sqrt"])

# 通过 native 声明使用
sin_f: (x: Float) -> Float = native("sin")
cos_f: (x: Float) -> Float = native("cos")

# 直接调用
result = sin_f(3.14159 / 2)

# 调用可能失败的 C 函数时使用 Result
file_open: (path: *const u8, mode: *const u8) -> Result(*mut opaque, Int)
    = native("fopen")
```

### Использование yx-bindgen

```bash
# 自动生成所有声明，不需要手写
yx-bindgen --header /usr/include/math.h --output math_bindings.yx

# 在 YaoXiang 中引入
import "math_bindings.yx"
# sin_f / cos_f 等已自动声明为 native("sin") / native("cos")
```
