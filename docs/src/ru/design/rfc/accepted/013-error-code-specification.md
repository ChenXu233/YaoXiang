# RFC 013: Спецификация кодов ошибок

## Краткое содержание

Настоящий RFC предлагает спецификацию классификации кодов ошибок компилятора YaoXiang, использующую
одноуровневую систему нумерации, аналогичную Rust, в сочетании с файлами ресурсов JSON для
обеспечения многоязычной поддержки, а также функциональность объяснения ошибок через команду
`yaoxiang explain`.

## Мотивация

### Зачем нужны стандартизированные коды ошибок?

1. **Пользовательский опыт**: Пользователь, видя код ошибки, может быстро определить тип и
   серьёзность ошибки
2. **Организация документации**: Группировка по категориям упрощает написание и сопровождение
   справочной документации по ошибкам
3. **Интеграция с инструментами**: IDE/LSP может предоставлять предложения по быстрому исправлению и
   ссылки на документацию на основе кодов ошибок
4. **Поддержка интернационализации**: Разделение сообщений об ошибках и кодов упрощает многоязычный
   перевод

### Цели проектирования

- **Простота**: Одноуровневая нумерация, пользователю не нужно запоминать сложные правила
  классификации
- **Дружелюбность**: Формат сообщений об ошибках, аналогичный Rust, с вспомогательной информацией и
  примерами
- **Расширяемость**: Управляется через файлы ресурсов, легко добавлять новые ошибки и языки
- **Удобство для инструментов**: Команда explain + вывод в формате JSON, поддержка интеграции с
  IDE/LSP

## Предложение

### Основная конструкция: Одноуровневая система нумерации

Используется четырёхзначная нумерация, сгруппированная по этапам компиляции:

```
Exxxx
││││
│││└── Порядковый номер (000-999)
││└─── Этап компиляции (0-9)
└───── Фиксированный префикс 'E'
```

### Разделение на этапы

| Этап  | Диапазон | Описание                               |
| ----- | -------- | -------------------------------------- |
| **0** | E0xxx    | Лексический и синтаксический анализ    |
| **1** | E1xxx    | Проверка типов                         |
| **2** | E2xxx    | Семантический анализ                   |
| **3** | E3xxx    | Генерация кода                         |
| **4** | E4xxx    | Дженерики и трейты                     |
| **5** | E5xxx    | Модули и импорт                        |
| **6** | E6xxx    | Ошибки времени выполнения              |
| **7** | E7xxx    | Ошибки ввода-вывода и системные ошибки |
| **8** | E8xxx    | Внутренние ошибки компилятора          |
| **9** | E9xxx    | Зарезервировано/Экспериментальные      |

### Перечисление категорий ошибок

```rust
/// 错误类别
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum ErrorCategory {
    Lexer,      // E0xxx: 词法和语法分析
    Parser,     // E0xxx: Parser errors
    TypeCheck,  // E1xxx: 类型检查
    Semantic,   // E2xxx: 语义分析
    Generic,    // E4xxx: 泛型与特质
    Module,     // E5xxx: 模块与导入
    Runtime,    // E6xxx: 运行时错误
    Io,         // E7xxx: I/O与系统错误
    Internal,   // E8xxx: 内部编译器错误
}
```

### Определение кодов ошибок и универсальный Builder

**Ключевой принцип**: Разделение определений кодов ошибок и отображаемого текста

- `ErrorCodeDefinition`: Метаданные кода ошибки (code, category, template), не содержат
  отображаемого текста
- `locales/*.json`: Отображаемый текст для каждого языка (title, message, help, коды ошибок как
  вложенные объекты)
- `DiagnosticBuilder`: Универсальный конструктор, заменяющий дизайн trait-per-error

#### Определение кода ошибки

```rust
// diagnostic/codes/mod.rs

use crate::util::span::Span;
use crate::util::diagnostic::{Diagnostic, Severity};

/// 错误码定义（仅元数据，展示文案在 i18n 文件）
#[derive(Debug, Clone, Copy)]
pub struct ErrorCodeDefinition {
    pub code: &'static str,
    pub category: ErrorCategory,
    pub message_template: &'static str,  // 消息模板，支持 {param} 占位符
}

/// 通用诊断构建器
pub struct DiagnosticBuilder {
    code: &'static str,
    message_template: &'static str,
    params: Vec<(&'static str, String)>,
    span: Option<Span>,
}

impl DiagnosticBuilder {
    pub fn new(code: &'static str, template: &'static str) -> Self {
        Self {
            code,
            message_template: template,
            params: Vec::new(),
            span: None,
        }
    }

    /// 添加模板参数
    pub fn param(mut self, key: &'static str, value: impl Into<String>) -> Self {
        self.params.push((key, value.into()));
        self
    }

    /// 设置位置
    pub fn at(mut self, span: Span) -> Self {
        self.span = Some(span);
        self
    }

    /// 构建 Diagnostic（模板渲染在编译期完成）
    pub fn build(&self, i18n: &I18nRegistry) -> Diagnostic {
        // 检查模板中所有 {key} 都有对应参数
        self.validate_params();

        let message = i18n.render(self.message_template, &self.params);
        let help = self.help(i18n);

        Diagnostic {
            severity: Severity::Error,
            code: self.code.to_string(),
            message,
            help,
            span: self.span,
            related: Vec::new(),
        }
    }
}
```

#### Сокращённые методы для каждого кода ошибки

```rust
// diagnostic/codes/e1xxx.rs

impl ErrorCodeDefinition {
    /// E1001 未知变量
    pub fn unknown_variable(name: &str) -> DiagnosticBuilder {
        let def = Self::find("E1001").unwrap();
        DiagnosticBuilder::new(def.code, def.message_template)
            .param("name", name)
    }

    /// E1002 类型不匹配
    pub fn type_mismatch(expected: &str, found: &str) -> DiagnosticBuilder {
        let def = Self::find("E1002").unwrap();
        DiagnosticBuilder::new(def.code, def.message_template)
            .param("expected", expected)
            .param("found", found)
    }
}
```

#### Пример использования

```rust
// checking/mod.rs

use crate::util::diagnostic::codes::{ErrorCodeDefinition, E1001};

// 简化方式
return Err(E1001::unknown_variable(&var_name)
    .at(span)
    .build(&i18n_registry));

// 手动方式
return Err(ErrorCodeDefinition::find("E1001")
    .builder()
    .param("name", var_name)
    .at(span)
    .build(&i18n_registry));
```

#### Преимущества дизайна

| Свойство                                          | Описание                                                      |
| ------------------------------------------------- | ------------------------------------------------------------- |
| **Единый Builder**                                | Один `DiagnosticBuilder` универсален для всех кодов ошибок    |
| **Типобезопасность**                              | Сокращённые методы гарантируют корректность параметров        |
| **Самодокументируемость**                         | `E1001::unknown_variable(name)` понятно с первого взгляда     |
| **Разделение шаблонов**                           | Шаблоны сообщений отделены от кода, что упрощает i18n         |
| **Нулевые накладные расходы во время выполнения** | Рендеринг во время компиляции, AOT-бинарник без таблиц поиска |

### Упрощение макросов ошибок

#### Макрос error! (автоматическое внедрение контекста)

```rust
/// 编译期自动获取 span 和 i18n 配置的宏
macro_rules! error {
    ($code:ident, $($key:ident = $value:expr),* $(,)?) => {
        $code()
            $(.$key($value))*
            .at(crate::util::span::Span::current())
            .build(crate::util::diagnostic::I18nRegistry::current())
    };
}

/// 使用：只需传参数，span 和 i18n 自动注入
return Err(error!(E1001, name = var_name));
return Err(error!(E1002, expected = "bool", found = cond_ty));
```

#### Ручное использование Builder

```rust
// 需要手动控制时
E1001::unknown_variable(&var_name)
    .at(my_span)           // 自定义 span
    .build(&custom_i18n)   // 自定义 i18n
```

> - E6006 изменён с Runtime index out of bounds на Function not found (реализация уже такая)
> - E6007 изменён с Type cast failed на общий Runtime error (единая точка для несопоставленных
>   вариантов ExecutorError)

> Правила позиционирования W-кодов: Изоморфны E-кодам, группируются по этапам (W + сегмент тысяч
> этапа), W1xxx = предупреждения этапа проверки типов.
>
> **Семантика кода мёртвого кода (утверждено #321, вариант B)**: Определения `pub` являются внешними
> интерфейсами и никогда не репортируются — используются ли они внешними потребителями, выходит за
> границы анализа одного файла, лучше молчать, чем выдавать ложные срабатывания.
> W1001/W1002/W1004/W1005 применяются только к **приватным (не pub) определениям**: сообщается, если
> они никогда не упоминались в анализе достижимости ссылок, начинающемся с `main` и определений
> `pub`. Метод (W1005) сопоставляется по короткому имени в точке вызова. Семантика bin/lib target
> (предупреждение о неиспользуемом pub в bin) — будущее расширение (#289 вариант A), требует
> поддержки модели проекта.
>
> **Неиспользуемый импорт (W1003)**: Обнаруживается при elaboration use на этапе проверки типов
> (pass2 регистрирует локальные имена импорта, попадание в позицию разбора выражений или аннотации
> типа считается использованием), охватывает как общий импорт (`use std.io` → псевдоним модуля), так
> и именованный импорт (`use std.io.{print}`).
>
> **Канал выброса**: Диагностика W-кодов по умолчанию помечается builder как `Severity::Warning` на
> основе префикса W (явное указание имеет приоритет), сбор и представление происходят по тому же
> каналу, что и ошибки (рендеринг с префиксом `warning[W####]`), но не блокируют компиляцию и не
> влияют на успешный код выхода. `yaoxiang check --deny-warnings` повышает предупреждения до сбоя
> (при наличии предупреждений выходит с ненулевым кодом), для строгого режима CI. Подавление
> per-code (атрибут allow и т.п.) — последующее расширение.

### Спецификация качества сообщений

> Этот раздел введён ревизией единого канала сообщений и качества (2026-09-03). Принудительно
> выполняется в CI скриптом `scripts/audit_diagnostics.py`.

1. **Единый канал сообщений**: Все видимые пользователю диагностические сообщения должны проходить
   через сокращённые методы авторитетного реестра + рендеринг шаблонов locales, код передаёт только
   структурированные параметры. Запрещено обходить реестр и напрямую конструировать собственные
   значения вроде `Diagnostic::error(...)` — этот путь обходит проверку кода и i18n.
2. **Допустимость кодов**: Запрещено использовать незарегистрированные коды и псевдокоды (например,
   `E_INTERNAL`); литералы кодов в точках использования должны быть определены в реестре. Все
   внутренние ошибки попадают в E8001 (`internal_error`).
3. **Отображение типов**: Display типа должен различать форму до и после инстанцирования
   (`Expected 'Container', found 'Container'` — голые имена неразличимы).
4. **Изоляция внутреннего состояния решателя**: Промежуточные TypeVar решателя (форма Display
   `t<N>`) не должны попадать в видимые пользователю сообщения. Привязка теста:
   `test_type_error_message_no_solver_typevar_leak`.
5. **Граница E8xxx**: E8xxx используется только для проблем внутренней согласованности компилятора
   (ICE). Запрещено использовать E8001 в качестве запасного варианта для ошибок, которые
   пользователь может исправить; сообщения ICE должны сопровождаться инструкциями по минимальному
   воспроизведению.

### Связь значений ошибок времени выполнения с кодами

> Этот раздел введён ревизией кодов значений ошибок времени выполнения (2026-09-03). Семантическое
> пространство E6xxx/E7xxx одновременно несёт два канала, кодовое пространство одно, каналы
> представления разные.

#### Два канала

| Канал                                 | Носитель                                                  | Способ представления                                          |
| ------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------- |
| **Канал диагностики компилятора/CLI** | Аппаратные ошибки уровня хоста, такие как `ExecutorError` | stderr `error[E####]:` (подключено E6003/E6005/E6007)         |
| **Канал значений ошибок в программе** | Носитель Err `Error` библиотеки std `Result(T, Error)`    | Значение языка, потребляемое программой через match/сравнение |

#### Структура Error (начиная с v0.8, ломающее изменение)

```
Error { code: String, message: String }
```

- `code` повторно использует нумерацию E6xxx/E7xxx данной спецификации, в строковом виде (например,
  `"E6008"`).
- **Стабильный контракт**: Семантика выделенных кодов не меняется между версиями; одна и та же
  семантика не использует повторно удалённые коды (прецедент E6002).
- **Сторона потребления**: Сравнение в программе `e.code == "E6xxx"` — единственный программируемый
  контракт определения; документация `yaoxiang explain E6xxx` согласована; цепочка инструментов (LSP
  / DAP, см. RFC-034) использует код как exceptionId.
- **Аксессоры**: `std.result.code(e)` / `std.result.message(e)`.
- **Пользовательские ошибки**: E в `Result(T, E)` — это параметр дженерика, для серьёзного
  моделирования используются пользовательские типы; std `Error` — лишь удобный запасной носитель,
  его система кодов не ограничивает пользовательский тип E.

#### Правила распределения кодов

1. Коды значений ошибок времени выполнения и коды диагностики компилятора совместно используют
   пространство E6xxx/E7xxx, новые коды распределяются по **реальным точкам срабатывания**, без
   резервирования под воображаемые сценарии.
2. Сначала регистрация, затем использование: новый код попадает в авторитетный реестр и проходит
   трёхстороннюю проверку согласованности (codes/*.rs ↔ locales ↔ таблица кодов данного документа),
   после чего может выбрасываться. Источником регистрации кодов значений ошибок времени выполнения
   является таблица `RUNTIME_ERROR_CODES` в `src/std/result.rs` (как и диагностические коды,
   подвергается проверкам на этапе сборки `build.rs` + `tools/code-tables`).
3. E7xxx — зарезервированный сегмент для значений ошибок std.io / std.net (в настоящее время пуст,
   активируется при переводе io/net на Result).
4. Точки выброса: модули std конструируют значения Error через `error_new(code, message)`; на
   стороне потребления `std.result.unwrap_err` извлекает носитель Err, `std.result.code/message`
   читают поля.

#### Путь развития (линия C, не реализовано)

После полной реализации сопоставления шаблонов (RFC-039), `Error` может быть обновлён до
`{ kind: ErrorKind, message: String }`, при этом `code` становится атрибутом, производным от kind
(определение варианта служит реестром кодов). В период развития стабильный контракт code данного
раздела остаётся неизменным; это обновление — независимое решение и не является обязательством
данного раздела.

#### Реализация I18nRegistry

```rust
// locales/*.json（错误码对象）

/// i18n 展示文案注册表（编译期从 JSON 加载，运行时零查表）
pub struct I18nRegistry {
    /// 标题
    titles: HashMap<&'static str, &'static str>,
    /// 描述
    messages: HashMap<&'static str, &'static str>,
    /// 帮助信息
    helps: HashMap<&'static str, &'static str>,
    /// 示例代码
    examples: HashMap<&'static str, &'static str>,
    /// 错误输出示例
    error_outputs: HashMap<&'static str, &'static str>,
}

/// 单个错误码信息
#[derive(Clone, Copy)]
pub struct ErrorInfo<'a> {
    pub title: &'a str,
    pub message: &'a str,
    pub help: &'a str,
    pub example: Option<&'a str>,
    pub error_output: Option<&'a str>,
}

impl I18nRegistry {
    /// 根据语言代码获取注册表
    pub fn new(lang: &str) -> Self {
        match lang {
            "zh" => Self::zh(),
            _ => Self::en(),
        }
    }

    /// 获取错误信息
    pub fn get_info(&self, code: &str) -> Option<ErrorInfo<'_>> {
        Some(ErrorInfo {
            title: self.titles.get(code)?,
            message: self.messages.get(code)?,
            help: self.helps.get(code)?,
            example: self.examples.get(code).copied(),
            error_output: self.error_outputs.get(code).copied(),
        })
    }

    /// 渲染模板（编译期完成，运行时零开销）
    pub fn render(&self, template: &'static str, params: &[(&str, String)]) -> String {
        let mut result = String::with_capacity(template.len() + 64);
        let mut chars = template.chars().peekable();

        while let Some(c) = chars.next() {
            if c == '{' {
                let mut key = String::new();
                while let Some(&c) = chars.peek() {
                    if c == '}' {
                        chars.next();
                        if let Some((_, value)) = params.iter().find(|(k, _)| k == &key) {
                            result.push_str(value);
                        } else {
                            result.push_str(&format!("{{{}}}", key));
                        }
                        break;
                    }
                    key.push(c);
                    chars.next();
                }
            } else {
                result.push(c);
            }
        }
        result
    }
}
```

#### Ключ к нулевым накладным расходам на поиск

**Рендеринг происходит во время компиляции пользовательского проекта, а не во время выполнения.**

```
┌─────────────────────────────────────────────────────────────────────────┐
│  阶段 1: Rust 编译 YaoXiang 编译器                                      │
│                                                                           │
│  JSON 打包进编译器二进制                                                 │
│  目的：explain 指令能直接读取 i18n 数据                                  │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│  阶段 2: YaoXiang 编译用户项目（渲染发生在这里）                          │
│                                                                           │
│  error! 宏调用时：                                                       │
│  1. 读取 yaoxiang.toml 获取语言偏好                                      │
│  2. 从编译器二进制加载对应语言的 i18n JSON                                │
│  3. 模板 + 参数 → render() → "Unknown variable: 'x'"                    │
│  4. Diagnostic.message = 已渲染的字符串                                   │
│                                                                           │
│  AOT 二进制直接存储最终字符串，无模板，无查表                            │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│  阶段 3: 用户程序运行时                                                  │
│                                                                           │
│  println!("{}", diagnostic.message)                                      │
│  // 直接输出最终字符串，无任何查表                                        │
└─────────────────────────────────────────────────────────────────────────┘
```

| Компонент                    | Обязанность                                | Время рендеринга                              |
| ---------------------------- | ------------------------------------------ | --------------------------------------------- |
| `I18nRegistry`               | Предоставляет шаблоны и отображаемый текст | Во время компиляции пользовательского проекта |
| `DiagnosticBuilder.render()` | Шаблон + параметры → итоговая строка       | Во время компиляции пользовательского проекта |
| `Diagnostic.message`         | Уже отрендеренная строка                   | Хранит итоговый результат                     |
| AOT-бинарник                 | Содержит итоговые строки                   | Используется напрямую во время выполнения     |

### Уровни серьёзности

Серьёзность ошибки управляется перечислением `DiagnosticLevel` и не связана с нумерацией кодов

pub enum DiagnosticLevel {

| Note    | `note[E####]:`    | Дополнительная информация  |
| Help    | `help[E####]:`    | Предложение по исправлению |

## Стратегия реализации

### Этап первый: Базовая инфраструктура кодов ошибок

1. Создание структуры каталога `src/diagnostics/`

### Этап третий: Интеграция на этапе компиляции

1. Обновление всех точек отчётов об ошибках для использования новой системы
2. Реализация внедрения параметров шаблона сообщения
3. Добавление логики приоритета языка
4. Покрытие модульными тестами

### Этап четвёртый: Интеграция IDE/LSP

1. Интеграция JSON-вывода explain в сервер LSP
2. Отображение ссылок на коды ошибок в IDE
3. Отображение объяснения ошибки при наведении
4. Предложения по быстрому исправлению

## Приложение

### Полная сводная таблица кодов ошибок

| Диапазон | Категория                              |
| -------- | -------------------------------------- |
| E0xxx    | Лексический и синтаксический анализ    |
| E1xxx    | Проверка типов                         |
| E2xxx    | Семантический анализ                   |
| E3xxx    | Генерация кода                         |
| E4xxx    | Дженерики и трейты                     |
| E5xxx    | Модули и импорт                        |
| E6xxx    | Ошибки времени выполнения              |
| E7xxx    | Ошибки ввода-вывода и системные ошибки |
| E8xxx    | Внутренние ошибки компилятора          |
| E9xxx    | Зарезервировано                        |

### Поддерживаемые языки

| Код   | Язык                 | Статус       |
| ----- | -------------------- | ------------ |
| en-US | English (US)         | По умолчанию |
| zh-CN | Упрощённый китайский | В планах     |

### Сравнение примеров сообщений об ошибках

```
# 英文 (en-US)
error[E1001]: Unknown variable: x
  --> src/main.yx:5:12
   5 |   print(x)
          ^
          help: Did you mean to define it?

# 中文 (zh-CN)
error[E1001]: 未知变量: x
  --> src/main.yx:5:12
   5 |   print(x)
          ^
          帮助: 你是否想要定义它？
```
