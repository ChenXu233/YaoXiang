# RFC-011: Дизайн системы generics - Zero-Cost Abstractions и альтернатива макросам

## Аннотация

Данный документ определяет **дизайн системы generics языка YaoXiang**, реализующей абстракции с
нулевой стоимостью за счёт мощных возможностей generics, уменьшающей зависимость от макросов
посредством compile-time оптимизаций, и предоставляющей механизмы устранения мёртвого кода.

**Основные дизайнерские решения**:

- **Унифицированный синтаксис сигнатур**: `(T: Type, R: Type) -> ...` параметры generics и обычные
  параметры унифицированы
- **Механизм самоописания Type**: `Type` — это специальная сущность уровня языка, позиция `Type` в
  сигнатуре автоматически заполняется путём вывода
- **Ограничения типов**: `T: Dup + Add` множественные ограничения, ограничения на типы функций
- **Ассоциированные типы**:
  `Iterator: (Item: Type) -> Type = { next: () -> Option(Item), has_next: () -> Bool }`
- **Compile-time generics**: `N: Int` параметры-значения generics, инстанциация константами времени
  компиляции
- **Условные типы**: `If: (C: Bool, T: Type, E: Type) -> Type` вычисления на уровне типов, type
  family

**Ценность**:

- Zero-cost abstractions: мономорфизация compile-time, без накладных расходов runtime
- Устранение мёртвого кода: анализ графа инстанциации + LLVM-оптимизации
- Альтернатива макросам: generics заменяют 90% сценариев использования макросов
- Type safety: проверки compile-time, дружелюбность к IDE
- **Явное лучше неявного**: `Type` самоописывающее, компилятор автоматически выводит

## Идея вселенной типов и зависимые от значений типы

Система generics YaoXiang построена на **идее вселенной типов**, где все концепции языка
унифицируются в многоуровневую структуру, а ключевая инновация заключается в возведении **зависимых
от значений типов** в первоклассных граждан уровня Type2.

### Что такое зависимые от значений типы?

**Зависимый от значения тип** — это тип, который зависит от одного или нескольких **значений** (а не
только от других типов). Эти значения могут быть вычислены compile-time, обеспечивая гарантии type
safety уже на этапе компиляции.

```yaoxiang
# Традиционные generics: параметры типа
List: (T: Type) -> Type

# Зависимые от значений типы: параметры-значения
Vec: (n: Int) -> Type  # тип вектора зависит от значения длины n
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type  # тип матрицы зависит от числа строк и столбцов
```

### Ключевые преимущества зависимых от значений типов

По сравнению с традиционными generics, зависимые от значений типы YaoXiang обладают следующими
ключевыми преимуществами:

| Свойство                          | Традиционные generics (C++/Rust)               | Зависимые от значений типы YaoXiang                                |
| --------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------ |
| Значения, от которых зависят типы | Только параметры типа                          | Любые значения, включая результаты вызовов функций                 |
| Вычисление compile-time           | C++ ручная специализация шаблонов, Rust — нет  | Автоматическое вычисление compile-time с гарантией завершимости    |
| Вычисления на уровне типов        | Шаблонная метапрограммирование (сложно/опасно) | Унифицированный движок вычислений на уровне типов                  |
| Type safety                       | C++ нет, Rust ограничен                        | Полная type safety, проверка compile-time                          |
| Проверка размерностей             | Проверка в runtime или ручная специализация    | Проверка размерностей compile-time, без накладных расходов runtime |

### Уровни вселенной типов и зависимые от значений типы

Идея вселенной типов разделяет концепции языка на уровни по семантической роли, при этом зависимые
от значений типы располагаются на уровне **Type2**:

| Уровень   | Роль                                                      | Примеры                                                                                              |
| --------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Type-1    | Значения                                                  | `42`, `factorial(5)`, сама функция                                                                   |
| Type0     | Ключевое слово метакласса                                 | `Type`                                                                                               |
| Type1     | Конкретные типы                                           | `Int`, `String`, `Vec(3)`                                                                            |
| **Type2** | **Функции/конструкторы типов/зависимые от значений типы** | `add: (Int, Int) -> Int`, `Vec: (n: Int) -> Type`, `Matrix: (T: Type, Rows: Int, Cols: Int) -> Type` |

**Ключевое дизайнерское решение**: Функции, конструкторы типов и зависимые от значений типы уровня
Type2 **унифицированы синтаксически** в форме `(params) -> result`:

- Обычная функция: `(Int, Int) -> Int` → возвращает значение
- Конструктор типа: `(T: Type) -> Type` → возвращает тип
- Зависимый от значения тип: `(n: Int) -> Type` → возвращает тип, но зависит от параметра-значения

> **Изоморфизм Карри-Ховарда**: Это унификация — не совпадение. Изоморфизм Карри-Ховарда гласит:
> «типы суть утверждения, программы суть доказательства» — функциональный тип `A → B` соответствует
> логической импликации «если A, то B», generics `(T: Type) -> Type` соответствуют квантору
> всеобщности «для всех типов T», а зависимый от значения тип `(n: Int) -> Type` соответствует «для
> каждого целого n существует тип». YaoXiang унифицирует функции, конструкторы типов и зависимые от
> значений типы на уровне Type2, по сути объединяя «доказательство» и «вычисление» в одну концепцию
> — **конструктивное доказательство**. Это прямое проявление изоморфизма Карри-Ховарда в дизайне
> языка: единая форма `(params) -> result` одновременно несёт логическое утверждение и процесс
> вычисления.

### Гарантия детерминизма compile-time

Идея вселенной типов YaoXiang требует: **Всё на уровне Type должно быть определено compile-time**.

```yaoxiang
# Пример проверки размерностей compile-time
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),
    # Проверка compile-time: размерности должны быть положительными
    _assert: Assert(Rows > 0),
    _assert: Assert(Cols > 0),
}

# Создание единичной матрицы 3x3 - выполняется compile-time
identity: (T: Add + Zero + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    # ...
}

# Вычисление compile-time: factorial(3) = 6, размер вектора определён compile-time
vec: Vec(factorial(3)) = Vec(6)()
```

Компилятор автоматически:

1. Обнаруживает вызовы функций в позициях типов
2. Выполняет проверку завершимости compile-time для функций (см. механизм проверки завершимости
   ниже)
3. Выполняет вычисление на этапе компиляции
4. Встраивает результат в порождаемый тип

### Сценарии применения зависимых от значений типов

#### Проверка размерностей compile-time

```yaoxiang
# Умножение матриц: проверка совпадения размерностей compile-time
multiply: (T: Add + Multiply + Zero,
           Rows: Int, Cols: Int, M: Int) -> ((
    a: Matrix(T, Rows, Cols),
    b: Matrix(T, Cols, M)
) -> Matrix(T, Rows, M)) = {
    # Проверка compile-time: a.Cols == b.Rows, иначе ошибка компиляции
    result = Matrix(T, Rows, M)()
    # ...
}

# Ошибка обнаруживается compile-time:
# multiply(matrix_2x3, matrix_4x2)  # Ошибка компиляции: 2 != 4
```

#### Type-safe размеры массивов

```yaoxiang
# Размер массива — константа compile-time
Array: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    length: N,
}

# N — константа compile-time, может использоваться в вычислениях на уровне типов
first_three: Array(Int, 3) = Array(Int, 3)(1, 2, 3)
# first_three.length == 3 (известно compile-time)
```

#### Условные типы

```yaoxiang
# If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Type family
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,
}
```

#### Обобщённые функции

```yaoxiang
# map: обобщённая функция, параметры типов T, R определяются compile-time
map: (T: Type, R: Type) -> (
    (list: List(T), f: (x: T) -> R) -> List(R)
) = (list, f) => {
    result = List(R)()
    for x in list {
        result.push(f(x))
    }
    return result
}

# Использование полностью прозрачно, типы выводятся автоматически
numbers = List(Int)()   # Корректура: двухуровневая форма конструктора значения (см. §9.1); элементы добавляются через push
numbers.push(1)
numbers.push(2)
numbers.push(3)
doubled = map(numbers, (x) => x * 2)  # Выводится как map[Int, Int]
```

### Механизм проверки завершимости (унифицирован с RFC-027)

Вычисление compile-time зависимых от значений типов должно быть **гарантированно завершающимся**,
иначе система типов попадёт в бесконечный цикл. Проверка завершимости выполняется **полностью
автоматически** конвейером доказательств compile-time из RFC-027 — компилятор автоматически
синтезирует метрики, рекурсии/циклы, для которых доказательство возможно, проходят, а те, для
которых доказательство невозможно, приводят к ошибке компиляции. **Полуавтоматические аннотации не
допускаются**: `//! decreases` и `/*! invariant !*/` из RFC-022 отменены вместе с RFC-022,
спецификации суть сами аннотации типов.

#### Проверка завершимости рекурсивных функций

Перед вычислением compile-time компилятор проверяет, что аргументы рекурсивных вызовов строго
убывают на каждой ветви рекурсии (RFC-027 §6.7). Какие-либо аннотации спецификаций не требуются:

```yaoxiang
# Факториал compile-time: без //! requires/ensures/decreases, компилятор анализирует автоматически
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)  # Анализ компилятора: n-1 < n → убывает → завершается
}

# Использование: вызов в позиции типа, компилятор сначала верифицирует завершимость, затем вычисляет
vec: Vec(factorial(5)) = Vec(120)()  # Вычисление compile-time: factorial(5) = 120
```

| Сценарий                                                        | Поведение                          |
| --------------------------------------------------------------- | ---------------------------------- |
| Компилятор может установить убывание рекурсии (например, `n-1`) | Вычисление compile-time            |
| Не убывает / убывание не может быть установлено                 | Ошибка компиляции                  |
| Вызов в runtime (не в позиции типа)                             | Проверка завершимости не требуется |

#### Проверка завершимости циклов

Циклы не требуют аннотаций `: Invariant(...)` или `: decreases(...)`. Аннотации уточнения типов
переменных (например, `UpTo(n)`) одновременно задают инвариант цикла и границу метрики. Компилятор
пытается применить четыре стратегии синтеза метрик в порядке приоритета и останавливается на первой
успешной (RFC-027 §7):

1. **Автоматический синтез линейной ранговой функции** — извлечение границ переменных из аннотаций
   типов, перебор линейных комбинаций, верификация SMT: m ≥ 0 и m' < m на всех путях
2. **Подсчёт нарушений предиката** (экспериментально) — извлечение violation_count из определения
   целевого типа (например, `Sorted`), покрытие соседних обменов/перемещений
3. **Шаблон ограниченного инкремента/декремента** — `v += const` → метрика `upper - v` (вырождение
   стратегии 1, самый быстрый путь)
4. **Шаблон метрики с мультипликативным масштабированием** — `v *= const` (const > 1) → метрика
   `ceil(log_const(upper / v))`

```yaoxiang
sum: (arr: Array(Int, n)) -> Int = {
    mut i: UpTo(arr.len) = 0   # Аннотация типа задаёт верхнюю границу arr.len и нижнюю 0
    while i < arr.len {
        # Компилятор автоматически выводит: метрика arr.len - i, каждая итерация строго уменьшает на 1 → завершимость доказана
        s += arr[i]; i += 1
    }
    return s
}
```

#### Рабочий процесс проверки завершимости

```
┌─────────────────────────────────────────────────────────────┐
│  Фаза проверки типов                                       │
│  Встречен вызов функции в позиции типа (например, Vec(factorial(5))) │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  1. Проверка завершимости (конвейер доказательств RFC-027, полностью автоматический) │
│     - Рекурсивные функции: проверка строгого убывания аргументов на каждом пути рекурсии │
│     - Циклы: четыре стратегии синтеза метрик (линейный ранг/подсчёт нарушений/ │

└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  2. Вычисление compile-time (выполняется встроенным интерпретатором) │
│     - Чистые функции: непосредственное вычисление           │

└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  3. Встраивание результата в тип                           │
│     - Vec(factorial(5)) → Vec(120)                         │
│     - Matrix(Float, 3, 3) → конкретный тип                 │
└─────────────────────────────────────────────────────────────┘
```

#### Преимущества

- **Безопасность**: гарантирует неизбежное завершение вычисления compile-time, предотвращая
  попадание системы типов в бесконечный цикл
- **Унификация**: проверка завершимости и верификация корректности (генерация VC) используют общий
  конвейер доказательств compile-time (RFC-027), без отдельного синтаксиса спецификаций
- **Полная автоматизация**: компилятор автоматически синтезирует метрики из аннотаций типов —
  доказуемое проходит, недоказуемое приводит к ошибке — без необходимости ручного написания
  `decreases`

## Мотивация

### Зачем нужна мощная система generics?

Существующие mainstream языки имеют ограничения в generics:

| Язык         | Возможности generics           | Проблема                                                                                       |
| ------------ | ------------------------------ | ---------------------------------------------------------------------------------------------- |
| Java         | Граничные типы                 | Мономорфизация compile-time, без специализации generics                                        |
| C#           | Ограничения generics           | Проверка типов в runtime, накладные расходы на производительность                              |
| Rust         | Generics + Trait               | Сложная система Trait, крутая кривая обучения                                                  |
| C++          | Шаблоны                        | Сложная специализация шаблонов, плохие сообщения об ошибках                                    |
| **YaoXiang** | **Зависимые от значений типы** | **Типы могут зависеть от значений, проверка размерностей compile-time, гарантия завершимости** |

### Ключевые противоречия

1. **Производительность vs гибкость**: гибкость runtime vs оптимизации compile-time
2. **Сложность vs простота**: мощная система типов vs удобство использования
3. **Макросы vs generics**: кодогенерация макросами vs type safety generics
4. **Зависимость от значений vs type safety**: традиционные generics не могут верифицировать
   размерности compile-time

### Ключевые преимущества зависимых от значений типов

**Зависимые от значений типы** YaoXiang — это ключевое преимущество перед традиционными generics:

| Преимущество                   | Описание                                                                                                                    |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------- |
| **Типы зависят от значений**   | `Vec: (n: Int) -> Type` позволяет типам зависеть от конкретных значений                                                     |
| **Вычисление compile-time**    | Вызовы функций в позициях типов вычисляются compile-time, результат встраивается в тип                                      |
| **Проверка размерностей**      | `Matrix(Float, 3, 3)` верифицирует размерности матрицы compile-time                                                         |
| **Вычисления на уровне типов** | Условные типы `If`, `Match` поддерживают вычисления на уровне типов                                                         |
| **Гарантия завершимости**      | Проверка завершимости compile-time (автоматический синтез метрик) гарантирует неизбежное завершение вычисления compile-time |

```yaoxiang
# Проверка compile-time, невозможная в C++/Rust
matrix: Matrix(Float, factorial(3), factorial(2)) = ...
# Вычисление compile-time: factorial(3) = 6, factorial(2) = 2
# Тип: Matrix(Float, 6, 2)

# Несовпадение размерностей обнаруживается compile-time
identity: Matrix(Float, 3, 3) = ...
# multiply(matrix_2x3, identity_3x3)  # Ошибка компиляции: 2 != 3
```

### Ценность системы generics

```yaoxiang
# Пример: унифицированный дизайн API
# Операция map для различных контейнеров

# Традиционный подход: отдельная реализация для каждого типа
map_int_array: (array: Array(Int), f: Fn(Int) -> Int) -> Array(Int) = ...
map_string_array: (array: Array(String), f: Fn(String) -> String) -> Array(String) = ...
map_int_list: (list: List(Int), f: Fn(Int) -> Int) -> List(Int) = ...
map_string_list: (list: List(String), f: Fn(String) -> String) -> List(String) = ...

# Подход с generics: одна обобщённая функция покрывает все типы
map: (T: Type, R: Type)(container: Container(T), f: Fn(T) -> R) -> Container(R) = {
    for item in container {
        result.push(f(item))
    }
    result
}
```

## Цели дизайна

### Основные цели

1. **Zero-cost abstractions** — вызов generics эквивалентен вызову конкретного типа
2. **Устранение мёртвого кода** — анализ compile-time, инстанциация только используемых generics
3. **Альтернатива макросам** — generics заменяют 90% сценариев использования макросов
4. **Type safety** — проверка compile-time, без накладных расходов типов в runtime
5. **Дружелюбность к IDE** — интеллектуальные подсказки, понятные сообщения об ошибках
6. **Зависимые от значений типы** — типы могут зависеть от значений, поддержка проверки размерностей
   compile-time
7. **Безопасность compile-time вычислений** — гарантируется проверкой завершимости compile-time
   (автоматический синтез метрик по RFC-027)

### Принципы дизайна

- **Детерминизм compile-time**: параметры generics определяются compile-time
- **Приоритет мономорфизации**: генерация конкретного кода, без вызовов виртуальных функций
- **Ограничения как руководство**: type constraints управляют инстанциацией
- **Платформенные оптимизации**: специализация для платформо-специфичных оптимизаций
- **Унификация вселенной типов**: функции/конструкторы типов/зависимые от значений типы
  унифицированы на уровне Type2
- **Гарантия завершимости**: вызовы функций в позициях типов должны быть доказуемо завершающимися

## Предложение

### 1. Базовые generics

#### 1.1 Параметры обобщённых типов

> **Ключевое правило**: Определение обобщённого типа **должно явно аннотироваться `: Type`**, иначе
> будет выведено HM как функция.
>
> | Запись                            | Значение                          |
> | --------------------------------- | --------------------------------- |
> | `List: (T: Type) -> Type = {...}` | ✅ Конструктор типа               |
> | `List = {...}`                    | ❌ HM выводит как функцию, не тип |

```yaoxiang
# Определение обобщённого типа (обязательно : Type)
Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self
}

Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self
}

List: (T: Type) -> Type = {
    data: Array(T),
    length: Int,
    push: (self: List(T), item: T) -> Void,   # self — просто имя по соглашению, не ключевое слово
    get: (self: List(T), index: Int) -> Option(T),
}

# Обобщённая функция (без : Type, HM выводит как функцию)
map: (T: Type, R: Type) -> ((opt: Option(T), f: Fn(T) -> R) -> Option(R)) = {
    return match opt {
        some => Option.some(f(some)),
        none => Option.none(),
    }
}

# Ограничения generics (прямое выражение, return можно опустить в одной строке)
clone: (T: Clone)(value: T) -> T = value.clone()

# Несколько параметров типа
combine: (T: Type, U: Type) -> ((a: T, b: U) -> (T, U)) = (a, b)
```

#### 2.4 Встроенные marker trait: Dup и Clone

**Три вида семантики копирования**:

| Тип                                | Значение                                                                                | Триггер                                           | Сценарий использования            |
| ---------------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------- | --------------------------------- |
| **Копирование значения-примитива** | При присваивании автоматическое копирование значения, два значения полностью независимы | Автоматически при присваивании/передаче параметра | Int, Float, Bool, Char            |
| **Dup**                            | Мелкая копия: копирование handle/token, общие базовые данные                            | Автоматически при присваивании/передаче параметра | `&T` token, `ref T`, String/Bytes |
| **Clone**                          | Глубокая копия: создание полной независимой копии                                       | `value.clone()`                                   | Любой тип, реализующий Clone      |

**Семантика Dup**: Тип, реализующий Dup, не передаёт владение при присваивании/передаче параметра —
компилятор копирует handle/token, несколько владельцев указывают на одни и те же базовые данные. Это
дополняет семантику Move по умолчанию в модели владения из RFC-009.

**Dup и Clone — ортогональные концепции**:

```
Dup = копирование handle, общие данные (модификации влияют друг на друга)
Clone = копирование данных, копия независима (модификации не влияют друг на друга)
```

**Правила**:

```
1. Примитивные типы значений (Int, Float, Bool, Char) — встроенное в компилятор копирование значений, не относятся к Dup
2. Dup — применимо только к типам ссылок/tokens и типам с внутренним подсчётом ссылок
3. Clone — явное глубокое копирование, любой тип может реализовать
4. Move по умолчанию — остальные типы сохраняют семантику Move по умолчанию
```

**Какие типы являются Dup**:

| Тип                           | Dup         | Причина                                                                                        |
| ----------------------------- | ----------- | ---------------------------------------------------------------------------------------------- |
| `&T` (токен заимствования)    | ✅          | Токен нулевого размера, копирование токена = несколько представлений указывают на те же данные |
| `ref T`                       | ✅          | Копирование Rc/Arc = счётчик ссылок +1, общие данные в куче                                    |
| String, Bytes                 | ✅          | Внутренний подсчёт ссылок, копирование handle разделяет нижележащий буфер                      |
| `&mut T` (токен изменяемости) | ❌          | Линейная исключительность, копирование невозможно                                              |
| struct                        | Производный | Все поля Dup → struct Dup                                                                      |
| enum                          | Производный | Все поля всех вариантов Dup → enum Dup                                                         |
| tuple                         | Производный | Все элементы Dup → tuple Dup                                                                   |
| Fn (замыкание)                | ❌          | Захваченное окружение может быть не Dup                                                        |
| `*T` (сырой указатель)        | ❌          | unsafe, не участвует в системе владения                                                        |

**Int/Float/Bool/Char не являются Dup** — это типы значений, при присваивании компилятор
автоматически копирует значение (два значения полностью независимы). Это не «мелкая копия», а
встроенная в компилятор обработка примитивов, которая не нуждается и не должна выражаться через
атрибут типа Dup.

```yaoxiang
# Примитивные типы значений: компилятор автоматически копирует значение (не Dup)
x: Int = 42
y = x          # Копирование значения, x и y полностью независимы
print(x)       # ✅

# Dup: мелкая копия, копирование handle с общими данными
view: &Point = &point
view2 = view    # ✅ Dup: копирование токена, оба указывают на один и тот же point
print(view.x)   # ✅

# Clone: явное глубокое копирование, создание независимой копии
backup = big_struct.clone()  # Явный вызов

# Ограничения generics
dup_use: (T: Dup) -> T = x         # T: Dup → можно мелко копировать
clone_use: (T: Clone) -> T = x.clone()  # T: Clone → можно глубоко копировать
```

> **Примечание**: `Send`/`Sync` не являются видимыми пользователю trait. Безопасность межзадачных
> операций обеспечивается ключевым словом `ref` и полностью автоматической обработкой компилятором —
> `ref` автоматически выбирает Rc или Arc, пользователю не нужно понимать Send/Sync.

```yaoxiang
# Trait Iterator (используется синтаксис (Item: Type) -> Type)
Iterator: (Item: Type) -> Type = {
    next: (Self) -> Option(Item),
    has_next: (Self) -> Bool,

collect_all: (T: Type, I: Iterator(T))(iter: I) -> List(T) = {
    result: List(T) = List(T)
    while iter.has_next() {
        if let Some(item) = iter.next() {
            result.push(item)
        }
    }
    return result
}

# Реализация Iterator для Array
# Используется синтаксический сахар: Array.Item, Array.next, Array.has_next
Array.has_next: (T: Type)(self: Array(T)) -> Bool = {
    return self.index < self.length
}

Array.next: (T: Type)(self: Array(T)) -> Option(T) = {
    if has_next(self) {
        item = self.data[self.index]
        self.index = self.index + 1
        return Option.some(item)
    } else {
        return Option.none()
    }
}

Array.Item: (T: Type)(arr: Array(T)) -> T = {
    return arr.data[0]
}
```

### 4. Compile-time generics

#### 4.1 Параметры констант compile-time

**Ключевое дизайнерское решение**: Маркер `Type` в сигнатуре generics помечает параметры типа
compile-time, а параметры-значения, такие как `Int`, в контексте generics по умолчанию считаются
определимыми compile-time. Ключевое слово `const` не требуется.

```yaoxiang
# ════════════════════════════════════════════════════════
# Параметры констант compile-time: Int в generics по умолчанию определим compile-time
# ════════════════════════════════════════════════════════

# Факториал compile-time: N должен быть литералом, известным compile-time
factorial: (N: Int) -> (n: N) -> Int = {
    return match n {
        0 => 1,
        _ => n * factorial(n - 1)
    }
}

# Сложение compile-time
add: (a: Int, b: Int) -> (a: a, b: b) -> Int = a + b

# ════════════════════════════════════════════════════════
# Массивы констант compile-time
# ════════════════════════════════════════════════════════
StaticArray: (T: Type, N: Int) -> Type = {
    data: Array(T, N),  # Массив с размером, известным compile-time
    length: N,
}

# Использование
arr: StaticArray(Int, factorial(5))  # StaticArray(Int, 120), компилятор вычисляет compile-time
```

#### 4.2 Вычисления compile-time

```yaoxiang
# ════════════════════════════════════════════════════════
# Примеры вычислений compile-time
# ════════════════════════════════════════════════════════

# Компилятор вычисляет compile-time вызовы функций с литеральными типами
SIZE: Int = factorial(5)  # Значение compile-time: 120

# Использование типа Matrix
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),
}

# Проверка размерностей compile-time
identity_matrix: (T: Add + Zero + One, N: Int)(size: N) -> Matrix(T, N, N) = {
    matrix: Matrix(T, N, N) = Matrix(T, N, N)()
    for i in 0..size {
        for j in 0..size {
            if i == j {
                matrix.data[i][j] = One::one()
            } else {
                matrix.data[i][j] = Zero::zero()
            }
        }
    }
    matrix
}

# Использование: вычисление compile-time, порождает Matrix(Float, 3, 3)
identity_3x3: Matrix(Float, 3, 3) = identity_matrix(Float, 3)(3)
```

### Never и Void: ⊥ и ⊤ системы типов

Система типов YaoXiang в изоморфизме Карри-Ховарда обладает одновременно ⊥ (ложь/пустой тип) и ⊤
(истина/Unit), представленными двумя встроенными именами типов: `Never` и `Void`:

**Never (⊥)** — три не подлежащих обсуждению ядерных свойства:

1. **Нулевые конструкторы**: Никакой литерал или выражение не может породить значение типа `Never`.
   Это мета-свойство, должно быть встроенным.
2. **Принцип взрыва**: `Never <: T` для любого типа `T`. Значение `Never` может использоваться как
   значение любого типа — именно поэтому код после `assert(false)` всё ещё проходит проверку типов
   (хотя никогда не выполнится).
3. **Маркер расходимости**: `f: (...) -> Never` означает, что `f` гарантированно не возвращается.
   Компилятор использует это для анализа мёртвого кода.

`Never` — это имя встроенного типа, а не ключевое слово, parser не делает различий. Синтаксис
пустого значения и литералов типа не открывается.

**Void (⊤, т.е. Unit)** — имеет ровно одного обитателя (значение void по умолчанию), является
носителем истинного утверждения «всегда истинно». `Void` — единичный элемент для нуль-полевого
типа-произведения, `Never` — единичный элемент для нуль-вариантного типа-суммы — они двойственны.
`x: Void = <по умолчанию>` допустимо, `x: Never = ...` не имеет правой части для записи.

#### 4.3 Верификация compile-time (реализация стандартной библиотеки)

```yaoxiang
# ════════════════════════════════════════════════════════
# Реализация стандартной библиотеки: использование условных типов
# ════════════════════════════════════════════════════════

# Определения стандартной библиотеки
# IsTrue: мост от вселенной значений к вселенной типов — отображение истинности Bool в тип
IsTrue: (b: Bool) -> Type = match b {
    true => Void,      # ⊤, имеет значение, программа продолжается
    false => Never,    # ⊥, без значения, расходимость
}

# Assert: примитив уточнения типа compile-time — типизированное выражение утверждения Bool
Assert: (cond: Bool) -> Type = IsTrue(cond)
#
# cond равно true  → Assert(true)  = Void    (всегда истинно, стирается)
# cond равно false → Assert(false) = Never   (всегда ложно, ошибка компиляции/расходимость)
# cond неразрешимо → конвейер доказательств решает по dispatch-режиму:
#                    CompileTime → Unknown, требует prove
#                    Runtime     → вставка check, инъекция предположения Γ

# Использование 1: в качестве ограничения в определении типа
Array: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    # Проверка compile-time: N должен быть больше 0 (Assert в позиции типа)
    length: Assert(N > 0),
}

# Использование 2: использование в выражении
IntArray: (N: Int) -> Type = StaticArray(Int, N)
# Верификация: размер IntArray(10) равен sizeof(Int) * 10
Assert(size_of(IntArray(10)) == sizeof(Int) * 10)
```

### 5. Условные типы

> **Изоморфизм Карри-Ховарда**: Условные типы с точки зрения Карри-Ховарда представляют
> **case-анализ** в логике. Тип `Bool` соответствует утверждению с двумя возможными значениями
> (True/False), `If` выбирает разные результаты в зависимости от истинности этого утверждения — это
> и есть логический case-дизъюнкт. `match C { True => T, False => E }` по сути выражает: «дано
> утверждение C, когда оно True, заключение — T, когда False, заключение — E».

#### 5.1 Условный тип If

```yaoxiang
# If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Примеры: ветвление compile-time
NonEmpty: (T: Type) -> Type = If(T != Void, T, Never)

Optional: (T: Type) -> Type = If(T != Void, T, Void)

# Верификация compile-time (унифицирована с определением Assert из §4.3)
# Assert: (cond: Bool) -> Type = IsTrue(cond)

# Использование
# Вычисление типа: If(True, Int, String) => Int
# Вычисление типа: If(False, Int, String) => String
```

#### 5.2 Type family

> **Изоморфизм Карри-Ховарда**: Type family — самое прямое воплощение принципа «утверждение есть
> тип». `Add: (A: Type, B: Type) -> Type` — это не «функция сложения, написанная на уровне типов», а
> **конструирование утверждения о сложении натуральных чисел**. `(Zero, B) => B` означает
> «утверждение Add(Zero, B) эквивалентно B», `(Succ(A'), B) => Succ(Add(A', B))` означает «если
> Add(A', B) выполняется, то Add(Succ(A'), B) также выполняется». Это и есть само определение
> сложения в аксиомах Пеано. Проверка типов, верифицирующая прохождение этого match-выражения,
> эквивалентна верификации логической согласованности этого определения.

```yaoxiang
# Преобразование типов compile-time
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,  # По умолчанию
}

# Вычисление на уровне типов
Length: (T: Type) -> Type = match T.length {
    0 => Zero,
    1 => Succ(Zero),
    2 => Succ(Succ(Zero)),
    _ => TooLong,
}

# Сложение на уровне типов (Карри-Ховард: case analysis + рекурсивный вызов, требует проверки завершимости для полной индукции)
Add: (A: Type, B: Type) -> Type = match (A, B) {
    (Zero, B) => B,
    (Succ(A'), B) => Succ(Add(A', B)),
}

# Пример: вычисление compile-time 2 + 3
Two: Type = Succ(Succ(Zero))
Three: Type = Succ(Succ(Succ(Zero)))
Five: Type = Add[Two, Three]  # Succ(Succ(Succ(Succ(Succ(Zero)))))
```

````
### 7. Механизм устранения мёртвого кода

#### 7.1 Анализ графа инстанциации

```rust
// Внутреннее представление компилятора: построение графа зависимостей инстанциации generics
struct InstantiationGraph {
    // Узлы: инстанциации generics
    nodes: HashMap<InstanceKey, InstanceNode>,

    // Рёбра: отношения использования
    edges: HashMap<InstanceKey, Vec<InstanceKey>>,
}

struct InstanceKey {
    generic: FunctionId,  // ID обобщённой функции
    type_args: Vec<TypeId>,  // Аргументы типа
    const_args: Vec<ConstId>,  // Аргументы const
}

// Алгоритм: анализ достижимости
fn eliminate_dead_instantiations(graph: &InstantiationGraph) {
    let mut reachable = HashSet::new();

    // Начинаем с точек входа (main, экспортируемые функции и т.д.)
    let entry_points = find_entry_points();
    for entry in entry_points {
        dfs_visit(entry, &graph, &mut reachable);
    }

    // Не посещённые инстанциации — мёртвый код
    for node in &graph.nodes {
        if !reachable.contains(node.key) {
            eliminate(node);
        }
    }
}
````

#### 9.1 Полный пример обобщённого контейнера

```yaoxiang

    length: Int,

    # Обобщённые методы (T автоматически вводится внешним List(T))
    push: (self: List(T), item: T) -> Void,
    pop: (self: List(T)) -> Option(T),
    map: (R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)),
    filter: (self: List(T), predicate: (T) -> Bool) -> List(T),
    fold: (U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U),
}

# ======== 2. Реализация обобщённых методов ========
# Определение функций в пространстве имён List (префикс List. = принадлежность пространству имён)
# Чтобы вызов через . (list.push(item)) работал, требуется явное связывание: List.push = push[0]
# self — просто имя параметра по соглашению, компилятор смотрит на тип, а не на имя

List.push: (T: Type) -> ((self: List(T), item: T) -> Void) = {
    if self.length >= self.data.length {
        # Расширение
        new_data = Array(T)(self.data.length * 2)
        for i in 0..self.length {
            new_data[i] = self.data[i]
        }
        self.data = new_data
    }
    self.data[self.length] = item
    self.length = self.length + 1
}

List.pop: (T: Type) -> ((self: List(T)) -> Option(T)) = {
    if self.length > 0 {
        self.length = self.length - 1
        return Option.some(self.data[self.length])
    } else {
        return Option.none()
    }
}

List.map: (T: Type, R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)) = {
    result = List(R)()
    for i in 0..self.length {
        result.push(f(self.data[i]))
    }
    return result
}

List.filter: (T: Type) -> ((self: List(T), predicate: (T) -> Bool) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        if predicate(self.data[i]) {
            result.push(self.data[i])
        }
    }
    return result
}

List.fold: (T: Type, U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U) = {
    result = initial
    for i in 0..self.length {
        result = f(result, self.data[i])
    }
    return result
}

# ======== 3. Использование type constraints ========
# Реализация Clone для List
List.clone: (T: Clone) -> ((self: List(T)) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        result.push(self.data[i].clone())
    }
    return result
}

# ======== 4. Примеры использования ========
# Создание обобщённого List
numbers = List(Int)()
numbers.push(1)
numbers.push(2)
numbers.push(3)

# Использование обобщённых методов
doubled = numbers.map((x) => x * 2)
evens = numbers.filter((x) => x % 2 == 0)

# Использование fold для вычисления
sum = numbers.fold(0, (acc, x) => acc + x)  # sum = 6

# Композиция generics
sum_of_evens = numbers
    .filter((x) => x % 2 == 0)
    .map((x) => x * 2)
    .fold(0, (acc, x) => acc + x)  # sum_of_evens = 8
```

#### 9.2 Пример обобщённого алгоритма

```yaoxiang
# ======== 1. Обобщённый алгоритм сортировки ========
Comparator: (T: Type) -> Type = {
    compare: (T, T) -> Int,  # -1 если a < b, 0 если a == b, 1 если a > b
}

# Обобщённая быстрая сортировка
quicksort: (T: Clone) -> ((array: Array(T), cmp: Comparator(T)) -> Array(T)) = {
    if array.length <= 1 {
        return array.clone()
    }

    pivot = array[array.length / 2]
    left = Array(T)()
    right = Array(T)()

    for i in 0..array.length {
        if i == array.length / 2 {
            continue
        }
        item = array[i]
        comparison = cmp.compare(item, pivot)
        if comparison < 0 {
            left.push(item)
        } else {
            right.push(item)
        }
    }

    sorted_left = quicksort(left, cmp)
    sorted_right = quicksort(right, cmp)

    result = sorted_left.clone()
    result.push(pivot)
    result.extend(sorted_right)
    return result
}

# ======== 2. Реализация IntComparator ========
# Реализация через перегрузку функций
compare: (a: Int, b: Int) -> Int = {
    if a < b {
        return -1
    } else if a > b {
        return 1
    } else {
        return 0
    }
}

# ======== 3. Примеры использования ========
# Сортировка массива Int
numbers = Array(Int)(3, 1, 4, 1, 5, 9, 2, 6)
sorted = quicksort(numbers, Comparator(Int)())

# Сортировка массива String (требует StringComparator)
strings = Array(String)("hello", "world", "foo", "bar")
sorted_strings = quicksort(strings, Comparator(String)())
```

#### 9.3 Пример compile-time generics

```yaoxiang
# ======== 1. Тип матрицы compile-time ========
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),

    # Проверка размерностей compile-time: используется тип Assert из стандартной библиотеки
    _assert: Assert(Rows > 0),  # Rows > 0, иначе ошибка компиляции
    _assert: Assert(Cols > 0),  # Cols > 0, иначе ошибка компиляции

    # Операции над матрицами
    multiply: (M: Int) -> ((self: Matrix(T, Rows, Cols), other: Matrix(T, Cols, M)) -> Matrix(T, Rows, M)) = {
        result = Matrix(T, Rows, M)()
        for i in 0..Rows {
            for j in 0..M {
                sum = Zero::zero()
                for k in 0..Cols {
                    sum = sum + self.data[i][k] * other.data[k][j]
                }
                result.data[i][j] = sum
            }
        }
        return result
    }
}

# ======== 2. Создание матрицы compile-time ========
identity: (T: Add + Multiply + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    for i in 0..N {
        for j in 0..N {
            if i == j {
                matrix.data[i][j] = One::one()
            } else {
                matrix.data[i][j] = Zero::zero()
            }
        }
    }
    return matrix
}

# ======== 3. Примеры использования ========
# Создание матрицы с размером, известным compile-time
# Матрица 2x3
matrix_2x3 = Matrix(Float, 2, 3)()
matrix_2x3.data[0][0] = 1.0
matrix_2x3.data[0][1] = 2.0
matrix_2x3.data[0][2] = 3.0
matrix_2x3.data[1][0] = 4.0
matrix_2x3.data[1][1] = 5.0
matrix_2x3.data[1][2] = 6.0

# Матрица 3x2
matrix_3x2 = Matrix(Float, 3, 2)()
matrix_3x2.data[0][0] = 7.0
matrix_3x2.data[0][1] = 8.0
matrix_3x2.data[1][0] = 9.0
matrix_3x2.data[1][1] = 10.0
matrix_3x2.data[2][0] = 11.0
matrix_3x2.data[2][1] = 12.0

# Умножение матриц: 2x3 * 3x2 = 2x2
result = matrix_2x3.multiply(matrix_3x2)

# Верификация compile-time: тип result — Matrix(Float, 2, 2)
# Единичная матрица 2x2
identity_3x3 = identity(Float, 3)()
```

## Компромиссы

### Преимущества

1. **Zero-cost abstractions**
   - Мономорфизация compile-time, без накладных расходов в runtime
   - Без виртуальных функций, без RTTI

2. **Устранение мёртвого кода**
   - Анализ compile-time, инстанциация только используемых generics
   - Раздувание кода управляемо

3. **Альтернатива макросам**
   - Type-safe кодогенерация
   - Дружелюбность к IDE, понятные сообщения об ошибках

4. **Вычисления compile-time**
   - Compile-time generics поддерживают вычисления compile-time
   - Такие возможности, как верификация размерностей
   - Без ключевого слова `const`, чистые type constraints

### Недостатки

1. **Время компиляции**
   - Инстанциация generics увеличивает время компиляции
   - Решение ограничений может быть медленным

2. **Потребление памяти**
   - Увеличивается потребление памяти компилятором
   - Механизмы кэширования требуют памяти

3. **Сложность реализации**
   - Сложный решатель ограничений
   - Сложный движок вычислений на уровне типов

4. **Диагностика ошибок**
   - Ошибки generics могут быть сложными
   - Требуются понятные подсказки об ошибках

### Меры по смягчению

1. **Стратегии кэширования**
   - Кэширование результатов инстанциации
   - LRU-кэш с ограничением памяти

2. **Инкрементальная компиляция**
   - Кэширование результатов компиляции
   - Инкрементальная инстанциация

3. **Подсказки об ошибках**
   - Понятные сообщения об ошибках
   - Подсказки по выводу параметров generics

4. **Параллельная компиляция**
   - Параллельная инстанциация generics
   - Многопоточное решение ограничений

## Альтернативные подходы

| Подход                         | Почему не выбран                             |
| ------------------------------ | -------------------------------------------- |
| Только базовые generics        | Невозможно заменить сложные макросы          |
| Чистая система макросов        | Нет type safety, плохие сообщения об ошибках |
| Только ограничения-зависимости | Недостаточная гибкость                       |
| Runtime generics               | Накладные расходы на производительность      |

### Риски

| Риск                          | Воздействие                  | Мера по смягчению                     |
| ----------------------------- | ---------------------------- | ------------------------------------- |
| Сложность решения ограничений | Слишком долгая компиляция    | Инкрементальное решение + кэширование |
| Раздувание кода               | Бинарный файл слишком велик  | DCE + пороговое управление            |
| Сложность реализации          | Увеличение цикла разработки  | Поэтапная реализация                  |
| Диагностика ошибок            | Плохой пользовательский опыт | Подробные сообщения об ошибках        |

### Синтаксис BNF

```bnf
# Параметры generics используют унифицированный синтаксис (), как часть функционального типа
# Например: map: (T: Type, R: Type) -> ((list: List(T), f: (T) -> R) -> List(R))

# Type constraint (в параметрах generics)
type_bound ::= identifier
             | identifier '+' identifier ('+' identifier)*

# Объявление параметра (тип + имя)
parameter ::= identifier ':' type

parameters ::= parameter (',' parameter)*

# Объявление функции: name: type = expression
# Параметры generics — первая группа параметров функционального типа: (T: Type) -> ((params) -> return)
function ::= identifier ':' type '=' (expression | block)

# Объявление метода: Type.method: type = expression
method ::= identifier '.' identifier ':' type '=' (expression | block)

# Определение типа (унифицированный синтаксис Binding)
# Обобщённый тип, например List: (T: Type) -> Type = { ... }
generic_type ::= identifier ':' type '=' type_expression

# Type в параметрах generics автоматически заполняется компилятором из типов фактических аргументов
# Например, в map(numbers, f) T извлекается из numbers: List(Int), R — из f: (Int) -> String
```
