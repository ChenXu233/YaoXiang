# RFC-011: Проектирование системы обобщённых типов — абстракция с нулевой стоимостью и замена макросов

## Аннотация

В данном документе определена **система обобщённых типов языка YaoXiang**, реализующая абстракцию с нулевой стоимостью посредством мощных возможностей обобщений, сокращая зависимость от макросов через compile-time оптимизацию и предоставляя механизм устранения мёртвого кода.

**Ключевые решения**:

- **Унифицированный синтаксис сигнатур**: `(T: Type, R: Type) -> ...` — обобщённые параметры унифицированы с обычными
- **Механизм самоописания Type**: `Type` является языковым примитивом; позиции `Type` в сигнатурах автоматически заполняются выводом
- **Ограничения типов**: `T: Dup + Add` — множественные ограничения, ограничения на function type
- **Ассоциированные типы**: `Iterator: (Item: Type) -> Type = { next: () -> Option(Item), has_next: () -> Bool }`
- **Compile-time обобщения**: `N: Int` — параметры-значения compile-time, константная инстанциация
- **Условные типы**: `If: (C: Bool, T: Type, E: Type) -> Type` — вычисления на уровне типов, type family

**Ценность**:

- Абстракция с нулевой стоимостью: compile-time мономорфизация, без накладных расходов runtime
- Устранение мёртвого кода: анализ графа инстанциации + оптимизация LLVM
- Замена макросов: обобщения охватывают 90% сценариев использования макросов
- Type safety: проверки на этапе компиляции, дружелюбие к IDE
- **Явное лучше неявного**: `Type` самоописание, автоматический вывод компилятором

## Идея Universe of Types и типы, зависимые от значений

Система обобщённых типов YaoXiang построена на идее **Universe of Types** — ментальной модели, объединяющей все концепции языка в иерархическую структуру. Ключевая инновация заключается в продвижении **типов, зависимых от значений**, до первоклассных граждан уровня Type2.

### Что такое типы, зависимые от значений?

**Тип, зависимый от значений** — это тип, который зависит от одного или нескольких **значений** (а не только от других типов). Эти значения могут вычисляться на этапе компиляции, обеспечивая гарантии type safety уже на стадии компиляции.

```yaoxiang
# Традиционные обобщения: параметры-типы
List: (T: Type) -> Type

# Типы, зависимые от значений: параметры-значения
Array: (T: Type, N: Int) -> Type  # Тип массива зависит от значения длины N
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type  # Тип матрицы зависит от числа строк и столбцов
```

### Иерархия именования container types

На языковом уровне существует три концепции контейнеров; коренное различие между ними — принадлежность информации о длине:

| Тип             | Длина         | Семантика                              | Основа                                 |
| --------------- | ------------- | ------------------------------------- | -------------------------------------- |
| `Array(T, N)`   | тип           | **Фиксированная длина**, N в типе      | Примитив ядра (стек/inline приоритет)  |
| `Vec(T)`        | runtime значение | **Runtime длина**, изменяемый буфер   | Примитив ядра (куча, непрерывный буфер)|
| `List(T)`       | runtime значение | Тип стандартной библиотеки            | Библиотека: `{ data: Vec(T), length: Int }` |

Принципы разделения ответственности:

- **`Array(T, N)` — единственная форма, где длина в типе** — длина является compile-time константой, поэтому возможен compile-time отказ при выходе за границы (`a[5]` при `a: Array(Int, 3)` вызывает ошибку компиляции, см. «Compile-time проверка размерностей» ниже).
- **`Vec(T)` — минимальная основа с runtime длиной** — предоставляет только четыре операции: «может выделить, может получить длину, может читать/писать, может расширяться». Стратегия ёмкости, фактор роста, возможность сжатия — всё это не входит в его компетенцию. Это строительный материал для других контейнеров.
- **`List(T)` — библиотечный тип, не примитив** — определён на YaoXiang в `std.list` (`{ data: Vec(T), length: Int }`), пользуется тем же статусом, что и пользовательские обобщённые record types. Вся стратегия изменяемой семантики (когда расширять, на сколько, возможность совместного использования) — в библиотеке. Компилятор не участвует.

Формы конструкции `Vec(T)` (два слоя: сначала параметры типа, затем параметры конструкции):

```yaoxiang
# Пустая конструкция — длина 0, элементы добавляются позже
v = Vec(Int)()

# Конструкция по элементам — длина определяется числом элементов
w = Vec(Int)(1, 2, 3)          # длина 3

# Распределение слотов — выделение n слотов с нулевыми значениями
buf = Vec(Int)(len=64)         # длина 64, все элементы — нулевые значения
```

> Распределение слотов использует **именованную форму** (`len=`) вместо позиционной: позиционная форма с одним целым числом создаёт неоднозначность с «вектором с одним элементом» (`Vec(Int)(64)` невозможно различить как «длина 64» или «содержит один элемент 64»). Это согласуется с унифицированными правилами конструкции обобщений: именованные аргументы связываются по имени и не зависят от позиционного вывода.
>
> Это единственный примитив, необходимый для расширения `List` — `List` при необходимости выделяет новые слоты и перемещает элементы:
>
> ```yaoxiang
> new_data = Vec(T)(len=self.data.length * 2)
> ```
>
> Когда расширять, на сколько, возможность сжатия — всё определяет `List`. `Vec` не реализует стратегию ёмкости.

Снизу вверх: производительность убывает, гибкость возрастает: `Array` > `Vec` > `List`.

> Основание для именования: `Vec`/`vector` в mainstream языках (Rust/C++) обозначает последовательность с runtime длиной и возможностью роста; `Array` обозначает фиксированную длину.

По сравнению с традиционными обобщениями, типы YaoXiang, зависимые от значений, обладают следующими преимуществами:

### Уровни Universe of Types и типы, зависимые от значений

Идея Universe of Types разделяет концепции языка по семантическим ролям на разные уровни. Типы, зависимые от значений, находятся на **уровне Type2**:

| Уровень        | Роль                                     | Пример                                                                                                              |
| -------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Type-1         | Значения                                | `42`, `factorial(5)`, сами функции                                                                                 |
| Type0          | Ключевое слово meta-типа                 | `Type`                                                                                                              |
| Type1          | Конкретные типы                         | `Int`, `String`, `Array(Int, 3)`                                                                                    |
| **Type2**      | **Функции/конструкторы типов/зависимые от значений типы** | `add: (Int, Int) -> Int`, `Array: (T: Type, N: Int) -> Type`, `Matrix: (T: Type, Rows: Int, Cols: Int) -> Type` |

**Ключевое решение**: функции, конструкторы типов и типы, зависимые от значений, на уровне Type2 **унифицированы синтаксически** — все имеют форму `(params) -> result`:

- Обычные функции: `(Int, Int) -> Int` → возвращаемое значение — значение
- Конструкторы типов: `(T: Type) -> Type` → возвращаемое значение — тип
- Типы, зависимые от значений: `(T: Type, N: Int) -> Type` → возвращаемое значение — тип, зависящий от параметра-значения N

> **Изоморфизм Curry-Howard**: эта унификация — не случайность. Изоморфизм Curry-Howard устанавливает, что «типы — это высказывания, программы — это доказательства». Function type `A → B` соответствует логическому импликации «если A, то B»; обобщение `(T: Type) -> Type` соответствует универсальной квантификации «для всех типов T»; тип, зависимый от значений, `(n: Int) -> Type` соответствует «для каждого целого n существует тип». Унификация функций, конструкторов типов и типов, зависимых от значений, на уровне Type2, по сути, унифицирует «доказательства» и «вычисления» в одну концепцию — **конструктивные доказательства**. Это прямое воплощение изоморфизма Curry-Howard в дизайне языка: одна форма (`(params) -> result`) одновременно выражает логические высказывания и вычислительные процессы.

### Гарантии compile-time детерминизма

Система Universe of Types YaoXiang требует: **всё на уровне Type является compile-time детерминированным**.

```yaoxiang
# Пример compile-time проверки размерностей
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),
    # Compile-time проверка: размерности должны быть положительными
    _assert: Assert(Rows > 0),
    _assert: Assert(Cols > 0),
}

# Создание единичной матрицы 3x3 — выполняется на этапе компиляции
identity: (T: Add + Zero + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    # ...
}

# Compile-time вычисление: factorial(3) = 6, размер массива определяется на этапе компиляции
arr: Array(Int, factorial(3)) = Array(Int, 6)()
```

Компилятор автоматически:

1. Обнаруживает вызовы функций в позициях типов
2. Выполняет compile-time проверку завершения (см. механизм проверки завершения ниже)
3. Вычисляет на этапе компиляции
4. Встраивает результат в генерируемый тип

### Сценарии применения типов, зависимых от значений

#### Compile-time проверка размерностей

```yaoxiang
# Умножение матриц: compile-time проверка соответствия размерностей
multiply: (T: Add + Multiply + Zero,
           Rows: Int, Cols: Int, M: Int) -> (((
    a: Matrix(T, Rows, Cols),
    b: Matrix(T, Cols, M)
) -> Matrix(T, Rows, M)) = {
    # Compile-time проверка: a.Cols == b.Rows, иначе ошибка компиляции
    result = Matrix(T, Rows, M)()
    # ...
}

# Ошибка перехватывается на этапе компиляции:
# multiply(matrix_2x3, matrix_4x2)  # Ошибка компиляции: 2 != 4
```

#### Type-safe размеры массивов

```yaoxiang
# Размер массива — compile-time константа
Array: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    length: N,
}

# N — compile-time константа, может использоваться для вычислений на уровне типов
first_three: Array(Int, 3) = Array(Int, 3)(1, 2, 3)
# first_three.length == 3 (известно на этапе компиляции)
```

#### Compile-time охват граничных ошибок

> **Описание состояния реализации**: Container types были деспециализированы — `Array(T, N)` является const泛型 конструктором, литеральные позиции, предикат membership `in` реализованы. `Array(T, N)` литеральные позиции: N и тип элемента уже принудительно проверены на этапе компиляции (E1002), **N уже достоверен** — цель данного раздела — построить механизм на основе «аннотации N == runtime длина». Текущий выход за границы `[]` индекса (E6003) и отсутствие ключа в Dict (E6008) являются **переходным состоянием runtime ошибок**; данный раздел о типах, зависимых от значений, — это механизм для переноса этих граничных ошибок на **этап компиляции**:
>
> - const индекс: `a[5]` (5 — compile-time константа) при `a: Array(Int, 3)` отклоняется напрямую на этапе компиляции;
> - Значение-индекс: `a[i]` требует предусловие `i < len(a)`, доказываемое контрактом типа, зависящего от значения;
> - Предикат `in` является основой предусловия по логике Хоара: `n in 1..10`, `x in some_set` — оба являются высказываниями, доказуемыми на этапе компиляции.
>
> Полный дизайн Refinement Types при внедрении дополнит данный раздел.

#### Условные типы

```yaoxiang
# Типовый If
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Типовые семейства
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,
}
```

#### Обобщённые функции

```yaoxiang
# map: обобщённая функция, типы параметров T, R определяются на этапе компиляции
map: (T: Type, R: Type) -> (
    (list: List(T), f: (x: T) -> R) -> List(R)
) = (list, f) => {
    result = List(R)()
    for x in list {
        result.push(f(x))
    }
    return result
}

# При использовании полностью прозрачно, типы выводятся автоматически
numbers = List(Int)()   # двухслойная форма значения-конструкции (см. §9.1); элементы заполняются через push
numbers.push(1)
numbers.push(2)
numbers.push(3)
doubled = map(numbers, (x) => x * 2)  # Выводится как map[Int, Int]
```

### Механизм проверки завершения (унифицированный с RFC-027)

Compile-time вычисление типов, зависимых от значений, должно **гарантированно завершаться**, иначе система типов войдёт в бесконечный цикл. Проверка завершения выполняется **приоритетно в автоматическом режиме** через compile-time доказательственный конвейер RFC-027 — компилятор сначала автоматически исследует метрики; доказуемая рекурсия/циклы проходят; если автоматический поиск не дал результатов и явная мера не предоставлена, выдаётся ошибка компиляции (RFC-027 §6.9 предоставляет fallback с явными мерами в типе). **Синтаксис аннотаций не предоставляется**: `//! decreases`, `/*! invariant !*/` из RFC-022 были упразднены вместе с RFC-022; спецификация — это сама аннотация типа.

> **Критерий триггера (RFC-027 §7)**: Обязанность проверки завершения активируется **Refinement Types** — тип, подвергаемый уточнению, входит в режим верификации. Обычные типы без уточнений не входят в режим верификации и не генерируют обязательств проверки завершения.

#### Проверка завершения рекурсивных функций

Компилятор для рекурсивных функций с уточнёнными сигнатурами проверяет, убывают ли параметры рекурсивных вызовов строго на каждом рекурсивном пути (RFC-027 §6.7). Аннотации спецификаций не требуются:

```yaoxiang
# Рекурсия с уточнённой сигнатурой: без //! requires/ensures/decreases, компилятор автоматически исследует убывание
factorial: (n: NonNegative(n)) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)  # Компилятор исследует: n-1 < n → убывает → завершается
}
```

| ------------------------------------------------- | ---------------------------- |
| Компилятор может исследовать убывание (напр. `n-1`) | Проходит                    |
| Не удалось исследовать, но мера дана в типе (§6.9) | SMT проверяет, при выполнении — проходит |
| Не удалось исследовать и нет явной меры / мера опровергнута SMT | Ошибка компиляции  |
| Сигнатура без уточнения (не входит в режим верификации) | Не генерирует обязательств проверки завершения |

#### Проверка завершения циклов

Циклы не требуют аннотаций `: Invariant(...)` или `: decreases(...)`. Аннотации уточнённых типов для переменных (например, `UpTo(n)`) одновременно предоставляют инвариант цикла и границу меры. Компилятор по приоритету尝试四种 метода исследования меры, найдя один — останавливается (RFC-027 §6.1–6.5):

1. **Автоматический синтез линейной rank-функции** — извлечение границ переменных из типовых аннотаций, перечисление линейных комбинаций, SMT-проверка m ≥ 0 и m' < m на всех путях
2. **Подсчёт нарушений предиката** (экспериментальный) — извлечение из определения целевого типа (например, `Sorted`) violation_count, покрытие смежных перестановок/перемещений
3. **Шаблоны ограниченного возрастания/убывания** — `v += const` → мера `upper - v` (вырожденный случай стратегии 1, самый быстрый путь)
4. **Метрика мультипликативного масштабирования** — `v *= const` (const > 1) → мера `ceil(log_const(upper / v))`

```yaoxiang
sum: (arr: Array(Int, n)) -> Int = {
    mut i: UpTo(arr.len) = 0   # Типовая аннотация предоставляет верхнюю границу arr.len и нижнюю 0 → вход в режим верификации
    while i < arr.len {
        # Компилятор автоматически исследует: мера arr.len - i, каждая итерация строго убывает на 1 → завершение доказано
        s += arr[i]; i += 1
    }
    return s
}
```

Когда автоматический поиск не даёт результатов, можно дать имя циклу и предоставить меру в типе (RFC-027 §6.9):

```yaoxiang
loop: (n: Int) -> Int = {
    mut i = 0
    acc: Terminates(n - i) = while i < n { i = i + 1 }
    return acc
}
```

#### Преимущества

- **Безопасность**: гарантия обязательного завершения compile-time вычислений, предотвращение бесконечных циклов системы типов
- **Унификация**: проверка завершения и верификация корректности (генерация VC) используют общий compile-time доказательственный конвейер (RFC-027), без отдельного синтаксиса спецификаций
- **Приоритет автоматизации**: компилятор автоматически исследует метрики из типовых аннотаций; если доказательство найдено — проходит; если автоматический поиск не дал результатов, можно предоставить меру в типе (`Terminates`), по-прежнему проверяемую SMT — не требует ручного написания синтаксиса `decreases`

## Мотивация

### Зачем нужна мощная система обобщений?

Возможности обобщений в текущих mainstream языках ограничены:

| Язык          | Возможности обобщений        | Проблемы                                        |
| ------------- | ---------------------------- | ----------------------------------------------- |
| Java          | Ограниченные типы            | Compile-time мономорфизация, без специализации обобщений |
| C#            | Ограничения обобщений         | Runtime проверка типов, накладные расходы производительности |
| Rust          | Обобщения + Trait            | Система Trait сложна, крутая кривая обучения   |
| C++           | Шаблоны                      | Специализация шаблонов сложна, плохие сообщения об ошибках |
| **YaoXiang**  | **Типы, зависимые от значений** | **Типы могут зависеть от значений, compile-time проверка размерностей, гарантия завершения** |

### Ключевые противоречия

1. **Производительность vs гибкость**: гибкость runtime vs compile-time оптимизация
2. **Сложность vs простота**: мощная система типов vs удобство использования
3. **Макросы vs обобщения**: генерация кода макросами vs type-safe обобщения
4. **Зависимость от значений vs type safety**: традиционные обобщения не могут верифицировать размерности на этапе компиляции

### Ключевые преимущества типов, зависимых от значений

**Типы, зависимые от значений**, YaoXiang — ключевое преимущество перед традиционными обобщениями:

| Преимущество           | Описание                                                           |
| ---------------------- | ------------------------------------------------------------------ |
| **Тип зависит от значения** | `Array: (T: Type, N: Int) -> Type` позволяет типу зависеть от конкретного значения |
| **Compile-time вычисление** | Вызовы функций в типовых позициях вычисляются на этапе компиляции, результат встраивается в тип |
| **Проверка размерностей** | `Matrix(Float, 3, 3)` верифицирует размерности матрицы на этапе компиляции |
| **Вычисления на уровне типов** | `If`, `Match` и другие условные типы поддерживают вычисления на уровне типов |
| **Гарантия завершения** | Проверка завершения compile-time (автоматический синтез метрик) обеспечивает обязательное завершение compile-time вычислений |

```yaoxiang
# Compile-time проверка, недоступная в C++/Rust
matrix: Matrix(Float, factorial(3), factorial(2)) = ...
# Compile-time вычисление: factorial(3) = 6, factorial(2) = 2
# Тип: Matrix(Float, 6, 2)

# Несоответствие размерностей перехватывается на этапе компиляции
identity: Matrix(Float, 3, 3) = ...
# multiply(matrix_2x3, identity_3x3)  # Ошибка компиляции: 2 != 3
```

### Ценность системы обобщений

```yaoxiang
# Пример: унифицированный дизайн API
# Операции map для различных типов контейнеров

# Традиционный подход: отдельная реализация для каждого типа
map_int_array: (array: Vec(Int), f: Fn(Int) -> Int) -> Vec(Int) = ...
map_string_array: (array: Vec(String), f: Fn(String) -> String) -> Vec(String) = ...
map_int_list: (list: List(Int), f: Fn(Int) -> Int) -> List(Int) = ...
map_string_list: (list: List(String), f: Fn(String) -> String) -> List(String) = ...

# Обобщённый подход: одна обобщённая функция покрывает все типы
map: (T: Type, R: Type)(container: Container(T), f: Fn(T) -> R) -> Container(R) = {
    for item in container {
        result.push(f(item))
    }
    result
}
```

## Цели проектирования

### Ключевые цели

1. **Абстракция с нулевой стоимостью** - обобщённые вызовы эквивалентны вызовам конкретных типов
2. **Устранение мёртвого кода** - compile-time анализ, инстанцируются только используемые обобщения
3. **Замена макросов** - обобщения заменяют 90% сценариев использования макросов
4. **Type safety** - compile-time проверки, без накладных расходов runtime
5. **Дружелюбие к IDE** - интеллектуальные подсказки, чёткие сообщения об ошибках
6. **Типы, зависимые от значений** - типы могут зависеть от значений, поддержка compile-time проверки размерностей
7. **Безопасность compile-time вычислений** - гарантия завершения compile-time вычислений через проверку завершения (автоматический синтез метрик RFC-027)

### Принципы проектирования

- **Compile-time детерминизм**: обобщённые параметры определяются на этапе компиляции
- **Приоритет мономорфизации**: генерация конкретного кода, избегание виртуальных вызовов
- **Ограничения как драйверы**: type constraints направляют инстанциацию
- **Оптимизация под платформу**: специализация поддерживает платформенно-специфичную оптимизацию
- **Унификация Universe of Types**: функции/конструкторы типов/типы, зависимые от значений, унифицированы на уровне Type2
- **Гарантия завершения**: вызовы функций в типовых позициях должны доказать завершение

## Предложение

### 1. Базовые обобщения

#### 1.1 Параметры обобщённых типов

> **Ключевое правило**: Определения обобщённых типов **должны явно аннотироваться `: Type`**, иначе HM выведет их как функции.
>
> | Запись                               | Значение                    |
> | ------------------------------------ | --------------------------- |
> | `List: (T: Type) -> Type = {...}`    | ✅ Конструктор типа         |
> | `List = {...}`                       | ❌ HM выводит как функцию, не тип |

```yaoxiang
# Определение обобщённого типа (обязательно : Type)
Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self
}

Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self
}

List: (T: Type) -> Type = {
    data: Vec(T),
    length: Int,
    push: (self: List(T), item: T) -> Void,   # self — это соглашение об именовании, не ключевое слово
    get: (self: List(T), index: Int) -> Option(T),
}

# Обобщённая функция (без : Type, HM выводит как функцию)
map: (T: Type, R: Type) -> ((opt: Option(T), f: Fn(T) -> R) -> Option(R)) = {
    return match opt {
        some => Option.some(f(some)),
        none => Option.none(),
    }
}

# Обобщённое ограничение (прямое выражение, return можно опустить в однострочном)
clone: (T: Clone)(value: T) -> T = value.clone()

# Несколько параметров типов
combine: (T: Type, U: Type) -> ((a: T, b: U) -> (T, U)) = (a, b)
```

### Синтаксис вызова обобщённых функций

#### 1.1 Унифицированный синтаксис сигнатур

```yaoxiang
# Обобщённые функции используют унифицированный синтаксис сигнатур (T: Type, R: Type)
map: (T: Type, R: Type) -> ((list: List(T), f: (x: T) -> R) -> List(R)) = ...

# Несколько параметров типов
combine: (T: Type, U: Type) -> ((a: T, b: U) -> (T, U)) = (a, b)
```

#### 1.2 Механизм самоописания Type

`Type` является языковым примитивом; компилятор естественно распознаёт позиции `Type` в сигнатурах и автоматически выводит и заполняет их из фактических типов аргументов.

```yaoxiang
# Компилятор автоматически выводит обобщённые параметры
numbers: List(Int) = List(Int)()
#         ^^^^^^^^   ^^^^^^^^
#         Объявление типа   Конструктивный вызов: Int заполняет T, () — значение-конструкция

# Вывод при вызове функции
numbers: List(Int) = List(Int)()
f: (x: Int) -> String = (x) => x.to_string()
strings: List(String) = map(numbers, f)
# Компилятор выводит: T=Int, R=String
```

#### 1.3 Мономорфизация

```yaoxiang
# Исходный код
map: (T: Type, R: Type) -> ((list: List(T), f: (x: T) -> R) -> List(R)) = {
    result: List(R) = List(R)()
    for x in list {
        result.push(f(x))
    }
    return result
}

# Точки использования
int_list: List(Int) = List(Int)()
doubled: List(Int) = map(int_list, (x: Int) => x * 2)  # Инстанциация map[Int, Int]

string_list: List(String) = List(String)()
uppercased: List(String) = map(string_list, (s: String) => s.to_uppercase())  # Инстанциация map[String, String]

# После компиляции (эквивалентный код)
map_Int_Int: (list: List(Int), f: (Int) -> Int) -> List(Int) = {
    result: List(Int) = List(Int)()
    for x in list {
        result.push(f(x))
    }
    return result
}

map_String_String: (list: List(String), f: (String) -> String) -> List(String) = {
    result: List(String) = List(String)
    for s in list {
        result.push(f(s))
    }
    return result
}
```

### 2. Система ограничений типов

#### 2.1 Одиночные ограничения

```yaoxiang
# Определение базового trait (interface type)
Clone: Type = {
    clone: (Self) -> Self,
}

Display: Type = {
    fmt: (Self, Formatter) -> Result,
}

Debug: Type = {
    fmt: (Self, Formatter) -> Result,
}

# Использование ограничений: прямое объявление type constraints в сигнатуре
clone: (T: Clone) -> (value: T) -> T = value.clone()

debug_print: (T: Debug)(value: T) -> Void = {
    formatter = Formatter.new()
    value.fmt(formatter)
    print(formatter.to_string())
}
```

#### 2.2 Множественные ограничения

```yaoxiang
# Синтаксис множественных ограничений
combine: (T: Clone + Add)(a: T, b: T) -> T = {
    a.clone() + b
}

# Сортировка обобщённого контейнера
sort: (T: Clone + PartialOrd)(list: List(T)) -> List(T) = {
    # Реализация алгоритма сортировки
    result: List(T) = list.clone()
    quicksort(&mut result)
    return result
}

# Ограничения на function type
map: (T: Type, R: FnMut(T))(array: Vec(T), f: R) -> Vec(R) = {
    result: Vec(R) = Vec()
    for item in array {
        result.push(f(item))
    }
    return result
}

# Использование
doubled: Vec(Int) = map(Vec(1, 2, 3), (x: Int) => x * 2)  # Компилятор выводит
```

> **Источник имён ограничений (заметка 2026-09-22)**: Ограничения операторов `Add` / `Subtract` / `Multiply` / `Divide` / `Modulo` определены и реализованы в [RFC-011b: Перегрузка операторов и интерфейсно-драйверные операторы](./011b-operator-overloading.md) — `T: Add` ≜ зарегистрированная инстанциация интерфейса `Add(T, T, T)` (три параметра типа, тип результата `O` явный). `Zero` / `One` / `PartialOrd` / `Fn` / `FnMut` в настоящее время **не имеют определения**, являются висячими именами ограничений; последующие RFC будут их реализовывать отдельно; до того примеры с этими именами являются иллюстративными.

#### 2.3 Ограничения на function type

```yaoxiang
# Ограничения на функции высшего порядка
call_twice: (T: Type, F: Fn() -> T)(f: F) -> (T, T) = (f(), f())

call_with_arg: (T: Type, U: Type, F: Fn(T) -> U)(arg: T, f: F) -> U = f(arg)

compose: (A: Type, B: Type, C: Type, F: Fn(A) -> B, G: Fn(B) -> C)(a: A, f: F, g: G) -> C = g(f(a))

# Примеры использования
result: Int = call_with_arg(42, (x: Int) => x * 2)  # result = 84
composed: String = compose(
    "hello",
    (s: String) => s.to_uppercase(),
    (s: String) => s + " WORLD"
)  # composed = "HELLO WORLD"
```

#### 2.4 Встроенные marker trait: Dup и Clone

**Три семантики копирования**:

| Тип               | Значение                                   | Способ активации        | Сценарии применения                    |
| ----------------- | ----------------------------------------- | ---------------------- | --------------------------------------- |
| **Примитивное значение** | Присваивание автоматически копирует значение, два значения полностью независимы | Присваивание/передача параметров автоматически | Int, Float, Bool, Char            |
| **Dup**           | Поверхностное копирование: копируются дескрипторы/токены, данные底层共同 | Присваивание/передача параметров автоматически | Токены `&T`, `ref T`, String/Bytes |
| **Clone**         | Глубокое копирование: создаётся полностью независимая копия | `value.clone()`        | Любой тип, реализующий Clone           |

**Семантика Dup**: типы, реализующие Dup, при присваивании/передаче параметров не передают владение — компилятор копирует дескрипторы/токены, несколько владельцев указывают на одни и те же底层 данные. Это дополнение к Move-семантике по умолчанию из RFC-009.

**Dup и Clone — ортогональные концепции**:

```
Dup = копирование дескрипторов, совместное использование данных (изменения взаимно влияют)
Clone = копирование данных, независимые копии (изменения не влияют друг на друга)
```

**Правила**:

```
1. Примитивные типы значений (Int, Float, Bool, Char) — встроенное компилятором копирование значений, не принадлежат Dup
2. Dup — применимо только к ссылочным/токенным типам и типам с внутренним подсчётом ссылок
3. Clone — явное глубокое копирование, любой тип может реализовать
4. Move по умолчанию — остальные типы сохраняют семантику Move по умолчанию
```

**Какие типы являются Dup**:

| Тип                  | Dup   | Причина                                           |
| -------------------- | ----- | ------------------------------------------------- |
| `&T` (заимствованный токен) | ✅    | Токен нулевого размера, копирование токена = несколько представлений на одни данные |
| `ref T`              | ✅    | Rc/Arc копирование = счётчик ссылок +1, совместное использование heap данных |
| String, Bytes        | ✅    | Внутренний подсчёт ссылок, копирование дескриптора совместно использует底层 буфер |
| `&mut T` (изменяемый токен) | ❌   | Линейный эксклюзив, не может копироваться         |
| struct               | Производный | Все поля Dup → struct Dup              |
| enum                 | Производный | Все поля всех вариантов Dup → enum Dup |
| tuple                | Производный | Все элементы Dup → tuple Dup            |
| Fn (замыкание)       | ❌    | Захваченное окружение может не быть Dup          |
| `*T` (сырой указатель) | ❌    | unsafe, не участвует в системе владения         |

**Int/Float/Bool/Char НЕ являются Dup** — это типы значений; при присваивании компилятор автоматически копирует значение (два значения полностью независимы). Это не «поверхностное копирование», это встроенная обработка примитивов компилятором; не нужно и не следует выражать через type attribute Dup.

```yaoxiang
# Примитивные типы значений: компилятор автоматически копирует значение (не Dup)
x: Int = 42
y = x          # Копирование значения, x и y полностью независимы
print(x)       # ✅

# Dup: поверхностное копирование, копирование дескрипторов совместно использует данные
view: &Point = &point
view2 = view    # ✅ Dup: копирование токена, оба указывают на тот же point
print(view.x)   # ✅

# Clone: явное глубокое копирование, создание независимой копии
backup = big_struct.clone()  # Явный вызов

# Обобщённые ограничения
dup_use: (T: Dup) -> T = x         # T: Dup → можно поверхностно копировать
clone_use: (T: Clone) -> T = x.clone()  # T: Clone → можно глубоко копировать
```

> **Примечание**: `Send`/`Sync` не являются видимыми для пользователя trait. Гарантия безопасности межзадачного взаимодействия обеспечивается ключевым словом `ref` и полностью автоматически компилятором — `ref` автоматически выбирает Rc или Arc, пользователю не нужно понимать Send/Sync.

        }

# Синтаксический сахар для методов: Vec.Item, Vec.next, Vec.has_next
# Позиция итерации переносится обёрточной записью (Vec сам является原始 буфером, без поля index)
VecIter: (T: Type) -> Type = {
    data: &Vec(T),
    index: Int,
}

    return self.index < self.data.length
}

    if self.index < self.data.length {
        item = self.data[self.index]
        self.index = self.index + 1
        return Option.some(item)
    } else {
        return Option.none()
    }
}

}

### 4. Compile-time обобщения

#### 4.1 Параметры-значения compile-time

**Ключевое решение**: `Type` в обобщённой сигнатуре помечает параметры-типы; параметры, аннотированные конкретными типами (`Int`/`Bool`/`Float` и т.д.), являются **кандидатами в параметры-значения compile-time**; становятся ли они таковыми, зависит от того, **используются ли их значения в типовых позициях** (зависимость от значения). Ключевое слово `const` не требуется.

> Критерий — **использование в типовой позиции**, а не «аннотировано конкретным типом»: в `add: (a: Int, b: Int) -> Int = a + b` параметры `a`/`b` являются runtime параметрами-значениями, так как ни один из них не появляется ни в одной типовой позиции.

**Правила определения (два шага)**:

1. **Грубый фильтр по форме**: параметр аннотирован не-`Type` конкретным типом (например, `Int`) → в список кандидатов.
2. **Тонкий фильтр по использованию**: имя кандидата появляется в **типовых позициях** (типы полей тела типа, типы параметров внутреннего `Fn`, предикаты `Assert`, фактические аргументы типа в `Array(T, N)` и т.д.) → подтверждается как параметр-значение compile-time; иначе считается **runtime параметром-значением**.

| Запись                                                           | Определение              | Причина                                        |
| ---------------------------------------------------------------- | ------------------------ | ---------------------------------------------- |
| `add: (a: Int, b: Int) -> Int = a + b`                          | a/b — runtime значения   | Появляются только в позициях значений, не участвуют в конструкции типа |
| `Array: (T: Type, N: Int) -> Type = { data: Array(T, N) }`       | N — compile-time значение | N появляется в фактическом аргументе типа `Array(T, N)` |
| `factorial: (N: Int) -> (k: N) -> Int`                          | N — compile-time значение | N используется как тип внутреннего параметра `k` |
| `Foo: (T: Type, N: Int) -> Type = { x: T }`                      | N неиспользован (см. ниже) | N не упоминается в теле типа, вырождается в runtime параметр |

> **Сущность зависимости от значения**: параметр-значение compile-time — это и есть тип, зависимый от значения — только когда значение используется для **конструирования типа**, требуется определение на этапе компиляции. Форма (`: Int`) только определяет статус кандидата; использование (появление в типовой позиции) определяет, является ли это compile-time параметром-значением. Это тот же критерий, что и в секции «Гарантии compile-time детерминизма»: «вызовы функций в типовых позициях вычисляются на этапе компиляции».

```yaoxiang
# ════════════════════════════════════════════════════════════════
# Параметры-значения compile-time: N используется в типовой позиции (слот длины Measure)
# ════════════════════════════════════════════════════════════════
Measure: (T: Type, N: Int) -> Type = {
    data: Array(T, N),  # N появляется в фактическом аргументе типа → compile-time параметр-значение
    length: N,
}

# Использование: factorial(5) вычисляется в типовой позиции (compile-time), результат 120 встраивается в тип
m: Measure(Int, factorial(5))  # Measure(Int, 120)

# ════════════════════════════════════════════════════════════════
# Зависимость от значения: N как тип внутреннего параметра k
# ════════════════════════════════════════════════════════════════
# N — compile-time параметр-значение (появляется в типе `(k: N)`);
# k — runtime параметр-значение, его тип — literal type N (однозначный тип).
factorial: (N: Int) -> (k: N) -> Int = {
    return match k {
        0 => 1,
        _ => k * factorial(k - 1)
    }
}
```

> **Обработка неиспользованных кандидатов**: кандидаты, аннотированные конкретным типом, но не появившиеся в типовой позиции (например, N `Foo` в таблице выше), вырождаются в runtime параметры-значения (на уровне функции). Неиспользованные кандидаты на пути конструктора типа не могут занимать runtime слоты (конструктор типа вычисляется на этапе компиляции), на стороне объявления выдаётся ошибка [E1094]: «N объявлен как compile-time параметр-значение, но не используется в теле типа» — ранее это молчаливо отбрасывалось, что приводило к несоответствию арности инстанциации.

# ════════════════════════════════════════════════════════════════

}

### Never и Void: ⊥ и ⊤ системы типов

Система типов YaoXiang в изоморфизме Curry-Howard одновременно обладает ⊥ (ложь/пустой тип) и ⊤ (истина/Unit), представленными двумя встроенными именами типов — `Never` и `Void`:

**Never (⊥)** — три не подлежащих обсуждению внутренних свойства:

1. **Ноль конструкторов**: ни один литерал и ни одно выражение не могут произвести значение типа `Never`. Это meta-level свойство, должно быть встроено.
2. **Принцип взрыва**: `Never <: T` выполняется для любого типа `T`. Значение `Never` может использоваться как любой тип — именно поэтому код после `assert(false)` проходит проверку типов (хотя никогда не выполняется).
3. **Маркер расхождения**: `f: (...) -> Never` означает, что `f` гарантированно не возвращается. Компилятор использует это для анализа dead code.

`Never` — встроенное имя типа, не ключевое слово; parser не затрагивается. Синтаксис пустых типов и объединений не предоставляется.

**Void (⊤, то есть Unit)** — ровно один обитатель (значение по умолчанию void), носитель тавтологии «всегда истинно». `Void` —幺元 нуль-полевого product type, `Never` —幺元 нуль-вариантного sum type — они двойственны. `x: Void = <по умолчанию>` корректно, `x: Never = ...` не имеет правой части для записи.

#### 4.3 Compile-time верификация (реализация стандартной библиотеки)

```yaoxiang
# ════════════════════════════════════════════════════════════════
# Реализация стандартной библиотеки: использование условных типов
# ════════════════════════════════════════════════════════════════

# Стандартное определение
# IsTrue: мост от universe значений к universe типов — Bool truth value отображается в тип
IsTrue: (b: Bool) -> Type = match b {
    true => Void,      # ⊤, есть значение, программа продолжается
    false => Never,    # ⊥, нет значения, расхождение
}

# Assert: примитив compile-time refinement type — высказывание типа Bool на уровне типов
Assert: (cond: Bool) -> Type = IsTrue(cond)
#
# cond = true  → Assert(true)  = Void    (всегда истинно, стирается)
# cond = false → Assert(false) = Never   (всегда ложно, ошибка компиляции/расхождение)
# cond не разрешим → конвейер доказательства решает по режиму dispatch:
#                  CompileTime → Unknown, требуется prove
#                  Runtime     → вставляет check, добавляет Γ assumption

# Способ использования 1: как ограничение в определении типа
Bounded: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    # Compile-time проверка: N должен быть больше 0 (Assert в типовой позиции)
    length: Assert(N > 0),
}

# Способ использования 2: в выражении
IntArray: (N: Int) -> Type = Array(Int, N)
# Верификация: sizeof(IntArray(10)) == sizeof(Int) * 10
Assert(size_of(IntArray(10)) == sizeof(Int) * 10)
```

### 5. Условные типы

> **Изоморфизм Curry-Howard**: условные типы с точки зрения Curry-Howard — это **case analysis** в логике. Тип `Bool` соответствует высказыванию с двумя возможными значениями (True/False); `If` выбирает разные результаты в зависимости от истинности этого высказывания — это и есть case disjunction в логике. `match C { True => T, False => E }` фактически выражает: «когда известно, что высказывание C истинно, заключение — T; когда C ложно, заключение — E».

#### 5.1 Условный тип If

```yaoxiang
# Типовый If
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Пример: compile-time ветвление
NonEmpty: (T: Type) -> Type = If(T != Void, T, Never)

Optional: (T: Type) -> Type = If(T != Void, T, Void)

# Compile-time верификация (унифицировано с определением Assert в §4.3)
# Assert: (cond: Bool) -> Type = IsTrue(cond)

# Использование
# Вычисление типа: If(True, Int, String) => Int
# Вычисление типа: If(False, Int, String) => String
```

#### 5.2 Типовые семейства

> **Изоморфизм Curry-Howard**: типовые семейства — наиболее прямое воплощение «высказывания — это типы». `Add: (A: Type, B: Type) -> Type` — это не «написанная функция сложения на уровне типов», а **конструирование высказывания о сложении натуральных чисел**. `(Zero, B) => B` утверждает «высказывание Add(Zero, B) эквивалентно B»; `(Succ(A'), B) => Succ(Add(A', B))` утверждает «если Add(A', B) верно, то Add(Succ(A'), B) тоже верно». Это само определение сложения из аксиом Пеано. Проверка типами того, что это match-выражение проходит проверку, эквивалентна верификации логической согласованности данного определения.

```yaoxiang
# Compile-time преобразование типов
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,  # По умолчанию
}

# Вычисления на уровне типов
Length: (T: Type) -> Type = match T.length {
    0 => Zero,
    1 => Succ(Zero),
    2 => Succ(Succ(Zero)),
    _ => TooLong,
}

# Сложение на уровне типов (Curry-Howard: case analysis + рекурсивный вызов, полная индукция требует проверки завершения)
Add: (A: Type, B: Type) -> Type = match (A, B) {
    (Zero, B) => B,
    (Succ(A'), B) => Succ(Add(A', B)),
}

# Пример: compile-time вычисление 2 + 3
Two: Type = Succ(Succ(Zero))
Three: Type = Succ(Succ(Succ(Zero)))
Five: Type = Add[Two, Three]  # Succ(Succ(Succ(Succ(Succ(Zero)))))
```

**Ключевая характеристика**: перегрузка функций и оптимизация встраивания естественно сочетаются, реализуя абстракцию с нулевой стоимостью.

   - Нулевые накладные расходы runtime
   - Без таблиц виртуальных функций

# Численные вычисления, чувствительные к производительности
fibonacci: (n: Int) -> Int = {
    if n <= 1 { return n }
    return fibonacci(n - 1) + fibonacci(n - 2)
}

fibonacci: (n: Float) -> Float = {
    # Использование формулы Бине
    phi = (1.0 + 5.0.sqrt()) / 2.0
    return (phi.pow(n) - (-phi).pow(-n)) / 5.0.sqrt()
}

# Компилятор автоматически выбирает и встраивает
fibonacci(10)      # Выбирается версия Int, полностью встраивается
fibonacci(10.5)    # Выбирается версия Float, используется формула Бине
```

**Что это означает?**

- ✅ **Специализация обобщений** → естественно решается перегрузкой функций
- ✅ **Оптимизация производительности** → автоматическое встраивание
- ✅ **Повторное использование кода** → одно имя функции, множество реализаций
- ✅ **Абстракция с нулевой стоимостью** → compile-time полиморфизм, нулевые накладные расходы runtime
- ✅ **Без новых ключевых слов** → идеально соответствует унифицированному синтаксису RFC-010

    const_args: Vec<ConstId>,  // Параметры Const

fn eliminate_dead_instantiations(graph: &InstantiationGraph) {
    let mut reachable = HashSet::new();

    // Начинаем с точек входа (main, экспортируемые функции и т.д.)
    let entry_points = find_entry_points();
    for entry in entry_points {
        dfs_visit(entry, &graph, &mut reachable);
    }

    // Непосещённые инстанциации — мёртвый код
    for node in &graph.nodes {
        if !reachable.contains(node.key) {
            eliminate(node);
        }
    }
}

Add: (A: Type, B: Type) -> Type = match (A, B) {

    (Float, Float) => Float,

    (Float, Int) => Float,
    _ => TypeError,
}

> **Связь с RFC-011b (заметка 2026-09-22)**: продвигаемое в данном разделе type family `Add(A, B)` — это перспектива уровня типов регистрационной таблицы интерфейса операторов из [RFC-011b](./011b-operator-overloading.md) — основная регистрация `Add(Int, Float, Float)` и данная таблица `(Int, Float) => Float` — это одно и то же правило; каждая пользовательская инстанциация интерфейса добавляет строку в эту таблицу. Peano `Add` на уровне типов в §5.2 — это чистое вычисление на уровне типов (одноимённое, но другое), не мешающее интерфейсу операторов на уровне значений — запрос оператора обращается к регистру инстанциации интерфейса, а не к разрешению имён.

# Использование синтаксиса (T: Type) -> Type
Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self,
}

Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self,
}

List: (T: Type) -> Type = {
    data: Vec(T),
    length: Int,

    # Обобщённые методы (T автоматически вводится во внешней область из List(T))
    push: (self: List(T), item: T) -> Void,
    pop: (self: List(T)) -> Option(T),
    map: (R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)),
    filter: (self: List(T), predicate: (T) -> Bool) -> List(T),
    fold: (U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U),
}

# ======== 2. Реализация обобщённых методов ========
# Определения функций в пространстве имён List (префикс List. = принадлежность пространству имён)
# Для работы синтаксиса вызова . вроде list.push(item) требуется явная привязка: List.push = push[0]
# self — это только соглашение об именовании, компилятор смотрит на типы, не на имена

List.push: (T: Type) -> ((self: List(T), item: T) -> Void) = {
    if self.length >= self.data.length {
        # Расширение
        new_data = Vec(T)(len=self.data.length * 2)
        for i in 0..self.length {
            new_data[i] = self.data[i]
        }
        self.data = new_data
    }
    self.data[self.length] = item
    self.length = self.length + 1
}

List.pop: (T: Type) -> ((self: List(T)) -> Option(T)) = {
    if self.length > 0 {
        self.length = self.length - 1
        return Option.some(self.data[self.length])
    } else {
        return Option.none()
    }
}

List.map: (T: Type, R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)) = {
    result = List(R)()
    for i in 0..self.length {
        result.push(f(self.data[i]))
    }
    return result
}

List.filter: (T: Type) -> ((self: List(T), predicate: (T) -> Bool) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        if predicate(self.data[i]) {
            result.push(self.data[i])
        }
    }
    return result
}

List.fold: (T: Type, U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U) = {
    result = initial
    for i in 0..self.length {
        result = f(result, self.data[i])
    }
    return result
}

# ======== 3. Использование type constraints ========
# Реализация Clone для List
List.clone: (T: Clone) -> ((self: List(T)) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        result.push(self.data[i].clone())
    }
    return result
}

# ======== 4. Примеры использования ========

numbers.push(2)
numbers.push(3)

    .map((x) => x * 2)
    .fold(0, (acc, x) => acc + x)  # sum_of_evens = 8

```yaoxiang
# ======== 1. Обобщённый алгоритм сортировки ========
Comparator: (T: Type) -> Type = {
    compare: (T, T) -> Int,  # -1 если a < b, 0 если a == b, 1 если a > b
}

# Обобщённый quicksort
quicksort: (T: Clone) -> ((array: Vec(T), cmp: Comparator(T)) -> Vec(T)) = {
    if array.length <= 1 {
        return array.clone()
    }

    pivot = array[array.length / 2]
    left = Vec(T)()
    right = Vec(T)()

    for i in 0..array.length {
        if i == array.length / 2 {
            continue
        }
        item = array[i]
        comparison = cmp.compare(item, pivot)
        if comparison < 0 {
            left.push(item)
        } else {
            right.push(item)
        }
    }

    sorted_left = quicksort(left, cmp)
    sorted_right = quicksort(right, cmp)

    result = sorted_left.clone()
    result.push(pivot)
    result.extend(sorted_right)
    return result
}

# ======== 2. Реализация IntComparator ========
# Использование перегрузки функций
compare: (a: Int, b: Int) -> Int = {
    if a < b {
        return -1
    } else if a > b {
        return 1
    } else {
        return 0
    }
}

# ======== 3. Примеры использования ========
# Сортировка массива Int
numbers = Vec(Int)(3, 1, 4, 1, 5, 9, 2, 6)
sorted = quicksort(numbers, Comparator(Int)())

# Сортировка массива String (требуется StringComparator)

Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {

    _assert: Assert(Rows > 0),  # Rows > 0, иначе ошибка компиляции
    _assert: Assert(Cols > 0),  # Cols > 0, иначе ошибка компиляции

            }
        }
        return result
    }

## Компромиссы

### Преимущества

1. **Абстракция с нулевой стоимостью**
   - Compile-time мономорфизация, без накладных расходов runtime
   - Без виртуальных функций, без RTTI

2. **Устранение мёртвого кода**
   - Compile-time анализ, инстанцируются только используемые обобщения
   - Разбухание кода контролируемо

3. **Замена макросов**
   - Type-safe генерация кода
   - Дружелюбие к IDE, чёткие сообщения об ошибках

4. **Compile-time вычисления**
   - Compile-time обобщения поддерживают compile-time вычисления
   - Проверка размерностей и другие возможности
   - Без ключевого слова `const`, чистые type constraints

### Недостатки

1. **Время компиляции**
   - Инстанциация обобщений увеличивает время компиляции
   - Решение ограничений может быть медленным

2. **Использование памяти**
   - Увеличение использования памяти компилятором
   - Механизм кэширования требует памяти

3. **Сложность реализации**
   - Решатель ограничений сложен
   - Движок вычислений на уровне типов сложен

4. **Диагностика ошибок**
   - Ошибки обобщений могут быть сложными
   - Требуются чёткие подсказки об ошибках

### Меры смягчения

1. **Стратегии кэширования**
   - Кэширование результатов инстанциации
   - Ограничение памяти через LRU-кэш

2. **Инкрементальная компиляция**
   - Кэширование результатов компиляции
   - Инкрементальная инстанциация

3. **Подсказки об ошибках**
   - Чёткие сообщения об ошибках
   - Подсказки вывода обобщённых параметров

4. **Параллельная компиляция**
   - Параллельная инстанциация обобщений
   - Многопоточное решение ограничений

## Альтернативные решения

| Решение          | Почему не выбрано                         |
| ---------------- | ------------------------------------------ |
| Только базовые обобщения | Невозможность замены сложных макросов    |
| Чистая макросистема      | Нет type safety, плохие сообщения об ошибках |
| Только ограничения       | Недостаточная гибкость                   |
| Runtime обобщения        | Накладные расходы производительности      |

### Риски

| Риск                 | Влияние                | Меры смягчения              |
| -------------------- | ---------------------- | --------------------------- |
| Сложность решения ограничений | Слишком долгая компиляция | Инкрементальное решение + кэширование |
| Разбухание кода      | Слишком большой бинарный файл | DCE + контроль порогов     |
| Сложность реализации | Увеличение цикла разработки | Поэтапная реализация       |
| Диагностика ошибок   | Плохой пользовательский опыт | Детальные сообщения об ошибках |

## Приложение

### Синтаксис BNF

```bnf
# Параметры обобщений используют унифицированный синтаксис (), как часть function type
# Например map: (T: Type, R: Type) -> ((list: List(T), f: (T) -> R) -> List(R))

# Ограничения типов (в обобщённых параметрах)
type_bound ::= identifier
             | identifier '+' identifier ('+' identifier)*

# Объявление параметра (тип + имя)
parameter ::= identifier ':' type

parameters ::= parameter (',' parameter)*

# Объявление функции: name: type = expression
# Обобщённые параметры — первая группа параметров в function type: (T: Type) -> ((params) -> return)
function ::= identifier ':' type '=' (expression | block)

# Объявление метода: Type.method: type = expression
method ::= identifier '.' identifier ':' type '=' (expression | block)

# Определение типа (унифицированный Binding синтаксис)
# Обобщённые типы, например List: (T: Type) -> Type = { ... }
generic_type ::= identifier ':' type '=' type_expression

# Параметры Type в обобщённых параметрах автоматически заполняются компилятором из типов аргументов
# Например map(numbers, f), T извлекается из numbers: List(Int), R из f: (Int) -> String
```
