# RFC-011: Дизайн системы обобщений - Абстракции с нулевой стоимостью и замена макросов

## Резюме

Данный документ определяет **дизайн системы обобщений** языка YaoXiang, реализующий абстракции с
нулевой стоимостью через мощные возможности обобщений, снижая зависимость от макросов за счёт
оптимизаций времени компиляции и предоставляя механизм устранения мёртвого кода.

**Основные проектные решения**:

- **Унифицированный синтаксис сигнатур**: `(T: Type, R: Type) -> ...` параметры обобщений и обычные
  параметры унифицированы
- **Механизм самоописания Type**: `Type` - это специальная сущность уровня языка, позиция `Type` в
  сигнатуре может быть автоматически распознана и заполнена
- **Ограничения типов**: `T: Dup + Add` множественные ограничения, ограничения типа функции
- **Ассоциированные типы**:
  `Iterator: (Item: Type) -> Type = { next: () -> Option(Item), has_next: () -> Bool }`
- **Обобщения времени компиляции**: `N: Int` параметры обобщённых значений, инстанцирование констант
  времени компиляции
- **Условные типы**: `If: (C: Bool, T: Type, E: Type) -> Type` вычисления на уровне типов, type
  family

**Ценность**:

- Абстракции с нулевой стоимостью: мономорфизация на этапе компиляции, без накладных расходов в
  runtime
- Устранение мёртвого кода: анализ графа инстанцирования + оптимизации LLVM
- Замена макросов: обобщения заменяют 90% сценариев использования макросов
- Безопасность типов: проверка времени компиляции, дружественность к IDE
- **Явное лучше неявного**: `Type` самоописывающий, компилятор автоматически выводит

## Идея вселенной типов и типы, зависящие от значений

Система обобщений YaoXiang построена на **идее вселенной типов** — ментальной модели, которая
унифицирует все концепции языка в многоуровневую структуру, центральной инновацией которой является
возведение **типов, зависящих от значений**, в полноправные граждане уровня Type2.

### Что такое типы, зависящие от значений?

**Тип, зависящий от значений** — это тип, который зависит от одного или нескольких **значений** (а
не только от других типов). Эти значения могут быть вычислены во время компиляции, обеспечивая
гарантии безопасности типов уже на этом этапе.

```yaoxiang
# Традиционные обобщения: параметры-типы
List: (T: Type) -> Type

# Типы, зависящие от значений: параметры-значения
Vec: (n: Int) -> Type  # Тип вектора зависит от значения длины n
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type  # Тип матрицы зависит от числа строк и столбцов
```

### Ключевые преимущества типов, зависящих от значений

По сравнению с традиционными обобщениями, типы YaoXiang, зависящие от значений, обладают следующими
ключевыми преимуществами:

| Свойство                      | Традиционные обобщения (C++/Rust)                     | Типы YaoXiang, зависящие от значений                                       |
| ----------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------- |
| Зависимость типов от значений | Только от параметров-типов                            | Может зависеть от любых значений, включая результаты вызовов функций       |
| Вычисление времени компиляции | C++ ручная специализация шаблонов, в Rust отсутствует | Автоматическое вычисление времени компиляции с гарантией завершаемости     |
| Вычисления на уровне типов    | Метапрограммирование шаблонов (сложное/опасное)       | Унифицированный движок вычислений на уровне типов                          |
| Безопасность типов            | C++ отсутствует, Rust ограниченная                    | Полная безопасность типов, проверка времени компиляции                     |
| Проверка размерности          | Проверка в runtime или ручная специализация           | Проверка размерности на этапе компиляции, без накладных расходов в runtime |

### Уровни вселенной типов и типы, зависящие от значений

Идея вселенной типов разделяет концепции языка по семантическим ролям на разные уровни, типы,
зависящие от значений, расположены на **уровне Type2**:

| Уровень   | Роль                                                       | Примеры                                                                                              |
| --------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Type-1    | Значения                                                   | `42`, `factorial(5)`, сама функция                                                                   |
| Type0     | Ключевое слово метатипа                                    | `Type`                                                                                               |
| Type1     | Конкретные типы                                            | `Int`, `String`, `Vec(3)`                                                                            |
| **Type2** | **Функции/конструкторы типов/типы, зависящие от значений** | `add: (Int, Int) -> Int`, `Vec: (n: Int) -> Type`, `Matrix: (T: Type, Rows: Int, Cols: Int) -> Type` |

**Ключевое проектное решение**: функции, конструкторы типов и типы, зависящие от значений, на уровне
Type2 имеют **унифицированный синтаксис** — все имеют форму `(params) -> result`:

- Обычная функция: `(Int, Int) -> Int` → возвращаемое значение — значение
- Конструктор типов: `(T: Type) -> Type` → возвращаемое значение — тип
- Тип, зависящий от значений: `(n: Int) -> Type` → возвращаемое значение — тип, но зависит от
  параметра-значения

> **Изоморфизм Карри-Ховарда**: это унификация не случайна. Изоморфизм Карри-Ховарда утверждает
> «типы суть propositions, программы суть доказательства» — тип функции `A → B` соответствует
> логической импликации «если A, то B», обобщение `(T: Type) -> Type` соответствует квантору
> всеобщности «для всех типов T», тип, зависящий от значений, `(n: Int) -> Type` соответствует «для
> каждого целого n существует тип». YaoXiang унифицирует функции, конструкторы типов и типы,
> зависящие от значений, на уровне Type2, что по сути объединяет «доказательство» и «вычисление» в
> одно понятие — **конструктивное доказательство**. Это прямое воплощение изоморфизма Карри-Ховарда
> в дизайне языка: одна форма (`(params) -> result`) одновременно несёт логические propositions и
> вычислительные процессы.

### Гарантия детерминированности времени компиляции

Идея вселенной типов YaoXiang требует: **всё на уровне Type детерминировано во время компиляции**.

```yaoxiang
# Пример проверки размерности времени компиляции
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),
    # Проверка времени компиляции: размерности должны быть положительными
    _assert: Assert(Rows > 0),
    _assert: Assert(Cols > 0),
}

# Создание единичной матрицы 3x3 - завершается во время компиляции
identity: (T: Add + Zero + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    # ...
}

# Вычисление времени компиляции: factorial(3) = 6, размер вектора определяется во время компиляции
vec: Vec(factorial(3)) = Vec(6)()
```

Компилятор автоматически:

1. Обнаруживает вызовы функций в позиции типа
2. Выполняет проверку завершаемости для функции во время компиляции (см. механизм проверки
   завершаемости ниже)
3. Выполняет вычисление во время компиляции
4. Встраивает результат в генерируемый тип

### Сценарии применения типов, зависящих от значений

#### Проверка размерности времени компиляции

```yaoxiang
# Умножение матриц: проверка совпадения размерностей во время компиляции
multiply: (T: Add + Multiply + Zero,
           Rows: Int, Cols: Int, M: Int) -> ((
    a: Matrix(T, Rows, Cols),
    b: Matrix(T, Cols, M)
) -> Matrix(T, Rows, M)) = {
    # Проверка времени компиляции: a.Cols == b.Rows, иначе ошибка компиляции
    result = Matrix(T, Rows, M)()
    # ...
}

# Ошибка перехватывается во время компиляции:
# multiply(matrix_2x3, matrix_4x2)  # Ошибка компиляции: 2 != 4
```

#### Размер массива с безопасностью типов

```yaoxiang
# Размер массива является константой времени компиляции
Array: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    length: N,
}

# N - константа времени компиляции, может использоваться для вычислений на уровне типов
first_three: Array(Int, 3) = Array(Int, 3)(1, 2, 3)
# first_three.length == 3 (известно во время компиляции)
```

#### Условные типы

```yaoxiang
# If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Type family
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,
}
```

#### Обобщённые функции

```yaoxiang
# map: обобщённая функция, параметры типов T, R определяются во время компиляции
map: (T: Type, R: Type) -> (
    (list: List(T), f: (x: T) -> R) -> List(R)
) = (list, f) => {
    result = List(R)()
    for x in list {
        result.push(f(x))
    }
    return result
}

# При использовании полностью прозрачно, тип выводится автоматически
numbers = List(1, 2, 3)
doubled = map(numbers, (x) => x * 2)  # Выводится как map[Int, Int]
```

### Механизм проверки завершаемости (унифицирован с RFC-027)

Вычисление времени компиляции для типов, зависящих от значений, должно **гарантировать
завершаемость**, иначе система типов попадёт в бесконечный цикл. Проверка завершаемости выполняется
**полностью автоматически** конвейером доказательств времени компиляции из RFC-027 — компилятор
автоматически синтезирует метрики; рекурсии/циклы, для которых доказательство возможно, проходят, а
те, для которых невозможно, сразу дают ошибку компиляции. **Полуавтоматическим аннотациям не
оставлено лазеек**: `//! decreases` и `/*! invariant !*/` из RFC-022 отменены вместе с RFC-022,
спецификация — это сама аннотация типа.

#### Проверка завершаемости рекурсивных функций

Компилятор перед вычислением времени компиляции проверяет, что аргументы рекурсивного вызова строго
убывают на каждой ветви рекурсии (RFC-027 §6.7). Никаких аннотаций спецификации не требуется:

```yaoxiang
# Факториал времени компиляции: без //! requires/ensures/decreases, компилятор анализирует автоматически
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)  # Анализ компилятора: n-1 < n → убывает → завершается
}

# Использование: при вызове в позиции типа компилятор сначала проверяет завершаемость, затем вычисляет
vec: Vec(factorial(5)) = Vec(120)()  # Вычисление времени компиляции factorial(5) = 120
```

| Сценарий                                                              | Поведение                           |
| --------------------------------------------------------------------- | ----------------------------------- |
| Компилятор может проанализировать убывание рекурсии (например, `n-1`) | Вычисление времени компиляции       |
| Не убывает / не удаётся определить убывание                           | Ошибка компиляции                   |
| Вызов в runtime (не в позиции типа)                                   | Проверка завершаемости не требуется |

#### Проверка завершаемости циклов

Циклам не требуются аннотации `: Invariant(...)` или `: decreases(...)`. Аннотации уточнения типов
на переменных (например, `UpTo(n)`) одновременно задают инвариант цикла и границу метрики,
компилятор по приоритету пробует четыре стратегии синтеза метрик, останавливаясь на первой успешной
(RFC-027 §7):

1. **Автоматический синтез линейной ранговой функции** — извлечение границ переменных из аннотаций
   типов, перебор линейных комбинаций, SMT-проверка m ≥ 0 и m' < m на всех путях
2. **Подсчёт нарушений предиката** (экспериментальный) — извлечение violation_count из определения
   целевого типа (например, `Sorted`), покрытие соседних обменов/перемещений
3. **Шаблон ограниченного инкремента/декремента** — `v += const` → метрика `upper - v` (вырождение
   стратегии 1, самый быстрый путь)
4. **Шаблон метрики мультипликативного масштабирования** — `v *= const` (const > 1) → метрика
   `ceil(log_const(upper / v))`

```yaoxiang
sum: (arr: Array(Int, n)) -> Int = {
    mut i: UpTo(arr.len) = 0   # Аннотация типа задаёт верхнюю границу arr.len и нижнюю 0
    while i < arr.len {
        # Компилятор автоматически выводит: метрика arr.len - i, на каждой итерации строго убывает на 1 → завершаемость доказана
        s += arr[i]; i += 1
    }
    return s
}
```

#### Рабочий процесс проверки завершаемости

```
┌─────────────────────────────────────────────────────────────┐
│  Фаза проверки типов                                        │
│  Встречается вызов функции в позиции типа (например, Vec(factorial(5))) │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  1. Проверка завершаемости (конвейер доказательств RFC-027, полностью автоматический) │
│     - Рекурсивные функции: проверка строгого убывания аргументов на каждой ветви рекурсии │
│     - Циклы: четыре стратегии синтеза метрик (линейная ранговая/подсчёт нарушений/ │
│       ограниченный шаблон/мультипликативное масштабирование), SMT-проверка убывания │
│     - Не удаётся доказать → ошибка компиляции (жёсткая граница, без полуавтоматических аннотаций) │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  2. Вычисление времени компиляции (выполняется встроенным интерпретатором) │
│     - Чистые функции: прямое вычисление                                              │
│     - Побочные эффекты: ошибка компиляции (в позиции типа побочных эффектов быть не должно) │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  3. Встраивание результата в тип                                                │
│     - Vec(factorial(5)) → Vec(120)                                                 │
│     - Matrix(Float, 3, 3) → конкретный тип                                         │
└─────────────────────────────────────────────────────────────┘
```

#### Преимущества

- **Безопасность**: гарантируется завершаемость вычислений времени компиляции, исключается
  зацикливание системы типов
- **Унификация**: проверка завершаемости и верификация корректности (генерация VC) разделяют один
  конвейер доказательств времени компиляции (RFC-027), без отдельного синтаксиса спецификаций
- **Полная автоматизация**: компилятор автоматически синтезирует метрики из аннотаций типов; если
  доказуемо — проходит, иначе — ошибка, без необходимости писать `decreases` вручную

## Мотивация

### Зачем нужна мощная система обобщений?

Существующие обобщения в主流 языках имеют ограничения:

| Язык         | Возможности обобщений           | Проблема                                                                                            |
| ------------ | ------------------------------- | --------------------------------------------------------------------------------------------------- |
| Java         | Граничные типы                  | Мономорфизация времени компиляции, без специализации                                                |
| C#           | Ограничения обобщений           | Проверка типов в runtime, накладные расходы по производительности                                   |
| Rust         | Обобщения + Trait               | Сложная система Trait, крутая кривая обучения                                                       |
| C++          | Шаблоны                         | Сложная специализация шаблонов, плохие сообщения об ошибках                                         |
| **YaoXiang** | **Типы, зависящие от значений** | **Тип может зависеть от значений, проверка размерности времени компиляции, гарантия завершаемости** |

### Ключевые противоречия

1. **Производительность vs гибкость**: гибкость в runtime vs оптимизации времени компиляции
2. **Сложность vs простота**: мощная система типов vs удобство использования
3. **Макросы vs обобщения**: генерация кода макросами vs безопасность типов в обобщениях
4. **Зависимость от значений vs безопасность типов**: традиционные обобщения не могут проверять
   размерности на этапе компиляции

### Ключевые преимущества типов, зависящих от значений

**Типы, зависящие от значений** YaoXiang — ключевое преимущество по сравнению с традиционными
обобщениями:

| Преимущество                      | Описание                                                                                                                         |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **Зависимость типов от значений** | `Vec: (n: Int) -> Type` позволяет типу зависеть от конкретного значения                                                          |
| **Вычисление времени компиляции** | Вызов функции в позиции типа вычисляется на этапе компиляции, результат непосредственно встраивается в тип                       |
| **Проверка размерности**          | `Matrix(Float, 3, 3)` проверяет размерности матрицы на этапе компиляции                                                          |
| **Вычисления на уровне типов**    | `If`, `Match` и другие условные типы поддерживают вычисления на уровне типов                                                     |
| **Гарантия завершаемости**        | Проверка завершаемости времени компиляции (автоматический синтез метрик) гарантирует завершаемость вычислений времени компиляции |

```yaoxiang

# Вычисление времени компиляции: factorial(3) = 6, factorial(2) = 2
```


## Цели дизайна

### Основные цели

1. **Абстракции с нулевой стоимостью** — вызов обобщений эквивалентен вызову конкретного типа
2. **Устранение мёртвого кода** — анализ времени компиляции, инстанцируются только используемые
   обобщения
3. **Замена макросов** — обобщения заменяют 90% сценариев использования макросов
4. **Безопасность типов** — проверка времени компиляции, без накладных расходов типов в runtime
5. **Дружественность к IDE** — интеллектуальные подсказки, понятные сообщения об ошибках
6. **Типы, зависящие от значений** — тип может зависеть от значений, поддержка проверки размерности
   времени компиляции
7. **Безопасность вычислений времени компиляции** — гарантируется проверкой завершаемости времени
   компиляции (автоматический синтез метрик в RFC-027)

### Принципы дизайна

- **Детерминированность времени компиляции**: параметры обобщений определяются во время компиляции
- **Приоритет мономорфизации**: генерация конкретного кода, без вызовов виртуальных функций
- **Управление через ограничения**: ограничения типов руководят инстанцированием
- **Платформенные оптимизации**: специализация для поддержки платформенно-специфичных оптимизаций
- **Унификация вселенной типов**: функции/конструкторы типов/типы, зависящие от значений,
  унифицированы на уровне Type2
- **Гарантия завершаемости**: вызовы функций в позиции типа должны доказывать завершаемость

## Предложение

### 1. Базовые обобщения

#### 1.1 Параметры обобщённых типов

> **Ключевое правило**: определение обобщённого типа **должно явно аннотироваться `: Type`**, иначе
> HM-вывод сочтёт его функцией.
>
> | Запись                            | Значение                            |
> | --------------------------------- | ----------------------------------- |
> | `List: (T: Type) -> Type = {...}` | ✅ Конструктор типа                 |
> | `List = {...}`                    | ❌ HM выводит как функцию, а не тип |

```yaoxiang
# Определение обобщённого типа (требуется : Type)
Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self
}

Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self
}

List: (T: Type) -> Type = {
    data: Array(T),
    length: Int,
    push: (self: List(T), item: T) -> Void,   # self - лишь соглашение об именовании, не ключевое слово
    get: (self: List(T), index: Int) -> Option(T),
}

# Обобщённая функция (без : Type, HM выводит функцию)
map: (T: Type, R: Type) -> ((opt: Option(T), f: Fn(T) -> R) -> Option(R)) = {
    return match opt {
        some => Option.some(f(some)),
        none => Option.none(),
    }
}

# Ограничение обобщения (прямое выражение, в одной строке return можно опустить)
clone: (T: Clone)(value: T) -> T = value.clone()

# Несколько параметров-типов
combine: (T: Type, U: Type) -> ((a: T, b: U) -> (T, U)) = (a, b)
```

#### 2.4 Встроенные marker trait: Dup и Clone

**Три вида семантики копирования**:

| Тип                                  | Значение                                                                                | Способ срабатывания                                | Сценарий применения                |
| ------------------------------------ | --------------------------------------------------------------------------------------- | -------------------------------------------------- | ---------------------------------- |
| **Копирование примитивных значений** | При присваивании автоматическое копирование значения, два значения полностью независимы | Автоматически при присваивании/передаче параметров | Int, Float, Bool, Char             |
| **Dup**                              | Поверхностное копирование: копирование дескриптора/токена, общие базовые данные         | Автоматически при присваивании/передаче параметров | `&T` токены, `ref T`, String/Bytes |
| **Clone**                            | Глубокое копирование: создание полной независимой копии                                 | `value.clone()`                                    | Любой тип, реализующий Clone       |

**Семантика Dup**: для типов, реализующих Dup, при присваивании/передаче параметров владение не
передаётся — компилятор копирует дескриптор/токен, и несколько владельцев указывают на одни и те же
базовые данные. Это дополняет семантику Move по умолчанию в модели владения из RFC-009.

**Dup и Clone — ортогональные понятия**:

```
Dup = копирование дескриптора, общие данные (изменения влияют друг на друга)
Clone = копирование данных, копия независима (изменения не влияют друг на друга)
```

**Правила**:

```
1. Примитивные типы значений (Int, Float, Bool, Char) — встроенное копирование значений компилятором, не относятся к Dup
2. Dup — применяется только к типам ссылок/токенов и типам с внутренним подсчётом ссылок
3. Clone — явное глубокое копирование, может быть реализовано любым типом
4. Move по умолчанию — остальные типы сохраняют семантику Move по умолчанию
```

**Какие типы являются Dup**:

| Тип                           | Dup         | Причина                                                                                       |
| ----------------------------- | ----------- | --------------------------------------------------------------------------------------------- |
| `&T` (токен заимствования)    | ✅          | Токен нулевого размера, копирование токена = несколько представлений указывают на одни данные |
| `ref T`                       | ✅          | Копирование Rc/Arc = счётчик ссылок +1, общие данные в куче                                   |
| String, Bytes                 | ✅          | Внутренний подсчёт ссылок, копирование дескриптора, общий нижележащий буфер                   |
| `&mut T` (токен изменяемости) | ❌          | Линейная монополия, копирование запрещено                                                     |
| struct                        | Производный | Все поля Dup → struct Dup                                                                     |
| enum                          | Производный | Все поля всех вариантов Dup → enum Dup                                                        |
| tuple                         | Производный | Все элементы Dup → tuple Dup                                                                  |
| Fn (замыкание)                | ❌          | Захватываемая среда может не быть Dup                                                         |
| `*T` (сырой указатель)        | ❌          | unsafe, не участвует в системе владения                                                       |

**Int/Float/Bool/Char не являются Dup** — они типы значений, и при присваивании компилятор
автоматически выполняет копирование значения (два значения полностью независимы). Это не
«поверхностное копирование», а встроенная обработка примитивов компилятором, она не нуждается и не
должна выражаться через атрибут типа Dup.

```yaoxiang
# Примитивные типы значений: компилятор автоматически копирует значение (не Dup)
x: Int = 42
y = x          # Копирование значения, x и y полностью независимы
print(x)       # ✅

# Dup: поверхностное копирование, копирование дескриптора, общие данные
view: &Point = &point
view2 = view    # ✅ Dup: копирование токена, оба указывают на один и тот же point
print(view.x)   # ✅

# Clone: явное глубокое копирование, создание независимой копии
backup = big_struct.clone()  # Явный вызов

# Ограничения обобщений
dup_use: (T: Dup) -> T = x         # T: Dup → можно поверхностно копировать
clone_use: (T: Clone) -> T = x.clone()  # T: Clone → можно глубоко копировать
```

> **Примечание**: `Send`/`Sync` не представлены как видимые пользователю trait. Безопасность
> межзадачных операций обрабатывается полностью автоматически ключевым словом `ref` и компилятором —
> `ref` автоматически выбирает Rc или Arc, пользователю не нужно понимать Send/Sync.

#### 3.1 Определение ассоциированных типов

```yaoxiang
# Iterator trait (с использованием синтаксиса (Item: Type) -> Type)
Iterator: (Item: Type) -> Type = {
    next: (Self) -> Option(Item),
    has_next: (Self) -> Bool,
    collect: (T: Type)(Self) -> List(T),
}

# Использование
collect_all: (T: Type, I: Iterator(T))(iter: I) -> List(T) = {
    result: List(T) = List(T)
    while iter.has_next() {
        if let Some(item) = iter.next() {
            result.push(item)
        }
    }
    return result
}

# Реализация Iterator для Array
# Используется синтаксический сахар методов: Array.Item, Array.next, Array.has_next
Array.has_next: (T: Type)(self: Array(T)) -> Bool = {
    return self.index < self.length
}

Array.next: (T: Type)(self: Array(T)) -> Option(T) = {
    if has_next(self) {
        item = self.data[self.index]
        self.index = self.index + 1
        return Option.some(item)
    } else {
        return Option.none()
    }
}

Array.Item: (T: Type)(arr: Array(T)) -> T = {
    return arr.data[0]
}
```

### 4. Обобщения времени компиляции

#### 4.1 Параметры-константы времени компиляции

**Ключевое проектное решение**: маркер `Type` в сигнатуре обобщения помечает параметр-тип времени
компиляции, а параметры-значения вроде `Int` в контексте обобщений по умолчанию детерминированы на
этапе компиляции. Ключевое слово `const` не требуется.

```yaoxiang
# ════════════════════════════════════════════════════════
# Параметры-константы времени компиляции: Int в обобщениях по умолчанию детерминирован во время компиляции
# ════════════════════════════════════════════════════════

# Факториал времени компиляции: N должен быть литералом, известным на этапе компиляции
factorial: (N: Int) -> (n: N) -> Int = {
    return match n {
        0 => 1,
        _ => n * factorial(n - 1)
    }
}

# Сложение времени компиляции
add: (a: Int, b: Int) -> (a: a, b: b) -> Int = a + b

# ════════════════════════════════════════════════════════
# Массивы констант времени компиляции
# ════════════════════════════════════════════════════════
StaticArray: (T: Type, N: Int) -> Type = {
    data: Array(T, N),  # Массив с размером, известным на этапе компиляции
    length: N,
}

# Способ использования
arr: StaticArray(Int, factorial(5))  # StaticArray(Int, 120), компилятор вычисляет на этапе компиляции
```

#### 4.2 Вычисления времени компиляции

```yaoxiang
# ════════════════════════════════════════════════════════
# Пример вычисления времени компиляции
# ════════════════════════════════════════════════════════

# Компилятор вычисляет вызовы функций с литеральными типами на этапе компиляции
SIZE: Int = factorial(5)  # На этапе компиляции равно 120

# Использование типа матрицы
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),
}

# Проверка размерности времени компиляции
identity_matrix: (T: Add + Zero + One, N: Int)(size: N) -> Matrix(T, N, N) = {
    matrix: Matrix(T, N, N) = Matrix(T, N, N)()
    for i in 0..size {
        for j in 0..size {
            if i == j {
                matrix.data[i][j] = One::one()
            } else {
                matrix.data[i][j] = Zero::zero()
            }
        }
    }
    matrix
}

# Использование: вычисление времени компиляции, генерируется Matrix(Float, 3, 3)
identity_3x3: Matrix(Float, 3, 3) = identity_matrix(Float, 3)(3)
```

### Never и Void: ⊥ и ⊤ в системе типов

Система типов YaoXiang в изоморфизме Карри-Ховарда одновременно обладает ⊥ (ложь/пустой тип) и ⊤
(истина/Unit), воплощёнными во встроенных именах типов `Never` и `Void`:

**Never (⊥)** — три не подлежащих обсуждению ядерных свойства:

1. **Нулевое число конструкторов**: ни один литерал или выражение не может породить значение типа
   `Never`. Это метауровневое свойство, должно быть встроенным.
2. **Принцип взрыва**: `Never <: T` для любого типа `T`. Значение `Never` может использоваться как
   значение любого типа — именно поэтому после `assert(false)` код всё равно проходит проверку типов
   (хотя никогда не выполнится).
3. **Маркер расходимости**: `f: (...) -> Never` означает, что `f` гарантированно не возвращается.
   Компилятор использует это для анализа мёртвого кода.

`Never` - встроенное имя типа, а не ключевое слово, парсер не делает различий. Синтаксис пустых и
литеральных типов не открывается.

**Void (⊤, т.е. Unit)** — ровно один обитатель (значение void по умолчанию), носитель истинного
proposition «всегда истинно». `Void` — единица нуль-полевого произведения типов, `Never` — единица
нуль-вариантного суммирования — они двойственны. `x: Void = <по умолчанию>` допустимо,
`x: Never = ...` не имеет правой части.

#### 4.3 Верификация времени компиляции (реализация стандартной библиотеки)

```yaoxiang
# ════════════════════════════════════════════════════════

# Определения стандартной библиотеки
# IsTrue: мост от вселенной значений к вселенной типов — отображение истинности Bool в тип
IsTrue: (b: Bool) -> Type = match b {
    true => Void,      # ⊤, имеет значение, программа продолжается
    false => Never,    # ⊥, не имеет значения, расходимость
}

# Assert: примитив уточняющего типа времени компиляции — типовое выражение proposition Bool
Assert: (cond: Bool) -> Type = IsTrue(cond)
#
# cond == true  → Assert(true)  = Void    (всегда истинно, стирается)
# cond == false → Assert(false) = Never   (всегда ложно, ошибка компиляции/расходимость)
# cond неразрешимо → конвейер доказательств решает по режиму dispatch:
#                    CompileTime → Unknown, требует prove
#                    Runtime     → вставляет check, инъекция гипотезы в Γ

    # Проверка времени компиляции: N должен быть больше 0 (Assert в позиции типа)
    length: Assert(N > 0),
}

# Способ использования 2: использование в выражении
IntArray: (N: Int) -> Type = StaticArray(Int, N)
# Верификация: размер IntArray(10) равен sizeof(Int) * 10
```

### 5. Условные типы

> **Изоморфизм Карри-Ховарда**: условные типы с точки зрения Карри-Ховарда представляют
> **case-анализ** в логике. Тип `Bool` соответствует proposition с двумя возможными значениями
> (True/False), `If` выбирает разные результаты в зависимости от истинности proposition — это и есть
> логический case-анализ дизъюнкции. `match C { True => T, False => E }` по сути выражает: «дано,
> что proposition C истинно, заключение — T; дано, что C ложно, заключение — E».

#### 5.1 Условный тип If

```yaoxiang
# If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Пример: ветвление времени компиляции
NonEmpty: (T: Type) -> Type = If(T != Void, T, Never)

Optional: (T: Type) -> Type = If(T != Void, T, Void)

# Верификация времени компиляции (унифицирована с определением Assert в §4.3)
# Assert: (cond: Bool) -> Type = IsTrue(cond)

# Использование
# Вычисление типа: If(True, Int, String) => Int
# Вычисление типа: If(False, Int, String) => String
```

#### 5.2 Type family

> **Изоморфизм Карри-Ховарда**: type family — наиболее прямое воплощение «propositions как типы».
> `Add: (A: Type, B: Type) -> Type` — это не «функция сложения, записанная на уровне типов», а
> **конструирование proposition о сложении натуральных чисел**. `(Zero, B) => B` говорит
> «proposition Add(Zero, B) эквивалентно B», `(Succ(A'), B) => Succ(Add(A', B))` говорит «если
> Add(A', B) выполняется, то Add(Succ(A'), B) тоже выполняется». Это и есть определение сложения из
> аксиом Пеано. То, что проверка типов валидирует это выражение match, эквивалентно валидации
> логической согласованности этого определения.

```yaoxiang
# Преобразование типов времени компиляции
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,  # По умолчанию
}

# Вычисления на уровне типов
Length: (T: Type) -> Type = match T.length {
    0 => Zero,
    1 => Succ(Zero),
    2 => Succ(Succ(Zero)),
    _ => TooLong,
}

# Сложение на уровне типов (Карри-Ховард: case-анализ + рекурсивный вызов, требует проверки завершаемости для полной индукции)
Add: (A: Type, B: Type) -> Type = match (A, B) {
    (Zero, B) => B,
    (Succ(A'), B) => Succ(Add(A', B)),
}

# Пример: вычисление времени компиляции 2 + 3
Two: Type = Succ(Succ(Zero))
Three: Type = Succ(Succ(Succ(Zero)))
Five: Type = Add[Two, Three]  # Succ(Succ(Succ(Succ(Succ(Zero)))))
```

````
### 7. Механизм устранения мёртвого кода

#### 7.1 Анализ графа инстанцирования

```rust
// Внутри компилятора: построение графа зависимостей инстанцирований обобщений
struct InstantiationGraph {
    // Узлы: инстанцирования обобщений
    nodes: HashMap<InstanceKey, InstanceNode>,

    // Рёбра: отношения использования
    edges: HashMap<InstanceKey, Vec<InstanceKey>>,
}

struct InstanceKey {
    generic: FunctionId,  // ID обобщённой функции
    type_args: Vec<TypeId>,  // Параметры-типы
    const_args: Vec<ConstId>,  // Параметры Const
}

// Алгоритм: анализ достижимости
fn eliminate_dead_instantiations(graph: &InstantiationGraph) {
    let mut reachable = HashSet::new();

    // Начинаем с точек входа (main, экспортируемые функции и т.д.)
    let entry_points = find_entry_points();
    for entry in entry_points {
        dfs_visit(entry, &graph, &mut reachable);
    }

    // Не посещённые инстанцирования — мёртвый код
    for node in &graph.nodes {
        if !reachable.contains(node.key) {
            eliminate(node);
        }
    }
}
````

```yaoxiang
    length: Int,

    # Обобщённые методы (T автоматически попадает в область видимости из внешнего List(T))
    push: (self: List(T), item: T) -> Void,
    pop: (self: List(T)) -> Option(T),
    map: (R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)),
    filter: (self: List(T), predicate: (T) -> Bool) -> List(T),
    fold: (U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U),
}

# ======== 2. Реализация обобщённых методов ========
# Определения функций находятся в пространстве имён List (префикс List. = принадлежность пространству имён)
# Чтобы работал синтаксис вызова через точку list.push(item), требуется явное связывание: List.push = push[0]
# self — лишь соглашение об именовании параметра, компилятор смотрит на тип, а не на имя

List.push: (T: Type) -> ((self: List(T), item: T) -> Void) = {
    if self.length >= self.data.length {
        # Расширение
        new_data = Array(T)(self.data.length * 2)
        for i in 0..self.length {
            new_data[i] = self.data[i]
        }
        self.data = new_data
    }
    self.data[self.length] = item
    self.length = self.length + 1
}

List.pop: (T: Type) -> ((self: List(T)) -> Option(T)) = {
    if self.length > 0 {
        self.length = self.length - 1
        return Option.some(self.data[self.length])
    } else {
        return Option.none()
    }
}

List.map: (T: Type, R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)) = {
    result = List(R)()
    for i in 0..self.length {
        result.push(f(self.data[i]))
    }
    return result
}

List.filter: (T: Type) -> ((self: List(T), predicate: (T) -> Bool) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        if predicate(self.data[i]) {
            result.push(self.data[i])
        }
    }
    return result
}

List.fold: (T: Type, U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U) = {
    result = initial
    for i in 0..self.length {
        result = f(result, self.data[i])
    }
    return result
}

# ======== 3. Использование ограничений типов ========
# Реализация Clone для List
List.clone: (T: Clone) -> ((self: List(T)) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        result.push(self.data[i].clone())
    }
    return result
}

# ======== 4. Примеры использования ========
# Создание обобщённого List
numbers = List(Int)()
numbers.push(1)
numbers.push(2)
numbers.push(3)

# Использование обобщённых методов
doubled = numbers.map((x) => x * 2)
evens = numbers.filter((x) => x % 2 == 0)

# Использование fold для вычисления
sum = numbers.fold(0, (acc, x) => acc + x)  # sum = 6

# Композиция обобщений
sum_of_evens = numbers
    .filter((x) => x % 2 == 0)
    .map((x) => x * 2)
    .fold(0, (acc, x) => acc + x)  # sum_of_evens = 8
```

```yaoxiang
# ======== 1. Обобщённый алгоритм сортировки ========
Comparator: (T: Type) -> Type = {
    compare: (T, T) -> Int,  # -1 if a < b, 0 if a == b, 1 if a > b
}

# Обобщённая быстрая сортировка
quicksort: (T: Clone) -> ((array: Array(T), cmp: Comparator(T)) -> Array(T)) = {
    if array.length <= 1 {
        return array.clone()
    }

    pivot = array[array.length / 2]
    left = Array(T)()
    right = Array(T)()

    for i in 0..array.length {
        if i == array.length / 2 {
            continue
        }
        item = array[i]
        comparison = cmp.compare(item, pivot)
        if comparison < 0 {
            left.push(item)
        } else {
            right.push(item)
        }
    }

    sorted_left = quicksort(left, cmp)
    sorted_right = quicksort(right, cmp)

    result = sorted_left.clone()
    result.push(pivot)
    result.extend(sorted_right)
    return result
}

# ======== 2. Реализация IntComparator ========
# Реализация через перегрузку функций
compare: (a: Int, b: Int) -> Int = {
    if a < b {
        return -1
    } else if a > b {
        return 1
    } else {
        return 0
    }
}

# ======== 3. Примеры использования ========
# Сортировка массива Int
numbers = Array(Int)(3, 1, 4, 1, 5, 9, 2, 6)
sorted = quicksort(numbers, Comparator(Int)())

# Сортировка массива String (требуется StringComparator)
strings = Array(String)("hello", "world", "foo", "bar")
sorted_strings = quicksort(strings, Comparator(String)())
```

```yaoxiang
# ======== 1. Тип матрицы времени компиляции ========
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),

    # Проверка размерности времени компиляции: с использованием типа Assert из стандартной библиотеки
    _assert: Assert(Rows > 0),  # Rows > 0, иначе ошибка компиляции
    _assert: Assert(Cols > 0),  # Cols > 0, иначе ошибка компиляции

    # Операции над матрицами
    multiply: (M: Int) -> ((self: Matrix(T, Rows, Cols), other: Matrix(T, Cols, M)) -> Matrix(T, Rows, M)) = {
        result = Matrix(T, Rows, M)()
        for i in 0..Rows {
            for j in 0..M {
                sum = Zero::zero()
                for k in 0..Cols {
                    sum = sum + self.data[i][k] * other.data[k][j]
                }
                result.data[i][j] = sum
            }
        }
        return result
    }
}

# ======== 2. Создание матрицы времени компиляции ========
identity: (T: Add + Multiply + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    for i in 0..N {
        for j in 0..N {
            if i == j {
                matrix.data[i][j] = One::one()
            } else {
                matrix.data[i][j] = Zero::zero()
            }
        }
    }
    return matrix
}

# ======== 3. Примеры использования ========
# Создание матриц с размером, известным на этапе компиляции
# Матрица 2x3
matrix_2x3 = Matrix(Float, 2, 3)()
matrix_2x3.data[0][0] = 1.0
matrix_2x3.data[0][1] = 2.0
matrix_2x3.data[0][2] = 3.0
matrix_2x3.data[1][0] = 4.0
matrix_2x3.data[1][1] = 5.0
matrix_2x3.data[1][2] = 6.0

# Матрица 3x2
matrix_3x2 = Matrix(Float, 3, 2)()
matrix_3x2.data[0][0] = 7.0
matrix_3x2.data[0][1] = 8.0
matrix_3x2.data[1][0] = 9.0
matrix_3x2.data[1][1] = 10.0
matrix_3x2.data[2][0] = 11.0
matrix_3x2.data[2][1] = 12.0

# Умножение матриц: 2x3 * 3x2 = 2x2
result = matrix_2x3.multiply(matrix_3x2)

# Проверка времени компиляции: тип result — Matrix(Float, 2, 2)
# Единичная матрица 2x2
identity_3x3 = identity(Float, 3)()

# Несовпадение размерностей: ошибка компиляции
```

## Компромиссы

### Преимущества

1. **Абстракции с нулевой стоимостью**
   - Мономорфизация времени компиляции, без накладных расходов в runtime
   - Без виртуальных функций, без RTTI

2. **Устранение мёртвого кода**
   - Анализ времени компиляции, инстанцируются только используемые обобщения
   - Управляемое раздувание кода

3. **Замена макросов**
   - Безопасная с точки зрения типов генерация кода
   - Дружественность к IDE, понятные сообщения об ошибках

4. **Вычисления времени компиляции**
   - Обобщения времени компиляции поддерживают вычисления времени компиляции
   - Возможности вроде проверки размерности
   - Без ключевого слова `const`, чистые ограничения типов

### Недостатки

1. **Время компиляции**
   - Инстанцирование обобщений увеличивает время компиляции
   - Решение ограничений может быть медленным

2. **Потребление памяти**
   - Увеличивается потребление памяти компилятором
   - Механизмы кэширования требуют памяти

3. **Сложность реализации**
   - Сложный решатель ограничений
   - Сложный движок вычислений на уровне типов

4. **Диагностика ошибок**
   - Ошибки обобщений могут быть сложными
   - Требуются понятные подсказки об ошибках

### Меры по смягчению

1. **Стратегия кэширования**
   - Кэширование результатов инстанцирования
   - LRU-кэш для ограничения памяти

2. **Инкрементальная компиляция**
   - Кэширование результатов компиляции
   - Инкрементальное инстанцирование

3. **Сообщения об ошибках**
   - Понятные сообщения об ошибках
   - Подсказки по выводу параметров обобщений

4. **Параллельная компиляция**
   - Параллельное инстанцирование обобщений
   - Многопоточное решение ограничений

## Альтернативные варианты

| Вариант                      | Почему не выбран                                    |
| ---------------------------- | --------------------------------------------------- |
| Только базовые обобщения     | Не может заменить сложные макросы                   |
| Чисто макросистема           | Нет безопасности типов, плохие сообщения об ошибках |
| Только зависимые ограничения | Недостаточная гибкость                              |
| Обобщения в runtime          | Накладные расходы по производительности             |

### Риски

| Риск                          | Влияние                      | Мера по смягчению              |
| ----------------------------- | ---------------------------- | ------------------------------ |
| Сложность решения ограничений | Слишком долгая компиляция    | Инкрементальное решение + кэш  |
| Раздувание кода               | Слишком большой бинарник     | DCE + управление порогом       |
| Сложность реализации          | Увеличение сроков разработки | Поэтапная реализация           |
| Диагностика ошибок            | Плохой пользовательский опыт | Подробные сообщения об ошибках |

### БНФ синтаксиса

```bnf
# Параметры обобщений используют унифицированный синтаксис () как часть типа функции
# Например, map: (T: Type, R: Type) -> ((list: List(T), f: (T) -> R) -> List(R))

# Ограничение типа (в параметрах обобщений)
type_bound ::= identifier
             | identifier '+' identifier ('+' identifier)*

# Объявление параметра (тип + имя)
parameter ::= identifier ':' type

parameters ::= parameter (',' parameter)*

# Объявление функции: name: type = expression
# Параметры обобщений — первая группа параметров в типе функции: (T: Type) -> ((params) -> return)
function ::= identifier ':' type '=' (expression | block)

# Объявление метода: Type.method: type = expression
method ::= identifier '.' identifier ':' type '=' (expression | block)

# Определение типа (унифицированный синтаксис Binding)
# Обобщённый тип, например List: (T: Type) -> Type = { ... }
generic_type ::= identifier ':' type '=' type_expression

# Type в параметрах обобщений автоматически заполняется компилятором по фактическим типам аргументов
# Например, map(numbers, f), T извлекается из numbers: List(Int), R — из f: (Int) -> String
```
