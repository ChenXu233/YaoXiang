# RFC-011: Дизайн системы обобщений - абстракции с нулевой стоимостью и замена макросов

## Резюме

Настоящий документ определяет **дизайн системы обобщений** языка YaoXiang, реализующий абстракции с
нулевой стоимостью за счёт мощных возможностей обобщений, использующий оптимизации времени
компиляции для снижения зависимости от макросов и предоставляющий механизм устранения мёртвого кода.

**Основные принципы дизайна**:

- **Единый синтаксис сигнатур**: `(T: Type, R: Type) -> ...` — параметры обобщений и обычные
  параметры унифицированы
- **Механизм самоописания Type**: `Type` — сущность уровня языка, позиции `Type` в сигнатурах могут
  быть автоматически выведены и заполнены
- **Ограничения типов**: `T: Dup + Add` — множественные ограничения, ограничения на типы функций
- **Ассоциированные типы**:
  `Iterator: (Item: Type) -> Type = { next: () -> Option(Item), has_next: () -> Bool }`
- **Обобщения времени компиляции**: `N: Int` — обобщённые параметры-значения, инстанциация
  константами времени компиляции
- **Условные типы**: `If: (C: Bool, T: Type, E: Type) -> Type` — вычисления на уровне типов,
  семейства типов

**Ценности**:

- Абстракции с нулевой стоимостью: мономорфизация во время компиляции, без затрат во время
  выполнения
- Устранение мёртвого кода: анализ графа инстанциации + оптимизации LLVM
- Замена макросов: обобщения заменяют 90% сценариев использования макросов
- Безопасность типов: проверка во время компиляции, удобно для IDE
- **Явное лучше неявного**: `Type` самоописывающий, компилятор автоматически выводит

## Концепция универсума типов и типы с зависимостью от значений

Система обобщений YaoXiang построена на **концепции универсума типов** — ментальной модели, которая
унифицирует все понятия языка в слоистую структуру. Ключевая инновация состоит в том, что **типы с
зависимостью от значений** (value-dependent types) получают статус полноправного гражданина слоя
Type2.

### Что такое тип с зависимостью от значений?

**Тип с зависимостью от значений** — это тип, который зависит от одного или нескольких **значений**
(а не только от других типов). Эти значения могут быть вычислены во время компиляции, обеспечивая
гарантии безопасности типов уже на этом этапе.

```yaoxiang
# 传统泛型：类型参数
List: (T: Type) -> Type

# 值依赖类型：值参数
Vec: (n: Int) -> Type  # 向量类型依赖于长度值 n
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type  # 矩阵类型依赖于行数和列数
```

### Ключевые преимущества типов с зависимостью от значений

По сравнению с традиционными обобщениями, типы с зависимостью от значений YaoXiang обладают
следующими ключевыми преимуществами:

| Свойство                      | Традиционные обобщения (C++/Rust)                            | Типы с зависимостью от значений YaoXiang                                                |
| ----------------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| Зависимость типа от значений  | Только от параметров-типов                                   | Может зависеть от любого значения, включая результат вызова функции                     |
| Вычисление времени компиляции | C++ шаблоны требуют ручной специализации, в Rust отсутствует | Автоматическое вычисление времени компиляции с гарантией завершения                     |
| Вычисления на уровне типов    | Метапрограммирование шаблонов (сложное/опасное)              | Единый механизм вычислений на уровне типов                                              |
| Безопасность типов            | В C++ отсутствует, в Rust ограничена                         | Полная безопасность типов, проверка времени компиляции                                  |
| Проверка размерности          | Проверка во время выполнения или ручная специализация        | Автоматическая проверка размерности во время компиляции, без затрат во время выполнения |

### Иерархия универсума типов и типы с зависимостью от значений

Концепция универсума типов разделяет понятия языка по семантической роли на разные слои. Типы с
зависимостью от значений располагаются на слое **Type2**:

| Слой      | Роль                                                         | Пример                                                                                               |
| --------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| Type-1    | Значения                                                     | `42`, `factorial(5)`, сама функция                                                                   |
| Type0     | Ключевое слово метатипа                                      | `Type`                                                                                               |
| Type1     | Конкретный тип                                               | `Int`, `String`, `Vec(3)`                                                                            |
| **Type2** | **Функция/конструктор типов/тип с зависимостью от значений** | `add: (Int, Int) -> Int`, `Vec: (n: Int) -> Type`, `Matrix: (T: Type, Rows: Int, Cols: Int) -> Type` |

**Ключевой дизайн**: функции слоя Type2, конструкторы типов и типы с зависимостью от значений имеют
**единый синтаксис** в форме `(params) -> result`:

- Обычная функция: `(Int, Int) -> Int` → результат — значение
- Конструктор типов: `(T: Type) -> Type` → результат — тип
- Тип с зависимостью от значений: `(n: Int) -> Type` → результат — тип, но зависит от
  параметров-значений

> **Изоморфизм Карри-Ховарда**: это единство — не случайность. Изоморфизм Карри-Ховарда утверждает,
> что «типы суть высказывания, программы суть доказательства» — тип функции `A → B` соответствует
> логической импликации «если A, то B», обобщение `(T: Type) -> Type` соответствует универсальной
> квантификации «для всех типов T», тип с зависимостью от значений `(n: Int) -> Type` соответствует
> «для каждого целого n существует тип». YaoXiang унифицирует функции, конструкторы типов и типы с
> зависимостью от значений в слое Type2, по сути объединяя «доказательство» и «вычисление» в одно
> понятие — **конструктивное доказательство**. Это и есть прямое воплощение изоморфизма
> Карри-Ховарда в дизайне языка: единая форма `(params) -> result` одновременно несёт логическое
> высказывание и процесс вычисления.

### Гарантия детерминизма времени компиляции

Концепция универсума типов YaoXiang требует: **всё на слое Type должно быть определено во время
компиляции**.

```yaoxiang
# 编译期维度验证示例
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),
    # 编译期检查：维度必须为正
    _assert: Assert(Rows > 0),
    _assert: Assert(Cols > 0),
}

# 创建 3x3 单位矩阵 - 编译期完成
identity: (T: Add + Zero + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    # ...
}

# 编译期计算：factorial(3) = 6，向量大小在编译期确定
vec: Vec(factorial(3)) = Vec(6)()
```

Компилятор автоматически:

1. Обнаруживает вызовы функций в позициях типов
2. Выполняет проверку завершимости вызова (см. механизм проверки завершимости ниже)
3. Выполняет вычисление во время компиляции
4. Встраивает результат в генерируемый тип

### Сценарии применения типов с зависимостью от значений

#### Проверка размерности во время компиляции

```yaoxiang
# 矩阵乘法：编译期验证维度匹配
multiply: (T: Add + Multiply + Zero,
           Rows: Int, Cols: Int, M: Int) -> ((
    a: Matrix(T, Rows, Cols),
    b: Matrix(T, Cols, M)
) -> Matrix(T, Rows, M)) = {
    # 编译期检查：a.Cols == b.Rows，否则编译错误
    result = Matrix(T, Rows, M)()
    # ...
}

# 错误在编译期捕获：
# multiply(matrix_2x3, matrix_4x2)  # 编译错误：2 != 4
```

#### Типобезопасный размер массива

```yaoxiang
# 数组大小是编译期常量
Array: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    length: N,
}

# N 是编译期常量，可以用于类型级计算
first_three: Array(Int, 3) = Array(Int, 3)(1, 2, 3)
# first_three.length == 3（编译期已知）
```

#### Целевой механизм переноса ошибок на границах во время компиляции

> **Замечание о состоянии реализации**: типы контейнеров деспециализированы — `Array(T, N)` является
> конструктором обобщений const; точки привязки в контексте литералов, предикат принадлежности `in`
> уже реализованы. Точка привязки литерала `Array(T, N)` — N и тип элемента — принудительно
> проверяется на этапе компиляции (E1002), **N считается надёжным** — механизм, преследуемый данным
> разделом, может основываться на «аннотации N == длина во время выполнения». В текущем состоянии
> выход за границы `[]` (E6003) и отсутствующий ключ Dict (E6008) являются **переходным состоянием
> ошибки времени выполнения**; типы с зависимостью от значений в этом разделе — целевой механизм,
> переносящий эти ошибки на границах на **время компиляции**:
>
> - индекс const: `a[5]` (5 — константа времени компиляции), когда `a: Array(Int, 3)`, сразу
>   отвергается во время компиляции;
> - индекс-значение: `a[i]` требует предусловия `i < len(a)`, доказываемого контрактом типа с
>   зависимостью от значений;
> - предикат `in` — основа предусловий логики Хоара: `n in 1..10`, `x in some_set` — это доказуемые
>   во время компиляции высказывания.
>
> Полный дизайн уточнённых типов будет дополнен отдельно при реализации этого раздела.

#### Обобщённые функции

```yaoxiang
# map: 泛型函数，类型参数 T, R 在编译期确定
map: (T: Type, R: Type) -> (
    (list: List(T), f: (x: T) -> R) -> List(R)
) = (list, f) => {
    result = List(R)()
    for x in list {
        result.push(f(x))
    }
    return result
}

# 使用时完全透明，类型自动推导
numbers = List(Int)()   # 勘误：值构造两层形式（见 §9.1）；元素用 push 填充
numbers.push(1)
numbers.push(2)
numbers.push(3)
doubled = map(numbers, (x) => x * 2)  # 推导为 map[Int, Int]
```

### Механизм проверки завершимости (унифицирован с RFC-027)

Вычисление во время компиляции для типов с зависимостью от значений должно **гарантировать
завершимость**, иначе система типов попадёт в бесконечный цикл. Проверка завершимости выполняется
**полностью автоматически** конвейером доказательств времени компиляции из RFC-027 — компилятор
автоматически синтезирует меры; рекурсия/цикл, которые удаётся доказать, проходят; те, что доказать
не удаётся, сразу дают ошибку компиляции. **Полуавтоматическим аннотациям не оставлено лазеек**:
`//! decreases` и `/*! invariant !*/` из RFC-022 отменены вместе с RFC-022, спецификация — это сама
аннотация типа.

#### Проверка завершимости рекурсивных функций

Перед вычислением во время компиляции компилятор проверяет, что аргументы рекурсивного вызова строго
убывают на каждом пути рекурсии (RFC-027 §6.7). Никакие аннотации спецификации не требуются:

```yaoxiang
# 编译期阶乘：无 //! requires/ensures/decreases，编译器自动分析
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)  # 编译器分析：n-1 < n → 递减 → 终止
}

# 使用：在类型位置调用，编译器先验证终止再求值
vec: Vec(factorial(5)) = Vec(120)()  # 编译期求值 factorial(5) = 120
```

| Сценарий                                                              | Поведение                          |
| --------------------------------------------------------------------- | ---------------------------------- |
| Компилятор может проанализировать убывание рекурсии (например, `n-1`) | Вычисление во время компиляции     |
| Убывание не обнаружено / неразрешимо                                  | Ошибка компиляции                  |
| Вызов во время выполнения (не в позиции типа)                         | Проверка завершимости не требуется |

#### Проверка завершимости циклов

Циклам не нужны аннотации `: Invariant(...)` или `: decreases(...)`. Аннотации уточнённых типов на
переменных (например, `UpTo(n)`) одновременно задают инвариант цикла и границу меры; компилятор
перебирает четыре стратегии синтеза мер по приоритету и останавливается на первой успешной (RFC-027
§7):

1. **Автоматический синтез линейной ранговой функции** — извлечение границ переменных из аннотаций
   типов, перебор линейных комбинаций, SMT-проверка m ≥ 0 и m' < m на всех путях
2. **Подсчёт нарушений предиката** (экспериментальный) — извлечение violation_count из определения
   целевого типа (например, `Sorted`), покрытие соседних обменов/перемещений
3. **Шаблон ограниченного возрастания/убывания** — `v += const` → мера `upper - v` (вырождение
   стратегии 1, самый быстрый путь)
4. **Шаблон меры с мультипликативным масштабированием** — `v *= const` (const > 1) → мера
   `ceil(log_const(upper / v))`

```yaoxiang
sum: (arr: Array(Int, n)) -> Int = {
    mut i: UpTo(arr.len) = 0   # 类型标注给出上界 arr.len 与下界 0
    while i < arr.len {
        # 编译器自动推导：度量 arr.len - i，每次迭代严格递减 1 → 终止得证
        s += arr[i]; i += 1
    }
    return sum
}
```

#### Рабочий процесс проверки завершимости

```
┌─────────────────────────────────────────────────────────────┐
│  阶段 проверки типов                                                │
│  Встречается вызов функции в позиции типа (например, Vec(factorial(5)))            │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  1. Проверка завершимости (конвейер доказательств RFC-027, полностью автоматический)                     │
│     - Рекурсивные функции: проверка строгого убывания аргументов на каждом пути рекурсии             │
│     - Циклы: четыре стратегии синтеза мер (линейная ранговая / подсчёт нарушений / ограниченный шаблон /      │
│       мультипликативное масштабирование), SMT-проверка убывания                                │
│     - Доказать не удалось → ошибка компиляции (жёсткая граница, без полуавтоматических аннотаций)        │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  2. Вычисление времени компиляции (выполняется встроенным интерпретатором)                           │
│     - Чистые функции: непосредственное вычисление                                       │
│     - Побочные эффекты: ошибка компиляции (позиция типа должна быть без побочных эффектов)                │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  3. Встраивание результата в тип                                            │
│     - Vec(factorial(5)) → Vec(120)                          │
│     - Matrix(Float, 3, 3) → конкретный тип                        │
└─────────────────────────────────────────────────────────────┘
```

#### Преимущества

- **Безопасность**: гарантирует, что вычисление времени компиляции обязательно завершится, не давая
  системе типов попасть в бесконечный цикл
- **Единообразие**: проверка завершимости и верификация корректности (генерация VC) используют общий
  конвейер доказательств времени компиляции (RFC-027), без отдельного синтаксиса спецификаций
- **Полная автоматизация**: компилятор автоматически синтезирует меры из аннотаций типов; доказуемое
  — проходит, недоказуемое — сообщает об ошибке, не полагаясь на ручные `decreases`

## Мотивация

### Зачем нужна мощная система обобщений?

Существующие обобщения в主流 языках имеют ограничения:

| Язык         | Возможности обобщений               | Проблема                                                                                          |
| ------------ | ----------------------------------- | ------------------------------------------------------------------------------------------------- |
| Java         | Ограниченные типы                   | Мономорфизация во время компиляции, без специализации обобщений                                   |
| C#           | Ограничения обобщений               | Проверка типов во время выполнения, затраты производительности                                    |
| Rust         | Обобщения + Trait                   | Сложная система Trait, крутая кривая обучения                                                     |
| C++          | Шаблоны                             | Сложная специализация шаблонов, плохие сообщения об ошибках компиляции                            |
| **YaoXiang** | **Типы с зависимостью от значений** | **Тип может зависеть от значений, проверка размерности во время компиляции, гарантия завершения** |

### Основные противоречия

1. **Производительность против гибкости**: гибкость во время выполнения против оптимизации времени
   компиляции
2. **Сложность против простоты**: мощная система типов против удобства использования
3. **Макросы против обобщений**: кодогенерация макросами против безопасности типов обобщений
4. **Зависимость от значений против безопасности типов**: традиционные обобщения не могут проверить
   размерности во время компиляции

### Ключевые преимущества типов с зависимостью от значений

**Типы с зависимостью от значений** YaoXiang — ключевое преимущество перед традиционными
обобщениями:

| Преимущество                      | Описание                                                                                                                                    |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **Зависимость типа от значений**  | `Vec: (n: Int) -> Type` позволяет типу зависеть от конкретного значения                                                                     |
| **Вычисление времени компиляции** | Вызовы функций в позиции типа вычисляются во время компиляции, результат непосредственно встраивается в тип                                 |

## Цели дизайна

### Основные цели

1. **Абстракции с нулевой стоимостью** — вызов обобщений эквивалентен вызову конкретного типа
2. **Устранение мёртвого кода** — анализ во время компиляции, инстанциация только используемых
   обобщений
3. **Замена макросов** — обобщения заменяют 90% сценариев использования макросов
4. **Безопасность типов** — проверка во время компиляции, без затрат на типы во время выполнения
5. **Удобство для IDE** — интеллектуальные подсказки, понятные сообщения об ошибках
6. **Типы с зависимостью от значений** — тип может зависеть от значений, поддержка проверки
   размерности во время компиляции
7. **Безопасность вычислений времени компиляции** — гарантия завершимости вычислений во время
   компиляции за счёт проверки завершимости (автоматический синтез мер из RFC-027)

### Принципы дизайна

- **Определённость времени компиляции**: параметры обобщений определяются во время компиляции
- **Приоритет мономорфизации**: генерация конкретного кода, без вызовов виртуальных функций
- **Управление через ограничения**: ограничения типов направляют инстанциацию
- **Оптимизации платформы**: специализация с поддержкой платформенно-специфичных оптимизаций
- **Единство универсума типов**: функции/конструкторы типов/типы с зависимостью от значений
  унифицированы в слое Type2
- **Гарантия завершимости**: вызовы функций в позиции типа должны доказуемо завершаться

### 1. Базовые обобщения

#### 1.1 Параметры-типы обобщений

> **Ключевое правило**: определение обобщённого типа **должно явно аннотироваться `: Type`**, иначе
> будет выведено HM как функция.
>
> | Запись                            | Значение                            |
> | --------------------------------- | ----------------------------------- |
> | `List: (T: Type) -> Type = {...}` | ✅ Конструктор типов                |
> | `List = {...}`                    | ❌ HM выводит как функцию, а не тип |

```yaoxiang
# 泛型类型定义（必须有 : Type）
Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self
}

Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self
}

List: (T: Type) -> Type = {
    data: Array(T),
    length: Int,
    push: (self: List(T), item: T) -> Void,   # self 只是约定名，不是关键字
    get: (self: List(T), index: Int) -> Option(T),
}

# 泛型函数（无 : Type，HM 推断为函数）
map: (T: Type, R: Type) -> ((opt: Option(T), f: Fn(T) -> R) -> Option(R)) = {
    return match opt {
        some => Option.some(f(some)),
        none => Option.none(),
    }
}

# 泛型约束（直接表达式，单行可省略 return）
clone: (T: Clone)(value: T) -> T = value.clone()

# 多类型参数
combine: (T: Type, U: Type) -> ((a: T, b: U) -> (T, U)) = (a, b)
```

#### 2.4 Встроенные маркерные trait: Dup и Clone

**Три вида семантики копирования**:

| Тип                                  | Значение                                                                                      | Способ срабатывания                               | Сценарий применения                |
| ------------------------------------ | --------------------------------------------------------------------------------------------- | ------------------------------------------------- | ---------------------------------- |
| **Копирование примитивных значений** | При присваивании автоматическое копирование значения, два значения полностью независимы       | Автоматически при присваивании/передаче параметра | Int, Float, Bool, Char             |
| **Dup**                              | Поверхностное копирование: копируется дескриптор/токен, базовые данные совместно используются | Автоматически при присваивании/передаче параметра | Токены `&T`, `ref T`, String/Bytes |
| **Clone**                            | Глубокое копирование: создание полной независимой копии                                       | `value.clone()`                                   | Любой тип, реализующий Clone       |

**Семантика Dup**: для типов, реализующих Dup, при присваивании/передаче параметра владение не
передаётся — компилятор копирует дескриптор/токен, и несколько владельцев указывают на одни и те же
базовые данные. Это дополняет семантику Move по умолчанию в модели владения из RFC-009.

**Dup и Clone — ортогональные понятия**:

```
Dup = копирование дескриптора, совместное использование данных (изменения влияют друг на друга)
Clone = копирование данных, копия независима (изменения не влияют друг на друга)
```

**Правила**:

```
1. Примитивные типы-значения (Int, Float, Bool, Char) — встроенное в компилятор копирование значений, не относятся к Dup
2. Dup  — применим только к ссылочным/токенным типам и типам со внутренним подсчётом ссылок
3. Clone — явное глубокое копирование, может реализовать любой тип
4. По умолчанию Move — остальные типы сохраняют семантику Move по умолчанию
```

**Какие типы являются Dup**:

| Тип                         | Dup       | Причина                                                                                    |
| --------------------------- | --------- | ------------------------------------------------------------------------------------------ |
| `&T` (токен заимствования)  | ✅        | Токен нулевого размера, копия токена = несколько представлений, указывающих на одни данные |
| `ref T`                     | ✅        | Копия Rc/Arc = счётчик ссылок +1, совместно используемые данные в куче                     |
| String, Bytes               | ✅        | Внутренний подсчёт ссылок, копия дескриптора совместно использует базовый buffer           |
| `&mut T` (изменяемый токен) | ❌        | Линейная исключительность, копирование невозможно                                          |
| struct                      | Выводится | Все поля Dup → struct Dup                                                                  |
| enum                        | Выводится | Все поля всех вариантов Dup → enum Dup                                                     |
| tuple                       | Выводится | Все элементы Dup → tuple Dup                                                               |
| Fn (замыкание)              | ❌        | Захваченное окружение может быть не Dup                                                    |
| `*T` (сырой указатель)      | ❌        | unsafe, не участвует в системе владения                                                    |

**Int/Float/Bool/Char — не Dup** — это типы-значения; при присваивании компилятор автоматически
копирует значение (два значения полностью независимы). Это не «поверхностное копирование», а
встроенная обработка примитивов компилятором, которую не нужно и не следует выражать через атрибут
типа Dup.

```yaoxiang
# 原语值类型：编译器自动值复制（不是 Dup）
x: Int = 42
y = x          # 值复制，x 和 y 完全独立
print(x)       # ✅

# Dup：浅拷贝，复制句柄共享数据
view: &Point = &point
view2 = view    # ✅ Dup：复制令牌，两者指向同一个 point
print(view.x)   # ✅

# Clone：显式深拷贝，创建独立副本
backup = big_struct.clone()  # 显式调用

# 泛型约束
dup_use: (T: Dup) -> T = x         # T: Dup → 可以浅拷贝
clone_use: (T: Clone) -> T = x.clone()  # T: Clone → 可以深拷贝
```

> **Замечание**: `Send`/`Sync` не делаются видимыми пользователю trait. Безопасность межзадачного
> доступа обеспечивается полностью автоматически ключевым словом `ref` и компилятором — `ref`
> автоматически выбирает Rc или Arc, пользователю не нужно понимать Send/Sync.

```yaoxiang
# Iterator trait（使用 (Item: Type) -> Type 语法）
Iterator: (Item: Type) -> Type = {
    next: (Self) -> Option(Item),

collect_all: (T: Type, I: Iterator(T))(iter: I) -> List(T) = {

        }
    }
    return result
}

# Array的Iterator实现
# 使用方法语法糖：Array.Item, Array.next, Array.has_next
Array.has_next: (T: Type)(self: Array(T)) -> Bool = {
    return self.index < self.length
}

Array.next: (T: Type)(self: Array(T)) -> Option(T) = {
    if has_next(self) {
        item = self.data[self.index]
        self.index = self.index + 1
        return Option.some(item)
    } else {
        return Option.none()
    }
}

Array.Item: (T: Type)(arr: Array(T)) -> T = {
    return arr.data[0]
}
```

### 4. Обобщения времени компиляции

#### 4.1 Параметры-значения времени компиляции

> **Исправление**: исходный текст гласил «параметры-значения, такие как `Int`, по умолчанию
> определены во время компиляции в контексте обобщений», что **строго неверно** — в
> `add: (a: Int, b: Int) -> Int = a + b` параметры `a`/`b` являются параметрами-значениями времени
> выполнения. Только **конкретные параметры-типы, на которые ссылаются в позиции типа**, являются
> параметрами-значениями времени компиляции. Правильное определение см. ниже.

**Ключевой дизайн**: ключевое слово `Type` в сигнатуре обобщения маркирует параметры-типы;
параметры, аннотированные конкретным типом (`Int`/`Bool`/`Float` и т.п.), становятся **кандидатами в
параметры-значения времени компиляции**; становятся ли они таковыми, зависит от того, **упоминаются
ли их значения в позиции типа** (зависимость от значений). Ключевое слово `const` не требуется.

**Правило определения (два шага)**:

1. **Грубая фильтрация по форме**: параметр аннотирован конкретным типом, отличным от `Type`
   (например, `Int`) → становится кандидатом.
2. **Тонкая фильтрация по использованию**: имя кандидата появляется в **позиции типа** (тип поля в
   теле типа, тип параметра внутренней `Fn`, предикат `Assert`, позиция аргумента конструктора типа
   вроде `Array(T, N)` и т.п.) → подтверждается как параметр-значение времени компиляции; иначе
   считается **параметром-значением времени выполнения**.

| Запись                                                     | Определение                                 | Причина                                                                       |
| ---------------------------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------- |
| `add: (a: Int, b: Int) -> Int = a + b`                     | a/b — параметры-значения времени выполнения | Появляются только в позиции значения, не участвуют в построении типа          |
| `Array: (T: Type, N: Int) -> Type = { data: Array(T, N) }` | N — параметр-значение времени компиляции    | N появляется в позиции аргумента конструктора типа `Array(T, N)`              |
| `factorial: (N: Int) -> (k: N) -> Int`                     | N — параметр-значение времени компиляции    | N выступает типом внутреннего параметра `k`                                   |
| `Foo: (T: Type, N: Int) -> Type = { x: T }`                | N выпадает (см. ниже)                       | N не упомянут в теле типа, вырождается в параметр-значение времени выполнения |

> **Суть зависимости от значений**: параметр-значение времени компиляции — это тип с зависимостью от
> значений — только когда значение используется для **построения типа**, требуется определённость во
> время компиляции. Форма (`: Int`) определяет лишь кандидатуру, использование (выход в позицию
> типа) определяет, является ли он параметром-значением времени компиляции. Это тот же критерий, что
> и в разделе «Гарантия детерминизма времени компиляции» о том, что «вызовы функций в позиции типа
> вычисляются во время компиляции».

```yaoxiang
# ════════════════════════════════════════════════════════
# 编译期值参数：N 在类型位置（Array 长度槽）被引用
# ════════════════════════════════════════════════════════
StaticArray: (T: Type, N: Int) -> Type = {
    data: Array(T, N),  # N 出现在类型构造实参位 → 编译期值参数
    length: N,
}

# 使用方式：factorial(5) 在类型位置求值（编译期），结果 120 嵌入类型
arr: StaticArray(Int, factorial(5))  # StaticArray(Int, 120)

# ════════════════════════════════════════════════════════
# 值依赖：N 作为内层参数 k 的类型
# ════════════════════════════════════════════════════════
# N 是编译期值参数（出现在 (k: N) 的类型位）；
# k 是运行时值参数，其类型为字面量类型 N（单值类型）。
factorial: (N: Int) -> (k: N) -> Int = {
    return match k {
        0 => 1,
        _ => k * factorial(k - 1)
    }
}
```

> **Обработка выпавших кандидатов**: кандидаты, аннотированные конкретным типом, но не упомянутые в
> позиции типа (например, `N` в `Foo` выше), вырождаются в параметры-значения времени выполнения
> (путь на уровне функции). Выпавшие кандидаты на пути конструктора типа не могут занять слот
> времени выполнения (конструктор типа вычисляется во время компиляции), поэтому сторона объявления
> сразу сообщает об ошибке [E1094]: «N объявлен как параметр-значение времени компиляции, но не
> упомянут в теле типа» — ранее тихое отбрасывание приводило к несоответствию арности инстанциации.

### Never и Void: ⊥ и ⊤ в системе типов

Система типов YaoXiang в изоморфизме Карри-Ховарда обладает одновременно ⊥ (ложь/пустой тип) и ⊤
(истина/Unit), выраженными двумя встроенными именами типов `Never` и `Void`:

**Never (⊥)** — три не подлежащих обсуждению базовых свойства:

1. **Нулевой конструктор**: ни один литерал или выражение не может породить значение типа `Never`.
   Это метауровневое свойство, должно быть встроенным.
2. **Принцип взрыва**: `Never <: T` выполняется для любого типа `T`. Значение `Never` может
   использоваться как значение любого типа — именно поэтому код после `assert(false)` всё ещё
   проходит проверку типов (хотя никогда не достигается).
3. **Маркер расходимости**: `f: (...) -> Never` означает, что `f` гарантирует невозврат. Компилятор
   использует это для анализа мёртвого кода.

`Never` — встроенное имя типа, не ключевое слово, парсер не замечает его. Синтаксис литерала пустого
и типа не открывается.

**Void (⊤, т.е. Unit)** — ровно один обитатель (значение void по умолчанию) — носитель истинного
высказывания «всегда истинно». `Void` — единичный элемент пустого типа-произведения, `Never` —
единичный элемент пустого типа-суммы — они двойственны. `x: Void = <по умолчанию>` допустимо,
`x: Never = ...` справа писать нечего.

#### 4.3 Верификация времени компиляции (реализация в стандартной библиотеке)

```yaoxiang
# IsTrue：值宇宙到类型宇宙的桥——Bool 真值映射为类型
IsTrue: (b: Bool) -> Type = match b {
    true => Void,      # ⊤，有值，程序继续
    false => Never,    # ⊥，无值，发散
}

# Assert：编译期精化类型原语——对 Bool 命题的类型级表述

#
# cond 为 true  → Assert(true)  = Void    （恒真，擦除）
# cond 为 false → Assert(false) = Never   （恒假，编译错误/发散）
# cond 判不了   → 由证明管道按 dispatch 模式决定：
#                  CompileTime → Unknown，要求 prove
#                  Runtime     → 插入 check，注入 Γ 假设

    length: Assert(N > 0),

# 验证：IntArray(10) 的大小等于 sizeof(Int) * 10
```


### 5. Условные типы

> **Изоморфизм Карри-Ховарда**: с точки зрения Карри-Ховарда условные типы представляют
> **case-анализ** в логике. Тип `Bool` соответствует высказыванию с двумя возможными значениями
> (True/False), а `If` выбирает разные результаты в зависимости от истинности этого высказывания —
> это и есть логическая дизъюнкция случаев. Выражение `match C { True => T, False => E }` на самом
> деле выражает: «если высказывание C истинно, заключение T, если ложно — заключение E».

#### 5.1 Условный тип If

```yaoxiang
# 类型级If
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# 示例：编译期分支
NonEmpty: (T: Type) -> Type = If(T != Void, T, Never)

Optional: (T: Type) -> Type = If(T != Void, T, Void)

# 编译期验证（统一到 §4.3 的 Assert 定义）
# Assert: (cond: Bool) -> Type = IsTrue(cond)

# 使用
# 类型计算：If(True, Int, String) => Int
# 类型计算：If(False, Int, String) => String
```

#### 5.2 Семейства типов

> **Изоморфизм Карри-Ховарда**: семейства типов — самое прямое воплощение принципа «высказывания
> суть типы». `Add: (A: Type, B: Type) -> Type` — это не «функция сложения, записанная на уровне
> типов», а **построение высказывания о сложении натуральных чисел**. `(Zero, B) => B` означает
> «высказывание Add(Zero, B) эквивалентно B», `(Succ(A'), B) => Succ(Add(A', B))` означает «если
> Add(A', B) выполняется, то Add(Succ(A'), B) также выполняется». Это и есть само определение
> сложения в аксиомах Пеано. То, что средство проверки типов принимает это выражение match,
> эквивалентно проверке логической непротиворечивости данного определения.

```yaoxiang
# 编译期类型转换
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,  # 默认
}

# 类型级计算
Length: (T: Type) -> Type = match T.length {
    0 => Zero,
    1 => Succ(Zero),
    2 => Succ(Succ(Zero)),
    _ => TooLong,
}

# 类型级加法（Curry-Howard：case analysis + 递归调用，需要终止性检查才是完整归纳）
Add: (A: Type, B: Type) -> Type = match (A, B) {
    (Zero, B) => B,
    (Succ(A'), B) => Succ(Add(A', B)),
}

# 示例：编译期计算 2 + 3
Two: Type = Succ(Succ(Zero))
Three: Type = Succ(Succ(Succ(Zero)))
Five: Type = Add[Two, Three]  # Succ(Succ(Succ(Succ(Succ(Zero)))))
```

````
### 7. Механизм устранения мёртвого кода

#### 7.1 Анализ графа инстанциации

```rust
// 编译器内部：构建泛型实例化依赖图
struct InstantiationGraph {
    // 节点：泛型实例化
    nodes: HashMap<InstanceKey, InstanceNode>,

    // 边：使用关系
    edges: HashMap<InstanceKey, Vec<InstanceKey>>,
}

struct InstanceKey {
    generic: FunctionId,  // 泛型函数ID
    type_args: Vec<TypeId>,  // 类型参数
    const_args: Vec<ConstId>,  // Const参数
}

// 算法：可达性分析
fn eliminate_dead_instantiations(graph: &InstantiationGraph) {
    let mut reachable = HashSet::new();

    // 从入口点开始（main、导出函数等）
    let entry_points = find_entry_points();
    for entry in entry_points {
        dfs_visit(entry, &graph, &mut reachable);
    }

    // 未访问的实例化就是死代码
    for node in &graph.nodes {
        if !reachable.contains(node.key) {
            eliminate(node);
        }
    }
}
````

```rust
    // 1. 单态化（YaoXiang编译器）
    ir.monomorphize();

    // 2. 内联优化
    ir.inline_small_functions();

    // 3. 常量传播
    ir.constant_propagation();

    // 4. 生成LLVM IR
    let llvm_ir = ir.to_llvm();

    // 5. LLVM优化pass
    llvm_ir.add_pass(Passes::DEAD_CODE_ELIMINATION);
    llvm_ir.add_pass(Passes::INLINE_FUNCTION);
    llvm_ir.add_pass(Passes::GLOBAL_DCE);
    llvm_ir.add_pass(Passes::MERGE_FUNC);

    // 6. 运行优化
    llvm_ir.run_optimization_passes();
}
```

### 9. Примеры

#### 9.1 Полный пример обобщённого контейнера

```yaoxiang
# ======== 1. 定义泛型容器 ========
# 使用 (T: Type) -> Type 语法
Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self,
}

Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self,
}

List: (T: Type) -> Type = {
    data: Array(T),
    length: Int,

    # 泛型方法（T 由外层 List(T) 自动带入作用域）
    push: (self: List(T), item: T) -> Void,
    pop: (self: List(T)) -> Option(T),
    map: (R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)),
    filter: (self: List(T), predicate: (T) -> Bool) -> List(T),
    fold: (U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U),
}

# ======== 2. 实现泛型方法 ========
# 函数定义在 List 命名空间下（List. 前缀 = 命名空间归属）
# 要让 list.push(item) 这种 . 调用语法生效，需要显式绑定：List.push = push[0]
# self 只是约定参数名，编译器不看名字看类型

List.push: (T: Type) -> ((self: List(T), item: T) -> Void) = {
    if self.length >= self.data.length {
        # 扩容
        new_data = Array(T)(self.data.length * 2)
        for i in 0..self.length {
            new_data[i] = self.data[i]
        }
        self.data = new_data
    }
    self.data[self.length] = item
    self.length = self.length + 1
}

List.pop: (T: Type) -> ((self: List(T)) -> Option(T)) = {
    if self.length > 0 {
        self.length = self.length - 1
        return Option.some(self.data[self.length])
    } else {
        return Option.none()
    }
}

List.map: (T: Type, R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)) = {
    result = List(R)()
    for i in 0..self.length {
        result.push(f(self.data[i]))
    }
    return result
}

List.filter: (T: Type) -> ((self: List(T), predicate: (T) -> Bool) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        if predicate(self.data[i]) {
            result.push(self.data[i])
        }
    }
    return result
}

List.fold: (T: Type, U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U) = {
    result = initial
    for i in 0..self.length {
        result = f(result, self.data[i])
    }
    return result
}

# ======== 3. 类型约束使用 ========
# 实现 Clone for List
List.clone: (T: Clone) -> ((self: List(T)) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        result.push(self.data[i].clone())
    }
    return result
}

# ======== 4. 使用示例 ========
# 创建泛型List
numbers = List(Int)()
numbers.push(1)
numbers.push(2)
numbers.push(3)

# 使用泛型方法
doubled = numbers.map((x) => x * 2)
evens = numbers.filter((x) => x % 2 == 0)

# 使用fold计算
sum = numbers.fold(0, (acc, x) => acc + x)  # sum = 6

# 泛型组合
sum_of_evens = numbers
    .filter((x) => x % 2 == 0)
    .map((x) => x * 2)
    .fold(0, (acc, x) => acc + x)  # sum_of_evens = 8
```

#### 9.2 Пример обобщённого алгоритма

```yaoxiang
# ======== 1. 泛型排序算法 ========
Comparator: (T: Type) -> Type = {
    compare: (T, T) -> Int,  # -1 if a < b, 0 if a == b, 1 if a > b
}

# 泛型quicksort
quicksort: (T: Clone) -> ((array: Array(T), cmp: Comparator(T)) -> Array(T)) = {
    if array.length <= 1 {
        return array.clone()
    }

    pivot = array[array.length / 2]
    left = Array(T)()
    right = Array(T)()

    for i in 0..array.length {
        if i == array.length / 2 {
            continue
        }
        item = array[i]
        comparison = cmp.compare(item, pivot)
        if comparison < 0 {
            left.push(item)
        } else {
            right.push(item)
        }
    }

    sorted_left = quicksort(left, cmp)
    sorted_right = quicksort(right, cmp)

    result = sorted_left.clone()
    result.push(pivot)
    result.extend(sorted_right)
    return result
}

# ======== 2. IntComparator实现 ========
# 使用函数重载实现
compare: (a: Int, b: Int) -> Int = {
    if a < b {
        return -1
    } else if a > b {
        return 1
    } else {
        return 0
    }
}

# ======== 3. 使用示例 ========
# 排序Int数组
numbers = Array(Int)(3, 1, 4, 1, 5, 9, 2, 6)
sorted = quicksort(numbers, Comparator(Int)())

# 排序String数组（需要StringComparator）
strings = Array(String)("hello", "world", "foo", "bar")
sorted_strings = quicksort(strings, Comparator(String)())
```

```yaoxiang
# ======== 1. 编译期矩阵类型 ========
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),

    # 编译期维度验证：利用 Assert 标准库类型
    _assert: Assert(Rows > 0),  # Rows > 0，否则编译错误
    _assert: Assert(Cols > 0),  # Cols > 0，否则编译错误

    # 矩阵运算
    multiply: (M: Int) -> ((self: Matrix(T, Rows, Cols), other: Matrix(T, Cols, M)) -> Matrix(T, Rows, M)) = {
        result = Matrix(T, Rows, M)()
        for i in 0..Rows {
            for j in 0..M {
                sum = Zero::zero()
                for k in 0..Cols {
                    sum = sum + self.data[i][k] * other.data[k][j]
                }
                result.data[i][j] = sum
            }
        }
        return result
    }
}

# ======== 2. 编译期矩阵创建 ========
identity: (T: Add + Multiply + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    for i in 0..N {
        for j in 0..N {
            if i == j {
                matrix.data[i][j] = One::one()
            } else {
                matrix.data[i][j] = Zero::zero()
            }
        }
    }
    return matrix
}

# ======== 3. 使用示例 ========
# 创建编译期已知大小的矩阵
# 2x3 矩阵
matrix_2x3 = Matrix(Float, 2, 3)()
matrix_2x3.data[0][0] = 1.0
matrix_2x3.data[0][1] = 2.0
matrix_2x3.data[0][2] = 3.0
matrix_2x3.data[1][0] = 4.0
matrix_2x3.data[1][1] = 5.0
matrix_2x3.data[1][2] = 6.0

matrix_3x2.data[1][1] = 10.0

# 矩阵乘法：2x3 * 3x2 = 2x2

# 编译期验证：result类型为 Matrix(Float, 2, 2)
```

## Компромиссы

### Преимущества

1. **Абстракции с нулевой стоимостью**
   - Мономорфизация во время компиляции, без затрат во время выполнения
   - Не нужны виртуальные функции, не нужен RTTI

2. **Устранение мёртвого кода**
   - Анализ во время компиляции, инстанциация только используемых обобщений
   - Управляемое раздувание кода

3. **Замена макросов**
   - Типобезопасная кодогенерация
   - Удобно для IDE, понятные сообщения об ошибках

4. **Вычисления во времени компиляции**
   - Обобщения во времени компиляции поддерживают вычисления во времени компиляции
   - Такие возможности, как проверка размерности
   - Без необходимости в ключевом слове `const`, чистое ограничение типов

### Недостатки

1. **Время компиляции**
   - Инстанциация обобщений увеличивает время компиляции
   - Разрешение ограничений может быть медленным

2. **Потребление памяти**
   - Увеличивается потребление памяти компилятором
   - Механизмам кэширования требуется память

3. **Сложность реализации**
   - Сложный решатель ограничений
   - Сложный механизм вычислений на уровне типов

4. **Диагностика ошибок**
   - Ошибки обобщений могут быть сложными
   - Требуются понятные подсказки об ошибках

### Меры по смягчению

1. **Стратегия кэширования**
   - Кэширование результатов инстанциации
   - LRU-кэш для ограничения памяти

2. **Инкрементальная компиляция**
   - Кэширование результатов компиляции
   - Инкрементальная инстанциация

3. **Подсказки об ошибках**
   - Понятные сообщения об ошибках
   - Подсказки по выводу параметров обобщений

4. **Параллельная компиляция**
   - Параллельная инстанциация обобщений
   - Многопоточное разрешение ограничений

## Альтернативы

| Решение                         | Почему не выбрано                                   |
| ------------------------------- | --------------------------------------------------- |
| Только базовые обобщения        | Не могут заменить сложные макросы                   |
| Чистая система макросов         | Нет безопасности типов, плохие сообщения об ошибках |
| Только ограничения зависимостей | Недостаточная гибкость                              |
| Обобщения времени выполнения    | Затраты производительности                          |

### Риски

| Риск                             | Воздействие                     | Мера по смягчению                        |
| -------------------------------- | ------------------------------- | ---------------------------------------- |
| Сложность разрешения ограничений | Слишком долгое время компиляции | Инкрементальное разрешение + кэширование |
| Раздувание кода                  | Слишком большой двоичный файл   | DCE + контроль порога                    |
| Сложность реализации             | Увеличенный цикл разработки     | Поэтапная реализация                     |
| Диагностика ошибок               | Плохой пользовательский опыт    | Подробные сообщения об ошибках           |

### Синтаксис BNF

```bnf
# 泛型参数使用统一 () 语法，作为函数类型的一部分
# 如 map: (T: Type, R: Type) -> ((list: List(T), f: (T) -> R) -> List(R))

# 类型约束（在泛型参数中）
type_bound ::= identifier
             | identifier '+' identifier ('+' identifier)*

# 参数声明（类型 + 名字）
parameter ::= identifier ':' type

parameters ::= parameter (',' parameter)*

# 函数声明：name: type = expression
# 泛型参数是函数类型中的第一个参数组：(T: Type) -> ((params) -> return)
function ::= identifier ':' type '=' (expression | block)

# 方法声明：Type.method: type = expression
method ::= identifier '.' identifier ':' type '=' (expression | block)

# 类型定义（统一 Binding 语法）
# 泛型类型如 List: (T: Type) -> Type = { ... }
generic_type ::= identifier ':' type '=' type_expression

# 泛型参数中的 Type 由编译器自动从实参类型填充
# 如 map(numbers, f)，T 从 numbers: List(Int) 提取，R 从 f: (Int) -> String 提取
```
