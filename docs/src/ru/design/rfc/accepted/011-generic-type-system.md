# RFC-011: Система обобщений — абстракции с нулевой стоимостью и замена макросов

## Резюме

Документ определяет **проект системы обобщений** языка YaoXiang, реализующий абстракции с нулевой
стоимостью через мощные возможности обобщений, использующий оптимизации времени компиляции для
снижения зависимости от макросов и обеспечивающий механизм устранения мёртвого кода.

**Ключевые проектные решения**:

- **Унифицированный синтаксис сигнатур**: `(T: Type, R: Type) -> ...` — параметры обобщений и
  обычные параметры унифицированы
- **Механизм самоописания Type**: `Type` — особая сущность языкового уровня; позиции `Type` в
  сигнатуре могут быть автоматически выведены и заполнены
- **Ограничения типов**: множественные ограничения `T: Dup + Add`, ограничения на типы функций
- **Ассоциированные типы**:
  `Iterator: (Item: Type) -> Type = { next: () -> Option(Item), has_next: () -> Bool }`
- **Обобщения времени компиляции**: `N: Int` — параметры-значения обобщений, инстанцирование
  константами времени компиляции
- **Условные типы**: `If: (C: Bool, T: Type, E: Type) -> Type` — вычисления на уровне типов,
  семейства типов

**Ценность**:

- Абстракции с нулевой стоимостью: мономорфизация на этапе компиляции, без накладных расходов во
  время выполнения
- Устранение мёртвого кода: анализ графа инстанцирования + оптимизации LLVM
- Замена макросов: обобщения заменяют 90% сценариев использования макросов
- Безопасность типов: проверка на этапе компиляции, дружелюбность к IDE
- **Явное лучше неявного**: `Type` самоописывающий, компилятор выполняет автоматический вывод

## Идея вселенной типов и типы, зависящие от значений

Система обобщений YaoXiang построена на **идее вселенной типов** — ментальной модели, которая
унифицирует все концепции языка в иерархическую структуру. Ключевая инновация заключается в
повышении **типов, зависящих от значений**, до полноправных сущностей уровня Type2.

### Что такое тип, зависящий от значений?

**Тип, зависящий от значений** — это тип, который зависит от одного или нескольких **значений** (а
не только от других типов). Эти значения могут быть вычислены на этапе компиляции, обеспечивая тем
самым гарантии безопасности типов ещё на стадии компиляции.

```yaoxiang
# Традиционные обобщения: параметры-типы
List: (T: Type) -> Type

# Типы, зависящие от значений: параметры-значения
Vec: (n: Int) -> Type  # Тип вектора зависит от значения длины n
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type  # Тип матрицы зависит от числа строк и столбцов
```

### Ключевые преимущества типов, зависящих от значений

По сравнению с традиционными обобщениями, типы YaoXiang, зависящие от значений, обладают следующими
ключевыми преимуществами:

| Свойство                         | Традиционные обобщения (C++/Rust)                     | Типы YaoXiang, зависящие от значений                                        |
| -------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------- |
| Значения, от которых зависит тип | Только параметры-типы                                 | Любые значения, включая результаты вызовов функций                          |
| Вычисление времени компиляции    | Ручная специализация шаблонов C++, отсутствует в Rust | Автоматическое вычисление времени компиляции с гарантией завершимости       |
| Вычисления на уровне типов       | Метапрограммирование шаблонов (сложно/опасно)         | Унифицированный движок вычислений на уровне типов                           |
| Безопасность типов               | В C++ отсутствует, в Rust ограничена                  | Полная безопасность типов, проверка на этапе компиляции                     |
| Проверка размерностей            | Проверка во время выполнения или ручная специализация | Проверка размерностей на этапе компиляции, без накладных расходов в runtime |

### Иерархия вселенных типов и типы, зависящие от значений

Идея вселенной типов разделяет концепции языка по семантической роли на разные уровни. Типы,
зависящие от значений, располагаются на **уровне Type2**:

| Уровень   | Роль                                                           | Примеры                                                                                              |
| --------- | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Type-1    | Значения                                                       | `42`, `factorial(5)`, сама функция                                                                   |
| Type0     | Ключевое слово метатипа                                        | `Type`                                                                                               |
| Type1     | Конкретные типы                                                | `Int`, `String`, `Vec(3)`                                                                            |
| **Type2** | **Функции / конструкторы типов / типы, зависящие от значений** | `add: (Int, Int) -> Int`, `Vec: (n: Int) -> Type`, `Matrix: (T: Type, Rows: Int, Cols: Int) -> Type` |

**Ключевое проектное решение**: функции, конструкторы типов и типы, зависящие от значений, на уровне
Type2 используют **унифицированный синтаксис** — все имеют форму `(params) -> result`:

- Обычная функция: `(Int, Int) -> Int` → результат — значение
- Конструктор типа: `(T: Type) -> Type` → результат — тип
- Тип, зависящий от значений: `(n: Int) -> Type` → результат — тип, но зависит от параметра-значения

> **Изоморфизм Карри-Ховарда**: это единство — не совпадение. Изоморфизм Карри-Ховарда утверждает,
> что «типы суть propositions, программы суть доказательства» — тип функции `A → B` соответствует
> логической импликации «если A, то B», обобщение `(T: Type) -> Type` соответствует квантору
> всеобщности «для всех типов T», тип, зависящий от значений `(n: Int) -> Type` соответствует «для
> каждого целого n существует тип». YaoXiang унифицирует функции, конструкторы типов и типы,
> зависящие от значений, на уровне Type2, что по существу объединяет «доказательство» и «вычисление»
> в одну концепцию — **конструктивное доказательство**. Это и есть прямое воплощение изоморфизма
> Карри-Ховарда в дизайне языка: одна форма (`(params) -> result`) одновременно несёт логическую
> propositions и процесс вычисления.

### Гарантия детерминированности времени компиляции

Идея вселенной типов YaoXiang требует: **всё на уровне Type детерминировано на этапе компиляции**.

```yaoxiang
# Пример проверки размерностей на этапе компиляции
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),
    # Проверка времени компиляции: размерности должны быть положительными
    _assert: Assert(Rows > 0),
    _assert: Assert(Cols > 0),
}

# Создание единичной матрицы 3x3 — выполняется на этапе компиляции
identity: (T: Add + Zero + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    # ...
}

# Вычисление времени компиляции: factorial(3) = 6, размер вектора известен на этапе компиляции
vec: Vec(factorial(3)) = Vec(6)()
```

Компилятор автоматически:

1. Обнаруживает вызовы функций в позициях типов
2. Выполняет проверку завершимости функции на этапе компиляции (см. механизм проверки завершимости
   ниже)
3. Производит вычисление на этапе компиляции
4. Встраивает результат в генерируемый тип

### Сценарии применения типов, зависящих от значений

#### Проверка размерностей на этапе компиляции

```yaoxiang
# Умножение матриц: проверка совпадения размерностей на этапе компиляции
multiply: (T: Add + Multiply + Zero,
           Rows: Int, Cols: Int, M: Int) -> ((
    a: Matrix(T, Rows, Cols),
    b: Matrix(T, Cols, M)
) -> Matrix(T, Rows, M)) = {
    # Проверка времени компиляции: a.Cols == b.Rows, иначе ошибка компиляции
    result = Matrix(T, Rows, M)()
    # ...
}

# Ошибка обнаруживается на этапе компиляции:
# multiply(matrix_2x3, matrix_4x2)  # Ошибка компиляции: 2 != 4
```

#### Типобезопасный размер массива

```yaoxiang
# Размер массива — константа времени компиляции
Array: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    length: N,
}

# N — константа времени компиляции, может использоваться в вычислениях на уровне типов
first_three: Array(Int, 3) = Array(Int, 3)(1, 2, 3)
# first_three.length == 3 (известно на этапе компиляции)
```

#### Условные типы

```yaoxiang
# If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Семейства типов
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,
}
```

#### Обобщённые функции

```yaoxiang
# map: обобщённая функция, параметры-типы T, R определяются на этапе компиляции
map: (T: Type, R: Type) -> (
    (list: List(T), f: (x: T) -> R) -> List(R)
) = (list, f) => {
    result = List(R)()
    for x in list {
        result.push(f(x))
    }
    return result
}

# При использовании всё прозрачно, типы выводятся автоматически
numbers = List(Int)()   # Примечание: двухслойная форма конструктора значения (см. §9.1); элементы добавляются через push
numbers.push(1)
numbers.push(2)
numbers.push(3)
doubled = map(numbers, (x) => x * 2)  # Выводится как map[Int, Int]
```

### Механизм проверки завершимости (унифицирован с RFC-027)

Вычисление времени компиляции для типов, зависящих от значений, должно быть **гарантированно
завершающимся**, иначе система типов попадёт в бесконечный цикл. Проверка завершимости выполняется
**полностью автоматически** конвейером доказательств времени компиляции из RFC-027 — компилятор
автоматически синтезирует метрики; рекурсии/циклы, которые удаётся доказать, проходят, остальные —
приводят к ошибке компиляции. **Полуавтоматические аннотации не допускаются**: `//! decreases` и
`/*! invariant !*/` из RFC-022 отменены вместе с RFC-022; спецификации — это сами аннотации типов.

#### Проверка завершимости рекурсивных функций

Перед вычислением времени компиляции компилятор проверяет, что аргументы рекурсивных вызовов строго
убывают на каждой ветви рекурсии (RFC-027 §6.7). Никаких аннотаций спецификаций не требуется:

```yaoxiang
# Факториал времени компиляции: без //! requires/ensures/decreases, компилятор анализирует автоматически
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)  # Анализ компилятора: n-1 < n → убывает → завершается
}

# Использование: в позиции типа вызов сначала верифицируется на завершимость, затем вычисляется
vec: Vec(factorial(5)) = Vec(120)()  # Вычисление времени компиляции: factorial(5) = 120
```

| Сценарий                                                              | Поведение                          |
| --------------------------------------------------------------------- | ---------------------------------- |
| Компилятор может проанализировать убывание рекурсии (например, `n-1`) | Вычисление времени компиляции      |
| Не убывает / не удаётся установить убывание                           | Ошибка компиляции                  |
| Вызов во время выполнения (не в позиции типа)                         | Проверка завершимости не требуется |

#### Проверка завершимости циклов

Для циклов не нужны аннотации `: Invariant(...)` или `: decreases(...)`. Аннотации типов уточнения
на переменных (например, `UpTo(n)`) одновременно задают инвариант цикла и границу метрики.
Компилятор перебирает четыре стратегии синтеза метрик в порядке приоритета и останавливается на
первой успешной (RFC-027 §7):

1. **Автоматический синтез линейной ранговой функции** — извлечение границ переменных из аннотаций
   типов, перебор линейных комбинаций, верификация SMT: m ≥ 0 и m' < m на всех путях
2. **Подсчёт нарушений предиката** (экспериментально) — извлечение violation_count из определения
   целевого типа (например, `Sorted`), покрытие соседних обменов/перемещений
3. **Паттерны ограниченного возрастания/убывания** — `v += const` → метрика `upper - v` (вырождение
   стратегии 1, самый быстрый путь)
4. **Шаблон метрики с мультипликативным масштабированием** — `v *= const` (const > 1) → метрика
   `ceil(log_const(upper / v))`

```yaoxiang
sum: (arr: Array(Int, n)) -> Int = {
    mut i: UpTo(arr.len) = 0   # Аннотация типа даёт верхнюю границу arr.len и нижнюю 0
    while i < arr.len {
        # Компилятор автоматически выводит: метрика arr.len - i, на каждой итерации строго убывает на 1 → завершимость доказана
        s += arr[i]; i += 1
    }
    return s
}
```

```

└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  1. Проверка завершимости (конвейер доказательств RFC-027, полностью автоматический) │

│     - Циклы: четыре стратегии синтеза метрик (линейная ранговая / подсчёт нарушений / │

└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  2. Вычисление времени компиляции (выполняется встроенным интерпретатором) │

│     - Побочные эффекты: ошибка компиляции (в позиции типа побочных эффектов быть не должно) │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  3. Встраивание результата в тип                             │
│     - Vec(factorial(5)) → Vec(120)                            │
│     - Matrix(Float, 3, 3) → конкретный тип                    │
└─────────────────────────────────────────────────────────────┘
```

#### Преимущества

- **Безопасность**: гарантия обязательной завершимости вычислений времени компиляции, предотвращение
  бесконечных циклов в системе типов
- **Единообразие**: проверка завершимости и верификация корректности (генерация VC) используют один
  и тот же конвейер доказательств времени компиляции (RFC-027), без отдельного синтаксиса
  спецификаций
- **Полная автоматизация**: компилятор автоматически синтезирует метрики из аннотаций типов; что
  можно доказать — проходит, что нельзя — приводит к ошибке; не зависит от ручного `decreases` от
  программиста

## Мотивация

### Зачем нужна мощная система обобщений?

Существующие мейнстримные языки имеют ограничения в обобщениях:

| Язык         | Возможности обобщений           | Проблема                                                                                             |
| ------------ | ------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Java         | Граничные типы                  | Мономорфизация на этапе компиляции, без специализации                                                |
| C#           | Ограничения обобщений           | Проверка типов во время выполнения, потеря производительности                                        |
| Rust         | Обобщения + Trait               | Сложная система Trait, крутая кривая обучения                                                        |
| C++          | Шаблоны                         | Сложная специализация шаблонов, плохие сообщения об ошибках                                          |
| **YaoXiang** | **Типы, зависящие от значений** | **Тип может зависеть от значений, проверка размерностей на этапе компиляции, гарантия завершимости** |

### Ключевые противоречия

1. **Производительность vs гибкость**: гибкость во время выполнения vs оптимизации на этапе
   компиляции
2. **Сложность vs простота**: мощная система типов vs удобство использования
3. **Макросы vs обобщения**: кодогенерация макросами vs типобезопасность обобщений
4. **Зависимость от значений vs безопасность типов**: традиционные обобщения не позволяют проверять
   размерности на этапе компиляции

### Ключевые преимущества типов, зависящих от значений

**Типы, зависящие от значений** YaoXiang — ключевое преимущество по сравнению с традиционными
обобщениями:

| Преимущество                      | Описание                                                                                                      |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Тип зависит от значений**       | `Vec: (n: Int) -> Type` позволяет типу зависеть от конкретного значения                                       |
| **Вычисление времени компиляции** | Вызовы функций в позициях типов вычисляются на этапе компиляции, результат непосредственно встраивается в тип |
| **Проверка размерностей**         | `Matrix(Float, 3, 3)` проверяет размерности матрицы на этапе компиляции                                       |
| **Вычисления на уровне типов**    | Условные типы `If`, `Match` поддерживают вычисления на уровне типов                                           |
| **Гарантия завершимости**         | Проверка завершимости на этапе компиляции (автоматический синтез метрик) гарантирует завершимость вычислений  |

```yaoxiang
# Проверка, невозможная в C++/Rust
matrix: Matrix(Float, factorial(3), factorial(2)) = ...
# Вычисление времени компиляции: factorial(3) = 6, factorial(2) = 2
# Тип: Matrix(Float, 6, 2)

# Несовпадение размерностей обнаруживается на этапе компиляции
identity: Matrix(Float, 3, 3) = ...
# multiply(matrix_2x3, identity_3x3)  # Ошибка компиляции: 2 != 3
```

### Ценность системы обобщений

```yaoxiang
# Пример: унифицированный дизайн API
# Операция map для разных типов контейнеров

# Традиционный подход: отдельная реализация для каждого типа
map_int_array: (array: Array(Int), f: Fn(Int) -> Int) -> Array(Int) = ...
map_string_array: (array: Array(String), f: Fn(String) -> String) -> Array(String) = ...
map_int_list: (list: List(Int), f: Fn(Int) -> Int) -> List(Int) = ...
map_string_list: (list: List(String), f: Fn(String) -> String) -> List(String) = ...

# Подход с обобщениями: одна обобщённая функция покрывает все типы
map: (T: Type, R: Type)(container: Container(T), f: Fn(T) -> R) -> Container(R) = {
    for item in container {
        result.push(f(item))
    }
    result
}
```

## Цели проектирования

### Основные цели

1. **Абстракции с нулевой стоимостью** — вызов обобщений эквивалентен вызову конкретного типа
2. **Устранение мёртвого кода** — анализ на этапе компиляции, инстанцирование только используемых
   обобщений
3. **Замена макросов** — обобщения заменяют 90% сценариев использования макросов
4. **Безопасность типов** — проверка на этапе компиляции, без накладных расходов на типы во время
   выполнения
5. **Дружелюбность к IDE** — интеллектуальные подсказки, понятные сообщения об ошибках
6. **Типы, зависящие от значений** — типы могут зависеть от значений, поддержка проверки
   размерностей на этапе компиляции
7. **Безопасность вычислений времени компиляции** — гарантия завершимости вычислений посредством
   автоматического синтеза метрик (RFC-027)

### Принципы проектирования

- **Детерминированность на этапе компиляции**: параметры обобщений определяются на этапе компиляции
- **Приоритет мономорфизации**: генерация конкретного кода, избежание вызовов виртуальных функций
- **Управление через ограничения**: ограничения типов направляют инстанцирование
- **Платформенные оптимизации**: специализация для платформенно-специфичных оптимизаций
- **Единая вселенная типов**: функции, конструкторы типов и типы, зависящие от значений,
  унифицированы на уровне Type2
- **Гарантия завершимости**: вызовы функций в позициях типов должны быть доказуемо завершающимися

## Предложение

### 1. Базовые обобщения

#### 1.1 Параметры-типы обобщений

> **Ключевое правило**: определение обобщённого типа **должно явно содержать аннотацию `: Type`**,
> иначе HM-вывод определит его как функцию.
>
> | Запись                            | Значение                            |
> | --------------------------------- | ----------------------------------- |
> | `List: (T: Type) -> Type = {...}` | ✅ Конструктор типа                 |
> | `List = {...}`                    | ❌ HM выводит как функцию, а не тип |

```yaoxiang
# Определение обобщённого типа (обязательно наличие : Type)
Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self
}

Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self
}

List: (T: Type) -> Type = {
    data: Array(T),
    length: Int,
    push: (self: List(T), item: T) -> Void,   # self — лишь имя по соглашению, не ключевое слово
    get: (self: List(T), index: Int) -> Option(T),
}

# Обобщённая функция (без : Type, HM выводит как функцию)
map: (T: Type, R: Type) -> ((opt: Option(T), f: Fn(T) -> R) -> Option(R)) = {
    return match opt {
        some => Option.some(f(some)),
        none => Option.none(),
    }
}

# Ограничение обобщения (прямое выражение, для однострочных форм return можно опустить)
clone: (T: Clone)(value: T) -> T = value.clone()

# Несколько параметров-типов
combine: (T: Type, U: Type) -> ((a: T, b: U) -> (T, U)) = (a, b)
```

#### 2.4 Встроенные маркерные trait: Dup и Clone

**Три категории семантики копирования**:

| Тип                                  | Значение                                                                                | Способ срабатывания                     | Сценарий применения                |
| ------------------------------------ | --------------------------------------------------------------------------------------- | --------------------------------------- | ---------------------------------- |
| **Копирование примитивных значений** | При присваивании автоматическое копирование значения, два значения полностью независимы | Автоматически при присваивании/передаче | Int, Float, Bool, Char             |
| **Dup**                              | Поверхностное копирование: копируется дескриптор/токен, нижележащие данные разделяются  | Автоматически при присваивании/передаче | токены `&T`, `ref T`, String/Bytes |
| **Clone**                            | Глубокое копирование: создание полной независимой копии                                 | Вызов `value.clone()`                   | Любой тип, реализующий Clone       |

**Семантика Dup**: для типов, реализующих Dup, при присваивании/передаче владение не передаётся —
компилятор копирует дескриптор/токен, и несколько владельцев указывают на одни и те же нижележащие
данные. Это дополняет семантику Move по умолчанию из модели владения RFC-009.

**Dup и Clone — ортогональные концепции**:

```
Dup  = копируется дескриптор, данные разделяются (изменения влияют друг на друга)
Clone = копируются данные, копия независима (изменения не влияют друг на друга)
```

**Правила**:

```
1. Примитивные типы значений (Int, Float, Bool, Char) — встроенное копирование значений компилятором, не относятся к Dup
2. Dup — применимо только к ссылочным/токенным типам и типам с внутренним подсчётом ссылок
3. Clone — явное глубокое копирование, любой тип может его реализовать
4. Move по умолчанию — остальные типы сохраняют семантику Move по умолчанию
```

**Какие типы являются Dup**:

| Тип                                        | Dup         | Причина                                                                           |
| ------------------------------------------ | ----------- | --------------------------------------------------------------------------------- |
| `&T` (токен заимствования)                 | ✅          | Токен нулевого размера, копирование токена = несколько представлений одних данных |
| `ref T`                                    | ✅          | Копирование Rc/Arc = подсчёт ссылок +1, разделяемые данные в куче                 |
| String, Bytes                              | ✅          | Внутренний подсчёт ссылок, копирование дескриптора разделяет буфер                |
| `&mut T` (токен изменяемого заимствования) | ❌          | Линейная эксклюзивность, копирование запрещено                                    |
| struct                                     | Производный | Все поля Dup → struct Dup                                                         |
| enum                                       | Производный | Все поля всех вариантов Dup → enum Dup                                            |
| tuple                                      | Производный | Все элементы Dup → tuple Dup                                                      |
| Fn (замыкание)                             | ❌          | Захватываемое окружение может не быть Dup                                         |
| `*T` (сырой указатель)                     | ❌          | unsafe, не участвует в системе владения                                           |

**Int/Float/Bool/Char не являются Dup** — это типы значений; при присваивании компилятор
автоматически выполняет копирование значения (оба значения полностью независимы). Это не
«поверхностное копирование», а встроенная обработка примитивов компилятором, которая не нуждается и
не должна выражаться через атрибут Dup.

```yaoxiang
# Примитивные типы значений: компилятор автоматически копирует значение (не Dup)
x: Int = 42
y = x          # Копирование значения, x и y полностью независимы
print(x)       # ✅

# Dup: поверхностное копирование, копируется дескриптор, данные разделяются
view: &Point = &point
view2 = view    # ✅ Dup: копируется токен, оба указывают на один и тот же point
print(view.x)   # ✅

# Clone: явное глубокое копирование, создаётся независимая копия
backup = big_struct.clone()  # Явный вызов

# Ограничения обобщений
dup_use: (T: Dup) -> T = x         # T: Dup → можно поверхностно копировать
clone_use: (T: Clone) -> T = x.clone()  # T: Clone → можно глубоко копировать
```

> **Примечание**: `Send`/`Sync` не предоставляются как видимые пользователю trait. Гарантии
> безопасности между задачами обеспечиваются полностью автоматически ключевым словом `ref` и
> компилятором — `ref` автоматически выбирает Rc или Arc, и пользователю не нужно понимать
> Send/Sync.

#### 3.1 Определение ассоциированных типов

```yaoxiang
# Trait Iterator (используется синтаксис (Item: Type) -> Type)
Iterator: (Item: Type) -> Type = {
    next: (Self) -> Option(Item),
    has_next: (Self) -> Bool,
    collect: (T: Type)(Self) -> List(T),
}

# Использование
collect_all: (T: Type, I: Iterator(T))(iter: I) -> List(T) = {
    result: List(T) = List(T)
    while iter.has_next() {
        if let Some(item) = iter.next() {
            result.push(item)
        }
    }
    return result
}

# Реализация Iterator для Array
# Используется синтаксический сахар: Array.Item, Array.next, Array.has_next
Array.has_next: (T: Type)(self: Array(T)) -> Bool = {
    return self.index < self.length
}

Array.next: (T: Type)(self: Array(T)) -> Option(T) = {
    if has_next(self) {
        item = self.data[self.index]
        self.index = self.index + 1
        return Option.some(item)
    } else {
        return Option.none()
    }
}

Array.Item: (T: Type)(arr: Array(T)) -> T = {
    return arr.data[0]
}
```

### 4. Обобщения времени компиляции

#### 4.1 Параметры-значения времени компиляции

> **Поправка (#296)**: исходный текст гласил «`Int` и другие параметры-значения по умолчанию
> определяются на этапе компиляции в контексте обобщений», что **строго неверно** — в
> `add: (a: Int, b: Int) -> Int = a + b` параметры `a`/`b` являются параметрами-значениями времени
> выполнения. Только **конкретные параметры-типы, на которые ссылаются в позициях типов**, являются
> параметрами-значениями времени компиляции. Корректное определение см. ниже.

**Ключевое проектное решение**: в сигнатуре обобщения метка `Type` обозначает параметр-тип;
параметры с аннотацией конкретного типа (`Int`/`Bool`/`Float` и т.д.) считаются **кандидатами в
параметры-значения времени компиляции**; станет ли параметр таковым, зависит от того, используется
ли его значение **в позиции типа** (зависимость от значения). Ключевое слово `const` не требуется.

**Правило определения (два шага)**:

1. **Грубая фильтрация по форме**: параметр аннотирован конкретным типом, отличным от `Type`
   (например, `Int`) → считается кандидатом.
2. **Тонкая фильтрация по использованию**: имя кандидата встречается в **позиции типа** (тип поля
   тела типа, тип параметра внутренней `Fn`, предикат `Assert`, аргумент конструктора типа вроде
   `Array(T, N)` и т.п.) → подтверждается как параметр-значение времени компиляции; иначе считается
   **параметром-значением времени выполнения**.

| Запись                                                     | Определение                                 | Причина                                                                       |
| ---------------------------------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------- |
| `add: (a: Int, b: Int) -> Int = a + b`                     | a/b — параметры-значения времени выполнения | Встречаются только в позициях значений, не участвуют в конструировании типов  |
| `Array: (T: Type, N: Int) -> Type = { data: Array(T, N) }` | N — параметр-значение времени компиляции    | N встречается в позиции аргумента конструктора типа `Array(T, N)`             |
| `factorial: (N: Int) -> (k: N) -> Int`                     | N — параметр-значение времени компиляции    | N выступает типом внутреннего параметра `k`                                   |
| `Foo: (T: Type, N: Int) -> Type = { x: T }`                | N — пропадает (см. ниже)                    | N не упомянут в теле типа, вырождается в параметр-значение времени выполнения |

> **Суть зависимости от значений**: параметр-значение времени компиляции — это и есть тип, зависящий
> от значений; только когда значение используется для **конструирования типа**, требуется его
> определённость на этапе компиляции. Форма (`: Int`) определяет лишь право быть кандидатом,
> использование (появление в позиции типа) — то, является ли он параметром-значением времени
> компиляции. Это тот же критерий, что и в разделе «Гарантия детерминированности времени компиляции»
> о том, что «вызовы функций в позициях типов вычисляются на этапе компиляции».

```yaoxiang
# ════════════════════════════════════════════════════════
# Параметр-значение времени компиляции: N упомянут в позиции типа (слот длины Array)
# ════════════════════════════════════════════════════════
StaticArray: (T: Type, N: Int) -> Type = {
    data: Array(T, N),  # N встречается в позиции аргумента конструктора типа → параметр-значение времени компиляции
    length: N,
}

# Использование: factorial(5) вычисляется в позиции типа (время компиляции), результат 120 встраивается в тип
arr: StaticArray(Int, factorial(5))  # StaticArray(Int, 120)

# ════════════════════════════════════════════════════════
# Зависимость от значения: N выступает типом внутреннего параметра k
# ════════════════════════════════════════════════════════
# N — параметр-значение времени компиляции (встречается в позиции типа (k: N));
# k — параметр-значение времени выполнения, его тип — литеральный тип N (однозначный тип).
factorial: (N: Int) -> (k: N) -> Int = {
    return match k {
        0 => 1,
        _ => k * factorial(k - 1)
    }
}
```

> **Обработка пропавших кандидатов**: кандидаты, аннотированные конкретным типом, но не упомянутые в
> позициях типов (например, `N` в `Foo` из таблицы выше), вырождаются в параметры-значения времени
> выполнения. Путь на уровне функций обрабатывает это корректно; на пути конструктора типа пропавшие
> кандидаты в текущей реализации молча отбрасываются, что приводит к несогласованным сообщениям об
> ошибках инстанцирования — см. issue [#297](https://github.com/ChenXu233/YaoXiang/issues/297).

### Never и Void: ⊥ и ⊤ в системе типов

Система типов YaoXiang в изоморфизме Карри-Ховарда одновременно обладает ⊥ (ложь/пустой тип) и ⊤
(истина/Unit), воплощёнными во встроенных именах типов `Never` и `Void`:

**Never (⊥)** — три не подлежащих обсуждению свойства ядра:

1. **Нулевое число конструкторов**: ни один литерал или выражение не может породить значение типа
   `Never`. Это мета-свойство, оно должно быть встроенным.
2. **Принцип взрыва**: `Never <: T` для любого типа `T`. Значение типа `Never` может использоваться
   как значение любого типа — именно поэтому код после `assert(false)` проходит проверку типов (хотя
   он никогда не будет выполнен).
3. **Маркер расходимости**: `f: (...) -> Never` означает, что `f` гарантированно не возвращается.
   Компилятор использует это для анализа мёртвого кода.

`Never` — встроенное имя типа, не ключевое слово, парсеру безразлично. Синтаксис пустого объединения
и литералов типа не открывается.

**Void (⊤, т.е. Unit)** — ровно один резидент (значение void по умолчанию), носитель истинной
propositions «всегда истинно». `Void` — единичный элемент произведения типов с нулём полей, `Never`
— единичный элемент суммы вариантов с нулём вариантов; они двойственны. `x: Void = <по умолчанию>`
корректно, `x: Never = ...` — справа писать нечего.

#### 4.3 Проверки на этапе компиляции (реализация в стандартной библиотеке)

```yaoxiang
# ════════════════════════════════════════════════════════
# Реализация стандартной библиотеки: использование условных типов
# ════════════════════════════════════════════════════════

# Определения стандартной библиотеки
# IsTrue: мост от вселенной значений ко вселенной типов — отображение истинного значения Bool в тип
IsTrue: (b: Bool) -> Type = match b {
    true => Void,      # ⊤, имеет значение, программа продолжается
    false => Never,    # ⊥, значения нет, расходимость
}

# Assert: примитив уточнения типа на этапе компиляции — типовое выражение propositions над Bool
Assert: (cond: Bool) -> Type = IsTrue(cond)
#
# cond == true  → Assert(true)  = Void    (всегда истинно, стирается)
# cond == false → Assert(false) = Never   (всегда ложно, ошибка компиляции / расходимость)
# cond не определимо → конвейер доказательств решает по режиму dispatch:
#                      CompileTime → Unknown, требуется prove
#                      Runtime     → вставка check, инъекция предположения в Γ

# Способ использования 1: как ограничение в определении типа
Array: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    # Проверка времени компиляции: N должно быть больше 0 (Assert в позиции типа)
    length: Assert(N > 0),
}

# Способ использования 2: использование в выражении
IntArray: (N: Int) -> Type = StaticArray(Int, N)
# Проверка: размер IntArray(10) равен sizeof(Int) * 10
Assert(size_of(IntArray(10)) == sizeof(Int) * 10)
```

### 5. Условные типы

> **Изоморфизм Карри-Ховарда**: условные типы с точки зрения Карри-Ховарда — это **case-анализ** в
> логике. Тип `Bool` соответствует propositions с двумя возможными значениями (True/False), а `If`
> выбирает разные результаты в зависимости от истинности этой propositions — это в точности
> case-анализ дизъюнкции в логике. Выражение `match C { True => T, False => E }` фактически
> выражает: «дано, что propositions C истинна, заключение — T; дано, что ложна, заключение — E».

#### 5.1 Условный тип If

```yaoxiang
# If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Пример: ветвление на этапе компиляции
NonEmpty: (T: Type) -> Type = If(T != Void, T, Never)

Optional: (T: Type) -> Type = If(T != Void, T, Void)

# Проверка времени компиляции (унифицирована с определением Assert из §4.3)
# Assert: (cond: Bool) -> Type = IsTrue(cond)

# Использование
# Вычисление типа: If(True, Int, String) => Int
# Вычисление типа: If(False, Int, String) => String
```

#### 5.2 Семейства типов

> **Изоморфизм Карри-Ховарда**: семейства типов — самое прямое воплощение «propositions как типов».
> `Add: (A: Type, B: Type) -> Type` — это не «функция сложения, записанная на уровне типов», а
> **конструирование propositions о сложении натуральных чисел**. `(Zero, B) => B` означает
> «propositions Add(Zero, B) эквивалентна B», `(Succ(A'), B) => Succ(Add(A', B))` — «если Add(A', B)
> верно, то верно и Add(Succ(A'), B)». Это и есть определение сложения в аксиомах Пеано. Проверка
> типов, подтверждающая прохождение этого match-выражения, эквивалентна проверке логической
> непротиворечивости этого определения.

```yaoxiang
# Преобразование типов на этапе компиляции
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,  # По умолчанию
}

# Вычисления на уровне типов
Length: (T: Type) -> Type = match T.length {
    0 => Zero,
    1 => Succ(Zero),
    2 => Succ(Succ(Zero)),
    _ => TooLong,
}

# Сложение на уровне типов (Карри-Ховард: case-анализ + рекурсивный вызов, требует проверки завершимости для полноты индукции)
Add: (A: Type, B: Type) -> Type = match (A, B) {
    (Zero, B) => B,
    (Succ(A'), B) => Succ(Add(A', B)),
}

# Пример: вычисление 2 + 3 на этапе компиляции
Two: Type = Succ(Succ(Zero))
Three: Type = Succ(Succ(Succ(Zero)))
Five: Type = Add[Two, Three]  # Succ(Succ(Succ(Succ(Succ(Zero)))))
```

#### 6.3 Идеальное сочетание перегрузки функций и инлайнинга

**Ключевое свойство**: перегрузка функций естественным образом сочетается с оптимизацией инлайнинга,
обеспечивая абстракции с нулевой стоимостью.

```yaoxiang
# ======== Исходный код ========
sum: (arr: Array(Int)) -> Int = {
    return native_sum_int(arr.data, arr.length)
}

sum: (arr: Array(Float)) -> Float = {
    return simd_sum_float(arr.data, arr.length)
}

sum: (T: Type) -> ((arr: Array(T)) -> T) = {
    result = Zero::zero()
    for item in arr {
        result = result + item
    }
    return result
}

# Использование
int_arr = Array(Int)(1, 2, 3, 4, 5)
result = sum(int_arr)

# ======== После компиляции (эквивалентный код) ========
# Компилятор автоматически выбирает оптимальную специализацию, затем инлайнит
result = native_sum_int(int_arr.data, int_arr.length)

# Полностью эквивалентно вручную написанному оптимизированному коду, без накладных расходов на вызов функции!
```

**Ключевые преимущества**:

1. **Интеллектуальный выбор компилятора**

   ```yaoxiang
   sum(int_arr)      # Автоматически выбирает sum: (Array(Int)) -> Int
   sum(float_arr)    # Автоматически выбирает sum: (Array(Float)) -> Float
   sum(custom_arr)   # Автоматически выбирает sum: (T: Type) -> ((arr: Array(T)) -> T)
   ```

2. **Оптимизация инлайнинга**
   - Маленькие функции автоматически инлайнятся в точку вызова
   - Нулевые накладные расходы на вызов функции
   - Полная эквивалентность вручную написанному оптимизированному коду

3. **Безопасность типов**
   - Проверка типов на этапе компиляции
   - Нулевые накладные расходы во время выполнения
   - Не требуется таблица виртуальных функций

4. **Идеально согласуется с RFC-010**

   ```yaoxiang
   # Полностью используется унифицированный синтаксис
   name: type = value
   # Не нужны новые ключевые слова: impl, where и т.п.
   ```

**Практические примеры применения**:

```yaoxiang
# Чувствительные к производительности численные вычисления
fibonacci: (n: Int) -> Int = {
    if n <= 1 { return n }
    return fibonacci(n - 1) + fibonacci(n - 2)
}

fibonacci: (n: Float) -> Float = {
    # Используется формула Бине
    phi = (1.0 + 5.0.sqrt()) / 2.0
    return (phi.pow(n) - (-phi).pow(-n)) / 5.0.sqrt()
}

# Компилятор автоматически выбирает и инлайнит
fibonacci(10)      # Выбирается версия для Int, полностью инлайнится
fibonacci(10.5)    # Выбирается версия для Float, используется формула Бине
```

**Что это означает?**

- ✅ **Специализация обобщений** → естественно решается перегрузкой функций
- ✅ **Оптимизация производительности** → инлайнинг выполняется автоматически
- ✅ **Повторное использование кода** → одно имя функции, несколько реализаций
- ✅ **Абстракции с нулевой стоимостью** → полиморфизм на этапе компиляции, нулевые накладные
  расходы во время выполнения
- ✅ **Новые ключевые слова не нужны** → идеально соответствует унифицированному синтаксису RFC-010

````

### 7. Механизм устранения мёртвого кода

#### 7.1 Анализ графа инстанцирования

```rust
// Внутри компилятора: построение графа зависимостей инстанцирования обобщений
struct InstantiationGraph {
    // Узлы: инстанцирования обобщений
    nodes: HashMap<InstanceKey, InstanceNode>,

    // Рёбра: отношения использования
    edges: HashMap<InstanceKey, Vec<InstanceKey>>,
}

struct InstanceKey {
    generic: FunctionId,  // ID обобщённой функции
    type_args: Vec<TypeId>,  // Аргументы-типы
    const_args: Vec<ConstId>,  // Аргументы-константы
}

// Алгоритм: анализ достижимости
fn eliminate_dead_instantiations(graph: &InstantiationGraph) {
    let mut reachable = HashSet::new();

    // Начинаем с точек входа (main, экспортируемые функции и т.п.)
    let entry_points = find_entry_points();
    for entry in entry_points {
        dfs_visit(entry, &graph, &mut reachable);
    }

    // Не посещённые инстанцирования — мёртвый код
    for node in &graph.nodes {
        if !reachable.contains(node.key) {
            eliminate(node);
        }
    }
}
````

### 9. Примеры

#### 9.1 Полный пример обобщённого контейнера

```yaoxiang
# ======== 1. Определение обобщённого контейнера ========
# Используется синтаксис (T: Type) -> Type
Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self,
}

Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self,
}

List: (T: Type) -> Type = {
    data: Array(T),
    length: Int,

    # Обобщённые методы (T автоматически попадает в область видимости из внешнего List(T))
    push: (self: List(T), item: T) -> Void,
    pop: (self: List(T)) -> Option(T),
    map: (R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)),
    filter: (self: List(T), predicate: (T) -> Bool) -> List(T),
    fold: (U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U),
}

# ======== 2. Реализация обобщённых методов ========
# Определение функций в пространстве имён List (префикс List. = принадлежность пространству имён)
# Чтобы синтаксис вызова через . (list.push(item)) работал, нужно явное связывание: List.push = push[0]
# self — лишь имя параметра по соглашению, компилятор смотрит на тип, а не на имя

List.push: (T: Type) -> ((self: List(T), item: T) -> Void) = {
    if self.length >= self.data.length {
        # Расширение
        new_data = Array(T)(self.data.length * 2)
        for i in 0..self.length {
            new_data[i] = self.data[i]
        }
        self.data = new_data
    }
    self.data[self.length] = item
    self.length = self.length + 1
}

List.pop: (T: Type) -> ((self: List(T)) -> Option(T)) = {
    if self.length > 0 {
        self.length = self.length - 1
        return Option.some(self.data[self.length])
    } else {
        return Option.none()
    }
}

List.map: (T: Type, R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)) = {
    result = List(R)()
    for i in 0..self.length {
        result.push(f(self.data[i]))
    }
    return result
}

List.filter: (T: Type) -> ((self: List(T), predicate: (T) -> Bool) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        if predicate(self.data[i]) {
            result.push(self.data[i])
        }
    }
    return result
}

List.fold: (T: Type, U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U) = {
    result = initial
    for i in 0..self.length {
        result = f(result, self.data[i])
    }
    return result
}

# ======== 3. Использование ограничений типов ========
# Реализация Clone for List
List.clone: (T: Clone) -> ((self: List(T)) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        result.push(self.data[i].clone())
    }
    return result
}

# ======== 4. Примеры использования ========
# Создание обобщённого List
numbers = List(Int)()
numbers.push(1)
numbers.push(2)
numbers.push(3)

# Использование обобщённых методов
doubled = numbers.map((x) => x * 2)
evens = numbers.filter((x) => x % 2 == 0)

# Использование fold для вычисления
sum = numbers.fold(0, (acc, x) => acc + x)  # sum = 6

# Композиция обобщений
sum_of_evens = numbers
    .filter((x) => x % 2 == 0)
    .map((x) => x * 2)
    .fold(0, (acc, x) => acc + x)  # sum_of_evens = 8
```

#### 9.2 Пример обобщённого алгоритма

```yaoxiang
# ======== 1. Обобщённый алгоритм сортировки ========
Comparator: (T: Type) -> Type = {
    compare: (T, T) -> Int,  # -1 if a < b, 0 if a == b, 1 if a > b
}

# Обобщённая быстрая сортировка
quicksort: (T: Clone) -> ((array: Array(T), cmp: Comparator(T)) -> Array(T)) = {
    if array.length <= 1 {
        return array.clone()
    }

    pivot = array[array.length / 2]
    left = Array(T)()
    right = Array(T)()

    for i in 0..array.length {
        if i == array.length / 2 {
            continue
        }
        item = array[i]
        comparison = cmp.compare(item, pivot)
        if comparison < 0 {
            left.push(item)
        } else {
            right.push(item)
        }
    }

    sorted_left = quicksort(left, cmp)
    sorted_right = quicksort(right, cmp)

    result = sorted_left.clone()
    result.push(pivot)
    result.extend(sorted_right)
    return result
}

# ======== 2. Реализация IntComparator ========
# Реализация через перегрузку функций
compare: (a: Int, b: Int) -> Int = {
    if a < b {
        return -1
    } else if a > b {
        return 1
    } else {
        return 0
    }
}

# ======== 3. Примеры использования ========
# Сортировка массива Int
numbers = Array(Int)(3, 1, 4, 1, 5, 9, 2, 6)
sorted = quicksort(numbers, Comparator(Int)())

# Сортировка массива String (требуется StringComparator)
strings = Array(String)("hello", "world", "foo", "bar")
sorted_strings = quicksort(strings, Comparator(String)())
```

```yaoxiang
# ======== 1. Тип матрицы времени компиляции ========
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),

    # Проверка размерностей на этапе компиляции: используется тип Assert из стандартной библиотеки
    _assert: Assert(Rows > 0),  # Rows > 0, иначе ошибка компиляции
    _assert: Assert(Cols > 0),  # Cols > 0, иначе ошибка компиляции

    # Операции над матрицами
    multiply: (M: Int) -> ((self: Matrix(T, Rows, Cols), other: Matrix(T, Cols, M)) -> Matrix(T, Rows, M)) = {
        result = Matrix(T, Rows, M)()
        for i in 0..Rows {
            for j in 0..M {
                sum = Zero::zero()
                for k in 0..Cols {
                    sum = sum + self.data[i][k] * other.data[k][j]
                }
                result.data[i][j] = sum
            }
        }
        return result
    }
}

# ======== 2. Создание матриц на этапе компиляции ========
identity: (T: Add + Multiply + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    for i in 0..N {
        for j in 0..N {
            if i == j {
                matrix.data[i][j] = One::one()
            } else {
                matrix.data[i][j] = Zero::zero()
            }
        }
    }
    return matrix
}

# ======== 3. Примеры использования ========
# Создание матриц с размером, известным на этапе компиляции
# Матрица 2x3
matrix_2x3 = Matrix(Float, 2, 3)()
matrix_2x3.data[0][0] = 1.0
matrix_2x3.data[0][1] = 2.0
matrix_2x3.data[0][2] = 3.0
matrix_2x3.data[1][0] = 4.0
matrix_2x3.data[1][1] = 5.0
matrix_2x3.data[1][2] = 6.0

# Матрица 3x2
matrix_3x2 = Matrix(Float, 3, 2)()
matrix_3x2.data[0][0] = 7.0
matrix_3x2.data[0][1] = 8.0
matrix_3x2.data[1][0] = 9.0
matrix_3x2.data[1][1] = 10.0
matrix_3x2.data[2][0] = 11.0
matrix_3x2.data[2][1] = 12.0

# Умножение матриц: 2x3 * 3x2 = 2x2
result = matrix_2x3.multiply(matrix_3x2)

# Проверка на этапе компиляции: тип result — Matrix(Float, 2, 2)
# Единичная матрица 2x2
identity_3x3 = identity(Float, 3)()

# Несовпадение размерностей: ошибка компиляции
```

## Компромиссы

### Преимущества

1. **Абстракции с нулевой стоимостью**
   - Мономорфизация на этапе компиляции, без накладных расходов во время выполнения
   - Не нужны виртуальные функции, не нужен RTTI

2. **Устранение мёртвого кода**
   - Анализ на этапе компиляции, инстанцирование только используемых обобщений
   - Контролируемое разрастание кода

3. **Замена макросов**
   - Типобезопасная кодогенерация
   - Дружелюбность к IDE, понятные сообщения об ошибках

4. **Вычисления на этапе компиляции**
   - Обобщения времени компиляции поддерживают вычисления времени компиляции
   - Возможности вроде проверки размерностей
   - Ключевое слово `const` не требуется, чистые ограничения типов

### Недостатки

1. **Время компиляции**
   - Инстанцирование обобщений увеличивает время компиляции
   - Решение ограничений может быть медленным

2. **Потребление памяти**
   - Возрастает потребление памяти компилятором
   - Механизмам кэширования нужна память

3. **Сложность реализации**
   - Решатель ограничений сложен
   - Сложен движок вычислений на уровне типов

4. **Диагностика ошибок**
   - Ошибки обобщений могут быть сложными
   - Нужны понятные сообщения об ошибках

### Меры по смягчению

1. **Стратегии кэширования**
   - Кэширование результатов инстанцирования
   - LRU-кэш для ограничения памяти

2. **Инкрементальная компиляция**
   - Кэширование результатов компиляции
   - Инкрементальное инстанцирование

3. **Сообщения об ошибках**
   - Понятные сообщения об ошибках
   - Подсказки по выводу параметров обобщений

4. **Параллельная компиляция**
   - Параллельное инстанцирование обобщений
   - Многопоточное решение ограничений

## Альтернативы

| Альтернатива                   | Почему не выбрана                                   |
| ------------------------------ | --------------------------------------------------- |
| Только базовые обобщения       | Не заменяют сложные макросы                         |
| Чистая система макросов        | Нет безопасности типов, плохие сообщения об ошибках |
| Только ограничения-зависимости | Недостаточная гибкость                              |
| Обобщения времени выполнения   | Накладные расходы на производительность             |

### Риски

| Риск                          | Воздействие                  | Мера по смягчению              |
| ----------------------------- | ---------------------------- | ------------------------------ |
| Сложность решения ограничений | Слишком долгая компиляция    | Инкрементальное решение + кэш  |
| Разрастание кода              | Чрезмерно большой бинарник   | DCE + пороговое управление     |
| Сложность реализации          | Увеличение сроков разработки | Поэтапная реализация           |
| Диагностика ошибок            | Плохой пользовательский опыт | Подробные сообщения об ошибках |

## Приложение

### BNF-грамматика

```bnf
# Параметры обобщений используют унифицированный синтаксис () как часть типа функции
# Например, map: (T: Type, R: Type) -> ((list: List(T), f: (T) -> R) -> List(R))

# Ограничение типа (в параметрах обобщений)
type_bound ::= identifier
             | identifier '+' identifier ('+' identifier)*

# Объявление параметра (тип + имя)
parameter ::= identifier ':' type

parameters ::= parameter (',' parameter)*

# Объявление функции: name: type = expression
# Параметры обобщений — первая группа параметров типа функции: (T: Type) -> ((params) -> return)
function ::= identifier ':' type '=' (expression | block)

# Объявление метода: Type.method: type = expression
method ::= identifier '.' identifier ':' type '=' (expression | block)

# Определение типа (унифицированный синтаксис Binding)
# Обобщённый тип, например List: (T: Type) -> Type = { ... }
generic_type ::= identifier ':' type '=' type_expression

# Type в параметрах обобщений автоматически заполняется компилятором из типов фактических аргументов
# Например, в map(numbers, f) — T извлекается из numbers: List(Int), R — из f: (Int) -> String
```
