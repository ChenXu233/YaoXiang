# RFC-011: Система обобщений — абстракции с нулевой стоимостью и замена макросов

## Резюме

Настоящий документ определяет **проект системы обобщений** языка YaoXiang, реализующий абстракции с
нулевой стоимостью за счёт мощного механизма обобщений, использующий оптимизации времени компиляции
для снижения зависимости от макросов и предоставляющий механизм удаления мёртвого кода.

**Ключевые проектные решения**:

- **Унифицированный синтаксис сигнатур**: `(T: Type, R: Type) -> ...` — параметры обобщений и
  обычные параметры унифицированы
- **Механизм самоописания Type**: `Type` — языковой специальный объект, позиции `Type` в сигнатуре
  автоматически выводятся и заполняются
- **Ограничения типов**: `T: Dup + Add` — множественные ограничения, ограничения на типы функций
- **Ассоциированные типы**:
  `Iterator: (Item: Type) -> Type = { next: () -> Option(Item), has_next: () -> Bool }`
- **Компайл-тайм обобщения**: `N: Int` — параметры-значения обобщений, инстанцирование константами
  времени компиляции
- **Условные типы**: `If: (C: Bool, T: Type, E: Type) -> Type` — вычисления на уровне типов,
  семейства типов

**Ценность**:

- Абстракции с нулевой стоимостью: мономорфизация во время компиляции, отсутствие накладных расходов
  в рантайме
- Удаление мёртвого кода: анализ графа инстанцирования + оптимизации LLVM
- Замена макросов: обобщения заменяют 90% сценариев использования макросов
- Безопасность типов: проверки во время компиляции, дружелюбность к IDE
- **Явное лучше неявного**: `Type` самоописывающий, компилятор автоматически выполняет вывод

## Идея вселенной типов и типы, зависящие от значений

Система обобщений YaoXiang построена на **идее вселенной типов** — ментальной модели, унифицирующей
все концепции языка в многоуровневую структуру. Ключевая инновация — возведение **типов, зависящих
от значений**, в полноправные сущности уровня Type2.

### Что такое тип, зависящий от значения?

**Тип, зависящий от значения** — это тип, который зависит от одного или нескольких **значений** (а
не только от других типов). Эти значения могут быть вычислены во время компиляции, обеспечивая
гарантии безопасности типов уже на этом этапе.

```yaoxiang
# Традиционные обобщения: параметр-тип
List: (T: Type) -> Type

# Тип, зависящий от значения: параметр-значение
Array: (T: Type, N: Int) -> Type  # Тип массива зависит от значения длины N
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type  # Тип матрицы зависит от числа строк и столбцов
```

### Именование контейнерных типов по уровням

На языковом уровне существуют три концепции контейнеров, ключевое различие между которыми — где
хранится информация о длине:

| Тип           | Длина            | Семантика                                         | Подложка                                    |
| ------------- | ---------------- | ------------------------------------------------- | ------------------------------------------- |
| `Array(T, N)` | Тип              | **Фиксированный** массив, N в типе                | Базовый примитив (стек/inline-приоритет)    |
| `Vec(T)`      | Рантайм-значение | **Примитивный буфер длины рантайма**, может расти | Базовый примитив (непрерывный буфер в куче) |
| `List(T)`     | Рантайм-значение | Тип стандартной библиотеки                        | Библиотека: `{ data: Vec(T), length: Int }` |

Принципы разделения:

- **`Array(T, N)` — единственная форма, помещающая длину в тип** — длина является константой времени
  компиляции, что позволяет выполнить отказ на этапе компиляции при ошибке границы (`a[5]` при
  `a: Array(Int, 3)` напрямую даёт ошибку компиляции, см. раздел «Компиляционная проверка
  размерности» ниже).
- **`Vec(T)` — минимальный фундамент длины рантайма** — предоставляет лишь четыре вещи: «уметь
  выделить, уметь получить длину, уметь читать/писать, уметь расширять». Политика ёмкости, фактор
  роста, вопрос сжатия — всё это не делается. Это сырьё для построения других контейнеров.
- **`List(T)` — библиотечный тип, не примитив** — определяется на самом YaoXiang в `std.list`
  (`{ data: Vec(T), length: Int }`), наравне с пользовательскими обобщёнными записями. Вся политика
  растущей семантики (когда расширять, насколько, возможно ли разделение владения) находится в
  библиотеке, компилятор не участвует.

Форма конструирования `Vec(T)` (два слоя: сначала параметры-типы, затем параметры конструктора):

```yaoxiang
# Пустое конструирование — длина 0, элементы добавляются позже
v = Vec(Int)()

# Конструирование элементами — длина определяется числом элементов
w = Vec(Int)(1, 2, 3)          # длина 3

# Выделение слотов — выделяет n нулевых слотов
buf = Vec(Int)(len=64)         # длина 64, все элементы — нулевые значения
```

> Выделение слотов использует синтаксис **с именами полей** (`len=`), а не позиционный: позиционный
> одиночный целочисленный аргумент был бы неоднозначен с «одноэлементным вектором» (`Vec(Int)(64)`
> невозможно отличить от «длины 64» и «содержащего один элемент 64»). Это согласуется с
> унифицированным правилом конструирования обобщений: аргументы с именами полей связываются по
> имени, не завися от позиционного вывода.
>
> Это единственный примитив, необходимый для расширения `List` — `List` при необходимости выделяет
> новые слоты и перемещает элементы:
>
> ```yaoxiang
> new_data = Vec(T)(len=self.data.length * 2)
> ```
>
> Когда расширять, насколько, сжимать ли — всё это решает `List`. `Vec` не занимается политикой
> ёмкости.

Снизу вверх производительность убывает, гибкость возрастает: `Array` > `Vec` > `List`.

> Обоснование именования: `Vec`/`vector` в основных языках (Rust/C++) обозначают растущую
> последовательность с длиной в рантайме; `Array` обозначает фиксированную длину.

### Ключевые преимущества типов, зависящих от значений

По сравнению с традиционными обобщениями, типы, зависящие от значений, в YaoXiang обладают
следующими ключевыми преимуществами:

| Свойство                         | Традиционные обобщения (C++/Rust)                | Типы, зависящие от значений, в YaoXiang                              |
| -------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------- |
| Значения, от которых зависит тип | Зависят только от параметров-типов               | Могут зависеть от любых значений, включая результаты вызова функций  |
| Вычисление во время компиляции   | C++ — ручная специализация шаблонов, Rust — нет  | Автоматическое вычисление во время компиляции, гарантия завершимости |
| Вычисления на уровне типов       | Шаблонное метапрограммирование (сложное/опасное) | Единый движок вычислений на уровне типов                             |
| Безопасность типов               | C++ — нет, Rust — ограниченная                   | Полная безопасность типов, проверка во время компиляции              |
| Проверка размерности             | Проверка в рантайме или ручная специализация     | Проверка во время компиляции, без накладных расходов в рантайме      |

### Иерархия вселенных типов и типы, зависящие от значений

Идея вселенной типов разделяет языковые концепции по семантической роли на разные уровни. Типы,
зависящие от значений, расположены на **уровне Type2**:

| Уровень   | Роль                                                       | Примеры                                                                                                         |
| --------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Type-1    | Значения                                                   | `42`, `factorial(5)`, сама функция                                                                              |
| Type0     | Ключевое слово метаязыка типов                             | `Type`                                                                                                          |
| Type1     | Конкретные типы                                            | `Int`, `String`, `Array(Int, 3)`                                                                                |
| **Type2** | **Функции/конструкторы типов/типы, зависящие от значений** | `add: (Int, Int) -> Int`, `Array: (T: Type, N: Int) -> Type`, `Matrix: (T: Type, Rows: Int, Cols: Int) -> Type` |

**Ключевое проектное решение**: функции, конструкторы типов и типы, зависящие от значений, на уровне
Type2 **имеют унифицированный синтаксис** — все имеют форму `(params) -> result`:

- Обычная функция: `(Int, Int) -> Int` → результат — значение
- Конструктор типа: `(T: Type) -> Type` → результат — тип
- Тип, зависящий от значения: `(T: Type, N: Int) -> Type` → результат — тип, зависящий от
  параметра-значения N

> **Изоморфизм Карри-Ховарда**: это единство не случайно. Изоморфизм Карри-Ховарда утверждает, что
> «типы суть утверждения, программы суть доказательства» — функциональный тип `A → B` соответствует
> логической импликации «если A, то B», обобщение `(T: Type) -> Type` соответствует квантору
> всеобщности «для всех типов T», а тип, зависящий от значения, `(n: Int) -> Type` соответствует
> «для каждого целого n существует тип». YaoXiang объединяет функции, конструкторы типов и типы,
> зависящие от значений, на уровне Type2, что по существу объединяет «доказательство» и «вычисление»
> в одну концепцию — **конструктивное доказательство**. Это прямое проявление изоморфизма
> Карри-Ховарда в дизайне языка: одна форма (`(params) -> result`) одновременно несёт логическое
> утверждение и процесс вычисления.

### Гарантия определённости во время компиляции

Идея вселенной типов YaoXiang требует: **всё на уровне Type определено во время компиляции**.

```yaoxiang
# Пример проверки размерности во время компиляции
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),
    # Проверка во время компиляции: размерности должны быть положительными
    _assert: Assert(Rows > 0),
    _assert: Assert(Cols > 0),
}

# Создание единичной матрицы 3x3 — выполняется во время компиляции
identity: (T: Add + Zero + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    # ...
}

# Вычисление во время компиляции: factorial(3) = 6, размер массива определяется во время компиляции
arr: Array(Int, factorial(3)) = Array(Int, 6)()
```

Компилятор автоматически:

1. Обнаруживает вызовы функций в позиции типа
2. Выполняет проверку завершимости функции во время компиляции (см. механизм проверки завершимости
   ниже)
3. Выполняет вычисление во время компиляции
4. Встраивает результат в порождаемый тип

### Сценарии применения типов, зависящих от значений

#### Проверка размерности во время компиляции

```yaoxiang
# Умножение матриц: проверка соответствия размерностей во время компиляции
multiply: (T: Add + Multiply + Zero,
           Rows: Int, Cols: Int, M: Int) -> ((
    a: Matrix(T, Rows, Cols),
    b: Matrix(T, Cols, M)
) -> Matrix(T, Rows, M)) = {
    # Проверка во время компиляции: a.Cols == b.Rows, иначе ошибка компиляции
    result = Matrix(T, Rows, M)()
    # ...
}

# Ошибка обнаруживается во время компиляции:
# multiply(matrix_2x3, matrix_4x2)  # Ошибка компиляции: 2 != 4
```

#### Размер массива, безопасный по типам

```yaoxiang
# Размер массива — константа времени компиляции
Array: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    length: N,
}

# N — константа времени компиляции, может использоваться в вычислениях на уровне типов
first_three: Array(Int, 3) = Array(Int, 3)(1, 2, 3)
# first_three.length == 3 (известно во время компиляции)
```

#### Целевое покрытие сбоев границ во время компиляции

> **Описание состояния реализации**: типы контейнеров уже деспециализированы — `Array(T, N)`
> является конструктором const-обобщений, литеральный контекст размещения и предикат принадлежности
> `in` уже реализованы. Точка размещения литерала `Array(T, N)` для N и типа элементов уже
> принудительно проверяется во время компиляции (E1002), **N считается достоверным** — механизм этой
> секции может строиться на утверждении «аннотация N == длина рантайма». Текущие `[]` выход за
> границы индекса (E6003) и отсутствующий ключ Dict (E6008) находятся в **переходном состоянии
> ошибок рантайма**; цель этой секции — сжать эти сбои границ до уровня **времени компиляции**:
>
> - const-индексирование: `a[5]` (5 — константа времени компиляции) при `a: Array(Int, 3)` — прямой
>   отказ во время компиляции;
> - индекс-значение: `a[i]` требует предусловия `i < len(a)`, доказываемого контрактом типа,
>   зависящего от значения;
> - предикат `in` — основа предусловий логики Хоара: `n in 1..10`, `x in some_set` — доказуемые во
>   время компиляции утверждения.
>
> Полный проект уточнённых типов будет дополнен этой секцией при реализации.

#### Условные типы

```yaoxiang
# If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Семейства типов
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,
}
```

#### Обобщённые функции

```yaoxiang
# map: обобщённая функция, параметры типов T, R определяются во время компиляции
map: (T: Type, R: Type) -> (
    (list: List(T), f: (x: T) -> R) -> List(R)
) = (list, f) => {
    result = List(R)()
    for x in list {
        result.push(f(x))
    }
    return result
}

# Использование полностью прозрачно, типы выводятся автоматически
numbers = List(Int)()   # исправление: двухуровневая форма конструирования значений (см. §9.1); элементы добавляются через push
numbers.push(1)
numbers.push(2)
numbers.push(3)
doubled = map(numbers, (x) => x * 2)  # выводится как map[Int, Int]
```

### Механизм проверки завершимости (унифицирован с RFC-027)

Вычисление во время компиляции для типов, зависящих от значений, должно **гарантировать
завершимость**, иначе система типов попадёт в бесконечный цикл. Проверка завершимости выполняется
**полностью автоматически** конвейером доказательств RFC-027 — компилятор автоматически синтезирует
метрики, проходит рекурсия/цикл, если она доказуема, и сразу сообщает об ошибке компиляции, если не
доказуема. **Полуавтоматическим аннотациям не оставлено лазеек**: `//! decreases`,
`/*! invariant !*/` из RFC-022 отменены вместе с RFC-022; спецификация — это сама аннотация типов.

#### Проверка завершимости рекурсивных функций

Перед вычислением во время компиляции компилятор проверяет, что аргументы рекурсивных вызовов строго
убывают на каждом рекурсивном пути (RFC-027 §6.7). Никаких аннотаций спецификации не требуется:

```yaoxiang
# Компиляционный факториал: без //! requires/ensures/decreases, компилятор анализирует автоматически
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)  # Анализ компилятора: n-1 < n → убывает → завершается
}

# Использование: в позиции типа вызов, компилятор сначала проверяет завершимость, затем вычисляет
arr: Array(Int, factorial(5)) = Array(Int, 120)()  # вычисление во время компиляции factorial(5) = 120
```

| Сценарий                                                              | Поведение                          |
| --------------------------------------------------------------------- | ---------------------------------- |
| Компилятор может проанализировать убывание рекурсии (например, `n-1`) | Вычисление во время компиляции     |
| Не убывает / невозможно определить убывание                           | Ошибка компиляции                  |
| Вызов в рантайме (не в позиции типа)                                  | Проверка завершимости не требуется |

#### Проверка завершимости циклов

Циклам не нужны аннотации `: Invariant(...)` или `: decreases(...)`. Аннотации уточнённых типов на
переменных (например, `UpTo(n)`) одновременно предоставляют инвариант цикла и границу метрики.
Компилятор пробует четыре стратегии синтеза метрик по приоритету, останавливаясь на первой успешной
(RFC-027 §7):

1. **Автоматический синтез линейной ранговой функции** — извлечение границ переменных из аннотаций
   типов, перебор линейных комбинаций, верификация SMT m ≥ 0 и m' < m на всех путях
2. **Подсчёт нарушений предиката** (экспериментально) — извлечение violation_count из определения
   целевого типа (например, `Sorted`), покрытие соседних обменов/перемещений
3. **Паттерны ограниченного возрастания/убывания** — `v += const` → метрика `upper - v` (вырождение
   стратегии 1, самый быстрый путь)
4. **Шаблон метрики мультипликативного масштабирования** — `v *= const` (const > 1) → метрика
   `ceil(log_const(upper / v))`

```yaoxiang
sum: (arr: Array(Int, n)) -> Int = {
    mut i: UpTo(arr.len) = 0   # Аннотация типа даёт верхнюю гр. arr.len и нижнюю гр. 0
    while i < arr.len {
        # Компилятор автоматически выводит: метрика arr.len - i, на каждой итерации строго убывает на 1 → завершимость доказана
        s += arr[i]; i += 1
    }
    return s
}
```

#### Рабочий процесс проверки завершимости

```
┌─────────────────────────────────────────────────────────────┐
│  Фаза проверки типов                                        │
│  Встречается вызов функции в позиции типа (например, factorial(5)) │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  1. Проверка завершимости (конвейер доказательств RFC-027,   │
│     полностью автоматический)                                │
│     - Рекурсивные функции: проверка строгого убывания        │
│       аргументов на каждом рекурсивном пути                  │
│     - Циклы: четыре стратегии синтеза метрик                 │
│       (линейный ранг/подсчёт нарушений/ограниченный паттерн/ │
│       мультипликативное масштабирование), SMT-верификация    │
│     - Невозможно доказать → ошибка компиляции                │
│       (жёсткая граница, без полуавтоматических аннотаций)    │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  2. Вычисление во время компиляции (выполняется             │
│     встроенным интерпретатором)                              │
│     - Чистые функции: прямое вычисление                      │
│     - Побочные эффекты: ошибка компиляции                    │
│       (позиция типа должна быть без побочных эффектов)       │
└─────────────────────────┬───────────────────────────────────┘
                          ▼
┌─────────────────────────────────────────────────────────────┐
│  3. Встраивание результата в тип                            │
│     - Array(Int, factorial(5)) → Array(Int, 120)             │
│     - Matrix(Float, 3, 3) → конкретный тип                   │
└─────────────────────────────────────────────────────────────┘
```

#### Преимущества

- **Безопасность**: гарантирует, что вычисление во время компиляции всегда завершается, избегая
  попадания системы типов в бесконечный цикл
- **Единство**: проверка завершимости и верификация корректности (генерация VC) разделяют один
  конвейер доказательств во время компиляции (RFC-027), без отдельного синтаксиса спецификаций
- **Полная автоматизация**: компилятор автоматически синтезирует метрики из аннотаций типов,
  проходит, если доказуемо, сообщает об ошибке, если не доказуемо — без зависимости от ручного
  `decreases` программиста

## Мотивация

### Зачем нужна мощная система обобщений?

Существующие обобщения в основных языках имеют ограничения:

| Язык         | Возможности обобщений           | Проблема                                                                                             |
| ------------ | ------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Java         | Граничные типы                  | Мономорфизация во время компиляции, без специализации обобщений                                      |
| C#           | Ограничения обобщений           | Проверка типов в рантайме, накладные расходы на производительность                                   |
| Rust         | Обобщения + Trait               | Сложная система Trait, крутая кривая обучения                                                        |
| C++          | Шаблоны                         | Сложная специализация шаблонов, плохие сообщения об ошибках                                          |
| **YaoXiang** | **Типы, зависящие от значений** | **Типы могут зависеть от значений, проверка размерности во время компиляции, гарантия завершимости** |

### Ключевые противоречия

1. **Производительность vs гибкость**: гибкость рантайма vs оптимизации компиляции
2. **Сложность vs простота**: мощная система типов vs удобство использования
3. **Макросы vs обобщения**: кодогенерация макросами vs безопасность типов обобщений
4. **Зависимость от значений vs безопасность типов**: традиционные обобщения не могут проверять
   размерность во время компиляции

### Ключевые преимущества типов, зависящих от значений

**Типы, зависящие от значений**, в YaoXiang — ключевое преимущество относительно традиционных
обобщений:

| Преимущество                       | Описание                                                                                                     |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **Тип зависит от значения**        | `Array: (T: Type, N: Int) -> Type` позволяет типу зависеть от конкретного значения                           |
| **Вычисление во время компиляции** | Вызовы функций в позиции типа вычисляются во время компиляции, результат непосредственно встраивается в тип  |
| **Проверка размерности**           | `Matrix(Float, 3, 3)` проверяет размерности матрицы во время компиляции                                      |
| **Вычисления на уровне типов**     | Условные типы `If`, `Match` поддерживают вычисления на уровне типов                                          |
| **Гарантия завершимости**          | Проверка завершимости во время компиляции (автоматический синтез метрик) гарантирует завершимость вычислений |

```yaoxiang
# Проверка во время компиляции, невозможная в C++/Rust
matrix: Matrix(Float, factorial(3), factorial(2)) = ...
# Вычисление во время компиляции: factorial(3) = 6, factorial(2) = 2
# Тип — Matrix(Float, 6, 2)

# Несоответствие размерностей обнаруживается во время компиляции
identity: Matrix(Float, 3, 3) = ...
# multiply(matrix_2x3, identity_3x3)  # Ошибка компиляции: 2 != 3
```

### Ценность системы обобщений

```yaoxiang
# Пример: унифицированный дизайн API
# Операция map для разных контейнерных типов

# Традиционное решение: отдельная реализация для каждого типа
map_int_array: (array: Vec(Int), f: Fn(Int) -> Int) -> Vec(Int) = ...
map_string_array: (array: Vec(String), f: Fn(String) -> String) -> Vec(String) = ...
map_int_list: (list: List(Int), f: Fn(Int) -> Int) -> List(Int) = ...
map_string_list: (list: List(String), f: Fn(String) -> String) -> List(String) = ...

# Решение с обобщениями: одна обобщённая функция покрывает все типы
map: (T: Type, R: Type)(container: Container(T), f: Fn(T) -> R) -> Container(R) = {

        result.push(f(item))
    }
    result
}
```

## Цели проектирования

### Основные цели

1. **Абстракции с нулевой стоимостью** — вызов обобщения эквивалентен вызову конкретного типа
2. **Удаление мёртвого кода** — анализ во время компиляции, инстанцирование только используемых
   обобщений
3. **Замена макросов** — обобщения заменяют 90% сценариев использования макросов
4. **Безопасность типов** — проверка во время компиляции, без накладных расходов на типы в рантайме
5. **Дружелюбность к IDE** — интеллектуальные подсказки, понятные сообщения об ошибках
6. **Типы, зависящие от значений** — типы могут зависеть от значений, поддержка проверки размерности
   во время компиляции
7. **Безопасность вычислений во время компиляции** — гарантия завершимости вычислений во время
   компиляции через проверку завершимости (автоматический синтез метрик по RFC-027)

### Принципы проектирования

- **Определённость во время компиляции**: параметры обобщений определяются во время компиляции
- **Приоритет мономорфизации**: генерация конкретного кода, избежание вызовов виртуальных функций
- **Управление через ограничения**: ограничения типов направляют инстанцирование
- **Оптимизации под платформу**: специализация для поддержки платформенно-специфичных оптимизаций
- **Единство вселенной типов**: функции/конструкторы типов/типы, зависящие от значений,
  унифицированы на уровне Type2
- **Гарантия завершимости**: вызовы функций в позиции типа должны доказывать завершимость

## Предложение

### 1. Базовые обобщения

#### 1.1 Параметры обобщённых типов

> **Ключевое правило**: определения обобщённых типов **должны явно аннотироваться `: Type`**, иначе
> будут выведены HM как функции.
>
> | Запись                            | Значение                          |
> | --------------------------------- | --------------------------------- |
> | `List: (T: Type) -> Type = {...}` | ✅ Конструктор типа               |
> | `List = {...}`                    | ❌ HM выводит как функцию, не тип |

```yaoxiang
# Определение обобщённого типа (обязательно : Type)
Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self
}

Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self
}

List: (T: Type) -> Type = {
    data: Vec(T),
    length: Int,
    push: (self: List(T), item: T) -> Void,   # self — лишь имя по соглашению, не ключевое слово
    get: (self: List(T), index: Int) -> Option(T),
}

# Обобщённая функция (без : Type, HM выводит как функцию)
map: (T: Type, R: Type) -> ((opt: Option(T), f: Fn(T) -> R) -> Option(R)) = {
    return match opt {
        some => Option.some(f(some)),
        none => Option.none(),
    }
}

# Ограничение обобщения (прямое выражение, однострочное может опускать return)
clone: (T: Clone)(value: T) -> T = value.clone()

# Множественные параметры типов
combine: (T: Type, U: Type) -> ((a: T, b: U) -> (T, U)) = (a, b)
```

`Type` — языковой специальный объект, компилятор изначально распознаёт позиции `Type` в сигнатуре и
автоматически выводит и заполняет их из типов фактических аргументов.

```yaoxiang
    result: List(String) = List(String)
```

```yaoxiang
# Сортировка обобщённого контейнера
```

#### 2.4 Встроенные маркерные trait: Dup и Clone

**Три вида семантики копирования**:

| Тип                                  | Значение                                                                        | Способ запуска                          | Сценарий использования             |
| ------------------------------------ | ------------------------------------------------------------------------------- | --------------------------------------- | ---------------------------------- |
| **Копирование примитивных значений** | Копирование значения при присваивании, два значения полностью независимы        | Автоматически при присваивании/передаче | Int, Float, Bool, Char             |
| **Dup**                              | Поверхностное копирование: копирование дескриптора/токена, общие базовые данные | Автоматически при присваивании/передаче | токены `&T`, `ref T`, String/Bytes |
| **Clone**                            | Глубокое копирование: создание полной независимой копии                         | `value.clone()`                         | Любой тип, реализующий Clone       |

**Семантика Dup**: типы, реализующие Dup, при присваивании/передаче не передают владение —
компилятор копирует дескриптор/токен, несколько владельцев указывают на одни и те же базовые данные.
Это дополняет семантику Move по умолчанию в модели владения из RFC-009.

**Dup и Clone — ортогональные концепции**:

```
Dup = копирование дескриптора, общие данные (изменения влияют друг на друга)
Clone = копирование данных, копия независима (изменения не влияют друг на друга)
```

**Правила**:

```
1. Примитивные типы значений (Int, Float, Bool, Char) — встроенное в компилятор копирование значений, не относятся к Dup
2. Dup  — применимо только к ссылочным/токенным типам и типам с внутренним подсчётом ссылок
3. Clone — явное глубокое копирование, любой тип может реализовать
4. Move по умолчанию — остальные типы сохраняют семантику Move по умолчанию
```

**Какие типы являются Dup**:

| Тип                                | Dup         | Причина                                                                             |
| ---------------------------------- | ----------- | ----------------------------------------------------------------------------------- |
| `&T` (токен заимствования)         | ✅          | Токен нулевого размера, копирование токена = несколько представлений на одни данные |
| `ref T`                            | ✅          | Копирование Rc/Arc = счётчик ссылок +1, общие данные в куче                         |
| String, Bytes                      | ✅          | Внутренний подсчёт ссылок, копирование дескриптора разделяет базовый буфер          |
| `&mut T` (токен изменяемой ссылки) | ❌          | Линейно эксклюзивный, нельзя копировать                                             |
| struct                             | Производный | Все поля Dup → struct Dup                                                           |
| enum                               | Производный | Все поля всех вариантов Dup → enum Dup                                              |
| tuple                              | Производный | Все элементы Dup → tuple Dup                                                        |
| Fn (замыкание)                     | ❌          | Захватываемая среда может быть не Dup                                               |
| `*T` (сырой указатель)             | ❌          | unsafe, не участвует в системе владения                                             |

**Int/Float/Bool/Char не являются Dup** — они типы значений, при присваивании компилятор
автоматически копирует значение (два значения полностью независимы). Это не «поверхностное
копирование», это встроенная обработка компилятором примитивов, которую не нужно и не следует
выражать через атрибут типа Dup.

```yaoxiang
# Примитивные типы значений: компилятор автоматически копирует значение (не Dup)
x: Int = 42
y = x          # копирование значения, x и y полностью независимы
print(x)       # ✅

# Dup: поверхностное копирование, копирование дескриптора с общими данными
view: &Point = &point
view2 = view    # ✅ Dup: копирование токена, оба указывают на тот же point
print(view.x)   # ✅

# Clone: явное глубокое копирование, создание независимой копии
backup = big_struct.clone()  # явный вызов

# Ограничения обобщений
dup_use: (T: Dup) -> T = x         # T: Dup → можно поверхностно копировать
clone_use: (T: Clone) -> T = x.clone()  # T: Clone → можно глубоко копировать
```

> **Примечание**: `Send`/`Sync` не делаются видимыми для пользователя trait. Безопасность
> межзадачных гарантий обеспечивается ключевым словом `ref` и полностью автоматической обработкой
> компилятором — `ref` автоматически выбирает Rc или Arc, пользователю не нужно понимать Send/Sync.

```yaoxiang
collect_all: (T: Type, I: Iterator(T))(iter: I) -> List(T) = {
    result: List(T) = List(T)
    while iter.has_next() {
        if let Some(item) = iter.next() {
            result.push(item)
        }
    }
    return result
}

# Реализация Iterator для Vec
# Использование синтаксического сахара методов: Vec.Item, Vec.next, Vec.has_next
# Позиция итерации переносится обёрточной записью (Vec сам — примитивный буфер, без поля index)
VecIter: (T: Type) -> Type = {
    data: &Vec(T),
    index: Int,
}

VecIter.has_next: (T: Type)(self: &VecIter(T)) -> Bool = {
    return self.index < self.data.length
}

VecIter.next: (T: Type)(self: &mut VecIter(T)) -> Option(T) = {
    if self.index < self.data.length {
        item = self.data[self.index]
        self.index = self.index + 1
        return Option.some(item)
    } else {
        return Option.none()
    }
}

VecIter.Item: (T: Type)(arr: &VecIter(T)) -> T = {
    return arr.data[arr.index]
}
```

### 4. Компиляционные обобщения

#### 4.1 Параметры-значения времени компиляции

> **Исправление**: в исходном тексте было «параметры-значения вроде `Int` по умолчанию определяемы
> во время компиляции в контексте обобщений», что **строго неверно** — в
> `add: (a: Int, b: Int) -> Int = a + b` параметры `a`/`b` являются параметрами-значениями рантайма.
> Только конкретные параметры-типы, **упомянутые в позиции типа**, являются параметрами-значениями
> времени компиляции. Корректное определение см. ниже.

**Ключевое проектное решение**: маркер `Type` в сигнатуре обобщения отмечает параметры-типы;
параметры, аннотированные конкретными типами (`Int`/`Bool`/`Float` и т.д.), становятся **кандидатами
в параметры-значения времени компиляции**; становятся ли они таковыми, зависит от того,
**используются ли их значения в позиции типа** (зависимость от значения). Ключевое слово `const` не
требуется.

**Правило определения (два шага)**:

1. **Грубая морфологическая фильтрация**: параметр, аннотированный не-`Type` конкретным типом
   (например, `Int`) → становится кандидатом.
2. **Точная фильтрация по использованию**: имя кандидата появляется в **позиции типа** (тип поля в
   теле типа, типы параметров внутреннего `Fn`, предикат `Assert`, аргументы конструкции типов вроде
   `Array(T, N)`) → подтверждается как параметр-значение времени компиляции; иначе рассматривается
   как **параметр-значение рантайма**.

| Запись                                                     | Определение                              | Причина                                                                   |
| ---------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------- |
| `add: (a: Int, b: Int) -> Int = a + b`                     | a/b — параметры-значения рантайма        | Появляются только в позиции значения, не участвуют в конструировании типа |
| `Array: (T: Type, N: Int) -> Type = { data: Array(T, N) }` | N — параметр-значение времени компиляции | N появляется в позиции аргумента конструкции типа `Array(T, N)`           |
| `factorial: (N: Int) -> (k: N) -> Int`                     | N — параметр-значение времени компиляции | N выступает типом внутреннего параметра `k`                               |
| `Foo: (T: Type, N: Int) -> Type = { x: T }`                | N пропадает (см. ниже)                   | N не используется в теле типа, вырождается в параметр-значение рантайма   |

> **Суть зависимости от значения**: параметр-значение времени компиляции — это и есть тип, зависящий
> от значения, — только когда значение используется для **конструирования типа**, его нужно
> определять во время компиляции. Морфология (`: Int`) лишь определяет кандидатуру, использование
> (появление в позиции типа) определяет, является ли он параметром-значением времени компиляции. Это
> тот же критерий, что и в разделе «Гарантия определённости во время компиляции» — «вызовы функций в
> позиции типа вычисляются во время компиляции».

```yaoxiang
# ════════════════════════════════════════════════════════
# Параметр-значение времени компиляции: N используется в позиции типа (слот длины Measure)
# ════════════════════════════════════════════════════════
Measure: (T: Type, N: Int) -> Type = {
    data: Array(T, N),  # N появляется в позиции аргумента конструкции типа → параметр-значение времени компиляции
    length: N,
}

# Использование: factorial(5) вычисляется в позиции типа (время компиляции), результат 120 встраивается в тип
m: Measure(Int, factorial(5))  # Measure(Int, 120)

# ════════════════════════════════════════════════════════
# Зависимость от значения: N выступает типом внутреннего параметра k
# ════════════════════════════════════════════════════════
# N — параметр-значение времени компиляции (появляется в позиции типа (k: N));
# k — параметр-значение рантайма, его тип — литеральный тип N (однозначный тип).
factorial: (N: Int) -> (k: N) -> Int = {
    return match k {
        0 => 1,
        _ => k * factorial(k - 1)
    }
}
```

> **Обработка пропавших кандидатов**: кандидаты, аннотированные конкретным типом, но не используемые
> в позиции типа (например, `N` из `Foo` в таблице выше), вырождаются в параметры-значения рантайма
> (путь на уровне функции). Пропавшие кандидаты пути конструктора типа не могут занять слот рантайма
> (конструктор типа вычисляется во время компиляции), сторона объявления сразу сообщает об ошибке
> [E1094]: «N объявлен как параметр-значение времени компиляции, но не используется в теле типа» —
> ранее тихое отбрасывание приводило к несоответствию арности инстанцирования.

### Never и Void: ⊥ и ⊤ в системе типов

Система типов YaoXiang в изоморфизме Карри-Ховарда одновременно обладает ⊥ (ложь/пустой тип) и ⊤
(истина/Unit), представленными двумя встроенными именами типов: `Never` и `Void`.

**Never (⊥)** — три не подлежащих обсуждению ключевых свойства:

1. **Нулевой конструктор**: ни один литерал или выражение не может породить значение типа `Never`.
   Это мета-свойство, должно быть встроенным.
2. **Принцип взрыва**: `Never <: T` для любого типа `T`. Значение `Never` может использоваться как
   значение любого типа — именно поэтому код после `assert(false)` проходит проверку типов (хотя
   никогда не выполняется).
3. **Метка расходимости**: `f: (...) -> Never` означает, что `f` гарантированно не возвращается.
   Компилятор использует это для анализа мёртвого кода.

`Never` — встроенное имя типа, не ключевое слово, парсер нечувствителен. Синтаксис пустого и
литерального типа не открывается.

**Void (⊤, т.е. Unit)** — ровно один обитатель (значение void по умолчанию), носитель истинного
утверждения «всегда истинно». `Void` — единица нуль-полевого произведения типов, `Never` — единица
нуль-вариантного суммирования типов — они двойственны. `x: Void = <по умолчанию>` допустимо,
`x: Never = ...` не имеет правой части для записи.

#### 4.3 Верификация во время компиляции (реализация стандартной библиотеки)

```yaoxiang
# ════════════════════════════════════════════════════════
# Реализация стандартной библиотеки: использование условных типов
# ════════════════════════════════════════════════════════

# Определения стандартной библиотеки
# IsTrue: мост от вселенной значений к вселенной типов — отображение истинного значения Bool в тип
IsTrue: (b: Bool) -> Type = match b {
    true => Void,      # ⊤, имеет значение, программа продолжается
    false => Never,    # ⊥, без значения, расходимость
}

# Assert: примитив уточнённого типа во время компиляции — выражение утверждения Bool на уровне типов
Assert: (cond: Bool) -> Type = IsTrue(cond)
#
# cond — true   → Assert(true)   = Void    (всегда истинно, стирается)
# cond — false  → Assert(false)  = Never   (всегда ложно, ошибка компиляции/расходимость)
# cond нельзя определить → конвейер доказательств решает по режиму dispatch:
#                           CompileTime → Unknown, требует prove
#                           Runtime     → вставка check, инъекция предположения Γ

# Способ использования 1: как ограничение в определении типа
Bounded: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    # Проверка во время компиляции: N должно быть больше 0 (Assert в позиции типа)
    length: Assert(N > 0),
}

# Способ использования 2: использование в выражении
IntArray: (N: Int) -> Type = Array(Int, N)
# Верификация: размер IntArray(10) равен sizeof(Int) * 10
Assert(size_of(IntArray(10)) == sizeof(Int) * 10)
```

### 5. Условные типы

> **Изоморфизм Карри-Ховарда**: условные типы с точки зрения Карри-Ховарда — это **case-анализ** в
> логике. Тип `Bool` соответствует утверждению с двумя возможными значениями (True/False), `If`
> выбирает разные результаты в зависимости от истинности/ложности утверждения — это именно
> логическая дизъюнкция case. `match C { True => T, False => E }` фактически выражает: «когда
> известно, что утверждение C истинно, заключение — T; когда ложно — E».

#### 5.1 Условный тип If

```yaoxiang
# If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Пример: ветвление во время компиляции
NonEmpty: (T: Type) -> Type = If(T != Void, T, Never)

Optional: (T: Type) -> Type = If(T != Void, T, Void)

# Верификация во время компиляции (унифицирована с определением Assert из §4.3)
# Assert: (cond: Bool) -> Type = IsTrue(cond)

# Использование
# Вычисление типа: If(True, Int, String) => Int
# Вычисление типа: If(False, Int, String) => String
```

#### 5.2 Семейства типов

> **Изоморфизм Карри-Ховарда**: семейства типов — самое прямое проявление «утверждения суть типы».
> `Add: (A: Type, B: Type) -> Type` — это не «функция сложения, написанная на уровне типов», а
> **конструирование утверждения о сложении натуральных чисел**. `(Zero, B) => B` означает
> «утверждение Add(Zero, B) эквивалентно B», `(Succ(A'), B) => Succ(Add(A', B))` означает «если
> Add(A', B) доказано, то Add(Succ(A'), B) также доказано». Это и есть определение сложения в
> аксиомах Пеано. То, что проверка типов подтверждает это match-выражение, эквивалентно
> подтверждению логической непротиворечивости этого определения.

```yaoxiang
# Преобразование типа во время компиляции
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,  # по умолчанию
}

# Вычисление на уровне типов
Length: (T: Type) -> Type = match T.length {
    0 => Zero,
    1 => Succ(Zero),
    2 => Succ(Succ(Zero)),
    _ => TooLong,
}

# Сложение на уровне типов (Карри-Ховард: case-анализ + рекурсивный вызов, требует проверки завершимости для полной индукции)
Add: (A: Type, B: Type) -> Type = match (A, B) {
    (Zero, B) => B,
    (Succ(A'), B) => Succ(Add(A', B)),
}

# Пример: вычисление во время компиляции 2 + 3
Two: Type = Succ(Succ(Zero))
Three: Type = Succ(Succ(Succ(Zero)))
Five: Type = Add[Two, Three]  # Succ(Succ(Succ(Succ(Succ(Zero)))))
```

````
struct InstantiationGraph {
    // Узлы: инстанцирования обобщений
    nodes: HashMap<InstanceKey, InstanceNode>,

    edges: HashMap<InstanceKey, Vec<InstanceKey>>,

    const_args: Vec<ConstId>,  // аргументы Const

fn eliminate_dead_instantiations(graph: &InstantiationGraph) {
    let mut reachable = HashSet::new();

    // Начинаем с точек входа (main, экспортируемые функции и т.д.)
    let entry_points = find_entry_points();
    for entry in entry_points {
        dfs_visit(entry, &graph, &mut reachable);
    }

    // Не посещённые инстанцирования — мёртвый код
    for node in &graph.nodes {
        if !reachable.contains(node.key) {
            eliminate(node);
        }
    }
}
````

```yaoxiang
# Использование синтаксиса (T: Type) -> Type
Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self,
}

Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self,
}

List: (T: Type) -> Type = {
    data: Vec(T),
    length: Int,

    # Обобщённые методы (T автоматически попадает в область видимости из внешнего List(T))
    push: (self: List(T), item: T) -> Void,
    pop: (self: List(T)) -> Option(T),
    map: (R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)),
    filter: (self: List(T), predicate: (T) -> Bool) -> List(T),
    fold: (U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U),
}

# ======== 2. Реализация обобщённых методов ========
# Определение функций в пространстве имён List (префикс List. = принадлежность пространству имён)
# Чтобы синтаксис вызова через . работал (list.push(item)), требуется явная привязка: List.push = push[0]
# self — лишь имя параметра по соглашению, компилятор смотрит на тип, а не на имя

List.push: (T: Type) -> ((self: List(T), item: T) -> Void) = {
    if self.length >= self.data.length {
        # Расширение
        new_data = Vec(T)(len=self.data.length * 2)
        for i in 0..self.length {
            new_data[i] = self.data[i]
        }
        self.data = new_data
    }
    self.data[self.length] = item
    self.length = self.length + 1
}

List.pop: (T: Type) -> ((self: List(T)) -> Option(T)) = {
    if self.length > 0 {
        self.length = self.length - 1
        return Option.some(self.data[self.length])
    } else {
        return Option.none()
    }
}

List.map: (T: Type, R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)) = {
    result = List(R)()
    for i in 0..self.length {
        result.push(f(self.data[i]))
    }
    return result
}

List.filter: (T: Type) -> ((self: List(T), predicate: (T) -> Bool) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        if predicate(self.data[i]) {
            result.push(self.data[i])
        }
    }
    return result
}

List.fold: (T: Type, U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U) = {
    result = initial
    for i in 0..self.length {
        result = f(result, self.data[i])
    }
    return result
}

# ======== 3. Использование ограничений типов ========
# Реализация Clone для List
List.clone: (T: Clone) -> ((self: List(T)) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        result.push(self.data[i].clone())
    }
    return result
}
```

```yaoxiang
# ======== 1. Обобщённый алгоритм сортировки ========
Comparator: (T: Type) -> Type = {
    compare: (T, T) -> Int,  # -1 если a < b, 0 если a == b, 1 если a > b
}

# Обобщённая быстрая сортировка
quicksort: (T: Clone) -> ((array: Vec(T), cmp: Comparator(T)) -> Vec(T)) = {
    if array.length <= 1 {
        return array.clone()
    }

    pivot = array[array.length / 2]
    left = Vec(T)()
    right = Vec(T)()

    for i in 0..array.length {
        if i == array.length / 2 {
            continue
        }
        item = array[i]
        comparison = cmp.compare(item, pivot)
        if comparison < 0 {
            left.push(item)
        } else {
            right.push(item)
        }
    }

    sorted_left = quicksort(left, cmp)
    sorted_right = quicksort(right, cmp)

    result = sorted_left.clone()
    result.push(pivot)
    result.extend(sorted_right)
    return result
}

# ======== 2. Реализация IntComparator ========
# Использование перегрузки функций
compare: (a: Int, b: Int) -> Int = {
    if a < b {
        return -1
    } else if a > b {
        return 1
    } else {
        return 0
    }
}

# ======== 3. Пример использования ========
# Сортировка массива Int
```

```yaoxiang
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {

    _assert: Assert(Rows > 0),  # Rows > 0, иначе ошибка компиляции

    multiply: (M: Int) -> ((self: Matrix(T, Rows, Cols), other: Matrix(T, Cols, M)) -> Matrix(T, Rows, M)) = {
```

## Компромиссы

### Преимущества

1. **Абстракции с нулевой стоимостью**
   - Мономорфизация во время компиляции, без накладных расходов в рантайме
   - Не требуются виртуальные функции, RTTI

2. **Удаление мёртвого кода**
   - Анализ во время компиляции, инстанцирование только используемых обобщений
   - Раздувание кода управляемо

3. **Замена макросов**
   - Безопасная по типам кодогенерация
   - Дружелюбность к IDE, понятные сообщения об ошибках

4. **Вычисления во время компиляции**
   - Обобщения во время компиляции поддерживают вычисления во время компиляции
   - Возможности вроде проверки размерности
   - Не требуется ключевое слово `const`, чистые ограничения типов

### Недостатки

1. **Время компиляции**
   - Инстанцирование обобщений увеличивает время компиляции
   - Решение ограничений может быть медленным

2. **Потребление памяти**
   - Увеличивается потребление памяти компилятором
   - Механизмы кэширования требуют памяти

3. **Сложность реализации**
   - Решатель ограничений сложен
   - Движок вычислений на уровне типов сложен

4. **Диагностика ошибок**
   - Ошибки обобщений могут быть сложными
   - Необходимы понятные сообщения об ошибках

### Меры по смягчению

1. **Стратегия кэширования**
   - Кэширование результатов инстанцирования
   - LRU-кэш ограничивает потребление памяти

2. **Инкрементальная компиляция**
   - Кэширование результатов компиляции
   - Инкрементальное инстанцирование

3. **Сообщения об ошибках**
   - Понятные сообщения об ошибках
   - Подсказки для вывода параметров обобщений

4. **Параллельная компиляция**
   - Параллельное инстанцирование обобщений
   - Многопоточное решение ограничений

## Альтернативы

| Альтернатива                   | Почему не выбрана                                   |
| ------------------------------ | --------------------------------------------------- |
| Только базовые обобщения       | Не может заменить сложные макросы                   |
| Чистая система макросов        | Нет безопасности типов, плохие сообщения об ошибках |
| Только ограничения-зависимости | Недостаточная гибкость                              |
| Обобщения в рантайме           | Накладные расходы на производительность             |

### Риски

| Риск                          | Воздействие                     | Мера по смягчению                     |
| ----------------------------- | ------------------------------- | ------------------------------------- |
| Сложность решения ограничений | Чрезмерное время компиляции     | Инкрементальное решение + кэширование |
| Раздувание кода               | Чрезмерно большой бинарный файл | DCE + контроль порога                 |
| Сложность реализации          | Увеличение цикла разработки     | Поэтапная реализация                  |
| Диагностика ошибок            | Плохой пользовательский опыт    | Подробные сообщения об ошибках        |

## Приложение

### Синтаксис BNF

```bnf
# Параметры обобщений используют унифицированный синтаксис () как часть функционального типа
# Например, map: (T: Type, R: Type) -> ((list: List(T), f: (T) -> R) -> List(R))

# Ограничения типов (в параметрах обобщений)
type_bound ::= identifier
             | identifier '+' identifier ('+' identifier)*

# Объявление параметра (тип + имя)
parameter ::= identifier ':' type

parameters ::= parameter (',' parameter)*

# Объявление функции: name: type = expression
# Параметры обобщений — первая группа параметров в функциональном типе: (T: Type) -> ((params) -> return)
function ::= identifier ':' type '=' (expression | block)

# Объявление метода: Type.method: type = expression
method ::= identifier '.' identifier ':' type '=' (expression | block)

# Определение типа (унифицированный синтаксис Binding)
# Обобщённый тип, например, List: (T: Type) -> Type = { ... }
generic_type ::= identifier ':' type '=' type_expression

# Type в параметрах обобщений автоматически заполняется компилятором из типов фактических аргументов
# Например, map(numbers, f), T извлекается из numbers: List(Int), R — из f: (Int) -> String
```
