# RFC-011: Дизайн системы обобщений — абстракции с нулевой стоимостью и замена макросов

## Резюме

Этот документ определяет **дизайн системы обобщений (generics)** языка YaoXiang, реализующий
абстракции с нулевой стоимостью посредством мощных возможностей обобщений, использующий оптимизации
времени компиляции для снижения зависимости от макросов и предоставляющий механизм устранения
мёртвого кода.

**Основные положения дизайна**:

- **Единый синтаксис сигнатур**: `(T: Type, R: Type) -> ...` — параметры обобщений и обычные
  параметры унифицированы
- **Механизм самоописания Type**: `Type` — особая сущность уровня языка; позиция `Type` в сигнатуре
  автоматически выводится и заполняется
- **Ограничения типов**: `T: Dup + Add` — множественные ограничения, ограничения на типы функций
- **Ассоциированные типы**:
  `Iterator: (Item: Type) -> Type = { next: () -> Option(Item), has_next: () -> Bool }`
- **Обобщения времени компиляции**: `N: Int` — параметры-значения обобщений, инстанциация
  константами времени компиляции
- **Условные типы**: `If: (C: Bool, T: Type, E: Type) -> Type` — вычисления на уровне типов,
  семейства типов

**Ценность**:

- Абстракции с нулевой стоимостью: мономорфизация на этапе компиляции, без накладных расходов во
  время выполнения
- Устранение мёртвого кода: анализ графа инстанциации + оптимизации LLVM
- Замена макросов: обобщения заменяют 90% сценариев использования макросов
- Безопасность типов: проверка на этапе компиляции, дружественность к IDE
- **Явное лучше неявного**: самоописание `Type`, автоматический вывод компилятора

## Идея вселенной типов и типы, зависящие от значений

Система обобщений YaoXiang построена на **идее вселенной типов**. Эта ментальная модель объединяет
все концепции языка в иерархическую структуру; ключевая инновация — возведение **типов, зависящих от
значений** (value-dependent types) в полноправные сущности уровня Type2.

### Что такое тип, зависящий от значений?

**Тип, зависящий от значений** — это тип, зависящий от одного или нескольких **значений** (а не
только от других типов). Эти значения могут быть вычислены на этапе компиляции, обеспечивая гарантии
безопасности типов уже на стадии компиляции.

```yaoxiang
# Традиционные обобщения: параметры-типы
List: (T: Type) -> Type

# Тип, зависящий от значений: параметр-значение
Array: (T: Type, N: Int) -> Type  # Тип массива зависит от значения длины N
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type  # Тип матрицы зависит от числа строк и столбцов
```

### Именование контейнерных типов по уровням

На уровне языка существуют три концепции контейнеров; местонахождение информации о длине — их
фундаментальное различие:

| Тип           | Длина                       | Семантика                                                   | Базовая реализация                          |
| ------------- | --------------------------- | ----------------------------------------------------------- | ------------------------------------------- |
| `Array(T, N)` | Тип                         | **Фиксированная** длина, N — в типе                         | Базовый примитив (стек/inline в приоритете) |
| `Vec(T)`      | Значение времени выполнения | **Примитивный буфер длины времени выполнения**, может расти | Базовый примитив (непрерывный буфер в куче) |
| `List(T)`     | Значение времени выполнения | Тип стандартной библиотеки                                  | Библиотека: `{ data: Vec(T), length: Int }` |

Принципы разделения:

- **`Array(T, N)` — единственная форма, выносящая длину в тип** — длина является константой времени
  компиляции, поэтому возможен отказ на этапе компиляции при ошибке границ (`a[5]` при
  `a: Array(Int, 3)` вызывает ошибку компиляции, см. раздел «Верификация измерений времени
  компиляции» ниже).
- **`Vec(T)` — минимальный фундамент длины времени выполнения** — предоставляет только четыре
  возможности: «выделить, получить длину, читать/писать, расширить»; ни стратегии ёмкости, ни
  коэффициент роста, ни политика сжатия не реализованы. Это сырьё для построения других контейнеров.
- **`List(T)` — библиотечный тип, не примитив** — определяется в самом YaoXiang в `std.list`
  (`{ data: Vec(T), length: Int }`), наравне с пользовательскими обобщёнными записями. Вся политика
  расширяемой семантики (когда расширять, на сколько, можно ли разделять) находится в библиотеке,
  компилятор не участвует.

Форма конструктора `Vec(T)` (двухуровневая: сначала параметры-типы, затем параметры-конструктора):

```yaoxiang
# Пустая конструкция — длина 0, элементы добавляются позже
v = Vec(Int)()

# Элементная конструкция — длина определяется числом элементов
w = Vec(Int)(1, 2, 3)          # длина 3

# Распределение слотов — n нулевых слотов
buf = Vec(Int)(len=64)         # длина 64, все элементы — нулевые значения
```

> Распределение слотов использует **именованный** синтаксис (`len=`), а не позиционный: позиционная
> форма с единственным целым неоднозначна с «одноэлементным вектором» (`Vec(Int)(64)` нельзя
> отличить от «длина 64» и «один элемент 64»). Это согласуется с едиными правилами конструктора
> обобщений: именованные аргументы связываются по имени и не подвержены позиционному выводу.
>
> Это единственный примитив, необходимый `List` для расширения — `List` при необходимости выделяет
> новые слоты и перемещает элементы:
>
> ```yaoxiang
> new_data = Vec(T)(len=self.data.length * 2)
> ```
>
> Решения о том, когда расширять, на сколько и сжимать ли, принимает `List`. `Vec` не реализует
> политику ёмкости.

Снизу вверх производительность падает, гибкость растёт: `Array` > `Vec` > `List`.

> Обоснование имён: `Vec`/`vector` в основных языках (Rust/C++) обозначают расширяемую
> последовательность длины времени выполнения; `Array` обозначает фиксированную длину.

### Ключевые преимущества типов, зависящих от значений

По сравнению с традиционными обобщениями, типы YaoXiang, зависящие от значений, имеют следующие
ключевые преимущества:

| Свойство                         | Традиционные обобщения (C++/Rust)                       | Типы YaoXiang, зависящие от значений                                  |
| -------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------- |
| Значения, от которых зависит тип | Только параметры-типы                                   | Любые значения, включая результаты вызовов функций                    |
| Вычисления времени компиляции    | Ручная специализация шаблонов в C++, отсутствует в Rust | Автоматическое вычисление времени компиляции с гарантией завершимости |
| Вычисления на уровне типов       | Метапрограммирование шаблонов (сложно/опасно)           | Единый движок вычислений на уровне типов                              |
| Безопасность типов               | Отсутствует в C++, ограничена в Rust                    | Полная безопасность типов, проверка времени компиляции                |
| Верификация измерений            | Проверка времени выполнения или ручная специализация    | Верификация измерений времени компиляции, без накладных расходов      |

### Иерархия вселенных типов и типы, зависящие от значений

Идея вселенной типов разделяет концепции языка по семантической роли на разные уровни; типы,
зависящие от значений, находятся на **уровне Type2**:

| Уровень   | Роль                                                       | Примеры                                                                                                         |
| --------- | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Type-1    | Значения                                                   | `42`, `factorial(5)`, сама функция                                                                              |
| Type0     | Метатип-ключевое слово                                     | `Type`                                                                                                          |
| Type1     | Конкретные типы                                            | `Int`, `String`, `Array(Int, 3)`                                                                                |
| **Type2** | **Функции/конструкторы типов/типы, зависящие от значений** | `add: (Int, Int) -> Int`, `Array: (T: Type, N: Int) -> Type`, `Matrix: (T: Type, Rows: Int, Cols: Int) -> Type` |

**Ключевой дизайн**: функции, конструкторы типов и типы, зависящие от значений, на уровне Type2
используют **единый синтаксис** — форму `(params) -> result`:

- Обычная функция: `(Int, Int) -> Int` → результат — значение
- Конструктор типа: `(T: Type) -> Type` → результат — тип
- Тип, зависящий от значений: `(T: Type, N: Int) -> Type` → результат — тип, зависящий от
  параметра-значения N

> **Изоморфизм Карри-Ховарда**: это единство — не совпадение. Изоморфизм Карри-Ховарда утверждает
> «типы суть propositions, программы суть доказательства» — тип функции `A → B` соответствует
> логической импликации «если A, то B», обобщение `(T: Type) -> Type` соответствует квантору
> всеобщности «для всех типов T», тип, зависящий от значений, `(n: Int) -> Type` соответствует «для
> каждого целого n существует тип». YaoXiang объединяет функции, конструкторы типов и типы,
> зависящие от значений, на уровне Type2, по сути объединяя «доказательство» и «вычисление» в одну
> концепцию — **конструктивное доказательство**. Это прямое воплощение изоморфизма Карри-Ховарда в
> дизайне языка: одна форма (`(params) -> result`) одновременно несёт логические propositions и
> вычислительные процессы.

### Гарантия детерминированности времени компиляции

Идея вселенной типов YaoXiang требует: **всё на уровне Type определено на этапе компиляции**.

```yaoxiang
# Пример верификации измерений времени компиляции
Matrix: (T: Type, Rows: Int, Cols: Int) -> Type = {
    data: Array(Array(T, Cols), Rows),
    # Проверка времени компиляции: измерения должны быть положительными
    _assert: Assert(Rows > 0),
    _assert: Assert(Cols > 0),
}

# Создание единичной матрицы 3x3 — завершается на этапе компиляции
identity: (T: Add + Zero + One, N: Int) -> ((size: N) -> Matrix(T, N, N)) = {
    matrix = Matrix(T, N, N)()
    # ...
}

# Вычисление времени компиляции: factorial(3) = 6, размер массива определяется на этапе компиляции
arr: Array(Int, factorial(3)) = Array(Int, 6)()
```

Компилятор автоматически:

1. Обнаруживает вызовы функций в позициях типов
2. Выполняет проверку завершимости вызова (см. механизм проверки завершимости ниже)
3. Производит вычисление на этапе компиляции
4. Встраивает результат в порождаемый тип

### Сценарии применения типов, зависящих от значений

#### Верификация измерений времени компиляции

```yaoxiang
# Умножение матриц: верификация совпадения измерений на этапе компиляции
multiply: (T: Add + Multiply + Zero,
           Rows: Int, Cols: Int, M: Int) -> ((
    a: Matrix(T, Rows, Cols),
    b: Matrix(T, Cols, M)
) -> Matrix(T, Rows, M)) = {
    # Проверка времени компиляции: a.Cols == b.Rows, иначе ошибка компиляции
    result = Matrix(T, Rows, M)()
    # ...
}

# Ошибка перехватывается на этапе компиляции:
# multiply(matrix_2x3, matrix_4x2)  # Ошибка компиляции: 2 != 4
```

#### Типобезопасный размер массива

```yaoxiang
# Размер массива — константа времени компиляции
Array: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    length: N,
}

# N — константа времени компиляции, может использоваться в вычислениях на уровне типов
first_three: Array(Int, 3) = Array(Int, 3)(1, 2, 3)
# first_three.length == 3 (известно на этапе компиляции)
```

#### Цель покрытия ошибок границ на этапе компиляции

> **Примечание о состоянии реализации**: контейнерные типы де-специализированы — `Array(T, N)` —
> конструктор обобщений с const; точки привязки литералов и предикат `in` для membership уже
> реализованы. Точка привязки литерала `Array(T, N)` к N и типу элемента принудительно проверяется
> на этапе компиляции (E1002), **N достоверно** — механизмы данного раздела могут опираться на
> «аннотацию N == длина времени выполнения». В настоящее время выход индекса за границы `[]` (E6003)
> и отсутствие ключа в Dict (E6008) находятся в **переходном состоянии ошибки времени выполнения**;
> типы, зависящие от значений, данного раздела — целевой механизм переноса этих ошибок границ на
> **этап компиляции**:
>
> - const-индексация: `a[5]` (5 — константа времени компиляции) при `a: Array(Int, 3)` напрямую
>   отвергается на этапе компиляции;
> - индексация значением: `a[i]` требует предусловия `i < len(a)`, доказуемого по контракту типов,
>   зависящих от значений;
> - предикат `in` — основа предусловий логики Хоара: `n in 1..10`, `x in some_set` — доказуемые
>   propositions времени компиляции.
>
> Полный дизайн уточнённых типов будет дополнен этим разделом при реализации.

#### Условные типы

```yaoxiang
# If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Семейства типов
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,
}
```

#### Обобщённые функции

```yaoxiang
# map: обобщённая функция, параметры-типы T, R определяются на этапе компиляции
map: (T: Type, R: Type) -> (
    (list: List(T), f: (x: T) -> R) -> List(R)
) = (list, f) => {
    result = List(R)()
    for x in list {
        result.push(f(x))
    }
    return result
}

# Использование полностью прозрачно, типы выводятся автоматически
numbers = List(Int)()   # Двухуровневая форма конструктора значения (см. §9.1); элементы добавляются через push
numbers.push(1)
numbers.push(2)
numbers.push(3)
doubled = map(numbers, (x) => x * 2)  # Выводится как map[Int, Int]
```

### Механизм проверки завершимости (унифицирован с RFC-027)

Вычисления времени компиляции для типов, зависящих от значений, должны быть **гарантированно
завершимыми**, иначе система типов попадёт в бесконечный цикл. Проверка завершимости выполняется
конвейером доказательства RFC-027 в режиме **полностью автоматического приоритета** — компилятор
сначала автоматически ищет меры; рекурсии/циклы, для которых доказательство найдено, проходят; если
автоматический поиск не удался и явная мера не предоставлена, выдаётся ошибка компиляции (RFC-027
§6.9 определяет явные меры в позиции типа как запасной вариант). **Синтаксису аннотаций не оставлено
лазеек**: `//! decreases` и `/*! invariant !*/` из RFC-022 устарели вместе с RFC-022; спецификация —
это сама аннотация типа.

> **Критерий срабатывания (RFC-027 §7)**: обязательство завершимости вызывается **уточнёнными
> типами** — как только тип уточнён, включается режим верификации. Неуточнённые обычные типы не
> входят в режим верификации и не порождают обязательств завершимости.

#### Проверка завершимости рекурсивных функций

Для рекурсивных функций с уточнённой сигнатурой компилятор проверяет, что аргументы рекурсивных
вызовов строго убывают на каждом пути рекурсии (RFC-027 §6.7). Никаких комментариев-спецификаций не
требуется:

```yaoxiang
# Рекурсия с уточнённой сигнатурой: без //! requires/ensures/decreases, компилятор автоматически ищет убывание
factorial: (n: NonNegative(n)) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)  # Автопоиск компилятора: n-1 < n → убывает → завершается
}
```

| Сценарий                                                    | Поведение                                 |
| ----------------------------------------------------------- | ----------------------------------------- |
| Компилятор находит убывание (например, `n-1`)               | Проходит                                  |
| Автопоиск не удался, но в позиции типа дана мера (§6.9)     | SMT решает, истина — проходит             |
| Автопоиск не удался, явной меры нет / мера опровергнута SMT | Ошибка компиляции                         |
| Сигнатура без уточнения (режим верификации не включён)      | Обязательство завершимости не порождается |

#### Проверка завершимости циклов

Циклам не нужны аннотации `: Invariant(...)` или `: decreases(...)`. Аннотации уточнённого типа на
переменных (например, `UpTo(n)`) одновременно задают инвариант цикла и границу меры; компилятор по
приоритету пробует четыре стратегии автопоиска меры и останавливается на первой найденной (RFC-027
§6.1–6.5):

1. **Автоматический синтез линейной ранговой функции** — из аннотаций типов извлекает границы
   переменных, перебирает линейные комбинации, SMT проверяет m ≥ 0 и m' < m на всех путях
2. **Подсчёт нарушений предиката** (экспериментальный) — из определения целевого типа (например,
   `Sorted`) извлекает violation_count, покрывает соседние обмены/перемещения
3. **Шаблон ограниченного инкремента/декремента** — `v += const` → мера `upper - v` (вырождение
   стратегии 1, самый быстрый путь)
4. **Шаблон меры с мультипликативным масштабированием** — `v *= const` (const > 1) → мера
   `ceil(log_const(upper / v))`

```yaoxiang
sum: (arr: Array(Int, n)) -> Int = {
    mut i: UpTo(arr.len) = 0   # Аннотация типа задаёт верхнюю границу arr.len и нижнюю 0 → включает режим верификации
    while i < arr.len {
        # Автопоиск компилятора: мера arr.len - i, на каждой итерации строго убывает на 1 → завершимость доказана
        s += arr[i]; i += 1
    }
    return s
}
```

Если автопоиск не удался, циклу можно присвоить имя и задать меру в позиции типа (RFC-027 §6.9):

```yaoxiang
loop: (n: Int) -> Int = {
    mut i = 0
    acc: Terminates(n - i) = while i < n { i = i + 1 }
    return acc
}
```

#### Преимущества

- **Безопасность**: гарантия обязательной завершимости вычислений времени компиляции, защита от
  зацикливания системы типов
- **Единообразие**: проверка завершимости и верификация корректности (генерация VC) используют общий
  конвейер доказательства времени компиляции (RFC-027), без отдельного синтаксиса спецификаций
- **Полностью автоматический приоритет**: компилятор автоматически ищет меры из аннотаций типов; при
  доказуемости — проходит; если автопоиск не удался, можно задать меру в позиции типа
  (`Terminates`), и она также проверяется SMT — без зависимости от ручного синтаксиса `decreases`

## Мотивация

### Зачем нужна мощная система обобщений?

Современные mainstream-языки имеют ограничения в обобщениях:

| Язык         | Возможности обобщений           | Проблема                                                                                            |
| ------------ | ------------------------------- | --------------------------------------------------------------------------------------------------- |
| Java         | Ограниченные типы               | Мономорфизация на этапе компиляции, без специализации                                               |
| C#           | Ограничения типов               | Проверка типов времени выполнения, потеря производительности                                        |
| Rust         | Обобщения + Trait               | Сложная система Trait, крутая кривая обучения                                                       |
| C++          | Шаблоны                         | Сложная специализация шаблонов, плохие сообщения об ошибках компиляции                              |
| **YaoXiang** | **Типы, зависящие от значений** | **Тип может зависеть от значений, верификация измерений времени компиляции, гарантия завершимости** |

### Ключевые противоречия

1. **Производительность vs гибкость**: гибкость времени выполнения vs оптимизации времени компиляции
2. **Сложность vs простота**: мощная система типов vs удобство использования
3. **Макросы vs обобщения**: кодогенерация макросами vs типобезопасность обобщений
4. **Зависимость от значений vs безопасность типов**: традиционные обобщения не могут верифицировать
   измерения на этапе компиляции

### Ключевые преимущества типов, зависящих от значений

**Типы YaoXiang, зависящие от значений** — ключевое преимущество по сравнению с традиционными
обобщениями:

| Преимущество                      | Описание                                                                                                              |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **Тип зависит от значений**       | `Array: (T: Type, N: Int) -> Type` позволяет типу зависеть от конкретного значения                                    |
| **Вычисления времени компиляции** | Вызовы функций в позициях типов вычисляются на этапе компиляции, результат напрямую встраивается в тип                |

```yaoxiang
# Пример: унифицированный дизайн API
```

## Цели дизайна

### Основные цели

1. **Абстракции с нулевой стоимостью** — вызов обобщений эквивалентен вызову конкретного типа
2. **Устранение мёртвого кода** — анализ на этапе компиляции, инстанциация только используемых
   обобщений
3. **Замена макросов** — обобщения заменяют 90% сценариев использования макросов
4. **Безопасность типов** — проверка на этапе компиляции, без накладных расходов на типы во время
   выполнения
5. **Дружественность к IDE** — интеллектуальные подсказки, ясные сообщения об ошибках
6. **Типы, зависящие от значений** — тип может зависеть от значений, поддержка верификации измерений
   времени компиляции
7. **Безопасность вычислений времени компиляции** — гарантия завершимости вычислений времени
   компиляции посредством проверки завершимости (автоматический синтез мер по RFC-027)

### Принципы дизайна

- **Определённость времени компиляции**: параметры обобщений определяются на этапе компиляции
- **Приоритет мономорфизации**: порождение конкретного кода, без вызовов виртуальных функций
- **Управление через ограничения**: ограничения типов направляют инстанциацию
- **Платформенные оптимизации**: специализация для поддержки платформенных оптимизаций
- **Единство вселенной типов**: функции/конструкторы типов/типы, зависящие от значений, объединены
  на уровне Type2
- **Гарантия завершимости**: вызовы функций в позициях типов должны доказуемо завершаться

## Предложение

### 1. Базовые обобщения

#### 1.1 Параметры-типы обобщений

> **Ключевое правило**: определение обобщённого типа **должно явно аннотироваться `: Type`**, иначе
> оно будет выведено HM как функция.
>
> | Запись                            | Значение                          |
> | --------------------------------- | --------------------------------- |
> | `List: (T: Type) -> Type = {...}` | ✅ Конструктор типа               |
> | `List = {...}`                    | ❌ HM выводит как функцию, не тип |

```yaoxiang
# Определение обобщённого типа (должно быть : Type)
Option: (T: Type) -> Type = {
    some: (T) -> Self,
    none: () -> Self
}

Result: (T: Type, E: Type) -> Type = {
    ok: (T) -> Self,
    err: (E) -> Self
}

List: (T: Type) -> Type = {
    data: Vec(T),
    length: Int,
    push: (self: List(T), item: T) -> Void,   # self — лишь имя по соглашению, не ключевое слово
    get: (self: List(T), index: Int) -> Option(T),
}

# Обобщённая функция (без : Type, HM выводит как функцию)
map: (T: Type, R: Type) -> ((opt: Option(T), f: Fn(T) -> R) -> Option(R)) = {
    return match opt {
        some => Option.some(f(some)),
        none => Option.none(),
    }
}

# Ограничение обобщений (прямое выражение, для одной строки можно опустить return)
clone: (T: Clone)(value: T) -> T = value.clone()

# Несколько параметров-типов
combine: (T: Type, U: Type) -> ((a: T, b: U) -> (T, U)) = (a, b)
```

### Синтаксис вызова обобщённых функций

#### 1.1 Единый синтаксис сигнатур

```yaoxiang
# Обобщённые функции используют единый синтаксис сигнатур (T: Type, R: Type)
map: (T: Type, R: Type) -> ((list: List(T), f: (x: T) -> R) -> List(R)) = ...

# Несколько параметров-типов
combine: (T: Type, U: Type) -> ((a: T, b: U) -> (T, U)) = (a, b)
```

#### 1.2 Механизм самоописания Type

`Type` — особая сущность уровня языка; компилятор изначально способен распознавать позиции `Type` в
сигнатурах и автоматически выводить и заполнять их из типов фактических аргументов.

```yaoxiang
# Компилятор автоматически выводит параметры обобщений
numbers: List(Int) = List(Int)()
#         ^^^^^^^^   ^^^^^^^^
#         объявление типа   вызов конструктора: Int заполняет T, () — конструкция значения

# Вывод при вызове функции
numbers: List(Int) = List(Int)()
f: (x: Int) -> String = (x) => x.to_string()
strings: List(String) = map(numbers, f)
# Вывод компилятора: T=Int, R=String
```

#### 1.3 Мономорфизация

```yaoxiang
# Исходный код
map: (T: Type, R: Type) -> ((list: List(T), f: (x: T) -> R) -> List(R)) = {
    result: List(R) = List(R)()
    for x in list {
        result.push(f(x))
    }
    return result
}

# Точки использования
int_list: List(Int) = List(Int)()
doubled: List(Int) = map(int_list, (x: Int) => x * 2)  # Инстанциация map[Int, Int]

string_list: List(String) = List(String)()
uppercased: List(String) = map(string_list, (s: String) => s.to_uppercase())  # Инстанциация map[String, String]

# После компиляции (эквивалентный код)
map_Int_Int: (list: List(Int), f: (Int) -> Int) -> List(Int) = {
    result: List(Int) = List(Int)()
    for x in list {
        result.push(f(x))
    }
    return result
}

map_String_String: (list: List(String), f: (String) -> String) -> List(String) = {
    result: List(String) = List(String)
    for s in list {
        result.push(f(s))
    }
    return result
}
```

````yaoxiang
### 2. Система ограничений типов

#### 2.1 Единичные ограничения

```yaoxiang
# Базовые определения trait (интерфейсные типы)
Clone: Type = {
    clone: (Self) -> Self,
}

Display: Type = {
    fmt: (Self, Formatter) -> Result,
}

Debug: Type = {
    fmt: (Self, Formatter) -> Result,
}

# Использование ограничений: объявление ограничений типов прямо в сигнатуре
clone: (T: Clone) -> (value: T) -> T = value.clone()

debug_print: (T: Debug)(value: T) -> Void = {
    formatter = Formatter.new()
    value.fmt(formatter)
    print(formatter.to_string())
}
````

#### 2.2 Множественные ограничения

```yaoxiang
# Синтаксис множественных ограничений
combine: (T: Clone + Add)(a: T, b: T) -> T = {
    a.clone() + b
}

# Сортировка обобщённого контейнера
sort: (T: Clone + PartialOrd)(list: List(T)) -> List(T) = {
    # Реализация алгоритма сортировки
    result: List(T) = list.clone()
    quicksort(&mut result)
    return result
}

# Ограничение типа функции
map: (T: Type, R: FnMut(T))(array: Vec(T), f: R) -> Vec(R) = {
    result: Vec(R) = Vec()
    for item in array {
        result.push(f(item))
    }
    return result
}

# Использование
doubled: Vec(Int) = map(Vec(1, 2, 3), (x: Int) => x * 2)  # Вывод компилятора
```

> **Источник имён ограничений (примечание от 2026-09-22)**: ограничения операторов `Add` /
> `Subtract` / `Multiply` / `Divide` / `Modulo` и т.п. определены и реализованы в
> [RFC-011b: Перегрузка операторов и интерфейсно-управляемые операторы](./011b-operator-overloading.md)
> — `T: Add` ≜ зарегистрированная инстанциация интерфейса `Add(T, T, T)` (три параметра-типа, тип
> результата `O` явный). `Zero` / `One` / `PartialOrd` / `Fn` / `FnMut` в настоящее время **не имеют
> определённого источника**, являются висячими именами ограничений и будут определены в последующих
> RFC; до этого примеры с этими именами — бумажные иллюстрации.

#### 2.3 Ограничения типов функций

```yaoxiang
# Ограничения для функций высшего порядка
call_twice: (T: Type, F: Fn() -> T)(f: F) -> (T, T) = (f(), f())

call_with_arg: (T: Type, U: Type, F: Fn(T) -> U)(arg: T, f: F) -> U = f(arg)

compose: (A: Type, B: Type, C: Type, F: Fn(A) -> B, G: Fn(B) -> C)(a: A, f: F, g: G) -> C = g(f(a))

# Примеры использования
result: Int = call_with_arg(42, (x: Int) => x * 2)  # result = 84
composed: String = compose(
    "hello",
    (s: String) => s.to_uppercase(),
    (s: String) => s + " WORLD"
)  # composed = "HELLO WORLD"
```

#### 2.4 Встроенные маркерные trait: Dup и Clone

**Три класса семантики копирования**:

| Тип                                | Значение                                                              | Способ срабатывания                     | Сценарий применения                |
| ---------------------------------- | --------------------------------------------------------------------- | --------------------------------------- | ---------------------------------- |
| **Копирование значения-примитива** | Копия значения при присваивании, два значения полностью независимы    | Автоматически при присваивании/передаче | Int, Float, Bool, Char             |
| **Dup**                            | Мелкая копия: копируется дескриптор/токен, базовые данные разделяются | Автоматически при присваивании/передаче | токены `&T`, `ref T`, String/Bytes |
| **Clone**                          | Глубокая копия: создаётся полная независимая копия                    | `value.clone()`                         | Любой тип, реализующий Clone       |

**Семантика Dup**: для типов, реализующих Dup, при присваивании/передаче владение не передаётся —
компилятор копирует дескриптор/токен, и несколько держателей указывают на одни и те же базовые
данные. Это дополнение к семантике Move по умолчанию из модели владения RFC-009.

**Dup и Clone — ортогональные концепции**:

```
Dup = копия дескриптора, данные разделяются (изменения влияют друг на друга)
Clone = копия данных, копии независимы (изменения не влияют друг на друга)
```

**Правила**:

```
1. Типы-значения примитивов (Int, Float, Bool, Char) — встроенное копирование значений компилятором, не относится к Dup
2. Dup — применимо только к ссылочным/токенным типам и типам с внутренним подсчётом ссылок
3. Clone — явное глубокое копирование, любой тип может реализовать
4. Move по умолчанию — остальные типы сохраняют семантику Move по умолчанию
```

**Какие типы являются Dup**:

| Тип                                        | Dup         | Причина                                                                      |
| ------------------------------------------ | ----------- | ---------------------------------------------------------------------------- |
| `&T` (токен заимствования)                 | ✅          | Токен нулевого размера, копия токена = несколько представлений тех же данных |
| `ref T`                                    | ✅          | Копия Rc/Arc = подсчёт ссылок +1, разделяемые данные в куче                  |
| String, Bytes                              | ✅          | Внутренний подсчёт ссылок, копия дескриптора разделяет базовый буфер         |
| `&mut T` (токен изменяемого заимствования) | ❌          | Линейная эксклюзивность, копирование невозможно                              |
| struct                                     | Производное | Все поля Dup → struct Dup                                                    |
| enum                                       | Производное | Все поля всех вариантов Dup → enum Dup                                       |
| tuple                                      | Производное | Все элементы Dup → tuple Dup                                                 |
| Fn (замыкание)                             | ❌          | Захваченное окружение может быть не Dup                                      |
| `*T` (сырой указатель)                     | ❌          | unsafe, не участвует в системе владения                                      |

**Int/Float/Bool/Char не являются Dup** — они типы-значения, при присваивании компилятор
автоматически выполняет копию значения (два значения полностью независимы). Это не «мелкая копия», а
встроенная обработка компилятором для примитивов, не требующая и не выражаемая через свойство Dup.

```yaoxiang
# Типы-значения примитивов: компилятор автоматически копирует значение (не Dup)
x: Int = 42
y = x          # Копия значения, x и y полностью независимы
print(x)       # ✅

# Dup: мелкая копия, копия дескриптора разделяет данные
view: &Point = &point
view2 = view    # ✅ Dup: копия токена, оба указывают на один и тот же point
print(view.x)   # ✅

# Clone: явное глубокое копирование, создаётся независимая копия
backup = big_struct.clone()  # Явный вызов

# Ограничения обобщений
dup_use: (T: Dup) -> T = x         # T: Dup → можно мелко копировать
clone_use: (T: Clone) -> T = x.clone()  # T: Clone → можно глубоко копировать
```

> **Примечание**: `Send`/`Sync` не являются видимыми пользователю trait. Гарантии межзадачной
> безопасности обеспечиваются ключевым словом `ref` и полностью автоматической обработкой
> компилятором — `ref` автоматически выбирает Rc или Arc, пользователю не нужно понимать Send/Sync.

```yaoxiang
Iterator: (Item: Type) -> Type = {
    next: (Self) -> Option(Item),
    has_next: (Self) -> Bool,
    collect: (T: Type)(Self) -> List(T),
}

# Использование
collect_all: (T: Type, I: Iterator(T))(iter: I) -> List(T) = {
    result: List(T) = List(T)
    while iter.has_next() {
        if let Some(item) = iter.next() {
            result.push(item)
        }
    }
    return result
}

# Реализация Iterator для Vec
# Используется синтаксический сахар: Vec.Item, Vec.next, Vec.has_next
# Позиция итерации переносится записью-обёрткой (Vec сам — сырой буфер, без поля index)
VecIter: (T: Type) -> Type = {
    data: &Vec(T),
    index: Int,
}

VecIter.has_next: (T: Type)(self: &VecIter(T)) -> Bool = {
    return self.index < self.data.length
}

VecIter.next: (T: Type)(self: &mut VecIter(T)) -> Option(T) = {
    if self.index < self.data.length {
        item = self.data[self.index]
        self.index = self.index + 1
        return Option.some(item)
    } else {
        return Option.none()
    }
}

VecIter.Item: (T: Type)(arr: &VecIter(T)) -> T = {
    return arr.data[arr.index]
}
```

### 4. Обобщения времени компиляции

#### 4.1 Параметры-значения времени компиляции

**Ключевой дизайн**: `Type` в сигнатуре обобщения помечает параметр-тип; параметры, аннотированные
конкретными типами (`Int`/`Bool`/`Float` и т.п.), рассматриваются как **кандидаты в
параметры-значения времени компиляции**; становится ли параметр параметром-значением времени
компиляции, зависит от того, **ссылаются ли на его значение в позиции типа** (зависимость от
значения). Ключевое слово `const` не требуется.

> Критерием служит **ссылка в позиции типа**, а не «аннотация конкретным типом»: в
> `add: (a: Int, b: Int) -> Int = a + b` `a`/`b` — параметры-значения времени выполнения, поскольку
> оба не встречаются ни в одной позиции типа.

**Правило определения (двухшаговое)**:

1. **Грубая фильтрация по форме**: параметр аннотирован конкретным типом, отличным от `Type`
   (например, `Int`) → считается кандидатом.
2. **Точная фильтрация по использованию**: имя-кандидат встречается в **позиции типа** (тип поля
   тела типа, тип параметра внутренней `Fn`, предикат `Assert`, аргумент конструктора типа вроде
   `Array(T, N)`) → подтверждается как параметр-значение времени компиляции; иначе рассматривается
   как **параметр-значение времени выполнения**.

| Запись                                                     | Определение                                 | Причина                                                                        |
| ---------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------ |
| `add: (a: Int, b: Int) -> Int = a + b`                     | a/b — параметры-значения времени выполнения | Встречаются только в позициях значений, не участвуют в конструировании типов   |
| `Array: (T: Type, N: Int) -> Type = { data: Array(T, N) }` | N — параметр-значение времени компиляции    | N встречается в позиции аргумента конструктора типа `Array(T, N)`              |
| `factorial: (N: Int) -> (k: N) -> Int`                     | N — параметр-значение времени компиляции    | N выступает типом внутреннего параметра `k`                                    |
| `Foo: (T: Type, N: Int) -> Type = { x: T }`                | N промахивается (см. ниже)                  | N не упомянут в теле типа → вырождается в параметр-значение времени выполнения |

> **Суть зависимости от значения**: параметр-значение времени компиляции — это тип, зависящий от
> значения, — только когда значение используется для **конструирования типа**, оно должно
> определяться на этапе компиляции. Форма (`: Int`) определяет только кандидатуру, использование
> (появление в позиции типа) определяет, является ли он параметром-значением времени компиляции. Это
> тот же критерий, что и в §«Гарантия детерминированности времени компиляции» о том, что «вызовы
> функций в позициях типов вычисляются на этапе компиляции».

```yaoxiang
# ════════════════════════════════════════════════════════
# Параметр-значение времени компиляции: N упоминается в позиции типа (слот длины Measure)
# ════════════════════════════════════════════════════════
Measure: (T: Type, N: Int) -> Type = {
    data: Array(T, N),  # N встречается в позиции аргумента конструктора типа → параметр-значение времени компиляции
    length: N,
}

# Использование: factorial(5) вычисляется в позиции типа (время компиляции), результат 120 встраивается в тип
m: Measure(Int, factorial(5))  # Measure(Int, 120)

# ════════════════════════════════════════════════════════
# Зависимость от значения: N как тип внутреннего параметра k
# ════════════════════════════════════════════════════════
# N — параметр-значение времени компиляции (встречается в позиции типа (k: N));
# k — параметр-значение времени выполнения, его тип — литеральный тип N (однозначный тип).
factorial: (N: Int) -> (k: N) -> Int = {
    return match k {
        0 => 1,
        _ => k * factorial(k - 1)
    }
}
```

> **Обработка промахнувшихся кандидатов**: кандидаты, аннотированные конкретным типом, но не
> упомянутые в позиции типа (например, `N` в `Foo` из таблицы выше), вырождаются в
> параметры-значения времени выполнения (путь на уровне функции). Промахнувшийся кандидат на пути
> конструктора типа не может занять слот времени выполнения (конструктор типа вычисляется на этапе
> компиляции), на стороне объявления сразу выдаётся ошибка [E1094]: «N объявлен как
> параметр-значение времени компиляции, но не упомянут в теле типа» — ранее тихое отбрасывание
> приводило к рассогласованию arity инстанциации.

### Never и Void: ⊥ и ⊤ в системе типов

Система типов YaoXiang в изоморфизме Карри-Ховарда одновременно обладает ⊥ (ложь/пустой тип) и ⊤
(истина/Unit), представленными двумя встроенными именами типов: `Never` и `Void`:

**Never (⊥)** — три не подлежащих обсуждению ядерных свойства:

1. **Нулевое число конструкторов**: ни один литерал или выражение не может породить значение типа
   `Never`. Это мета-свойство, должно быть встроено.
2. **Принцип взрыва**: `Never <: T` выполняется для любого типа `T`. Значение `Never` может
   использоваться как значение любого типа — именно поэтому код после `assert(false)` проходит
   проверку типов (хотя никогда не выполняется).
3. **Маркер расходимости**: `f: (...) -> Never` означает, что `f` гарантированно не возвращается.
   Компилятор использует это для анализа мёртвого кода.

`Never` — встроенное имя типа, не ключевое слово, parser его не замечает. Синтаксис пустого типа и
литерала типа не открывается.

**Void (⊤, т.е. Unit)** — ровно один обитатель (значение void по умолчанию), носитель истинной
propositions «всегда истинно». `Void` — единица нульарного декартова произведения, `Never` — единица
нульарной суммы — они двойственны. `x: Void = <по умолчанию>` допустимо, `x: Never = ...` не имеет
правой части.

#### 4.3 Верификация времени компиляции (реализация в стандартной библиотеке)

```yaoxiang
# ════════════════════════════════════════════════════════
# Реализация в стандартной библиотеке: использование условных типов
# ════════════════════════════════════════════════════════

# Определения стандартной библиотеки
# IsTrue: мост от вселенной значений к вселенной типов — Bool истина отображается в тип
IsTrue: (b: Bool) -> Type = match b {
    true => Void,      # ⊤, имеет значение, программа продолжается
    false => Never,    # ⊥, нет значения, расходимость
}

# Assert: примитив уточнённого типа времени компиляции — типовая формулировка propositions Bool
Assert: (cond: Bool) -> Type = IsTrue(cond)
#
# cond = true  → Assert(true)  = Void    (всегда истинно, стирается)
# cond = false → Assert(false) = Never   (всегда ложно, ошибка компиляции/расходимость)
# cond неразрешим → конвейер доказательства решает по режиму dispatch:
#                  CompileTime → Unknown, требуется prove
#                  Runtime     → вставляется check, инъекция предположения Γ

# Способ использования 1: как ограничение в определении типа
Bounded: (T: Type, N: Int) -> Type = {
    data: Array(T, N),
    # Проверка времени компиляции: N должно быть больше 0 (Assert в позиции типа)
    length: Assert(N > 0),
}

# Способ использования 2: использование в выражении
IntArray: (N: Int) -> Type = Array(Int, N)
# Верификация: размер IntArray(10) равен sizeof(Int) * 10
Assert(size_of(IntArray(10)) == sizeof(Int) * 10)
```

### 5. Условные типы

> **Изоморфизм Карри-Ховарда**: условные типы с точки зрения Карри-Ховарда — это **case-анализ** в
> логике. Тип `Bool` соответствует propositions с двумя возможными значениями (True/False), `If`
> выбирает различные результаты в зависимости от истинности/ложности этой propositions — это и есть
> case-дизъюнкция в логике. `match C { True => T, False => E }` по сути выражает: «если propositions
> C истинна, заключение — T, если ложна — заключение — E».

#### 5.1 Условный тип If

```yaoxiang
# If на уровне типов
If: (C: Bool, T: Type, E: Type) -> Type = match C {
    True => T,
    False => E,
}

# Пример: ветвление времени компиляции
NonEmpty: (T: Type) -> Type = If(T != Void, T, Never)

Optional: (T: Type) -> Type = If(T != Void, T, Void)

# Верификация времени компиляции (унифицирована с определением Assert в §4.3)
# Assert: (cond: Bool) -> Type = IsTrue(cond)

# Использование
# Вычисление типа: If(True, Int, String) => Int
# Вычисление типа: If(False, Int, String) => String
```

#### 5.2 Семейства типов

> **Изоморфизм Карри-Ховарда**: семейства типов — наиболее прямое воплощение «propositions как
> типов». `Add: (A: Type, B: Type) -> Type` — это не «функция сложения на уровне типов», а
> **построение propositions о сложении натуральных чисел**. `(Zero, B) => B` говорит «propositions
> Add(Zero, B) эквивалентна B», `(Succ(A'), B) => Succ(Add(A', B))` говорит «если Add(A', B)
> истинна, то и Add(Succ(A'), B) истинна». Это и есть определение сложения из аксиом Пеано. Проверка
> типов подтверждает, что это match-выражение проходит, — это эквивалентно проверке логической
> согласованности этого определения.

```yaoxiang
# Преобразование типа времени компиляции
AsString: (T: Type) -> Type = match T {
    Int => String,
    Float => String,
    Bool => String,
    _ => String,  # по умолчанию
}

# Вычисление на уровне типов
Length: (T: Type) -> Type = match T.length {
    0 => Zero,
    1 => Succ(Zero),
    2 => Succ(Succ(Zero)),
    _ => TooLong,
}

# Сложение на уровне типов (Карри-Ховард: case analysis + рекурсивный вызов, требует проверки завершимости для полной индукции)
Add: (A: Type, B: Type) -> Type = match (A, B) {
    (Zero, B) => B,
    (Succ(A'), B) => Succ(Add(A', B)),
}

# Пример: вычисление времени компиляции 2 + 3
Two: Type = Succ(Succ(Zero))
Three: Type = Succ(Succ(Succ(Zero)))
Five: Type = Add[Two, Three]  # Succ(Succ(Succ(Succ(Succ(Zero)))))
```

```yaoxiang
    push: (self: List(T), item: T) -> Void,
    pop: (self: List(T)) -> Option(T),
    map: (R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)),
    filter: (self: List(T), predicate: (T) -> Bool) -> List(T),
    fold: (U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U),

# Функции определяются в пространстве имён List (префикс List. = принадлежность пространству имён)
# Чтобы синтаксис вызова через . работал как list.push(item), требуется явная привязка: List.push = push[0]
# self — лишь имя параметра по соглашению, компилятор смотрит на тип, а не на имя

List.push: (T: Type) -> ((self: List(T), item: T) -> Void) = {
    if self.length >= self.data.length {
        # Расширение
        new_data = Vec(T)(len=self.data.length * 2)
        for i in 0..self.length {
            new_data[i] = self.data[i]
        }
        self.data = new_data
    }
    self.data[self.length] = item
    self.length = self.length + 1
}

List.pop: (T: Type) -> ((self: List(T)) -> Option(T)) = {
    if self.length > 0 {
        self.length = self.length - 1
        return Option.some(self.data[self.length])
    } else {
        return Option.none()
    }
}

List.map: (T: Type, R: Type) -> ((self: List(T), f: (T) -> R) -> List(R)) = {
    result = List(R)()
    for i in 0..self.length {
        result.push(f(self.data[i]))
    }
    return result
}

List.filter: (T: Type) -> ((self: List(T), predicate: (T) -> Bool) -> List(T)) = {
    result = List(T)()
    for i in 0..self.length {
        if predicate(self.data[i]) {
            result.push(self.data[i])
        }
    }
    return result
}

List.fold: (T: Type, U: Type) -> ((self: List(T), initial: U, f: (U, T) -> U) -> U) = {
    result = initial
    for i in 0..self.length {
        result = f(result, self.data[i])
    }
    return result
}

# ======== 3. Использование ограничений типов ========
```

```yaoxiang
# ======== 1. Обобщённый алгоритм сортировки ========
Comparator: (T: Type) -> Type = {
    compare: (T, T) -> Int,  # -1 if a < b, 0 if a == b, 1 if a > b
}

# Обобщённая быстрая сортировка
quicksort: (T: Clone) -> ((array: Vec(T), cmp: Comparator(T)) -> Vec(T)) = {
    if array.length <= 1 {
        return array.clone()
    }

    pivot = array[array.length / 2]
    left = Vec(T)()
    right = Vec(T)()

    for i in 0..array.length {
        if i == array.length / 2 {
            continue
        }
        item = array[i]
        comparison = cmp.compare(item, pivot)
        if comparison < 0 {
            left.push(item)
        } else {
            right.push(item)
        }
    }

    sorted_left = quicksort(left, cmp)
    sorted_right = quicksort(right, cmp)

    result = sorted_left.clone()
    result.push(pivot)
    result.extend(sorted_right)
    return result
}

# ======== 2. Реализация IntComparator ========
# Реализация через перегрузку функций
compare: (a: Int, b: Int) -> Int = {
    if a < b {
        return -1
    } else if a > b {
        return 1
    } else {
        return 0
    }
}

# ======== 3. Пример использования ========
```

### Преимущества

1. **Абстракции с нулевой стоимостью**
   - Мономорфизация на этапе компиляции, без накладных расходов во время выполнения
   - Без виртуальных функций, без RTTI

2. **Устранение мёртвого кода**
   - Анализ на этапе компиляции, инстанциация только используемых обобщений
   - Раздувание кода контролируемо

3. **Замена макросов**
   - Типобезопасная кодогенерация
   - Дружественность к IDE, ясные сообщения об ошибках

4. **Вычисления времени компиляции**
   - Обобщения времени компиляции поддерживают вычисления времени компиляции
   - Верификация измерений и подобные возможности
   - Без ключевого слова `const`, чистые ограничения типов

### Недостатки

1. **Время компиляции**
   - Инстанциация обобщений увеличивает время компиляции
   - Решение ограничений может быть медленным

2. **Потребление памяти**
   - Увеличение потребления памяти компилятором
   - Механизмам кэширования требуется память

3. **Сложность реализации**
   - Решатель ограничений сложен
   - Движок вычислений на уровне типов сложен

4. **Диагностика ошибок**
   - Ошибки обобщений могут быть сложными
   - Требуются ясные подсказки об ошибках

### Меры по смягчению

1. **Стратегия кэширования**
   - Кэширование результатов инстанциации
   - LRU-кэш для ограничения памяти

2. **Инкрементальная компиляция**
   - Кэширование результатов компиляции
   - Инкрементальная инстанциация

3. **Подсказки об ошибках**
   - Ясные сообщения об ошибках
   - Подсказки для вывода параметров обобщений

4. **Параллельная компиляция**
   - Параллельная инстанциация обобщений
   - Многопоточное решение ограничений

## Альтернативные варианты

| Вариант                      | Почему не выбран                                    |
| ---------------------------- | --------------------------------------------------- |
| Только базовые обобщения     | Не может заменить сложные макросы                   |
| Чисто макросистема           | Нет безопасности типов, плохие сообщения об ошибках |
| Только зависимые ограничения | Недостаточная гибкость                              |
| Обобщения времени выполнения | Накладные расходы производительности                |

| Риск                          | Влияние                      | Мера смягчения                 |
| ----------------------------- | ---------------------------- | ------------------------------ |

## Приложение

### Синтаксис BNF

```bnf
# Параметры обобщений используют единый синтаксис (), как часть типа функции
# Например: map: (T: Type, R: Type) -> ((list: List(T), f: (T) -> R) -> List(R))

# Ограничение типа (в параметрах обобщений)
type_bound ::= identifier
             | identifier '+' identifier ('+' identifier)*

# Объявление параметра (тип + имя)
parameter ::= identifier ':' type

parameters ::= parameter (',' parameter)*

# Объявление функции: name: type = expression
# Параметры обобщений — первая группа параметров типа функции: (T: Type) -> ((params) -> return)
function ::= identifier ':' type '=' (expression | block)

# Объявление метода: Type.method: type = expression
method ::= identifier '.' identifier ':' type '=' (expression | block)

# Определение типа (единый синтаксис Binding)
# Обобщённый тип вроде List: (T: Type) -> Type = { ... }
generic_type ::= identifier ':' type '=' type_expression

# Type в параметрах обобщений автоматически заполняется компилятором из типов фактических аргументов
# Например, для map(numbers, f): T извлекается из numbers: List(Int), R — из f: (Int) -> String
```
