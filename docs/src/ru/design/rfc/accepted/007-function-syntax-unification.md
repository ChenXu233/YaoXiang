# RFC-007: Унификация синтаксиса определения функций

> **Связанное дополнение**: Правила завершения операторов и переноса строк внутри тела функции (блок
> кода `{ ... }`) — явное разделение `;`, завершение переносом строки, исключения для продолжения
> строки — определены в [RFC-038 (черновик)](../draft/038-statement-termination.md), данный RFC их
> не затрагивает.

## Резюме

Настоящий RFC утверждает окончательное решение для **синтаксиса определения функций** языка
YaoXiang. Используется единый синтаксис `name: (params) -> Return = body`, полностью согласующийся с
моделью `name: type = value` из RFC-010.

Во избежание неоднозначности: при наличии входных параметров их типы должны быть явно указаны хотя
бы в одном из мест — в «сигнатуре» или в «lambda-заголовке»; отсутствие указаний в обоих местах
отвергается.

Внутри блока кода `{ ... }` для возврата значения обязательно используется `return`; при отсутствии
`return` по умолчанию возвращается `Void`. Выражение в форме `= expr` возвращает значение напрямую.

## Мотивация

### Зачем нужна эта возможность?

1. **Согласованность синтаксиса**: устранение исторического наследия старого синтаксиса, единый
   стиль.
2. **Краткость**: алгоритм HM автоматически выводит типы, сокращая шаблонный код.
3. **Безопасность типов**: алгоритм HM гарантирует безопасность типов, явные аннотации требуются
   только тогда, когда вывод невозможен.
4. **Зрелость языка**: алгоритм HM — зрелое решение, принятое в современных функциональных языках.

### Единая модель синтаксиса

**Ключевой принцип**: `name: Signature = LambdaBody`

- **Полная форма**: сигнатура (включая имена параметров + типы + `->` + тип возврата) +
  lambda-заголовок (включая имена параметров).
- **Правила сокращения**: опускайте всё, что не создаёт неоднозначности.
  - `->` не может быть опущен (это маркер функционального типа, иначе выражение будет разобрано как
    кортеж).
  - **При наличии входных параметров** их типы должны быть явно указаны хотя бы в одном месте — в
    сигнатуре или в lambda-заголовке.
  - Lambda-заголовок может быть опущен → если имена и типы параметров уже объявлены в сигнатуре.
  - Тип возврата может быть указан явно или опущен, если он выводим.

```yaoxiang
# Полная форма (сигнатура полностью + lambda-заголовок полностью)
add: (a: Int, b: Int) -> Int = (a, b) => a + b

# Сокращение: опущен lambda-заголовок (параметры объявлены в сигнатуре)
add: (a: Int, b: Int) -> Int = a + b

# Сокращение: опущена сигнатура (типы параметров указаны в lambda-заголовке)
add = (a: Int, b: Int) => a + b

# ❌ Ошибка: типы параметров не указаны ни в одном из мест
# add = (a, b) => a + b
```

### Цели проектирования

```yaoxiang
# === Полная форма ===
add: (a: Int, b: Int) -> Int = (a, b) => { a + b }

# === Сокращённые формы ===
add: (a: Int, b: Int) -> Int = a + b                 # опущен lambda-заголовок
add = (a: Int, b: Int) => a + b                      # опущена сигнатура

# === Функция без параметров ===
main: () -> Void = () => { println("Hello") }          # полная форма
main: () -> Void = { println("Hello") }                # опущен lambda-заголовок
main = { println("Hello") }                            # минимальная форма (выводится как () -> Void)

# === Обобщённая функция (использует единый синтаксис RFC-010) ===
identity: (T: Type) -> ((x: T) -> T) = (x) => x         # полная форма
identity: (T: Type) -> ((x: T) -> T) = x                # опущен lambda-заголовок
identity = (x: T) => x                                  # опущена сигнатура (типы указаны в lambda-заголовке)

# === Рекурсивная функция ===
factorial: (n: Int) -> Int = (n) => {
    if n <= 1 { return 1 } else { return n * factorial(n - 1) }
}
```

### Правила синтаксиса

| Сценарий                        | Синтаксис                                              | Пояснение                               |
| ------------------------------- | ------------------------------------------------------ | --------------------------------------- |
| **Полная форма**                | `name: (a: Type, b) -> Ret = (a, b) => { return ... }` | сигнатура + lambda-заголовок полностью  |
| **Опущен lambda-заголовок**     | `name: (a: Type, b: Type) -> Ret = { ... }`            | параметры объявлены в сигнатуре         |
| **Опущена сигнатура**           | `name = (a: Type, b: Type) => { ... }`                 | типы параметров в lambda-заголовке      |
| **Полная форма без параметров** | `name: () -> Void = () => { return ... }`              | полная форма для функции без параметров |
| **Сокращение без параметров**   | `name: () -> Void = { return ... }`                    | опущен lambda-заголовок                 |
| **Минимальная без параметров**  | `name = { return ... }`                                | максимально краткая форма               |

**Примечание**: внутри блока кода `{ ... }` для возврата значения обязательно используется `return`;
при отсутствии `return` по умолчанию возвращается `Void`. Выражение в форме `= expr` возвращает
значение напрямую.

**Примечание**: `->` — маркер функционального типа, его нельзя опускать (иначе выражение будет
разобрано как кортеж).

**Важно**: выражение `if` использует фигурные скобки `{}` для обрамления ветвей, ключевые слова
`then/else` не поддерживаются:

```yaoxiang
# Корректно: используются фигурные скобки
if n <= 1 { return 1 } else { return n * factorial(n - 1) }

# Ошибка: ключевые слова then/else не поддерживаются
# if n <= 1 then return 1 else return n * factorial(n - 1)
```

## Предложение

### Поддержка алгоритма HM и полиморфизма высшего ранга

**Ключевая возможность**: алгоритм HM поддерживает полиморфизм высшего ранга (Higher-rank
polymorphism) посредством аннотаций обобщённых типов.

**Принципы проектирования**:

- **Функции высшего порядка**: при передаче функции в качестве аргумента необходимы обобщённые
  ограничения для её функционального типа.
- **Формат аннотации типов**: `(T: Type) -> ((f: (T) -> T, x: T) -> T)` — обобщённый параметр
  ограничивает функциональный тип.
- **Работа HM**: вывод функционального типа через инстанциацию обобщений, обеспечивающий композицию
  полиморфных функций.

**Примеры**:

```yaoxiang
# ✅ Поддержка полиморфизма высшего ранга: обобщённое ограничение для функционального аргумента
call_twice: (T: Type) -> ((f: (T) -> T, x: T) -> T) = {
    return f(f(x))
}
# Использование: call_twice((x) => x + 1, 5)  # выводится T=Int

compose: (A: Type, B: Type, C: Type) -> ((f: (B) -> C, g: (A) -> B, x: A) -> C) = {
    return f(g(x))
}
# Использование: compose((x) => x * 2, (x) => x + 1, 5)  # выводится A=Int, B=Int, C=Int

# ❌ Не поддерживается: функция высшего порядка без обобщённого ограничения
# bad_hof: (f, x) => f(f(x))  # HM не может вывести тип, отсутствует обобщённый параметр
```

**Процесс вывода HM**:

1. Распознавание параметра функции высшего порядка: `f: (T) -> T`.
2. Создание обобщённого ограничения: `(T: Type)`.
3. Вывод конкретных типов через инстанциацию обобщений.
4. Реализация композиции полиморфных функций.

### Правила синтаксиса lambda-выражений

**Важное правило**: внутри блока кода `{ ... }` для возврата значения обязательно используется
`return`; при отсутствии `return` по умолчанию возвращается `Void`. Выражение в форме `= expr`
возвращает значение напрямую.

| Форма синтаксиса  | Синтаксис        | Способ возврата                                      |
| ----------------- | ---------------- | ---------------------------------------------------- |
| **Блочная форма** | `{ statements }` | требуется `return`; без `return` по умолчанию `Void` |
| **Выражение**     | `expression`     | значение выражения возвращается напрямую             |

**Примеры**:

```yaoxiang
main: () -> Void = { println("Hello") }         # возвращает Void (без return)
add: (a: Int, b: Int) -> Int = { return a + b }  # возвращает Int (явный return)
empty: () -> Void = {}                          # пустой блок по умолчанию возвращает Void

# Досрочный возврат: используйте return
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)
}

# Форма выражения: значение возвращается напрямую (без return)
add: (a: Int, b: Int) -> Int = a + b            # корректно: форма выражения
main: () -> Void = println("Hello")               # корректно: форма выражения
```

**Ключевые идеи**:

1. Определения функций используют алгоритм HM для вывода типов — максимальный вывод, явная ошибка,
   если вывод невозможен.
2. **Принцип работы алгоритма HM**: автоматический вывод типов на основе контекстной информации —
   ограничений типов операторов, отношений вызовов функций и т. д.
3. **Поддержка обобщений**: полиморфные функции используют синтаксис `(T: Type)` для явного
   ограничения параметров типа (RFC-010/011).
4. **Границы вывода**: тип возврата и локальные переменные выводимы; типы параметров функций с
   аргументами требуют явного указания (в сигнатуре или в lambda-заголовке).
5. Функции без параметров и без возврата используют форму `name: () -> Void = { ... }`, согласовано
   с RFC-010.
6. Старый синтаксис выводится из употребления, предоставляется инструмент миграции.

**Примеры вывода типов**:

```yaoxiang
# Обобщённая функция: явные параметры типа (использует единый синтаксис RFC-010)
identity: (T: Type) -> ((x: T) -> T) = x
map: (T: Type, R: Type) -> ((f: (T) -> R, list: List(T)) -> List(R)) = {
    result = List(R)()
    for item in list { result.push(f(item)) }
    return result
}

# Полиморфная функция: определяется через явные обобщённые ограничения (RFC-010/011)
add: (T: Add) -> ((a: T, b: T) -> T) = a + b
print_sum: (a: Int, b: Int) -> Void = { println(a + b) }  # выводится как (Int, Int) -> Void

# Полиморфизм высшего ранга: реализуется через обобщённые аннотации типов
call_twice: (T: Type) -> ((f: (T) -> T, x: T) -> T) = { return f(f(x)) }
compose: (A: Type, B: Type, C: Type) -> ((f: (B) -> C, g: (A) -> B, x: A) -> C) = { return f(g(x)) }
```

```yaoxiang
# === Определение функций: вывод типов алгоритмом HM ===

# Стандартная функция: алгоритм HM выводит тип возврата (типы параметров заданы явно)
add = (a: Int, b: Int) => a + b            # выводится как (a: Int, b: Int) -> Int
main = { println("Hello") }                # выводится как () -> Void

# Частично явные параметры: алгоритм HM выводит оставшиеся
print_sum: (a: Int, b: Int) -> Void = { println(a + b) }  # выводится как (Int, Int) -> Void
greet: (name: String) -> Void = { println("Hello " + name) }  # выводится как (String) -> Void

# Обобщённая функция: явное ограничение полиморфных параметров типа (использует единый синтаксис RFC-010)
identity: (T: Type) -> ((x: T) -> T) = x
map: (T: Type, R: Type) -> ((f: (T) -> R, list: List(T)) -> List(R)) = {
    # реализация функции map
    return List(R)()
}

# Рекурсивная функция: вывод через алгоритм HM и рекурсивные ограничения
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 } else { return n * factorial(n - 1) }
}

# === Присваивание переменных: вывод типов алгоритмом HM ===

# Явный тип
x: Int = 42

# Алгоритм HM автоматически выводит Int
y = 42                               # выводится как Int

# Алгоритм HM автоматически выводит String
name = "YaoXiang"                    # выводится как String

# Алгоритм HM автоматически выводит Float
pi = 3.14159                         # выводится как Float
```

**Правила вывода типов HM**:

| Сценарий                       | Синтаксис                                         | Что можно опустить | Пример                                 |
| ------------------------------ | ------------------------------------------------- | ------------------ | -------------------------------------- |
| **Полная форма**               | `name: (a: Type, b: Type) -> Ret = (a, b) => ...` | ничего             | сигнатура + lambda-заголовок полностью |
| **Опущен lambda-заголовок**    | `name: (a: Type, b: Type) -> Ret = ...`           | lambda-заголовок   | параметры объявлены в сигнатуре        |
| **Опущена сигнатура**          | `name = (a: Type, b: Type) => ...`                | сигнатура          | типы параметров в lambda-заголовке     |
| **Опущен тип возврата Ret**    | `name: (a: Type, b: Type) -> = ...`               | тип возврата       | HM выводит тип возврата                |
| **Полная без параметров**      | `name: () -> Void = () => { ... }`                | ничего             | полная форма без параметров            |
| **Сокращение без параметров**  | `name: () -> Void = { ... }`                      | lambda-заголовок   | опущено `() =>`                        |
| **Минимальная без параметров** | `name = { ... }`                                  | всё                | максимально краткая форма              |
| **Присваивание переменной**    | `name = value`                                    | тип                | HM выводит тип                         |
| **Явная переменная**           | `name: Type = value`                              | ничего             | явная аннотация типа                   |

**Ключевые принципы**:

- `->` — маркер функционального типа, его нельзя опускать (иначе выражение будет разобрано как
  кортеж).
- Тип возврата `Ret` можно опустить, HM выведёт его из тела функции.
- При наличии входных параметров их типы должны быть указаны явно (хотя бы в одном из мест — в
  сигнатуре или в lambda-заголовке).
- Остальные части можно опускать, если они выводимы и не создают неоднозначности.
- Никаких неявных преобразований типов — никакого хаоса в стиле JavaScript.

## Подробное проектирование

### Раскрытие синтаксического сахара

Независимо от сокращений, в итоге всё нормализуется к единому промежуточному представлению:

```rust
// Полная форма
add: (a: Int, b: Int) -> Int = (a, b) => a + b

// Развёрнутое IR
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    return a + b
};

// Опущен lambda-заголовок
add: (a: Int, b: Int) -> Int = a + b

// Развёрнутое IR (идентично полной форме)
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    return a + b
};

// Опущена сигнатура (типы параметров в lambda-заголовке)
add = (a: Int, b: Int) => a + b

// Развёрнутое IR
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    a + b
};
```

### Определение синтаксиса

```bnf
function_def ::= identifier ':' type_expr '=' expression
               | identifier '=' expression
               | identifier '=' block                    # минимальная форма: без параметров и без возврата

identifier ::= [a-zA-Z_][a-zA-Z0-9_]*

type_expr ::= identifier                     # ссылка на тип
       | '()'                          # пустой тип
       | '(' parameters ')' '->' type_expr   # функциональный тип (имена параметров в сигнатуре)
       | type_expr '->' type_expr            # простой функциональный тип
       | identifier '(' type_expr (',' type_expr)* ')'  # применение типа

expression ::= '(' parameters ')' '=>' block
             | '(' ')' '=>' block
             | '(' parameters ')' '=>' expression

parameters ::= parameter (',' parameter)*
parameter ::= identifier                # вывод типа
            | identifier ':' type_expr      # частично явный тип

block ::= '{' statement (',' statement)* '}'
        | expression

statement ::= identifier ':' expression  # оператор присваивания
           | expression                  # выражение-оператор (выполняется, но не возвращается)
           | 'return' expression         # оператор возврата (возвращает указанное значение)

# Примечание: внутри блока для возврата значения обязателен return; без return по умолчанию возвращается Void.
# Например: { return 1 + 1 } возвращает Int; { println("Hello") } возвращает Void.
# Примечание: обобщённые параметры используют синтаксис (T: Type) как часть функционального типа,
# отдельное правило BNF не требуется.
```

### Обработка ошибок

```yaoxiang
# === Примеры ошибок компиляции ===

# Ошибка 1: несоответствие типа возврата блока
add: (a: Int, b: Int) -> Int = { println(a + b) }
// Ошибка: в блоке нет return, по умолчанию возвращается Void, но сигнатура ожидает Int
// Корректно: add: (a: Int, b: Int) -> Int = a + b
// Или:     add: (a: Int, b: Int) -> Int = { return a + b }

# Ошибка 2: использование необъявленного параметра типа
identity: (x: T) -> T = x
// Ошибка: T не объявлен; требуется явный обобщённый параметр (RFC-010)
// Корректно: identity: (T: Type) -> ((x: T) -> T) = x

# Корректно: алгоритм HM выводит тип возврата
double = (x: Int) => x + x

# Полная форма (пошаговое сокращение)
double: (x: Int) -> Int = (x) => x + x                # полная форма
double: (x: Int) -> Int = x + x                       # опущен lambda-заголовок
double = (x: Int) => x + x                            # опущен тип возврата (HM выводит)
# double = (x) => x + x                               # ❌ типы параметров нельзя опускать в обоих местах
```

## Компромиссы

### Достоинства

- **Единый синтаксис**: модель `name: Signature = LambdaBody` покрывает все сценарии.
- **Гибкие сокращения**: любые части могут быть опущены, если они выводимы алгоритмом HM.
- **Безопасность типов**: алгоритм HM гарантирует типобезопасность, избегая неявных преобразований.
- **Поддержка рекурсии**: алгоритм HM и рекурсивные ограничения автоматически выводят типы.
- **Плавный переход**: от полной формы к минимальной — без скачков.

### Недостатки

- **Затраты на миграцию**: старый код требует конвертации инструментом миграции.
- **Затраты на обучение**: необходимо понять модель «полная форма + произвольные сокращения».

| Обязательное объявление типов | Все типы должны быть записаны явно                 | Нарушает принцип краткости, увеличивает шаблонный код      |
| Сохранение старого синтаксиса | Параллельная поддержка старого и нового синтаксиса | Раскол синтаксиса, высокая стоимость сопровождения         |
| Ключевое слово `fn`           | Введение `fn` для отделения функций от переменных  | Нарушает принцип «функция — это lambda»                    |

## Стратегия реализации

### Этапы

1. **Фаза 1: синтаксический разбор и алгоритм HM** (v0.3)
   - Реализация нового синтаксиса `name = lambda` + вывод типов алгоритмом HM.
   - Реализация заполнения по умолчанию для функций без параметров и без возврата.

2. **Фаза 2: инструмент миграции** (v0.3)
   - Разработка инструмента `yaoxiang-migrate --old-to-new`.
   - Автоматическая конвертация кода на старом синтаксисе.

3. **Фаза 3: проверка и документация** (v0.3)
   - Проверка завершённости миграции старого кода.
   - Обновление документации.

### Инструмент миграции

```bash
# Миграция одного файла
yaoxiang-migrate --old-to-new src/main.yaoxiang

# Миграция всего проекта
yaoxiang-migrate --old-to-new --recursive src/

# Предпросмотр миграции (без изменения файлов)
yaoxiang-migrate --old-to-new --dry-run src/main.yaoxiang
```

Правила миграции:

```yaoxiang
# Старый синтаксис
add(Int, Int) -> Int = (a, b) => { a + b }
main() -> Int = { println("Hello"); 0 }
main() = { println("Hello") }

# === Новый синтаксис: полная форма (сигнатура полностью + lambda-заголовок полностью) ===
add: (a: Int, b: Int) -> Int = (a, b) => a + b
main: () -> Void = () => { println("Hello") }

# === Сокращение: опущен lambda-заголовок ===
add: (a: Int, b: Int) -> Int = a + b
main: () -> Void = { println("Hello") }

# === Сокращение: вывод HM ===
add = (a: Int, b: Int) => a + b              # выводится как (a: Int, b: Int) -> Int
main = { println("Hello") }                  # выводится как () -> Void

# === Минимальная форма ===
main = {                                      # эквивалентно main: () -> Void = { ... }
    println("Hello")
}
```

### Зависимости

- Нет внешних зависимостей.
- Может быть реализовано независимо.

### Риски

| Риск             | Воздействие                            | Смягчение                                                                    |
| ---------------- | -------------------------------------- | ---------------------------------------------------------------------------- |
| Пропуск миграции | Старый код не компилируется            | Предоставить инструмент миграции, покрывающий все шаблоны старого синтаксиса |
| Ошибки парсера   | Нестабильность синтаксического разбора | Достаточное тестовое покрытие                                                |

## Открытые вопросы

> Следующие вопросы уже решены в проектировании и зафиксированы в Приложении A.

- ~~В1: Следует ли сохранить предельно краткую форму `main() = body`?~~ → Решено: сохранено в виде
  `main = { ... }`.
- ~~В2: Сохранять ли `:` после имени функции?~~ → Решено: сохранение опционально; однако для функций
  с параметрами типы параметров по-прежнему должны быть указаны в сигнатуре или в lambda-заголовке.
- ~~В3: Поддерживает ли алгоритм HM вывод типов параметров?~~ → Решено: тип возврата / локальные
  переменные выводимы; типы параметров функций с аргументами требуют явного указания.
- ~~В4: Вводить ли ключевое слово `fn`?~~ → Решено: не вводится, функция — это lambda.
- ~~В5: Какова стратегия миграции старого кода?~~ → Решено: предоставляется инструмент
  `yaoxiang-migrate`.
- ~~В6: Как использовать обобщённые функции?~~ → Решено: используется единый синтаксис RFC-010
  `(T: Type)`.

## Приложения

### Приложение A: Справка по синтаксису определения функций в различных языках

| Язык         | Стиль синтаксиса                                    | Особенности                              |
| ------------ | --------------------------------------------------- | ---------------------------------------- |
| Rust         | `fn add(a: i32, b: i32) -> i32 { ... }`             | ключевое слово + аннотация типов         |
| Haskell      | `add a b = ...` / `add :: Int -> Int -> Int`        | сигнатура типа отделена                  |
| OCaml        | `let add a b = ...`                                 | типы параметров можно опускать           |
| MoonBit      | `fn add(a: Int, b: Int): Int { ... }`               | компактная аннотация типов               |
| TypeScript   | `const add = (a: number, b: number): number => ...` | стиль lambda                             |
| Scala        | `def add(a: Int, b: Int): Int = { ... }`            | ключевое слово `def`                     |
| **YaoXiang** | `name = (a: Int, b: Int) => a + b`                  | **функция = lambda, HM выводит возврат** |

### Приложение C: Глоссарий

| Термин                       | Определение                                                                                                                                  |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Алгоритм HM                  | Алгоритм вывода типов Хиндли-Милнера, автоматически выводит типы функций и переменных                                                        |
