# RFC-007: Унификация синтаксиса определения функций

> **Исправление (2026-09-15, RFC-010a)**: Ранее в документе утверждалось, что «внутри блока кода для
> возврата значения необходимо использовать `return`, а без `return` по умолчанию возвращается
> `Void`». Это утверждение отменено — **значение блока = хвостовое выражение**, а `return` — это
> нелокальный выход типа `Never`. Подробности см. в
> [RFC-010a](./010a-tail-expression-and-return.md). Формальное определение функций в данном
> документе (полная форма / с опущенной lambda-головой / с опущенной сигнатурой / с пустыми
> параметрами) **остаётся без изменений**, а семантика «досрочного возврата» изначально согласована
> с данным RFC.
>
> **Дополнение (решение C)**: «Кратчайшая форма без параметров» `name = { ... }` из данного
> документа пересекается по синтаксической позиции с «блоком со значением» из RFC-010. Принято
> решение — **приоритет у аннотации, по умолчанию функция**: при отсутствии аннотации «кратчайшая
> форма без параметров» из данного документа считается функцией; блок-как-значение возникает только
> при аннотации не-Fn (например, `x: Int = { ... }`). См. приложение D в RFC-010a.

> **Связанное дополнение**: Правила завершения операторов и переноса строк внутри тела функции (блок
> `{ ... }`) — явное разделение `;`, завершение переносом строки, исключения для продолжения строки
> — определены в [RFC-038 (черновик)](../draft/038-statement-termination.md) и в данный RFC не
> входят.

## Резюме

Данный RFC устанавливает окончательный方案 синтаксиса **определения функций** языка YaoXiang.
Используется единый синтаксис `name: (params) -> Return = body`, полностью согласующийся с моделью
`name: type = value` из RFC-010.

Во избежание неоднозначности: при наличии входных параметров их типы должны быть явно указаны как
минимум в одном из мест — в «сигнатуре» или в «lambda-голове»; если опущены в обоих — будет отказано
в компиляции.

Значение блока кода `{ ... }` определяется **хвостовым выражением**; `return` — это нелокальный
выход типа `Never` (см. [RFC-010a](./010a-tail-expression-and-return.md)). Форма выражения `= expr`
непосредственно задаёт значение.

## Мотивация

### Зачем нужна эта возможность?

1. **Синтаксическая согласованность**: устранение наследия старого синтаксиса, унификация стиля
2. **Краткость**: алгоритм HM автоматически выводит типы, сокращая шаблонный код
3. **Безопасность типов**: алгоритм HM гарантирует безопасность типов; явное указание требуется
   только тогда, когда вывод невозможен
4. **Зрелость языка**: алгоритм HM — зрелое решение современных функциональных языков

### Унифицированная синтаксическая модель

**Ключевой принцип**: `name: Signature = LambdaBody`

- **Полная форма**: сигнатура (имя параметра + тип + `->` + тип возврата) + lambda-голова (с именами
  параметров)
- **Правила сокращения**: опускать везде, где это не вносит неоднозначности
  - `->` нельзя опускать (признак типа функции, иначе будет разобрано как кортеж)
  - **При наличии входных параметров** их типы должны быть явно указаны как минимум в одном месте: в
    сигнатуре или в lambda-голове
  - Lambda-голову можно опустить → если сигнатура уже объявляет имена и типы параметров
  - Тип возврата можно указать явно, либо опустить, если он выводим

```yaoxiang
# Полная форма (полная сигнатура + полная lambda-голова)
add: (a: Int, b: Int) -> Int = (a, b) => a + b

# Сокращение: опущена lambda-голова (параметры объявлены в сигнатуре)
add: (a: Int, b: Int) -> Int = a + b

# Сокращение: опущена сигнатура (типы параметров в lambda-голове)
add = (a: Int, b: Int) => a + b

# ❌ Ошибка: типы параметров не указаны ни в одном месте
# add = (a, b) => a + b
```

### Цели проектирования

```yaoxiang
# === Полная форма ===
add: (a: Int, b: Int) -> Int = (a, b) => { a + b }

# === Сокращённые формы ===
add: (a: Int, b: Int) -> Int = a + b                 # Опущена lambda-голова
add = (a: Int, b: Int) => a + b                      # Опущена сигнатура

# === Функции без параметров ===
main: () -> Void = () => { println("Hello") }          # Полная форма
main: () -> Void = { println("Hello") }                # Опущена lambda-голова
main: () -> Void = { println("Hello") }                            # Кратчайшая форма (выводится как () -> Void)

# === Обобщённые функции (с использованием единого синтаксиса RFC-010) ===
identity: (T: Type) -> ((x: T) -> T) = (x) => x         # Полная форма
identity: (T: Type) -> ((x: T) -> T) = x                # Опущена lambda-голова
identity = (x: T) => x                                  # Опущена сигнатура (типы в lambda-голове)

# === Рекурсивные функции ===
factorial: (n: Int) -> Int = (n) => {
    if n <= 1 { return 1 } else { return n * factorial(n - 1) }
}
```

### Правила синтаксиса

| Сценарий                        | Синтаксис                                              | Пояснение                                      |
| ------------------------------- | ------------------------------------------------------ | ---------------------------------------------- |
| **Полная форма**                | `name: (a: Type, b) -> Ret = (a, b) => { return ... }` | Полная сигнатура + полная lambda-голова        |
| **Опущена lambda-голова**       | `name: (a: Type, b: Type) -> Ret = { ... }`            | Параметры объявлены в сигнатуре                |
| **Опущена сигнатура**           | `name = (a: Type, b: Type) => { ... }`                 | Типы параметров в lambda-голове                |
| **Без параметров, полная**      | `name: () -> Void = () => { return ... }`              | Полная форма функции без параметров            |
| **Без параметров, сокращённая** | `name: () -> Void = { return ... }`                    | Опущена lambda-голова                          |
| **Без параметров, кратчайшая**  | `name = { return ... }`                                | Кратчайшая форма без параметров и без возврата |

**Внимание**: значение блока кода `{ ... }` определяется **хвостовым выражением** (единственный
выход); `return` — это нелокальный выход типа `Never`, выходящий за ближайшую границу функции. Форма
выражения `= expr` непосредственно задаёт значение. Подробности см. в
[RFC-010a](./010a-tail-expression-and-return.md).

**Внимание**: `->` — признак типа функции, его нельзя опускать (иначе будет разобрано как кортеж).

**Важно**: выражение `if` использует фигурные скобки `{}` для обрамления ветвей; ключевые слова
`then/else` не поддерживаются:

```yaoxiang
# Правильно: использование фигурных скобок
if n <= 1 { return 1 } else { return n * factorial(n - 1) }

# Ошибка: ключевые слова then/else не поддерживаются
# if n <= 1 then return 1 else return n * factorial(n - 1)
```

## Предложение

### Алгоритм HM и поддержка полиморфизма высшего ранга

**Ключевая особенность**: алгоритм HM через аннотации обобщённых типов поддерживает полиморфизм
высшего ранга (Higher-rank polymorphism).

**Принцип проектирования**:

- **Функции высшего порядка**: при передаче функции в качестве аргумента необходимы generics для
  ограничения функционального типа
- **Форма аннотации типов**: `(T: Type) -> ((f: (T) -> T, x: T) -> T)` — параметр типа ограничивает
  функциональный тип
- **Рабочий процесс HM**: вывод функциональных типов через обобщённые параметры, реализация
  композиции полиморфных функций

**Примеры**:

```yaoxiang
# ✅ Поддержка полиморфизма высшего ранга: обобщённое ограничение функционального аргумента
call_twice: (T: Type) -> ((f: (T) -> T, x: T) -> T) = {
    return f(f(x))
}
# Использование: call_twice((x) => x + 1, 5)  # Вывод T=Int

compose: (A: Type, B: Type, C: Type) -> ((f: (B) -> C, g: (A) -> B, x: A) -> C) = {
    return f(g(x))
}
# Использование: compose((x) => x * 2, (x) => x + 1, 5)  # Вывод A=Int, B=Int, C=Int

# ❌ Не поддерживается: функция высшего порядка без обобщённого ограничения
# bad_hof: (f, x) => f(f(x))  # HM не может выполнить вывод, отсутствует обобщённый параметр
```

**Процесс вывода HM**:

1. Распознавание аргументов функций высшего порядка: `f: (T) -> T`
2. Создание обобщённого ограничения: `(T: Type)`
3. Вывод конкретных типов через инстанциацию обобщений
4. Реализация композиции полиморфных функций

### Правила синтаксиса лямбда-выражений

**Важное правило**: значение блока кода `{ ... }` определяется **хвостовым выражением**
(единственный выход); `return` — это нелокальный выход типа `Never`, выходящий за ближайшую границу
функции. Форма выражения `= expr` непосредственно задаёт значение. Подробности см. в
[RFC-010a](./010a-tail-expression-and-return.md).

| Синтаксическая форма | Синтаксис        | Выход значения                                  |
| -------------------- | ---------------- | ----------------------------------------------- |
| **Блочная форма**    | `{ statements }` | Хвостовое выражение (пустой блок `{}` — `Void`) |
| **Форма выражения**  | `expression`     | Значение выражения                              |
| **`return`**         | `return e`       | Нелокальный выход из функции, тип `Never`       |

**Примеры**:

```yaoxiang
main: () -> Void = { println("Hello") }         # Хвостовое выражение имеет тип Void
add: (a: Int, b: Int) -> Int = { a + b }        # Значение даётся хвостовым выражением
empty: () -> Void = {}                          # Пустой блок → Void

# Досрочный возврат: использование return
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)
}

# Форма выражения: значение задаётся непосредственно
add: (a: Int, b: Int) -> Int = a + b            # Правильно: форма выражения
main: () -> Void = println("Hello")               # Правильно: форма выражения
```

**Основные идеи**:

1. Определение функций использует алгоритм HM для вывода типов, максимально полный вывод, явная
   ошибка при невозможности вывода
2. **Принцип работы алгоритма HM**: автоматический вывод типов на основе контекстной информации —
   ограничений типов операторов, отношений вызова функций и т. д.
3. **Поддержка обобщений**: полиморфные функции используют синтаксис generics `(T: Type)` для явного
   ограничения параметров типа (RFC-010/011)
4. **Границы вывода**: тип возврата и локальные переменные выводимы; типы параметров функций с
   аргументами должны быть указаны явно (в сигнатуре или в lambda-голове)
5. Функции без параметров и без возврата используют форму `name: () -> Void = { ... }`, согласовано
   с RFC-010
6. Старый синтаксис выводится из употребления, предоставляются инструменты миграции

**Примеры вывода типов**:

```yaoxiang
# Обобщённая функция: явные параметры типа (с использованием единого синтаксиса RFC-010)
identity: (T: Type) -> ((x: T) -> T) = x
map: (T: Type, R: Type) -> ((f: (T) -> R, list: List(T)) -> List(R)) = {
    result = List(R)()
    for item in list { result.push(f(item)) }
    return result
}

# Полиморфная функция: определяется через явные обобщённые ограничения (RFC-010/011)
add: (T: Add) -> ((a: T, b: T) -> T) = a + b
print_sum: (a: Int, b: Int) -> Void = { println(a + b) }  # Выводится как (Int, Int) -> Void

# Полиморфизм высшего ранга: реализуется через аннотации обобщённых типов для поддержки HM
call_twice: (T: Type) -> ((f: (T) -> T, x: T) -> T) = { return f(f(x)) }
compose: (A: Type, B: Type, C: Type) -> ((f: (B) -> C, g: (A) -> B, x: A) -> C) = { return f(g(x)) }
```

```yaoxiang
# === Определение функций: вывод типов алгоритмом HM ===

# Стандартная функция: HM выводит тип возврата (типы параметров должны быть явными)
add = (a: Int, b: Int) => a + b            # Выводится как (a: Int, b: Int) -> Int
main: () -> Void = { println("Hello") }                # Выводится как () -> Void

# Частично явные параметры: HM выводит остальное
print_sum: (a: Int, b: Int) -> Void = { println(a + b) }  # Выводится как (Int, Int) -> Void
greet: (name: String) -> Void = { println("Hello " + name) }  # Выводится как (String) -> Void

# Обобщённая функция: явное ограничение полиморфных параметров типа (RFC-010/011)
identity: (T: Type) -> ((x: T) -> T) = x
map: (T: Type, R: Type) -> ((f: (T) -> R, list: List(T)) -> List(R)) = {
    # Реализация функции map
    return List(R)()
}

# Рекурсивная функция: вывод через алгоритм HM и рекурсивные ограничения
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 } else { return n * factorial(n - 1) }
}

# === Присваивание переменных: вывод типов алгоритмом HM ===

# Явный тип
x: Int = 42

# HM автоматически выводит Int
y = 42                               # Выводится как Int

# HM автоматически выводит String
name = "YaoXiang"                    # Выводится как String

# HM автоматически выводит Float
pi = 3.14159                         # Выводится как Float
```

**Правила вывода типов HM**:

| Сценарий                        | Синтаксис                                         | Что можно опустить | Пример                                         |
| ------------------------------- | ------------------------------------------------- | ------------------ | ---------------------------------------------- |
| **Полная форма**                | `name: (a: Type, b: Type) -> Ret = (a, b) => ...` | Ничего             | Полная сигнатура + полная lambda-голова        |
| **Опущена lambda-голова**       | `name: (a: Type, b: Type) -> Ret = ...`           | Lambda-голова      | Параметры объявлены в сигнатуре                |
| **Опущена сигнатура**           | `name = (a: Type, b: Type) => ...`                | Сигнатура          | Типы параметров в lambda-голове                |
| **Опущен тип возврата Ret**     | `name: (a: Type, b: Type) -> = ...`               | Тип возврата       | HM выводит тип возврата                        |
| **Без параметров, полная**      | `name: () -> Void = () => { ... }`                | Ничего             | Полная форма функции без параметров            |
| **Без параметров, сокращённая** | `name: () -> Void = { ... }`                      | Lambda-голова      | Опущено `() =>`                                |
| **Без параметров, кратчайшая**  | `name = { ... }`                                  | Всё                | Кратчайшая форма без параметров и без возврата |
| **Присваивание переменной**     | `name = value`                                    | Тип                | HM выводит тип                                 |
| **Явная переменная**            | `name: Type = value`                              | Ничего             | Явная аннотация типа                           |

**Ключевые принципы**:

- `->` — признак типа функции, не может быть опущен (иначе будет разобрано как кортеж)
- Тип возврата `Ret` может быть опущен, HM выводит его по телу функции
- При наличии входных параметров их типы должны быть указаны явно (в сигнатуре или в lambda-голове)
- Остальные части можно опускать, если они выводимы и это не вносит неоднозначности
- Неявные преобразования типов отсутствуют, что предотвращает хаос в стиле JavaScript

## Детальное проектирование

### Раскрытие синтаксического сахара

Независимо от степени сокращения, итоговая нормализация приводит к единому промежуточному
представлению:

```rust
// Полная форма
add: (a: Int, b: Int) -> Int = (a, b) => a + b

// Раскрытие в IR
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    return a + b
};

// Опущена lambda-голова
add: (a: Int, b: Int) -> Int = a + b

// Раскрытие в IR (идентично полной форме)
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    return a + b
};

// Опущена сигнатура (типы параметров в lambda-голове)
add = (a: Int, b: Int) => a + b

// Раскрытие в IR
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    a + b
};
```

### Определение синтаксиса

```bnf
function_def ::= identifier ':' type_expr '=' expression
               | identifier '=' expression
               | identifier '=' block                    # Кратчайшая форма: без параметров и без возврата

identifier ::= [a-zA-Z_][a-zA-Z0-9_]*

type_expr ::= identifier                     # Ссылка на тип
       | '()'                          # Пустой тип
       | '(' parameters ')' '->' type_expr   # Тип функции (имена параметров в сигнатуре)
       | type_expr '->' type_expr            # Простой тип функции
       | identifier '(' type_expr (',' type_expr)* ')'  # Применение типа

expression ::= '(' parameters ')' '=>' block
             | '(' ')' '=>' block
             | '(' parameters ')' '=>' expression

parameters ::= parameter (',' parameter)*
parameter ::= identifier                # Вывод типа
            | identifier ':' type_expr      # Частично явный тип

block ::= '{' statement (',' statement)* '}'
        | expression

statement ::= identifier ':' expression  # Оператор присваивания
           | expression                  # Оператор-выражение (выполняется, но не возвращается)
           | 'return' expression         # Оператор возврата (возвращает указанное значение)

# Внимание: внутри блока кода для возврата значения необходимо использовать return; без return по умолчанию возвращается Void
# Например: { return 1 + 1 } возвращает Int; { println("Hello") } возвращает Void
# Внимание: обобщённые параметры используют синтаксис (T: Type) как часть типа функции, отдельное правило BNF не требуется
```

### Обработка ошибок

```yaoxiang
# === Примеры ошибок компиляции ===

# Ошибка 1: несоответствие типа возврата блока кода
add: (a: Int, b: Int) -> Int = { println(a + b) }
// Ошибка: в блоке нет return, по умолчанию возвращается Void, но сигнатура ожидает Int
// Правильно: add: (a: Int, b: Int) -> Int = a + b
// Или: add: (a: Int, b: Int) -> Int = { return a + b }

# Ошибка 2: использование необъявленного параметра типа
identity: (x: T) -> T = x
// Ошибка: T не объявлен; требуется явный обобщённый параметр (RFC-010)
// Правильно: identity: (T: Type) -> ((x: T) -> T) = x

# Правильно: алгоритм HM выводит тип возврата
double = (x: Int) => x + x

# Полная форма (с пошаговым сокращением)
double: (x: Int) -> Int = (x) => x + x                # Полная
double: (x: Int) -> Int = x + x                       # Опущена lambda-голова
double = (x: Int) => x + x                            # Опущен тип возврата (HM выводит)
# double = (x) => x + x                               # ❌ Типы параметров нельзя опускать в обоих местах
```

## Компромиссы

### Преимущества

- **Синтаксическая унификация**: модель `name: Signature = LambdaBody` покрывает все сценарии
- **Гибкие сокращения**: любые части можно опускать, когда они выводимы через HM
- **Безопасность типов**: алгоритм HM гарантирует безопасность типов, предотвращая неявные
  преобразования
- **Поддержка рекурсии**: алгоритм HM и рекурсивные ограничения автоматически выводят типы
- **Отсутствие накладных расходов**: плавный переход от полной формы к кратчайшей

### Недостатки

- **Стоимость миграции**: старый код требует конвертации инструментами миграции
- **Стоимость обучения**: необходимо понимать модель «полная форма + произвольные сокращения»

## Альтернативы

| Решение                       | Описание                                                | Почему не выбрано                                                     |
| ----------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------- |
| Вывод типов алгоритмом HM     | Использование алгоритма Хиндли-Милнера для вывода типов | ✅ **Принято**, стандарт современных функциональных языков            |
| Явное объявление типов        | Все типы должны быть записаны явно                      | Противоречит принципу упрощения синтаксиса, увеличивает шаблонный код |
| Сохранение старого синтаксиса | Одновременная поддержка старого и нового синтаксиса     | Раскол синтаксиса, высокие затраты на сопровождение                   |
| Ключевое слово fn             | Введение fn для различения функций и переменных         | Противоречит дизайну «функция — это lambda»                           |

### Инструмент миграции

```bash
# Миграция одного файла
yaoxiang-migrate --old-to-new src/main.yaoxiang

# Миграция всего проекта
yaoxiang-migrate --old-to-new --recursive src/

# Предварительный просмотр миграции (без изменения файлов)
yaoxiang-migrate --old-to-new --dry-run src/main.yaoxiang
```

Правила миграции:

```yaoxiang
# Старый синтаксис
add(Int, Int) -> Int = (a, b) => { a + b }
main() -> Int = { println("Hello"); 0 }
main() = { println("Hello") }

# === Новый синтаксис: полная форма (полная сигнатура + полная lambda-голова) ===
add: (a: Int, b: Int) -> Int = (a, b) => a + b
main: () -> Void = () => { println("Hello") }

# === Сокращение: опущена lambda-голова ===
add: (a: Int, b: Int) -> Int = a + b
main: () -> Void = { println("Hello") }

# === Сокращение: вывод HM ===
add = (a: Int, b: Int) => a + b              # Выводится как (a: Int, b: Int) -> Int
main: () -> Void = { println("Hello") }                  # Выводится как () -> Void

# === Кратчайшая форма ===
main: () -> Void = {                                      # Эквивалентно main: () -> Void = { ... }
    println("Hello")
}
```

### Зависимости

- Внешних зависимостей нет
- Может быть реализовано независимо

### Риски

| Риск                  | Влияние                                | Меры по смягчению                                                                |
| --------------------- | -------------------------------------- | -------------------------------------------------------------------------------- |
| Пропуски при миграции | Сбой компиляции старого кода           | Предоставление инструмента миграции, покрывающего все шаблоны старого синтаксиса |
| Ошибки парсера        | Нестабильность синтаксического разбора | Полное покрытие тестами                                                          |

## Открытые вопросы

> Следующие вопросы решены в ходе проектирования, зафиксированы в приложении A.

- ~~В1: Следует ли сохранить максимально краткую запись `main() = body`?~~ → Решено: сохранено в
  виде `main: () -> Void = { ... }`
- ~~В2: Сохранять ли `:` после имени функции?~~ → Решено: необязательно; но для функций с
  параметрами по-прежнему необходимо указывать типы параметров в сигнатуре или в lambda-голове
- ~~В3: Поддерживает ли алгоритм HM вывод типов параметров?~~ → Решено: тип возврата/локальные
  переменные выводимы; для функций с параметрами требуется явное указание типов параметров
- ~~В4: Вводить ли ключевое слово `fn`?~~ → Решено: не вводится, функция — это lambda
- ~~В5: Какова стратегия миграции старого кода?~~ → Решено: предоставляется инструмент
  `yaoxiang-migrate`
- ~~В6: Как использовать обобщённые функции?~~ → Решено: используется единый синтаксис RFC-010
  `(T: Type)`
