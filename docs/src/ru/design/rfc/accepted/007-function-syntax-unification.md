# RFC-007: Унифицированный синтаксис определения функций

> **Исправление (2026-09-15, RFC-010a)**: В данном документе ранее утверждалось, что «внутри блока
> кода для возврата значения необходимо использовать `return`, а при отсутствии `return` по
> умолчанию возвращается `Void`». Это утверждение отменено — **значение блока = хвостовое
> выражение**, а `return` является нелокальным выходом типа `Never`. Подробности см. в
> [RFC-010a](./010a-tail-expression-and-return.md). Формальные определения функций в данном
> документе (полная форма / опускание лямбда-заголовка / опускание сигнатуры / пустые параметры)
> **остаются без изменений**, а семантика «досрочного возврата» уже согласована с настоящим RFC.
>
> **Дополнение (решение C)**: «Простейшая форма с пустыми параметрами» `name = { ... }` в данном
> документе пересекается с синтаксисом «блока со значением» из RFC-010. Решено: **аннотация имеет
> приоритет, по умолчанию — функция** — без аннотации «простейшая форма с пустыми параметрами» из
> данного документа остаётся в силе (это функция), а при наличии аннотации не `Fn` это уже значение
> блока (`x: Int = { ... }`). См. приложение D в RFC-010a.
>
> **Связанное дополнение**: Правила завершения операторов и переноса строк внутри тела функции (блок
> `{ ... }`) — явное разделение `;`, завершение переносом строки, исключения для продолжения строки
> — определены в [RFC-038 (черновик)](../draft/038-statement-termination.md) и не входят в настоящий
> RFC.

## Резюме

Настоящий RFC устанавливает окончательную схему **синтаксиса определения функций** языка YaoXiang.
Используется унифицированный синтаксис `name: (params) -> Return = body`, полностью согласующийся с
моделью `name: type = value` из RFC-010.

Во избежание неоднозначности: когда функция имеет входные параметры, их типы должны быть явно
указаны как минимум в одном из мест — в «сигнатуре» или в «лямбда-заголовке»; отсутствие указаний в
обоих местах будет отклонено.

Значение блока кода `{ ... }` определяется **хвостовым выражением**; `return` — это нелокальный
выход типа `Never` (см. [RFC-010a](./010a-tail-expression-and-return.md)). Форма выражения `= expr`
непосредственно даёт значение.

## Мотивация

### Зачем нужна эта возможность?

1. **Согласованность синтаксиса**: устранение наследия старого синтаксиса, единый стиль
2. **Краткость**: алгоритм HM автоматически выводит типы, сокращая шаблонный код
3. **Безопасность типов**: алгоритм HM гарантирует безопасность типов; явное указание требуется
   только при невозможности вывода
4. **Зрелость языка**: алгоритм HM — зрелое решение, принятое в современных функциональных языках

### Унифицированная модель синтаксиса

**Базовый принцип**: `name: Signature = LambdaBody`

- **Полная форма**: сигнатура (включает имена параметров + типы + `->` + тип возврата) +
  лямбда-заголовок (включает имена параметров)
- **Правила сокращения**: максимальное опускание при отсутствии неоднозначности
  - `->` не может быть опущен (признак функционального типа, иначе будет разобрано как кортеж)
  - **При наличии входных параметров** их типы должны быть явно указаны как минимум в одном из мест
    — в сигнатуре или в лямбда-заголовке
  - Лямбда-заголовок может быть опущен → если имена и типы параметров уже объявлены в сигнатуре
  - Тип возврата может быть указан явно или опущен, если он выводим

```yaoxiang
# Полная форма (полная сигнатура + полный лямбда-заголовок)
add: (a: Int, b: Int) -> Int = (a, b) => a + b

# Сокращение: опускание лямбда-заголовка (параметры объявлены в сигнатуре)
add: (a: Int, b: Int) -> Int = a + b

# Сокращение: опускание сигнатуры (типы параметров в лямбда-заголовке)
add = (a: Int, b: Int) => a + b

# ❌ Ошибка: типы параметров не указаны нигде
# add = (a, b) => a + b
```

### Цели проектирования

```yaoxiang
# === Полная форма ===
add: (a: Int, b: Int) -> Int = (a, b) => { a + b }

# === Сокращённые формы ===
add: (a: Int, b: Int) -> Int = a + b                 # опускание лямбда-заголовка
add = (a: Int, b: Int) => a + b                      # опускание сигнатуры

# === Функции без параметров ===
main: () -> Void = () => { println("Hello") }          # полная форма
main: () -> Void = { println("Hello") }                # опускание лямбда-заголовка
main: () -> Void = { println("Hello") }                            # простейшая форма (выводится () -> Void)

# === Обобщённые функции (используется унифицированный синтаксис RFC-010) ===
identity: (T: Type) -> ((x: T) -> T) = (x) => x         # полная форма
identity: (T: Type) -> ((x: T) -> T) = x                # опускание лямбда-заголовка
identity = (x: T) => x                                  # опускание сигнатуры (типы в лямбда-заголовке)

# === Рекурсивные функции ===
factorial: (n: Int) -> Int = (n) => {
    if n <= 1 { return 1 } else { return n * factorial(n - 1) }
}
```

### Правила синтаксиса

| Сценарий                       | Синтаксис                                              | Пояснение                                         |
| ------------------------------ | ------------------------------------------------------ | ------------------------------------------------- |
| **Полная форма**               | `name: (a: Type, b) -> Ret = (a, b) => { return ... }` | Полная сигнатура + лямбда-заголовок               |
| **Опускание лямбда-заголовка** | `name: (a: Type, b: Type) -> Ret = { ... }`            | Параметры объявлены в сигнатуре                   |
| **Опускание сигнатуры**        | `name = (a: Type, b: Type) => { ... }`                 | Типы параметров в лямбда-заголовке                |
| **Пустые параметры (полная)**  | `name: () -> Void = () => { return ... }`              | Полная форма функции без параметров               |
| **Пустые параметры (сокр.)**   | `name: () -> Void = { return ... }`                    | Опускание лямбда-заголовка                        |
| **Пустые параметры (макс.)**   | `name = { return ... }`                                | Максимальное сокращение без параметров и возврата |

**Примечание**: значение блока кода `{ ... }` определяется **хвостовым выражением** (единственный
выход); `return` — это нелокальный выход типа `Never`, выходящий из ближайшей границы функции. Форма
выражения `= expr` непосредственно даёт значение. Подробности см. в
[RFC-010a](./010a-tail-expression-and-return.md).

**Примечание**: `->` является признаком функционального типа и не может быть опущен (иначе будет
разобрано как кортеж).

**Важно**: выражение `if` использует фигурные скобки `{}` для обрамления ветвей, ключевые слова
`then/else` не поддерживаются:

```yaoxiang
# Корректно: использование фигурных скобок
if n <= 1 { return 1 } else { return n * factorial(n - 1) }

# Ошибка: ключевые слова then/else не поддерживаются
# if n <= 1 then return 1 else return n * factorial(n - 1)
```

## Предложение

### Алгоритм HM и поддержка полиморфизма высшего ранга

**Ключевая возможность**: алгоритм HM поддерживает полиморфизм высшего ранга (Higher-rank
polymorphism) посредством аннотаций обобщённых типов

**Принципы проектирования**:

- **Функции высшего порядка**: при передаче функции в качестве аргумента требуется обобщённое
  ограничение её функционального типа
- **Форма аннотации типов**: `(T: Type) -> ((f: (T) -> T, x: T) -> T)` — обобщённый параметр
  ограничивает функциональный тип
- **Рабочий процесс HM**: вывод функциональных типов посредством обобщённых параметров, реализация
  композиции полиморфных функций

**Поясняющие примеры**:

```yaoxiang
# ✅ Поддержка полиморфизма высшего ранга: обобщённое ограничение параметров функционального типа
call_twice: (T: Type) -> ((f: (T) -> T, x: T) -> T) = {
    return f(f(x))
}
# Использование: call_twice((x) => x + 1, 5)  # вывод T=Int

compose: (A: Type, B: Type, C: Type) -> ((f: (B) -> C, g: (A) -> B, x: A) -> C) = {
    return f(g(x))
}
# Использование: compose((x) => x * 2, (x) => x + 1, 5)  # вывод A=Int, B=Int, C=Int

# ❌ Не поддерживается: функция высшего порядка без обобщённого ограничения
# bad_hof: (f, x) => f(f(x))  # HM не может выполнить вывод, отсутствуют обобщённые параметры
```

**Процесс вывода HM**:

1. Идентификация параметров функций высшего порядка: `f: (T) -> T`
2. Создание обобщённого ограничения: `(T: Type)`
3. Вывод конкретных типов посредством инстанциации обобщённых параметров
4. Реализация композиции полиморфных функций

### Правила синтаксиса лямбда-выражений

**Важное правило**: значение блока кода `{ ... }` определяется **хвостовым выражением**
(единственный выход); `return` — это нелокальный выход типа `Never`, выходящий из ближайшей границы
функции. Форма выражения `= expr` непосредственно даёт значение. Подробности см. в
[RFC-010a](./010a-tail-expression-and-return.md).

| Форма синтаксиса    | Синтаксис        | Выход значения                                  |
| ------------------- | ---------------- | ----------------------------------------------- |
| **Блочная форма**   | `{ statements }` | Хвостовое выражение (пустой блок `{}` = `Void`) |
| **Форма выражения** | `expression`     | Значение выражения                              |
| **`return`**        | `return e`       | Нелокальный выход из функции, тип `Never`       |

**Примеры**:

```yaoxiang
main: () -> Void = { println("Hello") }         # хвостовое выражение имеет тип Void
add: (a: Int, b: Int) -> Int = { a + b }        # значение даётся хвостовым выражением
empty: () -> Void = {}                          # пустой блок → Void

# Досрочный возврат: использование return
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)
}

# Форма выражения: значение непосредственно даётся
add: (a: Int, b: Int) -> Int = a + b            # корректно: форма выражения
main: () -> Void = println("Hello")               # корректно: форма выражения
```

**Ключевые идеи**:

1. Определение функций использует алгоритм HM для вывода типов, максимально стараясь вывести; при
   невозможности — явная ошибка
2. **Принцип работы алгоритма HM**: автоматический вывод типов посредством ограничений типов
   операторов, контекста вызовов функций и т.п.
3. **Поддержка обобщений**: полиморфные функции используют синтаксис `(T: Type)` для явного
   ограничения параметров типа (RFC-010/011)
4. **Границы вывода**: тип возврата и локальные переменные выводимы; типы параметров функций с
   аргументами должны быть указаны явно (в сигнатуре или в лямбда-заголовке)
5. Функции без параметров и без возвращаемого значения используют `name: () -> Void = { ... }`,
   согласовано с RFC-010
6. Вывод старого синтаксиса из эксплуатации, предоставляется инструмент миграции

**Примеры вывода типов**:

```yaoxiang
# Обобщённые функции: явные параметры типа (используется унифицированный синтаксис RFC-010)
identity: (T: Type) -> ((x: T) -> T) = x
map: (T: Type, R: Type) -> ((f: (T) -> R, list: List(T)) -> List(R)) = {
    result = List(R)()
    for item in list { result.push(f(item)) }
    return result
}

# Полиморфные функции: определение посредством явных обобщённых ограничений (RFC-010/011)
add: (T: Add) -> ((a: T, b: T) -> T) = a + b
print_sum: (a: Int, b: Int) -> Void = { println(a + b) }  # выводится (Int, Int) -> Void

# Полиморфизм высшего ранга: поддержка полиморфизма высшего ранга в HM посредством аннотаций обобщённых типов
call_twice: (T: Type) -> ((f: (T) -> T, x: T) -> T) = { return f(f(x)) }
compose: (A: Type, B: Type, C: Type) -> ((f: (B) -> C, g: (A) -> B, x: A) -> C) = { return f(g(x)) }
```

```yaoxiang
# === Определение функций: вывод типов алгоритмом HM ===

# Стандартные функции: HM выводит тип возврата (типы параметров должны быть явными)
add = (a: Int, b: Int) => a + b            # выводится (a: Int, b: Int) -> Int
main: () -> Void = { println("Hello") }                # выводится () -> Void

# Частично явные параметры: HM выводит оставшуюся часть
print_sum: (a: Int, b: Int) -> Void = { println(a + b) }  # выводится (Int, Int) -> Void
greet: (name: String) -> Void = { println("Hello " + name) }  # выводится (String) -> Void

# Обобщённые функции: явное ограничение параметров полиморфного типа (используется унифицированный синтаксис RFC-010)
identity: (T: Type) -> ((x: T) -> T) = x
map: (T: Type, R: Type) -> ((f: (T) -> R, list: List(T)) -> List(R)) = {
    # реализация функции map
    return List(R)()
}

# Рекурсивные функции: вывод посредством HM и рекурсивных ограничений
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 } else { return n * factorial(n - 1) }
}

# === Присваивание переменных: вывод типов алгоритмом HM ===

# Явный тип
x: Int = 42

# HM автоматически выводит Int
y = 42                               # выводится Int

# HM автоматически выводит String
name = "YaoXiang"                    # выводится String

# HM автоматически выводит Float
pi = 3.14159                         # выводится Float
```

**Правила вывода типов HM**:

| Сценарий                       | Синтаксис                                         | Опускаемая часть | Пример                              |
| ------------------------------ | ------------------------------------------------- | ---------------- | ----------------------------------- |
| **Полная форма**               | `name: (a: Type, b: Type) -> Ret = (a, b) => ...` | Нет              | Полная сигнатура + лямбда-заголовок |
| **Опускание лямбда-заголовка** | `name: (a: Type, b: Type) -> Ret = ...`           | Лямбда-заголовок | Параметры объявлены в сигнатуре     |
| **Опускание сигнатуры**        | `name = (a: Type, b: Type) => ...`                | Сигнатура        | Типы параметров в лямбда-заголовке  |
| **Опускание возврата Ret**     | `name: (a: Type, b: Type) -> = ...`               | Тип возврата     | HM выводит тип возврата             |
| **Пустые параметры (полная)**  | `name: () -> Void = () => { ... }`                | Нет              | Полная форма функции без параметров |
| **Пустые параметры (сокр.)**   | `name: () -> Void = { ... }`                      | Лямбда-заголовок | Опускание `() =>`                   |
| **Пустые параметры (макс.)**   | `name = { ... }`                                  | Всё              | Максимальное сокращение             |
| **Присваивание переменной**    | `name = value`                                    | Тип              | HM выводит тип                      |
| **Явная переменная**           | `name: Type = value`                              | Нет              | Явная аннотация типа                |

**Базовые принципы**:

- `->` — признак функционального типа, не может быть опущен (иначе будет разобрано как кортеж)
- Тип возврата `Ret` может быть опущен, HM выводит его из тела функции
- При наличии входных параметров их типы должны быть явно указаны (в сигнатуре или в
  лямбда-заголовке)
- Остальные части могут быть опущены, если они выводимы и не создают неоднозначности
- Неявные преобразования типов отсутствуют, что предотвращает хаос в стиле JavaScript

## Детальное проектирование

### Раскрытие синтаксического сахара

Независимо от сокращений, результат нормализуется к единому промежуточному представлению:

```rust
// Полная форма
add: (a: Int, b: Int) -> Int = (a, b) => a + b

// Раскрытое IR
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    return a + b
};

// Опускание лямбда-заголовка
add: (a: Int, b: Int) -> Int = a + b

// Раскрытое IR (аналогично полной форме)
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    return a + b
};

// Опускание сигнатуры (типы параметров в лямбда-заголовке)
add = (a: Int, b: Int) => a + b

// Раскрытое IR
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    a + b
};
```

### Определение синтаксиса

```bnf
function_def ::= identifier ':' type_expr '=' expression
               | identifier '=' expression
               | identifier '=' block                    # простейшая форма: без параметров и без возврата

identifier ::= [a-zA-Z_][a-zA-Z0-9_]*

type_expr ::= identifier                     # ссылка на тип
       | '()'                          # пустой тип
       | '(' parameters ')' '->' type_expr   # функциональный тип (имена параметров в сигнатуре)
       | type_expr '->' type_expr            # простой функциональный тип
       | identifier '(' type_expr (',' type_expr)* ')'  # применение типа

expression ::= '(' parameters ')' '=>' block
             | '(' ')' '=>' block
             | '(' parameters ')' '=>' expression

parameters ::= parameter (',' parameter)*
parameter ::= identifier                # вывод типа
            | identifier ':' type_expr      # частично явный тип

block ::= '{' statement (',' statement)* '}'
        | expression

statement ::= identifier ':' expression  # оператор присваивания
           | expression                  # оператор-выражение (выполнение без возврата)
           | 'return' expression         # оператор возврата (возвращает указанное значение)

# Примечание: внутри блока кода для возврата значения необходимо использовать return;
# при отсутствии return по умолчанию возвращается Void
# Например: { return 1 + 1 } возвращает Int; { println("Hello") } возвращает Void
# Примечание: обобщённые параметры используют синтаксис (T: Type), как часть функционального типа,
# отдельное правило BNF не требуется
```

### Обработка ошибок

```yaoxiang
# === Примеры ошибок компиляции ===

# Ошибка 1: несоответствие типа возврата блока
add: (a: Int, b: Int) -> Int = { println(a + b) }
// Ошибка: в блоке нет return, по умолчанию возвращается Void, но сигнатура ожидает Int
// Корректно: add: (a: Int, b: Int) -> Int = a + b
// Или: add: (a: Int, b: Int) -> Int = { return a + b }

# Ошибка 2: использование необъявленного параметра типа
identity: (x: T) -> T = x
// Ошибка: T не объявлен; требуется явный обобщённый параметр (RFC-010)
// Корректно: identity: (T: Type) -> ((x: T) -> T) = x

# Корректно: HM выводит тип возврата
double = (x: Int) => x + x

# Полная форма (пошаговое сокращение)
double: (x: Int) -> Int = (x) => x + x                # полная
double: (x: Int) -> Int = x + x                       # опускание лямбда-заголовка
double = (x: Int) => x + x                            # опускание типа возврата (HM выводит)
# double = (x) => x + x                               # ❌ типы параметров нельзя опускать в обоих местах
```

## Компромиссы

### Преимущества

- **Единый синтаксис**: модель `name: Signature = LambdaBody` покрывает все сценарии
- **Гибкие сокращения**: любая часть может быть опущена, если она выводима посредством HM
- **Безопасность типов**: алгоритм HM гарантирует безопасность типов, исключая неявные
  преобразования
- **Поддержка рекурсии**: алгоритм HM и рекурсивные ограничения автоматически выводят типы
- **Отсутствие накладных расходов**: плавный переход от полной формы к простейшей

### Недостатки

- **Стоимость миграции**: старый код требует конвертации инструментом миграции
- **Стоимость обучения**: необходимо понимание модели «полная форма + произвольные сокращения»

## Альтернативы

| Подход                        | Описание                                                | Почему не выбран                                          |
| ----------------------------- | ------------------------------------------------------- | --------------------------------------------------------- |
| Вывод типов алгоритмом HM     | Использование алгоритма Хиндли-Милнера для вывода типов | ✅ **Принят**, стандарт современных функциональных языков |
| Явные объявления типов        | Все типы должны быть указаны явно                       | Нарушает принцип упрощения синтаксиса, увеличивает шаблон |
| Сохранение старого синтаксиса | Одновременная поддержка старого и нового синтаксиса     | Разделение синтаксиса, высокая стоимость поддержки        |
| Ключевое слово `fn`           | Введение `fn` для различения функций и переменных       | Нарушает принцип «функция — это лямбда»                   |

## Стратегия реализации

### Этапы

1. **Этап 1: Синтаксический разбор и алгоритм HM** (v0.3)
   - Реализация нового синтаксиса `name = lambda` + вывод типов алгоритмом HM
   - Реализация заполнения по умолчанию для функций без параметров и без возврата

2. **Этап 2: Инструмент миграции** (v0.3)
   - Разработка инструмента `yaoxiang-migrate --old-to-new`
   - Автоматическая конвертация кода старого синтаксиса

3. **Этап 3: Верификация и документация** (v0.3)
   - Верификация завершения миграции старого кода
   - Обновление документации

### Инструмент миграции

```bash
# Миграция одного файла
yaoxiang-migrate --old-to-new src/main.yaoxiang

# Миграция всего проекта
yaoxiang-migrate --old-to-new --recursive src/

# Предварительный просмотр миграции (без изменения файлов)
yaoxiang-migrate --old-to-new --dry-run src/main.yaoxiang
```

Правила миграции:

```yaoxiang
# Старый синтаксис
add(Int, Int) -> Int = (a, b) => { a + b }
main() -> Int = { println("Hello"); 0 }
main() = { println("Hello") }

# === Новый синтаксис: полная форма (полная сигнатура + полный лямбда-заголовок) ===
add: (a: Int, b: Int) -> Int = (a, b) => a + b
main: () -> Void = () => { println("Hello") }

# === Сокращение: опускание лямбда-заголовка ===
add: (a: Int, b: Int) -> Int = a + b
main: () -> Void = { println("Hello") }

# === Сокращение: вывод HM ===
add = (a: Int, b: Int) => a + b              # выводится (a: Int, b: Int) -> Int
main: () -> Void = { println("Hello") }                  # выводится () -> Void

# === Простейшая форма ===
main: () -> Void = {                                      # эквивалентно main: () -> Void = { ... }
    println("Hello")
}
```

### Зависимости

- Внешние зависимости отсутствуют
- Может быть реализовано независимо

### Риски

| Риск             | Влияние                                | Меры по смягчению                                                              |
| ---------------- | -------------------------------------- | ------------------------------------------------------------------------------ |
| Пропуск миграции | Сбой компиляции старого кода           | Предоставление инструмента миграции, покрытие всех шаблонов старого синтаксиса |
| Ошибки парсера   | Нестабильность синтаксического разбора | Достаточное тестовое покрытие                                                  |

## Открытые вопросы

> Следующие вопросы уже решены в проектировании, записаны в приложении A.

- ~~В1: Стоит ли сохранять предельно краткую запись `main() = body`?~~ → Решено: сохранено как
  `main: () -> Void = { ... }`
- ~~В2: Сохраняется ли `:` после имени функции?~~ → Решено: необязательно; но для функций с
  параметрами типы параметров всё ещё требуются в сигнатуре или лямбда-заголовке
- ~~В3: Поддерживает ли алгоритм HM вывод типов параметров?~~ → Решено: возвращаемый тип/локальные
  переменные выводимы; типы параметров функций с аргументами требуют явного указания
- ~~В4: Вводить ли ключевое слово `fn`?~~ → Решено: не вводить, функция — это лямбда
- ~~В5: Какова стратегия миграции старого кода?~~ → Решено: предоставляется инструмент
  `yaoxiang-migrate`
- ~~В6: Как использовать обобщённые функции?~~ → Решено: используется унифицированный синтаксис
  RFC-010 `(T: Type)`

| TypeScript   | `const add = (a: number, b: number): number => ...` | Лямбда-стиль                                      |
| Scala        | `def add(a: Int, b: Int): Int = { ... }`            | Ключевое слово `def`                              |
| **YaoXiang** | `name = (a: Int, b: Int) => a + b`                  | **Функция = лямбда, HM выводит возвращаемый тип** |
