# RFC-007: Унификация синтаксиса определения функций

> **Связано**: В месте пересечения синтаксиса «простейшей формы без аргументов» `name = { ... }` и
> синтаксиса «блока со значением» из RFC-010, принято решение: **содержимое определяет тип** — `=>`
> всегда обозначает функцию, аннотация `Fn` означает функцию, аннотация, отличная от `Fn`, означает
> значение-блок, при отсутствии аннотации тип выводится по содержимому. См.
> [RFC-010a](./010a-tail-expression-and-return.md), приложение D.
>
> **Дополнительное примечание**: Правила завершения операторов и переноса строк в теле функции (блок
> кода `{ ... }`) — явное разделение через `;`, завершение переносом строки, исключения для
> продолжения строки — определены в [RFC-038 (черновик)](../draft/038-statement-termination.md);
> настоящий RFC их не затрагивает.

## Резюме

Настоящий RFC определяет окончательную схему **синтаксиса определения функций** языка YaoXiang.
Используется единый синтаксис `name: (params) -> Return = body`, полностью согласующийся с моделью
`name: type = value` из RFC-010.

Во избежание неоднозначности: при наличии входных параметров их типы должны быть явно указаны хотя
бы в одном из мест — в «сигнатуре» или в «lambda-заголовке»; опускание в обоих местах запрещено.

Значение блока кода `{ ... }` определяется **хвостовым выражением**; `return` представляет собой
нелокальный выход типа `Never` (см. [RFC-010a](./010a-tail-expression-and-return.md)). Форма
выражения `= expr` непосредственно даёт значение.

## Мотивация

### Зачем нужна эта возможность?

1. **Согласованность синтаксиса**: устранение исторического наследия старого синтаксиса, единый
   стиль
2. **Краткость**: алгоритм HM автоматически выводит типы, сокращая шаблонный код
3. **Типобезопасность**: алгоритм HM гарантирует безопасность типов; явное указание требуется только
   при невозможности вывода
4. **Зрелость языка**: алгоритм HM — зрелое решение современных функциональных языков

### Единая модель синтаксиса

**Основной принцип**: `name: Signature = LambdaBody`

- **Полная форма**: сигнатура (с именами параметров + типами + `->` + типом возврата) +
  lambda-заголовок (с именами параметров)
- **Правила сокращения**: опускать везде, где это не вносит неоднозначности
  - `->` не может быть опущен (признак функционального типа, иначе будет интерпретирован как кортеж)
  - **При наличии входных параметров** их типы должны быть явно указаны хотя бы в одном из мест — в
    сигнатуре или в lambda-заголовке
  - Lambda-заголовок может быть опущен, если сигнатура уже объявляет имена и типы параметров
  - Тип возврата может быть указан явно или опущен, если он выводим

```yaoxiang
# Полная форма (полная сигнатура + полный lambda-заголовок)
add: (a: Int, b: Int) -> Int = (a, b) => a + b

# Сокращение: lambda-заголовок опущен (параметры объявлены в сигнатуре)
add: (a: Int, b: Int) -> Int = a + b

# Сокращение: сигнатура опущена (типы параметров указаны в lambda-заголовке)
add = (a: Int, b: Int) => a + b

# ❌ Ошибка: типы параметров не указаны нигде
# add = (a, b) => a + b
```

### Цели проектирования

```yaoxiang
# === Полная форма ===
add: (a: Int, b: Int) -> Int = (a, b) => { a + b }

# === Сокращённые формы ===
add: (a: Int, b: Int) -> Int = a + b                 # lambda-заголовок опущен
add = (a: Int, b: Int) => a + b                      # сигнатура опущена

# === Функции без аргументов ===
main: () -> Void = () => { println("Hello") }          # полная форма
main: () -> Void = { println("Hello") }                # lambda-заголовок опущен
main: () -> Void = { println("Hello") }                            # простейшая форма (выводится () -> Void)

# === Обобщённые функции (с использованием единого синтаксиса RFC-010) ===
identity: (T: Type) -> ((x: T) -> T) = (x) => x         # полная форма
identity: (T: Type) -> ((x: T) -> T) = x                # lambda-заголовок опущен
identity = (x: T) => x                                  # сигнатура опущена (типы в lambda-заголовке)

# === Рекурсивные функции ===
factorial: (n: Int) -> Int = (n) => {
    if n <= 1 { return 1 } else { return n * factorial(n - 1) }
}
```

### Правила синтаксиса

| Сценарий                        | Синтаксис                                              | Пояснение                                      |
| ------------------------------- | ------------------------------------------------------ | ---------------------------------------------- |
| **Полная форма**                | `name: (a: Type, b) -> Ret = (a, b) => { return ... }` | Сигнатура + lambda-заголовок полные            |
| **Опущен lambda-заголовок**     | `name: (a: Type, b: Type) -> Ret = { ... }`            | Параметры объявлены в сигнатуре                |
| **Опущена сигнатура**           | `name = (a: Type, b: Type) => { ... }`                 | Типы параметров указаны в lambda-заголовке     |
| **Без аргументов, полная**      | `name: () -> Void = () => { return ... }`              | Полная форма функции без аргументов            |
| **Без аргументов, сокращённая** | `name: () -> Void = { return ... }`                    | Lambda-заголовок опущен                        |
| **Без аргументов, простейшая**  | `name = { return ... }`                                | Простейшая форма без параметров и без возврата |

**Примечание**: значение блока кода `{ ... }` определяется **хвостовым выражением** (единственный
выход); `return` — нелокальный выход типа `Never`, выходящий за ближайшую границу функции. Форма
выражения `= expr` непосредственно даёт значение. Подробности см. в
[RFC-010a](./010a-tail-expression-and-return.md).

**Примечание**: `->` — признак функционального типа, не может быть опущен (иначе будет
интерпретирован как кортеж).

**Важно**: выражение `if` использует фигурные скобки `{}` для обрамления ветвей, ключевые слова
`then/else` не поддерживаются:

```yaoxiang
# Корректно: используются фигурные скобки
if n <= 1 { return 1 } else { return n * factorial(n - 1) }

# Ошибка: ключевые слова then/else не поддерживаются
# if n <= 1 then return 1 else return n * factorial(n - 1)
```

## Предложение

### Алгоритм HM и поддержка полиморфизма высшего ранга

**Ключевая особенность**: алгоритм HM обеспечивает поддержку полиморфизма высшего ранга (Higher-rank
polymorphism) посредством аннотаций обобщённых типов.

**Принципы проектирования**:

- **Функции высшего порядка**: при передаче функции в качестве аргумента требуется обобщённое
  ограничение её функционального типа
- **Форма аннотации типа**: `(T: Type) -> ((f: (T) -> T, x: T) -> T)` — параметр типа ограничивает
  функциональный тип
- **Рабочий процесс HM**: вывод функциональных типов через инстанциацию обобщённых параметров,
  обеспечивающий композицию полиморфных функций

**Поясняющие примеры**:

```yaoxiang
# ✅ Поддерживается полиморфизм высшего ранга: обобщённое ограничение аргумента функционального типа
call_twice: (T: Type) -> ((f: (T) -> T, x: T) -> T) = {
    return f(f(x))
}
# Использование: call_twice((x) => x + 1, 5)  # выводится T=Int

compose: (A: Type, B: Type, C: Type) -> ((f: (B) -> C, g: (A) -> B, x: A) -> C) = {
    return f(g(x))
}
# Использование: compose((x) => x * 2, (x) => x + 1, 5)  # выводится A=Int, B=Int, C=Int

# ❌ Не поддерживается: функция высшего порядка без обобщённого ограничения
# bad_hof: (f, x) => f(f(x))  # HM не может выполнить вывод, отсутствует обобщённый параметр
```

**Процесс вывода HM**:

1. Идентификация аргумента-функции высшего порядка: `f: (T) -> T`
2. Создание обобщённого ограничения: `(T: Type)`
3. Вывод конкретных типов через инстанциацию обобщений
4. Реализация композиции полиморфных функций

### Правила синтаксиса lambda-выражений

**Важное правило**: значение блока кода `{ ... }` определяется **хвостовым выражением**
(единственный выход); `return` — нелокальный выход типа `Never`, выходящий за ближайшую границу
функции. Форма выражения `= expr` непосредственно даёт значение. Подробности см. в
[RFC-010a](./010a-tail-expression-and-return.md).

| Форма синтаксиса  | Синтаксис        | Выход значения                                          |
| ----------------- | ---------------- | ------------------------------------------------------- |
| **Блочная форма** | `{ statements }` | Хвостовое выражение (пустой блок `{}` имеет тип `Void`) |
| **Выражение**     | `expression`     | Значение выражения                                      |
| **`return`**      | `return e`       | Нелокальный выход из функции, тип `Never`               |

**Примеры**:

```yaoxiang
main: () -> Void = { println("Hello") }         # хвостовое выражение имеет тип Void
add: (a: Int, b: Int) -> Int = { a + b }        # значение даётся хвостовым выражением
empty: () -> Void = {}                          # пустой блок → Void

# Досрочный возврат: используется return
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)
}

# Форма выражения: значение даётся непосредственно
add: (a: Int, b: Int) -> Int = a + b            # корректно: форма выражения
main: () -> Void = println("Hello")               # корректно: форма выражения
```

**Основные идеи**:

1. Определение функций использует алгоритм HM для вывода типов; вывод производится максимально, при
   невозможности — явная ошибка
2. **Принцип работы алгоритма HM**: автоматический вывод типов посредством ограничений типов
   операторов, контекста вызовов функций и другой контекстной информации
3. **Поддержка обобщений**: полиморфные функции используют обобщённый синтаксис `(T: Type)` для
   явного ограничения параметров типа (RFC-010/011)
4. **Границы вывода**: тип возврата и локальные переменные выводимы; для функций с параметрами типы
   параметров должны быть указаны явно (в сигнатуре или в lambda-заголовке)
5. Функции без аргументов и без возврата используют форму `name: () -> Void = { ... }`,
   согласующуюся с RFC-010
6. Старый синтаксис выводится из употребления, предоставляется инструмент миграции

**Примеры вывода типов**:

```yaoxiang
# Обобщённые функции: явные параметры типа (используется единый синтаксис RFC-010)
identity: (T: Type) -> ((x: T) -> T) = x
map: (T: Type, R: Type) -> ((f: (T) -> R, list: List(T)) -> List(R)) = {
    result = List(R)()
    for item in list { result.push(f(item)) }
    return result
}

# Полиморфные функции: определяются посредством явных обобщённых ограничений (RFC-010/011)
add: (T: Add) -> ((a: T, b: T) -> T) = a + b
print_sum: (a: Int, b: Int) -> Void = { println(a + b) }  # выводится (Int, Int) -> Void

# Полиморфизм высшего ранга: реализуется через аннотации обобщённых типов, поддерживаемые HM
call_twice: (T: Type) -> ((f: (T) -> T, x: T) -> T) = { return f(f(x)) }
compose: (A: Type, B: Type, C: Type) -> ((f: (B) -> C, g: (A) -> B, x: A) -> C) = { return f(g(x)) }
```

```yaoxiang
# === Определение функций: вывод типов алгоритмом HM ===

# Стандартные функции: HM выводит тип возврата (типы параметров должны быть явными)
add = (a: Int, b: Int) => a + b            # выводится (a: Int, b: Int) -> Int
main: () -> Void = { println("Hello") }                # выводится () -> Void

# Частично явные параметры: HM выводит оставшуюся часть
print_sum: (a: Int, b: Int) -> Void = { println(a + b) }  # выводится (Int, Int) -> Void
greet: (name: String) -> Void = { println("Hello " + name) }  # выводится (String) -> Void

# Обобщённые функции: явное ограничение полиморфных параметров типа (используется единый синтаксис RFC-010)
identity: (T: Type) -> ((x: T) -> T) = x
map: (T: Type, R: Type) -> ((f: (T) -> R, list: List(T)) -> List(R)) = {
    # Реализация функции map
    return List(R)()
}

# Рекурсивные функции: вывод посредством HM и ограничения рекурсии
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 } else { return n * factorial(n - 1) }
}

# === Присваивание переменных: вывод типов алгоритмом HM ===

# Явный тип
x: Int = 42

# HM автоматически выводит Int
y = 42                               # выводится Int

# HM автоматически выводит String
name = "YaoXiang"                    # выводится String

# HM автоматически выводит Float
pi = 3.14159                         # выводится Float
```

**Правила вывода типов в HM**:

| Сценарий                        | Синтаксис                                         | Допустимые сокращения | Пример                                         |
| ------------------------------- | ------------------------------------------------- | --------------------- | ---------------------------------------------- |
| **Полная форма**                | `name: (a: Type, b: Type) -> Ret = (a, b) => ...` | Нет                   | Сигнатура + lambda-заголовок полные            |
| **Опущен lambda-заголовок**     | `name: (a: Type, b: Type) -> Ret = ...`           | Lambda-заголовок      | Параметры объявлены в сигнатуре                |
| **Опущена сигнатура**           | `name = (a: Type, b: Type) => ...`                | Сигнатура             | Типы параметров указаны в lambda-заголовке     |
| **Опущен тип возврата Ret**     | `name: (a: Type, b: Type) -> = ...`               | Тип возврата          | HM выводит тип возврата                        |
| **Без аргументов, полная**      | `name: () -> Void = () => { ... }`                | Нет                   | Полная форма функции без аргументов            |
| **Без аргументов, сокращённая** | `name: () -> Void = { ... }`                      | Lambda-заголовок      | Опущен `() =>`                                 |
| **Без аргументов, простейшая**  | `name = { ... }`                                  | Всё                   | Простейшая форма без параметров и без возврата |
| **Присваивание переменной**     | `name = value`                                    | Тип                   | HM выводит тип                                 |
| **Явная переменная**            | `name: Type = value`                              | Нет                   | Явная аннотация типа                           |

**Основные принципы**:

- `->` — признак функционального типа, не может быть опущен (иначе будет интерпретирован как кортеж)
- Тип возврата `Ret` может быть опущен; HM выводит его по телу функции
- При наличии входных параметров их типы должны быть указаны явно (в сигнатуре или в
  lambda-заголовке)
- Остальные части могут быть опущены, если они выводимы и не вносят неоднозначности
- Неявные преобразования типов запрещены, во избежание хаоса в стиле JavaScript

## Подробное проектирование

### Раскрытие синтаксического сахара

Независимо от того, какие части опущены, в конечном итоге всё нормализуется к единому промежуточному
представлению:

```rust
// Полная форма
add: (a: Int, b: Int) -> Int = (a, b) => a + b

// Раскрытое IR
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    return a + b
};

// Опущен lambda-заголовок
add: (a: Int, b: Int) -> Int = a + b

// Раскрытое IR (идентично полной форме)
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    return a + b
};

// Опущена сигнатура (типы параметров в lambda-заголовке)
add = (a: Int, b: Int) => a + b

// Раскрытое IR
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    a + b
};
```

### Определение синтаксиса

```bnf
function_def ::= identifier ':' type_expr '=' expression
               | identifier '=' expression
               | identifier '=' block                    # Простейшая форма: без параметров и без возврата

identifier ::= [a-zA-Z_][a-zA-Z0-9_]*

type_expr ::= identifier                     # Ссылка на тип
       | '()'                          # Пустой тип
       | '(' parameters ')' '->' type_expr   # Функциональный тип (имена параметров в сигнатуре)
       | type_expr '->' type_expr            # Простой функциональный тип
       | identifier '(' type_expr (',' type_expr)* ')'  # Применение типа

expression ::= '(' parameters ')' '=>' block
             | '(' ')' '=>' block
             | '(' parameters ')' '=>' expression

parameters ::= parameter (',' parameter)*
parameter ::= identifier                # Вывод типа
            | identifier ':' type_expr      # Частично явный тип

block ::= '{' statement (',' statement)* '}'
        | expression

statement ::= identifier ':' expression  # Оператор присваивания
           | expression                  # Оператор-выражение (выполняется, но не возвращается)
           | 'return' expression         # Оператор возврата (возвращает указанное значение)

# Примечание: внутри блока кода для возврата значения необходимо использовать return;
# при отсутствии return по умолчанию возвращается Void.
# Например: { return 1 + 1 } возвращает Int; { println("Hello") } возвращает Void.
# Примечание: обобщённые параметры используют синтаксис (T: Type) как часть функционального типа,
# отдельное правило BNF для них не требуется.
```

### Обработка ошибок

```yaoxiang
# === Примеры ошибок компиляции ===

# Ошибка 1: несоответствие типа возврата блока кода
add: (a: Int, b: Int) -> Int = { println(a + b) }
// Ошибка: в блоке нет return, по умолчанию возвращается Void, но сигнатура ожидает Int
// Корректно: add: (a: Int, b: Int) -> Int = a + b
// Или:     add: (a: Int, b: Int) -> Int = { return a + b }

# Ошибка 2: использование необъявленного параметра типа
identity: (x: T) -> T = x
// Ошибка: T не объявлен; требуется явный обобщённый параметр (RFC-010)
// Корректно: identity: (T: Type) -> ((x: T) -> T) = x

# Корректно: HM выводит тип возврата
double = (x: Int) => x + x

# Полная форма (пошаговое сокращение)
double: (x: Int) -> Int = (x) => x + x                # полная
double: (x: Int) -> Int = x + x                       # lambda-заголовок опущен
double = (x: Int) => x + x                            # тип возврата опущен (выводится HM)
# double = (x) => x + x                               # ❌ Тип параметра не может быть опущен в обоих местах
```

## Компромиссы

### Преимущества

- **Единый синтаксис**: модель `name: Signature = LambdaBody` покрывает все сценарии
- **Гибкие сокращения**: любая часть может быть опущена, если она выводима посредством HM
- **Типобезопасность**: алгоритм HM гарантирует безопасность типов, исключая неявные преобразования
- **Поддержка рекурсии**: алгоритм HM и ограничение рекурсии автоматически выводят типы
- **Отсутствие накладных расходов**: плавный переход от полной формы к простейшей

### Недостатки

- **Стоимость миграции**: старый код требует конвертации инструментом миграции
- **Стоимость обучения**: необходимо понимание модели «полная форма + произвольные сокращения»

## Альтернативы

| Решение                       | Описание                                            | Почему не выбрано                                                        |
| ----------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------ |
| Вывод типов алгоритмом HM     | Вывод типов с помощью алгоритма Хиндли-Милнера      | ✅ **Принято**, стандарт современных функциональных языков               |
| Явное объявление типов        | Все типы должны быть записаны явно                  | Нарушает принцип упрощения синтаксиса, увеличивает объём шаблонного кода |
| Сохранение старого синтаксиса | Одновременная поддержка старого и нового синтаксиса | Расщепление синтаксиса, высокая стоимость сопровождения                  |
| Ключевое слово `fn`           | Введение `fn` для различения функций и переменных   | Нарушает принцип «функция — это lambda»                                  |

## Стратегия реализации

### Этапы

1. **Этап 1: синтаксический разбор и алгоритм HM** (v0.3)
   - Реализация нового синтаксиса `name = lambda` и вывода типов алгоритмом HM
   - Реализация заполнения по умолчанию для функций без аргументов и без возврата

2. **Этап 2: инструмент миграции** (v0.3)
   - Разработка инструмента `yaoxiang-migrate --old-to-new`
   - Автоматическая конвертация кода со старым синтаксисом

3. **Этап 3: верификация и документация** (v0.3)
   - Верификация завершения миграции старого кода
   - Обновление документации

### Инструмент миграции

```bash
# Миграция одного файла
yaoxiang-migrate --old-to-new src/main.yaoxiang

# Миграция всего проекта
yaoxiang-migrate --old-to-new --recursive src/

# Предварительный просмотр миграции (без изменения файлов)
yaoxiang-migrate --old-to-new --dry-run src/main.yaoxiang
```

Правила миграции:

```yaoxiang
# Старый синтаксис
add(Int, Int) -> Int = (a, b) => { a + b }
main() -> Int = { println("Hello"); 0 }
main() = { println("Hello") }

# === Новый синтаксис: полная форма (полная сигнатура + полный lambda-заголовок) ===
add: (a: Int, b: Int) -> Int = (a, b) => a + b
main: () -> Void = () => { println("Hello") }

# === Сокращение: lambda-заголовок опущен ===
add: (a: Int, b: Int) -> Int = a + b
main: () -> Void = { println("Hello") }

# === Сокращение: вывод HM ===
add = (a: Int, b: Int) => a + b              # выводится (a: Int, b: Int) -> Int
main: () -> Void = { println("Hello") }                  # выводится () -> Void

# === Простейшая форма ===
main: () -> Void = {                                      # эквивалентно main: () -> Void = { ... }
    println("Hello")
}
```

### Зависимости

- Внешние зависимости отсутствуют
- Может быть реализовано независимо

### Риски

| Риск                  | Влияние                                | Меры по смягчению                                                                |
| --------------------- | -------------------------------------- | -------------------------------------------------------------------------------- |
| Пропуски при миграции | Старый код не компилируется            | Предоставление инструмента миграции, покрывающего все шаблоны старого синтаксиса |
| Ошибки парсера        | Нестабильность синтаксического разбора | Достаточное покрытие тестами                                                     |

## Открытые вопросы

> Перечисленные ниже вопросы решены в ходе проектирования и зафиксированы в приложении A.

- ~~В1: Следует ли сохранить предельно краткую форму `main() = body`?~~ → Решено: сохранена как
  `main: () -> Void = { ... }`
- ~~В2: Сохраняется ли `:` после имени функции?~~ → Решено: опционально; для функций с параметрами
  типы по-прежнему должны быть указаны в сигнатуре или в lambda-заголовке
- ~~В3: Поддерживает ли HM вывод типов параметров?~~ → Решено: тип возврата / локальные переменные
  выводимы; для функций с параметрами типы параметров должны быть указаны явно
- ~~В4: Вводить ли ключевое слово `fn`?~~ → Решено: не вводится, функция — это lambda
- ~~В5: Какова стратегия миграции старого кода?~~ → Решено: предоставляется инструмент
  `yaoxiang-migrate`
- ~~В6: Как использовать обобщённые функции?~~ → Решено: используется единый синтаксис RFC-010
  `(T: Type)`

| TypeScript   | `const add = (a: number, b: number): number => ...` | Стиль lambda                                  |
| Scala        | `def add(a: Int, b: Int): Int = { ... }`            | Ключевое слово `def`                          |
| **YaoXiang** | `name = (a: Int, b: Int) => a + b`                  | **Функция = lambda, HM выводит тип возврата** |
