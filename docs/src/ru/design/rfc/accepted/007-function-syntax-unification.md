# RFC-007: Унифицированный синтаксис определения функций

> **Связь**: В случае пересечения синтаксиса «без параметров, минимальная форма» `name = { ... }` с
> «блоком со значением» из RFC-010, решение принимается на основе содержимого — `=>` всегда означает
> функцию, аннотация `Fn` указывает на функцию, не-`Fn` аннотация указывает на блок-значение, при
> отсутствии аннотации тип определяется по содержимому. См. Приложение D
> [RFC-010a](./010a-tail-expression-and-return.md).
>
> **Дополнение**: Правила завершения операторов и переноса строк (`;` для явного разделения, перенос
> строки для завершения, исключения для продолжения строки) внутри тела функции (`{ ... }` блок
> кода) определены в [RFC-038 (черновик)](./038-statement-termination.md). Данный RFC не затрагивает
> эту тему.

## Краткое содержание

Данный RFC определяет окончательный вариант **синтаксиса определения функций** языка YaoXiang.
Используется унифицированный синтаксис `name: (params) -> Return = body`, полностью соответствующий
модели `name: type = value` из RFC-010.

Для предотвращения неоднозначности: при наличии входных параметров у функции, типы параметров должны
быть явно указаны либо в «сигнатуре», либо в «заголовке lambda» хотя бы в одном месте; пропуск типов
с обеих сторон приведёт к ошибке.

Значение блока кода `{ ... }` определяется **хвостовым выражением**; `return` является нелокальным
выходом типа `Never` (см. [RFC-010a](./010a-tail-expression-and-return.md)). Форма выражения
`= expr` напрямую задаёт значение.

## Мотивация

### Зачем нужен этот функционал?

1. **Синтаксическая согласованность**: устранение исторического наследия старого синтаксиса,
   унификация стиля
2. **Краткость**: алгоритм HM автоматически выводит типы, сокращение шаблонного кода
3. **Типовая безопасность**: алгоритм HM гарантирует типобезопасность, явное указание только при
   невозможности вывода
4. **Зрелость языка**: алгоритм HM — проверенное решение современных функциональных языков

### Унифицированная синтаксическая модель

**Ключевой принцип**: `name: Signature = LambdaBody`

- **Полная форма**: сигнатура (с именами параметров + типы + `->` + тип возврата) + заголовок lambda
  (с именами параметров)
- **Правила сокращения**: опускание допускается везде, где это не создаёт неоднозначности
  - `->` нельзя опускать (маркер типа функции, иначе будет распознано как кортеж)
  - **При наличии входных параметров**, типы параметров должны быть явно указаны хотя бы в сигнатуре
    или в заголовке lambda
  - Заголовок lambda можно опустить → если сигнатура уже объявляет имена и типы параметров
  - Тип возврата можно указать явно, а можно опустить при возможности вывода

```yaoxiang
# Полная форма (полная сигнатура + полный заголовок lambda)
add: (a: Int, b: Int) -> Int = (a, b) => a + b

# Сокращение: опущен заголовок lambda (сигнатура уже объявляет параметры)
add: (a: Int, b: Int) -> Int = a + b

# Сокращение: опущена сигнатура (заголовок lambda указывает типы параметров)
add = (a: Int, b: Int) => a + b

# ❌ Ошибка: типы параметров не указаны с обеих сторон
# add = (a, b) => a + b
```

### Цели дизайна

```yaoxiang
# === Полная форма ===
add: (a: Int, b: Int) -> Int = (a, b) => { a + b }

# === Сокращённые формы ===
add: (a: Int, b: Int) -> Int = a + b                 # опущен заголовок lambda
add = (a: Int, b: Int) => a + b                      # опущена сигнатура

# === Функции без параметров ===
main: () -> Void = () => { println("Hello") }          # полная форма
main: () -> Void = { println("Hello") }                # опущен заголовок lambda
main: () -> Void = { println("Hello") }                            # минимальная форма (выводится как () -> Void)

# === Обобщённые функции (с использованием унифицированного синтаксиса RFC-010) ===
identity: (T: Type) -> ((x: T) -> T) = (x) => x         # полная форма
identity: (T: Type) -> ((x: T) -> T) = x                # опущен заголовок lambda
identity = (x: T) => x                                  # опущена сигнатура (заголовок lambda указывает тип)

# === Рекурсивные функции ===
factorial: (n: Int) -> Int = (n) => {
    if n <= 1 { return 1 } else { return n * factorial(n - 1) }
}
```

### Синтаксические правила

| Сценарий                   | Синтаксис                                              | Описание                         |
| -------------------------- | ------------------------------------------------------ | -------------------------------- |
| **Полная форма**           | `name: (a: Type, b) -> Ret = (a, b) => { return ... }` | Полная сигнатура + заголовок     |
| **Опущен заголовок**       | `name: (a: Type, b: Type) -> Ret = { ... }`            | Сигнатура объявляет параметры    |
| **Опущена сигнатура**      | `name = (a: Type, b: Type) => { ... }`                 | Заголовок lambda указывает типы  |
| **Пустые параметры полн.** | `name: () -> Void = () => { return ... }`              | Полная форма без параметров      |
| **Пустые параметры сокр.** | `name: () -> Void = { return ... }`                    | Опущен заголовок lambda          |
| **Пустые параметры мин.**  | `name = { return ... }`                                | Минимальная форма без параметров |

**Примечание**: значение блока кода `{ ... }` определяется **хвостовым выражением** (единственный
выход); `return` является нелокальным выходом типа `Never`, выходящим за ближайшую границу функции.
Форма выражения `= expr` напрямую задаёт значение. Подробнее см.
[RFC-010a](./010a-tail-expression-and-return.md).

**Примечание**: `->` является маркером типа функции, не может быть опущен (иначе будет распознано
как кортеж).

**Важно**: выражение `if` использует фигурные скобки `{}` для веток, ключевые слова `then/else` не
поддерживаются:

```yaoxiang
# Правильно: использование фигурных скобок
if n <= 1 { return 1 } else { return n * factorial(n - 1) }

# Неправильно: ключевые слова then/else не поддерживаются
# if n <= 1 then return 1 else return n * factorial(n - 1)
```

## Предложение

### Алгоритм HM и поддержка полиморфизма высших порядков

**Основная возможность**: алгоритм HM поддерживает полиморфизм высших порядков (Higher-rank
polymorphism) через аннотации обобщённых типов

**Принцип проектирования**:

- **Функции высших порядков**: при передаче функций как параметров требуются обобщённые ограничения
  на типы функций
- **Форма аннотации типа**: `(T: Type) -> ((f: (T) -> T, x: T) -> T)` — обобщённый параметр
  ограничивает тип функции
- **Рабочий процесс HM**: вывод типов функций через обобщённые параметры, реализация полиморфной
  композиции функций

**Пояснение примеров**:

```yaoxiang
# ✅ Поддержка полиморфизма высших порядков: обобщённые ограничения типа функции
call_twice: (T: Type) -> ((f: (T) -> T, x: T) -> T) = {
    return f(f(x))
}
# Использование: call_twice((x) => x + 1, 5)  # Выводится T=Int

compose: (A: Type, B: Type, C: Type) -> ((f: (B) -> C, g: (A) -> B, x: A) -> C) = {
    return f(g(x))
}
# Использование: compose((x) => x * 2, (x) => x + 1, 5)  # Выводится A=Int, B=Int, C=Int

# ❌ Не поддерживается: функции высших порядков без обобщённых ограничений
# bad_hof: (f, x) => f(f(x))  # HM не может вывести, отсутствует обобщённый параметр
```

**Процесс вывода по HM**:

1. Распознавание параметров функций высших порядков: `f: (T) -> T`
2. Создание обобщённого ограничения: `(T: Type)`
3. Вывод конкретных типов через конкретизацию обобщённых
4. Реализация полиморфной композиции функций

### Правила синтаксиса Lambda-выражений

**Важное правило**: значение блока кода `{ ... }` определяется **хвостовым выражением**
(единственный выход); `return` является нелокальным выходом типа `Never`, выходящим за ближайшую
границу функции. Форма выражения `= expr` напрямую задаёт значение. Подробнее см.
[RFC-010a](./010a-tail-expression-and-return.md).

| Синтаксическая форма | Синтаксис        | Выход значения                                  |
| -------------------- | ---------------- | ----------------------------------------------- |
| **Блок кода**        | `{ statements }` | Хвостовое выражение (пустой блок `{}` → `Void`) |
| **Форма выражения**  | `expression`     | Значение выражения                              |
| **`return`**         | `return e`       | Нелокальный выход из функции, тип `Never`       |

**Примеры**:

```yaoxiang
main: () -> Void = { println("Hello") }         # хвостовое выражение → Void
add: (a: Int, b: Int) -> Int = { a + b }        # хвостовое выражение даёт значение
empty: () -> Void = {}                          # пустой блок → Void

# Ранний возврат: использование return
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 }
    return n * factorial(n - 1)
}

# Форма выражения: напрямую задаёт значение
add: (a: Int, b: Int) -> Int = a + b            # правильно: форма выражения
main: () -> Void = println("Hello")               # правильно: форма выражения
```

**Ключевые идеи**:

1. Определение функций использует вывод типов по алгоритму HM, по возможности выводит, при
   невозможности — выдаёт явную ошибку
2. **Принцип работы алгоритма HM**: автоматический вывод типов через контекстную информацию
   (ограничения типов операторов, отношения вызовов функций и т.д.)
3. **Поддержка generics**: полиморфные функции используют синтаксис generics `(T: Type)` для явного
   ограничения параметров типа (RFC-010/011)
4. **Границы вывода**: тип возврата и локальные переменные выводятся; типы параметров функций с
   параметрами требуют явной аннотации (в сигнатуре или заголовке lambda)
5. Функции без параметров и без возврата используют `name: () -> Void = { ... }`, унифицировано с
   RFC-010
6. Старый синтаксис выводится из эксплуатации, предоставляется инструмент миграции

**Примеры вывода типов**:

```yaoxiang
# Обобщённые функции: явные параметры типа (унифицированный синтаксис RFC-010)
identity: (T: Type) -> ((x: T) -> T) = x
map: (T: Type, R: Type) -> ((f: (T) -> R, list: List(T)) -> List(R)) = {
    result = List(R)()
    for item in list { result.push(f(item)) }
    return result
}

# Полиморфные функции: определение через явные обобщённые ограничения (RFC-010/011)
add: (T: Add) -> ((a: T, b: T) -> T) = a + b
print_sum: (a: Int, b: Int) -> Void = { println(a + b) }  # выводится как (Int, Int) -> Void

# Полиморфизм высших порядков: реализация поддержки HM через обобщённые аннотации типов
call_twice: (T: Type) -> ((f: (T) -> T, x: T) -> T) = { return f(f(x)) }
compose: (A: Type, B: Type, C: Type) -> ((f: (B) -> C, g: (A) -> B, x: A) -> C) = { return f(g(x)) }
```

```yaoxiang
# === Определение функций: вывод типов по алгоритму HM ===

# Стандартная функция: HM выводит тип возврата (типы параметров требуют явного указания)
add = (a: Int, b: Int) => a + b            # выводится как (a: Int, b: Int) -> Int
main: () -> Void = { println("Hello") }                # выводится как () -> Void

# Частично явные параметры: HM выводит остальное
print_sum: (a: Int, b: Int) -> Void = { println(a + b) }  # выводится как (Int, Int) -> Void
greet: (name: String) -> Void = { println("Hello " + name) }  # выводится как (String) -> Void

# Обобщённые функции: явное ограничение полиморфных параметров типа (унифицированный синтаксис RFC-010)
identity: (T: Type) -> ((x: T) -> T) = x
map: (T: Type, R: Type) -> ((f: (T) -> R, list: List(T)) -> List(R)) = {
    # реализация функции map
    return List(R)()
}

# Рекурсивные функции: вывод через HM и рекурсивные ограничения
factorial: (n: Int) -> Int = {
    if n <= 1 { return 1 } else { return n * factorial(n - 1) }
}

# === Присваивание переменных: вывод типов по алгоритму HM ===

# Явный тип
x: Int = 42

# HM автоматически выводит Int
y = 42                               # выводится как Int

# HM автоматически выводит String
name = "YaoXiang"                    # выводится как String

# HM автоматически выводит Float
pi = 3.14159                         # выводится как Float
```

**Правила вывода типов по HM**:

| Сценарий                    | Синтаксис                                         | Можно опустить   | Пример                                         |
| --------------------------- | ------------------------------------------------- | ---------------- | ---------------------------------------------- |
| **Полная форма**            | `name: (a: Type, b: Type) -> Ret = (a, b) => ...` | ничего           | Полная сигнатура + заголовок lambda            |
| **Опущен заголовок lambda** | `name: (a: Type, b: Type) -> Ret = ...`           | заголовок lambda | Сигнатура объявляет параметры                  |
| **Опущена сигнатура**       | `name = (a: Type, b: Type) => ...`                | сигнатуру        | Заголовок lambda предоставляет типы параметров |
| **Опущен возвращаемый Ret** | `name: (a: Type, b: Type) -> = ...`               | тип возврата     | HM выводит тип возврата                        |
| **Пустые параметры полн.**  | `name: () -> Void = () => { ... }`                | ничего           | Полная форма без параметров                    |
| **Пустые параметры сокр.**  | `name: () -> Void = { ... }`                      | заголовок lambda | Опущено `() =>`                                |
| **Пустые параметры мин.**   | `name = { ... }`                                  | всё              | Минимальная форма без параметров               |
| **Присваивание переменной** | `name = value`                                    | тип              | HM выводит тип                                 |
| **Явная переменная**        | `name: Type = value`                              | ничего           | Явная аннотация типа                           |

**Ключевые принципы**:

- `->` является маркером типа функции, не может быть опущен (иначе будет распознано как кортеж)
- Тип возврата `Ret` можно опустить, HM выведет его из тела функции
- При наличии входных параметров типы параметров должны быть явно указаны (в сигнатуре или заголовке
  lambda хотя бы в одном месте)
- Остальные части можно опустить при возможности вывода и отсутствии неоднозначности
- Нет неявных преобразований типов, избегая хаоса как в JavaScript

## Детальное проектирование

### Раскрытие синтаксического сахара

Независимо от степени сокращения, всё最终规范化到 унифицированного промежуточного представления:

```rust
// Полная форма
add: (a: Int, b: Int) -> Int = (a, b) => a + b

// Раскрытие в IR
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    return a + b
};

// Опущен заголовок lambda
add: (a: Int, b: Int) -> Int = a + b

// Раскрыщение в IR (идентично полной форме)
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    return a + b
};

// Опущена сигнатура (заголовок lambda указывает типы параметров)
add = (a: Int, b: Int) => a + b

// Раскрытие в IR
let add: (Int, Int) -> Int = |a: Int, b: Int| -> Int {
    a + b
};
```

### Синтаксическое определение

```bnf
function_def ::= identifier ':' type_expr '=' expression
               | identifier '=' expression
               | identifier '=' block                    # Минимальная форма: без параметров, без возврата

identifier ::= [a-zA-Z_][a-zA-Z0-9_]*

type_expr ::= identifier                     # Ссылка на тип
       | '()'                          # Пустой тип
       | '(' parameters ')' '->' type_expr   # function type (имена параметров в сигнатуре)
       | type_expr '->' type_expr            # Простой function type
       | identifier '(' type_expr (',' type_expr)* ')'  # Применение типа

expression ::= '(' parameters ')' '=>' block
             | '(' ')' '=>' block
             | '(' parameters ')' '=>' expression

parameters ::= parameter (',' parameter)*
parameter ::= identifier                # type inference
            | identifier ':' type_expr      # Частично явный тип

block ::= '{' statement (',' statement)* '}'
        | expression

statement ::= identifier ':' expression  # Оператор присваивания
           | expression                  # Выражение-оператор (выполняется, но не возвращает)
           | 'return' expression         # Оператор возврата (возвращает указанное значение)

# Примечание: внутри блока кода для возврата значения необходимо использовать return; при отсутствии return по умолчанию возвращается Void
# Например: { return 1 + 1 } возвращает Int; { println("Hello") } возвращает Void
# Примечание: обобщённые параметры используют синтаксис (T: Type), являются частью функционального типа, отдельное BNF-правило не требуется
```

### Обработка ошибок

```yaoxiang
# === Примеры ошибок компиляции ===

# Ошибка 1: несоответствие возвращаемого типа блока кода
add: (a: Int, b: Int) -> Int = { println(a + b) }
// Ошибка: в блоке нет return, по умолчанию Void, но сигнатура ожидает Int
// Правильно: add: (a: Int, b: Int) -> Int = a + b
// Или: add: (a: Int, b: Int) -> Int = { return a + b }

# Ошибка 2: использование необъявленного параметра типа
identity: (x: T) -> T = x
// Ошибка: T не объявлен; необходим явный обобщённый параметр (RFC-010)
// Правильно: identity: (T: Type) -> ((x: T) -> T) = x

# Правильно: HM выводит тип возврата
double = (x: Int) => x + x

# Полная форма (последовательное сокращение)
double: (x: Int) -> Int = (x) => x + x                # полная
double: (x: Int) -> Int = x + x                       # опущен заголовок lambda
double = (x: Int) => x + x                            # опущен тип возврата (HM выводит возврат)
# double = (x) => x + x                               # ❌ Нельзя опускать типы параметров с обеих сторон
```

## Компромиссы

### Преимущества

- **Унификация синтаксиса**: модель `name: Signature = LambdaBody` охватывает все сценарии
- **Гибкие сокращения**: любая часть может быть опущена при возможности вывода по HM
- **Типовая безопасность**: алгоритм HM гарантирует типобезопасность, отсутствие неявных
  преобразований типов
- **Поддержка рекурсии**: HM и рекурсивные ограничения автоматически выводят типы
- **Нулевая нагрузка**: плавный переход от полной к минимальной форме

### Недостатки

- **Стоимость миграции**: старый код требует инструмента конвертации
- **Стоимость обучения**: необходимо понимать модель «полная форма + произвольные сокращения»

## Альтернативные решения

| Решение                       | Описание                                          | Почему не выбрано                                                     |
| ----------------------------- | ------------------------------------------------- | --------------------------------------------------------------------- |
| Вывод типов по HM             | Использование алгоритма Hindley-Milner для вывода | ✅ **Принято**, стандарт современных функциональных языков            |
| Явные типы везде              | Все типы должны быть явно написаны                | Противоречит принципу упрощения синтаксиса, увеличивает шаблонный код |
| Сохранение старого синтаксиса | Поддержка обоих синтаксисов                       | Расщепление синтаксиса, высокая стоимость поддержки                   |
| Ключевое слово fn             | Введение fn для различения функций и переменных   | Противоречит принципу «функция есть lambda»                           |

## Стратегия реализации

### Фазы

1. **Фаза 1: Синтаксический анализ и алгоритм HM** (v0.3)
   - Реализация нового синтаксиса `name = lambda` + вывод типов по алгоритму HM
   - Реализация заполнения по умолчанию для функций без параметров и без возврата

2. **Фаза 2: Инструмент миграции** (v0.3)
   - Разработка инструмента `yaoxiang-migrate --old-to-new`
   - Автоматическая конвертация кода со старым синтаксисом

3. **Фаза 3: Верификация и документация** (v0.3)
   - Проверка завершения миграции старого кода
   - Обновление документации

### Инструмент миграции

```bash
# Миграция одного файла
yaoxiang-migrate --old-to-new src/main.yaoxiang

# Миграция всего проекта
yaoxiang-migrate --old-to-new --recursive src/

# Предпросмотр миграции (без изменения файлов)
yaoxiang-migrate --old-to-new --dry-run src/main.yaoxiang
```

Правила миграции:

```yaoxiang
# Старый синтаксис
add(Int, Int) -> Int = (a, b) => { a + b }
main() -> Int = { println("Hello"); 0 }
main() = { println("Hello") }

# === Новый синтаксис: полная форма (полная сигнатура + полный заголовок lambda) ===
add: (a: Int, b: Int) -> Int = (a, b) => a + b
main: () -> Void = () => { println("Hello") }

# === Сокращение: опущен заголовок lambda ===
add: (a: Int, b: Int) -> Int = a + b
main: () -> Void = { println("Hello") }

# === Сокращение: вывод по HM ===
add = (a: Int, b: Int) => a + b              # выводится как (a: Int, b: Int) -> Int
main: () -> Void = { println("Hello") }                  # выводится как () -> Void

# === Минимальная форма ===
main: () -> Void = {                                      # эквивалентно main: () -> Void = { ... }
    println("Hello")
}
```

### Зависимости

- Нет внешних зависимостей
- Может быть реализовано независимо

### Риски

| Риск                 | Влияние                            | Меры снижения                                                                |
| -------------------- | ---------------------------------- | ---------------------------------------------------------------------------- |
| Пропуск при миграции | Старый код не компилируется        | Предоставление инструмента миграции, охват всех паттернов старого синтаксиса |
| Ошибки парсера       | Нестабильный синтаксический анализ | Достаточное покрытие тестами                                                 |

## Открытые вопросы

> Следующие вопросы уже решены в процессе проектирования, записаны в Приложении A.

- ~~Q1: Следует ли сохранить сверхминимальную запись `main() = body`?~~ → Решено: сохранено как
  `main: () -> Void = { ... }`
- ~~Q2: Сохраняется ли `:` после имени функции?~~ → Решено: опционально; но функции с параметрами
  всё ещё требуют аннотации типов параметров в сигнатуре или заголовке lambda
- ~~Q3: Поддерживает ли HM вывод типов параметров?~~ → Решено: возврат/локальные переменные
  выводятся; типы параметров функций с параметрами требуют явной аннотации
- ~~Q4: Вводится ли ключевое слово `fn`?~~ → Решено: не вводится, функция есть lambda
- ~~Q5: Какова стратегия миграции старого кода?~~ → Решено: предоставлен инструмент
  `yaoxiang-migrate`
- ~~Q6: Как использовать обобщённые функции?~~ → Решено: унифицированный синтаксис RFC-010
  `(T: Type)`

| Scala        | `def add(a: Int, b: Int): Int = { ... }`            | Ключевое слово def                       |
| **YaoXiang** | `name = (a: Int, b: Int) => a + b`                  | **Функция = lambda, HM выводит возврат** |
