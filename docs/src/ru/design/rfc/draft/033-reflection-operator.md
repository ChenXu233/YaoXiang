# RFC-033: Оператор рефлексии `^^`

> **Справка**:
>
> - [RFC-010: Унифицированный синтаксис типов — модель name: type = value](../accepted/010-unified-type-syntax.md)
> - [RFC-011: Проектирование обобщённой системы типов](../accepted/011-generic-type-system.md)
> - [RFC-027: Предикаты времени компиляции и унифицированная статическая проверка](../accepted/027-compile-time-evaluation-types.md)
> - [RFC-011a: Реализация интерфейсов и динамическая диспетчеризация](../accepted/011a-interface-implementation.md)

## Аннотация

В данном документе предлагается введение оператора `^^` в качестве точки входа для рефлексии, позволяющей получать метаданные типов и значений. `^^T` возвращает статический объект метаданных типа `T`, а `^^obj` возвращает динамические метаданные типа значения `obj`. Объект метаданных представляет собой обычный тип записи, содержащий информацию о имени, параметрах, полях и т. д., который можно использовать во время компиляции и выполнения.

## Мотивация

### Зачем нужна эта возможность?

1. **Сериализация/десериализация**: требуется доступ к информации о полях типа для автоматической генерации кода сериализации
2. **Метапрограммирование во время компиляции**: требуется доступ к структуре типа во время компиляции для генерации кода или проверки ограничений
3. **Отладка и инструменты во время выполнения**: требуется вывод информации о типе во время выполнения для помощи в отладке
4. **Проверка типов во время выполнения**: требуется определение отношений типов во время выполнения, например, «к какому типу относится obj?»

### Текущая проблема

В настоящее время в YaoXiang отсутствует механизм рефлексии, не позволяющий получить доступ к метаданным типов ни во время компиляции, ни во время выполнения. Если напрямую использовать `.name`, `.fields` для доступа к метаданным типа, это приведёт к конфликту с определёнными пользователем полями:

```yaoxiang
Person: Type = { name: String, age: Int }

# Если Person.name — это имя метаданных типа или поле name?
# Это приведёт к сложностям разбора и семантической путанице
```

Необходим синтаксис, **не затрагивающий пространство имён обычных полей**, для доступа к метаданным типа.

## Предложение

### Основной замысел

Вводится оператор `^^` в качестве точки входа для рефлексии, чётко разделяющий обычный код и запросы метаданных.

**Два варианта использования**:

1. **Статическая рефлексия (действует на тип)**: `^^T` возвращает статический объект метаданных типа `T`
2. **Динамическая рефлексия (действует на значение)**: `^^obj` возвращает динамические метаданные типа значения `obj`

**Структура метаданных**:

```yaoxiang
TypeMeta: Type = {
    name: String,
    params: Array(ParamMeta),
    fields: Array(FieldMeta),
    return_type: Type,
    refinement: Option(Expr)  # На этапе компиляции Some(Expr), во время выполнения None
}

ParamMeta: Type = {
    name: String,
    type: Type
}

FieldMeta: Type = {
    name: String,
    type: Type
}
```

**Уровень вселенной**: если `T: Type_n`, то `^^T: Type_{n+1}`, что соответствует стандартному правилу повышения уровня вселенной в теории типов.

**Приоритет**: `^^` — унарный префиксный оператор с наивысшим приоритетом. `^^T.name` эквивалентно `(^T).name`.

### Примеры

#### Базовое использование

```yaoxiang
Point: Type = { x: Float, y: Float }

# Статическая рефлексия
meta = ^^Point
print(meta.name)           # "Point"
print(meta.fields.len)     # 2
print(meta.fields[0].name) # "x"
print(fields[0].type)      # Float

# Динамическая рефлексия (требуется включение рефлексии во время выполнения)
obj = Point(1.0, 2.0)
meta = ^^obj
print(meta.name)           # "Point"
```

#### Обобщённые типы

```yaoxiang
List: (T: Type) -> Type = { data: Array(T), length: Int }

# Рефлексия обобщённого типа как такового
meta = ^^List
print(meta.name)           # "List"
print(meta.params)         # [{ name: "T", type: Type }]

# Рефлексия конкретного инстанцированного типа
meta = ^^List(Int)
print(meta.name)           # "List(Int)"
print(meta.params)         # []
```

#### Функции

```yaoxiang
add: (a: Int, b: Int) -> Int = a + b

meta = ^^add
print(meta.name)           # "add"
print(meta.params)         # [{ name: "a", type: Int }, { name: "b", type: Int }]
print(meta.return_type)    # Int
```

#### Уточнённые типы

```yaoxiang
Positive: (x: Int) -> Type = { x > 0 }

# Во время компиляции: refinement равен Some(Expr)
meta = ^^Positive
print(meta.name)           # "Positive"
print(meta.refinement)     # Some(AST(x > 0))

# Во время выполнения: refinement равен None (стирание)
```

#### Использование в предикатах времени компиляции

```yaoxiang
# Проверка наличия полей у типа
HasFields: (T: Type) -> Type = { ^^T.fields.len > 0 }

# Проверка типа поля
HasFloatField: (T: Type) -> Type = {
    exists field in ^^T.fields: field.type == Float
}

# Использование
obj: HasFields(Point) = Point(1.0, 2.0)  # ✅ Проверка пройдена
# obj: HasFields(Int) = 42  # ❌ Проверка не пройдена
```

#### Пример сериализации

```yaoxiang
# Чистая функция времени компиляции: генерация JSON-строки
to_json: (T: Type) -> ((obj: T) -> String) = {
    meta = ^^T
    parts: Array(String) = []
    for field in meta.fields {
        # Генерация кода доступа к полю на этапе компиляции
        parts.push("\"${field.name}\": ${obj.${field.name}}")
    }
    return "{" + parts.join(", ") + "}"
}

# Использование
point_to_json = to_json(Point)
print(point_to_json(Point(1.0, 2.0)))  # '{"x": 1.0, "y": 2.0}'
```

### Синтаксические изменения

| До                       | После                             |
| ------------------------ | --------------------------------- |
| Без механизма рефлексии  | `^^T` получение метаданных типа  |
| Без механизма рефлексии  | `^^obj` получение метаданных динамического типа значения |

## Подробный дизайн

### Влияние на систему типов

- **Новые типы**: `TypeMeta`, `ParamMeta`, `FieldMeta`
- **Уровень вселенной**: тип, возвращаемый `^^T`, на один уровень выше, чем `T`
- **Взаимодействие с обобщениями**: поддерживаются как `^^List`, так и `^^List(Int)`
- **Взаимодействие с функциями**: `^^add` возвращает метаданные функции (включая параметры и тип возвращаемого значения)
- **Взаимодействие с уточнёнными типами**: `^^Positive` возвращает метаданные уточнённого типа (включая выражение уточнения)

### Поведение во время выполнения

**Рефлексия на этапе компиляции**:

- `^^T` полностью вычисляется во время компиляции, результат встраивается как константа
- Выражение уточнения доступно во время компиляции

**Рефлексия во время выполнения**:

- По умолчанию отключена, нулевые накладные расходы
- Включается через параметр компиляции `--enable-runtime-reflection`
- После включения `^^obj` возвращает динамические метаданные типа
- Выражение уточнения стирается в `None` во время выполнения

**Генерация по запросу + treeshake**:

- Метаданные генерируются только для тех типов, в которых фактически используется `^^`
- Для неиспользуемых типов метаданные не генерируются (treeshake)

### Изменения в компиляторе

1. **Лексический анализатор**: распознавание `^^` как одного токена
2. **Синтаксический анализатор**: добавление правила для префиксного выражения `^^`
3. **Система типов**: добавление определений типов `TypeMeta`, `ParamMeta`, `FieldMeta`
4. **Проверка типов**: генерация экземпляра метаданных для каждого типа
5. **Вычислитель времени компиляции**: поддержка вычисления `^^T` во время компиляции
6. **Время выполнения (опционально)**: генерация RTTI для типов с рефлексией

### Обратная совместимость

- ✅ Влияние на существующий синтаксис отсутствует: `^^` — новый оператор, не конфликтующий с существующим синтаксисом
- ✅ Влияние на существующие типы отсутствует: все типы автоматически поддерживают `^^`
- ✅ Влияние на существующие функции отсутствует: функции могут использовать `^^`, но это не обязательно
- ✅ Влияние на предикаты времени компиляции отсутствует: `^^T` в предикатах ведёт себя как обычное содержимое
- ✅ Влияние на время выполнения отсутствует: рефлексия во время выполнения отключена по умолчанию, нулевые накладные расходы

## Компромиссы

### Преимущества

- **Единообразие**: функции, обобщения и уточнённые типы обрабатываются унифицированно
- **Нулевые накладные расходы**: рефлексия во время компиляции полностью стирается, рефлексия во время выполнения опциональна
- **Интеграция с существующей системой**: бесшовная интеграция с предикатами времени компиляции (RFC-027)
- **Простота**: `^^` — чистый символ, не конфликтующий с идентификаторами, определёнными пользователем
- **Генерация по требованию**: оптимизация treeshake, нулевые накладные расходы для неиспользуемых типов

### Недостатки

- **Кривая обучения**: необходимо понимать семантику `^^` и структуру метаданных
- **Накладные расходы во время выполнения**: при включении рефлексии во время выполнения увеличиваются затраты памяти (один указатель на каждый экземпляр)
- **Сложность реализации**: требуется изменение нескольких компонентов компилятора

## Альтернативы

| Решение             | Причина отклонения                                           |
| ------------------- | ------------------------------------------------------------ |
| Функция `reflect(T)` | Вводит дополнительный идентификатор в область видимости, может быть перекрыт пользователем |
| Функция `type_info(T)` | Аналогично выше                                              |
| Одиночный оператор `^` | Возможен конфликт с побитовыми операциями; именно из-за конфликта в C++26 и выбрали `^^` |
| Символы `@@`, `##` и др. | Не имеют прецедентов; `^^` легче объяснить                  |

## Этапы реализации

| Этап      | Содержание                            | Зависимость   |
| --------- | ------------------------------------- | ------------- |
| Phase 1   | Разбор оператора `^^` во время компиляции | Нет           |
| Phase 2   | Определение структуры данных `TypeMeta`   | Phase 1       |
| Phase 3   | Генерация метаданных во время компиляции | Phase 2       |
| Phase 4   | Поддержка рефлексии во время выполнения (опционально) | Phase 3       |
| Phase 5   | Интеграция с предикатами времени компиляции | Phase 3       |

### Зависимости

```
Phase 1 (разбор)
    ↓
Phase 2 (структуры данных)
    ↓
Phase 3 (метаданные времени компиляции)
    ↓
    ├────────────┐
    ↓            ↓
Phase 4        Phase 5
(рефлексия    (предикаты
 выполнения)  компиляции)
```

### Риски

- **Конфликт при разборе**: `^^` может конфликтовать с существующим синтаксисом (после анализа конфликтов нет)
- **Влияние на производительность**: генерация метаданных во время компиляции может увеличить время компиляции (оптимизация treeshake помогает)
- **Накладные расходы во время выполнения**: при включении рефлексии во время выполнения увеличиваются затраты памяти (генерация по требованию снижает нагрузку)

## Открытые вопросы

- [x] Область действия `^^`: действует только на типы и значения, не на выражения
- [x] Цепочечный доступ: поддерживается, возвращаемые метаданные `^^T` можно использовать для обычного доступа к свойствам
- [x] Сопоставление с образцом: поддерживается, `TypeMeta` — обычный тип записи, можно использовать сопоставление с образцом
- [x] Сравнение: поддерживается, объекты метаданных одного типа равны
- [x] Накладные расходы памяти: генерация по требованию + оптимизация treeshake
