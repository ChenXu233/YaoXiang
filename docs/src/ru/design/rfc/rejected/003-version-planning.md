# RFC-003: Планирование версий

> **Дата отклонения**: 2026-06-01

## ⚠️ Причина отклонения

**Данный RFC не соответствует спецификации RFC и был отклонён.**

### Анализ проблем

| Проблема                         | Описание                                                                                                                                         |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Неверный тип документа**       | RFC — это документ решений о том, «почему так спроектировано», а данная статья — документ управления проектом о том, «где мы сейчас и куда идём» |
| **Отсутствие проектных решений** | Нет анализа компромиссов при выборе технологий, нет сравнения альтернативных вариантов, нет обоснований дизайна                                  |
| **Чрезмерное планирование**      | Запланировано 9 версий (v0.1-v1.0), но выполнено только 1.5, всё после v0.3 — лишь предположения                                                 |
| **Высокая стоимость поддержки**  | Таблица показателей успеха содержит 50 состояний, что сложно поддерживать                                                                        |
| **Путаница в нумерации версий**  | Пропущен v0.8 без объяснения причин                                                                                                              |

### Правильный тип документа

Данный документ следует вести как **дорожную карту проекта (Roadmap)**, а не как RFC. Дорожная карта
фиксирует факты и кракосрочные планы, RFC записывает проектные решения.

> **Ниже приведено исходное содержимое, сохранённое для справки.**

## Краткое содержание

План выпуска версий YaoXiang — дорожная карта от v0.1 до v1.0.

**Основные цели**:

1. **Компиляция в байт-код**: поддержка REPL и инкрементальной компиляции
2. **Самокомпиляция (Bootstrap)**: написание компилятора YaoXiang на YaoXiang
3. **AOT-компиляция**: компиляция байт-кода в машинный код для целевой платформы

## 一、Мотивация

### Зачем нужно планирование версий?

1. **Управление проектом**: разбиение целей на выполнимые вехи
2. **Ожидания пользователей**: информирование пользователей об этапах развития языка
3. **Распределение ресурсов**: определение приоритетов на каждом этапе
4. **Контроль рисков**: своевременное выявление проблем и корректировка направления

### Ключевые проектные решения

- **Приоритет байт-кода**: сначала реализуем интерпретацию, затем AOT
- **Поэтапная поставка**: каждая версия содержит работающий функционал
- **Обратная совместимость**: до v1.0 API может изменяться, но с предварительным уведомлением
- **Валидация через самокомпиляцию**: доказательство выразительности языка через самокомпиляцию
- **Послойная оптимизация производительности**: сначала запустить, затем оптимизировать

## 四、Трёхуровневая стратегия компиляции

| Уровень            | Версия | Вход                  | Выход           | Описание                    |
| ------------------ | ------ | --------------------- | --------------- | --------------------------- |
| L1: Байт-код       | v0.1+  | Исходный код (.yx)    | Байт-код (.yxb) | Интерпретация VM            |
| L2: Самокомпиляция | v0.9+  | Исходный код YaoXiang | Байт-код        | Компилирует сам себя        |
| L3: AOT            | v1.0+  | Исходный код/байт-код | Машинный код    | Нативная производительность |

**Обоснование приоритета байт-кода**:

1. **Поддержка REPL**: компиляция вводимого кода на лету, интерактивная разработка
2. **Инкрементальная компиляция**: изменение одной функции требует перекомпиляции только этой части
3. **Кроссплатформенность**: файлы .yxb работают на разных платформах, нужен только VM для целевой
   платформы

## 五、Стратегия зависимостей

**Краткосрочная перспектива**: Вызов библиотек Rust с crates.io (Cargo как основа)

**Текущие зависимости**:

- Параллелизм: parking_lot, crossbeam, rayon
- Структуры данных: indexmap, hashbrown, smallvec
- Сетевые: tokio
- Сериализация: serde, ron

**Долгосрочная перспектива**: Собственная стандартная библиотека и менеджер пакетов
