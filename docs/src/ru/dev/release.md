# Шаблон выпуска

> Команда `/release` генерирует changelog по этому шаблону.  
> changelog — это **описание изменений для людей**, а не список коммитов.

## Правила форматирования

```
:bookmark: V<номер_версии>: <заголовок>
```

| Изменение версии    | `<старая>` → `<новая>` |
| Количество коммитов | N коммитов             |

## 📋 Краткое описание обновления

Данный выпуск сосредоточен на стабилизации системы типов и модели владения. Инстанцирование generics
типов (например, `List(Int) = List(1, 2, 3)`) теперь работает корректно, исправлены многочисленные
граничные случаи доступа к полям `&T` и деструктуризации кортежей. Также выполнена унификация
проверок владения, что закладывает основу для доработки семантики move.

## ✨ Новые функции

### Инстанцирование generics типов

Поддержка синтаксиса `List(Int) = List(1, 2, 3)`, конструкторы типов корректно регистрируются как
Struct. При множественных вызовах generic функций вывод типов больше не конфликтует, каждый вызов
получает независимый экземпляр переменной типа.

- Регистрация конструкторов типов как Struct, исправление корневой причины инстанцирования
- Независимый вывод типов при множественных вызовах generic функций
- Исправление привязки методов интерфейса

### Перепривязка после Move

После перемещения переменной можно выполнить перепривязку к новому значению, поиск в порядке
присваивания теперь корректно обрабатывает состояние moved, исключая ложные сообщения "переменная
уже перемещена".

- Добавлен флаг состояния moved в VarInfo
- Добавлена ветка moved при поиске в порядке присваивания

### Resource marker trait

Добавлен новый `Resource` marker trait для типов с побочными IO-эффектами. Служит основой для
последующего отслеживания побочных эффектов и анализа безопасности конкурентности.

### PLDI SRC demo

Выполнены все задачи MVP для PLDI SRC demo, включая демонстрацию сквозной проверки типов и генерации
кода.

## 🐛 Исправления ошибок

### Доступ к полям &T

Исправлены многочисленные проблемы проверки типов при доступе к полям неизменяемых ссылочных типов,
включая присваивание полей и вывод типов при вызове конструкторов через ссылку.

- Исправление проверки типов при доступе к полям `&T`
- Вывод целевого типа для присваивания полей
- Вывод типов при вызове конструкторов через ссылку

### Семантическая подсветка в LSP

Исправлено отсутствие семантической подсветки для переменных внутри блоков `spawn {}` и
деструктуризации кортежей `(a, b) = ...`. Теперь `DestructureAssign.names` в AST содержит информацию
о позиции для каждого имени переменной.

- Корректная подсветка переменных внутри spawn блоков
- Корорректная подсветка имён переменных при деструктуризации кортежей
- Заложена основа для поддержки LSP при семантике move

### Удаление freeze

Удалена устаревшая функция `freeze`, очищены связанные тестовые случаи.

## ♻️ Рефакторинг и оптимизация

### Унификация диагностической системы

Оставшиеся 5 enum ошибок перенесены в унифицированную систему диагностики `ErrorCodeDefinition`,
покрытие ошибками увеличено с 60% до 80%. Все ошибки компиляции теперь следуют единому формату и
соглашениям об кодах ошибок.

### Унификация проверок владения

Разрозненная логика проверок владения унифицирована в `OwnershipPass`, единая точка входа для
проверок borrow, move и времени жизни. Снижена стоимость сопровождения, повышена согласованность
сообщений об ошибках.

### Упрощение модели конкурентности

Удалена система ограничений Send/Sync, `spawn {}` переработана в модель группового выполнения.
Удалён код декораторов `@block`/`@eager`/`@auto` (RFC-024 phase 1). Упрощена модель конкурентности,
подготовлена основа для расширяемых конкурентных примитивов.
