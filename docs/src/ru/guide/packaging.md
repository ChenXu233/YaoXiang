# Менеджер пакетов

Встроенный в YaoXiang менеджер пакетов, предоставляющий полный набор функций управления
зависимостями.

## Обзор

YaoXiang Package Manager (YPM) использует декларативное управление зависимостями:

- Объявление зависимостей проекта в `yaoxiang.toml`
- `yaoxiang.lock` фиксирует точные версии, обеспечивая воспроизводимость сборки
- Зависимости загружаются в каталог `vendor`

## Быстрый старт

```bash
# 创建新项目
yx init my-project
cd my-project

# 添加依赖
yx add http
yx add json

# 安装依赖
yx install

# 运行项目
yx run src/main.yx
```

## Структура проекта

```
my-project/
├── yaoxiang.toml      # 项目清单
├── yaoxiang.lock      # 依赖锁定文件
├── vendor/            # 依赖存储
└── src/
    └── main.yx
```

## init

Инициализирует новый проект.

### Использование

```bash
yx init <name>
```

### Параметры

| Параметр | Тип    | Описание    |
| -------- | ------ | ----------- |
| `name`   | string | Имя проекта |

### Описание

Создаёт новый проект YaoXiang в текущем каталоге или по указанному пути.

### Создаваемые файлы

- `yaoxiang.toml` — Манифест проекта
- `yaoxiang.lock` — Файл блокировки зависимостей
- `src/main.yx` — Файл точки входа
- `.gitignore` — Конфигурация игнорирования Git

### Примеры

```bash
# 在当前目录创建项目
yx init my-project

# 输出
# ✨ 项目已创建：my-project
#   my-project/yaoxiang.toml
#   my-project/yaoxiang.lock
#   my-project/src/main.yx
#   my-project/.gitignore
```

## add

Добавляет зависимость в проект.

### Использование

```bash
yx add <name> [version]
yx add <name> --dev
```

### Параметры

| Параметр  | Тип    | Описание                                       |
| --------- | ------ | ---------------------------------------------- |
| `name`    | string | Имя пакета                                     |
| `version` | string | Номер версии (необязательно, по умолчанию `*`) |

### Опции

| Опция         | Описание                     |
| ------------- | ---------------------------- |
| `--dev`, `-D` | Добавить как dev-зависимость |

### Описание

Добавляет зависимость в файл `yaoxiang.toml` проекта и обновляет `yaoxiang.lock`.

### Спецификация версий

| Спецификация | Описание           | Пример             |
| ------------ | ------------------ | ------------------ |
| `*`          | Любая версия       | `http = "*"`       |
| `1.0.0`      | Точная версия      | `http = "1.0.0"`   |
| `>=1.0.0`    | Минимальная версия | `http = ">=1.0.0"` |
| `~1.0.0`     | Совместимая версия | `http = "~1.0.0"`  |
| `^1.0.0`     | Caret-версия       | `http = "^1.0.0"`  |

### Источники зависимостей

#### Registry (по умолчанию)

```bash
yx add http
yx add http 1.0.0
```

#### Git-репозиторий

```bash
# 会在 manifest 中生成如下配置
# http = { version = "1.0.0", git = "https://github.com/example/http" }
```

#### Локальный путь

```bash
# 会在 manifest 中生成如下配置
# mylib = { version = "0.1.0", path = "./mylib" }
```

### Примеры

```bash
# 添加最新版本
yx add http

# 添加指定版本
yx add http 1.0.0

# 添加版本范围
yx add json ">=2.0.0"

# 添加开发依赖
yx add test-utils --dev
yx add benchmark -D
```

## rm

Удаляет зависимость из проекта.

### Использование

```bash
yx rm <name>
yx rm <name> --dev
```

### Параметры

| Параметр | Тип    | Описание   |
| -------- | ------ | ---------- |
| `name`   | string | Имя пакета |

### Опции

| Опция         | Описание                |
| ------------- | ----------------------- |
| `--dev`, `-D` | Удалить dev-зависимость |

### Описание

Удаляет указанную зависимость из `yaoxiang.toml` проекта и обновляет `yaoxiang.lock`.

### Примеры

```bash
# 移除运行时依赖
yx rm http

# 移除开发依赖
yx rm test-utils --dev
```

## install

Устанавливает зависимости проекта.

### Использование

```bash
yx install
```

### Описание

Читает объявления зависимостей из `yaoxiang.toml` и выполняет следующие действия:

1. Разрешает версии зависимостей
2. Обнаруживает конфликты версий
3. Загружает зависимости в каталог `vendor`
4. Генерирует/обновляет `yaoxiang.lock`

### Поведение

- Если зависимостей нет, выводит подсказку и завершает работу
- Если каталог `vendor` уже существует, проверяет и использует кэш
- При обнаружении конфликта версий выводит сообщение об ошибке и завершает работу

### Примеры

```bash
# 安装所有依赖
yx install

# 输出
# 📦 正在解析依赖...
#   http (1.0.0) [已安装]
#   json (2.0.0) [已缓存]
# ✅ 依赖已安装，锁文件已更新
```

### Обновление файла блокировки

Команда `install` обновляет `yaoxiang.lock`:

```toml
# yaoxiang.lock
[package]
version = 1

[package.http]
version = "1.0.0"
source = "registry"

[package.json]
version = "2.0.0"
source = "registry"
```

## update

Обновляет зависимости проекта.

### Использование

```bash
yx update
yx update <name>
```

### Параметры

| Параметр | Тип    | Описание                   |
| -------- | ------ | -------------------------- |
| `name`   | string | Имя пакета (необязательно) |

### Описание

### Полное обновление

Без аргументов обновляет все зависимости:

1. Очищает текущие зафиксированные версии
2. Удаляет старые версии из каталога `vendor`
3. Заново загружает все зависимости
4. Обновляет `yaoxiang.lock`

### Обновление одной зависимости

С аргументом обновляет только указанную зависимость:

1. Удаляет старую версию из `vendor`
2. Заново загружает новую версию
3. Обновляет соответствующую запись в `yaoxiang.lock`
4. Остальные зависимости не затрагиваются

### Примеры

```bash
# 更新所有依赖
yx update

# 输出
# 📦 正在更新依赖...
#   http (1.0.0 → 1.1.0)
#   json (2.0.0 → 2.1.0)
# ✅ 已更新 2 个依赖，锁文件已更新

# 更新单个依赖
yx update http

# 输出
# ✅ 已更新 http (1.0.0 → 1.1.0)
```

## list

Выводит список зависимостей проекта.

### Использование

```bash
yx list
```

### Описание

Отображает все зависимости проекта, включая:

- Зависимости времени выполнения (из `[dependencies]`)
- Зависимости разработки (из `[dev-dependencies]`)
- Версию и источник каждой зависимости

### Примеры

```bash
yx list

# 输出
# 📦 项目依赖
#
# 运行时依赖:
#   http        1.0.0    registry
#   json        2.0.0    registry
#
# 开发依赖:
#   test-utils  0.5.0    registry
```

## Файлы конфигурации

### yaoxiang.toml

Файл манифеста проекта, объявляющий метаданные проекта и зависимости.

```toml
[package]
name = "my-project"
version = "0.1.0"
description = "项目描述"
authors = ["作者 <email@example.com>"]
license = "MIT"

[dependencies]
http = "1.0.0"
json = "*"

[dev-dependencies]
test-utils = "0.5.0"
```

### yaoxiang.lock

Файл блокировки зависимостей, автоматически генерируемый менеджером пакетов.

```toml
# 由 YaoXiang 包管理器自动生成

[package]
version = 1

[package.http]
version = "1.0.0"
source = "registry"
```

## Ключевые концепции

### Зависимости времени выполнения vs зависимости разработки

- **Зависимости времени выполнения** (`[dependencies]`): пакеты, необходимые для работы проекта
- **Зависимости разработки** (`[dev-dependencies]`): пакеты, необходимые только при разработке и
  тестировании

### Источники зависимостей

| Тип      | Пример конфигурации                          | Описание                                    |
| -------- | -------------------------------------------- | ------------------------------------------- |
| Registry | `http = "1.0.0"`                             | Получение из удалённого репозитория пакетов |
| Git      | `{ version = "1.0.0", git = "https://..." }` | Получение из Git-репозитория                |
| Path     | `{ version = "0.1.0", path = "./lib" }`      | Получение из локального пути                |

### Файл блокировки

`yaoxiang.lock` автоматически генерируется менеджером пакетов. **Обязательно зафиксируйте его в
системе контроля версий**:

- Гарантирует, что все участники команды используют одинаковые версии зависимостей
- Гарантирует воспроизводимость CI-сборок
- Избегает проблемы «у меня на машине работает»

### Каталог vendor

Зависимости после загрузки хранятся в каталоге `vendor`:

- Автоматически управляется командами `yx install` и `yx update`
- Можно удалить и пересоздать, повторно запустив `install`
- Рекомендуется добавить в `.gitignore`, чтобы каждый участник команды управлял им независимо

## Часто задаваемые вопросы

### Q: Что делать при конфликте версий зависимостей?

YPM обнаружит конфликт версий зависимостей и сообщит об ошибке. Решения:

1. Скорректировать требования к версиям зависимостей
2. Дождаться исправления от автора зависимости
3. Рассмотреть удаление конфликтующей зависимости

### Q: Как использовать приватные пакеты?

Для приватных пакетов можно использовать Git-источник:

```bash
# 通过 Git URL 添加
# 手动编辑 yaoxiang.toml
[dependencies]
private-pkg = { version = "1.0.0", git = "https://github.com/org/private-pkg" }
```

### Q: Можно ли удалить каталог vendor?

Да. После удаления выполните `yx install`, чтобы заново загрузить все зависимости.

### Q: Как посмотреть информацию о пакете?

Используйте `yx list` для просмотра всех зависимостей или откройте `yaoxiang.toml`.
