> **Subsidiary Design Document**. This document is a subsidiary of
> [RFC-039 Compiler Architecture Refactoring](../../rfc/accepted/039-compiler-architecture.md),
> expanding the phase sequence in the RFC into **independently committable, independently
> verifiable** three-level tasks.
>
> Phase order and acceptance gates take RFC-039 main text as the sole authority; this document only
> handles decomposition to executable granularity and registers unresolved conflicts.

## Target Design: Phase Sequence

```
P0  Repository maintenance mechanism and code placement rules     08        ← New, rules first
P1  Revive orphan tests and fix defects           06 §S1
P2  Establish equivalence criterion baseline             07 entire
P3  Fix correctness vulnerabilities (minimal solution)        02 §S3-Vulnerability half
P4  Stage contract and unified Driver          02
P5  checker in-file split             02 + this document
P6  Type representation unification                 03
P7  Intermediate representation SSA-ification                04      } Can run in parallel
P8  Frontend paradigm change                   05      }
P9  Anti-rebound gates (including unified script list)     01 §Anti-rebound + 08 §Machine-checkable rules
P10 Other cleanup and status corrections             06 §S2/S3/S4/S5/S6
```

**Reason for adding P0**: Three prohibitions (no fabrication / no endless padding / should refactor
but applied a patch) constrain every action in P1–P10. Rules must be established before starting
work, otherwise when P1 revives tests, `mod` declarations are already being added to `tests/mod.rs`
— which is the cause of the G4 conflict.

## Key Decisions and Rationale

- **P0 independent as phase not merged into P9** — gate is "post-hoc check", rules are
  "pre-judgment". P9's scripts cannot prevent "should refactor but applied patch", only D0–D4's
  review checklist can.
- **P9 as sole authoritative list of CI scripts** — original gap G3's three coexisting lists led to
  inability to finalize. After this table's merge 10 scripts each attributed to one phase,
  report-only and switch-to-hard timing explicit and queryable.
- **P3.5 incorporates RFC-029g not "independent track, wait for after refactor"** — its deletion
  surface overlaps with P4/P5/P6/P7/P8's rewrite surface (RFC-039 D56). Leaving for after refactor
  equals redoing same batch of deletion on new grammar, new checker layout, new IR; this is same
  lesson as 7e incorporating `2315`/`2341`, S4 incorporating RFC status correction.
- **P5's steps completed by this document not merged into P4** — P4 is already largest single point
  risk, adding checker split will exceed revertable granularity.
- **5.3.2 with "zero call site change" as hard acceptance** — split must be independently
  revertable.
