# Multi-level Construction Task Table (WBS)

> **Subsidiary design document**. This document is a subsidiary of
> [RFC-039 Compiler Architecture Refactoring](../../rfc/accepted/039-compiler-architecture.md),
> expanding the phase sequence of the RFC into **independently submittable, independently
> verifiable** three-level tasks.
>
> The phase order and acceptance gates take RFC-039 as the sole authority; this document is only
> responsible for breaking them down to executable granularity and registering undecided conflicts.

**Numbering left blank (not recycled)**: P4 has no `4.7`/`4.8`, P8 has no `8.1`. All three have no
corresponding entries since the WBS was established—this document has zero hits on the three
headings `**4.7` / `**4.8` / `**8.1` in its entire history (verifiable via
`git log -S'**4.7' -- docs/src/dev/architecture/09-execution-wbs.md`), and there are no references
in the entire repository. The `8.1` corresponds precisely to Phase 1 of `05` (test revival and
completion): that phase has been split into P1 (`1.1`–`1.3`) and `8.8`, so the numbering of P8
aligns with its phase numbers (Phase 0 → `8.0`, Phase 2 → `8.2`, and so on).

**This document covers**: task breakdown, dependencies, parallel grouping, and acceptance criteria
binding.

**This document does not cover**: the design rationale of tasks (see `02`–`08`), or the
justification of phase ordering (see RFC-039).

**Registration convention (since 2026-10-12)**: Newly registered level 2/3 rows **must carry two
fields**—"**Owning Phase**" (which P it actually belongs to, which may differ from the chapter it
sits in) and "**Whether It Blocks the Main Line**"; `Registration pending scheduling` is no longer
the default state, and unmarked entries are considered **not schedulable**. Numbering must be
**unique throughout the document** (tasks crossing tracks use the track number, e.g. `029g.x`, and
must not occupy `N.x`). **Checkmark/completion registration is based on "task id + evidence (gate
value, run id, issue number, file:line)"—do not write commit hashes**—`pull --rebase` rewrites local
hashes, and hard-coded numbers will inevitably fail (2026-10-13 example: `94ad03ce4`→`631eb3e3c`).
Check commit hashes via `git log`.

## Target Design: Phase Sequence

```
P0  Repository maintenance mechanism and code placement rules      08        ← New, set rules first
P1  Revive orphan tests and fix defects                            06 §S1
P2  Establish equivalence criteria baseline                        07 All
P3  Fix correctness vulnerabilities (minimal solution)             02 §S3-vulnerability half
P4  Phase contract and unified Driver                             02
P5  checker intra-file splitting                                  02 + Completed by this document
P6  Unify type representation                                      03
P7  SSA-ify intermediate representation                           04      } Parallelizable
P8  Frontend paradigm change                                       05      }
P9  Anti-rebound gates (including unified script list)            01 §Anti-rebound + 08 §Machine-checkable rules
P10 Other cleanup and status corrections                          06 §S2/S3/S4/S5/S6
```

**Reason for the new P0**: The three prohibitions (no fabrication / no endless padding / should
refactor but only patched) constrain every action in P1–P10. Rules must be established before
construction starts; otherwise, when P1 revives tests, one is already adding `mod` declarations to
`tests/mod.rs`—which is precisely the cause of the G4 conflict.

## Implementation Points: Dependencies and Parallelism

### Mandatory Serial Main Chain

`P0 → P1 → P2 → P3 → P3.5 → P4 → P5 → P6 → (P7 ∥ P8) → P9 → P10`

> **P3 bleeding channel (2026-10-05 ruling)**: P3's prerequisite narrowed to **2.3.2 + 2.4.1 +
> 2.4.3** (multi-file corpus layer + two red criteria). P2's other parts (2.1 IR verifier, 2.2
> snapshots, 2.3.1/2.3.3 diff and performance baseline) can progress in parallel with P3. Bleeding
> of correctness vulnerabilities should not be blocked by criterion infrastructure construction; but
> **P4 still must wait for P2 all complete**——unified Driver needs all three layers of criteria in
> place.

| Constraint         | Reason                                                                                                                                                                                                                               |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| P0 → P1            | Three prohibitions constrain every action of P1 (1.2.x is adding `mod` declarations to `mod.rs`)                                                                                                                                     |
| P1 → P2            | Reviving tests will change test count and corpus baseline                                                                                                                                                                            |
| P2 (narrowed) → P3 | Vulnerability criterion must **be written red first** (2.4.1/2.4.3) + multi-file corpus layer (2.3.2) exists, red tests have somewhere to run                                                                                        |
| P3 → P4            | First fix bug then refactor; reverse order will let bugs be固化 by phase table as "established behavior"                                                                                                                             |
| P3.5 → P4          | RFC-029g's (#399) deletion surface covers P4 4.2.2 / P5 / P6 / P7 / P8 respective rewrite objects (list see this document §P3.5)——reverse order equals doing same batch of deletion on new grammar, new checker layout, new IR (D56) |
| P4 → P5            | `include!` modification and checker splitting touch same file                                                                                                                                                                        |
| P5 → P6            | Continuous changes to same file must be separated, otherwise regression cannot be located by bisection                                                                                                                               |
| P6 → P7 / P8       | Type representation not converged first, new IR will grow into third set of representation                                                                                                                                           |
| P7/P8 → P9         | 9.5's snapshot baseline and 9.3's `pub(crate)` leakage count only take final form after P7/P8                                                                                                                                        |

## Key Decisions and Reasons

- **P0 as independent phase rather than merged into P9**——gates are "post-hoc check", rules are
  "pre-judgment". P9's scripts cannot prevent "should refactor but only patched", only D0–D4's
  review checklist can.
- **P9 as sole authoritative list of CI scripts**——original gap G3's three coexisting lists led to
  inability to close. After merging, this table has 11 scripts each attributed to one phase,
  report-only and convert-to-hard timing explicitly queryable.
- **P3.5 incorporates RFC-029g rather than leaving as "independent track, wait for after
  refactoring"**——its deletion surface overlaps with P4/P5/P6/P7/P8's rewrite surface (RFC-039 D56).
  Leaving to execute after refactoring equals redoing the same batch of deletion on the new grammar,
  new checker layout and new IR; this is the same lesson as 7e incorporating `2315`/`2341`, S4
  incorporating RFC status correction.
- **P5's steps are completed by this document rather than merged into P4**——P4 is already the
  largest single-point risk, additionally stacking checker splitting would exceed rollback
  granularity.
- **5.3.2 uses "zero caller change" as hard acceptance**——split must be independently revertable.
