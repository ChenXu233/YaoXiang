# Multi-level Construction Task Table (WBS)

> **Subsidiary design document**. This document is a subsidiary of
> [RFC-039 Compiler Architecture Refactoring](../../rfc/accepted/039-compiler-architecture.md),
> expanding the RFC's phase sequence into **independently committable, independently verifiable**
> three-level tasks.
>
> The phase order and acceptance gates are governed solely by the body of RFC-039; this document
> only handles decomposition to an executable granularity and registers conflicts that have not yet
> been adjudicated.

## Target Design: Phase Sequence

```
P0  Repository maintenance mechanism and code placement rules     08        ← New addition, establish rules first
P1  Revive orphan tests and fix defects           06 §S1
P2  Establish equivalence criterion baseline      07 all
P3  Fix correctness vulnerabilities (minimum plan)        02 §S3-vulnerability half
P4  Stage contract and unified Driver          02
P5  checker file-internal split             02 + this document completes
P6  Type representation unification                 03
P7  Intermediate representation SSA-ification                04      } Parallelizable
P8  Frontend paradigm change                   05      }
P9  Anti-regression gate (with unified script list)     01 §Anti-regression + 08 §Machine-checkable rules
P10 Remaining cleanup and state correction             06 §S2/S3/S4/S5/S6
```

**Rationale for adding P0**: The three prohibitions (no fabrication / no endless padding / patching
when refactoring is needed) constrain every action in P1–P10. The rules must be established before
work begins; otherwise by the time P1 revives tests, additions to `mod` declarations in
`tests/mod.rs` are already happening — which is exactly what caused the G4 conflict.

## Key Decisions and Rationale

- **P0 as independent phase not merged into P9** — gate is "post-hoc check", rules are "prior
  judgment". P9's scripts cannot prevent "should refactor but patched", only D0–D4's review
  checklist can.
- **P9 as CI scripts' sole authoritative list** — original gap G3's three parallel lists caused
  unable to close. After this table's merge, 10 scripts each attributed to one phase, report-only
  and hard conversion timing explicitly queryable.
- **P3.5 incorporates RFC-029g not left as "independent track, wait until after refactor"** — its
  deletion surface overlaps with P4/P5/P6/P7/P8's rewrite surface (RFC-039 D56). Left to execute
  after refactor, equals redo same batch of deletions on new grammar, new checker layout and new IR;
  this is the same lesson as 7e incorporating `2315`/`2341`, S4 incorporating RFC state correction.
- **P5's steps completed by this document not merged into P4** — P4 is already largest single-point
  risk, stacking checker split exceeds rollback granularity.
- **5.3.2 with "zero caller change" as hard acceptance** — split must be independently revertible.
