> only responsible for breaking down to executable granularity and registering unresolved conflicts.

## Target Design: Phase Sequence

```
P0  Repository Maintenance Mechanism and Code Placement Regulations     08        ← New, establish rules first
P1  Revive Orphan Tests and Fix Defects           06 §S1
P2  Establish Equivalence Criterion Baseline     07 All
P3  Fix Correctness Vulnerabilities (Minimal Solution)        02 §S3-Vulnerability Half
P4  Phase Contracts and Unified Driver          02
P5  Checker In-File Split             02 + supplemented by this document
P6  Type Representation Unification                 03
P7  Intermediate Representation SSA-ification                04      } Parallel
P8  Frontend Paradigm Change                   05      }
P9  Anti-Rebound Gates (including Unified Script List)     01 §Anti-Rebound + 08 §Machine-Checkable Rules
P10 Other Cleanup and Status Correction             06 §S2/S3/S4/S5/S6
```

**Reason for newly-added P0**: The three prohibitions (must not invent / must not fill endlessly /
should refactor but patched instead) constrain every action of P1–P10. Rules must be established
before construction begins, otherwise P1's test revival would already be adding `mod` declarations
to `tests/mod.rs` — which is exactly the cause of the G4 conflict.

## Key Decisions and Reasons

- **P0 independent as phase not merged into P9** — gate is "post-check", regulation is
  "pre-judgment". P9's script cannot prevent "should refactor but patched instead", only D0–D4's
  review checklist can.
- **P9 as CI script's sole authoritative list** — original gap G3's three parallel coexisting lists
  led to inability to close. After this table merges, 10 scripts each attribute to one phase,
  report-only and convert-to-hard timing explicit and queryable.
- **P3.5 incorporates RFC-029g rather than leave as "independent track, do after refactor"** — its
  deletion surface overlaps with P4/P5/P6/P7/P8's rewrite surface (RFC-039 D56). Leaving for after
  refactor, equals redoing the same batch of deletions on new grammar, new checker layout and new
  IR; this is the same lesson as 7e incorporating `2315`/`2341`, S4 incorporating RFC status
  correction.
- **P5's steps supplemented by this document rather than merged into P4** — P4 is already the
  largest single point risk, adding checker split will exceed rollback granularity.
- **5.3.2 takes "zero caller change" as hard acceptance** — split must be independently revertible.
