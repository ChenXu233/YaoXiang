> [RFC-039 Compiler Architecture Refactor](../../rfc/accepted/039-compiler-architecture.md),

> be adjudicated.

## Target Design: Stage Sequence

```
P0  Repository maintenance mechanism and code placement rules     08        ← New, rules first
P1  Revive orphan tests and fix defects           06 §S1
P2  Establish equivalence oracle baseline         07 all
P3  Fix correctness vulnerabilities (minimum plan) 02 §S3-vulnerability half
P4  Stage contract and unified Driver             02
P5  checker file internal split                   02 + this document completes
P6  Type representation unification               03
P7  Intermediate representation SSA-ification      04      } Parallel
P8  Frontend paradigm change                      05      }
P9  Anti-rebound gates (incl. unified script list) 01 §Anti-rebound + 08 §Machine-checkable rules
P10 Other cleanup and state corrections            06 §S2/S3/S4/S5/S6
```

**Reason for new P0**: Three prohibitions (no fabrication / no endless filling / refactor needed but
patched instead) constrain every action in P1–P10. Rules must be established before work begins,
otherwise when P1 revives tests, `mod` declarations are already being added to `tests/mod.rs` —
which is exactly the cause of the G4 conflict.

`P0 → P1 → P2 → P3 → P3.5 → P4 → P5 → P6 → (P7 ∥ P8) → P9 → P10`

## Key Decisions and Reasons

- **P0 independent as stage rather than merged into P9** — Gates are "post-hoc check", rules are
  "pre-judgment". P9's scripts cannot prevent "refactor needed but patched instead", only D0–D4's
  review checklist can.
- **P9 as the only authoritative list of CI scripts** — Original gap G3's three coexisting lists
  made closing impossible. After this table's merge 10 scripts each attribute to one stage,
  report-only and hardening timing explicitly queryable.
- **P3.5 incorporates RFC-029g rather than leaving as "independent track, do after refactor"** — Its
  deletion face overlaps with P4/P5/P6/P7/P8's rewrite face (RFC-039 D56). Leaving for after
  refactor equals redoing same batch of deletion on new grammar, new checker layout and new IR; this
  is the same lesson as 7e incorporating `2315`/`2341`, S4 incorporating RFC state correction.
- **P5's steps completed by this document rather than merged into P4** — P4 is already largest
  single-point risk, overlaying checker split will exceed rollable granularity.
- **5.3.2 with "zero caller change" as hard acceptance** — Split must be independently revertable.
