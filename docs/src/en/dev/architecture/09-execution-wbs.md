# Multi-Level Work Breakdown Structure (WBS)

> **Companion design document**. This document is a companion to
> [RFC-039 Compiler Architecture Refactoring](../../rfc/accepted/039-compiler-architecture.md). It
> expands the RFC's phase sequence into **three levels of tasks that can be committed and verified
> independently**.
>
> The phase order and acceptance gates in the body of RFC-039 are the sole authority. This document
> is responsible only for breaking the work down to an executable granularity and registering
> conflicts that have not yet been adjudicated.

**Unused numbers (not recycled)**: P4 has no `4.7`/`4.8`, and P8 has no `8.1`. None of the three had
corresponding entries from the inception of the WBS—the entire history of this document has zero
matches for the three headings `**4.7` / `**4.8` / `**8.1` (verifiable with
`git log -S'**4.7' -- docs/src/dev/architecture/09-execution-wbs.md`), and there are no
repository-wide references. `8.1` corresponds precisely to phase 1 of `05` (test resurrection and
completion): that phase was split into P1 (`1.1`–`1.3`) and `8.8`, so P8's numbering remains aligned
with its phase numbers (phase 0 → `8.0`, phase 2 → `8.2`, and so on).

**Covered by this document**: Task decomposition, dependency relationships, parallelization groups,
and binding of acceptance criteria.

**Not covered by this document**: Design rationale for the tasks (see `02`–`08`) or justification of
phase order (see RFC-039).

**Registration convention (effective 2026-10-12)**: Every newly registered Level 2/Level 3 row
**must contain two fields**—**“Owning Phase”** (the P to which it truly belongs, which may differ
from its section) and **“Blocks the Mainline”**. `Pending scheduling` is no longer the default
state; an unmarked task is deemed **not schedulable**. Numbers must be **unique across the entire
document** (tasks on other tracks use a track number, such as `029g.x`, and must not occupy `N.x`).
**Check-off/completion registration is based on “task ID + evidence (gate values, run ID, issue
number, file:line)” and must not contain a commit hash**—`pull --rebase` rewrites local hashes, so
hard-coded hashes inevitably become invalid (2026-10-13 example: `94ad03ce4`→`631eb3e3c`). Check
commit hashes with `git log`.

## Target Design: Phase Sequence

```
P0  仓库维护机制与代码放置规程     08        ← 新增，先立规矩
P1  复活孤儿测试并修缺陷           06 §S1
P2  建立等价性判据基线             07 全部
P3  修正确性漏洞（最小方案）        02 §S3-漏洞半部
P4  阶段契约与统一 Driver          02
P5  checker 文件内拆分             02 + 本文补齐
P6  类型表示单一化                 03
P7  中间表示 SSA 化                04      } 可并行
P8  前端范式变更                   05      }
P9  防反弹门禁（含统一脚本清单）     01 §防反弹 + 08 §可机检规则
P10 其余清理与状态修正             06 §S2/S3/S4/S5/S6
```

**Reason for adding P0**: The three prohibitions (no fabrication / no endless padding / no patching
when a refactor is required) constrain every action in P1–P10. The rules must be established before
work begins; otherwise, while resurrecting tests in P1, work will already be adding `mod`
declarations to `tests/mod.rs`—which is precisely the cause of the G4 conflict.

## Implementation Points: Dependencies and Parallelization

### Mandatory Serial Main Chain

`P0 → P1 → P2 → P3 → P3.5 → P4 → P5 → P6 → (P7 ∥ P8) → P9 → P10`

> **P3 hemorrhage-stopping channel (decision of 2026-10-05)**: P3's prerequisites are narrowed to
> **2.3.2 + 2.4.1 + 2.4.3** (multi-file corpus layer + two red criteria). The rest of P2 (2.1 IR
> verifier, 2.2 snapshots, 2.3.1/2.3.3 differential and performance baseline) can proceed in
> parallel with P3. Stopping the correctness vulnerability is not blocked by
> criterion-infrastructure construction; however, **P4 must still wait for all of P2**—the unified
> Driver requires all three layers of criteria to be in place.

| Constraint                | Reason                                                                                                                                                                                                                                                          |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P0 → P1                   | The three prohibitions constrain every P1 action (1.2.x is itself adding `mod` declarations to `mod.rs`)                                                                                                                                                        |
| P1 → P2                   | Resurrecting tests changes the test count and corpus baseline                                                                                                                                                                                                   |
| P2 (after narrowing) → P3 | Vulnerability criteria must **be written in red first** (2.4.1/2.4.3), and the multi-file corpus layer (2.3.2) must exist so that the red tests have somewhere to run                                                                                           |
| P3 → P4                   | Fix bugs before refactoring; reversing the order would cause bugs to be frozen into the phase table as “established behavior”                                                                                                                                   |
| P3.5 → P4                 | RFC-029g (#399)'s deletion surface covers the rewrite targets of P4 4.2.2 / P5 / P6 / P7 / P8 (the inventory appears in §P3.5 of this document)—reversing the order means repeating the same deletions on the new grammar, new checker layout, and new IR (D56) |
| P4 → P5                   | The `include!` refactor and checker split modify the same file                                                                                                                                                                                                  |
| P5 → P6                   | Consecutive changes to the same file must be separated; otherwise regressions cannot be located by bisection                                                                                                                                                    |
| P6 → P7 / P8              | If type representations are not converged first, the new IR will grow into a third representation                                                                                                                                                               |
| P7/P8 → P9                | 9.5's snapshot baseline and 9.3's `pub(crate)` leak count reach their final form only after P7/P8                                                                                                                                                               |

## Key Decisions and Rationale

- **P0 is an independent phase rather than part of P9**—gates are “post-hoc checks,” while rules are
  “pre-work judgment.” P9's scripts cannot prevent “patching when a refactor is required”; only
  D0–D4's review checklist can.
- **P9 is the sole authoritative inventory of CI scripts**—the three concurrent inventories caused
  by original gap G3 made closure impossible. This table merges them into 11 scripts, each owned by
  one phase, with report-only status and hardening timing explicitly traceable.
- **P3.5 incorporates RFC-029g rather than leaving it as an “independent track to execute after the
  refactor”**—its deletion surface overlaps the rewrite surfaces of P4/P5/P6/P7/P8 (RFC-039 D56).
  Deferring it until after the refactor means repeating the same deletions on the new grammar, new
  checker layout, and new IR. This is the same lesson as incorporating `2315`/`2341` into 7e and RFC
  state corrections into S4.
- **P5's steps are supplied by this document rather than merged into P4**—P4 is already the largest
  single-point risk, and adding the checker split would exceed the granularity at which work can be
  rolled back.
- **5.3.2 uses “zero caller changes” as hard acceptance**—the split must be independently
  revertible.
