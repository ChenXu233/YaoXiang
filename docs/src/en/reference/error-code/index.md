# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit by hand. To change the wording, edit
`locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic carries a stable code (e.g. `E1001`), which makes it easy to search,
reference in issues, and filter by code in CI. The user-visible text of a diagnostic (title /
template / help) is provided by `locales/*.json`, and can be viewed in the terminal with
`yx explain <code>`.

## Code Numbering Scheme

A code consists of a prefix (family) and a four-digit number; the family corresponds to a compiler
phase:

| Family Prefix | Category           | Meaning                                                        | Registered Codes |
| ------------- | ------------------ | -------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntactic analysis errors                          | 11               |
| `E1xxx`       | `TypeCheck`        | Type checking errors                                           | 53               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                       | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR-level consistency checks) | 13               |
| `E4xxx`       | `Generic`          | Generics, trait, and constant evaluation errors                | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                       | 7                |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                   | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                          | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors (compiler bugs)                       | 3                |
| `W1xxx`       | `Warning`          | Warnings (do not block compilation)                            | 8                |

The `E3xxx` family has not been listed in any previous documentation and is now merged into this
page; its codes are produced during IR generation and entry-point checks.

## Marker Explanations

- **span exemption**: when `true`, the diagnostic is allowed to have no source location (e.g.
  internal errors, runtime diagnostics). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor a walk context (debug builds panic; release falls back to `E8001`).
- **Emission sites ⚠ Not yet emitted**: the code is preserved in the registry, but there is
  currently no call site in non-test code, so users cannot trigger it. Code numbers are not
  recycled, to prevent diagnostics in old artifacts from being reused with a different meaning.
- **std-layer runtime codes**: see the previous section; not counted in registry statistics.
