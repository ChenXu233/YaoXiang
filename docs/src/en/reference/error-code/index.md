# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; please do not edit it by hand. To change the
wording, edit `locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Every diagnostic in YaoXiang carries a stable code (e.g. `E1001`), which makes it easy to search,
reference in issues, and filter by code in CI. The user-visible text of each diagnostic (title /
template / help) is provided by `locales/*.json`, and can be viewed in the terminal with
`yx explain <code>`.

## Code Numbering Scheme

A code consists of a prefix (family) and a four-digit number, where the prefix indicates the
compiler stage:

| Family Prefix | Category           | Meaning                                                        | Registered Codes |
| ------------- | ------------------ | -------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntactic analysis errors                          | 11               |
| `E1xxx`       | `TypeCheck`        | Type checking errors                                           | 57               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                       | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR-layer consistency checks) | 13               |
| `E4xxx`       | `Generic`          | Generics, trait and constant evaluation errors                 | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                       | 8                |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                   | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                          | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors (defects in the compiler itself)      | 3                |
| `W1xxx`       | `Warning`          | Warnings (do not block compilation)                            | 11               |

The `E3xxx` family was not previously listed in any documentation; it is now incorporated into this
page. Its codes are produced during IR generation and entry-point checking.

## Marker Explanations

- **span exempt**: when `true`, this diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, etc.). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor a walk context (debug builds panic; release falls back to `E8001`).
- **Emission Point ⚠ Not yet emitted**: the code is reserved in the registry, but there are no call
  sites in current non-test code, so users cannot trigger it. The code number is not reclaimed, to
  prevent diagnostics in old artifacts from being reused for a different meaning.
- **std-layer runtime codes**: see the previous section; not included in registry statistics.

```rust
use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {

    }
}
```
