# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`. To change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Every diagnostic in YaoXiang has a stable code number (such as `E1001`), making it easy to look up,
cite in issues, and filter by code in CI. User-visible diagnostic wording (title / template / help)
is provided by `locales/*.json` and can be viewed in the terminal with `yx explain <code>`.

## Code Numbering System

A code number consists of a prefix (family) and a four-digit sequence. The family identifies the
compiler stage:

| Family Prefix | Category           | Meaning                                                                                                                                                                        | Registered Code Count |
| ------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                                                                                                                                             | 12                    |
| `E1xxx`       | `TypeCheck`        | Type checking errors                                                                                                                                                           | 61                    |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                                                                                                                                       | 23                    |
| `E3xxx`       | `Codegen`          | Code generation errors, including IR consistency checks                                                                                                                        | 14                    |
| `E4xxx`       | `Generic`          | Generics, traits, and constant evaluation errors                                                                                                                               | 15                    |
| `E5xxx`       | `Module`           | Module and import errors                                                                                                                                                       | 8                     |
| `E6xxx`       | `Runtime`          | Runtime errors in the VM and std native functions                                                                                                                              | 7                     |
| `E7xxx`       | `Io`               | I/O and system errors                                                                                                                                                          | 4                     |
| `E8xxx`       | `Internal`         | Internal compiler errors (defects in the compiler itself)                                                                                                                      | 3                     |
| `W1xxx`       | `Warning`          | Warnings (the W family defaults to the warn emission level and does not block compilation; the exception is `W1090`, whose emission level is error and does block compilation) | 12                    |

The `E3xxx` family was not previously listed in any documentation, but is now included on this page.
Its codes are emitted during IR generation and entry-point checks.

## Marker Descriptions

- **span exemption**: When `true`, this diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, and so on). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor a walk context (panic in debug builds; `E8001` in release builds).
- **Emission point ⚠ Not yet emitted**: The code is retained in the registry, but currently has no
  call site in non-test code and therefore cannot be triggered by users. Code numbers are not
  reclaimed, to prevent diagnostics in old artifacts from being reused with a different meaning.
- **std-layer runtime code**: See the previous section. These codes are not included in the registry
  statistics.

## Querying from Rust Code

```rust
use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {
    println!("Title: {}", i18n.get_title(&code));
    if let Some(help) = i18n.get_help(&code) {
        println!("Help: {}", help);
    }
}
```
