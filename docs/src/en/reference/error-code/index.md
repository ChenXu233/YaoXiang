# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/en.json`. Do not edit by hand. To change text, edit
`locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic carries a stable code number (such as `E1001`) for easy lookup, reference
in issues, and filtering by code in CI. The user-visible diagnostic text (title / template / help)
is provided by `locales/*.json` and can be viewed in the terminal with `yx explain <code>`.

## Code Numbering System

A code number consists of a prefix (family) and a four-digit sequence number; the family corresponds
to the compiler phase:

| Family Prefix | Category           | Meaning                                                        | Registered Count |
| ------------- | ------------------ | -------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                             | 11               |
| `E1xxx`       | `TypeCheck`        | Type check errors                                              | 53               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                       | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR-level consistency checks) | 13               |
| `E4xxx`       | `Generic`          | Generics, trait, and constant evaluation errors                | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                       | 7                |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                   | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                          | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors (defects in the compiler itself)      | 3                |
| `W1xxx`       | `Warning`          | Warnings (do not prevent compilation)                          | 8                |

The `E3xxx` family was not previously listed in any documentation; it has been merged into this
page. Its codes are produced during IR generation and entry point checks.

## Notation

- **Span Exempt**: when `true`, the diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, etc.). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor a walk context (debug builds panic, release falls back to `E8001`).
- **Emission Point ⚠ Not Yet Emitted**: the code is reserved in the registry, but there is no call
  site in non-test code at present, so the user cannot trigger it. The code number is not recycled,
  to avoid reusing a diagnostic from an old artifact for a different meaning.
- **std Layer Runtime Codes**: see the previous section; not included in the registry statistics.
