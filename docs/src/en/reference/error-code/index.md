# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`. To change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic has a stable code number (such as `E1001`), making it easy to look up,
cite in issues, and filter by code in CI. The user-facing diagnostic text (title / template / help)
is provided by `locales/*.json` and can be viewed in the terminal with `yx explain <code>`.

## Code Numbering System

A code number consists of a prefix (family) and a four-digit sequence number. The family corresponds
to a compiler stage:

| Family prefix | Category           | Meaning                                                                                                                              | Registered codes |
| ------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                                                                                                   | 11               |
| `E1xxx`       | `TypeCheck`        | Type-checking errors                                                                                                                 | 57               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                                                                                             | 23               |
| `E3xxx`       | `Codegen`          | Code-generation errors, including IR consistency checks                                                                              | 14               |
| `E4xxx`       | `Generic`          | Generic, trait, and constant-evaluation errors                                                                                       | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                                                                                             | 8                |
| `E6xxx`       | `Runtime`          | Runtime errors in the VM and native std functions                                                                                    | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                                                                                                | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors caused by defects in the compiler itself                                                                    | 3                |
| `W1xxx`       | `Warning`          | Warnings (the W family defaults to warn and does not block compilation; the exception `W1090` uses error and does block compilation) | 12               |

The `E3xxx` family was not previously listed in any documentation and is now included on this page.
Its codes are produced during IR generation and entry-point checks.

## Standard-Library Runtime Codes

The following codes are **not registered in the `define_codes!` registry**. They are constructed at
runtime by native functions in the standard library through `error_new("code", …)`, so they do not

## Marker Explanations

- **span exemption**: When `true`, the diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, and so on). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor a walk context (debug builds panic, while release builds result in `E8001`).
- **Emission site ⚠ Not yet emitted**: The code is retained in the registry, but currently has no
  call site in non-test code, so users cannot trigger it. Code numbers are not reclaimed, to prevent
  diagnostics in old artifacts from being reused with a different meaning.
- **Standard-library runtime codes**: See the previous section. These codes are excluded from
  registry statistics.

## Querying Codes in Rust Code

```rust
use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {
    println!("Title: {}", i18n.get_title(&code));
    if let Some(help) = i18n.get_help(&code) {
        println!("Help: {}", help);
    }
}
```
