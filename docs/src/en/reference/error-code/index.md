# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/en.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic has a stable code number (such as `E1001`), making it easy to search for,
cite in issues, and filter by code in CI. The user-facing diagnostic text (title / template / help)
is provided by `locales/*.json` and can be viewed in the terminal with `yx explain <code>`.

## Code Numbering System

A code consists of a prefix (family) and a four-digit sequence number. The family indicates the
compiler stage:

| Family prefix | Category           | Meaning                                                                                                                                                                          | Registered codes |
| ------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                                                                                                                                               | 11               |
| `E1xxx`       | `TypeCheck`        | Type checking errors                                                                                                                                                             | 59               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                                                                                                                                         | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors, including IR-layer consistency checks                                                                                                                    | 14               |
| `E4xxx`       | `Generic`          | Generic, trait, and constant evaluation errors                                                                                                                                   | 15               |
| `E5xxx`       | `Module`           | Module and import errors                                                                                                                                                         | 8                |
| `E6xxx`       | `Runtime`          | Runtime errors from the VM and std native functions                                                                                                                              | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                                                                                                                                            | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors caused by defects in the compiler itself                                                                                                                | 3                |
| `W1xxx`       | `Warning`          | Warnings (the W family defaults to the `warn` emission level and does not block compilation; the exception, `W1090`, uses the `error` emission level and does block compilation) | 12               |

The `E3xxx` family was not previously listed in any documentation. It is now included in this page;
its codes are produced during IR generation and entry-point checks.

## Marker Explanations

- **Span exemption**: When this is `true`, the diagnostic is allowed to have no source location, as
  with internal errors and runtime diagnostics. Non-exempt codes are rejected when there is neither
  an explicit `.at()` nor a walk context; debug builds panic, while release builds fall back to
  `E8001`.
- **Emission site ⚠ Not yet emitted**: The code remains in the registry, but it currently has no
  call site in non-test code, so users cannot trigger it. Code numbers are not recycled, which
  prevents diagnostics in older artifacts from being reused with a different meaning.
- **std-layer runtime code**: See the preceding section. These codes are not included in the
  registry statistics.

use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

}
