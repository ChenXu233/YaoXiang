# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`. To change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic has a stable code (such as `E1001`) for easy lookup, citation in issues,
and filtering by code in CI. The user-visible diagnostic text (title / template / help) is provided
by `locales/*.json` and can be viewed in the terminal with `yx explain <码号>`.

## Code Numbering System

A code consists of a prefix (family) and a four-digit sequence number. The family identifies the
compiler stage:

| Family Prefix | Category           | Meaning                                                                                                                                                                      | Registered Codes |
| ------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                                                                                                                                           | 11               |
| `E1xxx`       | `TypeCheck`        | Type checking errors                                                                                                                                                         | 57               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                                                                                                                                     | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR-layer consistency checks)                                                                                                               | 14               |
| `E4xxx`       | `Generic`          | Generics, traits, and constant evaluation errors                                                                                                                             | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                                                                                                                                     | 8                |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                                                                                                                                 | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                                                                                                                                        | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors (defects in the compiler itself)                                                                                                                    | 3                |
| `W1xxx`       | `Warning`          | Warnings (the W family defaults to the warn emission level and does not block compilation; the exception, `W1090`, uses the error emission level and does block compilation) | 12               |

The `E3xxx` family was not previously listed in any documentation and is now included on this page.
Its codes are produced during IR generation and entry-point checks.

## std-Layer Runtime Codes

The following codes are **not registered in `define_codes!`**: they are constructed at runtime by
standard-library native functions via `error_new("码号", …)`. Consequently, they do not appear in
the results of `ErrorCodeDefinition::find()`, but `locales/*.json` contains corresponding text, so
users may still see them in the terminal.

## Marker Descriptions

- **span exemption**: When `true`, the diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, etc.). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor walk context (panic in debug builds; falls back to `E8001` in release
  builds).
- **Emission Site ⚠ Not yet emitted**: The code is retained in the registry but currently has no
  call site in non-test code, so users cannot trigger it. Code numbers are not recycled, preventing
  diagnostics in old artifacts from being reused with a different meaning.
- **std-layer runtime codes**: See the preceding section. These codes are not included in the
  registry statistics.

## Querying from Rust Code

```rust
use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {
    println!("Title: {}", i18n.get_title(&code));
    if let Some(help) = i18n.get_help(&code) {
        println!("Help: {}", help);
    }
}
```
