# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/en.json`; please do not edit it by hand. To change text,
edit `locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic carries a stable code number (e.g. `E1001`) for easy lookup, referencing
in issues, and filtering by code in CI. The user-visible diagnostic text (title / template / help)
is provided by `locales/*.json` and can be inspected in the terminal via `yx explain <code>`.

## Code Numbering Scheme

A code number consists of a prefix (family) and a four-digit serial; the family corresponds to a
compiler phase:

| Family prefix | Category           | Meaning                                                        | Registered code count |
| ------------- | ------------------ | -------------------------------------------------------------- | --------------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                             | 11                    |
| `E1xxx`       | `TypeCheck`        | Type check errors                                              | 57                    |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                       | 23                    |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR-layer consistency checks) | 13                    |
| `E4xxx`       | `Generic`          | Generics, trait and constant evaluation errors                 | 14                    |
| `E5xxx`       | `Module`           | Module and import errors                                       | 8                     |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                   | 7                     |
| `E7xxx`       | `Io`               | I/O and system errors                                          | 4                     |
| `E8xxx`       | `Internal`         | Internal compiler errors (defects in the compiler itself)      | 3                     |
| `W1xxx`       | `Warning`          | Warnings (do not block compilation)                            | 10                    |

The `E3xxx` family was not previously listed in any documentation and is now included in this page;
its codes are produced during IR generation and entry point checking.

## Notation

- **span exempt**: When `true`, the diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, etc.). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor walk context (debug build panics, release falls back to `E8001`).
- **Emission points ⚠ Not yet emitted**: The code is reserved in the registry but currently has no
  call site in non-test code, and users cannot trigger it. The code number is not recycled, to avoid
  diagnostic codes in old artifacts being reused with different meanings.
- **std-layer runtime codes**: See the previous section; not counted in registry statistics.

## Querying in Rust Code

```rust
use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {
    println!("Title: {}", i18n.get_title(&code));
    if let Some(help) = i18n.get_help(&code) {
        println!("Help: {}", help);
    }
}
```
