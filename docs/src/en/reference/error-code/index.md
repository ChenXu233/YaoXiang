# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/en.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`; then rerun
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic has a stable code number (such as `E1001`), making it easy to search for,
cite in issues, and filter by code in CI. The user-facing diagnostic text (title / template / help)
is provided by `locales/*.json` and can be viewed in the terminal with `yx explain <code>`.

## Code Numbering System

A code number consists of a prefix (the family) and a four-digit sequence number. The family
corresponds to the compiler stage:

| Family prefix | Category           | Meaning                                                   | Registered code count |
| ------------- | ------------------ | --------------------------------------------------------- | --------------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                        | 11                    |
| `E1xxx`       | `TypeCheck`        | Type checking errors                                      | 57                    |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                  | 23                    |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR consistency checks)  | 13                    |
| `E4xxx`       | `Generic`          | Generics, trait, and constant evaluation errors           | 14                    |
| `E5xxx`       | `Module`           | Module and import errors                                  | 8                     |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)              | 7                     |
| `E7xxx`       | `Io`               | I/O and system errors                                     | 4                     |
| `E8xxx`       | `Internal`         | Internal compiler errors (defects in the compiler itself) | 3                     |
| `W1xxx`       | `Warning`          | Warnings (do not prevent compilation)                     | 12                    |

The `E3xxx` family was not previously listed in any documentation and is now included on this page;
its codes are produced during IR generation and entry point checking.

## Marker Descriptions

- **Span exempt**: When `true`, the diagnostic is allowed to have no source location (as with
  internal errors, runtime diagnostics, and so on). Non-exempt codes are rejected when there is
  neither an explicit `.at()` nor a walk context (debug builds panic; release builds fall back to
  `E8001`).
- **Emission site ⚠ Not yet emitted**: The code is retained in the registry, but currently has no
  call site in non-test code, so users cannot trigger it. Code numbers are not reclaimed, preventing
  diagnostics in old artifacts from being reused with a different meaning.
- **std-level runtime codes**: See the preceding section. These codes are not included in the
  registry statistics.

use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

    }
}
