# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit by hand. To change wording, edit
`locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic carries a stable code (e.g. `E1001`) for easy lookup, referencing in
issues, and filtering by code in CI. The user-visible text of a diagnostic (title / template / help)
is provided by `locales/*.json`, and can be viewed in the terminal with `yx explain <code>`.

## Code Number System

Codes consist of a prefix (family) and a four-digit sequence; the prefix indicates the compiler
phase:

| Prefix  | Category           | Meaning                                                        | Registered Count |
| ------- | ------------------ | -------------------------------------------------------------- | ---------------- |
| `E0xxx` | `Lexer` / `Parser` | Lexical and syntactic analysis errors                          | 11               |
| `E1xxx` | `TypeCheck`        | Type checking errors                                           | 53               |
| `E2xxx` | `Semantic`         | Semantic analysis errors                                       | 23               |
| `E3xxx` | `Codegen`          | Code generation errors (including IR-level consistency checks) | 13               |
| `E4xxx` | `Generic`          | Generics, traits, and constant evaluation errors               | 14               |
| `E5xxx` | `Module`           | Module and import errors                                       | 7                |
| `E6xxx` | `Runtime`          | Runtime errors (VM and std native functions)                   | 7                |
| `E7xxx` | `Io`               | I/O and system errors                                          | 4                |
| `E8xxx` | `Internal`         | Internal compiler errors (compiler bugs)                       | 3                |
| `W1xxx` | `Warning`          | Warnings (do not block compilation)                            | 8                |

The `E3xxx` family was not previously listed in any documentation and has now been merged into this
page; its codes are produced during IR generation and entry-point checks.

## Statistics

- `define_codes!` registry: **143** entries (135 `E` codes + 8 `W` codes).
- std-layer runtime codes: **5** (not in the `define_codes!` registry; see the next section).
- Total: **148** diagnostic codes.
- Of these, **35** registered codes currently have no emission site in non-test code, marked as "not
  yet emitted"—their code numbers are still reserved, but users cannot currently trigger them.

## Notation

- **span Exempt**: When `true`, the diagnostic is allowed to have no source location (e.g., internal
  errors, runtime diagnostics). Non-exempt codes are rejected when there is neither an explicit
  `.at()` nor a walk context (debug build panics, release falls back to `E8001`).
- **Emission Sites ⚠ Not yet emitted**: The code is reserved in the registry, but has no call site
  in current non-test code, so users cannot trigger it. The code number is not reclaimed, to avoid
  old artifacts' diagnostics being reused with different meanings.
- **std-Layer Runtime Codes**: See the previous section; not counted in the registry statistics.

## Querying in Rust Code

```rust
use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {

    if let Some(help) = i18n.get_help(&code) {

    }
}
```
