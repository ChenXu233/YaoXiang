# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/en.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Every diagnostic in YaoXiang has a stable code number (such as `E1001`), making it easy to search,
cite in issues, and filter by code in CI. The user-visible diagnostic text (title / template / help)
is provided by `locales/*.json` and can be viewed in the terminal with `yx explain <code>`.

## Code Numbering System

Code numbers consist of a prefix (family) and a four-digit sequence number. The family corresponds
to a compiler stage:

| Family Prefix | Category           | Meaning                                                                                                                                                                | Registered Codes |
| ------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                                                                                                                                     | 11               |
| `E1xxx`       | `TypeCheck`        | Type-checking errors                                                                                                                                                   | 57               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                                                                                                                               | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR-layer consistency checks)                                                                                                         | 14               |
| `E4xxx`       | `Generic`          | Generics, traits, and constant-evaluation errors                                                                                                                       | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                                                                                                                               | 8                |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                                                                                                                           | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                                                                                                                                  | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors (defects in the compiler itself)                                                                                                              | 3                |
| `W1xxx`       | `Warning`          | Warnings (the W code family emits at the `warn` level by default and does not block compilation; exception: `W1090` emits at the `error` level and blocks compilation) | 12               |

The `E3xxx` family was not previously listed in any documentation, but is now included on this page;
its codes are produced during IR generation and entry-point checking.

## Marker Descriptions

- **Span exemption**: When `true`, the diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, etc.). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor a walk context (they panic in debug builds and fall back to `E8001` in
  release builds).
- **Emission site ⚠ Not yet emitted**: The code remains in the registry, but it currently has no
  call site in non-test code and cannot be triggered by users. Code numbers are not reclaimed,
  preventing diagnostics in old artifacts from being reused with a different meaning.
- **std-layer runtime codes**: See the previous section; these are not included in the registry
  statistics.

## Querying from Rust Code

```rust
use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {
    println!("Title: {}", i18n.get_title(&code));
    if let Some(help) = i18n.get_help(&code) {
        println!("Help: {}", help);
    }
}
```
