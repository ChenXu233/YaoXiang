# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Please do not edit by hand. To change text, edit
`locales/*.json`; to change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic carries a stable code (e.g. `E1001`) for easy lookup, for reference in
issues, and for filtering by code in CI. The user-visible text of a diagnostic (title / template /
help) is provided by `locales/*.json` and can be viewed in the terminal with `yx explain <code>`.

## Code Numbering System

Code numbers consist of a prefix (family) and a four-digit sequence number, where the family is the
compiler phase:

| Family prefix | Category           | Meaning                                                        | Registered codes |
| ------------- | ------------------ | -------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntactic analysis errors                          | 11               |
| `E1xxx`       | `TypeCheck`        | Type checking errors                                           | 53               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                       | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR-layer consistency checks) | 13               |
| `E4xxx`       | `Generic`          | Generic, trait, and constant evaluation errors                 | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                       | 7                |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                   | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                          | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors (compiler's own defects)              | 3                |
| `W1xxx`       | `Warning`          | Warnings (do not block compilation)                            | 8                |

The `E3xxx` family was not previously listed in any documentation and has now been merged into this
page; its codes are produced during IR generation and entry-point checking.

## std Layer Runtime Codes

The following codes are **not in the `define_codes!` registry**: they are constructed at runtime by
standard library native functions via `error_new("code", …)`, so they do not appear in the results
of `ErrorCodeDefinition::find()`, but `locales/*.json` has matching text, and they may still be seen
by users in the terminal.

## Marker Description

- **span exempt**: When `true`, the diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, etc.). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor a walk context (panic in debug builds, falls back to `E8001` in release).
- **Emission point ⚠ Not yet emitted**: This code is reserved in the registry, but currently has no
  call site in non-test code and cannot be triggered by users. Code numbers are not recycled, to
  avoid diagnostics in old artifacts being reused with a different meaning.
- **std layer runtime codes**: See the previous section; not included in the registry statistics.
