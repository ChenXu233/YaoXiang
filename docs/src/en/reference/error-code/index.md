# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; please do not edit it by hand. To change
wording, edit `locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Each YaoXiang diagnostic carries a stable code (e.g. `E1001`) for easy lookup, reference in issues,
and filtering by code in CI. The user-visible wording (title / template / help) for each diagnostic
is provided by `locales/*.json`, and can be viewed in the terminal with `yx explain <code>`.

## Code Numbering Scheme

Codes are composed of a family prefix and a four-digit sequence; the family corresponds to a
compiler phase:

| Family Prefix | Category           | Meaning                                                        | Registered Count |
| ------------- | ------------------ | -------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntactic analysis errors                          | 11               |
| `E1xxx`       | `TypeCheck`        | Type checking errors                                           | 53               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                       | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR-level consistency checks) | 13               |
| `E4xxx`       | `Generic`          | Generics, traits, and constant evaluation errors               | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                       | 7                |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                   | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                          | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors (bugs in the compiler itself)         | 3                |
| `W1xxx`       | `Warning`          | Warnings (do not block compilation)                            | 8                |

The `E3xxx` family was not previously listed in any documentation and is now included on this page;
its codes are produced during IR generation and at entry-point checks.

## Marker Legend

- **Span exempt**: when `true`, this diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, etc.). Non-exempt codes will be rejected when there is neither an
  explicit `.at()` nor a walk context (panic in debug builds, fall back to `E8001` in release).
- **Emission sites ⚠ Not yet emitted**: the code is reserved in the registry, but there is currently
  no call site in non-test code, so users cannot trigger it. The code number is not reclaimed, to
  avoid diagnostics in old artifacts being reused with a different meaning.
- **std layer runtime codes**: see the previous section; not counted in registry statistics.

```rust
use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {
    println!("Title: {}", i18n.get_title(&code));
    if let Some(help) = i18n.get_help(&code)) {
        println!("Help: {}", help);
    }
}
```
