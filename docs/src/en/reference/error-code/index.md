# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/en.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`; then rerun
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic has a stable code number (such as `E1001`) to make it easy to search for,
reference in issues, and filter by code in CI. The user-facing diagnostic text (title / template /
help) is provided by `locales/*.json` and can be viewed in the terminal with `yx explain <code>`.

## Code Numbering System

Code numbers consist of a prefix (family) and a four-digit sequence number. Each family corresponds
to a compiler phase:

| Family Prefix | Category           | Meaning                                                                                                                                                                          | Registered Codes |
| ------------- | ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                                                                                                                                               | 11               |
| `E1xxx`       | `TypeCheck`        | Type checking errors                                                                                                                                                             | 57               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                                                                                                                                         | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR consistency checks)                                                                                                                         | 13               |
| `E4xxx`       | `Generic`          | Generics, traits, and constant evaluation errors                                                                                                                                 | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                                                                                                                                         | 8                |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                                                                                                                                     | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                                                                                                                                            | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors (defects in the compiler itself)                                                                                                                        | 3                |
| `W1xxx`       | `Warning`          | Warnings (the W family is emitted at warn level by default and does not prevent compilation; the exception is `W1090`, which is emitted at error level and prevents compilation) | 12               |

The `E3xxx` family was not previously listed in any documentation and is now included on this page.
Its codes are produced during IR generation and entry-point checking.

## Statistics

- The `define_codes!` registry contains **152** entries (140 `E` codes and 12 `W` codes).

  emitted.” Their code numbers are still retained, but users cannot currently trigger them.

## Marker Explanations

- **span exemption:** When `true`, the diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, and so on). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor a walk context (causing a panic in debug builds and falling back to `E8001`
  in release builds).
- **Emission point ⚠ Not yet emitted:** The code is retained in the registry, but currently has no
  call site in non-test code, so users cannot trigger it. Code numbers are never reclaimed,
  preventing diagnostics in old artifacts from being reused with a different meaning.
- **std runtime codes:** See the preceding section. These codes are not included in registry
  statistics.

use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {

    }
}
