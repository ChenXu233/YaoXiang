# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Please do not edit it by hand. To change
wording, edit `locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic carries a stable code (e.g. `E1001`) for easy lookup, referencing in
issues, and filtering by code in CI. The user-visible wording for each diagnostic (title / template
/ help) is provided by `locales/*.json` and can be viewed in the terminal with `yx explain <code>`.

## Code Numbering Scheme

Codes consist of a family prefix and a four-digit sequence; the family corresponds to a compiler
phase:

| Family Prefix | Category           | Meaning                                                        | Registered Count |
| ------------- | ------------------ | -------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                             | 11               |
| `E1xxx`       | `TypeCheck`        | Type checking errors                                           | 55               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                       | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR-level consistency checks) | 13               |
| `E4xxx`       | `Generic`          | Generics, trait, and constant evaluation errors                | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                       | 8                |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                   | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                          | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors (bugs in the compiler itself)         | 3                |
| `W1xxx`       | `Warning`          | Warnings (do not block compilation)                            | 10               |

The `E3xxx` family was not previously listed in any documentation and is now incorporated into this
page; its codes are emitted during IR generation and entry-point checks.

## Marker Notes

- **Span exempt**: when `true`, the diagnostic is allowed to have no source location (e.g. internal
  errors, runtime diagnostics). Non-exempt codes are rejected when there is neither an explicit
  `.at()` call nor a walk context (panic in debug builds, falls back to `E8001` in release).
- **Emission Points ⚠ Not yet emitted**: the code is reserved in the registry, but currently has no
  call sites in non-test code, so users cannot trigger it. Code numbers are not recycled, to avoid
  diagnostics from old artifacts being reused with different meanings.
- **std-layer runtime codes**: see the previous section; not counted in the registry statistics.

## Querying in Rust Code

```rust
use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {
    println!("Title: {}", i18n.get_title(&code));
    if let Some(help) = i18n.get_help(&code) {

    }
}
```
