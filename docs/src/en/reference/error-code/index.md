# Error Code Reference

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it by hand. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Every YaoXiang diagnostic carries a stable code (e.g. `E1001`) for easy lookup, referencing in
issues, and filtering by code in CI. The user-visible wording (title / template / help) for
diagnostics is provided by `locales/*.json`, and can be viewed in the terminal via
`yx explain <code>`.

## Code System

Codes consist of a prefix (family) and a four-digit number; the prefix denotes the compiler stage:

| Family Prefix | Category           | Meaning                                                        | Registered Count |
| ------------- | ------------------ | -------------------------------------------------------------- | ---------------- |
| `E0xxx`       | `Lexer` / `Parser` | Lexical and syntax analysis errors                             | 11               |
| `E1xxx`       | `TypeCheck`        | Type check errors                                              | 57               |
| `E2xxx`       | `Semantic`         | Semantic analysis errors                                       | 23               |
| `E3xxx`       | `Codegen`          | Code generation errors (including IR-layer consistency checks) | 13               |
| `E4xxx`       | `Generic`          | Generics, traits, and constant evaluation errors               | 14               |
| `E5xxx`       | `Module`           | Module and import errors                                       | 8                |
| `E6xxx`       | `Runtime`          | Runtime errors (VM and std native functions)                   | 7                |
| `E7xxx`       | `Io`               | I/O and system errors                                          | 4                |
| `E8xxx`       | `Internal`         | Internal compiler errors (defects in the compiler itself)      | 3                |
| `W1xxx`       | `Warning`          | Warnings (do not block compilation)                            | 11               |

The `E3xxx` family was not previously documented anywhere; it has now been incorporated into this
page. Its codes are produced during IR generation and entry-point checks.

## Marker Legend

- **span exempt**: when `true`, the diagnostic is allowed to have no source location (internal
  errors, runtime diagnostics, etc.). Non-exempt codes are rejected when there is neither an
  explicit `.at()` nor a walk context (debug builds panic, release falls back to `E8001`).
- **Emission Site ⚠ Not Yet Emitted**: the code is reserved in the registry, but currently has no
  call site in non-test code, so users cannot trigger it. The code number is not recycled, to
  prevent diagnostics in older artifacts from being reused for different meanings.
- **std-layer runtime codes**: see the previous section; not counted in the registry statistics.

## Querying in Rust Code

```rust
use yaoxiang::util::diagnostic::{ErrorCodeDefinition, I18nRegistry};

let i18n = I18nRegistry::default();

if let Some(code) = ErrorCodeDefinition::find("E1001") {
    println!("Title: {}", i18n.get_title(&code));
    if let Some(help) = i18n.get_help(&code) {
        println!("Help: {}", help);
    }
}
```
