Package manager (`yx install` / `add` / `rm` / `update` / `publish` / `cache` / `workspace`) errors
**do not carry an `E` code**: they are the `thiserror`-defined Rust enum `PackageError`, printed at
the CLI layer as `Error: <rendered format string>`, and do not enter the compiler's diagnostic
rendering pipeline. There are currently **23** variants, defined in `src/package/error.rs`. For
compiler diagnostic codes, see [Error Code Reference](../error-code/index.md).

## Handling

Group by category for troubleshooting:

| Symptom                            | Related Variants                                                                                                         | Handling                                                                                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `yaoxiang.toml` not found          | `NotProject` / `NotWorkspace`                                                                                            | Run the command from the project root; in workspace scenarios, ensure at least one `yaoxiang.toml` contains a `[workspace]` section                            |
| Manifest / lock file parse failure | `InvalidManifest` / `Toml`                                                                                               | Check the TOML syntax of `yaoxiang.toml` and `yaoxiang.lock`                                                                                                   |
| Dependency add/remove issues       | `DependencyNotFound` / `DependencyAlreadyExists` / `DependencyInstallFailed`                                             | Use `yx list` to view existing dependencies; if it already exists, run `yx rm` first, then reinstall                                                           |
| Workspace member issues            | `MemberMissing` / `MemberInvalid` / `NestedWorkspace`                                                                    | Check the paths in `[workspace] members`; nested workspaces are not supported, flatten the structure                                                           |
| Publish / network                  | `Network` / `RateLimited` / `AuthFailed` / `RegistryDeferred` / `VersionAlreadyExists` / `PublishTarget` / `TestsFailed` | Official registry is not yet open, so explicitly pass `--github` or `--dry-run` for publish; wait and retry for rate limits; check token for credential issues |
| Package content / cache            | `PackageTooLarge` / `InvalidPackage` / `ChecksumMismatch` / `Cache`                                                      | Source package limit is 20 MiB; checksum mismatch means the download is corrupted, clear the cache and retry                                                   |
| Underlying I/O                     | `Io`                                                                                                                     | Check disk space, file permissions, and whether files are in use                                                                                               |

## FAQ

### Q: What should I do if dependency installation fails?

1. Check your network connection
2. Verify the dependency name and version constraints are correct
3. Try `yx update` to refresh the index

### Q: What should I do if the vendor directory is corrupted?

Clear the cache and reinstall: `yx cache clean`, then `yx install`.

### Q: Publish reports that the official registry is not yet open?

This is expected behavior (RFC-014a decision 1). Use `yx publish --github` to publish to a GitHub
Release, or add `--dry-run` to perform a local check first.
