# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`; then re-run
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and do not block compilation, but indicate possible issues in the code.
The current registry has **11** warning codes; for the full index see the
[error code home page](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured via `yaoxiang.toml`:

```toml
[lint]
# Dead code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable the warning
- `warn`: show the warning (default)
- `deny`: treat the warning as an error and block compilation

- **Category**: `Warning`
- **span exempt**: No
- **Template**:

- **Help**: This is a phase contract defect inside the compiler, not your program being wrong: the

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exempt**: Yes
- **Template**: `Obligation field \`{field}\` in {file} has been produced but never consumed:
  {detail}`
- **Help**: This is a phase contract defect inside the compiler, not your program being wrong: an
  obligation field produced by one phase was not read by the next phase, so the effect of the
  obligation may have been silently dropped. Please report this diagnostic along with the field name
  and file path as an issue, with a minimal reproduction program. This code belongs to the **W
  family** (code prefix W), but **the emission level is error**: the 2026-10-13 user ruling (WBS
  4.3.2, the final state of RFC-039 D5) **promotes the same code to E** — no new E code is added
  (the same fact under two codes would be parallel representation), and the emission level is
  determined by the explicit severity; triggering it counts into `error_count` and changes the exit
  code. Note: a healthy program emits nothing (no warning when all obligations have delivery
  markers), so the upgrade only affects the build result when this defect actually occurs.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Warning Levels

| Level  | Effect                                              |
| ------ | --------------------------------------------------- |
| `off`  | Completely disable this kind of warning             |
| `warn` | Show the warning but continue compilation (default) |
| `deny` | Treat the warning as an error and block compilation |

## Difference from Error Codes

- **Error (`E` prefix)**: blocks compilation and must be fixed.
- **Warning (`W` prefix)**: indicates potential issues and can be fixed optionally.

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether an
external consumer exists, so these warnings are never triggered (#321 decision B). If you see an
"unused" warning, removing the corresponding `pub` will eliminate it; conversely, keep `pub` for
declarations that need to be called externally.
