# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit by hand. To change wording, edit
`locales/*.json`; to change the code table, edit `define_codes!`; then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W`; they do not block compilation but flag potential issues in the code.
The current registry contains **10** warning codes. For the full index, see the
[Error Codes Home](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured via `yaoxiang.toml`:

```toml
[lint]
# Dead code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable the warning
- `warn`: show the warning (default)
- `deny`: treat the warning as an error and block compilation

- **Category**: `Warning`
- **span Exempt**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a stage-contract defect inside the compiler, not a bug in your program: an
  obligation field produced by one stage is not read by the next stage, so the obligation's effect
  may have been silently discarded. Please file an issue with this diagnostic, including the field
  name and file path, along with a minimal reproducer. This code belongs to the **W family** (code
  prefix W), but its **emission level is error**: per the 2026-10-13 user ruling (WBS 4.3.2, the
  final state of RFC-039 D5), the same code is **upgraded to E** — no new E code is added (the same

  the explicit severity. When triggered, it counts toward error_count and changes the exit code.
  Note: healthy programs emit zero warnings (none are reported when all obligations carry a delivery
  marker), so the upgrade only affects build results when this defect actually occurs.
- **Emission Site**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Warning Levels

| Level  | Effect                                              |
| ------ | --------------------------------------------------- |
| `off`  | Completely disable this class of warnings           |
| `warn` | Show the warning but continue compilation (default) |
| `deny` | Treat the warning as an error and block compilation |

## Difference from Error Codes

- **Errors (`E` prefix)**: Block compilation; must be fixed.
- **Warnings (`W` prefix)**: Flag potential issues; fixing is optional.

## Criteria for Dead-Code Warnings

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface; the compiler has no way to know whether external
consumers exist, so these warnings are never triggered for them (per decision B of #321). If you see
an "unused" warning, removing the corresponding `pub` silences it; conversely, keep `pub` on
declarations that need to be called externally.
