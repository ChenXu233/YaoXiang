# Warning Codes

> This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!`
> registry in `src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it by hand —
> change `locales/*.json` for wording and `define_codes!` for the code table, then re-run
> `python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W`. They do not block compilation but indicate potential problems.
The registry currently holds **8** warning codes; for the full index see the
[error code index](../error-code/index.md).

## Configuration

Dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable the warning
- `warn`: show the warning (default)
- `deny`: treat the warning as an error

## Warning Levels

| Level | Effect |
| --- | --- |
| `off` | fully disable this class of warning |
| `warn` | show the warning but keep compiling (default) |
| `deny` | treat the warning as an error and block compilation |

## Error Codes vs Warning Codes

- **Errors (`E` prefix)**: block compilation and must be fixed.
- **Warnings (`W` prefix)**: point out potential problems; fixing them is optional.

## How dead-code warnings are decided

`W1001`–`W1005` fire on **unused private** (non-`pub`) functions / types / variables /
methods. A `pub` declaration is part of the public interface — the compiler cannot know
whether an external consumer exists, so these warnings never fire for it (#321 decision B).
If you see an "unused" warning, dropping the corresponding `pub` removes it; conversely,
keep `pub` on declarations that need to be called from outside.
