# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit by hand. To change the wording, edit
`locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and do not prevent compilation, but they indicate possible issues in
the code. The current registry contains **10** warning codes; see the full index on the
[Error Code Index](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured via `yaoxiang.toml`:

```toml
[lint]
# Dead code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable the warning
- `warn`: show the warning (default)
- `deny`: treat the warning as an error and prevent compilation

- **Category**: `Warning`
- **Span Exempt**: Yes
- **Template**: `Obligation field \`{field}\` in {file} was produced but never consumed: {detail}`
- **Help**: This is an internal phase-contract defect in the compiler, not a bug in your program: an
  obligation field produced by one phase was never read by the next phase, so the effect of the
  obligation may have been silently dropped. Please report this diagnostic along with the field name
  and file path as an issue, and attach a minimal reproducing program. This code belongs to the **W
  family** (code prefix W), but its **emission level is error**: the 2026-10-13 user ruling (WBS
  4.3.2, the final state of RFC-039 D5) **promotes the same code to E level** without adding a new E
  code (two codes for the same fact would be parallel representations); the emission level is
  determined by the explicit severity. When triggered, it counts toward error_count and changes the
  exit code. Note: a healthy program emits zero diagnostics (no warning when all obligations are
  delivery-marked), so the escalation only affects the build result when this defect actually
  occurs.
- **Emission Point**: `src/driver/obligations.rs:445`, `src/driver/obligations.rs:82`

## Warning Levels

| Level  | Effect                                                |
| ------ | ----------------------------------------------------- |
| `off`  | Completely disable this kind of warning               |
| `warn` | Show the warning but continue compiling (default)     |
| `deny` | Treat the warning as an error and prevent compilation |

## Difference from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential issues and can be fixed at your discretion.

## Dead-Code Warning Judgment Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether external
consumers exist, so these warnings are never triggered for `pub` declarations (decision B of #321).
If you see an "unused" warning, removing the corresponding `pub` will eliminate it; conversely, keep
`pub` for declarations that need to be called externally.
