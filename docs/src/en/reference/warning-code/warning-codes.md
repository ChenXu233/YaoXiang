# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`. To change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes begin with `W` and indicate potential problems in the code. Their default emission
level is `warn`, which does not prevent compilation. The exception is `W1090`, whose emission level
is `error` (the same code was promoted to E by the user ruling on 2026-10-13; see its entry for
details). When triggered, it counts toward `error_count`, changes the exit code, and prevents
compilation. The current registry contains **12** warning codes. See the
[error code home page](../error-code/index.md) for the complete index.

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename the
  local module; use --deny-shadowing to promote it to an error.
- **Emission point**: `src/driver/arms.rs:653`, `src/util/diagnostic/command.rs:78`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle follows only the deterministic convention of "lexicographic order of paths
  within the cycle" and is not a semantic guarantee. Breaking the cycle (moving one use in the cycle
  out of it, or changing it to deferred evaluation in a function body) makes the initialization
  order decidable. Division of labor with E3019: E3019 determines an initialization cycle between
  top-level bindings within a unit, whereas this code determines an import cycle between modules.
- **Emission point**: `src/driver/arms.rs:1752`

### W1082: Ownership analysis downgraded

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions use an empty ledger and borrow conflicts are not detected`
- **Help**: This is a stage-contract defect within the compiler, not a mistake in your program: at

  reproducer, as an issue.
- **Emission point**: `src/frontend/core/typecheck/checker.rs:1620`

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a stage-contract defect within the compiler, not a mistake in your program: an
  obligation field produced by one stage is not read by the next stage, so the effect of the
  obligation may have been silently discarded. Please report this diagnostic, along with the field
  name and file path, as an issue and include a minimal reproducer. This code belongs to the **W
  family** (code prefix W), but its **emission level is error**: the user ruling on 2026-10-13 (WBS
  4.3.2, final state of RFC-039 D5) **promotes the same code to E**—no new E code is added (two
  codes for the same fact would merely represent it in parallel)—and the emission level is
  determined by the explicit severity. When triggered, it counts toward `error_count` and changes
  the exit code. Note: healthy programs emit nothing (this warning is not emitted when all
  obligations have delivery markers), so the promotion affects the build result only when the defect
  actually occurs.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems. The default emission level is `warn`, and
  you can choose to fix them. The exception is `W1090`, whose emission level is `error`. When
  triggered, it counts toward `error_count`, changes the exit code, prevents compilation, and must
  be fixed (see its entry for details).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions, types, variables, and methods. A
`pub` declaration is part of the public interface, and the compiler cannot know whether it has an
external consumer, so these warnings are never triggered for it (final decision B in #321). If you
see an "unused" warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub`
for declarations that need to be called externally.
