# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`; then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes begin with `W` and indicate potential problems in the code. Their default emission
level is warn, which does not block compilation. The exception is `W1090`, whose emission level is
error (promoted from the same code to E by the user ruling of 2026-10-13; see its entry for
details). When triggered, it counts toward error_count, changes the exit code, and blocks
compilation. The current registry contains **12** warning codes; see the
[Error Code Home](../error-code/index.md) for the complete index.

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable warnings
- `warn`: Display warnings (default)
- `deny`: Treat warnings as errors and block compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest precedence (RFC-014): './src/{module}' overrides
  dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename the
  local module; use --deny-shadowing to promote it to an error.
- **Emission points**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle follows only the deterministic convention of “lexicographic order of paths
  within the cycle”; this is not a semantic guarantee. Breaking the cycle—either by moving one use
  in the cycle out of it or by changing it to deferred evaluation in a function body—makes the
  initialization order determinable. Division of responsibilities with E3019: E3019 detects
  initialization cycles among top-level bindings within a unit, whereas this code detects import
  cycles between modules.
- **Emission points**: `src/driver/arms.rs:1877`

- **Help**: This is a stage-contract defect inside the compiler, not an error in your program. An

  obligation may have been silently discarded. Please file an issue with this diagnostic, the field

  occurs.
- **Emission points**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:547`

## Differences from Error Codes

- **Errors (`E` prefix)**: Block compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems. Their default emission level is warn, and
  they may be fixed. The exception is `W1090`, whose emission level is error. When triggered, it
  counts toward error_count, changes the exit code, blocks compilation, and must be fixed (see its
  entry for details).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is a public interface, and the compiler has no way of knowing whether external
consumers exist, so these warnings never trigger (#321, Decision B). If you see an “unused” warning,
remove the corresponding `pub` to eliminate it; conversely, keep `pub` on declarations that need to
be called externally.
