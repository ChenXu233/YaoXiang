# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`; then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code. Their default emission
level is `warn`, which does not prevent compilation. The exception is `W1090`, whose emission level
is `error` (the same-code promotion to E was ruled by the user on 2026-10-13; see its entry for
details). Triggering it increments `error_count`, changes the exit code, and prevents compilation.
The current registry contains **12** warning codes; for the complete index, see the
[Error Code home page](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable warnings
- `warn`: Display warnings (default)
- `deny`: Treat warnings as errors and prevent compilation

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintentional, rename
  the local module; use --deny-shadowing to promote it to an error.
- **Emission point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle has only one deterministic convention—lexicographic ordering of paths
  within the cycle—not a semantic guarantee. Breaking the cycle (moving a use in the cycle out of
  it, or changing it to deferred evaluation in a function body) makes the initialization order
  determinable. Division of labor with E3019: E3019 identifies initialization cycles between
  top-level bindings within a unit, whereas this code identifies import cycles between modules.
- **Emission point**: `src/driver/arms.rs:1853`

## Differences from Error Codes

- **Error (`E` prefix)**: Blocks compilation and must be fixed.
- **Warning (`W` prefix)**: Indicates a potential problem; the default emission level is warn, and
  fixing it is optional. The exception is `W1090`, whose emission level is error. Triggering it
  increments `error_count`, changes the exit code, prevents compilation, and requires a fix (see its
  entry for details).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions, types, variables, and methods. A
`pub` declaration is an external interface, and the compiler cannot know whether it has any
consumers, so these warnings are never triggered for it (decision B finalized in #321). If you see
an "unused" warning, removing the corresponding `pub` will eliminate it; conversely, retain `pub`
for declarations that need to be called externally.
