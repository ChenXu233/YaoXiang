# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`. To change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code; their default emission
severity is warn, which does not prevent compilation. Exception: `W1090` has emission severity error
(the same-code promotion to E by user decision on 2026-10-13; see its entry for details). When
triggered, it counts toward error_count and changes the exit code, preventing compilation. The
current registry contains **12** warning codes. For the complete index, see the
[Error Code Home](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Show the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local module shadows a dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename
  the local module; use --deny-shadowing to promote it to an error.
- **Emission point(s)**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of `use` dependencies;
  ordering within a cycle has only the deterministic convention of "lexicographic path order within
  the cycle" and is not a semantic guarantee. Breaking the cycle (moving one `use` dependency on the
  cycle out of it, or changing it to deferred evaluation in a function body) makes the
  initialization order determinable. Division of responsibility with E3019: E3019 detects
  initialization cycles among top-level bindings within a unit, while this code detects import
  cycles between modules.
- **Emission point(s)**: `src/driver/arms.rs:1853`

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but was never consumed:
  {detail}`
- **Help**: This is a stage-contract defect within the compiler, not an error in your program: an
  obligation field produced by one stage is not read by the next stage, so the obligation's effects
  may have been silently discarded. Please report this diagnostic as an issue together with the
  field name and file path, and attach a minimal reproducer. This code belongs to the **W family**
  (code prefix W), but its **emission severity is error**: the user decision of 2026-10-13 (WBS
  4.3.2, the terminal state of RFC-039 D5) **promotes the same code to E** without adding a new E
  code (the two codes represent the same fact in parallel). The emission severity is determined by
  the explicit severity; when triggered, it counts toward error_count and changes the exit code,
  preventing compilation. Note that healthy programs emit no diagnostics (no report is issued when
  all obligations have delivery markers), so this promotion affects the build result only when the
  defect actually occurs.
- **Emission point(s)**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:547`

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems; their default emission severity is warn,
  and you may choose to fix them. Exception: `W1090` has emission severity error. When triggered, it
  counts toward error_count and changes the exit code, preventing compilation, and must be fixed
  (see its entry for details).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is a public interface, and the compiler has no way of knowing whether external
consumers exist, so these warnings are never emitted for it (#321, Decision B). If you see an
"unused" warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` for
declarations that need to be called externally.
