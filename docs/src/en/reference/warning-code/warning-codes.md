# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`; then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes begin with `W` and indicate potential problems in the code. Their default emission
level is warn, which does not prevent compilation. The exception is `W1090`, whose emission level is
error (promotion of the same code to E under the 2026-10-13 user ruling; see its entry for details).
When triggered, it counts toward error_count, changes the exit code, and prevents compilation. The
current registry contains **12** warning codes. For a complete index, see the
[Error Code Home](../error-code/index.md).

## Configuration

You can configure dead-code warning behavior through `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable warnings
- `warn`: Display warnings (default)
- `deny`: Treat warnings as errors and prevent compilation

### W1006: Local Module Shadows Dependency Package

- **Category**: `Warning`
- **span Exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename the
  local module; use --deny-shadowing to promote it to an error.
- **Emission Point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module Import Cycle

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic lexicographic-path convention (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle has only one deterministic convention—lexicographic order of paths within
  the cycle—which is not a semantic guarantee. Breaking the cycle (moving a use in the cycle out of
  the cycle, or changing it to deferred evaluation in a function body) allows the initialization
  order to be determined. Division of labor with E3019: E3019 detects initialization cycles among
  top-level bindings within a unit, whereas this code detects import cycles between modules.
- **Emission Point**: `src/driver/arms.rs:1853`

### W1082: Ownership Analysis Downgraded

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions are made against an empty ledger and borrow conflicts are not detected`
- **Help**: This is a defect in the compiler's internal stage contract, not a mistake in your
  program: the ownership layer cannot obtain the type ledger and call-site ownership table supplied
  by the function-body checker at runtime, so it lets the code through as though "nothing
  conflicts"—the entire borrow-conflict check is skipped. Please report this diagnostic, together
  with a minimal reproducer, as an issue.
- **Emission Point**: `src/frontend/core/sema/checker.rs:1420`

### W1090: Obligation Produced but Not Consumed

- **Category**: `Warning`
- **span Exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a defect in the compiler's internal stage contract, not a mistake in your
  program: an obligation field produced by one stage is not read by the next stage, so the
  obligation's effects may have been silently discarded. Please report this diagnostic as an issue,
  along with the field name and file path, and include a minimal reproducer. This code belongs to
  the **W family** (code prefix W), but its **emission level is error**: the user ruling of
  2026-10-13 (WBS 4.3.2, final state of RFC-039 D5) **promotes the same code to E**—no new E code is
  added (using two codes for the same fact is a parallel representation), and the emission level is
  determined by the explicit severity. When triggered, it counts toward error_count and changes the
  exit code. Note that healthy programs produce zero emissions (the diagnostic is not reported when
  all obligations have delivery markers), so the promotion affects the build result only when this
  defect actually occurs.
- **Emission Point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:547`

## Difference from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems. The default emission level is warn, and
  they may be fixed. The exception is `W1090`, whose emission level is error. When triggered, it
  counts toward error_count, changes the exit code, prevents compilation, and must be fixed (see its
  entry for details).

## Criteria for Dead-Code Warnings

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler cannot know whether there are external
consumers, so these warnings are never emitted (#321, finalized decision B). If you see an "unused"
warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` for declarations
that need to be called externally.
