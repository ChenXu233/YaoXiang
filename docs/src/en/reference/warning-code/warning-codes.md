# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and flag potential problems in the code. Their default emission level
is warn, which does not prevent compilation. The exception is `W1090`, whose emission level is error
(the same code was promoted to E by the user ruling on 2026-10-13; see its entry below). When
triggered, it counts toward error_count, changes the exit code, and prevents compilation. The
current registry contains **12** warning codes. For a complete index, see the
[error code index](../error-code/index.md).

## Configuration

You can configure dead-code warning behavior through `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Show the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local modules have the highest resolution priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename
  the local module; use --deny-shadowing to promote it to an error.
- **Emission point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle follows only the deterministic convention of "lexicographic order of paths
  within the cycle" and is not a semantic guarantee. Breaking the cycle (moving one use on the cycle
  out of it, or switching to deferred evaluation in a function body) makes the initialization order
  determinable. Division of responsibility with E3019: E3019 detects initialization cycles between
  top-level bindings within a unit, whereas this code detects import cycles between modules.
- **Emission point**: `src/driver/arms.rs:1853`

### W1082: Ownership analysis degraded

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Ownership analysis degraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership determination uses an empty ledger and borrow conflicts are not detected`
- **Help**: This is a defect in the compiler's internal stage contract, not an error in your
  program: at runtime, the ownership layer cannot access the type ledger and call-site ownership
  table provided by the function-body checker, so it lets everything through as if nothing
  conflicted—the entire borrow-conflict check is skipped. Please report this diagnostic together
  with a minimal reproducer as an issue.
- **Emission point**: `src/frontend/core/sema/checker.rs:1303`

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a defect in the compiler's internal stage contract, not an error in your
  program: an obligation field produced by one stage is not read by the next stage, so the effect of
  the obligation may have been silently discarded. Please report this diagnostic together with the
  field name and file path as an issue, and attach a minimal reproducer. This code belongs to the
  **W family** (code prefix W), but its **emission level is error**: the user ruling of 2026-10-13
  (WBS 4.3.2, terminal state of RFC-039 D5) **promotes the same code to E**—no new E code is added
  (two codes for the same fact would be parallel representations), and the emission level is
  determined by the explicit severity. When triggered, it counts toward error_count and changes the
  exit code. Note: healthy programs produce zero emissions (the warning is not emitted when all
  obligations have delivery markers), so the promotion affects the build result only when this
  defect actually occurs.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Flag potential problems. Their default emission level is warn, and you
  may choose to fix them. The exception is `W1090`, whose emission level is error; when triggered,
  it counts toward error_count, changes the exit code, prevents compilation, and must be fixed (see
  its entry above).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions, types, variables, and methods. A
`pub` declaration is a public interface, and the compiler has no way of knowing whether external
consumers exist, so these warnings are never triggered for it (decision B of #321). If you see an
"unused" warning, remove the corresponding `pub` to eliminate it. Conversely, keep `pub` on
declarations that need to be called externally.
