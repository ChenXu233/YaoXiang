# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and do not prevent compilation, but they indicate that the code may
contain problems. The current registry contains **12** warning codes; for the complete index, see
the [Error Code Index](../error-code/index.md).

## Configuration

You can configure dead-code warning behavior in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local Module Shadows Dependency Package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): `'./src/{module}'` overrides
  the dependency package `'{dependency}'` in `.yaoxiang/vendor/`. If the shadowing is unintentional,
  rename the local module; use `--deny-shadowing` to promote it to an error.
- **Emission site**: `src/driver/arms.rs:642`, `src/util/diagnostic/command.rs:78`

### W1007: Module Import Cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of `use` dependencies; the
  only deterministic convention for ordering within a cycle is "lexicographic order of paths within
  the cycle," which is not a semantic guarantee. Breaking the cycle (by moving one `use` in the
  cycle out of it, or by changing it to deferred evaluation inside a function body) makes the
  initialization order determinable. Division of responsibility with E3019: E3019 detects
  initialization cycles between top-level bindings within a unit, whereas this code detects import
  cycles between modules.
- **Emission site**: `src/driver/arms.rs:1726`

### W1082: Ownership Analysis Downgraded

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions are made against an empty ledger and borrow conflicts are not detected`
- **Help**: This is an internal compiler stage-contract defect, not an error in your program: at
  runtime, the ownership layer cannot obtain the type ledger and call-site ownership table provided
  by the function-body checker, so it lets the program pass as though "nothing conflicts"—the entire
  borrow-conflict check is skipped. Please report this diagnostic together with a minimal reproducer
  as an issue.
- **Emission site**: `src/frontend/core/typecheck/checker.rs:1620`

### W1090: Obligation Produced but Not Consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is an internal compiler stage-contract defect, not an error in your program: an
  obligation field produced by one stage is never read by the next stage, so the obligation's
  effects may have been silently discarded. Please report this diagnostic, along with the field name
  and file path, as an issue, and attach a minimal reproducer. This code belongs to the **W family**
  (code prefix `W`), but its **emission level is `error`**: the user ruling of 2026-10-13 (WBS
  4.3.2, the terminal state of RFC-039 D5) **elevates the same code to `E`**—no new `E` code is
  added (two codes for the same fact are parallel representations), and the emission level is
  determined by the explicit severity. When triggered, it is counted in `error_count` and changes
  the exit code. Note: healthy programs produce no emissions (no diagnostic is reported when every
  obligation has a delivery marker), so the escalation affects the build result only when this
  defect actually occurs.
- **Emission site**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from Error Codes

- **Error (`E` prefix)**: Prevents compilation and must be fixed.
- **Warning (`W` prefix)**: Indicates a potential problem that may optionally be fixed.

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether there is
an external consumer, so these warnings are never triggered (Decision B of #321). If you see an
"unused" warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` for
declarations that need to be called externally.
