# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code. Their default emission
severity is `warn`, which does not prevent compilation. The exception is `W1090`, whose emission
severity is `error` (the same code was elevated to E by the user ruling dated 2026-10-13; see its
entry for details). When triggered, it counts toward `error_count`, changes the exit code, and
prevents compilation. The current registry contains **12** warning codes. See the
[Error Code Home](../error-code/index.md) for the complete index.

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local Module Shadows Dependency Package

- **Category**: `Warning`
- **Span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local modules have the highest resolution priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename
  the local module; use --deny-shadowing to elevate it to an error.
- **Emission site**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:78`

### W1007: Module Import Cycle

- **Category**: `Warning`
- **Span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within the cycle has only the single deterministic convention of “lexicographic order of
  paths within the cycle” and is not a semantic guarantee. Breaking the cycle (moving one use
  statement in the cycle out of it, or changing it to deferred evaluation in a function body) makes
  the initialization order determinable. Division of responsibility with E3019: E3019 detects an
  initialization cycle between top-level bindings within a unit, whereas this code detects an import
  cycle between modules.
- **Emission site**: `src/driver/arms.rs:1811`

- **Category**: `Warning`
- **Span exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation had no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions are made against an empty ledger and borrow conflicts are not detected`
- **Help**: This is a stage-contract defect inside the compiler, not an error in your program. At

  by the function-body checker, so it lets everything pass as though nothing conflicts—the entire
  borrow-conflict check is skipped. Please report this diagnostic, along with a minimal reproducer,
  as an issue.
- **Emission site**: `src/frontend/core/sema/checker.rs:1266`

### W1090: Obligation Produced but Not Consumed

- **Category**: `Warning`
- **Span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but was never consumed:
  {detail}`
- **Help**: This is a stage-contract defect inside the compiler, not an error in your program. An
  obligation field produced by one stage is not read by the next stage, so the effects of the
  obligation may have been silently discarded. Please report this diagnostic, along with the field
  name and file path, as an issue and attach a minimal reproducer. This code belongs to the **W
  family** (code prefix W), but its **emission severity is error**: the user ruling dated 2026-10-13
  (the final state of WBS 4.3.2, D5 of RFC-039) **elevates the same code to E**—no new E code is
  added (using two codes for the same fact would provide parallel representations). The emission
  severity is determined by the explicit severity. When triggered, the diagnostic counts toward
  `error_count` and changes the exit code. Note that healthy programs produce no emissions (the
  warning is not emitted when all obligations have delivery markers), so the elevation affects the
  build only when the defect actually occurs.
- **Emission site**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Warning Levels

## Difference from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems. Their default emission severity is `warn`,
  and they may optionally be fixed. The exception is `W1090`, whose emission severity is error. When
  triggered, it counts toward `error_count`, changes the exit code, prevents compilation, and must
  be fixed (see its entry for details).

## Criteria for Dead-Code Warnings

`W1001`–`W1005` report **unused private** (non-`pub`) functions, types, variables, and methods. A
`pub` declaration is part of the public interface, and the compiler cannot know whether external
consumers exist, so these warnings are never emitted for it (the final decision B of #321). If you
see an “unused” warning, remove the corresponding `pub` to eliminate it. Conversely, retain `pub`
for declarations that need to be called externally.
