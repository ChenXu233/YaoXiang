# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and do not prevent compilation, but they point out potential problems
in the code. The current registry contains **12** warning codes. For the complete index, see the
[error code home page](../error-code/index.md).

## Configuration

You can configure dead-code warning behavior in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): `./src/{module}` overrides
  dependency package `{dependency}` in `.yaoxiang/vendor/`. If the shadowing is unintentional,
  rename the local module; use `--deny-shadowing` to promote it to an error.
- **Emission point**: `src/driver/arms.rs:642`, `src/util/diagnostic/command.rs:78`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of `use` dependencies.
  Within a cycle, the only convention is the "lexicographic order of paths within the cycle," which
  is not a semantic guarantee. Break the cycle (move one `use` on the cycle out of it, or switch to
  deferred evaluation in a function body) to make the initialization order determinable. Division of
  responsibility with E3019: E3019 detects an initialization cycle between top-level bindings within
  a unit, whereas this code detects an import cycle between modules.
- **Emission point**: `src/driver/arms.rs:1731`

### W1082: Ownership analysis downgraded

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions are made with an empty ledger and borrow conflicts are not detected`
- **Help**: This is a defect in the compiler's internal stage contract, not an error in your
  program: at runtime, the ownership layer cannot access the type ledger and call-site ownership
  table provided by the function-body checker, so it lets everything pass as though "nothing
  conflicts"—borrow conflict checking is skipped entirely. Please file an issue with this diagnostic
  and a minimal reproducer.
- **Emission point**: `src/frontend/core/typecheck/checker.rs:1620`

### W1090: Obligation produced but has no consumer

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a defect in the compiler's internal stage contract, not an error in your
  program: an obligation field produced by one stage is never read by the next stage, so the effect
  of the obligation may have been silently discarded. Please file an issue with this diagnostic, the
  field name, and the file path, and include a minimal reproducer. This code belongs to the **W
  family** (code prefix W), but its **emission level is error**: the user decision dated 2026-10-13
  (WBS 4.3.2, the final state of RFC-039 D5) **elevates the same code to E**—no new E code is added
  (using two codes for the same fact would be a parallel representation); the emission level is
  determined by the explicit severity; when triggered, it is counted in error_count and changes the
  exit code. Note that healthy programs produce no emissions (no diagnostic is emitted when all
  obligations have delivery markers), so the promotion affects the build result only when this
  defect actually occurs.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Warning Levels

| Level  | Effect                                                 |

| `off`  | Completely disable this category of warning            |
| `warn` | Display the warning but continue compilation (default) |
| `deny` | Treat the warning as an error and prevent compilation  |

## Difference from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems and may be fixed optionally.

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. `pub`
declarations are public interfaces, and the compiler has no way of knowing whether external
consumers exist, so these warnings are never emitted (#321, Decision B). If you see an "unused"
warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` for declarations
that need to be called externally.
