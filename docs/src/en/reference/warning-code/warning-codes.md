# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`; then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code. Their default emission
level is `warn`, and they do not prevent compilation. The exception is `W1090`, whose emission level
is `error` (the same-code elevation to `E` was ruled by the user on 2026-10-13; see its entry for
details). When triggered, it counts toward `error_count`, changes the exit code, and prevents
compilation. The current registry contains **12** warning codes; for the complete index, see the
[Error Code Home](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span Exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): `'./src/{module}'` overrides
  the dependency package `'{dependency}'` in .yaoxiang/vendor/. If the shadowing is unintended,
  rename the local module; use --deny-shadowing to elevate it to an error.
- **Emission Point**: `src/driver/arms.rs:660`, `src/util/diagnostic/command.rs:78`

### W1007: Module import cycle

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Module import cycle {cycle}: the initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within the cycle follows only the deterministic convention of “lexicographic path order
  within the cycle”; it is not a semantic guarantee. Breaking the cycle (moving one use on the cycle
  out of it, or changing it to deferred evaluation in a function body) makes the initialization
  order determinable. Division of responsibility with E3019: E3019 detects initialization cycles
  between top-level bindings within a unit, whereas this code detects import cycles between modules.
- **Emission Point**: `src/driver/arms.rs:1759`

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions use an empty ledger and borrow conflicts are not detected`
- **Help**: This is a stage-contract defect inside the compiler, not a mistake in your program: at

  reproducer, as an issue.

### W1090: Obligation produced but no consumer

- **Category**: `Warning`
- **span Exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a stage-contract defect inside the compiler, not a mistake in your program: an
  obligation field produced by one stage is not read by the next stage, so the effect of the
  obligation may have been silently discarded. Please report this diagnostic as an issue, together
  with the field name and file path, and attach a minimal reproducer. This code belongs to the **W
  family** (code prefix W), but its **emission level is error**: under the user ruling of 2026-10-13
  (WBS 4.3.2, the final state of RFC-039 D5), the **same code is elevated to E**—no new E code is
  added (using two codes for the same fact would merely duplicate the representation), and the
  emission level is determined by the explicit severity. When triggered, it counts toward
  error_count and changes the exit code. Note that healthy programs produce no diagnostics (none are
  emitted when all obligations have delivery markers), so this elevation affects the build result
  only when the defect actually occurs.
- **Emission Point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from Error Codes

- **Error (`E` prefix)**: Prevents compilation and must be fixed.
- **Warning (`W` prefix)**: Indicates a potential problem; the default emission level is warn, and
  you may choose to fix it. The exception is `W1090`, whose emission level is error. When triggered,
  it counts toward error_count, changes the exit code, prevents compilation, and must be fixed (see
  its entry).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. `pub`
declarations are external interfaces, and the compiler has no way of knowing whether external
consumers exist, so these warnings are never triggered (Final Decision B of #321). If you see an
“unused” warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` on
declarations that need to be called externally.
