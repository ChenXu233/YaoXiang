# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Please do not edit by hand. To change the text,
edit `locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and do not block compilation, but they hint at possible issues in the
code. The current registry contains **11** warning codes; see the
[Error Code Index](../error-code/index.md) for the complete list.

## Configuration

The behavior of dead-code warnings can be configured via `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable the warning
- `warn`: show the warning (default)
- `deny`: treat the warning as an error and block compilation

### W1082: Ownership analysis degradation

- **Category**: `Warning`
- **span Exempt**: No
- **Template**:
  `Ownership analysis degraded: this compilation has no function-body checker (type ledger and call-site ownership table missing), ownership judgment proceeds with an empty ledger, and borrow conflicts are not detected`
- **Help**: This is an internal phase-contract defect in the compiler, not a bug in your program: at
  runtime the ownership layer cannot obtain the type ledger and call-site ownership table provided
  by the function-body checker, so it lets everything through as if "nothing conflicts" —
  borrow-conflict checking is skipped entirely. Please file this diagnostic together with a minimal
  reproduction program as an issue.
- **Emission point**: `src/frontend/core/typecheck/checker.rs:1620`

### W1090: Obligation produced but no consumer

- **Category**: `Warning`
- **span Exempt**: Yes
- **Template**: `Obligation field \`{field}\` in {file} has been produced but never consumed:
  {detail}`
- **Help**: This is an internal phase-contract defect in the compiler, not a bug in your program: an
  obligation field produced by one phase is not read by the next phase, and the effect of the
  obligation may have been silently discarded. Please file this diagnostic together with the field
  name and file path as an issue, and attach a minimal reproduction program. This code belongs to
  the **W family** (code-number prefix W), but its **emission level is error**: per the 2026-10-13
  user ruling (WBS 4.3.2, final state of RFC-039 D5), it is **promoted to E with the same code** —
  no new E code is added (a parallel representation of the same fact via two codes is not created),
  the emission level is determined by the explicit severity; once triggered, it is counted into
  error_count and changes the exit code. Note: a healthy program produces zero emissions (it is not
  reported when all obligations carry a delivery tag), so the upgrade only affects the build result
  when this defect actually appears.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Warning Levels

| Level  | Effect                                              |
| ------ | --------------------------------------------------- |
| `off`  | Completely disable this kind of warning             |
| `warn` | Show the warning but continue compilation (default) |
| `deny` | Treat the warning as an error and block compilation |

## Differences from Error Codes

- **Error (`E` prefix)**: Blocks compilation and must be fixed.
- **Warning (`W` prefix)**: Indicates a potential problem; fixing is optional.

## Dead-Code Warning Judgment Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether it has
external consumers, so it never triggers these warnings (decision B of #321). If you see an "unused"
warning, removing the corresponding `pub` will suppress it; conversely, for declarations that need
to be called externally, please keep `pub`.
