# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`; then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes begin with `W` and indicate potential problems in the code; their default emission
level is warn, which does not prevent compilation. Exception: `W1090` has an emission level of error
(the same-code promotion to E decided by users on 2026-10-13; see its entry for details). When
triggered, it counts toward error_count and changes the exit code, preventing compilation. The
current registry contains **12** warning codes; see the [error code index](../error-code/index.md)
for the complete list.

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span Exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local modules have the highest resolution priority (RFC-014): './src/{module}' overrides
  dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename the
  local module; use --deny-shadowing to promote it to an error.
- **Emission Point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module import cycle

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic lexicographic path-order convention (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies;
  ordering within a cycle follows only the deterministic convention of lexicographic path order and
  is not a semantic guarantee. Breaking the cycle (moving one use in the cycle out of it, or
  changing it to deferred evaluation in a function body) makes the initialization order decidable.
  Division of responsibility with E3019: E3019 detects initialization cycles between top-level
  bindings within a unit, whereas this code detects import cycles between modules.
- **Emission Point**: `src/driver/arms.rs:1853`

### W1082: Ownership analysis degraded

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Ownership analysis degraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions are made against an empty ledger and borrow conflicts are not detected`
- **Help**: This is a defect in an internal compiler stage contract, not an error in your program:
  at runtime, the ownership layer cannot access the type ledger and call-site ownership table
  provided by the function-body checker, so it lets everything pass with "no conflicts"—the borrow
  conflict check is skipped entirely. Please report this diagnostic together with a minimal
  reproducer as an issue.
- **Emission Point**: `src/frontend/core/sema/checker.rs:1433`

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span Exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a defect in an internal compiler stage contract, not an error in your program:
  an obligation field produced by one stage is not read by the next, so the effect of the obligation
  may have been silently discarded. Please report this diagnostic together with the field name and
  file path as an issue, and attach a minimal reproducer. This code belongs to the **W family**
  (code prefix W), but its **emission level is error**: the 2026-10-13 user decision (final state of
  WBS 4.3.2, RFC-039 D5) **promotes the same code to E**—no new E code is added (using two codes for
  the same fact would provide parallel representations), and the emission level is determined by the
  explicit severity; when triggered, it counts toward error_count and changes the exit code. Note:
  healthy programs produce zero emissions (no warning is reported when all obligations have delivery
  markers), so the promotion affects build results only when this defect actually occurs.
- **Emission Point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:547`

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems; the default emission level is warn, and
  they may be fixed as needed. Exception: `W1090` has an emission level of error; when triggered, it
  counts toward error_count and changes the exit code, preventing compilation, and must be fixed
  (see its entry for details).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler cannot know whether an external
consumer exists, so these warnings are never emitted for it (final decision B in #321). If you see
an "unused" warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` on
declarations that need to be called externally.
