# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`; then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code. Their default emission
level is `warn`, which does not block compilation. The exception is `W1090`, whose emission level is
`error` (the user ruling of 2026-10-13 promoted the same code to E; see its entry). When triggered,
it counts toward error_count, changes the exit code, and blocks compilation. The registry currently
contains **12** warning codes; see the [Error Code Index](../error-code/index.md) for the complete
index.

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable the warning
- `warn`: display the warning (default)
- `deny`: treat the warning as an error and block compilation

## Per-Code Details

### W1001: Unused private function

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `unused function: '{name}'`
- **Help**: The function is never referenced; consider removing it or adding a call to it. This
  warning is not reported if another file in the package references it.
- **Emission point**: `src/frontend/core/typecheck/passes/dead_code.rs:861`

### W1006: Local module shadows a dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' takes
  precedence over the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is
  unintended, rename the local module; you can use --deny-shadowing to promote it to an error.
- **Emission point**: `src/driver/arms.rs:642`, `src/util/diagnostic/command.rs:78`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: The initialization order follows the topological order of use dependencies. Within the
  cycle, the only ordering convention is the deterministic “lexicographic order of paths within the
  cycle,” and it is not a semantic guarantee. Breaking the cycle (by moving one use in the cycle out
  of it, or changing it to lazy evaluation in a function body) makes the initialization order
  determinable. Division of responsibility with E3019: E3019 detects initialization cycles between
  top-level bindings within a unit, whereas this code detects import cycles between modules.
- **Emission point**: `src/driver/arms.rs:1731`

- **Help**: Ensure that the const parameter is a compile-time constant.
- **Emission point**: `src/frontend/core/typecheck/checker.rs:1547`

### W1081: Termination obligation not determined

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `{count} termination measure obligation(s) not determined (SMT solver unavailable)`
- **Help**: Install the Z3 solver and check again to obtain a termination determination. “Not
  determined” does not mean “non-terminating”; it means that determination of the obligation was
  skipped.
- **Emission point**: `src/frontend/core/typecheck/checker.rs:1534`

### W1082: Ownership analysis downgraded

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `ownership analysis downgraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions are made with an empty ledger and borrow conflicts are not detected`
- **Help**: This is a defect in the compiler's internal stage contract, not an error in your
  program: at runtime, the ownership layer cannot access the type ledger and call-site ownership
  table provided by the function-body checker, so it lets the program through as though “nothing
  conflicts”—the borrow-conflict check is skipped entirely. Please report this diagnostic together
  with a minimal reproducer as an issue.
- **Emission point**: `src/frontend/core/typecheck/checker.rs:1620`

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `obligation field \`{field}\` was produced in {file} but was never consumed:
  {detail}`
- **Help**: This is a defect in the compiler's internal stage contract, not an error in your
  program: an obligation field produced by one stage is not read by the next stage, so the effect of
  the obligation may have been silently discarded. Please report this diagnostic together with the
  field name and file path as an issue, and include a minimal reproducer. This code belongs to the
  **W family** (code prefix W), but its **emission level is error**: the user ruling of 2026-10-13
  (WBS 4.3.2, final state of RFC-039 D5) **promotes the same code to E**—no new E code is added (two
  codes for the same fact would be parallel representations)—and the emission level is determined by
  the explicit severity. When triggered, it counts toward error_count and changes the exit code.
  Note: healthy programs emit nothing (no diagnostic is emitted when all obligations have delivery
  markers), so this escalation affects the build result only when the defect actually occurs.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Warning Levels

| Level  | Effect                                              |
| ------ | --------------------------------------------------- |
| `off`  | Completely disable this category of warnings        |
| `warn` | Display warnings but continue compilation (default) |
| `deny` | Treat warnings as errors and block compilation      |

## Differences from Error Codes

- **Errors (`E` prefix)**: Block compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems; the default emission level is warn, and
  they can optionally be fixed. The exception is `W1090`, whose emission level is error. When
  triggered, it counts toward error_count, changes the exit code, blocks compilation, and must be
  fixed (see its entry).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is part of the public interface, and the compiler has no way of knowing whether
external consumers exist, so it never emits these warnings for such declarations (#321, finalized
decision B). If you see an “unused” warning, remove the corresponding `pub` to eliminate it;
conversely, retain `pub` for declarations that need to be called externally.
