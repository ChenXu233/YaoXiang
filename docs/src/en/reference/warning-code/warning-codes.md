# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W`. They do not prevent compilation, but they indicate potential problems
in the code. The current registry contains **12** warning codes. For a complete index, see the
[Error Code Home](../error-code/index.md).

## Configuration

You can configure the behavior of dead-code warnings through `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable warnings
- `warn`: Display warnings (default)
- `deny`: Treat warnings as errors and prevent compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename
  the local module. Use --deny-shadowing to promote it to an error.
- **Emission site**: `src/driver/arms.rs:642`, `src/util/diagnostic/command.rs:78`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: the initialization order within the cycle cannot be determined, and reading a top-level value that has not yet been initialized reports E6007 at runtime`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle has only the deterministic convention of "lexicographic order of paths
  within the cycle," which is not a semantic guarantee. Breaking the cycle (moving one use on the
  cycle out of the cycle, or changing it to deferred evaluation in a function body) makes the
  initialization order determinable. Division of responsibility with E3019: E3019 detects an
  initialization cycle between top-level bindings within a unit, whereas this code detects an import
  cycle between modules.
- **Emission site**: `src/driver/arms.rs:1726`

### W1082: Ownership analysis downgraded

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function body checker (the type ledger and call-site ownership table are missing), so ownership decisions are made using an empty ledger and borrow conflicts are not detected`
- **Help**: This is a flaw in the compiler's internal stage contract, not an error in your program.

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a flaw in the compiler's internal stage contract, not an error in your program.
  An obligation field produced by one stage is not read by the next stage, so the effect of the
  obligation may have been silently discarded. Please report this diagnostic together with the field
  name and file path as an issue, and include a minimal reproducer. This code belongs to the **W
  family** (code prefix W), but its **emission level is error**: the user ruling of 2026-10-13 (WBS
  4.3.2, final state of RFC-039 D5) **promotes the same code to E**—no new E code is added (using
  two codes for the same fact would be a parallel representation), and the emission level is
  determined by the explicit severity. When triggered, it is counted in error_count and changes the
  exit code. Note: healthy programs emit zero diagnostics (this warning is not reported when all
  obligations have delivery markers), so the upgrade affects the build result only when this defect
  actually occurs.
- **Emission site**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems and may be fixed at your discretion.

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether external
consumers exist, so these warnings are never emitted for it (final decision B in #321). If you see
an "unused" warning, removing the corresponding `pub` eliminates it. Conversely, retain `pub` for
declarations that need to be called externally.
