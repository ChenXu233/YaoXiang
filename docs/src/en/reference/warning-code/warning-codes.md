# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential issues in the code. Their default emission level
is `warn` and does not block compilation. The exception is `W1090`, whose emission level is `error`
(the same code was promoted to E by the user ruling dated 2026-10-13; see its entry). Triggering it
increments `error_count`, changes the exit code, and blocks compilation. The current registry
contains **12** warning codes. For the complete index, see the
[Error Code Home](../error-code/index.md).

## Configuration

You can configure dead-code warning behavior through `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and block compilation

- **Category**: `Warning`

- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename
  the local module; use --deny-shadowing to promote it to an error.
- **Emission site**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module Import Cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic lexicographic-by-path convention (not a semantic guarantee)`
- **Help**: Initialization order follows the topological order of use dependencies. Ordering within
  a cycle follows only the deterministic convention of "lexicographic order of paths within the
  cycle"; it is not a semantic guarantee. Break the cycle (move a use declaration in the cycle out
  of it, or switch to deferred evaluation inside a function body) to make the initialization order
  decidable. Division of responsibility with E3019: E3019 detects initialization cycles between
  top-level bindings within a unit, whereas this code detects import cycles between modules.
- **Emission site**: `src/driver/arms.rs:1853`

## Difference from Error Codes

- **Errors (`E` prefix)**: Block compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential issues; their default emission level is `warn`, and
  you may choose to fix them. The exception is `W1090`, whose emission level is `error`. Triggering
  it increments `error_count`, changes the exit code, and blocks compilation, so it must be fixed
  (see its entry).

## Dead-Code Warning Criteria

`W1001`–`W1005` report functions, types, variables, and methods that are **unused and private**
(that is, not `pub`). A `pub` declaration is a public interface, and the compiler has no way of
knowing whether external consumers exist, so these warnings never trigger (finalized as decision B
in #321). If you see an "unused" warning, remove the corresponding `pub` to eliminate it;
conversely, retain `pub` on declarations that need to be called from outside.
