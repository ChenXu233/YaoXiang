# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate possible problems in the code; their default emission
level is `warn`, which does not block compilation. Exception: `W1090` has an emission level of
`error` (the same-code promotion to E under the user ruling dated 2026-10-13; see its entry), so
triggering it is counted toward error_count, changes the exit code, and blocks compilation. The
registry currently contains **12** warning codes; for the complete index, see the
[Error Code Index](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and block compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span Exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local modules have the highest resolution priority (RFC-014): './src/{module}' overrides
  dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename the
  local module; use --deny-shadowing to promote it to an error.
- **Emission Point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module import cycle

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Module import cycle {cycle}: the initialization order within the cycle cannot be determined; ordering within the cycle follows only the deterministic convention of lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies;
  ordering within a cycle follows only the deterministic convention of lexicographic path order and
  is not a semantic guarantee. Breaking the cycle (moving one use in the cycle out of it, or
  changing it to deferred evaluation in a function body) makes the initialization order
  determinable. Division of responsibility with E3019: E3019 detects initialization cycles between
  top-level bindings within a unit, whereas this code detects import cycles between modules.
- **Emission Point**: `src/driver/arms.rs:1853`

- **Help**: Install the Z3 solver and run the checks again to obtain a termination decision; an

### W1082: Ownership analysis downgraded

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions use an empty ledger and borrow conflicts are not detected`
- **Help**: This is an internal stage-contract defect in the compiler, not an error in your program:
  at runtime, the ownership layer cannot obtain the type ledger and call-site ownership table
  provided by the function-body checker, so it lets the program through on a "nothing conflicts"
  basis—the entire borrow-conflict check is skipped. Please report this diagnostic together with a
  minimal reproducer as an issue.
- **Emission Point**: `src/frontend/core/sema/checker.rs:1280`

### W1090: Obligation produced but no consumer

- **Category**: `Warning`
- **span Exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is an internal stage-contract defect in the compiler, not an error in your program:
  an obligation field produced by one stage is not read by the next, so the effect of the obligation
  may have been silently discarded. Please report this diagnostic as an issue together with the
  field name and file path, and include a minimal reproducer. This code belongs to the **W family**
  (code prefix W), but its **emission level is error**: the user ruling dated 2026-10-13 (WBS 4.3.2,
  final state of RFC-039 D5) **promotes the same code to E**—without adding a new E code (two codes
  for the same fact would be parallel representations)—and the emission level is determined by the
  explicit severity; triggering it is counted toward error_count and changes the exit code. Note:
  healthy programs emit nothing (no warning is reported when all obligations have delivery markers),
  so the promotion affects the build result only when this defect actually occurs.
- **Emission Point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Difference from Error Codes

- **Error (`E` prefix)**: Blocks compilation and must be fixed.
- **Warning (`W` prefix)**: Indicates a potential problem; the default emission level is `warn`, and
  you may choose to fix it. Exception: `W1090` has an emission level of `error`; triggering it is
  counted toward error_count, changes the exit code, blocks compilation, and must be fixed (see its
  entry).

## Criteria for Dead-Code Warnings

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler cannot know whether external consumers
exist, so these warnings are never triggered (final decision B for #321). If you see an "unused"
warning, remove the corresponding `pub` modifier to eliminate it; conversely, keep `pub` on
declarations that need to be called externally.
