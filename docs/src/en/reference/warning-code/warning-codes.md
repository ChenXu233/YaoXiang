# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes begin with `W` and indicate potential problems in the code. Their default emission
level is `warn`, which does not prevent compilation. The exception is `W1090`, whose emission level
is `error` (the same code was promoted to E by the user ruling dated 2026-10-13; see its entry for
details). When triggered, it counts toward `error_count`, changes the exit code, and prevents
compilation. The current registry contains **12** warning codes. See the
[Error Code Index](../error-code/index.md) for the complete index.

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local Module Shadows Dependency Package

- **Category**: `Warning`
- **Span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local modules have the highest resolution priority (RFC-014): './src/{module}' overrides
  dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename the
  local module; use --deny-shadowing to promote it to an error.
- **Emission site**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:78`

### W1007: Module Import Cycle

- **Category**: `Warning`
- **Span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on the lexicographic order of paths (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle follows only the deterministic convention of lexicographic order among the
  paths in the cycle; it is not a semantic guarantee. Breaking the cycle (moving one use in the
  cycle out of it, or changing it to deferred evaluation in a function body) makes the
  initialization order determinable. Division of responsibility with E3019: E3019 identifies
  initialization cycles between top-level bindings within a unit, whereas this code identifies
  import cycles between modules.
- **Emission site**: `src/driver/arms.rs:1811`

- **Help**: This is a defect in the compiler's internal stage contract, not an error in your

  the field name and file path, as an issue, and attach a minimal reproducer. This code belongs to

  delivery markers), so the upgrade affects the build result only when this defect actually occurs.

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems. Their default emission level is `warn`,
  and you can choose whether to fix them. The exception is `W1090`, whose emission level is `error`;
  when triggered, it counts toward error_count, changes the exit code, prevents compilation, and
  must be fixed (see its entry for details).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions, types, variables, and methods. A
`pub` declaration is part of the external interface, and the compiler cannot know whether external
consumers exist, so these warnings are never emitted for it (Decision B of #321). If you see an
“unused” warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` for
declarations that need to be called externally.
