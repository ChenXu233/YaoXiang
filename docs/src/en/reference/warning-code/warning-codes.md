# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/en.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with W and indicate potential problems in the code. Their default emission level
is `warn`, so they do not prevent compilation. Exception: `W1090` has an emission level of `error`
(the 2026-10-13 user ruling promoted the same code to E; see its entry for details). When triggered,
it counts toward `error_count` and changes the exit code, blocking compilation. The registry
currently contains **12** warning codes. For the complete index, see the
[error code home](../error-code/index.md).

## Configuration

You can configure dead-code warning behavior in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable warnings
- `warn`: Display warnings (default)
- `deny`: Treat warnings as errors and block compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **Span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): `./src/{module}` overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename
  the local module; use --deny-shadowing to promote it to an error.
- **Emission site**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module import cycle

- **Category**: `Warning`
- **Span exemption**: No
- **Template**:
  `Module import cycle {cycle}: Initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic lexicographic path-order convention (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle follows only the deterministic convention of "lexicographic order of paths
  within the cycle" and is not a semantic guarantee. Breaking the cycle (removing one use dependency
  from the cycle, or changing it to lazy evaluation inside a function body) makes the initialization
  order well-defined. Division of responsibility with E3019: E3019 detects initialization cycles
  between top-level bindings within a unit, whereas this code detects import cycles between modules.
- **Emission site**: `src/driver/arms.rs:1853`

- **Category**: `Warning`

- **Help**: This is an internal stage-contract defect in the compiler, not a mistake in your

  of the obligation may have been silently discarded. Please report this diagnostic, together with
  the field name and file path, as an issue, and include a minimal reproducer. This code belongs to
  the **W family** (code prefix W), but its **emission level is error**: the 2026-10-13 user ruling

  determined by the explicit severity; when triggered, it counts toward `error_count` and changes

  delivery markers), so the promotion affects the build result only when the defect actually occurs.
- **Emission site**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:547`

## Warning Levels

| Level  | Effect                                                 |
| ------ | ------------------------------------------------------ |
| `off`  | Completely disable this category of warning            |
| `warn` | Display the warning but continue compilation (default) |
| `deny` | Treat the warning as an error and block compilation    |

## Difference from Error Codes

- **Errors (`E` prefix)**: Block compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems; their default emission level is `warn`,
  and fixing them is optional. Exception: `W1090` has an emission level of `error`; when triggered,
  it counts toward `error_count` and changes the exit code, blocks compilation, and must be fixed
  (see its entry for details).

## Criteria for Dead-Code Warnings

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler cannot know whether external consumers
exist, so these warnings are never triggered (#321, Decision B). If you see an "unused" warning,
remove the corresponding `pub` to eliminate it; conversely, retain `pub` on declarations that need
to be called externally.
