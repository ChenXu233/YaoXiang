# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code; their default emission
severity is warn, which does not block compilation. The exception is `W1090`, whose emission
severity is error (the same code was promoted to E by the user ruling on 2026-10-13; see its entry
for details). Triggering it counts toward error_count, changes the exit code, and blocks
compilation. The current registry contains **12** warning codes. For the complete index, see the
[error-code homepage](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning severity: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and block compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local modules have the highest resolution priority (RFC-014): './src/{module}' overrides
  dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename the
  local module; use --deny-shadowing to promote it to an error.
- **Emission points**: `src/driver/arms.rs:667`, `src/util/diagnostic/command.rs:78`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of `use` dependencies;
  ordering within a cycle has only the deterministic convention of "lexicographic order of paths
  within the cycle", which is not a semantic guarantee. Break the cycle (move one `use` in the cycle
  out of it, or change it to deferred evaluation inside a function body) to make the initialization
  order determinable. Division of responsibility with E3019: E3019 detects an initialization cycle
  between top-level bindings within a unit, whereas this code detects an import cycle between
  modules.
- **Emission points**: `src/driver/arms.rs:1799`

- **Category**: `Warning`

- **Help**: This is a flaw in an internal compiler stage contract, not an error in your program: the

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a flaw in an internal compiler stage contract, not an error in your program: an
  obligation field produced by one stage is not read by the next, so the effect of the obligation
  may have been silently discarded. Please report this diagnostic together with the field name and
  file path as an issue, and attach a minimal reproducer. This code belongs to the **W family**
  (code prefix W), but its **emission severity is error**: according to the user ruling on
  2026-10-13 (WBS 4.3.2, final state of RFC-039 D5), the **same code is promoted to E**—no new E
  code is added (using two codes for the same fact would be a parallel representation)—and the
  emission severity is determined by the explicit severity; triggering it counts toward error_count
  and changes the exit code. Note: healthy programs produce zero emissions (no warning is reported
  when all obligations have delivery markers), so the promotion affects build results only when this
  defect actually occurs.
- **Emission points**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Difference from Error Codes

- **Error (`E` prefix)**: Blocks compilation and must be fixed.
- **Warning (`W` prefix)**: Indicates a potential problem; the default emission severity is warn,
  and fixing it is optional. The exception is `W1090`, whose emission severity is error; triggering
  it counts toward error_count, changes the exit code, blocks compilation, and requires a fix (see
  its entry for details).

## Criteria for Dead-Code Warnings

`W1001`–`W1005` report **unused private** (non-`pub`) functions, types, variables, and methods. A
`pub` declaration is an external interface, and the compiler cannot know whether external consumers
exist, so these warnings are never emitted for it (decision B finalized in #321). If you see an
"unused" warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` for
declarations that need to be called externally.
