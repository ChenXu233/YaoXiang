# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code registry, edit `define_codes!`; then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes begin with `W` and indicate potential problems in the code; their default emission
level is warn, and they do not block compilation. The exception is `W1090`, whose emission level is
error (the same code was promoted to E by the user ruling of 2026-10-13; see its entry). When
emitted, it counts toward error_count, changes the exit code, and blocks compilation. The current
registry contains **12** warning codes; see the [Error Code Index](../error-code/index.md) for the
complete index.

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable the warning
- `warn`: display the warning (default)
- `deny`: treat the warning as an error and block compilation

- **Category**: `Warning`

- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing was unintended,
  rename the local module; use --deny-shadowing to promote it to an error.
- **Emission Point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module Import Cycle

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Module import cycle {cycle}: the initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle follows only the deterministic convention of "lexicographic ordering of
  paths within the cycle" and is not a semantic guarantee. Breaking the cycle (moving one use
  statement out of the cycle, or changing it to deferred evaluation in a function body) makes the
  initialization order determinable. Division of responsibility with E3019: E3019 detects
  initialization cycles between top-level bindings within a unit, whereas this code detects import
  cycles between modules.
- **Emission Point**: `src/driver/arms.rs:1853`

  defect actually occurs.

## Differences from Error Codes

- **Errors (`E` prefix)**: Block compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential issues; their default emission level is warn, and
  they may be fixed as needed. The exception is `W1090`, whose emission level is error. When
  emitted, it counts toward error_count, changes the exit code, blocks compilation, and must be
  fixed (see its entry).

## Criteria for Dead-Code Warnings

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. `pub`
declarations are external interfaces, and the compiler has no way of knowing whether external
consumers exist, so these warnings are never triggered for them (final decision B for #321). If you
see an "unused" warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub`
for declarations that need to be called externally.
