# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`. To change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes begin with `W` and indicate potential problems in the code. Their default emission
level is warn, which does not prevent compilation. The exception is `W1090`, whose emission level is
error (the same-code promotion to E was established by the user ruling on 2026-10-13; see its entry
for details). When triggered, it is counted toward error_count, changes the exit code, and prevents
compilation. The current registry contains **12** warning codes. See the
[Error Code Index](../error-code/index.md) for the complete index.

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local Module Shadows Dependency Package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing was unintended,
  rename the local module; use --deny-shadowing to promote it to an error.
- **Emission point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module Import Cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle follows only the deterministic convention of "lexicographic order of paths
  within the cycle" and is not a semantic guarantee. Breaking the cycle—either by moving one use in
  the cycle out of the cycle or by switching to deferred evaluation in a function body—makes the
  initialization order determinable. Division of responsibilities with E3019: E3019 determines
  initialization cycles among top-level bindings within a unit, whereas this code determines import
  cycles between modules.
- **Emission point**: `src/driver/arms.rs:1853`

### W1082: Ownership Analysis Downgraded

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function body checker (the type ledger and call-site ownership table are missing); ownership decisions are made using an empty ledger and borrow conflicts are not detected`
- **Help**: This is a defect in the compiler's internal stage contract, not an error in your
  program. The ownership layer cannot access the type ledger and call-site ownership table provided
  by the function body checker at runtime, so it allows everything through under the assumption that

  together with a minimal reproduction program as an issue.
- **Emission point**: `src/frontend/core/sema/checker.rs:1264`

### W1090: Obligation Produced but Has No Consumer

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but was never consumed:
  {detail}`
- **Help**: This is a defect in the compiler's internal stage contract, not an error in your
  program. An obligation field produced by one stage is not read by the next stage, so the effect of
  the obligation may have been silently discarded. Please report this diagnostic together with the
  field name and file path as an issue, and include a minimal reproduction program. This code
  belongs to the **W family** (code prefix W), but its **emission level is error**: the 2026-10-13
  user ruling (the final state of WBS 4.3.2 and RFC-039 D5) **promotes the same code to E**—no new E
  code is added (a single fact is represented by two codes in parallel), and the emission level is
  determined by the explicit severity. When triggered, it is counted toward error_count and changes
  the exit code. Note that healthy programs emit nothing—the warning is not reported when all
  obligations have delivery markers—so the promotion affects the build result only when this defect
  actually occurs.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems. Their default emission level is warn, and
  you can choose whether to fix them. The exception is `W1090`, whose emission level is error. When
  triggered, it is counted toward error_count, changes the exit code, prevents compilation, and must
  be fixed (see its entry for details).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions, types, variables, and methods. A
`pub` declaration is a public interface, and the compiler cannot know whether an external consumer
exists, so these warnings are never triggered for `pub` declarations (decision B in #321). If you
see an "unused" warning, remove the corresponding `pub` to eliminate it. Conversely, retain `pub`
for declarations that need to be called externally.
