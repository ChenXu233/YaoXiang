# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code; their default emission
level is warn, which does not prevent compilation. Exception: `W1090` has an emission level of error
(the same code was promoted to E by a user ruling on 2026-10-13; see its entry for details). When
triggered, it counts toward error_count, changes the exit code, and prevents compilation. The
current registry contains **12** warning codes; see the [Error Code Index](../error-code/index.md)
for the complete index.

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Show the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local module shadows a dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename
  the local module; use --deny-shadowing to promote it to an error.
- **Emission point**: `src/driver/arms.rs:642`, `src/util/diagnostic/command.rs:78`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies;
  ordering within a cycle follows only the deterministic convention of "lexicographic order of paths
  within the cycle" and is not a semantic guarantee. Breaking the cycle (moving one use in the cycle
  out of it, or switching to lazy evaluation in a function body) makes the initialization order
  determinable. Division of responsibility with E3019: E3019 detects an initialization cycle between
  top-level bindings within a unit, whereas this code detects an import cycle between modules.
- **Emission point**: `src/driver/arms.rs:1731`

### W1082: Ownership analysis downgrade

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions are made against an empty ledger and borrow conflicts are not detected`
- **Help**: This is a flaw in an internal compiler phase contract, not an error in your program: the
  ownership layer cannot access the type ledger and call-site ownership table provided by the
  function-body checker at runtime, so it lets everything pass as though nothing conflicted—borrow
  conflict checking is skipped entirely. Please file an issue with this diagnostic and a minimal
  reproducer.
- **Emission point**: `src/frontend/core/typecheck/checker.rs:1620`

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but was never consumed:
  {detail}`
- **Help**: This is a flaw in an internal compiler phase contract, not an error in your program: an
  obligation field produced by one phase is not read by the next phase, so the obligation's effect
  may have been silently discarded. Please file an issue with this diagnostic, the field name, the
  file path, and a minimal reproducer. This code belongs to the **W family** (code prefix W), but
  its **emission level is error**: the user ruling of 2026-10-13 (WBS 4.3.2, the final state of
  RFC-039 D5) promoted the **same code to E** without adding a new E code (representing the same
  fact with two codes in parallel); the emission level is determined by the explicit severity. When
  triggered, it counts toward error_count and changes the exit code. Note that healthy programs
  produce no emissions (nothing is reported when all obligations have delivery markers), so the
  promotion affects the build result only when this defect actually occurs.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems; the default emission level is warn, and
  they may be fixed. Exception: `W1090` has an emission level of error; when triggered, it counts
  toward error_count, changes the exit code, prevents compilation, and must be fixed (see its entry
  for details).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether an
external consumer exists, so these warnings are never emitted for such declarations (Decision B
finalized in #321). If you see an "unused" warning, remove the corresponding `pub` to eliminate it;
conversely, retain `pub` for declarations that need to be called externally.
