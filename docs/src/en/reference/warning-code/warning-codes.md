# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit manually. To change copy, edit
`locales/*.json`; to change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and do not block compilation, but flag potential issues in the code.
The current registry contains **8** warning codes. For a complete index, see the
[Error Code Home](../error-code/index.md).

## Configuration

The behavior of dead code warnings can be configured via `yaoxiang.toml`:

```toml
[lint]
# Dead code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable warnings
- `warn`: Show warnings (default)
- `deny`: Treat warnings as errors, blocking compilation

## Warning Levels

| Level  | Effect                                           |
| ------ | ------------------------------------------------ |
| `off`  | Completely disable this category of warnings     |
| `warn` | Show warnings but continue compilation (default) |
| `deny` | Treat warnings as errors, blocking compilation   |

## Difference from Error Codes

- **Errors (`E` prefix)**: Block compilation, must be fixed.
- **Warnings (`W` prefix)**: Indicate potential issues, can be optionally fixed.

## Dead Code Warning Determination Criteria

`W1001`–`W1005` report **unreferenced top-level bindings and type definitions**. RFC-029g removed
the `pub` keyword, and no modifier can exempt these warnings; the only exemption point is the
**in-package reference pool** (RFC-029f): a name referenced by any file in the project is considered
live—cross-file consumers are not visible in this file, which is a "preferring false negatives over
false positives" direction. The single-file (Script) path has no package view, and unreferenced
top-level bindings are reported unconditionally.
