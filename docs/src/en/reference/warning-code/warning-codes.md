# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit by hand. To change the wording, edit
`locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and do not block compilation, but indicate possible issues in the code.
The current registry contains **8** warning codes; see the
[error code index](../error-code/index.md) for the complete listing.

## Configuration

The behavior of dead code warnings can be configured via `yaoxiang.toml`:

```toml
[lint]
# Dead code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable the warning
- `warn`: show the warning (default)
- `deny`: treat the warning as an error and block compilation

## Warning Levels

| Level  | Effect                                              |
| ------ | --------------------------------------------------- |
| `off`  | Completely disable this category of warnings        |
| `warn` | Show the warning but continue compilation (default) |
| `deny` | Treat the warning as an error and block compilation |

## Difference from Error Codes

- **Errors (`E` prefix)**: block compilation and must be fixed.
- **Warnings (`W` prefix)**: indicate potential issues and can be optionally fixed.

## Dead Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether there are
external consumers, so these warnings are never triggered (resolution B of #321). If you see an
"unused" warning, simply remove the corresponding `pub`; conversely, keep `pub` for declarations
that need to be called externally.
