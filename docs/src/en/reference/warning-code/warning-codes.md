# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code. Their default emission
level is `warn`, and they do not block compilation. The exception is `W1090`, whose emission level
is `error` (the same-code promotion to `E` was ruled by the user on 2026-10-13; see its entry for
details). When triggered, it counts toward `error_count`, changes the exit code, and blocks
compilation. The current registry contains **12** warning codes. See the
[Error Code home page](../error-code/index.md) for the complete index.

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable warnings.
- `warn`: Display warnings (default).
- `deny`: Treat warnings as errors and block compilation.

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest precedence (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintended, rename
  the local module; use --deny-shadowing to promote it to an error.
- **Emission point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:94`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only the deterministic convention of lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of `use` dependencies.
  Within a cycle, ordering follows only the deterministic convention of “lexicographic path order
  within the cycle”; it is not a semantic guarantee. Breaking the cycle (moving one `use` dependency
  in the cycle out of it, or switching to deferred evaluation in a function body) makes the
  initialization order determinable. Division of responsibility with E3019: E3019 detects
  initialization cycles between top-level bindings within a unit, whereas this code detects import
  cycles between modules.
- **Emission point**: `src/driver/arms.rs:1877`

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Ownership analysis downgraded: there is no function-body checker in this compilation (the type ledger and call-site ownership table are missing), so ownership determination uses an empty ledger and borrow conflicts are not detected`
- **Help**: This is a defect in the compiler's internal phase contract, not an error in your

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but was never consumed:
  {detail}`
- **Help**: This is a defect in the compiler's internal phase contract, not an error in your
  program: an obligation field produced by one stage is not read by the next stage, so the effect of
  the obligation may have been silently discarded. Please report this diagnostic as an issue,
  including the field name, file path, and a minimal reproducer. This code belongs to the **W
  family** (code prefix `W`), but its **emission level is `error`**: the user ruling of 2026-10-13
  (WBS 4.3.2, the terminal state of RFC-039 D5) **promoted the same code to `E`** without adding a
  separate `E` code (the two codes represent the same fact in parallel). The emission level is
  determined by the explicit severity; when triggered, it counts toward `error_count` and changes
  the exit code. Note that healthy programs produce zero emissions (no diagnostic is emitted when
  every obligation has a delivery marker), so this promotion affects the build only when the defect
  actually occurs.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:547`

## Difference from Error Codes

- **Errors (`E` prefix)**: Block compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems; their default emission level is `warn`,
  and fixing them is optional. The exception is `W1090`, whose emission level is `error`; when
  triggered, it counts toward `error_count`, changes the exit code, blocks compilation, and must be
  fixed (see its entry for details).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions, types, variables, and methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether an
external consumer exists, so these warnings are never emitted (#321, finalized decision B). If you
see an “unused” warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` on
declarations that need to be called externally.
