# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code. Their default emission
level is warn, which does not prevent compilation. Exception: `W1090` has an emission level of error
(the 2026-10-13 user ruling promoted the same code to E; see its entry for details). When triggered,
it counts toward error_count, changes the exit code, and prevents compilation. The current registry
contains **12** warning codes; see the [Error Code Index](../error-code/index.md) for the complete
list.

## Configuration

You can configure dead code warning behavior in `yaoxiang.toml`:

```toml
[lint]
# Dead code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable warnings
- `warn`: Display warnings (default)
- `deny`: Treat warnings as errors and prevent compilation

### W1006: Local module shadows a dependency package

- **Category**: `Warning`
- **Span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local modules have the highest resolution priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If this shadowing is unintended,
  rename the local module; use --deny-shadowing to promote it to an error.
- **Emission site**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module import cycle

- **Category**: `Warning`
- **Span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: The initialization order is determined by the topological order of `use` dependencies.
  The only ordering convention within a cycle is “lexicographic order of paths within the cycle”;
  this is a deterministic convention, not a semantic guarantee. Breaking the cycle (moving one `use`
  on the cycle out of it, or changing it to deferred evaluation in a function body) makes the
  initialization order determinable. Division of responsibility with E3019: E3019 detects
  initialization cycles between top-level bindings within a unit, whereas this code detects import
  cycles between modules.
- **Emission site**: `src/driver/arms.rs:1877`

- **Category**: `Warning`
- **Span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a defect in an internal compiler stage contract, not an error in your program:
  an obligation field produced by one stage is never read by the next stage, so the effect of the
  obligation may have been silently discarded. Please report this diagnostic, along with the field
  name and file path, as an issue and include a minimal reproduction program. This code belongs to
  the **W family** (code prefix W), but its **emission level is error**: under the 2026-10-13 user
  ruling (WBS 4.3.2, terminal state of RFC-039 D5), **the same code was promoted to E**—no new E
  code is added (two codes representing the same fact are parallel representations)—and the emission
  level is determined by the explicit severity. When triggered, it counts toward error_count and
  changes the exit code. Note: healthy programs emit nothing (the warning is not reported when all
  obligations have delivery markers), so the promotion affects the build result only when this
  defect actually occurs.
- **Emission site**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:547`

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems; their default emission level is warn, and
  you may choose to fix them. Exception: `W1090` has an emission level of error. When triggered, it
  counts toward error_count, changes the exit code, prevents compilation, and must be fixed (see its
  entry for details).

## Criteria for Dead Code Warnings

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is a public interface, and the compiler cannot know whether an external consumer
exists, so it never emits these warnings (#321, finalized decision B). If you see an “unused”
warning, remove the corresponding `pub` to eliminate it; conversely, keep `pub` on declarations that
need to be called externally.
