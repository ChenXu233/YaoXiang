# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit by hand. To change wording, edit
`locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and do not block compilation, but indicate possible issues in the code.
The current registry has **8** warning codes; see the full index on the
[Error Codes Home](../error-code/index.md).

## Configuration

You can configure dead-code warning behavior via `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable the warning
- `warn`: show the warning (default)
- `deny`: treat the warning as an error and block compilation

## Warning Levels

| Level  | Effect                                              |
| ------ | --------------------------------------------------- |
| `off`  | Completely disable this category of warnings        |
| `warn` | Show the warning but continue compilation (default) |
| `deny` | Treat the warning as an error and block compilation |

## Difference from Error Codes

- **Errors (`E` prefix)**: block compilation and must be fixed.
- **Warnings (`W` prefix)**: indicate potential issues and are optional to fix.

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. `pub`
declarations are external interfaces; the compiler cannot know whether external consumers exist, so
they will never trigger these warnings (option B decided in #321). If you see an "unused" warning,
removing the corresponding `pub` will eliminate it; conversely, declarations that need to be called
externally should keep `pub`.
