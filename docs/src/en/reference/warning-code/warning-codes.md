# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit by hand. To change the wording, edit
`locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and do not prevent compilation, but indicate potential issues in the
code. The current registry contains **10** warning codes. See the
[Error Codes index](../error-code/index.md) for the full list.

## Configuration

The behavior of dead-code warnings can be configured via `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable the warning
- `warn`: show the warning (default)
- `deny`: treat the warning as an error and block compilation

| `deny` | Treat the warning as an error and block compilation |

## Difference from Error Codes

- **Error (`E` prefix)**: blocks compilation and must be fixed.
- **Warning (`W` prefix)**: indicates a potential issue and can optionally be fixed.

## Dead-Code Warning Decision Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether external
consumers exist, so these warnings are never triggered for `pub` items (decision B from #321). If
you see an "unused" warning, simply remove the corresponding `pub` to eliminate it; conversely, keep
`pub` for declarations that need to be called externally.
