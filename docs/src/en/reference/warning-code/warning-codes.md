# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`. To change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code; their default emission
level is `warn`, which does not block compilation. Exception: `W1090` has an emission level of
`error` (the same-code elevation to E ruled by the user on 2026-10-13; see its entry), and
triggering it counts toward error_count, changes the exit code, and blocks compilation. The current
registry contains **12** warning codes; for the complete index, see the
[error codes home page](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable warnings
- `warn`: Display warnings (default)
- `deny`: Treat warnings as errors and block compilation

### W1006: Local Module Shadows Dependency Package

- **Category**: `Warning`
- **span Exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing was not intentional,
  rename the local module; use --deny-shadowing to elevate it to an error.
- **Emission Point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module Import Cycle

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Module import cycle {cycle}: the initialization order within the cycle cannot be determined; the order within the cycle follows only a deterministic lexicographic ordering of paths (not a semantic guarantee)`
- **Help**: The initialization order is determined by the topological order of `use` dependencies;
  the order within a cycle follows only the deterministic convention of “lexicographic ordering of
  paths within the cycle” and is not a semantic guarantee. Breaking the cycle (moving one `use` on
  the cycle out of it, or changing it to deferred evaluation in a function body) makes the
  initialization order determinable. Division of responsibilities with E3019: E3019 detects
  initialization cycles among top-level bindings within a unit, whereas this code detects import
  cycles between modules.
- **Emission Point**: `src/driver/arms.rs:1836`

### W1082: Ownership Analysis Downgraded

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function body checker (the type ledger and call-site ownership table are missing); ownership is determined using an empty ledger, and borrow conflicts are not detected`
- **Help**: This is an internal compiler stage-contract defect, not an error in your program: at

  by the function body checker, so it allows the code through as though “nothing conflicts”—the

  reproducer as an issue.
- **Emission Point**: `src/frontend/core/sema/checker.rs:1257`

### W1090: Obligation Produced but No Consumer

- **Category**: `Warning`
- **span Exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is an internal compiler stage-contract defect, not an error in your program: an
  obligation field produced by one stage is not read by the next stage, so the effect of the
  obligation may have been silently discarded. Please report this diagnostic, together with the
  field name and file path, as an issue, and attach a minimal reproducer. This code belongs to the
  **W family** (code prefix W), but its **emission level is error**: the 2026-10-13 user ruling (WBS
  4.3.2, the terminal state of RFC-039 D5) **elevates the same code to E**—no new E code is added
  (two codes for the same fact would merely be parallel representations), and the emission level is
  determined by the explicit severity; triggering it counts toward error_count and changes the exit
  code. Note: healthy programs emit nothing (no diagnostic is reported when all obligations have
  delivery markers), so the elevation affects the build result only when this defect actually
  occurs.
- **Emission Point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Warning Levels

| Level  | Effect                                               |
| ------ | ---------------------------------------------------- |
| `off`  | Completely disable this warning category             |
| `warn` | Display a warning but continue compilation (default) |
| `deny` | Treat the warning as an error and block compilation  |

## Difference from Error Codes

- **Error (`E` prefix)**: Blocks compilation and must be fixed.
- **Warning (`W` prefix)**: Indicates a potential problem; the default emission level is warn, and
  fixing it is optional. Exception: `W1090` has an emission level of error; triggering it counts
  toward error_count, changes the exit code, blocks compilation, and must be fixed (see its entry).

## Criteria for Dead-Code Warnings

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. `pub`
declarations are public interfaces, and the compiler has no way of knowing whether external
consumers exist, so these warnings are never emitted (option B was finalized in #321). If you see an
“unused” warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` for
declarations that need to be called externally.
