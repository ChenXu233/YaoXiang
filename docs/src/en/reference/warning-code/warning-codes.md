# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code. Their default emission
severity is warn, and they do not prevent compilation. Exception: `W1090` is emitted at error
severity (the same-code promotion to E ruled by the user on 2026-10-13; see its entry), so
triggering it increments error_count and changes the exit code, preventing compilation. The current
registry contains **12** warning codes. For the full index, see the
[Error Code Index](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span Exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local modules have the highest resolution priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing is unintentional,
  rename the local module; use --deny-shadowing to promote it to an error.
- **Emission Point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:78`

### W1007: Module import cycle

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Module import cycle {cycle}: the initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of `use` dependencies.
  Ordering within a cycle follows only the deterministic convention of “lexicographic order of paths
  within the cycle”; it is not a semantic guarantee. Breaking the cycle (moving a `use` in the cycle
  out of it, or switching to deferred evaluation in a function body) makes the initialization order
  determinable. Division of responsibility with E3019: E3019 detects initialization cycles between
  top-level bindings within a unit, whereas this code detects import cycles between modules.
- **Emission Point**: `src/driver/arms.rs:1811`

- **Category**: `Warning`
- **span Exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is an internal compiler stage-contract defect, not an error in your program: an
  obligation field produced by one stage was not read by the next stage, so the effect of the
  obligation may have been silently discarded. Please report this diagnostic, along with the field
  name and file path, as an issue, and include a minimal reproducer. This code belongs to the **W
  family** (code prefix W), but its **emission severity is error**: on 2026-10-13, the user ruled
  (WBS 4.3.2, terminal state of RFC-039 D5) to **promote the same code to E**—without adding a new E

  is determined by the explicit severity; when triggered, it increments error_count and changes the
  exit code. Note: healthy programs emit nothing (no warning is reported when all obligations have
  delivery markers), so the promotion affects the build result only when this defect actually
  occurs.
- **Emission Point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems; their default emission severity is warn,
  and you can choose to fix them. Exception: `W1090` is emitted at error severity, so triggering it
  increments error_count and changes the exit code, preventing compilation; it must be fixed (see
  its entry).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is part of the public interface, and the compiler cannot know whether external
consumers exist, so these warnings never trigger (final decision B for #321). If you see an “unused”
warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` for declarations
that need to be called externally.
