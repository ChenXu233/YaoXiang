# Warning codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, and then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code. Their default emission
level is warn, which does not prevent compilation. The exception is `W1090`, whose emission level is
error (the same code was promoted to E by the user ruling dated 2026-10-13; see its entry for
details). When triggered, it counts toward error_count, changes the exit code, and prevents
compilation. The current registry contains **12** warning codes. For the complete index, see the
[error code index](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): `./src/{module}` overrides
  dependency package `{dependency}` in .yaoxiang/vendor/. If the shadowing is unintended, rename the
  local module; use `--deny-shadowing` to promote it to an error.
- **Emission point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic path-lexicographic convention (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies. Within
  a cycle, ordering follows only the deterministic convention of “lexicographic order of paths
  within the cycle,” not a semantic guarantee. Breaking the cycle (moving one use dependency out of
  the cycle, or switching to deferred evaluation in a function body) makes the initialization order
  determinable. Division of responsibility with E3019: E3019 determines initialization cycles
  between top-level bindings within a unit, while this code determines import cycles between
  modules.
- **Emission point**: `src/driver/arms.rs:1853`

### W1082: Ownership analysis downgraded

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), ownership decisions are made using an empty ledger, and borrow conflicts are not detected`
- **Help**: This is a defect in the compiler's internal stage contract, not an error in your
  program: at runtime, the ownership layer cannot obtain the type ledger and call-site ownership
  table supplied by the function-body checker, and therefore lets everything pass on a “nothing

  together with a minimal reproduction program as an issue.
- **Emission point**: `src/frontend/core/sema/checker.rs:1280`

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a defect in the compiler's internal stage contract, not an error in your
  program: an obligation field produced by one stage is not read by the next stage, so the effect of
  the obligation may have been silently discarded. Please report this diagnostic, along with the
  field name and file path, as an issue and include a minimal reproduction program. This code
  belongs to the **W family** (code prefix W), but its **emission level is error**: the user ruling
  dated 2026-10-13 (WBS 4.3.2, the final state of RFC-039 D5) **promotes the same code to E**—it
  does not add a separate E code (two codes for the same fact would represent it in parallel). The
  emission level is determined by the explicit severity; when triggered, it counts toward
  error_count and changes the exit code. Note that healthy programs produce zero diagnostics (the
  warning is not reported when every obligation has a delivery marker), so the promotion affects the
  build result only when this defect actually occurs.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from error codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems. The default emission level is warn, and
  they can be fixed as needed. The exception is `W1090`, whose emission level is error. When
  triggered, it counts toward error_count, changes the exit code, and prevents compilation, so it
  must be fixed (see its entry for details).

## Criteria for dead-code warnings

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether external
consumers exist, so these warnings are never emitted (#321, Decision B). If you see an “unused”
warning, remove the corresponding `pub` to eliminate it; conversely, retain `pub` for declarations
that need to be called externally.
