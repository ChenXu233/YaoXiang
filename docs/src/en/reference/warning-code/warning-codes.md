# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the wording,
edit `locales/*.json`; to change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and indicate potential problems in the code. Their default emission
level is warn, which does not prevent compilation. Exception: `W1090` has an emission level of error
(the same code was promoted to E by the 2026-10-13 user ruling; see its entry for details). When
triggered, it counts toward `error_count`, changes the exit code, and prevents compilation. The
current registry contains **12** warning codes. For the complete index, see the
[Error Code home](../error-code/index.md).

## Configuration

You can configure dead-code warning behavior through `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

- **Help**: The function is never referenced; consider removing it or adding a call. This warning is

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span Exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): `'./src/{module}'` overrides
  the dependency package '{dependency}' in `.yaoxiang/vendor/`. If the shadowing was unintended,
  rename the local module; use --deny-shadowing to promote it to an error.
- **Emission Point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:87`

### W1007: Module import cycle

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographical path order (not a semantic guarantee)`
- **Help**: Initialization order is determined by the topological order of use dependencies.
  Ordering within a cycle has only one deterministic convention, "lexicographical order of paths
  within the cycle," and is not a semantic guarantee. Breaking the cycle by moving one use in the
  cycle out of it or changing it to deferred evaluation within a function body makes the
  initialization order determinable. Division of responsibility with E3019: E3019 detects
  initialization cycles between top-level bindings within a unit, whereas this code detects import
  cycles between modules.
- **Emission Point**: `src/driver/arms.rs:1853`

- **Help**: Install the Z3 solver and run the check again to obtain a termination determination.

### W1082: Ownership analysis downgraded

- **Category**: `Warning`
- **span Exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation has no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions use an empty ledger and borrow conflicts are not detected`
- **Help**: This is an internal compiler stage-contract defect, not an error in your program. At
  runtime, the ownership layer cannot obtain the type ledger and call-site ownership table provided
  by the function-body checker, so it allows everything through on the assumption that "nothing
  conflicts"—the borrow-conflict check is skipped entirely. Please report this diagnostic, together
  with a minimal reproducing program, as an issue.
- **Emission Point**: `src/frontend/core/sema/checker.rs:1280`

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span Exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but was never consumed:
  {detail}`
- **Help**: This is an internal compiler stage-contract defect, not an error in your program. An
  obligation field produced by one stage is never read by the next stage, so the effect of the
  obligation may have been silently discarded. Please report this diagnostic as an issue, together
  with the field name and file path, and include a minimal reproducing program. This code belongs to
  the **W family** (code prefix W), but its **emission level is error**: the 2026-10-13 user ruling
  (WBS 4.3.2, terminal state of RFC-039 D5) **promotes the same code to E**—it does not add a new E
  code (two codes for the same fact would provide parallel representations). The emission level is
  determined by explicit severity; when triggered, the diagnostic counts toward `error_count` and
  changes the exit code. Note that healthy programs emit no diagnostics (no report is produced when
  all obligations have delivery markers), so the promotion affects the build result only when this
  defect actually occurs.
- **Emission Point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from Error Codes

- **Errors (`E` prefix)**: Prevent compilation and must be fixed.
- **Warnings (`W` prefix)**: Indicate potential problems. Their default emission level is warn, and
  fixing them is optional. Exception: the emission level of `W1090` is error. When triggered, it
  counts toward `error_count`, changes the exit code, prevents compilation, and must be fixed (see
  its entry for details).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is a public interface, and the compiler cannot determine whether external
consumers exist, so these warnings are never emitted for it (#321, final decision B). If you see an
"unused" warning, removing the corresponding `pub` will eliminate it; conversely, retain `pub` for
declarations that need to be called externally.
