# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it by hand. To change wording, edit
`locales/*.json`; to change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and do not block compilation, but they flag potential issues in the
code. The current registry has **10** warning codes; for a complete index see the
[Error Code Index](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured via `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Show the warning (default)
- `deny`: Treat the warning as an error and block compilation

## Warning Levels

| Level  | Effect                                              |
| ------ | --------------------------------------------------- |

| `warn` | Show the warning but continue compilation (default) |
| `deny` | Treat the warning as an error and block compilation |

## Difference from Error Codes

- **Error (`E` prefix)**: Blocks compilation and must be fixed.
- **Warning (`W` prefix)**: Flags potential issues and may be fixed at the developer's discretion.

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way to know whether external
code consumes it, so these warnings are never triggered for `pub` items (decision B of #321). If you
see an "unused" warning, removing the corresponding `pub` will suppress it; conversely, declarations
that need to be called from outside should keep `pub`.
