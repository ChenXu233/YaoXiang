# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry in
`src/util/diagnostic/codes/` and `locales/zh.json`. Do not edit by hand. To change text, edit
`locales/*.json`. To change the code table, edit `define_codes!`, then re-run
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W`, do not block compilation, but indicate potential issues in the code.
The current registry contains **10** warning codes. For a complete index, see
[Error Codes Home](../error-code/index.md).

## Configuration

The behavior of dead code warnings can be configured via `yaoxiang.toml`:

```toml
[lint]
# Dead code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: disable warning
- `warn`: show warning (default)
- `deny`: treat warning as error, blocking compilation

## Warning Levels

| Level  | Effect                                          |
| ------ | ----------------------------------------------- |
| `off`  | Completely disable this type of warning         |
| `warn` | Show warning but continue compilation (default) |
| `deny` | Treat warning as error, blocking compilation    |

## Difference from Error Codes

- **Errors (`E` prefix)**: block compilation and must be fixed.
- **Warnings (`W` prefix)**: indicate potential issues and can be optionally fixed.

## Dead Code Warning Detection Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. `pub`
declarations are external interfaces; the compiler has no way of knowing whether external consumers
exist, so these warnings are never triggered (#321 Decision B). If you see an "unused" warning,
removing the corresponding `pub` will eliminate it; conversely, keep `pub` on declarations that need
to be called externally.
