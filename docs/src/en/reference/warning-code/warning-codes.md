# Warning Codes

This page is generated by `scripts/docs/gen-error-code-docs.py` from the `define_codes!` registry
under `src/util/diagnostic/codes/` and `locales/zh.json`; do not edit it manually. To change the
wording, edit `locales/*.json`. To change the code table, edit `define_codes!`, then rerun
`python scripts/docs/gen-error-code-docs.py`.

Warning codes start with `W` and flag potential problems in code; their default emission level is
`warn`, which does not prevent compilation. Exception: `W1090` has an emission level of `error` (the
same-code promotion to E was decided by the user on 2026-10-13; see its entry), so triggering it
counts toward error_count and changes the exit code, preventing compilation. The current registry
contains **12** warning codes; for the complete index, see the
[error code homepage](../error-code/index.md).

## Configuration

The behavior of dead-code warnings can be configured in `yaoxiang.toml`:

```toml
[lint]
# Dead-code warning level: off | warn | deny
dead-code = "warn"
```

- `off`: Disable the warning
- `warn`: Display the warning (default)
- `deny`: Treat the warning as an error and prevent compilation

### W1006: Local module shadows dependency package

- **Category**: `Warning`
- **span exemption**: No
- **Template**: `Local module '{module}' shadows dependency package '{dependency}'`
- **Help**: Local module resolution has the highest priority (RFC-014): './src/{module}' overrides
  the dependency package '{dependency}' in .yaoxiang/vendor/. If the shadowing was not intended,
  rename the local module; use --deny-shadowing to promote it to an error.
- **Emission point**: `src/driver/arms.rs:676`, `src/util/diagnostic/command.rs:78`

### W1007: Module import cycle

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Module import cycle {cycle}: initialization order within the cycle cannot be determined; ordering within the cycle follows only a deterministic convention based on lexicographic path order (not a semantic guarantee)`
- **Help**: The initialization order is determined by the topological order of use dependencies;
  ordering within the cycle follows only the deterministic convention of "lexicographic order of
  paths within the cycle" and is not a semantic guarantee. Breaking the cycle (moving one use on the
  cycle out of it, or changing it to deferred evaluation in a function body) makes the
  initialization order determinable. Division of labor with E3019: E3019 determines initialization
  cycles between top-level bindings within a unit, whereas this code determines import cycles
  between modules.
- **Emission point**: `src/driver/arms.rs:1811`

### W1082: Ownership analysis downgraded

- **Category**: `Warning`
- **span exemption**: No
- **Template**:
  `Ownership analysis downgraded: this compilation had no function-body checker (the type ledger and call-site ownership table are missing), so ownership decisions are made against an empty ledger and borrow conflicts are not detected`
- **Help**: This is a defect in the compiler's internal stage contract, not a mistake in your
  program: at runtime, the ownership layer cannot obtain the type ledger and call-site ownership
  table provided by the function-body checker, so it allows the code through on the assumption that

  together with a minimal reproduction program as an issue.
- **Emission point**: `src/frontend/core/sema/checker.rs:1270`

### W1090: Obligation produced but not consumed

- **Category**: `Warning`
- **span exemption**: Yes
- **Template**: `Obligation field \`{field}\` was produced in {file} but never consumed: {detail}`
- **Help**: This is a defect in the compiler's internal stage contract, not a mistake in your
  program: an obligation field produced by one stage is never read by the next stage, and the effect
  of the obligation may have been silently discarded. Please report this diagnostic together with
  the field name and file path as an issue, and include a minimal reproduction program. This code
  belongs to the **W family** (code prefix W), but its **emission level is error**: on 2026-10-13,
  the user ruling (WBS 4.3.2, the final state of RFC-039 D5) **promoted the same code to E**—no new
  E code was added (representing the same fact with two codes would be a parallel representation),
  and the emission level is determined by the explicit severity; when triggered, it counts toward
  error_count and changes the exit code. Note: healthy programs produce no emissions (the warning is
  not reported when all obligations have delivery markers), so the promotion affects the build
  result only when this defect actually occurs.
- **Emission point**: `src/driver/obligations.rs:105`, `src/driver/obligations.rs:535`

## Differences from Error Codes

- **Errors (`E` prefix)**: Block compilation and must be fixed.
- **Warnings (`W` prefix)**: Flag potential problems; the default emission level is warn, and fixing
  them is optional. Exception: `W1090` has an emission level of error; triggering it counts toward
  error_count and changes the exit code, blocks compilation, and must be fixed (see its entry).

## Dead-Code Warning Criteria

`W1001`–`W1005` report **unused private** (non-`pub`) functions / types / variables / methods. A
`pub` declaration is an external interface, and the compiler has no way of knowing whether an
external consumer exists, so these warnings are never triggered (#321, Decision B). If you see an
"unused" warning, remove the corresponding `pub` to eliminate it; conversely, keep `pub` on
declarations that need to be called externally.
